## Commentary

### Yesterday

Twenty-two tasks closed — one of the heaviest days the loop has had. Three
threads ran through it.

**The remote experience got its identity back.** A remote window's titlebar now
says which machine you are typing into, and the chip is something you can act on
rather than decoration (T610). The Activity panel follows its window through a
reconnect instead of going blank (T614), and however you opened it, it names the
machine once rather than twice (T1419). Closing a remote window can now leave the
session running on the far end (T1390) — the thing you actually want when you are
done looking but not done working.

**The paint pipeline stopped lying to its own tests.** A month-old z-order test
was switched back on (T607), a stray always-on-top bit now heals on resize
(T1413), the terminal stopped blinking when you maximise or snap (T1393), the
viewer toolbar stopped repainting a beat behind the drag (T1392), and the find
bar's corners show the page behind them rather than a guessed colour (T1391).
Underneath those, T1405 and T585 finally *scored* the accent repaint by counting
paints instead of photographing them — which is a different kind of win, because
the old test passed 129 of 129 with the redraw removed entirely.

**And a few plain fixes:** a diff pane stopped falling back to Arial and Courier
New (T595), a tab grows to fit the title its own shell set (T584, T1396), closing
a busy pane asks again because ConPTY's prompt marks lie (T1398), and the Kill
button on a session card stops advertising itself after you have already gone
(T588).

### What shipped — and what did not

**win-v1.36.16** went out yesterday, published on the second of three attempts.
It was cut at **11:18 in the morning**, which is the whole problem with it: it
carries the day up to T1391 and nothing after. The remote-identity work, the
z-order fixes, the font fix, the tab sizing, the busy-pane prompt — all of it
landed in the eighteen hours *after* the release.

**40 commits are stranded** on this branch and on nobody's machine. That is the
largest gap since the stranding check was added. The publish watermark reads
`ok+40`: the release exists, so nothing is red, and forty commits of work is
still sitting here. The one-a-day cadence keeps producing this shape whenever the
day's best work happens in the evening — which, given the loop runs around the
clock, is most days.

### Today's focus

The queue's answer is **T1421**, filed this morning from main intake and the only
P0 on the board: signing out of your relay account on a Windows machine almost
certainly does not revoke that machine's enrollment. Mac fixed this yesterday in
two commits. Until it lands here, signing out on Windows looks like "this machine
is no longer mine" and isn't — the machine stays listed on your other computers,
stays online, and a session already bridged keeps streaming. That is a security
answer with a user-visible face, which is exactly the bar for jumping the queue.

### Reflection

**The publish cadence is now the weakest link in the chain, and it is the second
day running that the digest has had to say so.** Every other gate on this loop has
teeth — the push check, the CI verdict, guard staleness, stranded work, the
unshipped-user-report gate. Publishing is the one place where "we did the work"
and "the user has the work" are still separated by up to a day, and the failure is
quiet by construction: the watermark says `ok`, the health line is green, and the
user is running eighteen-hour-old software. `publish=ok+40` is the tell. The
existing remedy — a `-Request` filed by hand when the task came from a user — only
covers the case somebody remembered to flag. The idea filed on 09-06 (publish on
the supervisor tick rather than the turn) is the right shape and has not been
promoted to a task; it should be.

**The test-scoring thread is quietly the most valuable work of the week.** T1405,
T585, T1400 and T592 are all the same discovery in different clothes: a check that
photographs a result cannot tell "it repainted correctly" from "it never repainted
and the old pixels are still there". T1407 is the open generalisation of that —
every other live-update claim in `test/win32` rests on the same blind spot — and it
is still `todo`. Closing it is worth more than several feature tasks, because
every gate downstream of it is currently making a claim it cannot back.

**M1 is 266 of 338 closed**, 72 open. The denominator moved by three this morning
(all main intake, all promoted). Intake lag is back to zero commits, and the
Mac-side pace is picking up again — four commits overnight after a week of near
silence.

**The cutover is still gated on the same two things** it has been gated on for
weeks: T87 (the Mac regression build, a seat we cannot run from here) and the
`origin/main` commits that have to be merged into this branch first. Neither moved
yesterday. Worth saying plainly: nothing this seat does will unblock the cutover,
so it should stop appearing in reflections as though it might.

## Feature ideas

### User-facing UX

- **Ship the evening's work, not the morning's** (High) — the release you can
  install should be the newest good commit, not whatever happened to be HEAD when
  a clock struck. Publish when the day's work stops moving, so you never read
  about a fix you cannot install.
- **See what you are about to update to** (High) — the update prompt names the
  handful of things that actually changed since your build, in the same plain
  language the activity feed uses, instead of a version number.
- **Drag a pane out into its own window** (High) — grab a pane's tab or divider
  and pull; it becomes a window. Drop it back on another window's strip to put it
  back. The one split-management gesture every other tiling terminal has and this
  one does not.
- **Zoom one pane to fill the window, temporarily** (High) — a single chord swells
  the focused pane to the whole window and back, without disturbing the layout.
  For the moment you need to read a stack trace in a pane that is 40 columns wide.
- **A pane that remembers where it was looking** (Medium) — reopen a window and
  each pane returns to its scrollback position, not the bottom. Restoring the text
  but losing your place is half a restore.
- **Tell me when this finishes, whatever I am doing** (Medium) — mark a pane
  "notify me", and a Windows toast fires when its command exits, with the exit
  code and a click that focuses the pane.

### Technical / stability

- **A test that cannot pass while switched off** (Medium) — generalise T1405's
  count-the-paints trick into a harness rule: any live-update assertion must fail
  when the update is removed, proved once at authoring time. This week found three
  checks that could not fail; there is no reason to believe it found all of them.
- **Say how far behind the installed build is** (Medium) — the health line already
  knows the release and the commit count since it; surface that number in About, so
  the gap is visible from inside the product rather than only in the loop's
  telemetry.
