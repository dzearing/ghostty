## Commentary

### Yesterday

**The thing that had not shipped in three days shipped six times.** T1292 took
the daily publish off local Docker — the MSI is already built by fork CI on every
push, so the publish now reaches for that artifact instead of a container this box
would have to start. Then T1294 removed the once-a-day rule: a fix that lands
after the day's release no longer waits until tomorrow. The result is
**win-v1.36.1 through win-v1.36.6**, the first releases since 08-31. You are no
longer three days behind the work.

**Two freezes you would have felt are gone.** Letting go of a window edge after a
resize used to lock the window for about a second (T412). A pane printing
non-stop used to freeze the whole window for a moment every thirty seconds
(T1311) — that was the layout snapshot walking the tree on a timer while the
render thread waited. Alongside them, the log file Ghoztty leaves behind stopped
growing without limit (T410).

**Remote Desktop got a real look.** An unfocused pane was re-dimming itself on
every repaint over RDP, so it kept getting darker until it was unreadable
(T1295); that is fixed, and T1316 added a check that measures the darkening
rather than glancing at it once. A session resumed from another machine now keeps
the window name you gave it (T1296).

**And the Defender problem became work instead of a complaint.** Windows was
quarantining the download as `Wacatac.C!ml`. The download page now says so and
how to get the files back; T1312 arranged for a second scanner to be asked about
each release rather than trusting Defender alone; T1313 turned the false-positive
report to Microsoft into something generated from the release instead of typed by
hand.

**What is on your machine, and what is not.** The last release,
**win-v1.36.6 (c6e5b376a)**, carries everything through T1296. **Nineteen commits
have landed since** and are in no release — the whole T1311 flood-freeze fix, the
Defender work (T1312, T1313), the loop's own stall detection (T1319), and the
user-report release plumbing (T1315, T1321, T1323, T1325). None of it is on any
machine yet. Under the new same-day rule the next push should carry them.

### Today's focus

**The queue has run out of unblocked high-priority work on this seat, and that is
the headline.** Every open P0 and P1 for Windows is now one of three things:
waiting on you (T1179's clean-machine install walk, T1256's Remote Desktop watch,
T1293/D89's signing decision), waiting on the cutover chain (T1074 → T1180,
T1181), or waiting on the T443 crash ghost that only reproduces intermittently.
The queue therefore hands out **T419** — making the packaging steps run from
`zig build` on both platforms instead of bash scripts — which is honest P2 work
and removes the last Docker assumption from delivery.

The practical reading: the loop can keep grinding P2s indefinitely, but the
**cutover to `main` cannot move without you**. T1179 is the gate, and it is one
sitting: install from the website onto this box over a running Ghoztty, and say
what happened.

### Reflection

**Yesterday proved the diagnosis from the day before.** The 09-03 digest argued
that a step whose failure mode is "nothing happens" needs a gate measuring
elapsed reality, and that the 17:00 rule encoded a workday this loop does not
have. Both were fixed within a day, and delivery went from zero in three days to
six releases. That is the pattern worth keeping: **the reflection tab is
producing work items that matter more than the ones the backlog generates on its
own.** Three of yesterday's most valuable closures (T1292, T1294, T1319) came
from digest reasoning, not from the queue.

**The blocked P0 list is now the whole story.** Six of the seven things standing
between here and a shippable Windows Ghoztty are gated on a human: a walkthrough,
a screen-share, a certificate purchase. The loop has quietly become very good at
producing work it can finish and very bad at surfacing the work it cannot. A
health-line field for *"N P0s blocked on the user, oldest X days"* would put that
in front of you every morning instead of once a week when a digest gets
introspective.

**Watch the release cadence for the opposite failure now.** Six releases in
sixteen hours is the correct reaction to three days of silence, but a version
bump per fix means the version number stops meaning anything and every user
report arrives against a build nobody else has. Worth deciding soon whether
same-day publishing should coalesce — publish when N task-boundaries have
accumulated, or when a user-reported fix lands (which T1315/T1321 now detect),
rather than on every push.

**The trust problem is bigger than the bug.** Defender deleting the download is
not a packaging defect; it is what an unsigned binary from an unknown publisher
looks like to Windows, and no amount of hardening the MSI changes that. D89 is
open for exactly this reason and it is a purchase decision, not an engineering
one.

### Decisions

**D89 is open and it is the one that matters**: *Windows now deletes the download
on some machines, not just warns about it — buy a signing certificate?* Yesterday
sharpened it: the download page now apologises for the quarantine, and the report
to Microsoft is automated, but both are workarounds for the absence of a
signature. Every install-facing task (T1179, T1291, T1299) is being validated
against a binary that a fresh machine may simply erase.

The directive still steering the day is **D85** (2026-08-31): *the terminal
should only ever run something that was actually published.* Yesterday's six
releases are that rule finally being livable.

## Feature ideas

### User-facing

- **Run this one elevated, right here** — *High.* Needing an administrator shell
  today means opening a separate window, losing your directory and your history,
  and copying the command across. Let a pane request elevation for one command
  (or promote itself), with the output landing in place and a clear marker on the
  pane while it is elevated.
- **Come back to the environment you left, not just the shell** — *High.* A
  restored session gives you the right machine and the right directory, then
  drops you outside the virtualenv, the conda env, and the module set you had
  activated. Record what the shell had turned on and offer to turn it back on, so
  restore means "where I was" rather than "roughly where I was".
- **What did that command change on disk?** — *High.* After a build, an install,
  or a script somebody sent you, the interesting question is what moved. A small
  summary under the command — files added, modified, deleted, and the repo's
  status delta — answers it without a second `git status` and catches the writes
  you did not expect.
- **Pick the shell from the new-tab button** — *Medium.* The `+` always opens the
  same flavor, so a WSL or `cmd` tab means the palette or a config edit. A split
  button with the detected flavors, and the last-used one as the default click,
  makes a mixed-shell window normal instead of deliberate.
- **Flip back to the pane I was just in** — *Medium.* Moving between two panes in
  a busy layout is directional keys and aim. One binding that toggles between the
  current pane and the previously focused one turns the common case — comparing
  two things — into a single key held down.
- **Search a session you are not looking at** — *Medium.* Persistent sessions keep
  their scrollback, but you can only search the one on screen. Searching every
  live session at once, with results naming the session and offering to attach,
  makes the persistence feature findable rather than merely durable.

### Trust and delivery

- **A release you can verify byte for byte** — *Medium.* When Windows quarantines
  the download, there is currently no way for you or anyone else to establish that
  the file is the one the build machine produced. Publishing checksums with each
  release, and making the build reproducible enough that CI can re-derive them,
  turns "it is a false positive, trust me" into something checkable — and gives
  the report to Microsoft a much stronger claim.
