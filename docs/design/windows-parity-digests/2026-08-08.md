## Commentary

### Yesterday

**A day of finishing things rather than starting them.** Twenty-four tasks
closed against thirty-eight filed — and unlike the day before, most of what
closed was visible chrome rather than plumbing:

- **Windows can finally cut a release.** Two days of "the download page is
  stale" ended with `win-v1.31.0` published and the site pointing at it. The
  underlying problem was structural, not clerical: main has no Windows source
  at all, so a release has to be tagged on the branch the Windows code lives
  on. That is now written down in the runbook, along with why there are two
  tags. The download page also warns, out loud, that the Windows build is
  unsigned.
- **The Activity Monitor is usable from the keyboard.** It shows where the
  keyboard is, routes keys there, and its machine switcher no longer needs a
  mouse. It also stopped burning CPU while nobody was looking at it — the
  head-of-queue item from yesterday's digest, closed the same day.
- **Chrome consistency, five ways.** Every dialog now reads at the same size,
  the dialog panels stopped being dark-only, an accent change repaints the
  whole screen instead of just the tab strip, both dividers in a hero window
  are finally the same divider, and a divider color too faint to see is lifted
  until it is. Sloped icon arms no longer paint lighter than the marks beside
  them — a one-pixel complaint that was really an anti-aliasing bug.
- **Banner links look like links now**: dotted underline at rest, solid under
  the pointer, and the whole link lights up rather than the fragment you
  happen to be over.
- **Two small trust fixes**: a read-only pane wears a badge that turns the mode
  back off, and clicking a desktop notification focuses the pane that raised
  it instead of whatever was in front.
- **Float on Top exists on Windows.** The capability had been built and then
  given no door — no menu row, no palette entry. It has both now.
- **Viewer text is Segoe UI**, not Arial. The font stack named only the macOS
  families, so every Windows viewer had been falling through to the generic
  fallback next to chrome that is Segoe UI.
- **Three restore bugs, all the same shape**: a missing background agent, an
  agent crash, and a queued re-render each used to take out panes that had
  nothing to do with them.

**And the tracker grew a memory.** A status change now writes a receipt into
the task's own history, so "why is this task suddenly open again" is
answerable. That came directly out of a real confusion the day before, where a
parked crash-watch reopened itself and nobody could tell a deliberate change
from a stray click.

### Reflection

**Today the queue learned what main has been doing.** This is the first day the
daily main intake actually ran, and it found seventy-one commits waiting —
about ten days of upstream work that this branch had never looked at. Roughly
fifty of them are one arc: on the Mac, Ghoztty now sets up your coding agent
for you, installing the skill and the hooks that let it drive panes, and it
grew a panel to manage that. None of it exists on Windows. That is the single
largest parity gap this project has, and until this morning it was not in the
queue at all.

**Which reframes the convergence story.** The M1 number has been treated as the
distance to done, but it only counted what this seat had already noticed. A
daily intake means the denominator now moves for a legitimate reason — main
shipping — rather than only from this box's own discoveries. Better an honest
number that goes up than a flattering one that is measuring the wrong thing.

**The nine tasks filed from that intake were deliberately not fifty.** From the
Mac side the agent-integration work is a dozen components; from the Windows
seat it is one feature, one panel, and one consent dialog. Filing it as fifty
would have looked thorough and made the backlog unreadable. The commit list
lives inside each task so nothing is lost.

**The recurring theme this week is doors.** Float on Top was built and unusable
because nothing invoked it. The activity state machine works and lives in a
plugin the user has to install. The agent integration will be the same story on
Windows: capability with no way in. Three separate tasks, one pattern — features
here tend to get finished at the mechanism and abandoned at the affordance.
Worth a habit: a feature is not done until you can name the click that reaches
it.

**Still no Mac session, ten days running.** Thirty-five mac-seat tasks are now
queued, up from thirty-one yesterday, and four more were added this week by
this box alone. Every Windows fix that has a Mac half makes that number grow.
Nothing on this box can work it off.
