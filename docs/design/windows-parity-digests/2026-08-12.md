## Commentary

### Yesterday

**A `.html` file finally shows the page instead of its markup.** Open a local
web page in a side pane and you now get the page — its stylesheet, its scripts,
its images — with a save reloading it in place. This is the one that removes the
"start a little web server first" step that everything from a build report to
the dashboard you are reading this on had to do.

**Clicking Reconnect on a rebooted machine brings the window back.** Before, if
the machine at the other end had actually restarted, Reconnect could only fail:
the sessions it wanted were gone. It now opens a fresh shell in every pane and
rebuilds the window in place, so the split layout you arranged survives and only
the contents are new.

**Panes stop dying when the background daemon freezes.** A daemon that crashes
was already recovered; one that stays alive but stops answering was not — and
that left every pane frozen until you quit the app. It now keeps retrying for
about ninety seconds, stands down the moment the old link heals on its own, and
if it genuinely gives up it says so in the pane instead of leaving you guessing.

**Dragging a split divider now moves only that divider.** Previously a drag
could shove neighbouring boundaries along with it, which meant a careful layout
could be undone by one adjustment.

**And the small visible ones:** a bare file path typed into a pane banner is a
clickable link now; a split opened off a browser pane starts in the directory
that window is working in rather than your home folder; Ctrl+W over the machine
chooser closes the chooser instead of the window behind it; and the close
button's X is white on its red hover again.

**Thirty-eight tasks closed. Fifty-seven filed.** The highest closure count so
far — and, for the second day running, most of it was work on the workshop
rather than on the terminal.

### Reflection

**The queue is not broken in a subtle way — it is ignoring priority
outright.** Seventy of the open important tasks carry no position, and a task
with no position sorts *behind* every task that has one. So the head of the
queue is a run of minor test-harness jobs at positions 347–380, and three P0
bugs you reported by hand sat behind them for a full day while twenty-four
harness tasks closed in front of them. This is the third consecutive morning of
hand-sorting the queue to work around it, and today it cost the most: it is one
thing for the loop to work on the least valuable thing available, and another
for it to work past a P0 you filed yourself. **D55** is the standing decision
and it has now earned an answer.

**The workshop is not just outproducing the terminal — it is repeating
itself.** One broken audit (`persistence-flag.ps1`, red at HEAD since some turn
last week) was filed as a NEW task four separate times yesterday, by four
separate turns, each one discovering it fresh and none of them fixing it. That
is the treadmill made visible: the machinery reports a problem, the report
becomes a task, the task sorts behind other harness tasks, and tomorrow the same
machinery reports it again. Four of yesterday's fifty-seven filings were the
same defect. The fix is not more discipline about filing; it is that a red audit
should be *fixed by the turn that finds it*, or not filed.

**Three days of harness work has bought something real, though, and it is worth
saying so.** As of yesterday a test run can no longer report a pass without
having asserted anything, can no longer print failure and exit success, can
photograph a hovered control and the terminal's own pixels without stealing your
screen, and has to declare when it needs your foreground. Those were all real
holes and several had been quietly waving real defects through. The argument is
about *when* to stop, not about whether it was worth doing — and the answer this
morning is: now, until the three P0s and the visible parity gaps are gone.

**Main is still quiet — zero new commits for a second day**, so the intake lag
stays at zero and none of the above is being made worse by drift. The
hundred-and-twenty-six unmapped Mac commits (**T684**) and eighty-one unmapped
shared-core commits (**T716**) are still the honest distance to merging back, and

**Still no Mac session — fourteen days.** Fifty-four tasks are waiting on that

## Feature ideas

Fresh batch; nothing repeated from the previous three days. Say the word on any
of these and it becomes a task.

### UX improvements

- **A command palette that can actually do things** — *High.* One chord opens a
  searchable list of every command, every open pane, every recent directory and
  every saved layout, and running one is a single Enter. Ghoztty already has more
  capability than any menu exposes; right now the CLI is the only complete
  interface to it.
- **Undo the last layout change** — *High.* One chord puts back the pane you just
  closed, the split you just collapsed, or the divider you just dragged. Layout
  is the one thing in a terminal with no undo, and it is the easiest thing to
  destroy by accident.
- **Zoom a pane to fill the window, and back** — *High.* Temporarily blow one
  pane up to the whole window without disturbing the split tree, then drop back.
  With four-way splits now common, reading a long build log means either
  squinting or rearranging.
- **Pick up where a pane left off, in a new window** — *Medium.* Detach a running
  pane into its own window (and re-attach it later) by dragging or by a command.
  The sessions already survive independently of any window; nothing lets you move
  one.
- **Show me what changed while this pane scrolled** — *Medium.* A thin marker in
  the scrollbar for each command boundary and each error line, so a thousand-line
  build log becomes navigable without searching for strings you have to guess.
- **Confirm before closing a pane that is busy** — *Medium.* Closing a pane
  running a long build should ask; closing an idle prompt should not. Today both
  close silently, which makes the close button quietly dangerous.

### Reliability and performance

- **Open the window before anything else is ready** — *Medium.* Paint the frame
  and the first pane immediately and fill in restore, chooser data and daemon
  handshakes behind it, so launching never looks stalled on a cold boot.
- **A pane that is watched, not polled** — *Medium.* The activity state and the
  idle detection currently rest on reading the pane's tail on a timer; deriving
  them from the output stream itself would make them instant, cheaper, and
  correct for programs that redraw without changing.
