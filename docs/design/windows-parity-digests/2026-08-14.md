**The loop was dead for twenty-five hours, and it is worth knowing exactly
why.** The box rebooted at 08:07 yesterday morning — minutes after the daily

### Reflection

**The biggest loss on this project is no longer a bug — it is downtime.** A
twenty-five-hour stop erased more progress than any single defect fixed last
week, and it was caused by a Windows Update reboot, not by anything in the code.
Two mornings out of the last five have opened with "the loop is down". Every
mechanism built to prevent that so far — the lock, the watchdog, the
watchdog's own scheduled reviver — lives inside a signed-in Windows session, and
so does the thing it is protecting. The honest fix is either a revival path that
does not need a logon, or an out-of-band signal that reaches you when the loop
stops, so silence is never the failure mode. Right now silence is the only
failure mode.

**A decision answered after the code ships is a lagging signal.** D43 sat open
from 2026-08-09 to yesterday while T635 through T638 were built on the option it
had not chosen. The board did the right thing — it flagged a one-way door and
kept working under a stated assumption — but nothing stopped the dependent
tasks from stacking on that assumption in the meantime. A cheap change worth
considering: when a decision is marked as a one-way door, the tasks that depend
on its answer stay blocked rather than proceeding under the assumption, and only
the reversible ones carry on.

**The queue is finally honest about what matters, and it is not features.** Now
that priority is read before position, the head of the board is red lanes,
lying diagnostics and one loud purple pill. That is the right shape for a branch
that wants to merge back into main — but it means the visible pace slows while
the machinery gets trustworthy.

**And the distance to main is unchanged for the seventh day.** A hundred and
twenty-six unmapped Mac commits (T684) and eighty-one unmapped shared-core
commits (T716), with no one working either. The Mac seat has now been absent
**sixteen days**, with fifty-plus tasks waiting on it — several of them the
other half of things this box shipped last week.

## Feature ideas

### User-facing

- **Build progress on the taskbar button** (High) — a long build fills the
  Ghoztty taskbar icon like a progress bar and turns red when it fails, so you
  can watch a compile from another window without alt-tabbing to check.
- **An elevated pane looks elevated** (High) — an administrator shell gets
  visibly distinct chrome, so a destructive command can never be typed into the
  wrong pane by accident.
- **Recent projects on the taskbar jump list** (Medium) — right-click the
  taskbar icon for your last few repositories and saved layouts, and open one
  straight into its window, the way every native Windows app offers recent
  files.
- **Open this folder in Explorer or your editor** (Medium) — one action from the
  pane menu takes wherever the shell currently is and opens it in Explorer, VS
  Code, or a new pane, instead of retyping the path.
- **Copy the selection as an image** (Medium) — grab a stack trace or a table
  and paste it into chat or an issue as a rendered picture with the terminal's
  colors intact, not as grey monospace that loses the highlighting.

### Stability and performance

- **Predictive echo on remote panes** (High) — typing into a remote pane shows
  your characters immediately and reconciles when the far side answers, so a
  slow link feels local instead of laggy.
- **Snap groups that survive a restart** (Medium) — a Ghoztty window snapped
  beside a browser comes back as part of that snap group after a reboot, rather
  than floating loose in the middle of the screen.
