## Commentary

### Yesterday

**A reboot brings your windows back.** This was the biggest hole in the
persistence work and it is closed (T975). Restarting the machine used to leave
you with one empty window where a full layout had been; now the panes that were
open come back, with the shells still attached. Two separate defects had to meet
before the symptom appeared, which is why it survived so long: a client that
walked away could kill the session manager's own front door for the life of the
process, and after a reboot every recorded session is dead, so startup spent six
seconds dialling corpses before it would answer anybody. Both are fixed at the
mechanism, both have tests, and the wedge test was proven by putting the bug
back.

**And the pane you get back is the pane you left.** A restored pane now shows a
recent screen instead of the one from the last time a window happened to move
(T922), and the "this session was interrupted" notice reaches the banner above
the pane rather than only the scrollback where it scrolls away (T977). Together
with the reboot fix, the sequence a user actually experiences — restart, log in,
find your work — now works end to end for the first time.

**Nothing printed to a pane is lost to a crash any more.** Scrollback written
since the last save used to die with the session manager (T911); the holder now
keeps it and hands it back. That is the half of persistence you would notice
while reading a build log.

**The feedback composer became a real text editor.** The box you type a report
into was a control we drove by hand; it is now the same browser engine that
renders the page beside it (T934). What that buys, and what none of it had
before: a caret and selection you can trust, word wrap, undo, the clipboard,
drag-and-drop, IME for anyone typing in a language that needs one, and a screen
reader that can read the field. On top of it, a quoted passage looks quoted
again and keeps its identity when you edit it (T935), and an image is one object
— Backspace beside it deletes the whole picture instead of biting a bracket off
and silently dropping it from the report, and pasting or dragging in a picture
is now the browser's own paste (T936).

**A floor run takes as long as its lanes again.** It had been taking three
times longer, and the cause was that the test binaries were spawning themselves
— inside a test build, "launch our own program" resolves to the test runner, so
every holder-backed session launched another copy of the suite, detached and out
of reach of anything that could clean it up (T933). Sixty-one minutes of wall
clock for seventeen minutes of work, now measured back at 1078 seconds for 1076
seconds of lanes.

**And the test suite stopped photographing blurred windows.** Forty screenshot
probes across twenty-two scripts now make the window draw for the camera before
the picture is taken (T941, T942). For the main window this removed a timing
dependency rather than a live flake; for the machine chooser it fixed a real
one — about one capture in twenty was reading the previous frame.

### Today's focus

**T943 heads the queue**: the last twenty-odd screenshot probes still take the
torn photo — the activity monitor, the confirm dialog, and the split-dim
checks. The activity monitor is the one that matters, because its assertions
read table columns, and a half-drawn frame corrupts exactly that kind of
measurement. This finishes the conversion T940 started, after which every pixel
assertion in the suite is measuring the window rather than the compositor.

### Reflection

**Yesterday answered the question this project keeps asking: does a feature
survive the machine turning off?** For weeks the persistence work has been
landing in pieces — holders, adoption, durability, snapshots — each one green,
none of them provably the thing a user cares about. The reboot fix was the
moment the pieces had to work together, and the honest result is that they did
not: two defects that neither unit tests nor any single-feature acceptance
script could see, because both only exist when every session on the box is dead
at once. The lesson is that the end-to-end shape *is* a distinct test subject,
not a sum of its parts, and the queue now reflects that — T974 exists to make
"a pane survives a session-manager restart" a standing assertion rather than a
thing somebody checked by hand on the day.

**The suite has a standing-red problem, and it is worse than a flake.** Two
scripts have been failing one or two assertions on every run for weeks —
`menu-bar` against a row the app renamed months ago (T987), `chooser-selection`
against a selection style T828 replaced (T988) — and the work of the last two
days walked past both without stopping, because a red that is always red stops
reading as a signal. That is the exact condition under which a real regression
hides. Both are now P1. The process change worth making is stronger than fixing
these two: a harness that has been red on its last N runs should be *louder*
than one that just went red, not quieter, and nothing in the guard model
currently expresses that.

**M1 is a category, not a target — and it is time to say so or fix it.**
Yesterday's reflection flagged this and the numbers have not moved: 189 of 248
closed today against 182 of 237 yesterday, which is seven closed and eleven
added. The denominator is not padded with junk — every promotion is genuinely
user-facing — but a milestone that admits members every day cannot converge by
construction. The concrete proposal for tomorrow's triage: **freeze M1's
membership at the end of this week** and route everything filed after that into
M2, so the remaining number is a countdown rather than a running total. The
existing rule already forbids demoting a task to make the number move; a freeze
date is the other half of that discipline.

**The composer rewrite is the model for how a translation should go.** D43 was
answered months ago and T635 shipped the opposite of the answer while the
decision sat open; T934 finally built what the decision said. What made it work
was not the WebView2 — it was inverting where truth lives (the page owns the
document, native keeps a snapshot) rather than emulating the old control's
question-and-answer shape in a place that cannot answer synchronously. Every
remaining Mac-to-Windows translation on the board has that same tell: the ones
that go badly are the ones where we kept the Mac mechanism's *shape* and
swapped its parts.

### Decisions

**Two open, both still yours, both unchanged since yesterday.**

- **D80 — should Ghoztty start absorbing upstream Ghostty's last three months
  of terminal improvements, in stages?** Recommendation is yes, staged. The
  cost is that one stage moves the whole app to a new Zig toolchain and pauses
  Windows feature work while it lands. The fork is ~764 commits behind and the
  gap grows by roughly 250 a month, so the price of waiting is the only thing
  that changes.
- **D79 — when Ghoztty is already running and you start it again, should the
  second copy join the first?** Assumed no; the second launch is its own app
  and no longer steals the first one's terminals. Joining would match Mac and
  Windows Terminal, at the cost of not being able to run two builds side by
  side, which is how this project is developed.

**And the physical ask is still open**: the T443/T857 experiment needs the
elevated Turbo-Boost commands run from the pane banner whenever you are at the
box. The boost-off arm has still not been applied.

## Feature ideas

### User-facing

- **Pick up where the crash left off** (High) — after an unexpected exit, the
  first window offers "restore what was open" with a preview of the layout,
  instead of restoring silently or not at all. You decide, and you can see what
  you are deciding about.
- **A scrollback you can leave and come back to** (High) — mark a spot in a
  pane's output and return to it later by name, across restarts. Long build and
  test logs are read in passes, and every pass currently starts by scrolling.
- **Compare two panes side by side** (High) — pick two panes and get a diff
  view of their output, so "why did this box fail and that one pass" is a
  glance rather than two windows and a scroll wheel.
- **Type into the terminal with the composer's editing** (Medium) — the
  multi-line editing the feedback box just got (real caret, undo, wrap, IME)
  offered as an optional input line for long commands, so a 300-character
  `docker run` is editable rather than a one-shot line.
- **Name a window after what it is for, and have it stick** (Medium) — a window
  you titled keeps that title through a restart, a restore, and a shell that
  tries to rename it. Today the name is whoever spoke last.
- **A pane that tells you what it is waiting on** (Medium) — when nothing has
  printed for a while, the pane says whether the program is working, blocked on
  input, or blocked on the network, instead of leaving you to guess from a
  cursor.

### Stability and performance

- **Never a red suite as background noise** (Medium) — the app's own quality
  signal should distinguish "just broke" from "has been broken for weeks", so a
  new failure is loud even in a suite carrying old ones. Users feel this as
  regressions that ship.
- **Open the window before the work** (Medium) — the first frame should appear
  immediately and fill in as sessions attach, rather than waiting on the
  session manager. Every restore-path bug this week presented to the user as a
  slow or empty window.
