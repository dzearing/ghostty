## Commentary

### Yesterday

Yesterday was the day the install epic stopped being a plan and started being
something a person walked into and broke. That is the highest-value kind of day.

**Every hard FAIL from the clean-machine walk got fixed the same day.**
Installing over a running Ghoztty now has a graceful path (**T1204**) instead of
saying "configuring" and vanishing, and it no longer inherits an unrelated
Windows Update pending-reboot flag and presents it as its own demand. "Which
build am I running?" now has one answer instead of four (**T1205**): About
reports the process's own identity, the file's mtime appears only inside a
clearly-labelled stale-build paragraph, the app raises a restart offer on its
own when a newer build is on disk, and Apps & Features shows `1.35.0` instead of
the `26.8.3108` sequencing number. **T1207** closed the nastiest one nobody had
hit yet - the installer could terminate the session agent and its PTY holders,
taking every restored session with it.

Then a decision changed the shape of the week. **D85** asked whether the user's
terminal should keep being swapped every morning by a repo build, or update
itself from published releases like any other app. The user chose **published
only** - explicitly *not* the recommended option, and the better call: fewer
surprise restarts, and a version that always describes bytes somebody actually
released. **T1218** executed it, and executed it harder than specified: rather
than changing a default, the user's install is now **unwritable by repo
tooling**. `install-ownership.ps1` holds the rule, `upgrade-ghoztty-windows.ps1`
and `launch-upgrade.ps1` refuse a user-install target outright, `morning-refresh.ps1`
is deleted, and go.md step 6.5 now reads "publish, do not swap". A default drifts
back; a refusal does not.

The rest of the day was a long tail of things the walk exposed indirectly: dev
builds writing machine-wide registrations the user's shell obeys (**T1151**),
soak runs leaving autostart entries behind (**T1168**), the loop pushing every
turn and never looking at CI (**T1219**), sessions listed as running forever
after their shell exited (**T1162**), and four viewer-pane defects (**T1159**,
**T1183**, **T1184**, **T1185**). Overnight it also closed **T1191** - a win32
module's unit tests could sit un-run forever because nothing checked the lane's
hand-written import list, which is exactly how T1205's tests went green while
never executing.

**49 commits** since the last digest. Fork CI on the branch head is **green**.

### Today's focus

**T1179's second half is the whole story, and it is waiting on the user.**
`win-v1.36.0` is published and the website is serving it. The test is
deliberately the case that failed yesterday: **install it over a running
Ghoztty, without closing anything first.** That exercises T1204's Restart
Manager path directly. What should happen: a Files In Use dialog naming Ghoztty,
an offer to close and restart it, no reboot demand, and 1.36.0 agreeing across
About, `--version` and Apps & Features afterwards.

One criterion is still **owed rather than failed**: nobody has yet observed
whether the installer launches Ghoztty by itself when it finishes (**T1176**).
The 1.35.0 round had a reboot in the middle, so the moment went unwatched. Watch
for it this time.

Behind the gate: **T1203** (the MSI is unsigned, so SmartScreen greets every new
user with "Unknown publisher" - the last thing between the download page and
"it just works"), **T1220** (publish at the end of a day's work, which is what
makes "same-day fixes still arrive same-day" true now that the swap is gone),
and **T1221** (the Desktop portable and the network share still receive
unpublished repo builds - the same defect D85 just settled, in two other
places).

Open: **D86** - when a viewer pane gets too narrow for its address bar, should
the box shrink or disappear? Shipped disappearing; not blocking.

### Reflection

Three P0s remain in the whole tracker and **all three are stale**: two need the
Mac seat (T30, T330) and one is the intermittent agent segfault (T443). Nothing
P0 is blocked on the Windows seat. That is worth saying plainly, because it
means the queue's real shape now is 54 P1s and a very long P2 tail - and the
merge-back is gated on a human walk, not on engineering.

The lesson from yesterday holds and is worth restating: **the last mile is a
different discipline than the feature work.** Every defect the walk found lived
at a seam nobody owned - the installer meeting a running process, the version
meeting three surfaces, the download meeting SmartScreen, the swap meeting the
updater. None were findable from inside the loop. All were findable by one
person spending ten minutes installing the thing.

D85 is the sharpest example. The loop built a perfectly good "make the morning
swap honest" and recommended it. The user chose to delete the mechanism instead.
The loop optimised the thing that existed; the user asked whether it should
exist. That is the question a loop is structurally bad at asking about its own
work, and it is the argument for keeping the human walk in the cycle rather than
treating it as a one-time gate.

One process note against ourselves: **this digest was 19 minutes late and was
written by the controller, not the loop.** go.md step 0.5 puts it at 5am; the
loop finished T1193 at 04:48 and went straight into T1194 without it. A step
that only runs when someone notices is not a step.
