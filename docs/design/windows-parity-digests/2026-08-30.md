### Today's focus

The queue answers T1175 — retire the standalone agent MSI from the website, the
relay's download endpoints, `install.ps1`, `relay/deploy/msi` and CI. It is the
right first move because it is subtraction: every other install task gets
easier once there is only one artifact to reason about, and the failure it
removes ("I installed it and got half a product") is one no error dialog can
apologise for.

### Reflection

**The gap between "shipped" and "installed" is the last big one.** Nearly
everything this project has built for four months is measured on a box where
the build is already there. The install epic is the first time the queue is
pointed at the thirty seconds before any of that exists — and it is the only
stretch of the experience with no telemetry, no acceptance script, and until
today, no tasks. That the failure mode is *silence* (no window, no dialog)
rather than an error is the tell: nobody was watching that path at all.

**Six days of quiet cost nothing, and that is itself worth noticing.** The
tracker, the guard stamps, the watermark and the lock all came back exactly
where they were left; the claim this morning reported a clean tree, a clean
push state, ninety-odd current guards, and a box that had signed itself back in
after a reboot without anyone at the keyboard. The machinery designed for
crash recovery turns out to handle *deliberate absence* just as well. The
process change worth making is to stop treating a dark loop as an incident to
diagnose — the log entries from previous outages read as post-mortems, and this
one needed none.

**Main is drifting toward the viewer, and so are we.** All three tasks filed by
today's intake are viewer work, as were all three on 2026-08-22. The viewer
pane has quietly become the second product inside this terminal, and it is
worth asking whether it deserves its own acceptance suite and its own section
in the docs routing table rather than living as a scattering of
`viewer-*` harnesses.

**One idea closed the loop from tab to shipped feature.** "Find in the viewer
pane (Ctrl+F for rendered docs, diffs and pages)" was suggested here on
2026-08-22 and main shipped it on 2026-08-26; it is now T1184. That is the
first time an entry from this tab has come back as an intake task, and it is a
reason to keep writing them.

## Feature ideas

### User-facing

- **Print or share what a viewer pane is showing** — *High.* A rendered
  README, a diff or a report is often the thing you want to hand someone, and
  today the only way out is a screenshot. Export the pane to PDF or a
  self-contained HTML file from its own toolbar.
- **A viewer pane that keeps your place when the file changes** — *High.* Live
  reload is the reason to keep a doc open beside your work, and every save
  throws you back to the top. Restore the scroll position, and flag what
  changed since you last looked.
- **Jump from a diff line into your editor at that line** — *High.* You read
  the change in the pane and then hunt for the file by hand. Click the line
  number, land in the editor on it.
- **An outline for code files, like markdown gets** — *Medium.* A code pane
  shows a 3000-line file with no way to navigate it; the contents card that
  markdown panes already have, filled with functions and types, makes the
  viewer usable for real source.
- **Fold enormous output automatically** — *Medium.* One `npm install` buries
  everything you were reading. Collapse a block over a few hundred lines into a
  single row you can expand, with the exit status on it.
- **A shortlist of docs you keep opening in side panes** — *Medium.* The same
  four files get opened every day by hand. Pin them, and open one with a key.
- **Zoom the viewer's content, and remember it per pane** — *Medium.* Rendered
  text sits at one size regardless of the monitor. Ctrl +/− should work there
  the way it works in a browser, and stick.

### Stability

- **A viewer pane that survives its renderer crashing** — *Medium.* If the web
  view host dies the pane goes white and stays white. Show a reload card that
  keeps the address and the history, so a crash costs a click rather than the
  pane.
