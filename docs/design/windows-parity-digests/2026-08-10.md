## Commentary

### Yesterday

**The frozen-windows bug is fixed, and it turned out to be one wrong number.**
This was the one worth having: reopen the app, your windows come back looking
perfect, and then nothing you type reaches them. It had survived a full day of
hunting on Friday without reproducing once. The cause was that a restored pane
asked the background daemon to resume its output "from where I left off" using a
bookmark into a stream of bytes that no longer existed — so the daemon had
nowhere to start, and the pane sat there showing a photograph of itself. It now
reproduces on demand and is fixed.

**And the reason it survived a whole day of green tests is now fixed too.** Every
test that restored a window checked what was on the screen — which a dead pane
passes perfectly, because a picture of a working terminal is what it *is*. Every
one of those tests now types into the pane it restored and demands an answer
back. Eleven scripts, and a switch that makes all of them go red on purpose so
each one could be proved to have teeth.

**The Windows feedback button is finished.** You can now paste a picture into a
report and see it as a thumbnail; the `+` button takes a screenshot with a
region you drag out yourself (Windows' own snipping tools publish through the
clipboard, which would have clobbered whatever you had copied — so Ghoztty draws
its own); and reports written with accents or emoji put quotes and pictures
exactly where you put them, instead of drifting a few characters left. The only
piece still missing from the Mac version is the long-lived draft folder.

**Also, in ordinary parity:** a pane opened with a command now lands at a live
shell instead of a dead one; a pane the daemon refuses says why in 150ms instead
of blaming a timeout ten seconds later; a website's pop-up window becomes a real
Ghoztty window that the page can still talk to and close; dropping a pane out of
a rearranged layout no longer leaves it running where nothing can reach it; and
the terminal fetches its own update in the morning without interrupting you.

**Twenty-seven tasks closed. Forty-five filed.** The biggest closing day so far.

### Today's focus

**T663 — the morning self-update types its own restart instruction back into the
session, and some characters go missing on the way.** Since yesterday, the
terminal updates itself the first time the day's work is pushed after 5am, then
restarts this session and tells it to carry on. Three times in a row the
instruction arrived mangled. That means the feature you got yesterday — a client
that stays current on its own — currently has a one-in-one chance of quietly
stopping the work that produces the updates. It goes first.

Behind it: a text argument ending in a Windows line ending submits twice (it can
run a command you never asked for), and `+send-keys` can silently lose the first
character of a pasted prompt.

**The queue needed re-sorting by hand again, and that is now a filed problem
rather than a morning chore.** Yesterday five severe tasks had to be pulled to
the front because they had no position number and the sorter puts those last.
All five are closed, and this morning the exact same thing had happened one level
down: the top of the queue was a run of minor test-harness jobs while a hundred
and seven more important tasks sat unreachable behind them. Fourteen were pulled
forward today. **D55** asks whether the sorter should read importance before it
reads the hand-written position, so nobody has to do this a third time.

### Reflection

**Two mornings in a row, the most valuable thing in the triage was not about the
code.** Yesterday's reflection said the tracker's rules are "enforced by
convention and re-derived by hand each morning, when they could be enforced by
the tool at the moment of writing." Today that prediction came true in the most
literal way available: the identical defect, one priority tier down, found the
same way, fixed the same way. The difference is that this time it was filed as a
tool change (T696) with the call written up (D55) instead of being re-done
tomorrow. That is the pattern worth generalising — when a morning pass finds
something, the question to ask is not "what do I fix" but "what would have
noticed this without me".

**"The test could not tell a live thing from a picture of one" is now a theme,
not an incident.** It has appeared three times this month: a restored pane that
was a screenshot, a banner that was a picture of a banner, a daemon reporting a
child as alive while it was wired to nothing. All three passed every assertion
put to them. The new rule — a restore test must *type* — closes this class for
restores specifically, but the general shape is worth naming: an assertion that
reads state is weaker than one that provokes a response. It might be worth a
sweep asking which other tests only ever look.

**A third of yesterday's work was the workshop, not the product.** The morning
refresh, the restart chord, the test sandbox getting its own daemon, the loop
lock, the persistence flags, the parity gate, the evidence capture — nine of
twenty-seven closures were about the machinery that does the work rather than the
terminal you use. That was the right call yesterday, because the machinery was
actively lying (a whole suite green over a dead pane). But it is not the right
ratio to hold, and the next few days should tilt back toward things you can see.

**Still no Mac session — twelve days.** Forty-five tasks are waiting on that
seat, twenty of them user-facing. Several are the other half of something this
box has already finished, which means those features currently work in one
direction only.

**And the number that actually measures the goal is 126.** That is how many Mac
commits have been merged into this branch without ever being mapped to a Windows
work item (T684). The daily intake gate now catches new ones — today it caught
one and filed it — but the backlog behind it predates the gate. Until that number
comes down, "how far from merging back" has no honest answer.

## Feature ideas

Fresh batch, nothing repeated from yesterday's. Say the word on any of these and
it becomes a task.

### UX improvements

- **Clickable paths in terminal output** — *High.* A file path in a stack trace,
  a compiler error, or `git status` becomes clickable: click opens it in a side
  pane at the right line. Right now the most common thing you do with terminal
  output is copy a path out of it by hand.
- **Command blocks** — *High.* The terminal learns where each command started and
  ended, so you can jump to the previous command, fold a noisy one away, and copy
  exactly one command's output with a single action — no more dragging a
  selection across a screenful of build log.
- **Select text, then act on it** — *High.* The little Quote/Copy toolbar that
  already appears when you select text in a viewer pane, brought to terminal
  panes — plus "open this path", "search this error", "send to that pane". One
  idiom, everywhere in the app.
- **Open this pane's output as a document** — *High.* One action turns a pane's
  scrollback into a searchable, syntax-highlighted viewer pane you can scroll and
  search freely while the terminal keeps running underneath. Composes two things
  Ghoztty already has.
- **Search every pane at once** — *Medium.* "Where did that error print?" across
  all open panes and windows, with results grouped by pane and click-to-jump.
  Today you have to remember which pane it was.
- **Drop a file onto a pane** — *Medium.* Dragging a file from Explorer into a
  pane types its quoted path at the caret. Small, and used constantly by anyone
  who works with files that are not in the current directory.
- **Dim the panes you are not typing in** — *Medium.* A gentle wash over inactive
  panes so the focused one is unmistakable at a glance. In a four-pane layout the
  question "which one am I typing into" currently costs a second every time.

### Stability

- **A pane whose shell died stays readable** — *Medium.* When a shell crashes or
  exits, the pane keeps its output and offers a one-key restart in place, instead
  of vanishing and taking the error message you needed with it.
