## Commentary

### Yesterday

**Windows got the feedback button — the whole thing, in one day.** This was the
big one. On a Mac, when you have a doc or a local web page open in a side pane,
you can click a button, type what is wrong, paste a screenshot, quote the exact
sentence you are pointing at, and it files a report into the checkout the page
belongs to. None of that existed on Windows yesterday morning. All of it exists
now:

- The pane **works out which checkout it is showing** — from the file it is
  displaying, or, for a `localhost:3000` dev server, by finding the process
  listening on that port and asking where it is running from. Windows has no
  API for the last part, so it reads it out of the process directly rather than
  guessing from a command line.
- The composer is **a real text box**, not a hand-rolled one: caret, selection,
  word wrap, undo, clipboard and international input all come from Windows.
- **Pasting a picture attaches it.** A screenshot from a browser is copied byte
  for byte; anything else is normalised through the OS and re-encoded, with the
  encoder written from scratch so nothing new had to be vendored.
- **Selecting text and clicking Quote** puts the passage into the report as a
  proper quoted block, carrying enough context that whoever reads it can find
  what you were looking at.
- **Send writes a real report** — a self-contained folder that appears complete
  or not at all, never half-written.

That is six tasks and about ten hours, and it takes the largest remaining
Windows-only hole in the viewer down to a short list of extras: a thumbnail
strip, screenshot capture behind the `+` button, and a draft folder.

**Before that, the remote-machines work finished its week.** A dropped remote
window now re-dials itself and takes its sessions back; its titlebar says
whether the connection is alive; a Mac's windows can be rebuilt on a Windows
machine and vice versa; the Activity Monitor stopped freezing, stopped losing
your scroll position, and keeps measuring while its Kill dialog is open. And
Ghoztty now answers CLI commands while it is still restoring your windows —
before, the first second and a half after launch silently swallowed them.

Twenty-one tasks closed. Forty-four new ones filed.

### Today's focus

**The queue was pointing at the wrong thing, and that has been fixed.** The
head of the list this morning was a thumbnail strip for the feedback composer.
Behind it, untouched, sat nine P0s — including one from three days ago where
reopening the app restores your windows as *dead pictures*: they paint
correctly, and then nothing you type reaches them. The app logs success at
every step while doing it.

The reason is mechanical rather than anything anyone decided: the queue sorts
by an explicit position number, and every one of those P0s had none, which the
sorter treats as "goes last". So the most severe defects in the tracker were
structurally unreachable. Five of them now have positions at the front, and
today starts on the frozen-windows one. That judgement is filed as **D49** in
case you want it back the other way.

### Reflection

**Two duplicate pairs surfaced in a single triage, which is a first.** The same
flaky test was written up three separate times on three separate days (T615,
T643, T649), and the same 09:20 incident from Tuesday was written up twice with
the same verbatim quote in both (T529, T532). Nobody was careless — the filing
command has no lookup of any kind, so an agent that has just watched a lane go
red has no cheap way to ask "is this known?". Five task files for two defects.
That is now filed as its own piece of work: warn on a similar title before
writing the file, never block.

**The deeper version of that problem is the one worth naming.** This project
files a lot — forty-four tasks yesterday against twenty-one closed — and every
mechanism for keeping the backlog honest is a *review* mechanism that runs once
a day, after the fact. The duplicate check, the priority triage, the M1 call:
all of it is cleanup. Yesterday's dedup found five files for two problems only
because someone read forty-four titles in a row. That does not scale, and it is
the second morning in a row where the most valuable thing in the triage was
something structural rather than something about the code.

**Which connects to the ordering bug.** A queue where `priority: P0` has no
effect on what gets worked is not a queue with a bug in it — it is a queue
whose two ordering fields were never reconciled, and nobody noticed for a week
because the thing it starved was the thing nobody was looking at. The pattern
across both findings is the same: the tracker's *invariants* are enforced by
convention and re-derived by hand each morning, when they could be enforced by
the tool at the moment of writing. `validate` already exists and passes 681
tasks; it checks structure, not sense.

**The feedback arc is the counter-example, and worth learning from.** Six tasks,
filed as a deliberate split with dependencies wired in order, each one landing
in a couple of hours with its own acceptance script. No re-planning between
them, no surprises that turned into new tasks mid-arc. The difference from the
usual shape is that somebody spent a task *decomposing* before any of it was
built. That is the third time this month that pattern has paid, and it might be
worth making the default for anything above a few hours rather than something
that happens when the work looks big enough to warrant it.

**Still no Mac session, eleven days running.** Thirty-nine mac-seat tasks are
queued, and two of yesterday's — a Mac that cannot read a Windows layout, and
a close-confirmation gap — are halves of features this box has already
finished. Every one of those is a feature that ships broken in one direction.

## Feature ideas

### UX improvements

- **Jump to any pane** — *High.* One hotkey opens a fuzzy switcher over every
  open pane by title, running command, and directory — type "log", land in
  the pane tailing the log. With many panes across windows, finding the right
  one is currently a visual hunt.
- **Reopen closed tab** — *High.* Ctrl+Shift+T brings back the pane you just
  closed, scrollback intact — the browser habit everyone already has in their
  fingers. Session persistence already keeps the process alive briefly; this
  gives that window a door.
- **Smart paste guard** — *High.* Pasting multiple lines into a shell prompt
  shows a quick preview and offers to strip leading `$`/`>` prompt markers
  from copied docs — ending the classic "pasted a tutorial, ran six garbage
  commands" accident.
- **Layout presets** — *High.* Save the current split arrangement as a named
  preset ("dev": editor + server + logs) and spawn it with one action, each
  pane with its remembered directory and command.
- **Watch rules** — *High.* "Tell me when this pane goes quiet" / "when it
  prints ERROR" as a right-click on any pane — a toast fires when it happens.
  The machinery exists for agents; this hands it to the human.
- **Broadcast typing** — *Medium.* Type into several selected panes at once
  (with unmistakable chrome while active) — the classic multi-server
  administration move.
- **Keyboard copy mode** — *Medium.* A mode where arrows/vim keys select text
  precisely without touching the mouse — terminal text selection by hand is
  still the fiddliest thing power users do daily.
- **Scrollback search with a minimap** — *Medium.* Search the whole
  scrollback with match markers on a slim strip along the pane edge; click a
  marker to jump. Today finding "where did the build fail" is scroll-and-squint.

### Performance

- **Instant first window** — *Medium.* A pre-warmed background process makes
  the first window of the day appear in under 100ms instead of a cold start —
  the single most-felt speed moment in a terminal's whole day.
