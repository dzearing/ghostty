## Commentary

### Yesterday

**Typing into a pane got honest.** Four separate defects in how text reaches a
terminal were closed in one morning: a message ending in a Windows line break
submitted twice (so a chat pane got your text and then an empty second turn); a
multi-line paste arrived as a run of Enter presses instead of line breaks, which
turned two typed lines into two executed commands; the first character of a
pasted prompt could vanish; and a WSL pane asked to run a command looked for a
program with the whole command line as its name, failed, and died. All four are
fixed, and the last two are now measured byte-for-byte on the wire rather than
judged by looking at the screen.

**The self-update that restarts this work no longer has to be trusted.**
Yesterday's worry was that the morning refresh types its own "carry on"
instruction back into the session and three times in a row it seemed to arrive
mangled. It was arriving fine — the *check* on it was reading an empty screen.
The instruction was never broken; the thing watching it was.

**A pane that cannot get its session back now says why.** After a reboot, an
upgrade, or picking a session out of the chooser, a pane that failed to rejoin
used to print a sentence about "exhausting a system resource", which is true of
no failure a person can act on. It now names the actual reason — the session is
gone, it died, someone else has it — and does so in milliseconds instead of
after a ten-second wait.

**You can ask which build of the background terminal daemon is running.** That
daemon deliberately outlives the app, so it is routinely older than everything
around it, and until now the only place that comparison appeared was a log line
on a machine that had already moved on. `ghoztty +sessions --agent` prints the
running build, the bundled one, how far behind it is, and what will happen next.

**And a link can now raise a window.** `ghoztty://focus/<name>` in a document, a
banner, or a web page brings that terminal to the front — the Windows half of
something main shipped the day before, filed and closed inside 24 hours.

**Plus the small visible things:** a hovered link in a background window can no
longer park its address bubble over whatever app you are actually using, the
split divider's resize arrow points the right way, closing a split no longer
leaks a window handle every time, two keyboard shortcuts work again while a
viewer pane has focus, the screenshot picker can be driven entirely from the
keyboard, and the tab strip stops dancing when a shell renames itself.

**Twenty-nine tasks closed. Forty-four filed.** Another record day for closures.

### Today's focus

**T666 — reconnect to the same session twice and the older scrollback is gone.**
Restore a window, close the app, restore it again, and the second time the pane
comes back holding only its last screen. Session persistence is the feature this
whole branch leans on hardest, and "your history survives, but only once" is the
kind of half-guarantee that is worse than none — you stop being able to trust
what a restored pane shows you. It goes first.

Behind it: the app crashes if you close a remote window while its Activity
Monitor panel is open; running `ghoztty` from an existing terminal opens in your
home folder instead of the directory you were standing in; and a `.html` file
opened in a viewer pane shows its source instead of the page, which is why the
dashboard you are reading this on has to be served over a local web server
rather than just opened.

### Reflection

**The workshop is now the single biggest source of new work, and that is the
number to watch.** Of the forty-four tasks filed yesterday, about twenty are
about the test harness and the tooling rather than the terminal. Half of
yesterday's closures were too. That was defensible last week, when the machinery
was actively lying — a whole suite passing over a dead pane — but it has now run
for three days, and a workshop that files work faster than it finishes it is a
treadmill, not an investment. Two of yesterday's own filings (**T725**, **T732**)
say the same thing from the inside: the harness rules only run when somebody
remembers to run them, so each new script meets them one red run at a time. The
proposal is not to stop doing this work but to *batch* it — give harness tasks
one slot rather than letting them interleave with everything a user can see.

**Three mornings, the same manual chore, and the fix for it is still sitting
open.** Sixty-one important tasks carry no position in the queue, so they sort
behind a run of minor harness jobs; twelve had to be pulled to the front by hand
again today, exactly as on the two previous mornings. **D55** asks whether the
queue should read importance before position. Every day it stays open costs the
same fifteen minutes and risks the same thing: the loop quietly working on the
least valuable thing available.

**The good news is that the intake gate is holding.** Main added one commit
yesterday, it was release notes, the sweep confirmed nothing was owed, and the
lag is zero commits for the third day running. The daily-intake experiment from
four days ago has done what it was asked to do — new work from main is in the
queue within hours now, not weeks.

**The debt behind that gate is still the honest measure of "how far from
merging back".** A hundred and twenty-six merged Mac commits were never mapped
to any Windows work item (**T684**), and yesterday's widened sweep found
**eighty-one more** in the shared core (**T716**, promoted into the milestone
today). That is the number that has to come down before the merge-back question
has an answer, and nothing is working on it yet.

**Still no Mac session — thirteen days.** Forty-nine tasks are waiting on that
seat. Several are the second half of something this box has already shipped,
which means those features currently exist in one direction only.

## Feature ideas

Fresh batch, nothing repeated from the previous two days. Say the word on any of
these and it becomes a task.

### UX improvements

- **Give every project its own window identity** — *High.* A window picks up a
  color accent and a short badge from the repository or worktree it was opened
  in, so six windows across six worktrees stop looking identical. Right now the
  only way to tell them apart is to read the title, and the titles differ by one
  word.
- **Drag a tab where you want it** — *High.* Reorder tabs by dragging, tear one
  out into its own window, or drop it into another window's strip. The tab strip
  is now good enough that not being able to move a tab is conspicuous.
- **Tell me when this finishes** — *High.* Mark a pane as "notify me", and when
  its long build or test run ends you get a Windows notification and a badge on
  the tab, with the exit status. The terminal already knows when a pane goes
  from busy to idle; nothing surfaces it.
- **What happened while I was away** — *High.* Come back to a window after a
  while and a banner summarizes it: which panes printed something, which
  finished, which failed. Composes the activity states and the banner overlay
  that already exist.
- **Tab titles that name what is actually running** — *High.* A tab reads `zig
  build · running` or `git push · failed (1)` instead of `cmd.exe`, so the strip
  becomes a status board you can read from across the room.
- **Say which machine and shell a pane is on** — *Medium.* A small badge for
  WSL / PowerShell / cmd / a remote host. With remote panes and four shell
  flavors in play, "which world am I typing into" is a real question with no
  visible answer today.
- **Copy output as markdown** — *Medium.* Select terminal output and copy it as
  a fenced code block with the command that produced it, ready to paste into a
  pull request or an issue. Today that is three manual edits every time.

### Capacity

- **Keep hours of scrollback without holding it in memory** — *Medium.* Spill
  older scrollback to disk per pane, so a pane left running for a day keeps a
  full day of history and a window with twelve panes does not pay for it in RAM.
  The background daemon already snapshots output rings; this is the same idea
  pointed at the user's history instead of at restore.
