## Commentary

### Yesterday

**Viewer panes stopped being a preview and became a feature.** Nine separate
pieces landed in one day, and together they are the difference between "a
pane that can show a file" and something you would actually keep open:

- A **navigation bar** slides in when you hover the top of the pane — back,
  forward, reload, home, and an address field you can type into. It crosses
  the file/web line in both directions.
- Markdown documents got a **table of contents** card that follows you as you
  scroll, sits in a gutter on a wide pane and slides in as an overlay on a
  narrow one, and can be dragged wider.
- **Links now go somewhere sensible**: a web link opens your browser, a
  relative doc link opens another pane, anything else opens in its own app.
- The **command palette** can open a file, a URL, or a blank browser pane, so
  you no longer need the CLI to get one.
- **The keyboard works inside a viewer**: app chords pass through, Ctrl+R
  reloads, Ctrl+D/Ctrl+L reach the address bar, Ctrl+Plus/Minus/0 zoom the
  page — and each one hands the key back to the shell the moment you focus a
  terminal again.
- **Select-and-copy** works on every page now, not just the bundled markdown
  one.
- Unfocused viewer panes **dim** like terminal panes do, and a viewer finally
  draws a real preview tile in the window switcher instead of a blank card.

**Session persistence got quieter and more honest.** The restart notice now
names the command that was actually running rather than the shell that hosted
it; `+sessions` distinguishes a session that can be revived from one that is
genuinely gone; closing a session no longer makes the caller wait on the
teardown; and a detached process now inherits *your* environment instead of
the daemon's — a subtle one that would have produced very confusing bugs
later.

**Chrome fixes you would notice**: a pinned window title is visible again when
tabs share the caption row, a tab now owns its full height so the resize edge
stops stealing clicks along the top of it, hovering a tab shows that pane's
working directory, and starting a process from the Activity Monitor no longer
flashes a console window.

**Robustness**: a crash immediately after resizing a window can no longer
restore the old size on next launch, and a whole class of "action with no
payload" calls stopped handing the UI layer uninitialized bytes.

Thirty-six tasks closed in twenty-four hours; forty-five were filed.

### Reflection

**The intake number is the story today: 36 closed, 45 filed.** Yesterday was
the most productive day of the effort and the backlog still grew. That is not
a failure — most of those 45 came *out of* the work (a viewer feature lands,
its rough edges get filed honestly) — but it is proof that closing faster
will never be the thing that converges this. The M1 cutline is doing its job
precisely because it refuses to absorb them.

**The Mac backlog is now the whole risk.** `next` skipped **31** mac-seat
tasks this morning, up from 22 yesterday. Every day this box works, it files
more Mac halves — yesterday alone added five. This is compounding in the
wrong direction, and no amount of Windows throughput fixes it. Starting a Mac
session remains the single highest-leverage act available.

**A process gap worth naming: nothing here ever *plays with* what it built.**
The viewer got nine tasks' worth of features yesterday, each validated by its
own script, and the first time anyone opened a pane and simply used it for a
while would be… you. Scripted acceptance proves a claim; it does not notice
that a carousel is in the wrong order or that a tooltip kept its old colors —
both of which were caught only because a human-ish pass happened to look.
Worth considering a standing "sit with the feature for ten minutes" step
after any user-visible arc closes, filed as its own task rather than left to
chance.

**Merge-back groundwork still has no owner** — third day running. The
divergence inventory against upstream ghostty and the Claude-isms sweep (your
D11 directive) are still digest-only ideas. I have stopped promising to file
them and will treat that as a decision for you: they are real work that
competes with parity, and I keep deferring them because parity is more
legible.
