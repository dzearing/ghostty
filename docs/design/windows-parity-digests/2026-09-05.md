### Reflection

**Yesterday was the first day in a while where the work was mostly *feel* rather
than *function*.** Splitter latency, banner flicker, a card that slides, a header
made of glass. None of that closes a parity gap on paper, and all of it is what
the difference between the two builds actually feels like in the hand. Worth
noticing that this only became possible because the correctness backlog ran dry
on this seat — the P2 band is where the product gets good, not where it gets
padded.

**The tooling fixes have a common shape and it is worth naming.** T451, T453,
T436, T527 are all the same defect: *a failure reported as the wrong failure.* A
compiler crash read as a test failure. An out-of-memory box read as a red lane. A
dead process read as a timeout. Each one cost a turn of chasing the wrong thing
before somebody fixed the reporting. That is now four instances in a week, which
suggests a standing rule rather than four fixes: **every failure path in the
harness should name its own cause, and a path that can only say "it failed" is a
defect even while everything is green.** A sweep for the remaining ones would
probably pay for itself twice.

**The release cadence question from yesterday is now answerable.** Six releases
in sixteen hours, twelve in three days. Nothing has gone wrong with it — but the
version number now increments faster than anyone reads release notes, and a user
report arriving against `win-v1.36.9` tells you almost nothing about what the
reporter had. Two cheap things would fix that without slowing delivery: name the
tasks each release carries in its notes (the data is already in the commits), and
let the update notification say what changed rather than only that something did.

**And the blocked-on-user list still has no light on it.** Yesterday's digest
proposed a health-line field for *"N P0s blocked on the user, oldest X days"*.
That has not been filed, and it is exactly the kind of thing this tab keeps
re-noticing instead of turning into work. Three of yesterday's most valuable
closures came out of digest reasoning; the ones that stay in prose here do not
count.

## Feature ideas

### User-facing

- **Run this project's scripts without remembering them** — *High.* Every repo
  has a handful of commands worth running and they live in `package.json`, a
  `justfile`, or a Makefile that you go and read. Let the palette offer the ones
  it finds in the pane's directory, so the common commands of the project you are
  standing in are two keys away.
- **Scrollback that survives a restart** — *High.* Persistent sessions come back
  after a reboot with the shell intact and the history above the prompt gone,
  which is the half you wanted. Keeping a bounded amount of each session's output
  on disk would make "reboot" and "close the lid" stop being the same thing as
  "lose the morning".
- **Know which machine you are about to type into** — *High.* A remote or WSL
  pane looks like a local one, and the destructive command you meant for your own
  box reads identically in both. Marking those panes clearly and confirming
  before a genuinely dangerous command runs in one turns a category of accident
  into a keystroke.
- **Do not close a window that is still working** — *Medium.* Closing a window
  with a build, a deploy or a long test still running kills it silently. A
  confirmation that names what is running — and offers to keep the session alive
  instead — is the difference between a misclick and an afternoon.
- **The tab knows which branch you are on** — *Medium.* Tab titles name the
  directory and the running command; the thing you actually need before you type
  is which branch it is and whether it is dirty. A small chip in the tab, updated
  as you switch, removes a `git status` you run dozens of times a day.
- **Send a colleague your layout** — *Medium.* Named layouts save the arrangement
  for you, but "open the three panes I use for this project" is a thing you would
  want to hand to somebody joining it. A layout that exports to a small file, and
  opens from one, makes a working setup shareable rather than personal.
- **Rewind what a pane printed** — *Medium.* When output scrolls past faster than
  you can read, the recovery today is scrolling and searching. A scrubber over
  the last few minutes — drag back, watch it replay, drop a mark — makes a flood
  reviewable instead of merely retained.
