## Commentary

### Yesterday

Yesterday was the biggest single day this project has had: **23 tasks closed and
v1.34.0 went out**. Three things landed that you can actually feel. The Windows
download page stopped being a release behind and its portable ZIP hands you a
file again, so someone finding Ghoztty for the first time gets the build we are
actually working on. Downloaded installs got their `ghoztty` command line back —
before that fix, every installed copy had a command that did nothing. And
starting an older Ghoztty now asks you first instead of silently handing you the
newer one's window.

Underneath that, the day was mostly about **making the safety net real**. The
whole acceptance suite — all 241 automated checks — was run end to end for the
first time, which had never happened. It found a wall of reds nobody knew about,
and every one of them now has its own task with an owner. That is why the task
count jumped by 73 overnight; almost none of it is new breakage, it is breakage
that was already there and invisible.

The other quiet win: a commit can no longer stay on this machine. The loop now
pushes as part of finishing a task and fails the turn if it did not, which closes
the gap where a finished piece of work existed only on this box.

### Today's focus

The queue's answer is **T1099**, and it is the right one: the eight staged
commits the merge-to-main plan depends on are not referenced by any branch, so a
routine git housekeeping pass could delete them — and the check that exists to
notice exactly this prints "OK" over it. A gate that reports green on the thing
it is supposed to guard is worse than no gate, because it buys false confidence.

After that the P0 band is empty on this seat: the two remaining P0s are the Mac
seat's (T30, T330).

### Reflection

The theme of the last week is **the work has outgrown its instrumentation, and we
keep discovering that the hard way**. The acceptance suite existed for months
without anything able to run it as a suite. The push gate existed as a habit
before it existed as a check. T1099 is the same shape again: a plan whose
foundations are unreferenced, guarded by a check that cannot see them. Each time,
the fix is cheap and the discovery was expensive.

That suggests a process change worth making deliberately rather than reactively:
**every gate should be asked, at least once, to prove it can fail.** We already
do this in one place — acceptance scripts have a `-NegativeControl` mode that must
score exactly one failure — and that habit is why those scripts are trusted. The
claim-time and validate-time gates have no equivalent. A gate with no demonstrated
red is an assumption wearing a uniform.

On the merge-to-main goal, the picture is sharper than it has been. Readiness says
five of ten criteria are unmet, and only two of them are real work: the open P0
(today's task) and **T87, the Mac regression build**, which this box cannot run.
The lane and acceptance criteria are simply unmeasured today, and the tree is
dirty with this morning's own triage. Nothing structural stands in the way any
more — the branch fully contains main, and 1431 commits are waiting to become the
trunk. The bottleneck is now a Mac-seat validation pass, not Windows work, and
that is worth saying plainly because it changes what "almost there" means.

One recurring cost worth naming: **ambiguous vocabulary keeps buying wrong
turns.** "Merge back" meant three different things and cost two of them before
being pinned down yesterday. That is the second time this month a phrase, not a
bug, was the defect. Where a term is load-bearing, it belongs in CLAUDE.md with
its senses enumerated — cheap insurance against an expensive class of mistake.

## Feature ideas

### User-facing

- **Make Ghoztty the terminal Windows opens by default** (High) — register as the
  system default terminal host, so every console app, every `Win+R`, and every
  "Open in Terminal" lands in Ghoztty with your theme and layout. Right now half
  the terminals you get in a day are not the one you chose.
- **"Open Ghoztty here" in the Explorer right-click menu** (High) — right-click a
  folder or its background and get a pane already in that directory, with a
  shift-variant for a new tab in the current window. It is the single most-used
  entry point for a Windows terminal and we do not have it.
- **Bring this session to the machine I am sitting at** (High) — a running
  session, picked up from a different PC through the relay account, with its panes
  and scrollback intact. Sharing a machine is already possible; moving yourself
  between them is not.
- **Find in the viewer pane** (High) — Ctrl+F inside a rendered README, a diff or
  a web page, with match highlighting and next/previous. Scrollback has search and
  the viewer does not, which is a surprising place to hit a wall.
- **A password prompt that does not look frozen** (Medium) — when a program reads
  hidden input, show a small masked-input indicator instead of a dead cursor.
  Everyone has typed a `sudo` password into a pane they thought had hung.
- **One key hides every piece of chrome** (Medium) — tab strip, banner, dividers
  gone, just the text, for a screenshot, a demo, or a screen share. Coming back is
  the same key.
- **Mute a chatty pane** (Medium) — per-pane control over bells, toasts and
  taskbar flashes, so a log tail cannot keep interrupting you while the build in
  the next pane still can.

### Developer experience

- **Tab-completion for the `ghoztty` command itself** (Medium) — verbs, flags and
  live pane ids completing in pwsh, so `+send-keys --target=<tab>` offers the panes
  that actually exist. The CLI is the main interface for scripted and agent-driven
  use, and it is currently memorised rather than discovered.
