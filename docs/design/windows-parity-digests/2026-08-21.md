## Commentary

### Yesterday

**The merge back to upstream Ghostty actually began.** You answered D80 with
"start now, in stages", and Stage 0 landed: a permanent upstream remote so the
plan's commits stay resolvable, merge drivers for the files where both sides
only ever append, and a script that re-applies this fork's identity over an
upstream tree with a verifier behind it. That last piece turns 52 of the 131
risky files from hand-resolved conflicts into a mechanical step — in this merge
and in every future one. No upstream code was merged yet, deliberately.

**Three things you would actually notice were fixed.** Copying can no longer
hand you another app's clipboard content, because a copy now claims an owner
window and its two steps happen as one. Panes stopped blanking and repainting
every frame while you drag a divider or expand a banner — resizing is smooth
instead of strobing. And starting Ghoztty again opens a window in the copy you
already have rather than a second app, while still refusing to join when the
two are different builds.

**Session recovery got noticeably more careful.** When the session manager is
replaced underneath a running app, each window now gets its own layout back by
name instead of by counting, so recovery cannot hand one window another's
panes. Alongside it, the updater stopped reading the app's own healthy startup
restart as a dead app — a slow start used to stall the whole loop.

**And the test suite's staleness gate stopped being a formality.** A sweep the
day before had touched about thirty harnesses, which put every one of them into
"nobody has run this since the code changed" — and rather than stop, each
commit for the next stretch simply passed the override flag. Thirty-two
harnesses were re-run and re-stamped, so the gate speaks again. Two related
holes closed with it: a script that throws halfway through can no longer print
ALL PASS, and a script can no longer grade a `zig-out` binary that was built
before the code it is measuring.

### Today's focus

**First, the box's own disk.** The build cache has nothing that evicts it, so
the repo drive fills up on roughly a monthly clock and every build lane then
fails with a bare `error: Unexpected` that points at nothing. It has been paid
at least twice. The fix is a standing prune with a floor, plus a diagnostic
that says "you are out of space" instead of that message.

**Then the thing every download is broken by.** The MSI and the portable ZIP
ship without `ghoztty.com`, which is the small console shim that makes typing
`ghoztty` work from PowerShell. Anyone who installs from a release right now
gets an app that works and a command line that silently does nothing — and it
has been that way for two weeks of real artifacts.

**Then two fixes that came in from main overnight** (below), and after those,
two follow-ups: two release copies at *different versions* still share one app
(the version check you asked for on D79 is loud but not yet refusing), and
in-place recovery still pairs tabs by position rather than by name — the same
class that was just fixed for windows, one level down.

### Reflection

**Main moved for the first time in thirteen days, and both commits were fixes
to code this branch already ships.** That is the merge-lag argument in
miniature, and it is worth sitting with. One is a Mac-side policy fix (an app
update was restarting the session manager for a version-stamp difference alone,
and it ended ninety-five live sessions doing it). The other is in the *shared*
core: a restored pane could hand a dead full-screen program's "keep sending me
mouse reports" agreement to a plain shell, so moving the mouse typed garbage at
the prompt. Neither arrived through the Mac app directory; the second one
arrived through code that compiles into this build. The lesson for how this
queue is watched: the parity channel is `src/`, not `macos/`, and it is
watched by default — which is exactly why widening the sweep to the whole
shared core in T685 was right.

**A gate that everyone routes around is worse than no gate.** For twelve days
every commit carried the "skip the staleness check" flag, because a mechanical
sweep had put thirty-two harnesses out of date at once and nobody could clear
them in one turn. The gate was still there; it just stopped meaning anything,
and the feeling of coverage survived the coverage. The generalisable rule is
the one that already fixed picking-and-claiming a task: **an edit and its
re-validation are one act, not two.** A sweep that mechanically touches N
harnesses is not finished when the edit lands — it is finished when the N
harnesses are green again. Worth building into the sweep scripts themselves
rather than trusting the next turn to notice.

**Your side of the board is clear for the first time in a while.** There are no
open decisions this morning — D81 was the last one and you answered it. The
only thing still waiting on a human is physical: the elevated Turbo-Boost
commands for the T443/T857 experiment, which are the sole reason the two parked
P0s are parked. Everything else in the queue is this seat's to do.

**The queue is now sequenced the way T345 intended, and it is worth naming.**
Yesterday froze the hand-curated priority list and made `next` the only
authority. Today's triage put an explicit sequence on the five P1s instead of
writing a list above the queue — which is the sanctioned replacement working as
designed: the ordering lives *in* the tasks, so there is no second place for it
to disagree with itself.

**One thing yesterday asked for and today still did not do:** the divergence
inventory — the per-file answer to "will upstream rewrite this underneath us?"

honest reason is that it is still awkward to run: it fetches upstream by hand
instead of using the remote Stage 0 just made permanent (T1024). A tool that is

better triage question, and it should be picked up as soon as the P1 band

## Feature ideas

### User-facing

- **Finish my command before I type it** (High) — as you type, the rest of the
  line you most recently ran that starts the same way appears greyed ahead of
  the cursor; one key accepts it. This is the single feature people miss most
  when they leave a shell that has it, and it needs no configuration to be
  useful on day one.
- **Press a key, every link on screen gets a label** (High) — one shortcut
  paints a short letter tag on every path, URL and error location visible in
  the pane; typing the tag opens it. Turns "find the file in that stack trace"
  from a mouse hunt into two keystrokes, and it works on remote panes where the
  mouse is least pleasant.
- **My terminal looks the same on every machine I sign into** (High) — the
  relay account already knows who you are; let it carry the settings, theme and
  keybindings so a new box is one sign-in away from your setup. Today every
  machine is a fresh start.
- **Let someone watch this pane** (Medium) — a read-only link that shows a live
  pane to a colleague, with a visible indicator while anyone is watching and a
  one-click revoke. Pair debugging over a screen share is worse than this in
  every way that matters.
- **A cheat sheet for the keys you have** (Medium) — one shortcut opens an
  overlay listing every binding, searchable, grouped by what it does. Half the
  features already built are invisible to anyone who has not read the config
  file.
- **Zoom just this pane, and remember it** (Medium) — Ctrl+scroll or a shortcut
  changes the font size of the pane you are in, per pane, and it survives a
  restart. Useful for a log pane you want small beside an editor you want
  large; also the fastest accessibility lever in the app.

### Stability and performance

- **Stay responsive when a pane floods** (Medium) — when a command dumps tens
  of megabytes, the app should keep drawing at a steady rate and keep every
  other pane and the input line fully live, rather than following the flood
  frame for frame. A `cat` of the wrong file should never cost you the window.
- **Tell me when a saved session's program has died** (Medium) — a pinned
  session whose shell exited should say so on its card in the chooser instead
  of looking identical to a live one. Right now the difference is only
  discovered by opening it.
