## Commentary

### Yesterday

**The installer stopped being the worst part of the product.** Upgrading over a
running Ghoztty used to leave every open window on the old build with no hint
that anything had changed; the installer now offers to restart the terminal it
just replaced (T1352). Running the installer a second time no longer dies
silently either — it asks Repair or Cancel before it touches anything (T1367).
Both came straight out of the install walk you did, and both are the kind of
thing you only find by actually double-clicking the thing.

**Remote sessions got honest.** The machine chooser was listing sessions that
were not there any more; it lists live ones only now (T1364). `+sessions` says
what a plain shell is running (T545) and names the pane each session lives in
(T552), so a script can tell one window's session from another's. And the agent
can no longer replace its own binary or put an icon in your tray (T550) — it is
a daemon, and it now behaves like one.

**The chrome quietly became one typeface.** The small dialogs and the command
palette follow the system theme (T563), the default split divider takes its
color from your terminal's own palette rather than a hard-coded grey (T581), the
banner is set in the same type as the rest of the app (T583), and the key-table
card explains itself on hover (T576). Small individually; together it is the
difference between an app and a pile of windows. A keybind on F10 also fires now
instead of opening the window menu (T575), which is the sort of bug that only
bites the people who bind F10.

**And a large day of test work you will never see.** Nine of yesterday's
twenty-four closures were the harness proving things it used to assert:
clicking the dashboard's buttons rather than calling their handlers (T565),
walking the Activity Monitor with real Tab and Shift+Tab (T567/T569/T570),
taking the keyboard away from a window on purpose (T568), proving a hover fill
without a pointer (T571), and getting the interactive suite running again at all
(T572). The watchdog also learned to notice a session that has stopped
*working*, not merely one with unsent text (T1370) — the hole that let the loop
sit still for two and a half hours reading healthy.

**What shipped — and what did not.** The last release is **win-v1.36.14**
(2026-09-05 09:27, from `aafd3f832`). **Thirty-eight commits have landed since
and are in no release at all** — everything from T1364 onward, which is the
whole installer-manners set, the theme work, and the F10 fix. Yesterday's
publish fired once in the morning and the evening gate never came back around.
That is the largest stranded pile since T1294 was filed to stop exactly this,
and it is today's first correction: the next task-boundary push should carry a
publish request rather than waiting for 17:00.

### Reflection

**The publish cadence is the weakest link in the whole chain now, and it keeps
failing in a new way each time.** T1294 fixed "one a day strands the rest" with
publish requests. T1369 fixed "a failed publish consumes the day". Yesterday
found the third variant: a successful morning publish, then a full day of work
behind it and no second run because 17:00 arrived during a stalled turn. Three
fixes, three misses, all the same underlying shape — the trigger is a *side
effect of a turn happening*, so a day where turns stop happening at the wrong
hour ships nothing. The honest fix is a trigger that does not depend on the
loop's rhythm at all: the supervisor already runs every ten minutes and already
has its own scheduled task. It, not the turn, should be the thing that notices
the day has work in it and nothing released.

**Two red acceptance scripts survived a turn boundary as "probably
pre-existing".** That phrase is where regressions hide. `guard-due` exists so a
harness cannot go quietly stale, but nothing catches a harness that is loudly
red and has been mentally filed as somebody else's problem. A red script with no
task attached is a worse state than a stale one, because the staleness gate at
least has teeth. Worth a small gate: a harness whose last run FAILED should
count as due, not as run.

**The polish band is doing better work than its priority suggests.** Yesterday's
theme, divider, banner and hover fixes are exactly the "this app was made by
someone" signal, and they are all P2 because no single one is user-blocking.
That is the right per-task call and the wrong aggregate one. Something like a
"coherence" grouping — closing eight of these in a run, then publishing them as
one visible improvement — would land better with you than eight lines in a
digest.

## Feature ideas

### User-facing

- **Put the release you are missing in front of you** (High) — the terminal
  knows its own version and the release feed; when the build you are running is
  a day and thirty-eight commits behind, say so in the About card with the two
  or three headline changes, not just a silent update badge.
- **Undo the pane you just closed** (High) — Ctrl+Shift+T for panes and windows,
  restoring the split geometry and the working directory, with a five-second
  toast that names what would come back.
- **Name a window and get back to it from anywhere** (High) — a global hotkey
  that opens a fuzzy list of every window and pane by title, directory and
  running command, and jumps to it — the palette's jump, but across the whole
  app rather than the current window.
- **Type once into several panes** (Medium) — a broadcast toggle that sends your
  keystrokes to every selected pane in a window, with the receiving panes clearly
  marked so you cannot forget it is on.
- **A quiet mode for a demo** (Medium) — one switch that hides the tab strip,
  silences notifications, bumps the font a step, and switches to a
  high-contrast theme, then puts everything back.

### Technical / stability

- **Publish on a clock the loop cannot miss** (High) — move the daily release
  trigger onto the supervisor's ten-minute tick, so a day whose turns stall at
  the wrong hour still ships what landed.
- **A red harness counts as due** (Medium) — `guard-due` treats a failing last
  run the same as an unrun one, so "probably pre-existing" cannot survive a turn
  boundary unnoticed.
- **Warm the first frame** (Medium) — measure and cut the time from double-click
  to first prompt; the window appears well before it is usable, and that gap is
  the first impression.
