## Commentary

### Yesterday

**The Windows download is current again.** For the first time in eleven days,
someone who goes to the site and clicks the Windows link gets the same version
a Mac visitor gets: 1.33.0, published as a real release with an MSI and a
portable ZIP, and the site's links moved with it (T895). Yesterday's digest
called this the widest thing standing between the work and actual users —
three weeks of shipped features reaching nobody who is not sitting at this box.
That gate is open. The CI check that went red every time a Windows release was
missed is green again, and it went green *after* the publish rather than
before, which is the check working rather than a fluke.

**Persistent terminals now survive the daemon that runs them — for everyone.**
The holder work of the last few days shipped behind a flag; yesterday the flag
came off (T909). Every box, including the user's, now keeps its shells alive
when the session manager restarts or updates itself. That is the constraint
that has kept the morning refresh from ever shipping a new session daemon, and
it is now gone.

**Docker stopped holding the commit gate hostage.** Yesterday's reflection
named this: three tasks filed in one day about the same wedge, where a test
harness whose only unrunnable parts need Docker could never re-stamp its guard,
so every later commit needed a manual override. Fixed at the model level
(T898), and the seven duplicate filings it had spawned were collapsed into one.

**And a long run of things you would actually feel.** Double-clicking a link in
a pane gives back the whole link again instead of `https` (T802). Starting a
second copy of Ghoztty no longer steals the running copy's terminals (T851) —
a freeze, not a nuisance. A mistyped flag on `+split`, `+close` and friends now
says so instead of quietly doing something else (T852). A link out of a live
viewer page opens in your browser (T825), and right-clicking one offers
Ghoztty's own menu (T826). A relaunched pane stops typing mouse gibberish at
its own prompt (T824). The chooser's selected row looks like Windows'
selection instead of a purple pill (T828). A Ctrl key held down in a completely
different app no longer decides where a page's popup opens (T860). Underneath
all of it: a reboot nobody signed in to now announces itself instead of
silently costing a day (T829), the floor lanes stopped leaking test binaries
that tripled their runtime (T837), and window screenshots in the test suite
hold still for the camera (T940 and its four follow-ups).

### Today's focus

**T911 heads the queue**: scrollback that lives between the agent's periodic
snapshots is lost if the agent crashes — you get back the bytes the holder
still had in hand and nothing else. It sits directly under the self-upgrading
daemon that landed on Tuesday: a handover restarts the viewer, which is exactly
the moment the hole becomes visible. Yesterday's work made sessions survive a
restart; this makes what you were *reading* survive it too, which is the half a
user would notice.

### Reflection

**Two things that had been called "the widest gap" both closed yesterday.** The
distribution gate and the Docker guard wedge were both named in Sunday's
reflection as structural, not incidental — and both were fixed within a day of
being named. That is worth noticing as a process result, not just two closures:
the digest's own Reflection section is functioning as a queue that gets served.
The lesson to keep is that naming a recurring friction in plain language is
what makes it fixable; the three duplicate Docker tasks could not fix it
because each one described a symptom.

**The queue is not converging, and the reason is not laziness.** Fifty-three
new tasks were filed yesterday against forty-six closures. M1 moved from 166/227
to 182/237 — sixteen closed, ten added. The intake is not noise: most of it is
the honest cost of finishing things (a split into buildable pieces, the Mac
half of a Windows fix, the harness gap the work exposed). But at this rate the
denominator keeps pace with the numerator, and "M1 complete" recedes at roughly
the speed it is approached. The next triage should consider whether M1 needs a
freeze date rather than a bar — a milestone that admits new members daily is a
category, not a target.

**The upstream question is now the biggest open thing on the board, and it is
the user's to answer.** T879 turned a 131-file merge risk into a sequenced plan
and filed D80 with it. The fork is roughly 764 upstream commits and three
months behind; the gap grows by about 250 commits a month. One stage of the
plan moves the whole app to a new Zig toolchain and pauses Windows feature work
while it lands, which is precisely why it is a decision and not a task. Nothing
about it gets cheaper by waiting, and the plan is written either way.

**The Mac pile is 70 open tasks** — up one, after climbing every day for a
week. Yesterday's reflection proposed treating it as a merge-review checklist
rather than a backlog, and nothing has changed to argue against that. It is the
one number on the board that no queue will ever draw down.

## Feature ideas

### User-facing

- **Type the same command into a whole group of panes** (High) — mark two or
  more panes as a group and have your keystrokes go to all of them, with a
  clear visual band so you always know when you are broadcasting. Anyone
  driving several machines or several build dirs does this by hand today.
- **A per-pane task list built from what you actually ran** (High) — the pane
  quietly notices long-running commands and shows them as a small list with
  status and duration, so "did the migration finish?" is a glance rather than a
  scroll.
- **Bring back the pane I closed by accident, with its scrollback** (High) —
  not just reopening a shell in the same spot, but restoring the output that
  was in it. Closing the wrong split currently destroys evidence, which is a
  different kind of loss from destroying a shell.
- **Explain this error** (High) — select a failing chunk of output and get a
  plain-language reading of what went wrong and what to try, without leaving
  the terminal or pasting anything anywhere.
- **A quiet warning before a destructive command** (Medium) — recognize the
  handful of genuinely irreversible shapes (a recursive delete at a drive root,
  a force-push to a protected branch) and ask once, inline, instead of after.
- **Remember where I was in this project** (Medium) — reopening a project
  restores not just the layout but the working directory and the last command
  in each pane, so resuming is one action rather than four.

### Stability and performance

- **A pane that never blocks on a wedged program** (Medium) — if the thing on
  the other end stops reading, the window stays responsive and says which pane
  is stuck, instead of the whole app going grey.
- **Show me what this build is** (Medium) — a small, always-answerable "which
  build am I running, and is a newer one installed?" in the app itself. The
  recurring cost of not having it is a user reporting a missing feature that
  shipped days ago.
