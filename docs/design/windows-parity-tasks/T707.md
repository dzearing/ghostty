# T707 - agent-attach-refused.ps1's third launch never states whether it wants a restore

## Summary

`test/win32/persistence-flag.ps1` is RED: `A1 no launch leaves persistence
unstated (undeclared: 1 of 159)`. The one site is
`test/win32/agent-attach-refused.ps1:276` — arm C's launch,
`Start-OnTestDesktop -Exe $Exe -Arguments @() -StdErr ...`, which passes an
empty argument array and so never says whether it wants the previous launch's
panes restored. Found while running the sweep as a side check for T681 (whose
own new script declares the flag); the gap is not T681's and predates it.

Persistence is ON by default, so arm C currently gets back whatever the
previous section left. Arm C is the "same message against a suppressed
capability" arm of T657, and it may genuinely WANT persistence on — in which
case the fix is the `# persistence: <reason>` marker rather than the flag. That
call belongs to whoever knows T657's intent, which is why this is filed rather
than patched blind.

## In plain terms

One of the automated tests starts the terminal without saying whether it wants
the windows from the previous test to come back. That makes the test measure
panes nobody in it created, which is how a green suite ends up reporting on the
wrong thing. Nothing a user sees is broken; the guard that catches this class of
mistake is currently red because of it.

## Goals

- [ ] arm C of `agent-attach-refused.ps1` declares its persistence intent (flag
      or `# persistence:` marker, whichever matches what the arm needs)
- [ ] the arm still passes with the intent stated

## Validation criteria

- [ ] `powershell -NoProfile -File test\win32\persistence-flag.ps1` → ALL PASS
      (A1 reports `undeclared: 0`).
- [ ] `powershell -NoProfile -File test\win32\agent-attach-refused.ps1` → ALL
      PASS with the declaration in place.
