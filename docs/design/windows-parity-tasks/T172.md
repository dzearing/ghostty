# T172 - Machine chooser: owner-drawn machine rows, cue-banner filter, wrapping footer (T140 split 1/3)

## Summary

Split out of T140. The screenshot complaint's visual half: replace the default LISTBOX (full-width blue selection bar, single-line strings) with owner-drawn rows carrying per-row machine identity - status indicator, machine name, and a dimmed subline (hostname / 'this machine') - a rounded accent selection and a hover wash in the app's dark palette; give the unlabeled filter EDIT a cue banner ('Filter machines...'); and make the footer hint WRAP and the dialog grow to fit it so a sentence is never clipped mid-word. Pure row-text/metrics/height math lives in a new pure module with none-lane unit tests; on-box proof extends test/win32/ipc-machine-chooser.ps1.

## Details

### What shipped

- **`src/apprt/win32/chooser_rows.zig`** (new, pure): what a row SAYS and WHERE
  its pieces sit. `localRow()` / `deviceRow()` port Mac's `row(for:)` including
  its `hostnameSubtext` rule (a hostname equal to the display name is noise -
  "MaximusHome" over "(maximushome)" - so the row falls back to "Relay
  device"); `Status`/`Glyph` carry Mac's SHAPE-coded reachability (filled dot /
  hollow ring / nothing for Local, which still reserves the column so every row
  shares one grid); `rowMetrics(scale)` is the DPI-scaled geometry; `blend` +
  `selectionFill`/`selectionBorder`/`hoverFill` pre-composite the accent
  (GDI has no alpha for these primitives, the `banner_card.zig` trick).
- **`MachineChooser.zig`**: the LISTBOX is now `LBS_OWNERDRAWFIXED` with NO
  `LBS_HASSTRINGS` (the lParam is the row index, not a string), painted by
  `drawRow` - inset rounded selection pill + accent border, hover wash, status
  dot, a GDI-drawn machine glyph (laptop / two-unit rack: drawn, not an icon
  font, so a missing symbol font can never render as tofu), name, and a dimmed
  smaller subline. Row height is set explicitly via `LB_SETITEMHEIGHT` because
  `WM_MEASUREITEM` arrives DURING `CreateWindowExW`, before the dialog's
  userdata points at `self` (`WM_MEASUREITEM` is handled too, for later
  re-measures). The listbox is subclassed (`GWLP_WNDPROC` + `CallWindowProcW`)
  for hover, which the parent never sees.
- **Filter cue banner** ("Filter machines...", `EM_SETCUEBANNER` with
  wParam=1 so it survives focus) - the screenshot's "unlabeled empty edit".
- **Wrapping footer**: `layout(scale, hint_lines)` sizes the hint control to
  its measured line count and grows the dialog by exactly that much;
  `setHint` measures with `DT_CALCRECT | DT_WORDBREAK` in the dialog's own
  font and re-runs `applyLayout` (which re-places every control and re-centers
  the window) when the count changes. `clampHintLines` floors at 1 and caps at
  4 so a runaway error string cannot grow the dialog without bound.
- Dialog widened 420 -> 440 DIP; the list is now sized to exactly five whole
  rows so it never shows a clipped half row.

### Validation

- `zig build test -Dapp-runtime=none` and `-Dapp-runtime=win32`: PASS.
  13 new pure tests in `chooser_rows.zig` (row text incl. the three
  hostname-fallback cases, metric nesting/ordering/inset/DPI, hint clamping,
  blend endpoints + selection-vs-hover ordering) and 3 new `layout` tests
  (a wrapping hint grows the dialog by exactly its extra lines and nothing
  spills past the client area; the cap holds; the list shows whole rows only).
- `test/win32/ipc-machine-chooser.ps1` **ALL PASS (23) x3** - extended with
  the look of the thing: the list carries `LBS_OWNERDRAWFIXED` and not
  `LBS_HASSTRINGS`, row height 56 (>= 40 = name + subline), and a
  screen-capture pixel oracle at the selected row - the pill reads b-r = 47
  (the computed `blend(30,30,30, 3D8EF8, 0.25)`) while the gutter beside it
  and an unselected row both read b-r = 0. The filter's text is empty yet its
  interior has drawn pixels (the cue banner). A SECOND, signed-out launch
  proves the footer: its hint is 3 lines to the signed-in run's 1, the window
  grew by exactly that difference, and the wrapped tail is really painted
  inside the control.
- **Negative control** (the claim that matters - "not a full-width bar"): with
  `drawRow` temporarily painting the fill edge-to-edge, the gutter probe reads
  b-r = 47 and `selection is inset, not full-width` FAILS. Reverted, rebuilt,
  re-passed.
- Two false alarms worth recording. (1) The first probe run had every pixel
  assertion agreeing on one wrong value: an unaware process gets
  DPI-VIRTUALIZED `GetWindowRect` while `Graphics.CopyFromScreen` is physical,
  so the capture was 189px off at 125% - the script now calls
  `SetProcessDPIAware()` first, and derives the DPI scale from the chooser's
  own client width (`px(440, scale)` by construction) instead of hardcoding a
  line height. (2) Per-pixel `GetPixel` on the desktop DC under DWM is ~1000x
  slower than a blit; it took the script from seconds to minutes. One
  `CopyFromScreen` per probe set, then managed reads.
