# T1290 - The acceptance clean slate leaves the agent's session store behind, so every run inherits the last run's pinned sessions

## Summary

lib\CleanSlate.ps1's Reset-GhozttyTestState cuts two of the three restore sources - it deletes session-layout-debug.json and the agent's layouts.json - but never touches the agent's sessions.json. Measured 2026-09-02 while working T1285: after a floor run that store held five PINNED sessions from previous runs, one of them still carrying P1's 'echo p1-marker' argv, with unclaimed_restarts up to 2. Not the cause of T1285's red (a seeded 24-session store and the real 5-session one both left +new-window at 300-450ms and +split under 150ms, and resurrected no holders), but it is cross-run state that the reset's own header says should not survive, and nothing measures whether it stays harmless as the store grows toward the 256-tombstone cap. The work: clear it with the agent kill, and survey the scripts that SEED sessions.json first - a seed-then-reset caller would break.
