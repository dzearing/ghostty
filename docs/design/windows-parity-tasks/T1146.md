# T1146 - A release build run from the repo still rewrites the user's agent autostart entry

## Summary

T1124 gave the ghoztty:// registration a location gate: a build whose exe sits inside a source checkout registers nothing. LocalAgent's autostart Run key has the same build-MODE gate and the same missing LOCATION gate, and a worse blast radius - the entry survives a reboot, so a single GUI launch of the staging release at zig-out-release would have Windows start the agent that owns the user's live sessions out of a scratch directory that development rebuilds and deletes. Give writeAutostart the same source-checkout gate, and sweep the other launch-time self-heals for the same hole (PathInstaller has an install-dir gate; AgentIntegration's one-time offer and anything else writing outside zig-out needs checking).

## In plain terms

Ghoztty can ask Windows to start its background session-keeper for you at
sign-in, so the terminals you had open come back after a reboot. That request
records the exact folder the app was launched from. Building a test copy of the
app inside the source folder and opening it once was enough to rewrite that
request to point at the scratch folder -- which gets rebuilt and deleted all
day -- and unlike a mis-registered link, this one survives a restart. After
this, a copy of the app running out of a source folder quietly registers
nothing, and the real install keeps its entry exactly as before.

## Goals
