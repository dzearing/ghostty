# T933 - The floor run takes three times longer than its lanes because the agent lane leaks its test binaries

## Summary

Measured 2026-08-17 during T829: floor-lane.ps1 -Lane all reported lib 52s + none 282s + win32 361s + agent 363s = 17.6 minutes of lanes, and took 61 minutes of wall clock. The agent lane printed PASS at 13:55:31, and at 14:37 ghoztty-agent-test.exe and ghoztty-agent-core-test.exe (spawned 13:52:04) were STILL alive and burning about 38 percent of a core each, having spawned and outlived a tree of msedgewebview2.exe children; the wrapper blocked until they finally died, then exited 0. So every turn on this box pays roughly 40 minutes of dead time per floor run, the loop's single most-run command, and the run looks like a slow lane rather than a leak - the summary even says 'leaked webview hosts swept: 0' while the leak is the TEST BINARIES, not the webview hosts. Wanted: the agent test binaries exit when their lane does, the wrapper reports and reaps anything still alive at lane end (naming it, so a leak reads as a leak), and the stall detector is not fooled by a leaked child still burning CPU.
