# T368 - T56d: extend ipc-relay.ps1 with kill+restart-agent-under-a-live-remote-window reconnect validation

## In plain terms

If the machine at the other end of a remote window restarts its background
service, the window you are looking at has to end up somewhere definite: either
it comes back and you can type in it again, or it says plainly that it is
disconnected. What it must never do is sit there spinning forever, take the
whole terminal down with it, or quietly leak a little bit of the app every time
it happens. Nothing was checking any of that, so this adds the check.

## Goals

- [x] The relay harness kills AND restarts the agent under a live remote window
- [x] It asserts the window reaches a definite verdict - reconnected, or clearly
      disconnected - rather than spinning
- [x] The reconnected arm is proved by typing into the pane, not by a field
- [x] It proves the app leaves no connection threads behind after the window closes
- [x] `scripts\guard-due.ps1` ties an edit to the ladder or the relay dial to
      running this harness

## What the driver gives you to assert against (T366, 2026-08-08)

The driver is in. Its behaviour, so the script knows what "came back" means:

- The ladder is **5 attempts at 1/2/4/8/15s**, so a full fast pass is ~30s. Give
  the script a budget past that, and do NOT read a 20s silence as a failure.
- Exhaustion is **not** terminal: the window is kept and a background re-dial
  runs every **45s**, so a script that restarts the agent late still sees a
  recovery — just not quickly.
- A restarted agent materializes its sessions as relaunchable tombstones, and
  the driver ATTACHes those, so the pane comes back with the
  `--- session restarted ---` / session-interrupted treatment rather than empty.
- **Oracles today are log lines** — `remote reconnect: '<name>' dropped;
  attempt N/5 in Nms`, `... is back on a fresh transport (N pane(s)
  re-attached)`, `... exhausted its fast ladder`, `... is terminally
  disconnected`. That is a weak contract (it moves when the wording does);
  **T609** adds a `connection` field to `+list --json` and this script should
  assert against that instead once it lands. Consider taking T609 first.
- **No orphan threads** is directly checkable: a replaced transport is retired
  (shut down off-thread) and freed at window close, so after `+close` the
  process's thread count must return to its pre-drop level.
