# T601 - The Windows viewer shows a .html file as source; main renders it as a live page with live reload

## In plain terms

Open a `.html` file in a Ghoztty side pane on Windows and you see its markup,
the way you would see a `.zig` file. On the Mac you see the page it describes,
and it re-renders when you save. This is why the task dashboard has to be served
over localhost instead of just opened - a local `.html` displays its own source.

## Goals

- [x] a `.html` or `.htm` file opens as the page it describes, with its own
      stylesheet, scripts and images working
- [x] saving the file updates the pane without losing your place
- [x] a page can only read files in its own folder, not the whole disk
- [x] a missing file says which file, instead of showing a browser error page
- [x] `+reload`, `+list --json`, the address bar and session restore all treat
      it like every other viewer pane

## Summary

Upstream: `2007e2cb0` "feat(viewer): render .html files as live pages, and live-reload
them on save" plus its merge `378d08223`. The win32 viewer already has the
file-watcher and the scroll-preserving re-render (T391), so this is a routing
change in the viewer's mode selection plus a load path that gives the page its
own base URL for relative assets.

Watch: a rendered local page can reach out to the network and can run script. The
Mac decision is the precedent to follow, not to re-litigate.

## Validation criteria

- [x] `ghoztty +split --view=some.html` renders the page, not its source.
      `test\win32\viewer-html.ps1` section A: the pane loads
      `https://ghoztty-page/index.html` and the page then FETCHES its own
      stylesheet, script and image, which a source view never does. Section E is
      the paired control: the identical bytes opened as `.txt` produce neither
      log line, in the same run against the same app.
- [x] Saving the file re-renders it, preserving scroll position. Section C: the
      save re-loads the page, and the served length follows the file's new size
      (so it is a re-read of disk, not a cache hit). Scroll preservation is the
      choice of PLAN, since nothing on the background test desktop can read a
      scroll offset: `reload_in_place` (a plain reload, which the engine
      restores scroll across) for a save vs `refetch` for `+reload`, asserted in
      the none lane by "reloadPlan: the branch is the verb's whole contract".
- [x] Relative assets (css, images, scripts) next to the file resolve. Section
      A covers all three, including an image in a subdirectory of the grant;
      section G asserts the grant's edge — a page in `docs\` reaching up for
      `../app.css` is refused, which is Mac's narrow-by-default grant and is now
      a checked property rather than an incidental one.
- [x] `+list --json` reports the pane the way it does for other viewer modes.
      Section B: `type` is `viewer` and `url` is the FILE's own path, not the
      synthetic origin the engine loaded it from.
- [x] Acceptance script in `test/win32/`: `viewer-html.ps1`, ALL PASS
      (40 assertions), plus a missing-file arm (the pane's own error card names
      the file, rather than the engine's can't-be-reached page) and a `.htm` arm.
- [x] Floor: `scripts\floor-lane.ps1 -Lane all` = none/win32/agent all PASS;
      P1, P2, P3 ALL PASS.
