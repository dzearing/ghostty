# T1264 - The 'session restarted' divider is missing when a tombstoned pane relaunches

## In plain terms

When a terminal session comes back after the background service that keeps it
alive is restarted, the pane is supposed to show a faint `--- session restarted ---`
line between the old output it replays and the new shell that starts under it.
Right now that line is missing in at least one of the two ways a session comes
back, so the user sees old output run straight into a fresh prompt with nothing
saying where one ended and the other began.

## Summary

`test\win32\session-relaunch.ps1` section B has been RED on this box - measured
twice, back to back, against an unmodified checkout on 2026-09-01:

```
  FAIL B7 the deferred relaunch printed the '--- session restarted ---' divider
  1 FAILURE(S)
```

B is the `session-relaunch=prompt` policy: the pane shows a tombstone, the user
presses a key, and the session relaunches. The replayed scrollback and the fresh
shell both arrive; only the divider is absent.

Section A (`rerun`, the automatic path) passes as the script stands today, but it
fails the SAME assertion the moment the script's launches move to the background
test desktop (T1238) - a launch through `Start-OnTestDesktop` instead of
`Start-Process -WindowStyle Minimized`, which differs in window geometry (the
harness clears the debug window-placement memory) and in nothing else about what
is asserted. Measured there:

```
  DBG read code=0 text=[Microsoft Windows [...] C:\Users\David>RELAUNCHAUTO47552ZZZ
                        Microsoft Windows [...] C:\Users\David> ]
  FAIL A10 the relaunched pane shows the '--- session restarted ---' divider
  FAIL A11 the pre-kill ring scrollback (marker) precedes the divider
```

The pre-kill marker IS replayed and the fresh shell DOES start - so the ring
snapshot and the relaunch both work. Only the divider is missing, which points at
the hand-off between the two places that can emit it: the agent bakes
`session.zig`'s `reboot_divider` into the preloaded ring snapshot and the client
then suppresses its own (`relaunch_replayed` in `src\termio\Remote.zig`
`threadEnter`, whose `restart_divider` is documented as byte-identical by
contract). A suppression that fires when the agent did NOT bake the divider in
would produce exactly this: replayed scrollback, no marker line, no error.

That the A case flips on a window-geometry change is the useful lead: it makes
the failure reproducible on demand instead of only in section B.

## Where

- `src\termio\Remote.zig` - `restart_divider`, `relaunch_replayed`, `threadEnter`
- `src\remote\agent\session.zig` - `reboot_divider`
- `src\remote\agent\ring_snapshot.zig` - the preloaded snapshot the agent replays
- `test\win32\session-relaunch.ps1` - sections A and B

## Root cause

Two defects, one symptom, one per relaunch path.

1. **Nobody drew it on a live-agent tombstone.** The agent bakes the divider
   into the ring at AGENT-RESTART time only (`preloadRingSnapshot` →
   `appendRestartDivider`). A session whose shell dies under a still-running
   agent never goes near that path, but its ring is non-empty all the same — so
   `RELAUNCHED.replayed` came back true, the viewer suppressed its own divider
   by contract, and no line was drawn by anybody.
2. **The respawned shell repainted over it.** Whatever is on the ACTIVE SCREEN
   when the fresh child's first bytes land is overwritten — conhost hands over
   its whole screen buffer as absolutely-positioned VT. The divider is the last
   line of the replay, so it survived or vanished according to how the replay
   happened to sit in the window. That is why the same assertion passed at the
   user-desktop geometry and failed on the test desktop, and why B7 was red
   everywhere: the deferred path's client-side inject sat on the active screen
   with nothing but luck protecting it.

The fix puts both halves where they can be correct. The agent places the divider
on every RELAUNCH (`appendRestartDivider` is now idempotent, so the reboot path's
existing one is left alone — exactly one line, ever), and the viewer parks the
replayed screen into SCROLLBACK at the replay's end offset before the child's
repaint can reach it, which is the same T666 move the attach path already makes.
`RELAUNCHED` carries a new additive `replay_bytes` so the viewer knows where that
boundary is.
