# T1250 - Ghoztty runs over Remote Desktop

## In plain terms

Connect to a Windows machine remotely, install Ghoztty, and it will not start.
The remote connection hands programs a very basic graphics driver, and Ghoztty
draws its terminal with something much newer than that driver can do. There is
no setting and no workaround: the terminal simply does not run on that machine
while you are connected remotely.

After this, it runs. It may draw more slowly than it does sitting at the
machine, and it should say so rather than leave the user guessing.

## Split from

[[T1224]]. Its other half, [[T1249]], made the refusal honest - it now explains
the cause instead of telling the user to reinstall. This is the half that makes
the terminal actually work there.

## What the user hit (2026-09-01)

Connected to a Windows machine with **Windows App** (Microsoft's RDP client)
from a MacBook. Installed Ghoztty. On launch: *"Ghoztty could not start ...
Error: OpenGLOutdated"*. Reinstalling could not help.

## Why there is no cheap version of this

`src/renderer/OpenGL.zig` requires OpenGL 4.3 (`gl_report.min_version_major` /
`_minor` since T1249). An RDP session's display driver exposes OpenGL **1.1**
("GDI Generic", Microsoft Corporation) because the desktop is encoded and
shipped over the wire rather than scanned out of a GPU. Lowering the floor
therefore fixes nothing - 1.1 is two decades short of anything the renderer
does, not a version or two.

There is no second path today: a search of `src/apprt/win32/` and
`src/renderer/` finds no ANGLE, no EGL, no software rasterizer and no D3D11
backend. One renderer, one hard floor, no degraded mode.

## Approaches to weigh before committing

- **A software desktop-GL implementation adjacent to the exe** (Mesa's
  `llvmpipe`, or its `d3d12` gallium driver, which reaches the GPU through
  Direct3D and so works over RDP). Its attraction is that it is *desktop* GL
  4.5: no shader rewrite, no renderer changes, the existing pipeline runs
  unmodified. Its costs are download size (tens of MB) and vendoring a
  third-party binary into the installer.
- **ANGLE** (GL ES over Direct3D 11, falling back to WARP). Smaller and the
  standard Windows answer, but ANGLE speaks GL ES 3.x while the renderer is
  written against desktop GL 4.3 - so this is a shader and pipeline port, not a
  drop-in.

Whichever is chosen, the **loading** is the part with a trap in it:
`opengl32.dll` is not a KnownDLL, so a copy sitting next to `ghoztty.exe` wins
over System32 for *every* launch - which would put every user on the software
path, GPU or not. A conditional fallback therefore needs the GL entry points
resolved dynamically (`wglCreateContext`, `wglMakeCurrent`, `SwapBuffers` are
`extern "opengl32"` today, in `Surface.zig` and `OpenGL.zig`) so the
implementation can be chosen at runtime after the system one has been measured.

## Requirements

- **Detect rather than crash.** `gl_report.Report.belowFloor()` already names
  the condition; that is the point where a fallback context is attempted
  instead of returning `error.OpenGLOutdated`. Key off the measured context,
  not `GetSystemMetrics(SM_REMOTESESSION)` - a weak local GPU and a VM produce
  the same failure without RDP.
- **Say which renderer is in use**, in About and in the log, so a slow session
  over RDP is diagnosable rather than mysterious. The log half exists (T1249
  logs renderer and vendor); About does not.
- **Keep the T1249 dialog for the genuinely impossible case** - when no
  renderer at all can be created, the user still gets an honest refusal.
- **Mac parity:** macOS uses Metal and has no such failure. Windows-only gap,
  no mac half to file.

## Validation criteria

- [ ] Ghoztty starts and renders over an RDP session, proven by an acceptance
      script rather than a manual look.
- [ ] The fallback is exercised on a context below the floor - the
      `GHOZTTY_GL_FORCE_VERSION` seam (T1249) builds that state on a normal box
      - and the renderer actually chosen is reported in About and in the log.
- [ ] A context at or above the floor still selects the system GL: no user with
      a working GPU is quietly moved onto a software renderer.
- [ ] The startup dialog still appears when NO renderer can be created, with
      the T1249 wording.
- [ ] `ghoztty +list` and session restore behave the same over RDP as locally.
- [ ] Installer and portable zip carry whatever the fallback needs, and
      `deliver-windows-build.ps1`'s manifest check accounts for the new files.
