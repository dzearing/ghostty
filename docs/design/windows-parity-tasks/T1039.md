# T1039 - An acceptance script that throws mid-run still prints ALL PASS and stamps its guard

## Summary

Measured in T329 on test\win32\activity-monitor-dialed.ps1: calling .Trim() on an empty files -Raw content (which is null) ended the run at the top of its last section, the finally block ran, and the script printed ALL PASS (27 assertions) and STAMPED its guard - recording every covered file as freshly proven while a whole section had measured nothing. The cause is structural, not local: these scripts wrap their body in try/finally with NO catch, and under ErrorActionPreference = Continue a statement-terminating error unwinds the try, runs the cleanup, and then falls through to the verdict with the failure count still 0. 95 of the 155 scripts in test\win32 are in exactly that shape (Continue + top-level finally + no catch); 39 more have a finally and no catch under other preferences. T329 fixed the one script it was working in by adding a catch arm that scores the throw as a FAILURE. The sweep is to make that structural rather than per-script - the natural home is lib\TestScore.ps1, which already owns the rule that a verdict must be backed by assertions (T271) and could own beside it the rule that a verdict must not be printed over an unwound run, e.g. a marker the script sets when it reaches the end of its body and that Write-TestVerdict refuses to be green without.
