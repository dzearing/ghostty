# T1039 - An acceptance script that throws mid-run still prints ALL PASS and stamps its guard

## Summary

Measured in T329 on test\win32\activity-monitor-dialed.ps1: calling .Trim() on an empty files -Raw content (which is null) ended the run at the top of its last section, the finally block ran, and the script printed ALL PASS (27 assertions) and STAMPED its guard - recording every covered file as freshly proven while a whole section had measured nothing. The cause is structural, not local: these scripts wrap their body in try/finally with NO catch, and under ErrorActionPreference = Continue a statement-terminating error unwinds the try, runs the cleanup, and then falls through to the verdict with the failure count still 0. 95 of the 155 scripts in test\win32 are in exactly that shape (Continue + top-level finally + no catch); 39 more have a finally and no catch under other preferences. T329 fixed the one script it was working in by adding a catch arm that scores the throw as a FAILURE. The sweep is to make that structural rather than per-script - the natural home is lib\TestScore.ps1, which already owns the rule that a verdict must be backed by assertions (T271) and could own beside it the rule that a verdict must not be printed over an unwound run, e.g. a marker the script sets when it reaches the end of its body and that Write-TestVerdict refuses to be green without.

## In plain terms

The scripts that prove Ghoztty works can crash halfway through and still finish
by announcing that everything passed. When one of them hits an unexpected error
in the middle - a file that turned out to be empty, a value that was not there -
the rest of that script's checks are quietly skipped, the last line still says
ALL PASS, and the script records that it has proved the feature is fine. After
this lands, a run that does not reach its own end says so and is red, and it
records nothing - so "this was tested" stops being a thing a broken test run can
claim about itself.

## Goals

- [x] the shared scorer refuses a green verdict over a run that unwound
- [x] the guard stamp - the part that outlives the run - is refused too
- [x] the rule is structural: one place, not a `catch` arm remembered per script
- [x] every script it covers is converted, and a sweep keeps them converted
- [x] the other verdicts (FAILURE(S), ASSERTED NOTHING) keep their wording

## Validation criteria

- [x] an unwound body prints `RUN DID NOT FINISH` and exits 2, measured on the
      wire as a real process - including the original T329 shape, a `.Trim()`
      on an empty file's `-Raw` content (`body-complete-audit.ps1` A3-A9)
- [x] a run that reaches the end still says ALL PASS and exits 0 (A1-A2), and
      failures / precondition skips / floor misses keep their own wording and
      exit codes (A10-A14)
- [x] `guard-due.ps1 update` writes NO stamp for an unfinished run, exits 3, and
      still stamps for a finished one and for a caller that is not a scored run
      at all (B1-B9)
- [x] the analyzer names each violating shape and stays quiet on the guarded-
      expression idiom that is not a run body (C1-C10)
- [x] the sweep over `test\win32\*.ps1` reports zero findings across all 58
      scored scripts (D1-D2), and `-TeethCheck` proves that assertion can fail
- [x] the suite's own harnesses still pass with the marker in place:
      `asserted-nothing.ps1`, `guard-due.ps1`, `stderr-capture-audit.ps1`,
      `printclient-audit.ps1`, `verdict-exit-audit.ps1`, `isolation-meta.ps1`,
      `launch-preflight-audit.ps1`, and the P1-P3 floor
