# T503 - Backfill tags onto open tracker tasks so the dashboard categories cover the whole queue

## In plain terms

Task categories (tags) exist as of T502, but only newly filed tasks carry
them - the several hundred existing open tasks show no category on the
dashboard, so the at-a-glance view only covers new work until the backlog is
tagged.

## Summary

Sweep the OPEN tasks (todo / in-progress / blocked; done tasks only as
activity cards surface them) and add `tags:` frontmatter from the closed
vocabulary (feature / fix / polish / perf / test / infra / docs / security),
using each task's title, triage-reason and summary as evidence. Commit as
`chore(tracker)` so the bulk edit does not stamp the whole tracker
"modified today" (the fileDates() triage-commit rule already handles this).

## Goals

- [x] a real verb for tagging an already-filed task, instead of hand-editing frontmatter
- [x] every OPEN task in the tracker carries at least one category
- [x] a harness section that keeps it true rather than a one-time sweep

## Validation criteria

- [x] `set-tags <id> -Tags a,b` writes the field where `new` puts it, on a
      file that has no `tags:` line and on one that predates `priority:` -
      section R (R1, R1b, R4) of `test\win32\parity-tasks-seat.ps1`.
- [x] Replace is the default and `-Add` unions without duplicating - R2, R3.
- [x] An out-of-vocabulary tag and an empty `-Tags` are both refused and leave
      the file byte-identical - R5/R5b, R6/R6b.
- [x] No OPEN task (todo / in-progress / blocked) in
      `docs/design/windows-parity-tasks/` is without a category: R7 asserts it
      against the real tracker on every run, and read 0 untagged after the
      backfill (24 before it).
- [x] `parity-tasks.ps1 validate` ALL PASS over the backfilled tracker, so no
      tag written by the sweep is outside the closed vocabulary.
- [x] Floor green: `scripts\floor-lane.ps1 -Lane all`.
