# T1168 - Soak runs leave agent autostart entries behind in the user's registry

## In plain terms

Running the test suite is quietly adding startup programs to this machine. Four
of them were sitting in the user's "run these at sign-in" list on 2026-08-23,
each one pointing at a throwaway test sandbox from a soak run earlier that day,
and each one will launch a background agent process at the next sign-in for a
sandbox that no longer means anything. Nothing about a test run should still be
running tomorrow morning.

## Summary

Found while measuring T1142. `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
held, alongside the user's real `GhozttyAgent` entry:

```
GhozttyAgent-soak-47404  "D:\git\ghoztty\zig-out-release\bin\ghoztty-agent.exe"
                         "--listen-pipe=\\.\pipe\ghoztty-agent-soak-47404-David"
                         "--port-file=...\Temp\ghoztty-soak\20260823-093902\sandbox\..."
GhozttyAgent-soak-48720  (same shape, 20260823-094339)
GhozttyAgent-soak-43452  (same shape, 20260823-094639)
GhozttyAgent-soak-47856  (same shape, 20260823-100937)
```

Four in one morning, from four soak runs. The mechanism is T167's per-lineage
autostart: `GHOZTTY_AGENT_INSTANCE=<tag>` correctly gives the sandbox agent its
own Run VALUE name instead of clobbering the user's — which is what stops a test
from breaking their terminal — but nothing removes that value when the run ends,
so each isolated run leaves a permanent one behind. Confirmed the same way from
this seat: a T1142 measurement under `GHOZTTY_AGENT_INSTANCE=ingest48876` left
`GhozttyAgent-ingest48876` behind, and it was removed by hand.

This is squarely the rule in `docs/claude/testing.md` — *tests must never touch
live user state* — and the leak is invisible to every existing sweep, because
`HarnessLeak.ps1` and the clean-slate audits look at processes, windows, pipes
and files, not at the registry.

## Where

- `src/remote/agent/` — whichever autostart install path writes the Run value
  (`enroll.zig` / `keepalive.zig` / the `--listen-pipe` bring-up); the lineage
  suffix is T167's.
- `test\win32\lib\CleanSlate.ps1` — where a per-run teardown would belong.
- `test\win32\lib\HarnessLeak.ps1` — the sweep that should be able to see it.
- `test\win32\soak.ps1`, `test\win32\holder-soak.ps1` — the observed producers.

## Notes

The four existing entries were left in place rather than deleted from under the
user; whoever takes this should confirm with them before removing what is there,
and then make the leak impossible rather than tidying it once.

## Validation criteria

- [ ] a soak/isolated run that finishes normally leaves NO
      `GhozttyAgent-<instance>` value behind in `HKCU\...\Run`
- [ ] a run that is KILLED mid-way is also swept — by the next run's clean-slate
      if not by its own teardown, since a crash is exactly when this leaks
- [ ] the leak sweep can SEE the condition: an arm that plants a fake
      `GhozttyAgent-<tag>` value and requires the audit to report it
- [ ] the user's own `GhozttyAgent` entry is never touched by any of the above,
      proven with a before/after read in the same run
- [ ] the four entries already on this box are resolved with the user
