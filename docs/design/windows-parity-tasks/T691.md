# T691 - Convert the win32 acceptance suites off kill-the-debug-lineage onto GHOZTTY_AGENT_INSTANCE

## In plain terms

Our automated tests currently have to shut down the background helper that is
keeping the developer's own terminal sessions alive, just to run. It works, but
it means a test run can interrupt real work, and two test runs can never happen
at the same time. The mechanism that removes the need for that now exists; this
is the job of actually switching the tests over to it.

## Summary

T167 added `GHOZTTY_AGENT_INSTANCE=<suffix>`: one env var that gives a sandbox
its own agent lineage (guard, lock, heartbeat, state dir, pipe, autostart value,
`+sessions`). What it did NOT do is spend it — every existing suite still opens
with some version of

```powershell
Get-CimInstance Win32_Process -Filter "Name='ghoztty-agent.exe'" |
    Where-Object { $_.CommandLine -like '*local-agent-debug*' } |
    ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

which kills whatever debug agent is holding the loop's own panes, and which is
also why two acceptance scripts can never run concurrently.

## Details

The work, per suite:

1. Give the run a per-run lineage (`"<suite><PID>"`, ≤ 24 chars) and set
   `$env:GHOZTTY_AGENT_INSTANCE` alongside the `LOCALAPPDATA` /
   `GHOSTTY_LOCAL_AGENT_BIN` / `GHOZTTY_PIPE_SUFFIX` block the suite already has.
2. Narrow the teardown from "kill every zig-out agent" to "kill the pids this
   script started" (the pattern `agent-instance-lineage.ps1` uses).
3. Where a suite was silently non-persistent all along, its assertions will
   change — that is the point, and each such change needs reading rather than
   accepting. `upgrade-no-fork.ps1`'s explicit "the sandbox pane really is
   agent-backed (port.json written)" assert is the shape every converted suite
   should carry.

Candidates (anything that starts an agent or asserts on persistence):
`agent-pipe.ps1` (also drops its `--force-replace` + `GHOSTTY_AGENT_HEARTBEAT`
hack), `agent-session-cap.ps1`, `agent-recovery.ps1`, `agent-upgrade.ps1`,
`agent-open-refused.ps1`, `agent-autostart.ps1`, `agent-shell-integration.ps1`,
`agent-user-env.ps1`, `agent-job-escape.ps1`, the `session-*` family,
`upgrade-no-fork.ps1`, and the `chooser-*` scripts that need a live roster.

Worth doing as one sweep rather than one-suite-at-a-time: the value only arrives
when NO suite kills the lineage, since one that still does takes every
concurrent run down with it.

## Validation criteria

- [ ] No script under `test\win32\` kills an agent it did not start (grep for
      `local-agent-debug` and `'*zig-out*'` in kill predicates comes back empty
      except where the subject IS process cleanup)
- [ ] Each converted suite still passes standalone
- [ ] Two persistence-touching suites run CONCURRENTLY and both pass — the
      capability that does not exist today
- [ ] A debug agent started before the run (standing in for the loop's own) is
      still alive and still holding its sessions afterwards
