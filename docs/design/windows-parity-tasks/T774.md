# T774 - ghoztty.log grows without bound - no size cap or rotation

## Summary

The shared Windows log sink has no upper bound. It was 8.6 MB when T270 was filed, and T270's per-line timestamp+pid prefix adds ~30 bytes to every line, so it now grows faster. Nothing trims it: every GUI launch, agent and one-shot CLI invocation appends forever. Rotation is deliberately NOT folded into T270 because it has its own contract to keep - a rotating writer must not lose the atomic-append property T229 established (FILE_APPEND_DATA, one write per line), and a rename/truncate race between concurrent writers is exactly the class of defect that sink has already been bitten by twice. Direction: a size check at open time, renaming to ghoztty.log.1 past a cap (a few MB) and keeping one or two generations - with the concurrency question answered explicitly, since N processes may notice the cap at the same instant. Validation: extend test\win32\log-append.ps1 with a rotation arm that drives the writer past the cap under concurrency and asserts no line is lost across the boundary.
