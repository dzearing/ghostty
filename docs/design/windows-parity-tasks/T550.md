# T550 - Retire the agent code that only the standalone install needed: the --relay self-updater and the tray

## In plain terms

Nothing a user sees changes here. The agent still carries machinery from when
it was installed on its own: it downloads and swaps in new copies of itself
from a web address, and it has a system-tray icon. Neither belongs to an agent
that ships inside Ghoztty and is updated with it - and code that can replace
the binary the app installed is code that can fight the app's own updater.

## What landed

- **Deleted**: `src/remote/agent/self_update.zig` (994 lines - the relay-hosted
  binary swap), `tray.zig` (743) and `tray_account.zig` (220 - the standalone
  install's only UI), and `scripts/deploy-windows-agent.sh`. 2,327 lines out,
  267 in.
- **Kept, moved**: the pre-daemon error box is now `startup_error.zig`. It was
  living inside `tray.zig` as the "pre-tray" surface, but it was never about
  the tray - it fires when first-run enrollment fails, before any daemon setup,
  and the GUI-subsystem exe has no console to print to instead. Deleting it
  with the tray would have made a failed enrollment silent.
- **Wiring**: `runListen` and `runRelay` no longer branch on a Windows message
  pump; every mode now runs its loop on the main thread, which is the shape
  `--headless` used to select. `--headless` is still accepted and still means
  something in relay mode (no browser self-enroll); it no longer selects a UI.
- **Build**: `shell32` is no longer linked (it was the tray's
  `Shell_NotifyIcon`); `user32` stays for the message box.
- **Downloads**: `publish-agent.sh` publishes only the signpost and the landing
  page. `/dl/ghoztty-agent.exe` and `/dl/version.json` retire with their only
  reader, and `--if-changed` now keys off a `# published-from:` stamp in the
  uploaded `install.ps1` rather than the manifest it no longer writes.
- **Docs**: the release runbook's Step 4 stopped building and publishing an
  agent; the Caddyfile, `relay/README.md`, `session-persistence.md`,
  `testing.md` and the consolidation design doc were updated in the same
  change.

## Summary

Cleanup half of T417, re-scoped on 2026-08-30. **T1175 already did the delivery
half**: the website's agent download card, the hosted one-liner (now a
signpost), `relay/deploy/msi/`, the MSI half of `publish-agent.sh`, and the
docs that pointed at them. What is left is the agent-side code, which is riskier
and wants its own tests:

- **`src/remote/agent/self_update.zig`** and its wiring in `runRelay`
  (`main.zig` ~2420: `cleanupLeftovers`, `maybeStart`). Per Decision 1 of
  `docs/design/one-installer-agent-consolidation.md` the consolidated agent has
  **no self-update** - the binary is owned by the app install (T89h) and moves
  with app delivery, so a relay-hosted updater would fight it.
- **`src/remote/agent/tray.zig`**, the standalone install's only UI. The
  product's account UI is the machine chooser (T141), which both platforms
  have; headless is also the only symmetric shape, since the Mac agent never
  had a tray.
- `scripts/deploy-windows-agent.sh`, if it still exists.

**What must NOT break.** `/dl/version.json` and `/dl/ghoztty-agent.exe` are
still published by `publish-agent.sh` precisely because the self-updater still
reads them; they retire in the SAME change, not before it, and
`test\win32\one-installer.ps1` section C asserts the two sides agree until then.
Any box still running an agent that was installed by the old standalone MSI is
T549's adoption path, which must have run first.
