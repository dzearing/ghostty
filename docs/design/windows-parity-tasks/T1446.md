# T1446 - a REMOTE machine on an incompatible protocol reads as merely unreachable on macOS

## Summary

The macOS half of T628, filed under the platform-symmetry rule. Windows now
tells the difference between a machine that is off and a machine whose Ghoztty
no longer speaks to ours, in the chooser, on the connection pill, in the CLI
error and in `+list --json`; the Mac still collapses both into "couldn't reach
that machine" and retries the skew until its ladder is spent.

Half of the work is already done and shared: `src/remote/tcp_dial.zig` and
`src/remote/relay_dial.zig` are shared Zig and both now raise
`error.ProtocolIncompatible` (T628 taught the relay dialer the discrimination
`tcp_dial` already had, via the shared `classifyHandshakeError`). What is
missing is everything above the dialer, which on the Mac is Swift.

## In plain terms

If a machine you connect to runs a version of Ghoztty that no longer matches
yours, the Mac says it could not reach the machine. So you check whether the
machine is awake, whether the network is up, whether the agent is running — and
all of those are fine. The real answer, that the two versions no longer speak to
each other, is the one thing it does not say, and the reconnect indicator keeps
counting out attempts that cannot succeed.

## Goals

- [ ] A remote dial that fails on an incompatible handshake says so in the
      machine chooser and on the connection pill, rather than "unreachable".
- [ ] The reconnect ladder stops retrying a skew while still retrying every
      transient failure exactly as it does now.
- [ ] Nothing on a remote machine is ever restarted from here — a remote agent
      is not ours to kill; the answer is to update one side.

## Details

The Windows shape to translate, all landed by T628:

- `src/apprt/win32/dial_failure.zig` — pure classification of a dial error into
  unreachable / unauthorized / incompatible, plus the one place each of those
  three sentences is written. This module is pure std and could be shared
  wholesale rather than re-decided in Swift.
- `src/apprt/win32/remote_reconnect.zig` — `DialResult.incompatible` →
  `ProbeOutcome.incompatible_agent` → `.terminal`, and a
  `WindowState.disconnected.reason` that carries the skew out to the pill.
- `src/apprt/win32/remote_pill.zig` — a fourth pill mode whose distinguishing
  signal is TEXT (`winbox — Version mismatch`) and not hue, so WCAG 1.4.1 stays
  satisfied without a fourth colour.
- `MachineConnectionPool.Failure.incompatible` and
  `chooser_sessions.State.incompatible` — the roster's own sentence.

Mac counterparts: `MachinePillView.swift`, the chooser's session browser, and
whatever the Swift side of the reconnect ladder is (`BaseTerminalController`,
`MARK: Remote Reconnect`).

## Validation criteria

- [ ] An acceptance run dials a local agent forced to a different
      `GHOZTTY_AGENT_PROTO_VERSION` over the remote path and the message names a
      version mismatch, not unreachability.
- [ ] The reconnect ladder does not spin on it.
- [ ] The Mac regression build stays green.
