# T874 - Mac SkillComponent/BannerScriptInstaller rollback can delete a previously-installed skill: a failed upgrade removes everything the call wrote, including files that were already installed before it

## In plain terms

If Ghostty on the Mac is refreshing your agent setup and hits a snag halfway
(say your own file sits where the second skill goes), it cleans up by
deleting everything it just wrote — including a skill that was working fine
before the refresh started. You end up with LESS installed than before the
failed attempt. The Windows port already behaves correctly; the Mac app
should match.

## Summary

Found while porting to Windows (T867). `SkillComponent.install()` on Mac
appends every successfully-written URL to `written` and, on any later
failure, calls `removeIfManaged` on all of them — with no memory of whether
the file existed (managed) BEFORE the call. So a re-install/upgrade that
fails on skill 2 deletes skill 1 even though skill 1 was installed and
current before the call began. `BannerScriptInstaller.install()` is worse:
it has no rollback at all, so a mid-install failure leaves a half-pair of
hook scripts with hooks referencing a missing sibling.

The Windows port (`src/apprt/win32/SkillComponent.zig`,
`BannerScriptInstaller.zig`) fixes both: it snapshots each destination's
install state before writing, and rollback removes — in reverse order — only
the files THIS call created (pre-state `not_installed` + successful write).
A file that was already managed keeps the freshly-written content (still
ours; a retry converges it), and is never deleted by rollback. Port that
semantics into the Swift originals.

## Validation criteria

- [ ] Mac unit test: install once, corrupt skill 2's path with a user file,
      re-install fails — skill 1 still present and managed afterwards.
- [ ] Mac unit test: fresh install failing on skill 2 still removes the
      freshly-created skill 1 (the existing rollback behavior for new files).
- [ ] BannerScriptInstaller gets the same created-files-only rollback so a
      failed pair install leaves no half-pair.
- [ ] Mac test suite green.
