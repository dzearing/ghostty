# T563 - The small dialogs and the command palette are still hardcoded dark

## In plain terms

Set Windows to the light theme and the rename box, the confirm box, the banner
editor, the New Process box, the Host Settings box and the command palette all
still come up black with pale grey text, next to a window that is now light.
T308 fixed the two big panels and the carousel; these are the same problem one
size down.

## Summary

T308 gave the panels a derived palette (`panel_theme.zig`, resolved through
`system_colors.panelPalette` from `chrome_theme.chromeBase` + the accent) and
rewired the Activity Monitor, the machine chooser and the hero carousel to it.
It deliberately did NOT touch the smaller dialogs, which still hold the same
"RenameDialog dark palette" literals T308 removed from its three:

- `RenameDialog.zig:79-81` — `COLOR_BG = RGB(32,32,32)`, `COLOR_TEXT = RGB(230,230,230)`
- `ConfirmDialog.zig:60-61` — the same pair
- `BannerDialog.zig:43-45` — the same pair
- `NewProcessDialog.zig:38-40` — the same pair
- `HostSettingsDialog.zig:37-39` — the same pair
- The **command palette**, which is not a dialog and is the surface a user
  opens most: `App.zig:6031` (`RGB(30,30,30)` / `RGB(45,45,45)` behind its
  edit) and `Surface.zig:2194,2513` (`palette_brush`, `RGB(30,30,30)`).

## Fix

The machinery already exists and this should be mechanical:

- `pal()`/`palFor(app)` calling `system_colors.panelPalette(config.window-theme,
  config.background)`, exactly as `MachineChooser.zig` and
  `ActivityMonitor.zig` now do.
- `brush_cache.CachedBrush` for anything that was a process-lifetime brush, and
  `hbrBackground = null` + a `WM_ERASEBKGND` arm for any class that carried its
  background brush (a class brush is captured at registration and cannot follow
  a theme flip).
- A `WM_SETTINGCHANGE`/`WM_DWMCOLORIZATIONCOLORCHANGED` arm so an open dialog
  repaints when the theme moves under it.

Watch the palette specifically: it is a child of the terminal surface rather
than a top-level window, so it will NOT receive the broadcast theme messages
itself — it has to be invalidated from the window that does.
