# T414 - CLAUDE.md documents session-persistence = off|on but the CLI/config bool parser rejects off and on

## Summary

Found by T118 (2026-08-03). CLAUDE.md's Session Persistence section says
`session-persistence = off|on (macOS + Windows, default on)`, and the config
key is a plain `bool` (`src/config/Config.zig:1219`). `cli/args.zig:654`
`parseBool` accepts exactly `1 t T true` / `0 f F false` — **`off` and `on` are
`error.InvalidValue`**. So the documented spelling is rejected, and because a
bad config value is logged and skipped rather than fatal, the setting silently
keeps its default.

## Evidence

Launching an instance with `--session-persistence=off` for T118's acceptance
script did NOT turn persistence off. The instance kept the default (on),
restored the OTHER instance's `session-layout-debug.json`, and re-ATTACHed its
panes — so a `+list` against instance B returned instance A's windows. The
script was measuring a fixture that answered a different question, and it read
as a product failure for one debug cycle. `--session-persistence=false` behaves
as documented-in-prose.

This is the same class of trap as T248: the failure is silent and the wrong
state looks like a plausible test result.

## Fix (pick one, deliberately)

1. **Teach `parseBool` `on`/`off`** (and then `yes`/`no`?) — it is the spelling
   the docs, the tracker and the user's own vocabulary use for this setting, and
   it costs two entries in the existing string lists. Upstream ghostty shares
   this parser, so weigh the divergence.
2. **Fix the docs** — CLAUDE.md, and grep the rest of `docs/` for `= off` /
   `= on` config examples (this may not be the only one).

Whichever way it goes, **an invalid config value for a known key should be
loud** on Windows: it currently costs the user their setting with only a log
line they never see (the release build has no console — see T410).

## Validation

- A unit test in the `none` lane pinning whatever `parseBool` ends up accepting.
- `grep -rn "= off\b\|= on\b" CLAUDE.md docs/` returns nothing that a user could
  paste into a config and have silently ignored.
