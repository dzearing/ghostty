# T574 - +list --json does not report whether a pane is read-only

## Summary

A pane can be in read-only mode, and nothing on the wire says so: +list --json reports type, url, banner, session_id and background_tint, but not readonly. An automation that finds a pane silently swallowing +send-keys has no way to ask why - and now that a badge marks the mode for a HUMAN (T445), the machine-readable half is the missing symmetric piece. Add an additive boolean field (absent or false when off) on both servers, the way session_id and banner were added, and cover it in ipc-p1/p3.

## In plain terms

A pane can be put in read-only mode, where it ignores everything you type. A
human can see that - the pane wears a little "read-only" badge - but a script
could not ask. So an agent that sent keystrokes into such a pane got a cheerful
"sent" and nothing happened, with no way to find out why. After this, `+list
--json` says which panes are read-only, on both Mac and Windows.

## Goals

- [x] `+list --json` reports a `readonly` flag per terminal pane
- [x] the flag is additive: absent (not `false`) when the mode is off, and on
      viewer panes, so older clients see the shape they always saw
- [x] both servers report it - the win32 one and the Mac one
- [x] the wire field is proved end to end against a really-toggled pane

## Validation criteria

- [x] `+list --json` reports `"readonly": true` for a pane toggled into
      read-only mode - `test/win32/readonly-badge.ps1` section B, on a real
      GUI with a real chord (37/37 PASS).
- [x] Per PANE, not per app: with two panes read-only the wire reports two, and
      leaving the mode on one drops the key on that one only - sections F and G
      of the same script.
- [x] Additive: no `readonly` key at all while the mode is off, before it is
      ever turned on and after it is turned back off - sections A and H of the
      same script, plus the `List: readonly is additive (T574)` golden test in
      `src/apprt/ipc/list.zig` (none lane), which pins the exact bytes for
      true/false/absent.
- [x] The two servers do not drift: the T370 shape detector reads the Swift
      encoder's own source and now sees `readonly` on both sides - it FAILED
      with "the Mac encoder emits 'readonly', this encoder does not" until the
      Zig side matched, which is the check working.
- [x] Floor green: `scripts/floor-lane.ps1 -Lane all`, `ipc-p1`/`p2`/`p3`.
