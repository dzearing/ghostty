# T343 - In-place agent recovery matches captured windows by POSITION; the T338 uuid is a real key

Found doing T338 (2026-08-02), which created the identity this task can use.

## The defect

`App.recoverLocalAgentInPlace` (the T229/T230 path: the agent was terminated and
re-dialed under the user's live windows) captures the topology, then walks
`self.windows.items` again and pairs each live window with a captured one **by
position**, replaying the capture's skip rule by hand:

```zig
// src/apprt/win32/App.zig (in-place recovery)
//   "we replay the skip rule here rather than trying to key on a synthesized
//    `win-N` id."
for (self.windows.items) |win| {
    if (win.is_quick_terminal) continue;
    if (win.remote_dialed != null) continue;
    if (win.tab_count == 0) continue;
    defer ci += 1;
    ...captured.windows[ci]
}
```

The comment is honest about why: at the time there was no id worth keying on.
The cost is that the pairing is correct only while the two walks agree exactly -
a skip rule that drifts, or a window closing between the capture and the rebuild
(the capture is followed by a `reconnectForRecovery` that can block for seconds),
silently pairs a window with **another window's** captured topology. There is no
assertion that would notice; every pane would be rebuilt from the wrong tree.

## Why it is worth fixing now

T338 gave every window a stable `layout_uuid`, recorded on the captured
`session_layout.Window` as `uuid`. The pairing can become a lookup by that value,
with a window whose uuid is absent from the capture simply skipped - which is
also the correct behavior for a window that appeared after the capture.

Not urgent: the two walks do agree today, and this has never been observed to
misfire. It is filed because a positional join that has to restate someone
else's filter is a latent defect, and the key that removes it now exists.

## Validation

- Unit: a capture/rebuild pairing helper matches by uuid and skips an unmatched
  window, exercised with a window list reordered between the two walks.
- On box: the acceptance script that covers the T229 in-place recovery confirm
  path still ALL PASS.
