# T942 - The machine chooser probes still take the torn photo - convert the chooser scripts to the synchronous capture

## Summary

T843's second half for `MachineChooser`, unblocked by T940's `WM_PRINTCLIENT`
handler. Switch the chooser probes to `-Sync` and re-run each script several
times.

Scripts, from the T843 survey: `chooser-selection.ps1`, `chooser-sessions.ps1`,
`chooser-session-sort.ps1`, `chooser-session-cpu.ps1`,
`chooser-roster-refetch.ps1`, `chooser-resume.ps1`, `chooser-link-hover.ps1`,
and the `$h` site in `ipc-machine-chooser.ps1` if it targets the chooser rather
than the window behind it.

These assertions are the ones most exposed to a torn frame: they read a row's
text extent and a selection highlight, which is exactly the measurement T835
found reading 1062/1283/1179 px for one unchanged frame.

## In plain terms

The tests that check the machine list — which row is selected, what order the
sessions are in, what the hover looks like — are reading a photograph that can
come out half-taken. This points them at the steady one.

## Validation criteria

- [ ] No `Get-TestWindowPixels` call targeting a chooser window is left without
      `-Sync` (or a comment saying why it cannot have it)
- [ ] Every converted script is ALL PASS over at least 3 consecutive runs
- [ ] The measured flake rate before and after is written into this file
