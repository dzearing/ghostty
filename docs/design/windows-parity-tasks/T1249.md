# T1249 - An unrunnable display explains itself instead of telling the user to reinstall

## In plain terms

On a machine you are connected to remotely, Ghoztty will not start, and the
message it shows says "reinstall it". Reinstalling cannot help: the problem is
the graphics the remote connection gives to programs, not anything about the
install. So the user reinstalls, fails again, and has learned nothing.

After this, the same failure tells them what actually happened - which graphics
their display offers, which one Ghoztty needs, that Remote Desktop is the usual
cause, and what genuinely changes it. The terminal still does not run there;
that is [[T1250]]. This is about not sending them the wrong way while it does
not.

## Split from

[[T1224]], which asked for both halves at once. Making Ghoztty actually run
over Remote Desktop means a second renderer, a vendored graphics library and an
installer change - a project, and one that needs a remote box to validate on.
Telling the truth in the meantime needs none of that and should not wait behind
it.

## What was wrong

`renderer/OpenGL.zig` requires OpenGL 4.3 and returns `error.OpenGLOutdated`
below it. `apprt/win32/startup_error.zig` had no case for that name, so it fell
through to the catch-all remedy: *"Start Ghoztty again. If it keeps failing,
reinstall it."* An RDP session's display driver offers OpenGL 1.1 no matter how
many times Ghoztty is laid down.

Two things were missing, not one. The remedy was wrong, and the dialog never
said what the display actually offered - so even a user who read it carefully
could not tell whether their machine was the problem or the install was.

## What changed

- `src/renderer/gl_report.zig` (new): what the GL context turned out to be -
  version, vendor, renderer string - captured into fixed buffers at load time.
  A leaf module (`std` only) so the startup dialog can read it without
  importing the renderer, and the version floor now has ONE definition, aliased
  by `OpenGL.zig`, rather than a constant in one file and a number retyped into
  a sentence in another.
- `src/renderer/OpenGL.zig`: `prepareContext` records that report and logs the
  renderer and vendor alongside the version, so a bug report from a machine
  nobody can reach still names the driver.
- `src/apprt/win32/startup_error.zig`: `OpenGLOutdated` / `GLInitFailed` get
  their own remedy - names the required version, names Remote Desktop and VMs
  as the usual cause, says using the machine directly or giving the session
  access to its graphics hardware is what works, and says outright that
  reinstalling will not change it. `describeWithDetail` adds a diagnosis line
  between the error name and the remedy ("This display offers OpenGL 1.1 (GDI
  Generic, Microsoft Corporation).") and omits it entirely when there is
  nothing to say.
- `GHOZTTY_GL_FORCE_VERSION=1.1`: a debug-only seam in the context load that
  makes a context report an older version than it has. There is no way to make
  a local GPU report 1.1 from outside the process and no RDP box in this suite,
  so without it the refusal would be one nobody had ever watched fire. It moves
  the reported version only - the shipping floor check, error, reporter and
  dialog all run.
