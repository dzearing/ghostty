# T158 - Sweep test/win32 for scripts that launch without --session-persistence=false

## In plain terms

The Windows tests sometimes fail against a build that is working perfectly.
The reason is that the terminal remembers its windows: a test that starts the
app without saying otherwise gets back whatever panes the previous test left
open, and then measures those instead of the ones it just created. It has
already cost two rounds of chasing a "regression" that was never in the
product. After this, every test launch states what it wants — restore, or a
clean slate — and a check fails the day someone adds one that says nothing.

## Goals

- [x] Enumerate every launch of the app under test in `test/win32` (not just
      the ones a grep for the flag happens to find).
- [x] Give the launches that were silently relying on the default an explicit
      answer: the flag where restore is unwanted, a stated reason where it is
      the fixture.
- [x] Make it a standing check, so a new script cannot re-introduce the class.
- [x] Prove the flag is load-bearing with a live negative control (restore
      happens without it, does not happen with it).

## Summary

A standing script that launches a GUI **without**
`--session-persistence=false` restores whatever panes the last launch left
behind, so its own setup assertions describe someone else's layout. T131 fixed
this for `pane-banner.ps1`; T155 hit it again in `split-dim.ps1` and
`split-zoom-nav.ps1` and fixed those two. Nobody has checked the other ~28
scripts, and the failure mode is expensive: it presents as a product
regression in whatever change happens to be in flight.

Measured during T155 (2026-07-29), in order:

1. Both scripts failed `default setup: 2 visible panes` on a build whose
   pane geometry was independently verified correct (2 panes tiling with a
   1px band, enumerated by hand).
2. `%LOCALAPPDATA%\ghoztty\session-layout-debug.json` held **15 windows** of
   1-3 panes accumulated from earlier runs. Sidelining it moved the failure
   from the FIRST section to the SECOND — proving each section's own launch
   writes the manifest the next section restores. Self-poisoning, so it does
   not even need a dirty box to trigger.
3. Adding the flag to both launchers: `split-dim` ALL PASS (23),
   `split-zoom-nav` ALL PASS (16).

## What the sweep found (2026-08-10)

The suite had grown from ~28 scripts to 144, so the sweep was written as code
rather than done by hand: `test/win32/lib/PersistenceSweep.ps1` enumerates
every launch of the app under test — `Start-OnTestDesktop` and raw
`Start-Process` alike — and resolves the arguments through variables, splats
and helper parameters. **145 launch sites** across the suite, of which 61
already passed the flag directly and 23 more reached it through a variable or
splat.

The remaining 60 had never stated an answer. Sorting them by what they
actually need:

- **56 want persistence ON** and were relying on the default: the `session-*`,
  `agent-*`, `layout-blobs`, `viewer-restore`, `window-name-restore`,
  `tab-tooltip`, `pane-id`, `gui-launch-command` and `relaunch-guard` families,
  plus a handful of CLI invocations (`+list`, `+version`) that open no window
  at all and one launch of `node`. Each of those now carries a
  `# persistence: <reason>` marker naming why — a comment, so no behavior
  moved.
- **4 were the real defect** and now pass `--session-persistence=false`:
  `ipc-read-race.ps1`, `path-selfheal.ps1`, `wheel-scroll.ps1` and
  `update-check.ps1`. All four launch and kill the GUI one or more times with
  nothing to do with sessions; `path-selfheal` and `update-check` relaunch
  repeatedly inside one run, which is the self-poisoning shape from T155.

## Why a declaration and not "always pass the flag"

Roughly a third of the suite WANTS persistence on — for them the flag's
absence is the fixture, not an oversight. So the checkable property is not
"every launch passes the flag" but "every launch declares its intent", which
a reader and the sweep can both tell apart from a launch that never considered
the question. A runtime guard in `Start-OnTestDesktop` was the alternative; it
was rejected because it would force ~60 live edits into the session/agent
family to say what they already do, and every one of those would then need
re-validating to prove it changed nothing.

## Details

Two adjacent hazards found in the same pass were filed rather than folded in,
because each is a 34-file sweep of its own: **T688** (every
`Kill-RepoInstances` copy kills once without verifying, so a survivor turns a
healthy launch into `SETUP FAIL: GUI died at launch`) and **T689** (launches
that capture no stderr leave a dead GUI undiagnosable).

## Validation criteria

- [x] Every launch site in `test/win32` declares its persistence intent —
      section A of `test\win32\persistence-flag.ps1`, 148 sites, 0 undeclared
      (literal=63, marker=57, var=23, callers=5).
- [x] A declaration must carry a value `parseBool` accepts, not just the flag:
      `--session-persistence=nope` is logged, dropped, and restores anyway —
      section B7.
- [x] The sweep has teeth: a synthetic fixture exercises each declaration form
      AND an undeclared launch, so a sweep that stopped finding sites fails
      instead of reporting a clean bill — section B, 7 arms.
- [x] Live negative control: a two-pane window, killed and relaunched, comes
      back without the flag (C2a) and does NOT with it (C3a/C3b) — section C.
- [x] The restored pane is proved LIVE, not a picture (C2b, `Test-PaneLive`),
      and that arm goes red — alone — under `GHOZTTY_TEST_LIVENESS_BREAK=1`.
- [x] `persistence-flag.ps1` ALL PASS (20) x3 on the box, after the value
      check landed (and ALL PASS (19) x3 before it).
- [x] The four behavior-edited scripts ALL PASS x2 each: `ipc-read-race`,
      `wheel-scroll` (4), `path-selfheal` (13), `update-check` (12);
      `ipc-instance-addressability` ALL PASS (16) after its comment fix.
- [x] The 34 marker-only scripts are unchanged in behavior: their diff is 56
      inserted comment lines and nothing else (`git diff --numstat` shows a
      deletion only in the five files edited on purpose), and all 156 scripts
      parse clean (`[Parser]::ParseFile`).
- [x] Floor: P1/P2/P3 ALL PASS; `floor-lane.ps1 -Lane all` →
      `none#1=PASS win32#1=PASS agent#1=PASS`.
