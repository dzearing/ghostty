# T741 - macOS: verify the T666 restored-screen park

## In plain terms

Windows found and fixed a bug where a terminal that comes back after a crash
kept only its last screen and threw the rest of its history away. The fix lives
in code both platforms share, so the Mac build already has it — nobody has
watched it work there.

## What to check

The fix (T666) parks the restored screen into scrollback at the agent's snapshot
head, gated on the peer advertising `grid_snapshot`. Two things are
Windows-shaped and need a Mac eye:

1. **The park itself.** `agent/grid_snapshot.zig` is shared, so a macOS agent
   also opens its post-attach repaint with `ESC[H ESC[2J` — the same eraser.
   Confirm a Mac pane restored twice in a row keeps the scrollback from before
   the first restore.
2. **The widened T106 reflow.** The replay-geometry reflow now runs on the
   snapshot attach path as well as the full-ring one. On Windows this was
   load-bearing (ConPTY's gap-fill is geometry-bound in-place redraws); on a real
   pty it should be a no-op whenever the geometry matches, and harmless when it
   does not. Confirm it does not disturb a Mac re-attach.

## Validation criteria

- [ ] A macOS pane killed and relaunched twice keeps the marker planted before
      the FIRST kill, not just the most recent one.
- [ ] A full-screen (alt-screen) app restored on macOS is unaffected — the park
      deliberately skips the alternate screen, which has no scrollback.
- [ ] `scripts/e2e/session-persistence.py` stays green on macOS.
