# T949 - The release-artifacts guard can never go green on this box: its packaging sections need Docker, and a skipped run does not stamp

## In plain terms

One of the automated checks the loop is required to run before every commit
cannot pass on this machine at all. Two of its sections need Docker, Docker is
deliberately kept off here (starting it has buried the box), and the check
refuses to record a pass unless every section ran. So the gate stays red
forever, and each turn has to wave it through by hand — which is exactly how a
gate stops meaning anything.

## Goals

- [ ] `guard-due.ps1 check` can reach green on this box without Docker running
- [ ] Whatever the packaging sections cover is still covered — the fix is not
      "stop checking", it is "check it somewhere it can be checked"

## Summary

`scripts\guard-due.ps1 check` reports `GUARD DUE release-artifacts` and
`parity-tasks.ps1 validate` fails on it (T783), but
`test\win32\release-artifacts.ps1` cannot clear it here: sections B1/B2 need
Docker + the `msitools-local` image, they SKIP when Docker is down, and the
script only stamps on `failures -eq 0 -and skipped -eq 0` (line ~301 — a
deliberate rule, since a Docker-less run never looked at the packaging it
claims to cover). Docker stays down on this box by user directive (the WSL2
backend has taken the machine out).

Measured 2026-08-17 on the T851 turn: the harness exits 0 with `ALL PASS (2
skipped)`, no stamp is written, and the guard is still due — so the commit went
out under `validate -NoGuardDue`, which is the loud hatch, not a fix.

Options to weigh (mechanism, so whoever picks this decides):

- Split the row: guard the workflow/CI files that only sections A/C-F cover
  with a stamp those sections alone can write, and give the packaging sections
  their own row that is only due when the packaging inputs move.
- Let a Docker-less run stamp the files it DID cover, recording the skipped
  section set in the stamp so a later run with Docker is still due.
- Run the packaging sections in CI (where Docker exists) and have the guard
  read that result.

## Validation criteria

- [ ] `powershell -NoProfile -File scripts\guard-due.ps1 check` exits 0 on this
      box with Docker not running
- [ ] `test\win32\release-artifacts.ps1` still fails (not skips) when Docker IS
      available and the packaging is wrong — `-RequireDocker` proves it
- [ ] `test\win32\go-loop-guard.ps1` ALL PASS (the guard's own harness)
