# T792 - persistence-flag.ps1 is RED: four launch sites still leave session persistence unstated

## In plain terms

Every test that starts the terminal has to say whether it wants the previous
run's windows restored — otherwise a test can poison the next one with the panes
it left behind. A checker enforces that, and right now the checker is failing:
four places start the app without saying either way. Nothing is broken for a
user; what is broken is the check that stops a whole class of test flakiness
from coming back.

## Summary

Found while running T294's neighbouring suites. `test\win32\persistence-flag.ps1`
exits 1 with

```
FAIL  A1 no launch leaves persistence unstated (undeclared: 4 of 178)
      declared by: literal=82, marker=62, =4, var=25, callers=5
```

The four undeclared launch sites (from `Get-GhozttyLaunchSites`):

| file | line |
|---|---|
| `test/win32/agent-attach-refused.ps1` | 276 |
| `test/win32/url-scheme.ps1` | 359 |
| `test/win32/url-scheme.ps1` | 368 |
| `test/win32/url-scheme.ps1` | 381 |

Pre-existing, and not T294's doing: none of those files were touched by it, and
the same failure reproduces at `4ce6ff818`.

Both look like sites the T158 rule expects a **marker** rather than a flag:

- `agent-attach-refused.ps1:276` is section C's `Start-OnTestDesktop -Exe $Exe
  -Arguments @()` — that section's whole subject is the LAUNCH RESTORE against a
  hand-written manifest, so it wants persistence ON and the `@()` is deliberate.
- `url-scheme.ps1:359/368/381` are three `ghoztty-debug://open/...` ACTIVATIONS,
  i.e. the forward-and-exit second-instance path the rule already names as a
  marker case.

So the likely fix is three or four `# persistence: <reason>` markers, not four
flags — but the reason has to be READ off each site rather than assumed, since a
marker that states the wrong intent is worse than none.

## Validation criteria

- [ ] `powershell -NoProfile -File test\win32\persistence-flag.ps1` ends ALL PASS
      and exits 0.
- [ ] Every one of the four sites carries either an explicit
      `--session-persistence=` value or a `# persistence: <reason>` marker whose
      reason matches what that section actually needs.
- [ ] `agent-attach-refused.ps1` and `url-scheme.ps1` both still ALL PASS
      afterwards (a marker must not have been "fixed" by changing what the
      launch does).
