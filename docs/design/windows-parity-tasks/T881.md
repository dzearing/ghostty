# T881 - Mac chooser roster marks live local sessions no window holds ('not in any window' badge) - sibling of win32 T520

## Summary

win32 T520 gave the machine chooser's LOCAL session roster a "not in any
window" badge: a live session on the local agent that no local pane holds and
no other viewer has attached is marked, so a left-over session is
distinguishable at a glance from one another window owns. The Mac chooser
(`MachineChooserView.swift`, the per-session detail rows at `:608-730`) has the
same blindness its Summary describes — its cards show liveness/activity/attach
badges but nothing says "nothing shows this".

Land the same affordance there. The win32 rule to match (see
`chooser_sessions.orphaned`, `src/apprt/win32/chooser_sessions.zig`):

- marked iff LOCAL target AND `alive` AND no local pane/window holds the
  session AND not `attached` by any other viewer;
- `attached` alone is NOT the signal — a momentarily-detached reconnect swap
  must not flicker the mark on (the local-pane check is computed against the
  live window set, which stays stable across the swap), and a session another
  machine's viewer holds is "attached", not "left over";
- dead (even relaunchable) tombstones are never marked;
- badge text "not in any window", warning tone, in the openness badge slot
  (after the activity badge), matching the win32 order which itself matches
  Mac's `MachineChooserView.swift:632-646`.

Note Mac's C API currently drops `relaunchable` (T322) — irrelevant to the
predicate (alive-only) but worth knowing when reading the roster model.

## In plain terms

The background service can keep a terminal session running after its window is
gone. On Windows the session list now labels such a session "not in any
window" so you can spot and resume or kill it; the Mac session list should show
the same label so both platforms read alike.

## Validation criteria

- [ ] With a live session opened directly against the agent (no window holds
      it), the Mac chooser's local roster marks exactly that card.
- [ ] Sessions shown in open windows never carry the mark, including across a
      split/close churn.
- [ ] Resuming the marked session clears the mark.
- [ ] A session attached by another viewer reads "attached", not the orphan
      mark.
