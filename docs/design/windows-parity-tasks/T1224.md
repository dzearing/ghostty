# T1224 - Old soak runs left four autostart entries on the box pointing into the repo

## In plain terms

Four leftover entries are still telling Windows to start a program from a
folder inside the source tree every time the user signs in. The runs that
created them finished a week ago; the entries did not go away with them. At
best they do nothing, at worst they start something half-built. Nothing on the
box has been cleaning them up, and nothing notices they are there.

## Summary

Found while taking the section-D snapshot for T1151. `HKCU\Software\Microsoft\
Windows\CurrentVersion\Run` currently holds, alongside the legitimate
`GhozttyAgent` value:

```
GhozttyAgent-soak-43452 = "D:\git\ghoztty\zig-out-release\bin\ghoztty-agent.exe" ...
GhozttyAgent-soak-47404 = ... (same shape)
GhozttyAgent-soak-47856 = ... (same shape)
GhozttyAgent-soak-48720 = ... (same shape)
```

Each names `zig-out-release` and a `%TEMP%\ghoztty-soak\20260823-*\sandbox`
state directory, so they date from the 2026-08-23 soak runs. They are the
inverse of T1151: that task stops a repo build from WRITING such an entry;
these are entries a repo build already wrote and nobody removed.

Two things to fix, and the second is the one that matters:

1. **Clean up what is there.** The four values, and any `GhozttyAgent-soak-*`
   sibling. Deleting from the user's registry is user-gated, so this is
   OFFERED with the exact command, not done silently.
2. **Make the soak harness own its own registrations.** A sandboxed run that
   registers something must remove it on the way out, including on a crash -
   the same rule the acceptance scripts already follow for panes and agents.
   Check what else the soak leaves behind while there (state dirs under
   `%TEMP%\ghoztty-soak\` are still on disk too).

Worth checking whether the T1146 gate would even allow this today: the soak
runs a release build from `zig-out-release`, which the location gate now
refuses - so the leak may already be closed and this is the cleanup plus a
regression assertion. Establish that first; it changes the size of the task.

## Validation criteria

- [ ] The Run key holds no `GhozttyAgent-soak-*` value (after the user
      approves the removal).
- [ ] A soak run that registers anything removes it at teardown, demonstrated
      by a run whose before/after registry snapshot is byte-identical.
- [ ] If the T1146 gate already prevents the write, an assertion in the soak
      harness (or `registration-sites.ps1`) says so, so it cannot silently
      regress.
