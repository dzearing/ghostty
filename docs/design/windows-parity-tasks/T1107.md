# T1107 - The agent never marks a resumed session as attached, so unattached_since is never cleared

## In plain terms

The background session keeper tracks when a session stopped being shown in a window, so it can tell you about sessions left running on their own. When a session is brought back into a window, that clock is supposed to reset. It does not, so a session you have already reclaimed still counts as abandoned.

## Summary

`test\win32\orphan-notify.ps1` scored `2 FAILURE(S) (11 passed)` in the T1094 sweep:

```
FAIL  the agent reports the resumed session ATTACHED
FAIL  the attach reset unattached_since to null
```

Eleven assertions pass, so detection and notification of genuinely orphaned sessions works; it is the ATTACH transition that does not land. `unattached_since` staying non-null is what keeps the session looking abandoned forever after.

This script was stamped green TODAY (`GUARD CURRENT orphan-notify (3 files, stamped 2026-08-22 from f59d987c5)`) and is red in the sweep hours later - so either the stamp covers a narrower run than the full script, or something landed between. That discrepancy is worth understanding on its own: the guard-due stamp is supposed to mean this harness has been run green against the code as it now stands.

Same two facts fail inside `chooser-orphan-badge.ps1`; one attach-path fix likely closes both.
