# T1244 - Give the update download progress panel a way to stop the download

## Summary

T1195 gave the consented download a progress panel. Closing that panel
dismisses the REPORT, not the transfer: the user consented to install, and
silently cancelling behind a close box would be a different promise than the
dialog made. But there is now no way to change your mind either - a large
download on a bad link runs to completion or to failure, and the app then
quits to install it.

Mac's Sparkle panel carries a Cancel. The mechanism on Windows is an
`InternetCloseHandle` on the connection from the GUI thread, which makes the
worker's in-flight `InternetReadFile` fail; the worker already treats a read
failure as a failed download, so the plumbing downstream exists.

## In plain terms

Once you say yes to an update, the download runs to the end no matter what.
If it turns out to be slow, or you realise you are on a metered connection,
there is nothing to click to stop it.

## Validation criteria

- [ ] The progress panel carries a Cancel that actually stops the transfer
- [ ] A cancelled download stages nothing and never quits the app to install
- [ ] Cancelling says so, rather than reading as a failure
- [ ] The offer is still there afterwards: the balloon path can start it again
