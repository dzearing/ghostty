# T1437 - About twenty fixtures still print 1 for a record that does not exist

## Summary

T617 added test\win32\lib\CountOrZero.ps1 and adopted it in chooser-restore-all-remote.ps1, the script the trap was found in. A grep for the idiom finds roughly twenty more sites across test\win32 (chooser-restore-all.ps1 lines 333-339 are the direct twin, plus chooser-restore-all-adopt.ps1, layout-blobs.ps1, session-crash-recover.ps1 and others). Most GUARD the assertion correctly with an explicit null check, so the verdict is right; what is still wrong is the MESSAGE beside it, which formats the same possibly-null value and prints 1 for a missing record. That is the exact half that did the damage in 2026-08: the assertion went red honestly and the sentence next to it described a plausible product defect, so six days were spent believing the wrong thing. This is a sweep, not a fix - each script touched makes its own guard due and owes a run, which is why it is deliberately separate from T617 rather than smuggled into it.

## In plain terms

When a test here cannot find the record it was looking for, it currently says
"found 1 of them" instead of "found nothing" - a quirk of the scripting language
rather than anything real. The number looks like a genuine measurement, so the
sentence sends whoever reads it after the wrong bug. The helper that says this
correctly now exists; this is the pass that puts it everywhere it belongs.

## Goals

- [ ] Every fixture that counts a possibly-absent record uses the shared helper
- [ ] A message can no longer report a count for a record that is not there
- [ ] Each touched script is re-run so its guard is green rather than merely due

## Validation criteria

- [ ] A repo-wide search for `@($<var>.<field>).Count` in `test\win32` returns
      only sites where the value is known non-null two lines above.
- [ ] `chooser-restore-all.ps1` - the direct twin - reports `<absent>` rather
      than `1` for a missing blob, demonstrated by pointing its lookup at a key
      that does not exist.
- [ ] Every script changed by the sweep has been RUN and its guard re-stamped;
      `guard-due.ps1 check` is clean afterwards.
- [ ] `test\win32\count-or-zero.ps1` still ALL PASS, its negative control
      included.
