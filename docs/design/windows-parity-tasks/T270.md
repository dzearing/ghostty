# T270 - ghoztty.log has no timestamps, so ordering across concurrent processes is unknowable

## Summary

`%LOCALAPPDATA%\ghoztty\ghoztty.log` carries a level, a scope and a message —
and **no timestamp and no pid**. It is a SHARED sink: the GUI app, the agent and
every one-shot `ghoztty +...` CLI invocation append to it, and on this box there
are several a second. So the file is an interleaving of many processes' output
with nothing to tell them apart or place them in time.

T229 lost real time to this. Reconstructing what happened around the three
`user confirmed destructive agent refresh` lines meant guessing which of nine
identical `ghoztty version=...` banners belonged to a GUI and which to a
`+list`, and the pairing of a confirmation to the `showing mandatory restart
confirmation` line that preceded it was **~6,500 lines away** in the file with no
way to prove they belonged to the same process. A question as basic as "did the
app die, or did it sit there for twenty minutes?" is not answerable from this
log.

Sibling of the loss defect T229 fixed (concurrent `seek`+`write` was silently
clobbering lines; now `FILE_APPEND_DATA`). That one made lines vanish; this one
makes the surviving lines unreadable.

## Direction

Prefix every line written to the FILE sink with a timestamp and the pid:

```
2026-08-01T14:22:31.104Z 13060 warning(win32): user confirmed destructive agent refresh (...)
```

- File sink only. stderr (Debug) and the macOS unified log both already have
  their own timestamping, and duplicating it there would be noise.
- The pid is what makes the sink demultiplexable — `Select-String ' 13060 '`
  becomes a single process's log.
- Keep it one `bufPrint` into the existing 2 KB buffer and one `write`: the
  append is atomic per write, so the prefix must not become a second write or
  it can interleave inside a line.
- Cheap: `std.time.milliTimestamp` + `GetCurrentProcessId`, both already
  reachable.

Worth considering alongside: a size cap / rotation. The file is 8.6 MB today
with no bound.

## Validation

- Every line in the file matches `^\d{4}-\d\d-\d\dT[\d:.]+Z \d+ (debug|info|warning|error)`.
- Two concurrent processes' lines can be separated by pid, and each pid's lines
  are monotonically ordered in time.
- Extend `test/win32/log-append.ps1` (which already runs N concurrent writers
  against the real release binary): assert the prefix shape on every line, and
  that the run's own pids all appear.
