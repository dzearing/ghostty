# T1439 - A Restore All whose chooser closed mid-flight has no acceptance oracle

## Summary

Both arms of Restore All post their reply to the APP's message window precisely so a chooser that closed first cannot discard it, and both free everything the job carries on that path. Nothing measures either claim: the relay arm has carried it since T339 and the local arm since T618, and the failure mode - a leaked transport per window, or a rebuild silently dropped - is invisible until someone counts handles. Wanted: an acceptance script that dismisses the chooser while a restore is in flight (the delay seams make the interval reachable now: -SlowConnectMs for the relay, GHOZTTY_RESTORE_PULL_DELAY_MS for the local arm) and asserts the windows still come back, plus the quitting case rebuilding nothing.
