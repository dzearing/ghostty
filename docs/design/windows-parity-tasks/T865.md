# T865 - win32 agent integrations (1/8): no marker-guarded atomic writer exists for agent-config artifacts - port ManagedFile with reparse-point refusal and atomic replace

## In plain terms

Ghoztty is about to start writing files into folders that coding agents like
Claude Code also use. Before it can do that safely, it needs a careful file
writer that only ever touches files Ghoztty itself created, never half-writes
a file, and never follows a booby-trapped link to overwrite something else.
This task builds that writer; nothing user-visible changes yet.

## Summary

First slice of the T598 split (the Mac agent-integration subsystem from
`origin/main`, ~50 commits). Port `ManagedFile.swift` +
`GhosttyManagedMarker.swift` + `ComponentInstallState.swift` to Zig for the
win32 app. This is the foundation every other slice builds on.

Mac source (exported study copies were under the T598 turn's scratchpad; the
originals are on `origin/main` under `macos/Sources/Features/Setup/`):

- `GhosttyManagedMarker`: ONE ownership token, `ghoztty-managed`, with
  per-format comment wrappers (`# ghoztty-managed` for shell,
  `<!-- ghoztty-managed -->` for markdown). Changing the token orphans every
  installed file — single source of truth, never inline literals.
- `ComponentInstallState`: three-state enum `not_installed | installed |
  outdated`, shared by components and the aggregate runtime level.
- `ManagedFile` operations to port:
  - `state(path, expected, marker)`: unreadable → not_installed; no marker →
    not_installed; content == expected → installed; else outdated.
  - `write(contents, path, marker)`: refuse to clobber an existing file that
    does NOT contain the marker (`error.NotManaged`); then atomic write.
  - `writeAtomicNoFollow(contents, path)`: refuse a symlink/reparse point at
    the destination; write to a unique dot-temp in the same directory; atomic
    replace; used markerless for the user-owned `settings.json`.
  - `removeIfManaged(path, marker)`: absent → ok; unmarked → `error.NotManaged`;
    marked → delete.

**Windows translation (mechanism decisions, made per D46 policy):**

- Reparse-point refusal replaces the Mac symlink check: stat the destination
  and refuse `FILE_ATTRIBUTE_REPARSE_POINT` (covers symlinks, junctions, and
  OneDrive-style placeholders). Zig: `std.fs` metadata / `GetFileAttributesW`.
- Atomic replace: write the temp file, then `MoveFileExW(tmp, dest,
  MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` (equivalent of Mac's
  `replaceItemAt`). Expect and surface `ERROR_SHARING_VIOLATION` cleanly —
  T598's notes call out that a locked destination fails here in ways POSIX
  `rename(2)` does not; the error must be a typed failure the caller reports,
  never a half-written file.
- `mode_t`/`chmod` has no Windows analog — drop it (default ACLs inherit from
  the profile dir, which is already owner-only for `%USERPROFILE%` children).
- Temp name: `.ghoztty-<random>.tmp` in the destination directory (same-volume
  guarantee for the atomic move), created with `CREATE_NEW` semantics.
- Put the pure logic (marker/state/expected comparison) where the `none` lane
  tests it; the file-ops half is exercised in the win32 lane with tempdir
  tests (the `claude_setup.zig` vs `ClaudeIntegration.zig` split pattern).

Suggested shape: `src/apprt/win32/managed_file.zig` (file ops + tests) and a
tiny pure module for marker/state so the `none` lane covers the comparison
grammar. Follow the no-mega-files rule.
