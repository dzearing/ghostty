# T364 - The T43 debug tint lightens the bar, so every chrome wash off it steps less far on dark themes

## Summary

Every chrome surface above the bar — an inactive tab, a hovered tab, an icon
button's hover fill — is `color_math.wash(bar, k)`: a fixed FRACTION of the
distance from the bar to white. So the step's absolute size depends on how dark
the bar is, and T43's debug tint makes a dark bar much lighter.

Measured on `--background=#000000`:

| | bar | inactive tab | step |
|---|---|---|---|
| release chrome | `(20,20,20)` | `(34,34,34)` | 14 / 14 / 14 |
| debug marker on | `(102,77,20)` | `(111,88,34)` | **9** / 11 / 14 |

A ~35% smaller step, on a lighter surface where it reads smaller still. It is a
debug-build-only degradation of exactly the separation T206 was filed to create
("inactive tabs should be visible somewhat").

## Details

Filed rather than fixed in T43 because the fix is a design decision, not an
adjustment. Three candidates, none free:

1. **Make the tint luminance-preserving** — adopt the marker's hue and
   saturation, keep the base's brightness. Every wash then steps exactly as far
   as it does in the release build, and `isLight` cannot flip. The catch is
   real: at constant luminance a near-black bar has no room to carry a hue —
   `(30,30,30)` shifted to saturated amber is `(30,25,13)`, a channel distance
   of 21 against a `debug_min_delta` of 48. So it needs a brightness FLOOR for
   dark bases, which reintroduces the problem in the range where it bites.
2. **Lower `debug_tint_amount`** (0.35 today). Cheap, and it only narrows the
   gap rather than closing it.
3. **Make the washes absolute-stepped rather than fractional** where the step
   is a separation signal. The most correct and by far the widest blast radius
   — `tab_shape.INACTIVE_LIFT` / `HOVER_LIFT` and `chrome_theme.hover_wash` are
   shared with the release chrome, so this changes what SHIPS to fix what a dev
   sees.

Note the scope honestly: with `GHOZTTY_DEBUG_MARKER=0` set by the acceptance
harness, this affects only a human running a debug build, and only on a dark
theme. That is why it is a follow-up and not part of T43.

*Validation:* pick one, and assert the property in `chrome_theme.zig`'s sweep —
for every background, the inactive/hover step off the MARKED bar is within some
stated fraction of the step off the unmarked one. A number in a test, not an
eyeball.
