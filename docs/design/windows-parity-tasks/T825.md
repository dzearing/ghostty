# T825 - Viewer: a cross-origin link click leaves the pane for the default browser

## Summary

Main 18acc4f6f taught the Mac viewer to hand cross-origin main-frame link clicks to the system browser and keep same-site navigation in the pane. The win32 WebView2 viewer still follows every link in place, so clicking out of a localhost dev server or a rendered doc renders logged-out inside a cookie store nothing else shares. Windows needs the same routing, over the same shared src/viewer/links.js the merge brings in.

## In plain terms

A viewer pane can show a live web page — a dev server, a local HTML mock, a
website. Until now, clicking a link in one of those followed it right there in
the pane, even when the link led somewhere else entirely. That is a worse place
to land than it sounds: the viewer keeps its own private set of cookies, so a
site you are signed into everywhere else opens signed-OUT here, and there is no
address bar in the browser to get back to.

Now a click that leads out of the page's own site opens in your normal browser,
where your session already lives, and the pane stays where it was. Clicking
around WITHIN the same site — through a dev server's pages, through a local
mock's pages — is unchanged.

## What it is NOT

Only a click the person made, on the top-level page, leaves. Everything a page
does to itself — a redirect, a script navigation, a form post, an iframe — stays
in the pane, because that is the page working, not somebody asking to go
somewhere.

## Goals

- [x] a click out of a live page's site is cancelled and opens in the default
      browser
- [x] a click that stays on the site still navigates in the pane
- [x] a page navigating itself off-site is left alone
- [x] the pane's OWN loads (`--view=<url>`, the address bar, a restored
      session) are never routed
- [x] the policy is unit-testable without a browser, and covered on the box

## Notes

- **WebView2 has no `.linkActivated`.** `IsUserInitiated` turns out to mean
  "not initiated by page script", so it is TRUE for a host `Navigate` as well —
  the first draft of this cancelled the pane loading its own `--view=<url>`.
  The pane therefore counts the navigations it issues
  (`ViewerPane.self_nav_pending`) and subtracts them.
- **Known divergence from Mac:** a script-synthesized `a.click()` is
  `.linkActivated` to WebKit and would route there; WebView2 reports it as not
  user-initiated, so it stays in the pane. Erring that way keeps a page's own
  machinery working.
- Mac's second family of rules — `file://` containment inside the page's own
  directory — has no counterpart here because a rendered `.html` file is served
  from the synthetic `ghoztty-page` host, so the grant IS a host and a link
  cannot spell its way out from under it.
- The right-click menu half of main 18acc4f6f (and `src/viewer/links.js` with
  it) is T826, not this task.
