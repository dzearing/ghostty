# T1301 - Uninstalling a throwaway test product leaves its Start Menu shortcut behind

## In plain terms

Three test harnesses install a throwaway copy of Ghoztty and then uninstall it,
so that the installer can be exercised without touching the terminal you
actually use. The uninstall does not finish the job: the Start Menu entry it
created stays behind, pointing at a folder that no longer exists. Every run
leaves another one, and nothing was checking.

## What is actually wrong

`scripts\msi-test-identity.ps1` rewrites a published package into a throwaway
product. Measured on `win-v1.36.2` on 2026-09-03:

| Component | ComponentId in the published package | after the rewrite |
|---|---|---|
| `C_UserPathEntry` | `{AE832FF0-BD88-5A1A-98AE-C2877CCAD643}` | remapped, non-empty |
| `C_StartMenuShortcut` | `{E4ED7C37-21EB-5C3D-A455-85C590CB13E3}` | **empty** |

A component with no ComponentId is never registered, so Windows Installer does
not believe it is installed. The uninstall log says so in one line:

```
Component: C_StartMenuShortcut; Installed: Null;   Request: Absent;   Action: Null
Component: C_UserPathEntry;     Installed: Local;  Request: Absent;   Action: Absent
```

The install still works, which is what hides it - it is the UNINSTALL that
quietly does less than it says, exactly the shape the rewriter's own header
describes for the blanked *primary keys* it already repairs
(`Restore-DamagedKeys`). This one is not a primary key, so nothing puts it back
and nothing notices: the script's verification pass checks
`Property.ProductCode`, `Property.ProductVersion` and friends, but never asks
whether every `Component` row still HAS a ComponentId.

Left behind on this box by earlier runs, still there today:
`HKCU\Software\dzearing\GhozttyT1194Test` and `...\GhozttyT1209Test`.

## What to do

- Find which write frees the string (the rewrite order is Component GUIDs ->
  Registry keys -> Shortcut name, all inside one session; the string pool is
  refcounted, and `Shortcut`.`Name` is the write that replaces the last use of
  "Ghoztty"). Restore the cell the way `Restore-DamagedKeys` restores a blanked
  key, or reorder so nothing shares a freed string.
- Add the missing gate to the script's verification pass: **every `Component`
  row has a non-empty ComponentId after the rewrite**, and the count of distinct
  ComponentIds equals the row count. A rewrite that half-registers a product must
  fail loudly rather than produce a package that installs and cannot be removed.
- Then delete the `T1301` skip in `test\win32\install-walkthrough.ps1` (F5) so
  the walk asserts the shortcut is gone again, and drop the two leftover HKCU
  keys above.

## Validation criteria

- [ ] A rewritten package has a non-empty, distinct ComponentId on every
      `Component` row, asserted by `msi-test-identity.ps1`'s own verification
      pass (and shown going red against a deliberately blanked row).
- [ ] `test\win32\install-walkthrough.ps1` runs with F5 ENABLED and passes: the
      Start Menu shortcut is gone after uninstall.
- [ ] `test\win32\update-real-msi.ps1` and `test\win32\update-graceful.ps1` are
      still green (the rewriter is theirs too), and neither leaves a
      `HKCU\Software\dzearing\Ghoztty*Test` key behind.
