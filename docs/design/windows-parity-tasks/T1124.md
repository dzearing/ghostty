# T1124 - The ghoztty:// handler is registered pointing into the repo's build output

## In plain terms

Clicking a ghoztty:// link on this machine launches a copy of the app out of the source folder rather than the properly installed one. That means a link can start a half-built or deleted development build instead of the terminal the user actually installed.

## Summary

`test\win32\url-scheme.ps1` scored `1 FAILURE(S) (31 passed)` in the T1094 sweep:

```
FAIL  ...and in particular does not point into this repo
      (got '"D:\git\ghoztty\zig-out-release\bin\ghoztty.exe" "%1"')
```

The registered handler points at `zig-out-release` inside the working tree. 31 assertions pass, so the scheme itself works - it is registered at the wrong target.

Why this matters beyond the test: this is real, current machine state. A `ghoztty://` link clicked by the user right now launches a build out of a scratch directory that gets rebuilt, moved and deleted by ordinary development. It also violates the standing rule that dev work must not reach into the user's installed experience.

The question to answer is HOW it got registered that way, because whatever did it will do it again. A test that registers the handler must restore the previous value, and a dev build should never claim a machine-wide scheme in the first place.

## Where

- the URL-scheme registration (`HKCU\Software\Classes\ghoztty`)
- `test/win32/url-scheme.ps1`
- whatever registers the handler at build, install or test time

## Goals

- [ ] Point the registration back at the installed release and confirm a link opens it.
- [ ] Find what wrote the repo path - a test that did not restore, or a dev build that registers on launch.
- [ ] Make a dev build unable to claim the machine-wide scheme, and make any test that touches the registration restore it on the way out.
- [ ] Have the script assert the restoration too, so this cannot be left behind again.

## Validation criteria

- [ ] the registered handler points at the installed release, verified in the registry
- [ ] the cause of the repo-path registration is identified and prevented
- [ ] a run of `url-scheme.ps1` leaves the registration exactly as it found it
- [ ] `test\win32\url-scheme.ps1` is ALL PASS
