# T1074 - Execute the cutover: merge the windows branch to main once ship-readiness is green

## Summary

T1058 defined the criteria, the machinery and the post-cutover turn shape
(`docs/design/windows-parity-ship-workflow.md`). This task is the act itself:
merging `users/dzearing/windows-amd64` into `origin/main` and retiring the
long-branch path in `go.md`.

**Do not start until `scripts\ship-readiness.ps1 -RunLanes` exits 0.** That is
not ceremony: the gate names its own unmet criteria and every one of them is a
way the cutover can go wrong.

Two of those criteria are not this seat's work. T1073 closes the `behind` gap.
**T87 is the Mac seat's** macOS regression build, and this box cannot run it -
the cutover is explicitly sequenced behind it rather than assumed past it.

## In plain terms

This is the day the Windows work stops being a side branch and becomes the main
line. After it, new features are proposed one at a time instead of piling up.
