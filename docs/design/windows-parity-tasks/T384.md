# T384 - Viewer quote messages reach native and are dropped: no win32 feedback composer (design P10)

## In plain terms

On a Mac, a viewer pane can file feedback — a written note, quoted passages
from what you are reading, and pasted screenshots — straight into the copy of
the repo it belongs to. Windows has none of that. This was the umbrella entry
for the whole missing feature; it has now been broken into six pieces that can
each be built and checked on their own.

into the sub-tasks above and it is closed as a duplicate; do not work it.

## Summary

T375 landed the bridge, so `selection.js`'s Quote button now posts a fully
populated `{"type":"quote", ...}` — text, `headingId`/`headingText`,
`blockSelector`/`blockText`, `offsetInBlock`, `documentOffset` — and
`ViewerPane.applyMessage` parses it and writes a `log.debug`. Nothing consumes
it. On Mac the same message opens the feedback composer and inserts the passage
as a quoted block (`handleQuoteMessage`), and on send the whole thing becomes a
`temp/feedback/new/<stamp>/report.json` folder.

That is `docs/design/viewer-panes-windows.md` P10 ("Feedback capture, deferred,
design-first"), and it had no task file — which is exactly the loose thread the
turn protocol exists to prevent.

*(Correction, 2026-08-08: this task originally said the consequence was a
Quote button that appears to do nothing. It is not — T162/T375 set
`window.__ghozttyHideQuote` (`viewer_bridge.zig:69`) so `selection.js` ships
the Copy half alone on Windows. The consequence is the whole feature missing,
with the Quote button deliberately hidden until there is somewhere to put the
text. T635 removes that flag.)*

## Details

Scope is the whole win32 half of CLAUDE.md's "Worktree feedback capture": the
nav-bar feedback button and its worktree provenance (strategy D — port lookup
first, pane-origin fallback), the composer pill with its screenshot and send
buttons, the `[Image #N]` chips and thumbnail carousel, quote insertion with
the accent bar, and the atomic staged-folder report writer. It is far too big
for one task; the first job is to SPLIT it (`parity-tasks.ps1 new`, parent set
to `skipped(split -> ...)`), the way T90d was split into T372-T375.

Two things T375 already settled and a split should not re-litigate:

- The message arrives parsed. `viewer_bridge.Quote` carries every field Mac's
  `ViewerFeedbackQuote` does, with the same normalization (trimmed text, empty
  strings and negative offsets as null), and it is unit tested in the none
  lane.
- `sourceLine` is NOT in the message and must not be: Mac resolves it natively
  at send time by searching the file for the passage, because mapping rendered
  DOM back to markdown source is unreliable. Windows has to do the same.

*Validation:* per sub-task. The end state is a report folder written under a
real worktree by an on-box acceptance script, with the quote's referential
context intact.
