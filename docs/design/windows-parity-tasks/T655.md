# T655 - Acceptance arm for T532's writer half

## In plain terms

The fix for the dead-restored-windows bug has two parts: one stops a bad
bookmark being written down, the other stops a bad bookmark being trusted. The
second part has a test that fails without it. The first part does not — it was
reasoned about and shipped, which is how a fix quietly rots later.

## What is already proven, and what is not

- **Reader half — proven.** `test\win32\session-reattach-zombie.ps1` section D
  ages the manifest's recorded offset to a phantom value and requires the
  restored pane to be live. Neutering `Connection.resumeOffset` turns it RED
  (D7) with 25 assertions still green.
- **Writer half — not proven.** `termio.Remote` now resets `attach_offset` to 0
  on the three paths that start a fresh byte stream (`did_relaunch`,
  `did_notify`, `awaiting_relaunch`). Nothing fails if that line is deleted,
  because the reader's clamp silently absorbs the bad record it produces. That
  is precisely the shape that gets "simplified away" in two years.

## The arm to write

The invariant is directly observable in the session-layout manifest: after a
notify-policy restore across an AGENT restart, a leaf's
`screen_snapshot_offset` must be a small number belonging to the new stream —
NOT at or above the offset the same leaf recorded before the agent died.

`test\win32\session-relaunch-notify.ps1` already does the hard part (it kills
the agent, restores under each policy, and asserts the notice). It has no
manifest helpers yet; `session-reattach-zombie.ps1` has a `Read-Manifest` /
`All-Leaves` / `First-Snapshot-Leaf` set worth lifting into `test\win32\lib\`
rather than copying a third time.

## Validation criteria

- [x] An arm captures each commanded pane's recorded offset BEFORE the agent
      kill and asserts the post-restore offset is strictly below it.
      `Build-AndKill` snapshots `pane_id -> screen_snapshot_offset` at the last
      moment the dying stream owns it; arm A scores A18/A19 against a manifest
      the app wrote AFTER the restore (checked on the file's mtime, so the dead
      app's copy cannot satisfy it). Green run, 131 assertions:
      `36288->895 | 2254->880 | 2476->607`.
- [x] Teeth verified, not assumed: deleting the `attach_offset = 0` reset in
      `termio.Remote.threadEnter` turns the new arm RED and leaves the rest of
      the script green. Measured with the reset neutered and a Debug win32
      rebuild: `A19 ... (0/3)` FAIL, 130 of 131 still passing, exit 1, and the
      recorded points were exactly pre+fresh (`2254->2864`, `36298->37197`,
      `2665->3549`).
- [x] The manifest helpers live in one place (`test\win32\lib\`), not copied.
      `test\win32\lib\SessionManifest.ps1`, dot-sourced by
      `session-reattach-zombie.ps1` (which lost its copies) and
      `session-relaunch-notify.ps1`. Named `Manifest-Leaves`, not `All-Leaves`:
      the notify script already has a function by that name for the `+list`
      tree, and a dot-source that replaced it would have handed a live-window
      walker a manifest. T1456 tracks the ~20 scripts still hand-rolling their
      own.

## What the arm found on the way

Two defects that had nothing to do with the writer half, and both were only
visible because the arm made the script look at something new:

- `First-Snapshot-Leaf` called its own walker as `@(All-Leaves $m)`. PowerShell's
  `@()` KEEPS the single-element wrapper a `return , $arr` helper hands back, so
  the loop ran once with the whole array as its item and member enumeration made
  `screen_snapshot_offset` an `Object[]`. Latent since the day it was written;
  harmless only because it had never been pointed at a multi-leaf manifest.
  T1455 files the audit for the shape.
- The cast that threw took the whole run with it: `session-relaunch-notify.ps1`
  wraps its body in a `try { } finally { }` with no `catch`, so the unwind ran
  the cleanup and fell through to the verdict with the failure count still zero.
  It printed **ALL PASS (12)** - arms A-F and M never ran - and STAMPED the
  `session-relaunch` guard. The script now scores its own throw. The suite-wide
  version of this rule is `lib\BodyCompleteAudit.ps1`, which only reaches
  scripts scored by `lib\TestScore.ps1`; converting this one is T775.
