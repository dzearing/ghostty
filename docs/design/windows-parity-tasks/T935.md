# T935 - Draw the composer's quoted passages in CSS, and give each quote a real id

## Summary

With the composer a web page, a quoted passage becomes its own block element with the tinted wash and the accent bar as ordinary CSS, and its identity becomes a data attribute on that element rather than something recovered from the text. viewer_feedback_doc.zig derives quote identity by matching passages against line-aligned runs precisely because RichEdit has no per-run user field to hang an id on - a DOM node has one, so deleting a quote drops its metadata because the node is gone, and editing a quote no longer silently orphans it. The report writer keeps its Entry/Span input shape; what changes is where the spans come from.

Split out of T830; read its `## Design` section first.

## In plain terms

When you quote a passage from the page into a feedback report, the quote used
to look like a quote: tinted, indented, with a coloured bar down its left edge.
Moving the composer to a web view last night took that away - a quote landed as
plain text, indistinguishable from what you typed. This puts it back, drawn by
the page itself.

The part you cannot see matters more. The app used to work out which quotes a
report still carried by SEARCHING your text for the passages you had quoted, so
fixing a typo inside a quote quietly detached it from the page it came from -
the report kept the words and lost the link. A quote is now its own thing in the
document with its own name, so deleting it takes its details with it and editing
it keeps them.

## Goals

- [x] A quoted passage is a block again - wash, accent bar and indent - drawn in
      CSS from the same colours and DIP numbers the app derives once.
- [x] Each quote carries its own identity in the document instead of being
      recognised by its text.
- [x] Deleting a quote drops it from the report; editing one keeps it.
- [x] The composer does not grow by a line it is not using when a quote is in
      it.
- [x] Closing and reopening the composer brings the quoted blocks back looking
      like quoted blocks.

## Validation criteria

- [x] The block is drawn by the page: `src/viewer/composer.css` styles
      `#c .q` with the wash, `border-left` accent and indent, every one of them
      a custom property the host writes - asserted by
      `viewer_feedback_page.zig`'s "both assets agree on what a quote block is"
      and the pre-existing "no size or color of its own" test (`none` lane,
      green).
- [x] Identity is the node's, end to end, against a REAL browser: the `host
      floor` test in `ViewerPane.zig` (win32 + agent lanes) quotes a passage
      into a composer holding non-ASCII text and then waits for the page to
      report the block back - `quote: page reported id=1 span=12..39` in the
      win32 lane's log, with the span converted back to bytes covering exactly
      `ghoztty quoted this passage` and naming registry entry 0.
- [x] The pane prefers the page's blocks over text matching, and forgets them
      when the buffer moves behind the page's back: the new
      `T935: the page's quote blocks are the pane's truth...` test builds a
      buffer holding the same passage TWICE, so the DOM answer (the second
      occurrence) is one the old derivation could not produce - win32 lane,
      green.
- [x] Nothing reaches the report writer that it cannot quote: the same test
      feeds `feedbackSetQuoteSpans` a span past the end of the buffer, an empty
      one, an overlapping one and one naming a registry entry that does not
      exist, and only the sane span survives.
- [x] The protocol is unit-tested with no browser: `viewer_feedback_page.zig`
      covers the seed's `quotes` array, a snapshot's, the additive degrade (no
      field = no quotes) and every malformed shape - `none` lane, green.
- [x] The composer does not grow by a line the text does not occupy: the quote
      block is asserted to carry no vertical margin or padding, since the
      wrapped line count is measured as scrollHeight / lineHeight.
- [x] Floor: `scriptsloor-lane.ps1` lib/none/win32/agent ALL PASS,
      `ipc-p1/p2/p3` ALL PASS, `viewer-composer.ps1` ALL PASS (30),
      `viewer-feedback.ps1` ALL PASS (71) on the RichEdit fallback,

## What this deliberately did NOT do

- **A quote still is not undoable** (T983): a native insertion is a
  whole-document seed, which the browser's undo stack sees as one opaque
  replacement. T935 makes the quote a node; it does not make the insertion a
  browser edit.
- **The report format does not yet say which wording is which** for a quote the
  user edited - now possible for the first time, filed as T985.
- **Image chips are still literal text** (T936), and the RichEdit fallback with
  its own quote formatting is still live (T937).
