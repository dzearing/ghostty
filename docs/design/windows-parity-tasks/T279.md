# T279 - Audit PowerShell call sites that put free text on a ghoztty CLI argv (rename --title, set-banner): PS 5.1 silently strips quotes

## Summary

T210 fixed ONE call site — the resume prompt into `+send-keys` — and gave the
CLI a file transport (`--keys-file`) to fix it with. The underlying hazard is
not specific to `+send-keys`: **PowerShell 5.1 does not escape an embedded `"`
when it builds a native command line**, so ANY free text a PowerShell script
hands to `ghoztty.exe` as an argument is at risk, silently.

Measured on the box 2026-08-01 (argv oracle, `python -c` printing `sys.argv`):

| payload | what the child received |
|---|---|
| `pct %LOCALAPPDATA% and plus + and dash -Flag` | intact |
| `single 'quotes' inside` | intact |
| `has a " quote in it` | child never ran |
| `a "quoted phrase" mid string` | child never ran |
| `trailing backslash dir\` | child never ran |

And through `ghoztty +send-keys`, `/reset-context settle the
"DWM/PrintWindow" question ...` arrived **2 characters short with both quotes
gone** — quietly, exit 0.

## Which call sites

The ones that carry text a human or another program wrote, not a fixed literal:

- `+rename --title=<text>` — `scripts/go-loop-exec.ps1` `Set-Mark` builds
  `"--title=$Marker $Label"`; `$Label` is a parameter.
- `+set-banner <text>` — the banner is markdown a caller composed, with `|`
  tables and `[text](url)` links; `~/.claude/scripts/ghoztty-banner.sh` is bash
  (different rules) but any PowerShell caller has this problem.
- `+new-window --title=` / `--command=` / `--working-directory=` with paths that
  can end in `\` (a trailing backslash is the second half of the trap: it makes
  the CRT read the closing quote as escaped).
- `+split --command=`, `+new-remote-window --command=`.
- The acceptance scripts under `test/win32/` that pass titles/commands through.

Grep start: `Select-String -Path scripts\*.ps1,test\win32\*.ps1 -Pattern
'\+(rename|set-banner|new-window|split|send-keys|new-remote-window)'`.

## Deliverables

1. Enumerate every PowerShell → ghoztty CLI call whose argument is not a fixed
   literal, and say for each whether the text can contain `"` or end in `\`.
2. Decide the transport per verb. Two options, and the answer is probably both:
   - a `--<field>-file=<path>` for the verbs that carry long free text
     (`--title-file`, `--banner-file`), mirroring `--keys-file`; or
   - one shared PowerShell escaper for the short ones (`$s -replace
     '(\\*)"','$1$1\"' -replace '(\\+)$','$1$1'`), hoisted next to
     `New-LoopPromptFile` in `scripts/loop-session.ps1` so there is exactly one
     copy. Four copies of a rounding rule is what T257 was about.
3. Whichever is chosen, the CLI's own doc comment and CLAUDE.md say which
   transport is correct for generated text.

## Validation

- Extend `test/win32/ipc-send-keys-fidelity.ps1` (or a sibling) with a case per
  verb: set a title / banner containing `"` and a trailing `\`, then read it
  back with `+list --json` and compare byte-for-byte.
- Every case needs the POSITIONAL-ARGUMENT negative control alongside it. A
  payload that was never broken proves nothing — that is how T210's length
  theory survived for a day.
