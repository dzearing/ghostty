# T1071 - In-place recovery still pairs PANES by index, so a split swapped mid-recovery hands two panes each other's shells

## In plain terms

When the background service that holds your shells is restarted, the terminal
rebuilds your panes underneath you. It works out which pane gets which shell by
counting positions, and it only sanity-checks that the layout still has the
same SHAPE. So if you swap two panes around during the few seconds the rebuild
takes, the shape is unchanged, the count still lines up - and the two panes come
back running each other's programs. T1048 fixed the same counting problem for
tabs; this is the last place it survives.

## Goals

- [ ] Panes are paired to their captured leaf by identity, not by node index.
- [ ] A leaf the capture has no entry for is left alone rather than rebuilt
      from a neighbour.
- [ ] Unit coverage in the `none` lane for a leaf walk reordered between the
      two walks.

## Summary

Last level of the T343/T1048 positional-join class. rebuildTabLeavesInPlace walks node index i and hands captured.nodes[i] to the live tree's nodes[i]; the only licence is a node-SHAPE comparison, which two swapped leaves in an otherwise identical tree pass. The key to fix it - the leaf's pane_id - is already recorded in the manifest.

## Validation criteria

- [ ] Unit: the leaf pairing follows `pane_id` through a swapped tree and
  refuses an empty/absent id (mirror of T1048's `pairTabs` tests).
- [ ] On box: `test/win32/agent-recovery.ps1` and
  `test/win32/agent-recovery-tabs.ps1` still ALL PASS.
- [ ] The new arm FAILS on the pre-fix build - measured, and quoted here the
  way T1048's was.

## Details

`App.rebuildTabLeavesInPlace` re-reads the live tree every iteration (each
replacement re-allocates the node array) and takes `window.tab_trees[ti].nodes[i]`
for captured `tab.nodes[i]`. `capturedNodeShapes` is what licenses it, and it
compares `agent_recovery.NodeShape` only - so a `swap_split` (ctrl+shift+arrow),
a drag, or a `+rearrange` that preserves the shape passes the check with the
leaves exchanged.

The fix has the same shape as T1048: leaves already carry `pane_id` (T113) in
the manifest and the live `PaneView` already answers `paneId()`, so `pairByKey`
in `session_layout.zig` can be reused directly. The empty-key rule matters here
too - a leaf whose OPEN was still in flight at capture time has no id and must
pair with nothing rather than fall back to its index.
