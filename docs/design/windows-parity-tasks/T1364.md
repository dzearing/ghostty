# T1364 - The machine chooser lists sessions whose program already exited

## In plain terms

The list of sessions you pick from when opening a window is supposed to be
"what is still running that you cannot already see". Today it also shows
sessions that finished long ago - the program exited, or the box rebooted -
so the list keeps growing with things that are over, and the useful rows get
buried. After this, a finished session is simply not offered: the list is the
live work you have no window on, and nothing else.

## Summary

The user answered D91 on 2026-09-05:

> the list represents the processes still alive. If we don't have a ghoztty
> window for something still running in the agent, we should list it,
> otherwise if it's a dead process and not working we don't.

T466 assumed the opposite option and shipped it: a session whose child had
exited stayed in the chooser with a "can relaunch" badge, and Return reopened
it on a fresh prompt. That behavior is now the defect. This task makes the
chooser's session list mean exactly what the directive says:

- a session whose program is still running **and** which has no Ghoztty
  window attached to it: listed;
- a session whose program has exited (tombstone): not listed at all;
- (unchanged) a session already shown in a window is not offered again.

Scope includes unwinding the parts of T466 that exist only to offer a dead
row - the relaunch badge and the tombstone arm of `resumeTarget` - without
disturbing launch-time restore, which legitimately revives a tombstone leaf
from a saved layout and is a different path with a different contract.
