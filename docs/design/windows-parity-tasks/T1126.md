# T1126 - profile-latency.ps1 needs a release build, so a Debug suite run scores it as a failure

## In plain terms

One check only makes sense against a properly optimised build, and the suite is run against a debug build for safety. It correctly refuses to run - but it is then counted as a failure, so the suite can never be all-green in a normal run and the number stops meaning anything.

## Summary

`test\win32\profile-latency.ps1` was scored `fail` in the T1094 sweep after 0.9 seconds, having refused to run:

```
GHOZTTY_TEST_ALLOW_RELEASE=1 for the run.
```

This is the `lib\BuildMode.ps1` guard working exactly as intended. The suite is deliberately run against a `-Doptimize=Debug` build, because a non-debug `zig-out` derives the USER'S endpoints and would silently drive the terminal they are sitting in. `profile-latency.ps1` measures latency, which is meaningless on a Debug build, so it declines.

The defect is in the SCORING, not in either the script or the guard. A refusal-by-design is a SKIP with a reason. Counted as a `fail`, it guarantees the suite can never report all-green in its normal configuration - and a suite that always has at least one red trains everyone to stop reading the number, which is the thing T361 built the runner to fix.

There may be other release-only scripts in the same position; the fix should find them rather than special-case this one.

## Where

- `scripts/suite-run.ps1` - `lib\TestScore.ps1` verdict mapping
- `test/win32/lib/BuildMode.ps1` - the refusal and its exit code
- `test/win32/profile-latency.ps1`

## Goals

- [ ] Give the build-mode refusal a distinct exit code (or a recognisable line) that `TestScore.ps1` maps to a SKIP verdict carrying the reason.
- [ ] Add a `skip` column to the suite summary and exclude it from the failure count, while still listing it so nobody forgets it was not run.
- [ ] Enumerate every script that needs a release build, and give the suite a documented way to run that subset against `zig-out-release`.
- [ ] Re-run the suite and confirm the failure count drops by exactly the number of by-design refusals.

## Validation criteria

- [ ] a build-mode refusal is scored SKIP with its reason, not FAIL
- [ ] the suite summary lists skipped scripts separately from failures
- [ ] the set of release-only scripts is enumerated and has a documented way to be run green
- [ ] a Debug-build suite run reports zero failures attributable to the build mode
