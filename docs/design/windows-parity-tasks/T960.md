# T960 - Re-run the divergence inventory monthly so the cost of not merging upstream stays visible

## Summary

D80's option 'merge upstream later in one pass' carries a mitigation that has to exist or the option silently loses its safety net: re-run scripts/divergence-inventory.ps1 on a schedule so the growing gap is measured rather than assumed. Today the inventory is a one-off snapshot (2026-08-16) and nothing re-runs it, so 'the risk set is 131 files' will quietly become false and nobody will notice. Wire it into the daily triage (go.md step 0.6) as a monthly job, or into the digest, and have it report the delta since the last run - risk-set growth, new upstream commits, and whether the Zig-0.16 boundary has moved. Cheap, and it is the only thing that keeps docs/design/windows-parity-merge-back-plan.md honest over time.
