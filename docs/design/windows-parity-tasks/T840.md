# T840 - The T443 soak can load the box with CPU spinners but not with the compiles every sighting actually had

## Summary

test-binary-soak.ps1 -LoadWorkers holds N CPU/allocation processes on the box, which cost the agent lane only ~13% wall clock (192s -> 217s). Every T443 sighting instead happened while another zig BUILD was compiling and testing: memory bandwidth, page faults, disk and heap-manager contention, not just CPU. Give the load a command-shaped form (workers loop a real build/test command) so the condition with all the sightings in it can be soaked as it actually occurred. Note the cache-lock hazard: a second zig build in the same repo shares the zig cache with the measured lane, so a load command must not wedge it - the load must be discardable, the measured lane must not be.

## In plain terms

We are hunting a crash that only shows up when the machine is busy — and every
time it has been seen, "busy" meant another build was compiling and running
tests. The tool that repeats the experiment could only keep the processor busy,
which turns out not to be the same thing at all. This teaches it to hold real
builds on the box while it measures, so the hunt can be run in the condition the
bug actually lives in.

## Goals

- [x] The soak's load can take a COMMAND's shape, not just a CPU's —
      `-LoadKind build` (an isolated `zig build test` loop) and `-LoadKind
      command` / `-LoadCommand "<line>"`
- [x] The load cannot wedge the lane it is timing: a private local cache and
      prefix per worker, and a bare `zig build` load command is refused rather
      than run
- [x] The load is MEASURED, not claimed — completed iterations are counted per
      worker and land in the summary (`load=2:build load-iters=7`), and a load
      that completed nothing says so
- [x] The load is discardable: worker process TREES are killed at the end, and
      the private build caches are removed
- [x] The condition is soaked and the result recorded in T443

## What the design settled, and why

- **Private LOCAL cache, shared GLOBAL cache.** The local cache holds the build
  manifest and its locks, which is the hazard this task's summary names; it is
  isolated per worker and wiped each iteration (or the second pass is a cache
  hit and the load quietly stops being a load). The global cache is a
  content-addressed package store that is already populated. Measured, not
  assumed: a fully private global cache spent its first pass rebuilding
  freetype/harfbuzz and then failed in `zig rc`, which is neither the load shape
  wanted nor a reliable one. Sharing it makes the worker compile THIS repo's
  source, which is what the sightings had next to them.
- **Kill the tree, not the worker.** A worker's `zig build` is a grandchild;
  killing only the worker orphans a compiler that then loads the box for the
  NEXT soak — silently corrupting the measurement this knob exists to make.
- **A zero-iteration load is a failure to report, not a number to omit.** A
  worker whose command never completes leaves the soak effectively unloaded, and
  a soak that still printed `load=2` would be the T832 mistake one level down.

## Validation criteria

- [x] A command-shaped load runs and is counted — `load=2:command` with
      `load-iters` > 0, asserted in section 3c of `test\win32\test-binary-soak.ps1`
- [x] A load that completes no iteration warns and reports `load-iters=0`
      (fixture: a worker command that outlives the soak)
- [x] A worker's grandchild is dead when the soak ends (fixture: a long `ping`
      under the worker; the assertion counts survivors)
- [x] `zig build` as a load command without `--cache-dir` is refused with the
      cache-lock reason, and `-LoadKind build` composes the isolated form —
      per-worker `--cache-dir`/`--prefix`, shared `--global-cache-dir`, on the
      repo's drive (T243)
- [x] `-LoadDryRun` composes and starts nothing
- [x] `test\win32\test-binary-soak.ps1` ALL PASS (52 assertions); floor lanes
      none/win32/agent PASS (292s/349s/191s) and P1/P2/P3 ALL PASS (25/20/16)
- [x] The compile-loaded agent lane actually soaked, with the result written
      into T443 whatever it says — `SOAK T443-compileload: runs=5 pass=5 crash=0
      load=2:build load-iters=8 started=8`, and it says the ghost stayed away

## The measurement this bought (2026-08-14)

The knob was built to answer a specific objection, and it answered it:

- **The load is a different box, and that is measured.** The first round under
  two concurrent isolated `zig build test` loops cost **342s against 192s
  quiesced (+78%)**, where 16 CPU spinners cost 13%. Eight full build iterations
  completed inside the soak.
- **The answer was still zero.** `pass=5 crash=0`. Combined with turn 6's runs
  that is 28 consecutive clean build-runner runs, so "the load was the wrong
  shape" is no longer an available explanation for T443's silence. The write-up
  is in T443's "THE COMPILE-SHAPED LOAD IS NOW MEASURED TOO" section.
- **A negative that closes a cell is the point of the instrument**, not a
  disappointment: the hunt now has one fewer place to look and a soak harness
  that can express the condition next time the signal returns.
