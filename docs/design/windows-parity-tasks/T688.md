# T688 - Kill-RepoInstances kills once without verifying, in 34 private copies

## In plain terms

Some of the Windows test scripts sometimes report that the app "died at
launch" when it did nothing of the sort — a leftover copy from the previous
test was still running, so the new one handed its window to the old one and
exited, exactly as designed. The report reads like a crash, and whoever is
watching goes looking for a bug that is not there. This makes the tests wait
until the box is actually clean before they blame the app.

## Summary

`Kill-RepoInstances` is a five-line private helper, copy-pasted into **34**
scripts in `test/win32/` (`Select-String -Pattern 'function Kill-RepoInstances'`).
Every copy kills once, sleeps ~500ms and returns — it never verifies that the
processes are gone. When one survives the sleep:

- the script's own launch finds the pipe already owned, forwards its
  `new-window` and exits (log line: `another instance owns the IPC pipe;
  forwarding new-window`);
- three seconds later `$proc.HasExited` is true and the script prints
  `SETUP FAIL: GUI died at launch`, which reads as a crash and is not one.

Noted while sweeping the suite for T158. Two adjacent facts matter for the fix:

- `ghoztty +list` / `+split` **auto-launch** an instance when none is running,
  so a stray CLI call between the kill and the launch re-creates the very
  process the kill removed. A verify loop has to run immediately before the
  launch, not at the top of the script.
- `lib\CleanSlate.ps1`'s `Stop-RepoGhoztty` is the shared version of this
  helper and has the same shape — kill, sleep, return a count — so the fix
  belongs there and the copies should route through it rather than growing 34
  private loops.

## Details

Route every copy through a shared helper that polls until the matching
processes are gone (path-exact, as today) or a deadline expires, and reports
which pids survived when it gives up. Keep the path-exact filter: matching on
process NAME would take the user's installed release and its live sessions with
it.

## Validation criteria

- [ ] `Stop-RepoGhoztty` (lib\CleanSlate.ps1) polls until zero matching
      processes remain, or fails loudly naming the survivors.
- [ ] The 34 private `Kill-RepoInstances` copies call it instead of
      hand-rolling kill+sleep.
- [ ] A negative control proves the loop: hold a repo-path instance alive past
      the old 500ms sleep and assert the helper waits for it rather than
      returning early.
- [ ] A sample of the edited scripts still ALL PASS on the box.
