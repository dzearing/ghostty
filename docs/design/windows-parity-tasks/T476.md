# T476 - zig 0.15.2 self-hosted x86_64 backend cannot compile ghostty-test: zig.exe access-violates at a fixed offset, deterministically

## Summary

Measured under **T473** (2026-08-04). Building the test binary with the
self-hosted backend instead of LLVM crashes the compiler:

```
zig build -Dapp-runtime=win32 -Demit-test-exe -Dtest-llvm=false
  -> compile test ghostty-test Debug native-native-msvc failure
  -> error: the following command exited with error code 5
```

`error code 5` is `std.process.Child` truncating an NTSTATUS to a byte
(T444): the real code is `0xC0000005`, confirmed against the Windows
`Application Error` log.

**Four attempts, four crashes, all at the same address:**

| attempt | elapsed | faulting module + offset |
|---|---|---|
| 1 | 12s | `zig.exe+0x0000000000fcb364` |
| 2 | 9s | `zig.exe+0x0000000000fcb364` |
| 3 | 9s | `zig.exe+0x0000000000fcb364` |
| 4 (`-Dtest-filter=terminal.`) | 9s | `zig.exe+0x0000000000fcb364` |

The identical offset every time is what separates this from **T451** (`zig.exe`
taking *sporadic* access violations on this box): this one is deterministic and
reproduces in under 10 seconds. Narrowing with `-Dtest-filter` does not help
and cannot — a filter changes which tests *run*, not what gets *analysed*, so
the compile is byte-identical.

Upstream Ghostty already carries `// Crash on x86_64 without this` next to the
`.use_llvm = true` on this artifact, so the backend has been known-bad for this
tree for a while; what is new is that the failure is now *the compiler dying*,
with an address to report.

## In plain terms

There are two ways to translate this project's code into a program, and the
newer one crashes the translator itself, the same way every time, within ten
seconds. Nothing ships that way today, so nothing is broken for users — but it
removes a tool the team wanted for chasing a hard bug, and it is very likely a
bug in the compiler worth reporting.

## Goals

- [ ] Reduce to a case small enough to report (start from the failing module,
      bisect imports — the crash is fast, so bisection is cheap)
- [ ] File it upstream against zig 0.15.2 with the reduction and the offset
- [ ] Recheck on the next zig the repo moves to, and drop `-Dtest-llvm` if it
      starts working

## Details

- `-Dtest-llvm` is the knob T473 added to `build.zig`; `-Dtest-llvm=false`
  selects the self-hosted backend for the three test binaries only.
- Reproduce in one command from a clean shell:

  ```powershell
  $env:ZIG_GLOBAL_CACHE_DIR = 'D:\zig-global-cache'
  zig build -Dapp-runtime=win32 -Demit-test-exe -Dtest-llvm=false `
      --prefix zig-out-t473\win32-debug-selfhosted
  ```

- Read the real exception back with
  `Get-ProcessCrashEvent -Since (Get-Date).AddMinutes(-5) -NameLike 'zig.exe'`
  from `scripts/lib/CrashDiag.ps1`.
- **P2 on purpose**: nothing we ship uses this backend, so this blocks no
  delivery. It cost T473 one of its two arms, which is the reason to write it
  down rather than the reason to drop everything.

## Validation
