# T827 - Prove +rearrange places viewer panes on Windows, the way main c0c86e88e proved it on the Mac

## Summary

Main c0c86e88e fixed a Mac defect where a layout naming a viewer pane failed with 'pane is no longer alive', making any window holding a preview pane permanently un-rearrangeable, and covered it with RearrangeLayoutTests plus scripts/e2e/rearrange-viewer.py. Reading IpcHandlers.handleRearrange, win32 does not have the defect by construction - it resolves every name to a *PaneView and never through a surface, checks tree membership, and its post-swap focus pick is PaneView-based with a first-leaf fallback - but nothing MEASURES that, so the property is currently an assertion in a task file. Add the on-box coverage (viewer pane in a mixed layout, viewer-only layout, dead pane, wrong window) and, if the check comes back red, promote to P1/M1 and fix.
