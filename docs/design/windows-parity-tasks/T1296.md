# T1296 - git-commit-guard refuses its own commit when -Paths carries a glob, after making it

## Summary

Hit while landing T1292. git-commit-guard.ps1 commit -Paths 'test\win32\*.stamp.json',... stages and COMMITS correctly - git expands the glob - and then the read-back compares the commit's files against the literal glob string, does not match, and reports the T948 'another session's changes landed under this subject' failure. The commit is already made at that point, so the remedy it prints is a reset. Two costs: the message accuses another session of something that did not happen, and a turn that trusts it could reset away work that was its own. Either expand globs into the want-list the same way git does, or refuse a glob in -Paths up front and say so.
