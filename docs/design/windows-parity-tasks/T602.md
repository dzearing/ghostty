# T602 - The Windows machine chooser has no identity header band and its session list cannot be sorted

## In plain terms

The chooser (Ctrl+Shift+N) is where you pick a machine and take over one of its
sessions. On the Mac the machine you selected is now named in a band across the
top, the session list is taller, and you can sort it. On Windows the same dialog
gives you an unsorted list and makes you infer which machine you are looking at.
After this lands, Windows reads the same way: the machine's name and session
count sit in the top band, the list gained about 50 pixels of rows, and CPU and
Name are clickable column headers whose choice is remembered.

## Goals

- [x] The selected machine's glyph, name and session count move into the header
      band, flush left, and the detail pane starts at its action row.
- [x] CPU and Name are clickable column headers over the session list: click to
      sort, click the active one to flip, a chevron marks the active column.
- [x] The order persists across app restarts (LOCALAPPDATA preference file, the
      viewer-chrome pattern).
- [x] Rows sort by the WHOLE percent the meter displays, ties by name then
      session id always ascending, so equal rows never reshuffle.
- [x] The keyboard cursor is anchored to a session ID, so it survives a re-sort
      and a CPU tick.
- [x] One displayed list (`sessionView`) feeds the paint, the hit tests and the
      cursor, closing the Mac cursor-drift bug's Windows analog.
