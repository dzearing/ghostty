# T602 - The Windows machine chooser has no identity header band and its session list cannot be sorted

## In plain terms

The chooser (Ctrl+Shift+N) is where you pick a machine and take over one of its
sessions. On the Mac the machine you selected is now named in a band across the
top, the session list is taller, and you can sort it. On Windows the same dialog
gives you an unsorted list and makes you infer which machine you are looking at.

## Summary

Upstream: `2389d3182` "feat(chooser): lift the machine identity into the header
band, and make the session list sortable" (merged as `ead18cce4`).

Sort keys worth carrying: activity state, working directory, and last-used, with
the choice persisted the way other viewer/chooser preferences are.

Windows chrome rules apply (`docs/design/win32-design-system.md`): the header
band is chrome, so 4 DIP scale, contrast floors, and geometry asserted at
1.0/1.25/1.5/2.0 in the pure layout module.

## Validation criteria

- [ ] The selected machine's identity is visible in a header band without
      re-reading the machine list.
- [ ] The session list sorts by at least the keys the Mac offers, and the choice
      persists across app restarts.
- [ ] Keyboard navigation (T318-T320 paths) still works with sorting applied.
- [ ] Layout geometry asserted at 1.0/1.25/1.5/2.0.
- [ ] Acceptance script drives sort + selection.
