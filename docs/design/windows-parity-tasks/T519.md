# T519 - Mac launch restore logs the T411 gap line: attached N pane(s); M live agent session(s) unattached

## Summary

T411 (win32, done 2026-08-06) made the Windows launch restore compare the live
session ids the agent reports against the ids the restored panes attached to,
and log one line right after `restored N window(s)`:

```
session-restore: attached 3 pane(s); 1 live agent session(s) unattached
```

- `warn` level when the count is nonzero, `info` at zero — the ZERO case logs
  too, because a counter that only appears when nonzero cannot be told from a
  counter that never runs.
- Only ALIVE sessions count toward the gap (a live pinned orphan is a real
  shell holding a session slot the reaper is correctly not allowed to touch);
  dead tombstones are T278's problem.
- A failed roster probe logs `unattached live session count unknown (probe
  failed)` rather than silently omitting the line.
- Win32 keying: `App.leafAttachSessionId` is the ONE attach rule shared by
  `restoreAttachOverride` and the counter, so the two cannot drift.

The Mac restore path (`SessionLayoutRestore.swift`) has the same one-way
blindness the T411 evidence showed on Windows: the app can have both numbers in
hand in the same second and say nothing about the gap. Land the same line there
so a live orphaned session is a grep on either platform.

## In plain terms

When the app starts it reconnects to the terminal sessions that kept running
in the background. If the background service is holding a live session that no
window picked up, that session sits there invisibly, using a slot and a real
shell process, forever. Windows now prints one log line naming the leak the
moment it happens; the Mac app should print the same line.

## Validation criteria

- [ ] After a normal launch restore with no orphan, the Mac log contains the
      zero-case line (`attached N pane(s); 0 live agent session(s) unattached`).
- [ ] With an extra live session opened directly against the agent (no pane
      references it), a relaunch logs `1 live agent session(s) unattached` and
      still re-attaches every layout session.
- [ ] The counted set is ALIVE sessions only (tombstones excluded), matching
      the win32 rule.
