# T718 - The ghoztty agent skill does not mention ghoztty:// links, so generated documents never carry one

## Summary

T695 (Windows) and main's `c36456863` (macOS) give a document the ability to
say "jump to that terminal" with `ghoztty://focus/<target>`. The documents in
question — a worktree dashboard, a build report, a status page — are written by
an agent following the `ghoztty` skill, and the skill says nothing about the
scheme, so nothing emits one.

main updated its bundled copy (`macos/Resources/Ghoztty/skills/ghoztty/
SKILL.md`, +116 lines in `c36456863`). **That file does not exist on this
branch**, and the skill this box actually loads lives in the
dzearing-claude-marketplace repo (plus its plugin cache) — so this is a change
in a different repo, which is why it is filed rather than done inline.

What it should teach: the one form, that `<target>` is anything `--target`
accepts (so `$GHOZTTY_PANE_ID` works), that focus is the ONLY verb and why, and
that a banner link or a rendered markdown link is where such a link is usually
put.

## In plain terms

Ghoztty can now be linked to, but nothing that writes documents knows that yet.
Until the skill says so, the feature is available and unused.

## Validation criteria

- [ ] The `ghoztty` skill documents `ghoztty://focus/<target>`, its one verb,
      and where such a link is usefully placed
- [ ] Patched in BOTH the marketplace source repo and the active plugin cache
      (the standing rule for skill edits on this box)
- [ ] A fresh session asked for a document linking to a pane emits a working
      link; verified on box
