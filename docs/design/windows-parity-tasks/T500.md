# T500 - Consolidate the remaining fixed-name atomic-write copies onto atomic_write.zig

## In plain terms

We just fixed a bug where two parts of the program saving the same file at
the same moment could corrupt it (T183). Three other places in the code still
save files the old way. They are safe today because each has only one writer,
but they are copies of the exact pattern that caused the bug - the next
person who adds a second writer to any of them reintroduces it silently. This
task moves them onto the shared safe helper so the mistake becomes impossible.

## Summary

T183 root-caused the floor-lane flake to `writeAtomic` staging every write at
the FIXED sibling name `<path>.tmp`: two overlapping writers truncate and
rename each other's staging file - one can publish a torn file, the other
fails FileNotFound. The four multi-writer modules (`session_meta`,
`layout_meta`, `ring_snapshot`, win32 `session_layout`) now delegate to
`src/remote/agent/atomic_write.zig`, which stages at a unique
`<path>.<hex64>.tmp` per call.

Three single-writer copies of the old pattern remain (found by grepping
`\.tmp` under `src/`): `main.zig writeInfoFile`, `enroll.zig saveRelayEnv`
(+ its `delete`), and `relay_account.zig`. Each has extra specifics (DACL
hardening, DPAPI) so the consolidation is not purely mechanical - preserve
those behaviors and their tests.
