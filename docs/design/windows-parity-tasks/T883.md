# T883 - Acceptance scripts that assert native stderr text via '2>&1 | Out-String' read '' under a consoleless host - sweep them onto a host-independent capture

## Summary

Found during T526 (2026-08-16). PowerShell wraps a native command's stderr
lines in ErrorRecords when redirected with `2>&1`, and under a **consoleless
host** — which is exactly how the go-loop's automated tool sessions run every
acceptance script — PS 5.1 formats an ErrorRecord through
`Out-String`/`Format-*` as a BLANK line. `ToString()` on the same record keeps
the text, and a detached powershell with its own conhost formats the full
NormalView block. The app is not involved: raw-pipe capture (.NET
`RedirectStandardError`) shows ghoztty writing the correct UTF-8 bytes.

Consequence: any assert that matches stderr TEXT out of a
`$x = (& exe ... 2>&1 | Out-String)` capture silently compares against `''`
when run by the loop. In `viewer-panes.ps1` that hid 14 red asserts behind
what looked like one stale failure (T526); the same pattern exists in ~33
other scripts (54 occurrences — `grep '2>&1 | Out-String' test/win32`),
including `go-loop-guard.ps1` (9), `cli-shim-redirect.ps1` (4), and
`history-guard-flavor.ps1` (3). Occurrences that only capture native STDOUT
are unaffected (strings pass through unwrapped); only stderr-text oracles are
blind.

## In plain terms

Many of our automated test scripts check that a command prints the right
error message. Because of a PowerShell quirk, when those scripts run
unattended the captured "message" is an empty string — so a test can pass or
fail for reasons that have nothing to do with the app. Each affected script
needs its capture switched to a form that keeps the text everywhere.

## Goals

- [x] Every host-dependent capture in the test tree is converted to a shape
      that reads the same in any host
- [x] The trap cannot regrow silently: an audit fails the suite when one
      comes back, and it is wired to a guard row so somebody is obliged to
      run it
- [x] The rule is written down where the next author will meet it

## Details

Two proven-good capture shapes; pick per call site:

1. Stringify each object before joining (minimal diff, what T526 applied to
   `viewer-panes.ps1`):
   `(& $exe @Args 2>&1 | ForEach-Object { $_.ToString() } | Out-String)`
2. `cmd /c "exe args > file 2>&1"` + read the file (what
   `cli-unknown-flag.ps1` already does; bytes on disk, host-independent).

Sweep rule: only sites whose captured value is matched against stderr text
need converting, but converting a stdout-only site is harmless — prefer
consistency within a script. Consider a shared helper in `test/win32/lib/`
so the next script does not re-grow the trap, and a harness-audit rule
(docs/claude/testing.md) naming the pattern.

Note the flip side discovered the same day: in a REAL console the unfixed
spelling works, so these asserts pass when a human runs the script by hand.
That split brain — green by hand, blind in the loop — is the whole reason
this is P1 despite being "just tests".

## What the sweep actually found

The grep in the Summary was the floor, not the ceiling. Three things moved:

1. **56 `2>&1`/`*>&1 | Out-String` sites across 36 files** converted to
   `... | ForEach-Object { $_.ToString() } | Out-String`, `lib\BuildMode.ps1`
   included. Converted wholesale rather than site-by-site: the sweep rule says
   a stdout-only conversion is harmless, and consistency within a script beats
   a per-line judgement nobody can re-check later.
2. **Five `6>&1 | Out-String` sites no `2>&1` grep could ever have found**
   (`floor-lane-cache-heal.ps1` x3, `floor-lane-leak-sweep.ps1` x2). The
   INFORMATION stream carries a helper's `Write-Host` output as
   InformationRecords, and `Out-String` formats those to the host width too.
   Measured on the box: a 300-character `LEAK ...` line came back with a
   newline through it and a `-match` on the whole phrase FAILED, while the
   stringified capture kept it whole.
3. **Two PowerShell file redirections that were text oracles** —
   `build-locked-artifact.ps1` (`& zig ... *> $log`, every assert reads that
   log) and `release-artifacts.ps1`'s D-section — rewritten to stringify into
   the log. `upgrade-no-fork.ps1:422` is left: it redirects to a file nothing
   reads back.

Two harnesses whose guard rows existed but which never STAMPED
(`floor-lane-cache-heal.ps1`, `floor-lane-leak-sweep.ps1`) now do, so those
rows can go current from a run rather than only by hand.

Measured while doing it, for the record: the mechanism is the FORMATTER, not
the console. `Out-String` passes plain strings through verbatim (a
300-character string survives unwrapped at any width) and formats objects to
the host's width — the same `git --nosuchflag` capture came back 774
characters in this box's tool session (width 134) and 778 in a consoleless
child (width 120). Blank is the extreme case of that, not a separate bug.
