# T415 - Mac seat: verify the shared CLI endpoint split (T118) did not change macOS dialing

## Summary

T118 (2026-08-03) split `src/os/ipc_client.zig`'s endpoint resolution into
`endpointPath` (pure derivation, what the server binds) and
`clientEndpointPath` (what a client dials), and pointed `connect` /
`connectWithReset` at the latter. That file is **shared Zig**, so macOS moved
too, and this seat cannot validate it.

## What changed for macOS, precisely

1. `+list`, `+read`, `+version`, `+rearrange` and `+new-remote-window` call
   `ipc_client.connect` directly. They previously used the derivation
   (`$TMPDIR/ghostty[-debug]-<uid>.sock`) and now prefer the pane's baked
   `$GHOZTTY_IPC_SOCKET`, which is what `apprt.ipc.socketPath` (and therefore
   every other verb, via `performIpc`) already did. This should be a
   *convergence*, not a change — that is the claim to check.
2. New precedence rule: an explicit `$GHOZTTY_PIPE_SUFFIX` **outranks** the
   baked endpoint (it exists to let a harness aim at one instance; a pane's
   baked value must not override a caller who is aiming on purpose). On
   Windows this is load-bearing for the acceptance suite. Mac harnesses may
   not set the var at all, in which case this is inert there — confirm.
3. `apprt.ipc.socket_env` is now an alias of `ipc_client.endpoint_env`; same
   string, one definition.

## Validation (Mac seat)

- `zig build test` (none lane) green on macOS, including the three new
  `ipc_client` tests.
- From inside a debug-app pane with the release app also running:
  `ghoztty +list` and `ghoztty +read` reach the DEBUG instance (they are the
  verbs that changed path); `ghoztty +split` still does too (unchanged path).
- From a plain non-Ghoztty shell (no baked var): unchanged behavior.
- `GHOSTTY_IPC_SOCKET=<other app's socket> ghoztty +list` still aims.
- Grep the Mac test scripts for `GHOZTTY_PIPE_SUFFIX`; if any set it while
  running inside a pane, confirm rule 2 is what they want (it is the rule that
  keeps such a script off the user's own instance).
