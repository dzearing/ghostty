# T175 - Machine chooser: master-detail layout shell (T173 split 1/2)

## Summary

The structural half of T173. Today's win32 chooser is a 440-wide single column
(account row / filter / 5-row list / hint / Open+Cancel). Mac's
`MachineChooserView` is a **840x540 master-detail** chooser:

- account row across the top, then a horizontal divider;
- a **fixed 260-wide** machine-list column on a faint wash at the left
  (filter field on top, rows below), a vertical divider;
- a **detail pane** at the right showing the selected machine's glyph (30
  wide), name (title3 semibold) and subtitle line, with a prominent primary
  action (`New Window`) and a management `...` button beside it;
- a divider, then a footer holding **Cancel alone**.

This task ports that shape. The `...` button is **not** created here - a menu
button with no menu is worse than no button - so it lands with T176, which owns
the menu and the actions behind it.

## Outcome (DONE 2026-07-30)

Landed as described. `chooser_layout.zig` is a new pure module holding the whole
840x540 geometry (the old `MachineChooser.Layout`/`layout` moved there and got
its own tests); `MachineChooser.zig` keeps the HWNDs and paints the wash, the
three rules and the detail header in `WM_PAINT`, reusing the row model's GDI
glyph routine at a larger size. `chooser_rows` gained `localDetail`/
`deviceDetail` (what the detail header says) and `columnWash`/`dividerColor`.
The footer's Open button became the detail pane's `New Window`; Cancel is alone
in the footer.

Decisions worth keeping:

- **The detail pane below the header is deliberately empty.** Mac fills it with
  the browsed session list; Windows cannot browse sessions yet (T146). Inventing
  a placeholder would claim a state the app cannot observe.
- **Detail titles.** Local reads `This PC` (Mac says "This Mac"); a device reads
  its name over `Online - <hostname>` / `Offline`, because Mac's "N sessions -
  hostname" subtitle needs the session counts T146 will bring.
- **The list needed `LBS_NOINTEGRALHEIGHT`.** Two bugs found by the new
  shrink-accounting assertion: a listbox snaps its height to whole items at
  CREATION using the DEFAULT item height (our `LB_SETITEMHEIGHT` lands after),
  which shaved a row off and then pinned the height there - so the column
  silently stopped flexing when the status strip wrapped. `chooser_layout` snaps
  to whole rows itself, so the style is safe.
- **`LB_SETCURSEL` does not notify.** Arrow keys had to call `refreshDetail`
  by hand or the pane kept describing the machine you left.

## Details

Mac reference numbers (`macos/Sources/Features/Remote/MachineChooserView.swift`):
client 840x540 (line 270); account row padding 16 horiz / 10 vert (251-252);
master column `.frame(width: 260)` on `Color.primary.opacity(0.035)` (259-260);
filter padding top/horiz 14, bottom 10 (329-330); row list inset 8 horiz / 8
bottom, row spacing 2 (343-344); detail header `VStack(spacing: 14).padding(16)`
with a 30-wide glyph column and 12 gap (440-454); footer `Cancel` right-aligned
with 16 padding (737-742).

Windows-specific decisions to record when doing the work:

- The footer **hint** (T172's grow-to-fit status sentence) has no Mac twin at
  the bottom of the dialog - Mac's equivalent is the refresh/error strip pinned
  to the bottom of the master column (391-407). Move the hint there, and since
  the dialog is now a fixed 840x540, the LIST shrinks by the hint's extra lines
  instead of the dialog growing. `ipc-machine-chooser.ps1`'s "dialog grew by
  exactly the extra hint height" assertion must become "the list shrank by
  exactly the extra hint height" - same no-clipping invariant, measured on the
  control that actually flexes now.
- The detail pane below the header stays **empty** for now. Mac fills it with
  the browsed session list, which Windows does not have yet (T146). Do not
  invent a placeholder that claims a state the app cannot observe.
