# T341 - Action.cval leaves the C union's bytes undefined for void-payload actions

## Summary

`Action.cval` (`src/apprt/action.zig:496`) converts the core's tagged union
into the C ABI union handed to embedded apprts:

```zig
const value: CValue = switch (self) {
    inline else => |v, tag| @unionInit(CValue, @tagName(tag), ...),
};
```

For a **void-payload** action (`toggle_window_decorations`,
`toggle_tab_overview`, `quit_timer`, `quit`, `new_window`, … — most of the
enum) that initializes a zero-size member and leaves **the rest of the union's
bytes undefined**. Every embedded apprt then reads that union through a `C`
struct whose members overlap, and the C side has no tag-payload binding to
protect it.

**T29 is what that costs when a reader picks the wrong member**: the macOS
switch read `child_exited.timetime_ms` for `toggle_window_decorations`, i.e.
uninitialized memory, and a nonzero read popped a "process exited" bar over a
live surface. T29 fixed *that reader*. This task removes the *hazard*: make
the bytes deterministic so the same class of mistake reads a defined zero and
fails visibly-boring instead of randomly.

## Why it is its own task

It is shared core code on the path of **every** action to **every** embedded
apprt (macOS, GTK's C API surface, and win32's own embedded uses). That is a
different blast radius from a one-file Swift switch, and it is testable in the
`-Dapp-runtime=none` lane on the Windows box, where T29's Swift half is not.

## Fix (proposed)

Zero-initialize `CValue` before the `@unionInit`, or build it as
`var value: CValue = std.mem.zeroes(CValue);` then set the active member —
whichever keeps the extern-union layout and costs nothing measurable (these
are a handful of words, dispatched at human speed).

Check first, before writing the fix: whether `CValue` contains any pointer
member for which all-zeroes is a *worse* lie than garbage (a null a reader
might dereference where garbage would have crashed loudly). If so, prefer a
`0xAA`-style poison in Debug and zeroes in release, or say plainly in the task
why zeroing is still the right trade.

## Validation

- A new unit test in the none lane: for each void-payload `Action.Key`, build
  the action, `cval()` it, and assert the union's bytes are all zero — read
  via `std.mem.asBytes` on the `CValue`, not through a typed member (reading
  an inactive member is the very thing under test).
- Assert the populated case still round-trips: a `size_limit` action's four
  fields survive `cval()` unchanged.
- Both lanes + `test-agent` + P1–P3.
