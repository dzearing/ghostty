# T344 - parity-tasks: next hands the Windows loop Mac-seat tasks it cannot do

## Summary

`scripts\parity-tasks.ps1 next` is the loop's task selector once **Current
priorities** is exhausted - which it now is (2026-08-02: every named chain in
that section is done). The first `todo` it returns is **T30, "Mac-side: IPC
dial must not modal-block the app/IPC server"**, whose Validation begins *"Mac
regression build"*. This session runs on the Windows box. It cannot build the
Swift app, so it cannot do T30, and it cannot mark it `done` without violating
THE BAR.

That is a loop stall, not a one-turn annoyance: `next` is a pure function of
the task files, so **every future turn gets the same answer** and has to
re-derive by hand that the head of its own queue is not its work. Behind T30
sit six more of them - T87, T134, T186, T246, T247, T340 - all titled "Mac
seat" or "Mac-side", a convention this tracker has used since T87 and that the
tooling has never known about.

## Details

The tracker already models the split in prose (task titles, and the "Note for
the Mac seat" paragraphs in T132/T240/T150 follow-ups). It does not model it in
data, so `next` cannot act on it. Fix: give a task an optional **seat**.

- New optional frontmatter field `seat:` with three values:
  - `win` - work for this box. **The default when the field is absent**, which
    is what makes the change a no-op for all 340-odd existing files.
  - `mac` - needs a macOS build/run; the Mac seat owns it.
  - `any` - either seat can do it (docs, shared-Zig-only work).
- `next` filters to the requested seat (`-Seat win` by default, so this box's
  behavior is the one that changes), treating `any` as always eligible.
- `list` gains the same `-Seat` filter, and a `Seat` column so the split is
  visible when you look for it.
- `validate` rejects a seat value outside that set, the same way it rejects an
  odd status - a typo'd seat must not silently hide a task from the loop.

**Skipping must be loud.** A task filtered out by seat is not a task that
disappeared; `next` prints how many it passed over and their ids, for the same
reason the workflow rules forbid silent caps. A future Mac session runs
`next -Seat mac` and finds its own queue.

The seven current `mac` tasks get the field: T30, T87, T134, T186, T246, T247,
T340.

Testability: `parity-tasks.ps1` derives its task directory from `$PSScriptRoot`
with no override, so nothing can exercise it without writing into the real
tracker. Add a `-TaskDir` parameter (same escape hatch as
`GHOSTTY_HOST_DEFAULTS` for host defaults) and point the acceptance script at a
temp fixture.

## Outcome (2026-08-02)

Shipped as designed. `seat:` is optional and defaults to `win`, so the change
is a no-op for all 344 existing files; the seven Mac-seat todos carry
`seat: "mac"` and `next` now returns a task this box can actually do, naming
the seven it passed over. `next -Seat mac` gives the Mac seat T30 as ITS head,
so nothing was hidden - the queue was split, not truncated.

Two decisions worth keeping:

- **The skip line scans the whole list, not just the todos ahead of the pick.**
  The first draft accumulated the other seat's ids as it walked, so what it
  reported depended on where this seat's next task happened to sit in file
  order - with a `win` task at the head it reported nothing at all, which is
  the silent-drop behavior the field exists to end. The acceptance script
  caught it (section G).
- **`list` defaults to every seat; `next` defaults to this one.** They are
  different questions. `list` is the human's view of the tracker, where hiding
  rows by default would be a lie; `next` is a selector running on one box.

Positive control: making `Test-SeatMatch` return `$true` unconditionally (the
pre-T344 behavior) turns **15** assertions red across sections B, E, F, G and
I - including *"next no longer returns the Mac-side T30"* against the real
tracker. Reverted; ALL PASS (41) restored.

*Validation:* `test\win32\parity-tasks-seat.ps1` - hermetic, builds its own
fixture task dir under `$env:TEMP`, never touches
`docs\design\windows-parity-tasks\`. Sections: default-seat back-compat (a file
with no `seat:` is `win`); `next` skips `mac` and names what it skipped;
`next -Seat mac` returns the mac task; `any` is returned to both seats; `list
-Seat` filters; `validate` fails a bogus seat and passes a good one; `new
-Seat mac` writes the field. Plus, against the REAL tracker: `parity-tasks.ps1
validate` ALL PASS and `next` returns a `win` task rather than T30.
