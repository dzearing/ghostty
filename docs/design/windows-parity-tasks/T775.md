# T775 - Every acceptance script's verdict goes through the shared scorer, so an uncounted ALL PASS cannot exist

## In plain terms

Our test scripts end with a line that says either "ALL PASS" or "N FAILURES".
About forty of them print that pass line with no number in it, so nobody reading
the result - a person or the loop - can tell a run that checked forty things
from a run that checked none. T271 built the scorer that always prints the
number and refuses to call zero a pass; this is the job of moving the remaining
scripts onto it.

## Summary

T271 landed `test/win32/lib/TestScore.ps1` (`Write-TestVerdict`), which owns the
verdict wording AND the exit code - 0 for a pass, 1 for failures, 2 for a run
that asserted nothing - and fixed the four scripts that could actually score
green having measured nothing. What it deliberately did NOT do is convert the
whole suite: `test/win32/asserted-nothing.ps1` reports the number of scripts
that still print an UNCOUNTED final verdict (39 at the time of filing) and
asserts only that the number does not GROW.

That ceiling is a ratchet, not the goal. Until a script's verdict goes through
the scorer, the invariant is enforced for it only by static shape analysis:
nothing stops it reaching its final verdict with every assertion skipped and
announcing ALL PASS.

## Direction

- Convert the remaining `uncounted-final` scripts (the acceptance script names
  the count; `Get-AssertedNothingSweep` names the files) onto
  `Write-TestVerdict`. Most need a `$script:passes` counter added to their
  `Assert`/`Check` helper - `test/win32/ipc-p1.ps1`, `ipc-p2.ps1` and
  `ipc-p3.ps1` are the pattern-setters, including the `-NoExit` shape for a
  script that must tee its failure line into a transcript.
- Drop the ceiling in `asserted-nothing.ps1` as it falls, and when it reaches
  0, turn `uncounted-final` into a hard kind
  (`Get-AssertedNothingHardKinds`) so a new script cannot reintroduce one.
- Consider `-MinPass` for the scripts that know their own floor: a run that
  scores 3 of its 30 assertions is closer to "asserted nothing" than to a pass,
  and the scorer already reports that as `ASSERTED TOO LITTLE`.

## Validation criteria

- [ ] `test/win32/asserted-nothing.ps1` reports 0 `uncounted-final` scripts.
- [ ] `uncounted-final` is enforced (in `Get-AssertedNothingHardKinds`), and
      `-TeethCheck` still goes red on a synthesized violator.
- [ ] Every converted script still passes on the box, verdict line and exit
      code both.
- [ ] `verdict-exit-audit.ps1`, `skip-visibility.ps1` and
      `harness-exitcode-audit.ps1` stay ALL PASS across the conversion.
