# T1441 - Mac chooser rows never show machine load either (its metrics probe only feeds direct-TCP rows, and nothing creates one)

## In plain terms

Cmd-Shift-N lists the machines you can open a window on. None of the rows says
anything about what the machine is doing, so picking one is a guess — even
though the picker already builds a live connection to every machine it could
show it for.

When this lands, each row carries that machine's live CPU and memory while the
picker is open, matching what the Windows chooser will show (T1440).

## Summary

The Mac seat's half of T1440, and the reason that task exists. Verified by
reading, 2026-09-07:

- `MachineChooserView` starts its probe as
  `probe.start(registry.machines.filter { !$0.isRelay })`
  (MachineChooserView.swift:2014), and `probe.readings` is read ONLY from
  `tcpSublineText`, which is called only in the non-relay branch of
  `subline(for:)` (:1632-1668) and `detailSubtitle` (:627-633). A relay row
  shows `(hostname)` and never a metrics line.
- Nothing ever adds a direct-TCP machine to the registry. `MachineRegistry.add(_:)`
  (Machine.swift:343) has NO callers in `macos/Sources`; `refreshFromRelay` and
  `rebuild` produce relay machines only (:508-554); Machine.swift:262 still
  carries `TODO(wp4): load TCP machines from ~/.config/ghostty`. Every other
  `Machine(...)` construction (AppDelegate.swift:1459, :1585,
  `LocalAgentManager.localMachine`) builds a value for a window or a connection,
  never for the registry list.

So `MachineMetricsProbe` is, in the chooser, wired to a list that is always
empty: the feature its own header describes ("surfacing each machine's live
CPU/memory so the picker can show activity in place of the IP:port") has never
shipped to a user.

## The shape of the fix

Small, because the probe is already written and already correct about
threading and teardown:

- Point `probe.start` at the machines that are actually listed, not at
  `!isRelay` — a relay machine reaches its agent through the relay dial, which
  is what `RemoteActivityMonitor` already does with a resolved token
  (`RemoteActivityMonitor.swift:73`), so the probe needs the relay transport
  alongside `ghostty_remote_connection_new_tcp`.
- Extend `subline(for:)` so a relay row shows the reading when it has one and
  falls back to `(hostname)` when it does not. Two rules survive from the
  current comment and should be kept: status is carried by the leading shape
  indicator alone (never an "Online"/"Offline" line), and the host:port is
  never displayed.
- Whatever the two seats settle on for row layout has to match: this and T1440
  are one feature.

## Validation criteria

- [ ] A chooser row for a reachable machine shows a live CPU/mem reading, for a
      RELAY machine (the only kind the registry actually holds).
- [ ] A machine that cannot be reached keeps its plain subline rather than
      showing a stale or invented number.
- [ ] Closing the picker tears down every probe connection (`probe.stop()` in
      `finish`), asserted rather than assumed.
- [ ] The Mac build is green and the row reads identically to the Windows
      chooser's (T1440).
