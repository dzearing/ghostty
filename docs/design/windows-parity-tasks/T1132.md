# T1132 - The upstream-pull plan is still filed under a name that says 'merge-back', the phrase CLAUDE.md bans

## In plain terms

A planning document is named after a phrase that means three different things in
this project. Twice already someone has read it the wrong way and worked on the
wrong thing for a while. Renaming the file to say which of the three it actually
is costs nothing and removes the trap.

## Summary

T1097 pinned down that "merge back" names three distinct jobs here — the cutover
of this branch onto the fork's `main`, a pull FROM ghostty-org, and contributing
TO ghostty-org (which never happens) — and CLAUDE.md now says never to write the
bare phrase. `docs/design/windows-parity-merge-back-plan.md` is the largest
remaining instance, and it is the *second* sense: a pull from upstream, which
D80 (corrected 2026-08-22) makes the user's call.

The doc's own first section already disambiguates in prose. The filename does not,
and the filename is what a turn sees in a search result.

Rename to something that says which merge it is — `windows-parity-upstream-pull-plan.md`
is the obvious candidate — and update every reference:

- `scripts/upstream-remote.ps1` — `$PlanRelative`
- `scripts/guard-due.ps1` — the `upstream-remote` guard's `Covers` list (T1099)
- `test/win32/upstream-remote.ps1` — section A's `$planPath`
- citations in `windows-parity-divergence.md`, task files, digests and the log

Use `git mv` so the history follows, and grep the whole repo afterwards rather
than trusting the list above.
