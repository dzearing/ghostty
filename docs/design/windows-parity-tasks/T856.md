# T856 - New acceptance scripts can land with audit-violating shapes because the harness audit sweeps run only when somebody remembers them

## Summary

The asserted-nothing ceiling (39) was found exceeded at 41: cli-unknown-flag.ps1 (T489) and window-name-env.ps1 (T492) both landed with uncounted final verdicts, each in a turn that ran its own harness green but never ran test\win32\asserted-nothing.ps1 - the T505 turn caught it only because it happened to run all five audit sweeps. The audits (asserted-nothing, skip-visibility, verdict-exit, exitcode, foreground) are AST/text analyzers that finish in seconds, but nothing at any boundary is obliged to run them: they are not in the P1-P3 floor, and guard-due rows map harness->covered-files, which cannot express 'any NEW script in test\win32'. Options to weigh: a guard-due row whose Covers is test\win32\*.ps1 for a combined fast audit runner; or parity-tasks.ps1 validate running the analyzers directly (they are cheap); or a claim-time report like guard-due check. Whatever the mechanism, the property to hold is: a new or edited acceptance script that violates a sweep fails step 6 validate in the same turn, not N turns later when the ceiling assertion trips for an innocent.
