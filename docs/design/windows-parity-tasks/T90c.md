## Done 2026-08-02

### What landed

`src/apprt/win32/PaneView.zig` — the tree's new view type: a tagged union
`{ terminal: *Surface, viewer: *ViewerPane }` carrying the ref count the
SplitTree protocol drives, plus kind-generic accessors (`hwnd`,
`parentWindow`, `paneId`, `title`, `setVisible`, `bannerLayoutInset`,
`showDimOverlay`/`hideDimOverlay`, `healOverlayZOrders`,
`setSessionCloseIntent`) and the two narrowings (`surface()`, `viewer()`).

`src/apprt/win32/ViewerPane.zig` — scaffolding, so the union is the real
two-armed shape the design pins rather than a single-variant placeholder T90d
would have to re-shape. It carries only what a split-tree leaf must have to be
a normal citizen: HWND, visibility, title, location/home-location, stable pane
id. Nothing constructs one yet.

Retyped: `Window.tab_trees` and `tab_active_surface` → `tab_active_pane:
[64]*PaneView` (the active pane MUST be able to be a viewer, or a focused
viewer is unrepresentable), `IpcRegistry.Target.pane` → `*PaneView`,
`IpcHandlers.SplitTree`, `newSplitAt(at: *PaneView)`, `findTabIndex` /
`findHandle` / `leafAt` / `leafIndexOf`, `closeSplitSurface` →
`closeSplitPane`, `closeTabMode`, `heroOnSurfaceFocused` →
`heroOnPaneFocused`, plus HeroCarousel, MachineChooser, SessionRoster,
RenameDialog and App.zig call sites.

### Two decisions worth keeping

**Ownership goes one way and the count lives in ONE place.** The PaneView
holds exactly one reference on the Surface (taken in `createTerminal`,
released when its own count hits zero); `Surface.ref_count` is unchanged, so
its hide/deinit/destroy teardown is byte-identical. `Surface.pane_view` is a
back-pointer for the destroy paths that only hold a `*Surface` — chiefly
`Surface.deinit`'s `ipcForget`, whose registry key is now the leaf. It is
deliberately NOT cleared before `Surface.unref`: teardown reaches back through
it, so the PaneView is freed *after*, not before.

**`destroyUnowned` exists because `unref` on a count of zero underflows.** A
pane that never entered a tree (a `SplitTree.init`/`split` that failed after
`createTerminal`) has never been ref'd, so `unref` would wrap the `u32` to
`maxInt` and leak everything under it. Three call sites use it.

### One real bug fixed on the way

`newSplitAt` had a **double free on its error path**, pre-existing and
independent of this retype: a function-wide `errdefer` freed `new_surface`
while the later `defer insert_tree.deinit()` — which runs FIRST, defers being
LIFO — had already unref'd it to zero and destroyed it. Any failure of
`tab_trees[tab].split(...)` hit it. Cleanup now hands off in one direction:
once `insert_tree` owns the pane, its deinit is the only thing that frees.

### Deliberate no-ops, not omissions

Viewer arms that do nothing today, each because the capability is genuinely
terminal-only or lands in a named later task: hero snapshots (viewers are
excluded from hero mode, T90a §15), banners (`+set-banner` rejects viewers),
activity state, close-confirmation (a viewer runs no process), agent
close-intent, scrollbars, live-resize. Dim overlays and z-order healing are
no-ops only until T90d gives a viewer a host window.

The terminal-only IPC verbs now answer `<target> is a viewer pane, not a
terminal` (CLAUDE.md's documented text) instead of type-erroring; `+list` and
the session manifest grew their viewer branches (`"type": "viewer"` + `url`;
`kind` / `viewer_location`). All unreachable until T90d constructs a viewer —
coverage belongs to T90d/T90h, noted in **T371**.
