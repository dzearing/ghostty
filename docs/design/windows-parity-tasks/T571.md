# T571 - The banner chevron's hovered FILL is a permanent SKIP in pane-banner.ps1 - give it the DIB-paint oracle T165 used for links

## Summary

The chevron's hovered FILL had no proof for months: on the background test
desktop there is no real pointer, so Windows delivered WM_MOUSELEAVE a frame
after every posted WM_MOUSEMOVE and the hovered frame was gone before the
capture read it. `pane-banner.ps1` printed `SKIP T209 chevron fill` on every
run.

Re-verified on 2026-09-05: half of that is already gone. T282/T845 moved the
capture onto the app's own GUI-thread stack (`Get-TestHoverCapture`), so
section 6g now asserts rest / hovered / hovered-elsewhere and the rounded
corner for real. What is still missing is the half this task named: the rule
itself - a fill that is absent at rest, lit off the CARD's color, and rounded
away at the corner - is arithmetic, and there is no test of it in the zig lane
at all. So the deliverable is T165's DIB oracle applied to the chevron: paint
one overlay twice into a `CreateDIBSection` memory DC with only
`hover_chevron` different and read the two frames, with the acceptance script's
6g comment pointing at it.

## In plain terms

Hover the little arrow at the top-right of a banner and it lights up, the way
every other button in the chrome does. Proving that on a real desktop needs a
real mouse pointer, and for a long time the test machine had none - so the
check quietly gave up every run. Now the same rule is checked a second way,
by painting the banner twice in memory and comparing the two pictures, which
needs no pointer at all. If the arrow ever stops lighting up, something says
so.

## Goals

- [x] A test that proves the hover fill without a pointer, a desktop or a
      timing window.
- [x] It checks the exact color, that the fill is absent at rest, and that
      the corner is rounded.
- [x] It is shown to fail when the fill is taken away.
- [x] The acceptance script says which half it still owns.

## Validation criteria

- [x] A zig-lane test paints the chevron at rest and hovered into a memory DC
      and asserts the fill's exact color, its absence at rest, its rounded
      corner, and that nothing else on the row moved - `banner overlay: the
      chevron's fill lights on hover and is rounded` in
      `src/apprt/win32/BannerOverlay.zig`, green in `zig build test
      -Dapp-runtime=win32`.
- [x] It runs at four DPI scales (1.0 / 1.25 / 1.5 / 2.0) and takes its
      geometry from `icon_button.fillRegion` rather than re-deriving the
      inset, so it cannot agree with itself while disagreeing with the paint.
- [x] It is SHOWN to fail: with `icon_button.T204_NEUTERED = true` the win32
      test lane reports `'apprt.win32.BannerOverlay.test.banner overlay: the
      chevron's fill lights on hover and is rounded' failed: expected 30,
      found 20`, alongside the two icon_button neuter tests. Flag restored to
      `false` after the run.
- [x] `test\win32\pane-banner.ps1` section 6g names that test, and says which
      half each side owns - the pixels there, the pointer reaching them here.
