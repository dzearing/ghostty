# T1188 - Cleanup screen: inventory every Ghoztty on the box and remove the temporary ones, so the official release installs onto a clean machine

## Summary

T1179 needs a machine with no prior Ghoztty, and this box has at least four (installed release at %LOCALAPPDATA%\Programs\Ghoztty, the Desktop portable ZIP, the homeassistant share copy, and zig-out* dev builds) plus MSI ARP registrations, a user PATH entry, Start Menu shortcuts, an HKCU Run entry for the agent, named pipes, the DPAPI credential store and session state. Build a cleanup screen that INVENTORIES all of it with provenance (path, version, build date, which category) and lets the user remove the temporary and dev artifacts, then re-audits and reports clean. Two hard guards, both already paid for: (1) it must NEVER offer msiexec /x on the ghost 26.7.502 ARP entry {A10466B5-D625-4A80-95D2-8AA648F5086C}, whose uninstall would delete same-path files from the LIVE install; (2) nothing is removed without explicit per-item confirmation - the screen proposes, the user disposes. The clean verdict it prints is the precondition T1179 asserts.

## In plain terms

Over months of building and testing, copies of Ghoztty have piled up all over
this machine - an installed one, two portable ones, half a dozen leftover build
folders, plus the entries Windows keeps about them: a Start Menu shortcut, a
line in the PATH, autostart entries, an Apps & Features listing, and a folder of
saved sessions and sign-in details. Nobody can say from memory what is really
there. The next step in the install work needs a machine that has never had
Ghoztty on it, and "I think I deleted everything" is not good enough.

This adds a cleanup screen: run it and it lists every trace of Ghoztty on the
box, says where each one came from, and offers to remove them one at a time -
asking before each, never removing anything on its own. When it is done it looks
again from scratch and prints a plain verdict: clean, or here is exactly what is
still here. Anything you decide to keep on purpose, you say so and it remembers
why. One listing is never offered for removal at all, because uninstalling it
would delete the terminal you are actually using.

## Goals

- [x] One screen that inventories every Ghoztty artifact class on the box, with
      provenance for each
- [x] The known ghost Apps & Features entry is never offered for uninstall, and
      no uninstall command for it is ever printed
- [x] Nothing is removed without an explicit per-item yes; unanswered means keep
- [x] After removing, it re-audits from scratch and prints a clean/dirty verdict
- [x] A deliberate keep is recorded on disk with its reason, so the verdict
      survives the pane it was printed in
- [x] An acceptance harness with a negative control proving the ghost guard is
      real

      edit to either file makes the harness due and `parity-tasks.ps1 validate`

## The clean verdict this produces (for T1179)

`verdict` exits 0 only when every removable artifact is GONE, explicitly kept
(`keep <id> -Reason "<why>"`, recorded in `temp\ghoztty-cleanup-keep.json`), or
permanently protected. An unaccounted artifact is the only thing that makes the
box dirty, and it is named in the verdict with its path. That output is what
T1179 step 2 records as evidence that "no prior Ghoztty" was true rather than
assumed.

## What the first real run found

Read-only `inventory` on this box, 2026-08-30: 24 artifacts. Four installs (the
release, the Desktop portable, the share copy, six `zig-out*` dev prefixes), the
protected ghost `Ghoztty 26.7.502`, a stray `Ghoztty Remote Agent 1.12.1`
registration nobody had noticed, six HKCU Run entries (the agent, the go-loop
watchdog, and FOUR leftover soak-test agents from 2026-08-23), two settings
keys, the PATH entry, two Start Menu shortcuts, and a 750 MB state directory.
None of that was written down anywhere before this ran.
