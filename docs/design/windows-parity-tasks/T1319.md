# T1319 - Nobody has measured what a session-layout capture costs the macOS UI thread

## Summary

The Windows seat measured its layout capture at 195-991 ms on the UI thread with eight panes printing (T412, T1311): almost none of it the dump, nearly all of it waiting on each pane's renderer_state.mutex while the IO thread feeds output. macOS runs the same core dump (Surface.sessionSnapshot) from SessionLayoutManifest's capture, on the main thread, and nothing there has ever put a number on it. Measure it at 1/3/8 panes idle and flooded, the way test\win32\layout-capture-cost.ps1 does, and decide from the number whether the Mac path needs the same treatment - carrying screens forward on topology-only triggers, and a bounded pass when a forced capture lands mid-flood. macOS has no periodic refresh tick, so the 30-second ceiling case T1311 fixed does not exist there; the mutation-triggered captures do.
