# T674 - A job-escape tier that needs no shell window, so a daemon still escapes headlessly

## In plain terms

Ghoztty starts its background service in a way that keeps Windows from
shutting the two down together. That works when there is a desktop to lean on,
and quietly does not when there is not — so in an automated or headless run the
service is back in the same group as the app. Nothing a normal user sees today,
but it means the protection is conditional, and a protection you cannot state
unconditionally is one nobody can rely on.

## Summary

`job_spawn.spawnEscapingJob` (T524, generalised in T426) escapes the caller's
Windows job object in three tiers:

1. `CREATE_BREAKAWAY_FROM_JOB` — **refused with ACCESS_DENIED on this box**.
   Measured again in T426: the app's own job reports `LimitFlags = 0x2000`
   (`KILL_ON_JOB_CLOSE`, and no `BREAKAWAY_OK`), and nested-job breakaway needs
   every job in the chain to permit it.
2. Shell-parent hop (`PROC_THREAD_ATTRIBUTE_PARENT_PROCESS` at explorer) — the
   tier that actually fires in production. It needs `GetShellWindow()`.
3. In the job, loudly.

So the escape rests entirely on tier 2, and tier 2 rests on there being a
shell. There is not always one: on the acceptance harness's background test
desktop `GetShellWindow()` returns nothing and both the agent spawn and the
relaunch-guard arm degrade to tier 3 — measured in T426
(`agent-upgrade.ps1` arm H: `job escape=IN-JOB (degraded)` for both). A
Ghoztty started from a service, a scheduled task, or any session without
explorer is in the same position.

## Where to start

Candidate tier between 2 and 3, none validated yet:

- **`Win32_Process.Create` over WMI** — the new process is created by
  `WmiPrvSE.exe`, i.e. in a completely different job context, and needs no
  window station or shell. Costs a COM call and an explicit environment (same
  problem tier 2 already solves).
- **A pre-existing jobless anchor** — any process the app can already open with
  `PROCESS_CREATE_PROCESS` and that is known not to be in a killable job, used
  the way tier 2 uses explorer. `GetShellWindow` is only one way to find one.
- **Task Scheduler** (`ITaskService`, run-on-demand) — heavyweight, but it is
  the OS's own answer to "start something that is nobody's child".

Whatever is chosen, the tier ordering must stay: cheapest reliable escape
first, and the degraded case stays loud.

## Validation criteria

- [ ] A new tier fires where tier 2 cannot, proven on the background test
      desktop (`test\win32\lib\TestDesktop.ps1`), where today's escape degrades
- [ ] `test\win32\agent-job-escape.ps1` passes when RUN ON THAT DESKTOP, not
      only on the interactive one
- [ ] `agent-upgrade.ps1` H23/H24 can be tightened from "named its tier / was
      loud" to "escaped", because degrading is no longer expected there
- [ ] The spawned process still gets the app's environment, not the donor's
      (the trap tier 2 already documents)
- [ ] Floor green
