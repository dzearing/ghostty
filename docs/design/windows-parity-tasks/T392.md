# T392 - Viewer link routing: NavigationStarting policy (split from T90f)

## Summary

NavigationStarting policy for file-mode viewers: http(s) -> default browser, relative .md -> viewer split, other local file -> default app; web-mode in-pane navigation preserved. Pure policy in viewer_content.zig + a win32 handler.

## In plain terms

Click a link inside a rendered markdown or code file on Windows and, until
now, the wrong thing happened: the pane itself tried to load the link, so a
web link took over the document you were reading and a link to another file
went nowhere useful. Now links behave the way they already do on the Mac
build: a web link opens in your normal browser, a link to another markdown
file opens as a new viewer pane beside the one you are reading, and a link to
any other file opens it in whatever app normally handles it. Websites shown
in a viewer pane are untouched - they still navigate inside the pane like a
browser.

## Goals

- [x] In a file viewer, clicking an http(s) link opens the default browser,
      not the pane.
- [x] Clicking a relative link to a markdown file opens a viewer split next
      to the pane (only if the file exists).
- [x] Clicking a link to any other local file opens it with its default app.
- [x] Website viewers keep navigating in-pane; reloads and back/forward in
      file panes are untouched.
- [x] The whole policy is pure and unit-tested; the COM half is proven by a
      live test that never opens a real browser.
