# T1440 - Machine chooser rows do not say how busy each machine is

## In plain terms

Ctrl+Shift+N lists the machines you can open a window on. Every row shows a
name, a status dot and (sometimes) a hostname — nothing about what the machine
is doing. Picking one is a guess: you cannot tell which box is idle and which
is pinned until you are already on it and typing.

When this lands, each row carries that machine's live CPU and memory while the
picker is open, so the busy box is obvious before you commit to it. A machine
that cannot be reached says so instead of showing a number that is not true.

## Summary

**This is a feature, not a parity gap** — filed out of T619's re-verification,
which found the parity claim behind it to be false in both directions:

- Mac's `MachineChooserView` does own a `MachineMetricsProbe`, but it starts it
  as `probe.start(registry.machines.filter { !$0.isRelay })`
  (MachineChooserView.swift:2014) and reads it only from `tcpSublineText`,
  called only in the **non-relay** branch of `subline(for:)` and
  `detailSubtitle`. A relay row shows the hostname and never a metrics line.
- And nothing ever puts a direct-TCP machine in that registry:
  `MachineRegistry.add(_:)` (Machine.swift:343) has no callers, `refreshFromRelay`
  produces relay rows only, and Machine.swift:262 still carries
  `TODO(wp4): load TCP machines from ~/.config/ghostty`.

So no user on either platform has ever seen load on a chooser row, and the two
platforms are level. The IDEA is still good — it is the one T619 wrote up, and
it is what `MachineMetricsProbe`'s own header says the probe exists for
("surfacing each machine's live CPU/memory so the picker can show activity in
place of the IP:port"). This task is that idea, filed honestly.

**Twin: T1441 is the Mac seat's half.** Under the platform-symmetry rule this
ships on both or neither; the Mac half is the smaller job, because the probe is
already written and only its input list and its relay branch need to change.

## What the Windows half has to build on

Every piece already exists, from T298's Activity Monitor work:

- `activity_probe.zig` — pure policy, and reusable as-is: `want` (which machines
  to probe, deduplicated, capped), `retryDelayMs` (30 s doubling to a 5 min
  ceiling), `isStale` (five missed pushes retires a reading), `parseHostPort`.
- `activity_probe_conn.zig` — the connection half: dial on a detached thread,
  `(slot, serial, gen)` landing rule, unsubscribe-before-join-before-free.
- `MachineConnectionPool` (T461) already holds ONE warm connection for the
  chooser's SELECTED machine, and `SessionCpuProbe` (T462) already rides it.
  `Connection` has separate `metrics_handler` and `session_cpu_handler` slots
  (connection.zig:984-987), so the selected machine's metrics can ride the
  pooled connection rather than opening a second socket to the box you are
  about to open a window on.

## Decisions it has to make rather than copy

- **Which rows get a probe.** The chooser can list up to 128 devices and the
  probe budget is 8. The filtered/visible rows are the candidate set, which
  means the set churns as the user types — the retry backoff must survive that
  churn rather than restarting on every keystroke.
- **Where the reading goes.** Mac replaces the subline. Windows' relay subline
  already carries the hostname, which Mac deliberately keeps; the row has no
  third line.
- **Teardown.** The chooser is modal and short-lived and has no message-only
  window of its own, so a dial that lands after the dialog closed must free
  what it was handed — the `(slot, serial)` rule, and `SessionCpuProbe`'s
  route-by-chooser-id posting to the app's message-only window.

## Validation criteria

- [ ] A chooser row for a reachable machine shows a live CPU/mem reading.
- [ ] A machine that refuses the dial shows its plain subtitle, not a spinner
      that never resolves, and is not re-dialed in a tight loop.
- [ ] The SELECTED machine gets its reading without a second connection to it.
- [ ] Closing the chooser with dials still in flight frees every connection —
      asserted on the socket count, as `activity-monitor-remote.ps1` H7 does.
- [ ] Both `zig build test` lanes plus `zig build test-agent` green; P1-P3 ALL
      PASS.
