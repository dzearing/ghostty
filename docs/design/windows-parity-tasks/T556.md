# T556 - The tab tooltip could also rescue truncated tab titles (show the full title above the cwd when the strip elided it)

## In plain terms

When lots of tabs are open, a tab's name can get cut off with "…" and there
was no way to read the whole thing without clicking around. Now hovering
that tab shows its full name in the little tooltip, on a line above the
folder path it already shows. Tabs whose names fit keep the simple
one-line tooltip — nothing gets noisier.

## Goals

- [x] Hovering a tab with a cut-off title shows the full title above the cwd
- [x] Tabs whose titles fit keep the one-line cwd-only tooltip
- [x] The tooltip control actually renders two lines (multiline enabled)

## Summary

Follow-up to T447, which noted the tooltip plumbing "is reusable for
truncated tab titles". T235 sizes a tab to its content capped at 50% of the
run, so a long title can still be elided when many tabs compete. When the
hovered tab's painted title is elided, the tooltip should carry the FULL
title as a first line above the cwd (a two-line tip: title, then path).
When the title fits, the tooltip stays cwd-only — no redundant line.

Where: `Window.tabTipTextFor` (compose), `tab_tooltip.zig` (pure two-line
derivation + a "was it elided" input), the existing measure in the strip
paint path knows whether the title fit.

## Validation criteria
