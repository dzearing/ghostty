# T1452 - Viewer feedback: a Mac pane on localhost never notices a dev server that starts later

## In plain terms

Open a viewer pane on `http://localhost:3000` before your dev server is
running, then start the server. On Windows the feedback button now appears on
its own within a few seconds; on Mac it still does not, and you have to reopen
the pane. Same terminal, two different behaviours.

## Summary

T650 established that NOTHING re-resolved a viewer pane that had stopped
navigating, on either platform: `ViewerWorktreeCache`'s 15s `ttl` expired with
no one left to ask, so the promise the TTL exists for — start a dev server and
the affordance appears without reopening the pane — was never true. Every call
into `ViewerView.refreshWorktree` is a navigation (`location`'s `didSet`, and
`init`).

The Windows half landed with T650; this is the Mac half, and it is filed rather
than landed because the Swift build and its regression run belong to the Mac
seat.

## Details

The shape to translate (`src/apprt/win32/ViewerPane.zig`,
`src/apprt/win32/ViewerWorktreeProbe.zig`):

- A repeating timer at `ViewerWorktreeCache.ttl`, armed ONLY while the pane's
  location is a loopback URL — a file's directory and a remote site's origin
  cannot move while the location sits still, so only these panes can change
  answers without navigating.
- The tick is skipped while the pane is not visible, so a stack of background
  tabs costs nothing.
- The cache memoizes directory → worktree root for five minutes, so an unmoved
  listener is answered by the port lookup alone and costs no `git` process. The
  memo expires rather than living forever, because `git init` under a running
  server does change the answer.

## Validation criteria

- [ ] A Mac pane opened on a dead loopback port grows the feedback button,
      pointed at the listener's checkout, within a bounded wait after a server
      comes up — with no navigation and no reopen.
- [ ] An idle pane that is not on a loopback port, or is not visible, costs no
      process and no lookup per tick.
- [ ] Demonstrated to fail without the fix (the Windows arm's negative control
      shape: with the poll disabled, the pane stays on its origin tree).
