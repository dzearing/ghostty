# T1232 - An update you did not take right away disappears with the balloon, and nothing on screen says one is waiting

## Summary

T1171 follow-up. The update offer is a transient tray balloon: dismiss it, miss it while away from the desk, or click Later, and nothing on screen says a newer version is waiting - the only way back is the command palette's check-for-updates, which you have to know to look for. D84's answer was that the user is TOLD a newer build is waiting and takes it when they choose, and a notification that vanishes only half delivers that. Since T1171 the app re-checks on a timer and deliberately does NOT re-balloon a version it already offered, which makes the missing persistent affordance the whole remaining gap. Wanted: somewhere durable that says it - the Mac's About/menu affordance is the reference, on Windows plausibly a tray-icon state, a window-chrome indicator, or a line in the pane banner. Acceptance: after declining an offer, a user who never saw the balloon can still find and take the waiting update without knowing a command name.
