# T122 — pane banners don't survive relaunch/re-attach on Windows

## Summary

Pane banners don't survive relaunch/re-attach on Windows — main's `5d5897936` added a `banner` field to the session-layout manifest so a restore brings banner text back across quit/relaunch/upgrade re-attach and agent RELAUNCH. win32's `session_layout.zig` has no banner field at all (grep: zero `banner` hits). Note the READ side is already at parity — `IpcHandlers.zig:1368` emits `banner` in `+list --json` — so this is purely manifest write + restore-apply. Additive manifest field, so it must degrade cleanly both ways per the CLAUDE.md agent-contract rules (older app reading a newer manifest and vice versa)

## Details

Main's `5d5897936` added a `banner` field to the session-layout manifest so a
restore brings banner text back — across app quit/relaunch, upgrade re-attach,
and agent RELAUNCH alike. CLAUDE.md (merged in T117) now documents this as the
behavior.

win32's `session_layout.zig` has no banner field at all (zero `banner` hits).
The READ side is already at parity — `IpcHandlers.zig:1368` emits `banner` in
`+list --json` — so this is purely: write the banner into the manifest leaf, and
re-apply it on restore.

**Compatibility:** this is an additive manifest field and the manifest crosses
app/agent version skew, so it must degrade both directions per CLAUDE.md's
agent-contract rules — an older app reading a newer manifest ignores it; a newer
app reading an older manifest restores no banner rather than failing.

**Validation:** set a banner, quit, relaunch, assert the banner text is back and
that `+list --json` reports it; repeat across an agent restart (RELAUNCH path).

## In plain terms

You can pin a note above any pane. This task was filed because those notes
vanished whenever Ghoztty reopened your windows. They no longer do — the fix
landed under a different task (T422) on 2026-08-03, and re-verified on the box
today it holds on both paths: closing and reopening the app, and the background
process restarting underneath a pane. Nothing was left to build here, so this
card is closed as already-done rather than done twice.

## Resolution: superseded by T422 (verified on box 2026-08-09)

T422 (`d588cbebe`, "a restored pane keeps its own banner and title, and the
notice stops taking a slot it does not own") is this task, found from the other
end — from the user report that restored panes all showed the same
session-interrupted notice. Its root cause was the missing manifest field this
task names. Point by point against the Details above:

- **Manifest write** — `Leaf.banner` exists in `session_layout.zig:164`,
  captured in `App.captureLeaf` (`App.zig:1534`) from `Surface.banner_text` as
  raw markdown SOURCE. `setPaneBanner` also marks the layout dirty, without
  which a banner set long before a quit never reached disk.
- **Restore apply** — `restoreLeafPresentation` (`App.zig:2625`) re-applies it
  (and `Leaf.title`, which was captured but never applied before T422).
- **Agent RELAUNCH path** — covered by T422's precedence rule (decision D2): the
  banner slot belongs to the pane, so the session-interrupted notice folds into
  scrollback always and claims the slot only when the pane has none. Signal:
  `pane_banner_restored` (`App.zig:2350`) through core into `termio.Remote`.
- **Both skew directions** — the field is optional (older manifest → null
  banner, asserted by `session_layout.zig`'s "a pre-banner manifest still loads"
  test) and the parse sets `ignore_unknown_fields = true` (`session_layout.zig:276`,
  asserted at line 754), so an older app reading a newer manifest ignores it.
- **Read side** — `+list --json`'s `banner` was already at parity, as filed.

Re-verified live at HEAD today, not taken on the strength of the earlier turn's
report — both acceptance scripts run against a fresh `-Doptimize=Debug` build:

- `test\win32\session-reattach.ps1` → **ALL PASS (44)**, including `F1b` (the
  banner is set before quit — the positive control) and `F9b` (the restored
  pane's sticky banner came back). `F9b` reads `+list --json`, which reports the
  LIVE overlay rather than the manifest, so a pass means the pane really is
  showing it again.
- `test\win32\session-relaunch-notify.ps1` → **ALL PASS (93)**, including arm E:
  two panes keep their own banners across an agent restart, the third
  (bannerless) pane takes the notice, and `E5b` requires all three restored
  panes to be on a LIVE shell — not a painted picture.

No source change was made, so the standing zig/P1–P3 floor is untouched by this
turn and was not re-run; the two scripts above are the direct evidence for the
claim being closed.
