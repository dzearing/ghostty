# T724 - macOS: an on-box settle-window test for in-place agent recovery (the win32 T195 half)

## In plain terms

The Mac is where the "a brief hiccup must not rebuild your panes" rule came
from — it was added there after an incident that destroyed live sessions. The
Windows seat now has an end-to-end test that freezes the helper process and
proves the rule holds on a real machine. The Mac has the rule and its unit
tests, but as far as this seat can tell no equivalent end-to-end check. This is
that half, filed rather than left as an undocumented gap.

## Summary

The win32 half is T195: sections G and H of `test/win32/agent-recovery.ps1`.
The Mac equivalent would exercise `LocalAgentManager.SharedLinkDropVerdict`
(`03f0f1f30` + `e65cfa4d5`) the same way — `SIGSTOP` the `ghoztty-agent`, wait
for the app to open its settle window, `SIGCONT` inside it, and prove nothing
was rebuilt — with a control that holds the stop past the window.

## The one trap worth carrying across (measured on win32, 2026-08-10)

**Child pids cannot be the oracle for a stop/continue stimulus.** A stopped
agent never loses a child, so a rebuild re-ATTACHes the very same sessions and
the pids are identical whether or not recovery ran. Verified by holding the
stop past the window: recovery demonstrably ran and the pid assertion still
passed. The win32 test uses the set of pane SURFACES instead (recovery keeps the
window and replaces the surfaces inside it); the Mac analog is the identity of
the `SurfaceView`/pane views in the rebuilt tab.

## Validation criteria

- [ ] A blip inside the settle window leaves the panes, their sessions and the
      tab topology untouched, and the panes still round-trip typed input.
- [ ] A control with the same stimulus held past the window DOES rebuild, by the
      same measurement.
- [ ] The measurement is an outcome, not a log line; the log is used only to
      time the resume against the app's own state.
