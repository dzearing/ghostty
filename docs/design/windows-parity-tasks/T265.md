# T265 - Merged chrome row has nowhere to paint a pinned window title (T205 follow-up)

## Summary

T205 put the tab run inside the caption band. In that mode `caption_layout`
returns an EMPTY `title` rect on purpose — the tabs occupy the row's left half
and painting a window title behind them is the two-rows problem in one row —
so a window showing 2+ tabs (or launched `--window-show-tab-bar=always`) draws
no window title at all.

That matches the reference exactly: Windows Terminal, Edge and Explorer show
no title text once tabs are in the caption. What makes it worth a task anyway
is that **ghoztty documents a window title as a first-class, pinnable thing**:

> `--title`: Set the **window title**. A window title pins the titlebar — it
> wins over any tab or pane title and survives pane focus changes and shell OSC
> title updates — until cleared.
> (CLAUDE.md, `+new-window` / `+rename --title=`; interactive equivalent
> Cmd+Shift+R "Change Window Title".)

So a user or an agent can pin a title and, at two tabs, see nothing. The pin
still works — it is in the taskbar, in `+list`, and it is what the titlebar
would show if the strip went away — but the on-screen affordance is gone in the
state most agent workflows are in.

## Options (decide, do not drift)

1. **Accept and document.** Match the reference; state in CLAUDE.md that on
   Windows the window title is shown only when the strip is not up, and that
   the taskbar carries it otherwise. Cheapest, and defensible.
2. **Paint it in the drag region.** The empty band between the "+" and the "…"
   is exactly the space a title could use. It is variable — it shrinks as tabs
   are added and can reach zero — so it needs a minimum width below which the
   title drops, and it moves whenever a tab title changes (see T249, which is
   about the same reflow). Closest to "the pin is honored".
3. **Only when pinned.** Paint it only when a title was explicitly pinned
   (not the fallback chain), so the common case still reads like WT and the
   documented feature still shows something.

Option 3 is the recommendation: it keeps the reference look for everyone who
never pins a title, and makes the documented pin visible for everyone who does.

## Validation

- `test/win32/chrome-merged-row.ps1` gains: with `+rename --title=…` on a
  2-tab window, the pinned string is found by an ink/text probe in the row (or,
  under option 1, an assertion that it deliberately is NOT, plus the CLAUDE.md
  wording).
- The one-tab case must be unchanged: `caption-bar.ps1` already asserts a
  standalone band paints its title.
- Negative control mandatory.
