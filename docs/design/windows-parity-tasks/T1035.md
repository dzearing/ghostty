# T1035 - Nothing proves a resizing pane actually waits for its new frame - the synchronous-present path has no oracle

## Summary

T1031 put the divider drag, the window-edge drag and the banner toggle on the same synchronous-present path and wired the frame signal that path waits on, but its acceptance can only assert the erase decision and the clip styles - 'the pane blocked up to 16ms for a frame at its new size' is a schedule, not a pixel, and resize-flicker.ps1 says so in its own header. So the wiring could be removed again and every test would stay green. Wanted: an oracle with teeth. The likely shape is the GHOZTTY_PERF telemetry already in renderer/OpenGL.zig - have the resize path log the wait outcome (frame arrived vs timed out) in debug builds and assert the arrived case over a scripted drag, the way the erase decision is asserted now.
