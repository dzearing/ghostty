# T919 - A panicking zig test binary prints no stack trace on this box (Unable to dump stack trace: InvalidBlockIndex), so every test panic costs a cdb round-trip

## Summary

Reproduced while validating T811: a deliberately induced 'Invalid free' panic in the none lane printed 'thread 41056 panic: Invalid free' followed by 'Unable to dump stack trace: InvalidBlockIndex' twice and nothing else, so the panicking frame is unknown without attaching cdb. That is why T811's original 2026-08-12 incident needed scripts\crash-catch.ps1 and a dump to name Connection.destroy at all, and the same tax lands on every future test panic (T442, T443 and T536 all paid it). InvalidBlockIndex comes out of std.debug's PDB reader, so the first experiment is cheap and named: build the test binaries with -Dstrip=false (and check what .pdb the test artifacts actually emit next to the exe) and re-run the same induced panic to see whether the in-process trace resolves. If a flag fixes it, wire it into scripts\floor-lane.ps1 so every lane run has it. If it cannot be fixed, document the cdb recipe at the point of pain instead of in three task files.
