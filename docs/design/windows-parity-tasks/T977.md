# T977 - After a reboot the interrupted-session notice never appears in the pane's banner, only in its scrollback

## Summary

Newly scoreable once T975 made the true reboot shape (app + session manager + every --pty-host holder killed) restore the layout again. Arm E of test/win32/session-relaunch-notify.ps1 measures the T422 rule - a restored pane keeps a banner it already owned, and a pane with a FREE banner slot takes the session-interrupted notice there. Measured 2026-08-18 on the fixed build, twice: ownA=1 ownB=1 noticed=0 bannerless=1 over 3 leaves. The two panes that owned banners kept them (E1/E2 PASS) and every pane carries the notice in its own scrollback (E5 PASS), but NO pane shows the notice as a banner, so the plain pane comes back with an empty banner slot and nothing above it saying its program was interrupted - E3 (noticed<=1 and bannerless==0) and E4 (noticed==1) both FAIL. The user-visible gap: after a reboot the sticky one-line 'Session interrupted' notice the design puts above a restored pane is simply absent, and the only trace is a line in the scrollback that scrolls away. Almost certainly the same restore path T922 owns (the fresh OPEN of a dead tombstone) never publishing the banner; check where the notice is published for the did_notify path in src/termio/Remote.zig / session_notice.zig against the banner store. Together with T922's A12/A15/A16/A17 these are the only reds keeping the session-relaunch guard stamp due.

## In plain terms

When the machine reboots, Ghoztty brings your windows and panes back — but the
program each pane was running is gone, so a one-line "Session interrupted"
notice is supposed to sit above the restored pane telling you that, and naming
what was running. The report was that this notice never showed up above the
pane, only buried in the scrollback where it scrolls away. It turns out the
notice was there all along: the measurement looked a fraction of a second too
early, before the pane had published it. What was genuinely missing was any
check that it arrives *promptly* — so this closes with the notice proven to land
under a second after the panes come back, and a check that will go red if it
ever starts crawling.
