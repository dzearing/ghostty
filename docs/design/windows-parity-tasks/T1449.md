# T1449 - Activity Monitor: Mac says a kill may need elevation when the process had already exited

## In plain terms

You pick a process in the Activity Monitor and hit Kill. While you read the
confirmation the process finishes on its own, so there is nothing left to kill.
The panel tells you it "may require elevated privileges" - which sends you off
looking for an admin prompt that would not have helped. It should just say the
process had already exited. Windows now does; Mac still does not.

## Summary

Filed out of T632, which fixed this on Windows. `RemoteActivityMonitorView.swift`
builds its whole failure sentence from the target list (:587-596) and knows
nothing about WHY each kill failed, so every failure gets the same elevation
guess. This is the same defect on both platforms and the Windows fix puts the
two out of step until this lands.

What T632 did, for the seat that can port it:

- `proc_control.killProc` classifies the failure rather than only logging it. On
  Windows a corpse whose handle somebody still holds answers `ACCESS_DENIED`
  exactly like a live process we may not touch, so the fix asks the process
  OBJECT (a signalled handle) instead of the error code. POSIX already
  distinguishes them - `killPosix` maps `error.ProcessNotFound` to "no such
  process" - so the Mac half is a classification of the string that already
  exists, not new OS work.
- `killOne` returns a small enum (`ok` / `gone` / `denied` / `other`) instead of
  a bool, mapping generously so an unrecognised message from an older agent
  lands on `other` rather than a confident `denied`.
- `killFailureText` splits the tally into killed + already-exited + failed, which
  always sums to the total: an all-gone batch says "All 3 processes had already
  exited." and never mentions privileges, a denied batch keeps today's sentence,
  and a mixed batch names both. The Windows wording is in
  `src/apprt/win32/activity_actions.zig` with unit tests beside it.

## Validation criteria

- [ ] The Mac panel's failure sentence says the process had already exited for a
      target that exited between the click and the confirm, and never mentions
      privileges for that case.
- [ ] A denied failure keeps today's elevation sentence; a mixed batch says
      something true of both halves and its tally sums to the batch size.
- [ ] Swift unit tests cover the three shapes, mirroring the Zig tests in
      `activity_actions.zig`.
- [ ] The wording matches the Windows build's, so the two seats do not diverge.
