# T1422 - The hero-mode divider has no real grab target on Windows

## In plain terms

The line between the big hero pane and the strip of thumbnails is one pixel
wide, and on Windows that one pixel is also the only place the mouse can grab
it. Dragging the divider to resize becomes a hunt: the cursor has to land
exactly on the hairline or nothing happens. The Mac build just fixed this by
giving the divider an invisible grab band wider than the line it draws.

## Goals

- [ ] Verify the win32 hero divider's hit rect against what it paints
- [ ] The grab band is comfortably wider than the drawn line, matching the Mac feel
- [ ] The resize cursor appears over the whole grab band, not only the hairline
- [ ] The wider hit area does not steal clicks from the panes on either side

## Summary

Main intake, 2026-09-07. `origin/main` `83e6359be` ("give the hero divider a
real grab target") widened the Mac hero divider's hit target
(`macos/Sources/Features/HeroMode/HeroModeView.swift`,
`macos/Sources/Features/Splits/SplitView.Divider.swift`, with
`macos/Tests/HeroMode/HeroDividerHitTargetTests.swift` as the assertion).

Check the win32 hero carousel divider for the same gap. Note T250 already
brought this divider onto the design system's section 5 rules, so the drawn
width is settled; this is about the hit rect, which is separate.

## Validation criteria

- [ ] A test asserts the divider's hit rect is wider than its painted width
- [ ] A pointer a few DIPs off the line still starts the drag and still shows the resize cursor
- [ ] Clicking just inside either neighbouring pane still focuses that pane
