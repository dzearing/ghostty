# T943 - The activity monitor, confirm dialog and split-dim probes still take the torn photo - convert them to the synchronous capture

## Summary

T843's second half for the remaining classes we own, unblocked by T940's
`WM_PRINTCLIENT` handlers. Switch the probes to `-Sync` and re-run each script
several times.

Scripts, from the T843 survey: `activity-monitor.ps1` (10 sites) and the
`$panel` sites in `chrome-theme.ps1` (4) — both `ActivityMonitor`;
`confirm-dialogs.ps1` and `config-errors.ps1` — `ConfirmDialog`;
`split-dim.ps1` and `split-dim-viewer.ps1` — `DimOverlay` or the window behind
it, check which before converting.

The activity monitor is the priority inside this task: its probes read table
columns, and a torn frame stops mid-text at a glyph boundary, which is what
made T835's readings look like stable wrap positions rather than noise.

## In plain terms

The rest of the tests that photograph the app — the activity panel, the
confirmation dialogs, the dimmed pane — are reading a photograph that can come
out half-taken. This points them at the steady one.
