# T1176 - The one Windows MSI installs client and agent and launches Ghoztty when it finishes

## Summary

Installing should end with a running terminal, not a Start Menu entry the user has to find. The MSI must (a) verifiably lay down ghoztty.exe, ghoztty.com and ghoztty-agent.exe together, and (b) launch Ghoztty on completion of a successful install (and not on a silent/upgrade-in-place install driven by the updater). Add the acceptance coverage that proves both, so a build that drops the agent fails the release lane instead of shipping.

## In plain terms

Today you download the Windows installer, double-click it, watch the progress
bar finish -- and nothing happens. There is a new entry in the Start Menu, and
finding it is your problem. After this, the installer ends the way installing
an app should end: the terminal is already open in front of you. The other
half is quieter but worse if it breaks -- the installer has to lay down all
three pieces of the product (the app, the `ghoztty` command line, and the
background service that keeps your terminals alive across restarts), and a
package that silently dropped one of them would look installed and behave like
a half-product.

## Goals

- [x] the install ends with a running Ghoztty window
- [x] a scripted/silent install, and an update over an install you already
      have, do NOT pop a surprise window
- [x] the packaging build fails, loudly, if the launch wiring is missing from
      the compiled package
- [x] the packaging build fails if the app, the console twin or the agent is
      missing from the package
- [x] acceptance coverage that has been watched going red for every one of
      those failures
