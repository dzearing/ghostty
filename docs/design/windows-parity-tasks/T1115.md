# T1115 - test-desktop-spike.ps1 reports that PrintWindow returns no real content on the test desktop

## In plain terms

This is the small experiment that answers 'can we take a picture of a window on the hidden test desktop?'. It answers no. Because several other checks depend on being able to do exactly that, this one decides what happens to them.

## Summary

`test\win32\test-desktop-spike.ps1` scored `1 FAILED / 11 passed` in the T1094 sweep, and left a process running:

```
FAIL  PrintWindow(PW_RENDERFULLCONTENT) returns real content (meanLum=51, distinct=60)
```

Eleven assertions pass, so the test desktop is created, the app launches on it and is addressable - it is specifically image capture that does not work. `meanLum=51, distinct=60` is the measured evidence, not a guess.

This script is the spike, so its job is to produce a decision rather than to go green by being made lenient. The decision it should produce: is there ANY capture route that works on a non-interactive desktop (BitBlt from the desktop DC, a DWM thumbnail, moving those scripts to the interactive desktop under a lock), or is pixel assertion simply unavailable there.

Whatever the answer, it should be written into the spike so the next person does not re-run the experiment. Also `[leaked 1]` - see the leak task.
