# T965 - The release-artifacts guard can never come back green on this box (its stamp needs Docker)

## Summary

release-artifacts.ps1 only stamps when zero sections skipped, and sections B1/B2 skip whenever Docker is not running - which it is not, by standing user policy (starting the WSL2 backend buried the box once). So the guard went DUE when the release workflow files changed on 2026-08-16 and cannot come back: every turn since has had to reach for validate -NoGuardDue. A permanently red guard is the one shape a staleness gate must not have. Options: stamp only the files the sections that RAN actually cover, or split the Docker-dependent packaging checks into their own guard row so the pure ones can go green without a container runtime.

## In plain terms

Nothing a user can see. This is a broken smoke alarm in the workshop: one of
the automatic "has anybody tested this since it changed?" checks got stuck in
the alarm state and cannot be reset on this machine, so every piece of work
now has to walk past a red light. A red light nobody can turn off is one
everybody stops reading.

## Validation criteria

- [ ] `scripts\guard-due.ps1 check` exits 0 on a box with no container runtime,
      after a clean run of whatever the pure half of the harness became
- [ ] the Docker-dependent packaging checks still gate something: they either
      keep their own guard row (DUE when the packaging inputs change) or the
      pure guard's `Covers` no longer claims those inputs — never a silent
      widening that calls unrun checks current
- [ ] a turn no longer needs `validate -NoGuardDue` for this guard
