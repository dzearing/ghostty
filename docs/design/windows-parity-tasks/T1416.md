# T1416 - No live check that a quick-terminal slide survives an update notification (T608 landed the static half)

## Summary

T608 fixed the timer-id collision that stalled the quick-terminal slide when an
update notification arrived, and proved the fix the only way this box allows:
`test\win32\msg-timer-ids.ps1` reads the source and the compile, not the screen.
The behavioral check the task originally asked for was never run, because
neither half of it can be staged here -- SendInput does not land on the
background test desktop the suite runs on (T218), so the quick terminal cannot
be toggled by its keybind, and this box draws no toasts at all (ToastEnabled=0,
measured in `notification-click-real.ps1`), so no balloon can be put on screen
to race the slide.

Nothing is known to be broken. This is the missing OBSERVATION: a run on a box
with a shell and the input desktop, where the slide is started, an update
notification is raised mid-slide, and the quick terminal is asserted to reach
its fully-open geometry with the balloon's icon cleared afterwards. Both halves
of that already exist elsewhere in the suite -- `overlay-zorder.ps1` section H
drives the quick terminal by keybind and reads its window back, and
`notification-click-real.ps1` is the input-desktop, real-toast pattern -- so
this is an assembly job, not new machinery. It is P3 because the property it
would observe is now enforced at compile time.

## In plain terms

The bug where the drop-down terminal froze mid-slide if an update popped up is
fixed, and the build now refuses to let it come back. What is missing is the
final look with our own eyes: nobody has watched the slide finish with a real
update notification on screen, because this machine has notifications turned
off and cannot type into the test desktop.

## Validation criteria

- [ ] An interactive-desktop acceptance (not part of the floor, declared in
      `lib\TestDesktop.ps1`'s input-desktop exception list) starts a
      quick-terminal slide, raises a real update notification during it, and
      asserts the quick terminal reaches its open geometry
- [ ] The same run asserts the balloon's tray icon is cleaned up afterwards --
      the second half of the T608 symptom
- [ ] It carries a `-NegativeControl` that fails, and names its SKIP capability
      when the box has no toasts
