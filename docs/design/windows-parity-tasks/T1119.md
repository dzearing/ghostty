# T1119 - ipc-fake-server.ps1 dies immediately with 'All pipe instances are busy'

## In plain terms

A check that stands up a pretend server crashes the moment it starts, because the name it wants to listen on is already taken. It tests nothing at all in this state.

## Summary

`test\win32\ipc-fake-server.ps1` died in 0.2 seconds during the T1094 sweep, with no verdict line and no assertions:

```
New-Object : Exception calling ".ctor" with "3" argument(s): "All pipe instances are busy."
At D:\git\ghoztty\test\win32\ipc-fake-server.ps1:48 char:9
+ $pipe = New-Object System.IO.Pipes.NamedPipeServerStream(
```

`All pipe instances are busy` means something already holds a server instance on that pipe name at its instance limit. Two candidate causes, and they need different fixes:

1. **A leftover from a previous run** - a fake server from an earlier invocation that was never torn down. The suite's leak sweep covers processes out of `zig-out`, and a PowerShell-hosted pipe server is NOT that, so it would slip straight through.
2. **A real app or agent** holding the endpoint the script wants, which would mean the script is not as isolated as it believes.

Either way the script should say which, rather than throwing a raw .NET exception. A test that cannot acquire its own resource should fail with a sentence, not a stack trace.

## Goals

- [ ] Reproduce and identify what holds the pipe (`handle`/`Get-ChildItem \\.\pipe\` will name it).
- [ ] Give the script a private, per-run pipe name if it does not already have one - a fixed name is what makes this collide at all.
- [ ] Turn the raw exception into a readable setup failure naming the pipe and the holder.
- [ ] If the holder turns out to be a leaked earlier run, widen the suite's leak sweep to cover non-zig-out holders of our pipe names.
