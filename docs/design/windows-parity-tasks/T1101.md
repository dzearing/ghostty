# T1101 - The inactive-pane dim overlay measures as no colour at all in split-dim.ps1 and split-dim-viewer.ps1

## In plain terms

When you have several panes open, the ones you are not typing in are supposed to be shaded slightly darker. The check that measures that shade is coming back with no colour at all - not the wrong colour, nothing - so we currently have no evidence either way about whether the shading still works.

## Summary

Two scripts in the T1094 sweep, same failure shape.

`split-dim.ps1` - `2 FAILED / 27 passed`:

```
FAIL  default: overlay paints the background color #101014 (got )
FAIL  custom: overlay paints the configured fill #ff0000 (want 255,0,0, got )
```

`split-dim-viewer.ps1` - `1 FAILED / 28 passed`:

```
FAIL  viewer overlay paints the background color #101014 (got )
```

The measured value is EMPTY, not wrong. An empty read is the signature of a capture that returned nothing, which is what [[T1100]] is about - so the first job here is attribution, not a product fix. If the capture is repaired and the colour is still wrong, this becomes a real dim-overlay defect and the task stays open on those terms.

Worth noting the other 55 assertions across the two scripts pass, so the split machinery itself is exercised and healthy; it is specifically the colour probe that is blind.
