# T149 — Banner chrome parity: no collapse toggle, no content inset

## Summary

**Banner chrome parity: no collapse toggle, no content inset.** `a5adff229` (symmetric padding, content inset, shaded background, collapse toggle) has ZERO references in any Windows doc; `ec0c62671`/`89465f320` (instant-then-animated collapse/expand with the terminal inset snapping once) are cited only in passing. A Mac banner can be collapsed to a thin strip and expanded again; the win32 overlay cannot, so a tall banner permanently eats pane rows with no user recourse. Depends on T131's card work landing first so the collapsed state has a shape to collapse to

## In plain terms

A banner with several lines in it can be folded away to a single line by
clicking it — that already worked here. What was missing is the motion: the
card jumped from tall to short in a single frame, so it read as the banner
being replaced rather than folded, and you had to work out where the text
went. Now the card glides between the two sizes over about a fifth of a
second, the way it does on the Mac. The terminal underneath still moves in
one step, immediately — text that reflowed eleven times on the way would be
worse than no animation at all.

## Goals

- [x] Clicking a multi-line banner folds and unfolds it with a smooth resize,
      not a jump cut
- [x] The terminal grid below moves exactly once per click, at once
- [x] A second click mid-fold reverses from where the card actually is
- [x] Users who turned Windows' "animation effects" off keep the instant
      toggle
- [x] The audit's other two claims (no collapse toggle, no content inset)
      re-checked against the code rather than trusted
