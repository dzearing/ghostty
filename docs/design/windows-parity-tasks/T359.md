# T359 - remote-test-client is an on-demand build target, but two acceptance scripts require it - a clean tree fails them for a reason that reads like a product bug

## In plain terms

Some of the automated checks that prove terminal sessions keep working need a
small helper program that talks to the session daemon without a window. That
helper is not built by the normal build, so on a freshly built tree those
checks stopped at the first line with "remote-test-client is missing" - which
reads like the session daemon itself failed to build, and sent more than one
person hunting a bug that was not there. Now the checks build the helper
themselves when it is absent, and if that ever fails they print the exact
command to run.

## Goals

- [x] a shared helper resolves the client and builds it on demand
- [x] the two scripts the task names pass on a tree with no client
- [x] every other consumer of the client goes through the same helper
- [x] a precondition failure names the exact build command
- [x] the helper has its own acceptance script

## Summary

`remote-test-client.exe` is built **on demand only** (`build.zig:171-175`, its
own `zig build remote-test-client` step), but two acceptance scripts require it
as a prerequisite: `test/win32/agent-pipe.ps1` (T89c) and
`test/win32/agent-user-env.ps1` (T42). A tree that has only ever run
`zig build -Dapp-runtime=win32` does not have the binary, so both scripts fail
at their first assertion — and the failure names a missing exe, which reads
like the agent failed to build rather than "this lane was never asked for".

## Evidence

- `build.zig:168-175`: `remote_test_client_step.dependOn(...)` only — nothing in
  the default install step reaches it. Same shape for `wp4-e2e`.
- `test/win32/agent-pipe.ps1:18` and `test/win32/agent-user-env.ps1` default
  `-ClientExe` to `zig-out\bin\remote-test-client.exe` and assert existence.
- Observed 2026-08-02 doing T42: the client had to be built with an explicit
  extra `zig build remote-test-client` before the new script could run.

## The fix (pick one, then write it down)

Either make the scripts self-sufficient — build the client themselves when it
is missing (a `zig build remote-test-client` shell-out, the way the delivery
launcher builds the staging release rather than assuming it) — or add it to
whatever the standing "test binaries" target is so the floor produces it.
Prefer the former: it keeps the default build lean and makes the script's
prerequisite explicit at the point of use.

Whichever way it goes, the `-ClientExe` assertion message should say **how** to
produce the binary; a precondition that cannot be acted on is half a failure
message. Check `wp4-e2e` for the same trap while here.

## Validation

Delete `zig-out\bin\remote-test-client.exe`, run both scripts, and get ALL PASS
without a manual build step (or a failure line that states the exact command).

## Validation criteria

- [x] with `zig-out\bin\remote-test-client.exe` deleted,
      `test\win32\agent-pipe.ps1` runs to ALL PASS with no manual build step
- [x] same for `test\win32\agent-user-env.ps1`
- [x] `test\win32\test-client-build.ps1` is ALL PASS (helper contract, fast
      path, `-NoBuild`, the real rebuild, and the consumer-wiring audit)
- [x] a client that cannot be produced fails with a message quoting
      `zig build remote-test-client -Doptimize=Debug`
- [x] the four zig lanes stay green (`scripts\floor-lane.ps1 -Lane all`)

- New `test\win32\lib\TestClient.ps1`: `Resolve-RemoteTestClient` returns an
  existing client, otherwise runs `zig build remote-test-client -Doptimize=Debug`
  with `ZIG_GLOBAL_CACHE_DIR` derived onto the repo's drive (T243). `-NoBuild` is
  the hatch; every failure message quotes the build command from one spelling
  (`Get-RemoteTestClientBuildCommand`).

  `chooser-orphan-badge`, `session-reattach`, `agent-relay-session-e2e` (that last
  one used to SKIP the whole e2e for a binary we can produce in seconds).
- `wp4-e2e` checked for the same trap: no script in `test\` or `scripts\` consumes
  it, so there is no second half to fix.
- With `zig-out\bin\remote-test-client.exe` deleted: `agent-pipe.ps1` ALL PASS,
  `agent-user-env.ps1` ALL PASS (20) - each built its own client first.
- New `test\win32\test-client-build.ps1`: ALL PASS (21). Section D deletes the
  real client and makes the helper put it back; section E re-derives the consumer

- Floor: all four zig lanes PASS (lib/none/win32/agent), P1-P3 ALL PASS, and every
  guard these edits made due is green again (orphan-notify, agent-relay-session,
