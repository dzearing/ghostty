# T160 - Viewer markdown table of contents: native card, scroll spy, gutter/overlay, resize

## In plain terms

On the Mac, opening a markdown document in a viewer pane shows a floating
"Contents" card listing the document's headings — the section you are reading
stays highlighted as you scroll, clicking a heading jumps there, and you can
drag the card wider or narrower. On Windows that card simply did not exist:
a long document had no outline and no way to jump around it. This task builds
the same card natively on Windows — in a wide pane it sits in its own column
beside the text; in a narrow pane it tucks away behind a button in the pane's
toolbar.

## Goals

- [x] A markdown document with two or more headings shows the native
      Contents card; one heading (or a code file / website) shows none.
- [x] The highlight follows the section being read, and clicking a row
      scrolls the page there and keeps that row highlighted through the
      scroll animation.
- [x] Wide panes (≥ 720 DIP) put the card in a left gutter the document
      reflows around; narrow panes get a toolbar button that overlays the
      card, switching live as the pane is resized.
- [x] Dragging the card's right edge resizes it, and the width is remembered
      as a preference shared by every viewer pane.
- [x] The card, the banner, and the document agree on the same 12px outer
      margin (asserted, not eyeballed).

## Details

Mac sites: `ViewerTOC.swift` (panel, rows, pill selection, pinned CONTENTS
header on `glassBackdrop()`, `GlassCard.shape` / `GlassCardBackground` /
`GlassCard.outerMargin` at `:88-96`), plus `ViewerView.setTOCItems`,
`scrollToHeading`, `setTOCPanelOpen`, `mountTOCPanel`, `applyTOCPanelState`,
`desiredTOCLayout`, `updateTOCLayout`, `updateTOCResizeHandle`,
`setTOCCardWidth`, `pushTOCGutter`, `clearTOC`, `tocGutterMinWidth = 720`
(`:176`). The document side (`indexHeadings`, `reportActiveHeading`,
`pinActiveHeading`, `releasePinnedHeading`, `scrollToAnchor`, `setGutter`) is in
shared `src/viewer/viewer.js` and comes free.

Scope:

- Consume the scroll-spy / heading-index messages over the P1 bridge (the
  `window.webkit.messageHandlers` shim, landing in T90d) and paint the card
  with `banner_card.zig`. Do NOT grow a second card renderer.
- Only for markdown, and only with 2+ headings.
- Selection is a rounded pill in the system's own selection colors -- accent
  fill + white text while the window is key, the neutral unemphasized gray
  otherwise; hover is a separate faint wash.
- Clicking a row PINS the selection to it (the smooth scroll fires a scroll
  event per frame and must not walk the highlight off the requested row); the
  next scroll gesture hands selection back to the spy. `viewer.js` already
  implements the pin -- the host must not fight it.
- Wide pane: card in a left gutter, document column reflows beside it
  (`__viewer.setGutter`). Narrow pane (< 720pt PANE width): card becomes an
  overlay, the nav bar stays pinned open and gains a contents button as its
  first item. The switch follows pane width LIVE, so dragging a split divider
  reflows it.
- Drag the card's right edge to resize; gutter and text column follow in the
  same layout pass. Width is a PREFERENCE shared by every viewer pane -- store
  it where win32 keeps preferences (`window_memory.zig` neighborhood), NOT in
  the session manifest.
- Panel open/closed state is deliberately ephemeral: it must NOT survive a
  session restore (restoring an overlay would hide the content it covers).
- Margins are one number: `GlassCard.outerMargin` (12pt) on all four sides of
  the card, and the document leaves the same 12px on all four of its own, so a
  TOC card and a banner in the neighbouring pane line up at their corners. Mac
  enforces this with `documentAlignsToTheCard` in `ViewerTOCTests`; win32 needs
  the equivalent assert.

*Validation:* `viewer-panes.ps1` grown -- a 2+ heading document shows the card
and a 1-heading one does not; scrolling moves the highlight; clicking a row
scrolls to it AND keeps it highlighted through the animation; dragging the
split below 720pt switches to the overlay and back above it; the resize drag
changes both card and text column; card and a neighbouring pane's banner agree
on the 12pt margin. Unit tests both lanes for the layout thresholds and the
heading-nesting math.
