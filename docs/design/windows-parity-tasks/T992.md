# T992 - Copying can hand the user another app's clipboard content because our copy claims no owner window

## Summary

Found by T947's new harness. The terminal's copy opens the clipboard with a NULL owner window, and OpenClipboard(NULL) excludes nobody - measured directly: while a process holds the clipboard that way, every other process opens it straight through. So the copy's EmptyClipboard-then-SetClipboardData is not atomic: another app can open, empty and write between our two calls, and the user's copy silently yields that app's content or nothing. Passing a real HWND (the surface's, as the paste read already does) makes the pair atomic the way every other Windows app's copy is. Same family as T947 but a different failure: T947 was the copy never starting, this is the copy being overtaken mid-flight.
