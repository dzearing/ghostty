# T1187 - Re-run the release-artifacts packaging harness with Docker up after the T1175 MSI-comment edit

## In plain terms

Nothing is broken. A test that proves the Windows installer packages correctly
now thinks it is out of date, because a comment in the build script changed. It
needs Docker running to say so, and this box does not start Docker on its own.

## Summary

T1175 corrected one comment in `dist/windows-installer/build-msi.sh` - it named
`relay/deploy/msi/ghoztty-agent.wxs` as the model for the wxs template, and that
directory was deleted by the same change, so the pointer was about to dangle.
The edit made `guard-due`'s `release-artifacts-packaging` row DUE, and clearing
it means:

```
powershell -NoProfile -File test\win32\release-artifacts.ps1 -RequireDocker
```

which needs Docker Desktop up (the msitools-local image). Without it the harness
reports `ALL PASS (1 skipped)` and deliberately does NOT stamp - a skipped
section must never look like a green one. T1175 therefore committed under
`-NoGuardDue` naming this task.

Nothing in the packaging path changed, so the expected result is a clean green
run and a stamp.

## Validation criteria

- [ ] `test\win32\release-artifacts.ps1 -RequireDocker` ALL PASS with no
      skipped sections, on a box with Docker up.
- [ ] `scripts\guard-due.ps1 check` reports
      `GUARD CURRENT release-artifacts-packaging`.
