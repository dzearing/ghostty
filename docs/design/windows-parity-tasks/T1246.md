# T1246 - Ghoztty has no code signing certificate, so the signing pipeline has nothing to sign with

## In plain terms

Downloading Ghoztty for Windows still raises a full-screen warning naming the
publisher as unknown. The machinery to stop that now exists and runs on every
release; what it is missing is the certificate itself, which someone has to buy
in Ghoztty's name. Once that certificate is in the repo's secrets the warning
goes away with no further code change.

## Summary

T1203 built the signing pipeline: `dist/windows-installer/sign-artifacts.sh`,
called from the shared `build-release-artifacts.sh`, signs `ghoztty.exe`,
`ghoztty.com` and `ghoztty-agent.exe` before the packages are cut and then the
MSI itself, using `osslsigncode` on the Linux release runner. It reads two
secrets:

| Secret | What it holds |
|---|---|
| `WINDOWS_SIGN_PFX_BASE64` | the PKCS#12 certificate, `base64 -w0 cert.pfx` |
| `WINDOWS_SIGN_PASSWORD` | its password |

While `WINDOWS_SIGN_PFX_BASE64` is unset, every release builds normally and
prints an UNSIGNED banner naming this task. Nothing else has to change: adding
the secrets is the whole remaining act.

What remains is therefore not code. It is:

1. **Choose a certificate type.** This is the call that decides whether the
   warning actually goes away, and it is filed as a decision for the user
   because they can tell the two apart by using the product. An **OV**
   certificate removes "Unknown publisher" but SmartScreen reputation accrues
   by download volume, so early downloads can keep warning for weeks. An **EV**
   certificate carries reputation immediately and the warning is gone from the
   first download; it costs more and the key must live on hardware or in a
   cloud HSM.
2. **Buy it**, which needs payment and organization/identity validation. Not
   something this seat can do.
3. **Load the secrets** into `dzearing/ghoztty` and cut a release.

Note the shape of (1) for an EV certificate bought today: most issuers no
longer ship an exportable `.pfx` for EV, only a hardware token or a cloud
signing service. If the user picks EV, `sign-artifacts.sh` needs a second
backend (the issuer's cloud signing tool in place of `-pkcs12`), which is
mechanism and this seat's to write once the issuer is known.

## Validation criteria

**Superseded by D87 (2026-09-02).** The user chose to stay unsigned and keep
explaining the warning, so no certificate is being bought and the criteria
below are the ones the ANSWERED question would have needed. They are left
verbatim as the specification for reversing that call. What this task was
closed against instead:

- [x] The unsigned state reads everywhere as a deliberate standing choice
      rather than a pending purchase - `sign-artifacts.sh`'s release banner
      now names D87 instead of "expected until a certificate is added".
- [x] Every place a user meets the SmartScreen warning explains it the way
      the page does: lead with **Run anyway**, offer *More info* as the
      conditional second shape, frame the click as an override rather than a
      blessing. The portable ZIP's READ-ME-FIRST was still on the pre-T1203
      wording and is fixed.
- [x] That text is covered by a test that can fail - B4b/B4b2/B4b3/B4b4 in
      `test\win32\release-artifacts.ps1`, verified red against the old
      wording (B4b2 and B4b4 FAILED) and green against the fix.
- [x] The one remaining inaccuracy - the page's "not code-signed *yet*" - is
      filed as T1270 together with the structural reason it could not land
      here (nothing publishes the in-repo mirror's prose to gh-pages).

Original criteria, for a future certificate purchase:

- [ ] A code signing certificate exists in Ghoztty's name and is loaded into
      `dzearing/ghoztty` as `WINDOWS_SIGN_PFX_BASE64` + `WINDOWS_SIGN_PASSWORD`.
- [ ] A release-built MSI is Authenticode-signed, and
      `Get-AuthenticodeSignature` on it reports `Valid` with the expected
      subject.
- [ ] `ghoztty.exe`, `ghoztty.com` and `ghoztty-agent.exe` inside both the MSI
      and the portable ZIP report `Valid` too, not just the MSI wrapper.
- [ ] Downloading that MSI on a machine that has never seen Ghoztty and running
      it shows a normal per-user install with NO "unrecognized app" screen and
      a named publisher.
- [ ] The release log shows the signing step and does NOT contain the
      certificate or its password.
- [ ] The website's SmartScreen note is removed, since it no longer applies.
