# T591 - A launch-time session restore regenerates every viewer pane's id instead of adopting the recorded one

## Summary

restoreViewerOpen (App.zig) passes a viewer leaf's location/home/origin but NOT its recorded pane_id, so ViewerPane.create draws a fresh random one on every app relaunch. A terminal leaf keeps its id across the same restore (T113, restoreAttachOverride). Found while doing T399, whose oracle IS that regeneration. Consequence: a script holding a viewer pane's id (--target=<id>, +reload, the +list --json join key) loses it across a relaunch, and the session manifest's own pane_id for that leaf is written fresh each run. Fix: give ViewerPane.Open a pane_id override, adopt it in Window.createViewerPane, and pass leaf.pane_id from restoreViewerOpen.

## In plain terms

Every pane in Ghoztty has a permanent id that scripts and agents use to point at
it. A terminal pane keeps its id when the app restarts and puts your windows
back. A document/web pane does not — it comes back with a brand-new one. So any
automation that was pointed at a preview pane silently stops finding it after a
restart, and nothing says why.
