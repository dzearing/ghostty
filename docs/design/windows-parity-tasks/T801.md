# T801 - Terminal output does not linkify Windows environment paths (%USERPROFILE%\foo) - the POSIX $VAR/ branch has no Windows spelling

## In plain terms

A tool prints a path written with a Windows environment variable in it —
`%USERPROFILE%\src\app` or `%LOCALAPPDATA%\ghoztty\ghoztty.log`. On the Mac
the equivalent (`$HOME/src/app`) is clickable; here that spelling stays dead
text, because the pattern only knows the dollar-sign form.

## Summary

`src/config/url.zig`'s rooted branch has a `$VAR/` form
(`(?:[\w][\w\-.]*\/)*(?<!\w)\$[A-Za-z_]\w*\/`), which is what makes
`$HOME/src/config/url.zig` match. T757 added the Windows drive and UNC
branch, but not this: a `%NAME%\…` prefix has no branch, so it never
matches. ✓ VERIFIED by the T757 no-match case `"%USERPROFILE%\\foo"` in
`test "url regex"`, which passes today.

Worth settling when this is picked up: whether the variable is *expanded*
for the click (the POSIX side does not expand `$VAR` either — it hands the
literal text to the opener), and whether `%VAR%` mid-path counts the way
`foo/$BAR/baz` does.

## Validation criteria

- [ ] `%USERPROFILE%\src\app` and `%LOCALAPPDATA%\ghoztty\ghoztty.log`
      match as whole paths (cases added to `test "url regex"`)
- [ ] Prose containing a stray percent (`50% done`, `a%b`) does not match
- [ ] Every pre-existing case in that test still matches — no regression
      to the POSIX branches or to T757's Windows branch
