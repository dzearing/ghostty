# T163 - DEFERRED from viewer v1: adopt WebView2 popups as ghoztty windows

## In plain terms

When a page inside a Ghoztty viewer pane opens a second window — a sign-in
popup, a "preview" window, anything that calls `window.open()` — Windows used
to throw every one of them at the default browser. For a normal link that is
the right answer. For the popups a browser cannot take, it was not: a page that
opens an empty window and then draws into it got nothing at all, because there
was no window to draw into and the browser was handed the literal text
`about:blank`. Now such a popup opens as its own small Ghoztty window, at the
size the page asked for, and the page can write into it and close it again —
the same as on the Mac.

## Goals

- [x] A popup the browser cannot be handed — a bare `window.open()`, or a
      non-web scheme — opens as its own ghoztty window instead of being shelled
      out.
- [x] Ctrl-held is the escape hatch that keeps any popup in Ghoztty (Mac's
      Cmd).
- [x] An ordinary `http(s)` popup still goes to the default browser, unchanged.
- [x] The popup is ADOPTED, not re-opened: `window.opener`, writing through the
      returned handle, and `window.close()` all work.
- [x] The window honors `width=`/`height=` from the opener.
- [x] Covered by an acceptance script and by a live ABI test in the win32 unit
      lane.

## Summary

Filed 2026-07-29 by the T127 re-scope as an EXPLICIT deferral, so the cut stays
visible instead of becoming invisible scope. Mac opens `window.open()` /
`target="_blank"` popups as ghoztty windows that adopt the WebKit-created web
view, which is what preserves the opener<->popup relationship and therefore
`window.close()`. Windows v1 keeps the T90a behavior instead: hand the URL to
the default browser. Design: `docs/design/viewer-panes-windows.md` P9,
inventory row 19.

## Details

Mac sites: `WKUIDelegate.createWebViewWith` (`ViewerView.swift:2431`),
`webViewDidClose` (`:2482`), and the `adopting adopted:` branch of
`setupWebView` (`:390-402`) with its comment on never rebuilding the inherited
configuration.

Why this is a deferral and not a bug: v1's `NewWindowRequested -> Handled=TRUE
-> ShellExecute` is correct, useful behavior -- the popup opens in the user's
browser. Adopting it into a ghoztty window is strictly nicer and strictly
optional, and it needs a second controller lifecycle plus window plumbing that
would otherwise sit inside the T90d host floor.

Scope when taken:

- `add_NewWindowRequested` -> `get_Deferral`, create a ghoztty window with a
  viewer pane, and hand its controller back via `put_NewWindow` so the popup
  IS that pane (not a fresh navigation to the same URL -- that is what breaks
  `window.close()` and the opener relationship).
- `add_WindowCloseRequested` -> close the adopted pane, matching
  `webViewDidClose`.
- The v1 constraint this task depends on: T90d must not consume
  `NewWindowRequested` in a way that discards the deferral.

### What actually landed (2026-08-10)

The one thing the scope above got WRONG, found by reading the Mac source rather
than the task: Mac does not adopt every popup. `ViewerView.popupDestination`
hands an `http(s)` popup to the **default browser** and keeps it in Ghoztty only
when Cmd is held, when there is no URL at all (a bare `window.open()`), or when
the scheme is not web. Adopting everything would have been a regression, not
parity — the cookie-store argument in CLAUDE.md is exactly why. So the win32
change is that three-way decision PLUS the adoption machinery, not a
replacement of the browser hand-off.

- `src/apprt/win32/viewer_popup.zig` — pure, `none` lane: the destination
  decision (Ctrl / no URL / non-web scheme ⇒ ghoztty window, else browser) and
  the requested-size math (scaled, floored, clamped). `about:blank` is win32's
  spelling of Mac's nil URL and is mapped here, in one place.
- `webview2_iface.zig` — the popup args declared in full (11 slots:
  `put_NewWindow` 4, `GetDeferral` 9, `get_WindowFeatures` 10), plus
  `ICoreWebView2Deferral`, `ICoreWebView2WindowFeatures` (whose vtable puts
  **Height before Width**), and `ICoreWebView2` grown to 60 slots for
  `add_WindowCloseRequested` (59). Every offset asserted.
- `ViewerPane.zig` — `PopupRequest`, a refcounted token holding the args and the
  deferral. Two owners (the trampoline, then the pane), and **the last one out
  answers the page**: a request that is merely dropped leaves the opening
  script's `window.open()` waiting forever, so `fail()` and `deinit()` both
  release. `adoptController` hands the pane's own web view to `put_NewWindow`
  and completes the deferral INSTEAD of navigating, after every other
  subscription is already registered (completing the deferral is what starts the
  popup's first navigation).
- `Window.zig` / `App.zig` — the popup trampoline (`open_popup_window`) and the
  close seam (`close_from_page`), both keyed on the PANE rather than its leaf,
  because a bare test pane must not have a `pane_view` (that would make
  `notifyTitle` dereference an undefined `parent_window`). `InitOptions
  .initial_size` honors `width=`/`height=`, frame added via `AdjustWindowRectEx`.
- `GetAsyncKeyState` (new extern) for Ctrl: WebView2 puts no modifier state on
  the args, and `GetKeyState` in a WebView2 callback answers for the
  browser-process message being dispatched rather than for the click.

*Validation:* a new `test/win32/viewer-popup.ps1` (its own script, not a section
of `viewer-panes.ps1` — it needs a two-route page server and a scripted close),
and a live ABI test in the win32 unit lane. See `## Validation criteria`.

## Validation criteria

- [x] A bare `window.open()` becomes its own ghoztty window with one viewer pane
      at `about:blank` — `test/win32/viewer-popup.ps1` section B, ALL PASS (19).
- [x] The popup is ADOPTED, not re-opened: the opener writes a document through
      the handle `window.open()` returned and it lands in that pane's title —
      section C, and the same claim in the win32 lane's live test. **Teeth-
      checked**: replacing `req.answer(web)` with `answer(null)` +
      `applyNavigation()` (the "open a pane at the same URL" mistake) turns the
      title oracle red.
- [x] The window honors `width=520,height=680` — section D asserts PORTRAIT
      (668×897 measured at 1.25 scale), which catches both a swapped
      Height/Width vtable pair and a request ignored outright (the default is
      landscape). The unit lane asserts the exact scaled number.
- [x] `window.close()` closes the popup window and nothing else — section E; the
      opener is still there with its pane.
- [x] An `http(s)` popup still reaches the default browser — the live test's
      last section, through the `LinkSink` seam so no real browser is launched.
      (Deliberately not in the acceptance script: it would open the user's
      browser over a green run.)
- [x] Pure decision + size math unit-tested in the `none` lane
      (`viewer_popup.zig`), including the `about:blank` mapping and the clamps.
- [x] Every new/changed WebView2 vtable slot asserted by `@offsetOf`/`@sizeOf`
      in `webview2_iface.zig`.
- [x] `test/win32/persistence-flag.ps1` ALL PASS (the new script's one launch
      states `--session-persistence=false`).
- [x] Standing floor green: `scripts\floor-lane.ps1 -Lane all`, P1–P3.
