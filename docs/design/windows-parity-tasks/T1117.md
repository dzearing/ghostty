# T1117 - A pane told its child is POSIX does not disarm the history guard

## In plain terms

Ghoztty protects terminal history differently depending on which kind of shell is running. When a pane says it is running a POSIX shell, the Windows-specific protection is supposed to switch itself off and let the shell manage its own history. It stays on.

## Summary

`test\win32\history-guard-flavor.ps1` scored `1 FAILURE(S) (4 assertions passed)` in the T1094 sweep:

```
FAIL  B: a pane told its child is POSIX disarms the guard (lost 0, expected > 0)
```

`lost 0, expected > 0` is the shape: the test expects that with the guard disarmed, some history IS lost (because the POSIX shell owns it and the guard is no longer compensating). Nothing was lost, so the guard is still armed.

Small script, four other assertions passing - so the guard works, it just does not respond to the flavor signal.
