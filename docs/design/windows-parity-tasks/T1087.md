# T1087 - orphan-notify.ps1 waits a fixed 3s for the resume to attach, so it goes red when another suite ran just before it

## In plain terms

One of the tests presses the key that resumes an abandoned session, then waits
three seconds and checks whether it worked. On a busy machine three seconds is
not always enough, so the test reports a failure that is really just impatience.
A test that is sometimes wrong for no reason teaches whoever reads it to stop
believing the ones that are right.

## Summary

Measured on T352, on identical bytes, in the same minute:

- Run inside a batch, with six acceptance harnesses immediately before it:
  **2 FAILURE(S) (11 passed)** - `the agent reports the resumed session
  ATTACHED` and `the attach reset unattached_since to null`.
- Run standalone straight afterwards, nothing else touching the box:
  **ALL PASS (13 assertions)**.

Section 4 (`test\win32\orphan-notify.ps1:222-230`) sends `Return` to the
chooser and then does:

```powershell
Start-Sleep -Seconds 3
$row = @(Get-Sessions | Where-Object { $_.id -eq $loose[0].id })
Assert ($row.Count -eq 1 -and $row[0].attached) 'the agent reports the resumed session ATTACHED'
```

One fixed sleep, one sample, no retry. The attach it is waiting on is an app
dial plus an agent-side state change, and both follow box load - so the wait is
a guess about a duration nobody measured. The row selection is NOT the problem
and was checked: the target is found by session `id`, so the `index 0 of 2` /
`index 1 of 2` difference between the two runs is only sort order.

There is a second fixed clock four lines up - `Start-Sleep -Milliseconds 400`
between the arrow keys and `Return` - which is the shape T342 replaced with a
polled read everywhere else in the chooser harnesses.

## What to do

- Poll for the attached state up to a generous cap instead of sampling once at
  3s, and report the elapsed time on success so a slow box is visible as slow
  rather than as broken.
- On timeout, say what the agent DID report (attached=false with an
  `unattached_since` still set is a different failure from "the session is not
  there at all"), so a genuine regression is still legible.
- Replace the 400ms pre-Return sleep with the polled focus read `ChooserControls`
  already provides (T342).
- Check the sibling harnesses for the same pattern while in there; T1047 already
  tracks the last fixed-sleep focus read in `hero-nav.ps1`.

## Validation criteria

- [ ] `orphan-notify.ps1` ALL PASS standalone
- [ ] ALL PASS when run immediately after another acceptance suite (the
      condition that reproduced the red)
- [ ] A deliberately broken attach still fails, and the message names what the
      agent reported rather than just timing out
- [ ] The success line reports the observed attach latency
