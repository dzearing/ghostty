# T521 - Live orphaned agent sessions optionally lose their pin and age out after N days (config; default keep-forever)

## Summary

Item (3) of T411 ("Age, do not kill"). The pin that protects persistent local
sessions from the idle-TTL reaper is correct — a session must survive its
viewer quitting — but it is also what makes a LIVE orphan (a session no pane
ever re-attached) immortal: it holds a session slot (cap 256) and a real shell
process until someone finds it by hand. T411 made the leak loud (restore log
line); T520 makes it visible in the chooser; this task is the only piece that
would ever make one go away on its own.

Proposed shape: a config key (e.g. `session-orphan-ttl-days`, default 0 =
keep forever — today's behavior must stay the default) under which the agent
drops the pin on a session that has been continuously unattached for N days,
making it subject to the existing idle-TTL reaper. "Continuously unattached"
needs a recorded since-when timestamp that RESETS on every attach, so a
session in daily use never ages. The decision on whether to build this at all,
and what N/default should be, is the user's — see the linked decision
(parity-decisions, filed 2026-08-06 with T411).

Do NOT start this before the decision is resolved; if the user picks
"keep-forever only", close this as skipped with that rationale.

## In plain terms

A terminal session that keeps running in the background but that no window
ever picks up again currently lives forever, holding memory and one of a
limited number of session slots. This would add an optional setting to let
such forgotten sessions expire after a number of days — off by default, so
nothing changes unless the user asks for it.

## Validation criteria

- [ ] Default config: an orphaned live session is still never reaped (the
      T411 acceptance orphan survives arbitrarily long).
- [ ] With the TTL configured, a session continuously unattached past N drops
      its pin and is reaped by the existing idle-TTL pass; a session that gets
      re-attached resets its clock.
- [ ] Agent-contract rules hold: the new field/behavior is additive; an older
      app against a newer agent (and vice versa) degrades gracefully.
