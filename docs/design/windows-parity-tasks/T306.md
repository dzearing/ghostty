# T306 - T203c: evaluate Mica for the titlebar/tab band and record the decision

## Summary

T203's fourth deliverable, kept separate because it is explicitly a judgment
call and not a mandate: evaluate `DWMWA_SYSTEMBACKDROP_TYPE` (Mica /
Mica Alt / Acrylic) for the merged caption + tab band, and record the decision
either way — the way T124 records Liquid Glass as deliberately not ported.

Mica is the single most recognizable Windows 11 window cue and is what makes
Terminal's strip read as part of the frame. It also interacts with two things
this app has already committed to: the terminal background tint on the caption
(`applyChromeTheme`) and T202's selected chiclet MERGING into the pane, which
requires the band and the pane to agree on a color. A backdrop that samples the
desktop wallpaper does not.

Ordered after T305 because the accent/theme plumbing is what makes the
comparison meaningful — evaluating a backdrop against today's `bg + 20` bar
would be judging the wrong baseline.

## In plain terms

Windows 11 windows usually have a faintly see-through top strip that picks up a
hint of your desktop wallpaper — it is what makes Windows Terminal's tabs look
like part of the window frame. Ghoztty's Windows build does the opposite: the
title and tab band takes its color from *your terminal's* background, so the
selected tab blends into the text area below it, exactly like the Mac build.
This task was the deliberate look at whether to switch. The answer is no, and
the reasons are now written down with the measurements behind them, so nobody
has to re-litigate it from taste.

## What landed

**No system backdrop.** `DWMWA_SYSTEMBACKDROP_TYPE` stays unset; the band
stays `chrome_theme`'s wash of the terminal background. Written up as
**§3.4 "Window material: the caption + tab band is NOT Mica"** in the design
system, in the shape T124 used for Liquid Glass: a deliberate non-port with
its evidence, not a silent omission.

Three measured findings decided it:

1. **The attribute alone is a no-op.** DWM accepts every backdrop value
   (`S_OK`, reads back) and composites the material *behind* the window. Our
   client area is opaque GDI to the top edge (T254 took the caption into it),
   so the band pixel is unchanged at `#7e6734` for Auto, Mica, Acrylic and
   Tabbed alike. Adoption is not a flag flip.
2. **Opening glass into the client area destroys the band rather than
   revealing Mica.** With `DwmExtendFrameIntoClientArea(-1)`, GDI's missing
   alpha turns the band into a blend the painter never computed: `#7e6734` →
   `#a69368`, and the title measures **3.0:1** against it — under §2.3's
   non-negotiable 4.5:1. The washed color is *identical* under a solid black
   and a solid white wallpaper, which is the tell that it is not the material
   at all. Real Mica means an alpha-correct repaint of the caption, tab shapes,
   glyphs and text: a chrome-painter rewrite.
3. **After that rewrite the band's color would follow the wallpaper**, and
   three commitments depend on it not doing so: §2.3's contrast floors are
   computed from the band color; T202's selected chiclet merges into the pane
   and needs the two to agree on a color a desktop-sampling material cannot
   see; and `window-theme = auto` tints the caption to the terminal background
   (`applyChromeTheme`), which is the Mac behavior this seat matches.

Plus a fourth, practical one: the acceptance harness captures with
`PrintWindow` on a background desktop and DWM composes only the input desktop
(`test/win32/lib/TestDesktop.ps1`'s CAPTURE LIMIT), so a material's colors
would be scored on the painted band while the user looked at a composited one.

**Code change:** `MARGINS` and `DwmExtendFrameIntoClientArea` are removed from
`src/apprt/win32/win32.zig`. Both were declared and never called — a loaded gun
pointing the opposite way from the decision — and the comment left in their
place names the measurement and the design-system section.

**Filed alongside:**

- **D81** — the decision, framed as what the user would see, so this can be
  overturned by them rather than by a future turn's taste.
- **T1016** — the still-open neighbour: `background-blur` enables blur through
  the undocumented `SetWindowCompositionAttribute` accent policy, whose
  documented Win11 successor IS `DWMWA_SYSTEMBACKDROP_TYPE=3`. That case is
  about a window the user has deliberately made translucent, which §3.4 does
  not rule out.

## Evidence (measured on the box, 2026-08-20, Windows 11 26200)

**Method.** The backdrop was applied to a live debug window **from outside the
app** (the way MicaForEveryone does it), so no experiment code had to ship to
answer the question. The probes ran on the **input desktop**, deliberately: DWM
composes only that desktop, so the background test desktop cannot answer a
question about composition at all. The window was parked topmost at a known
rect and captured with `CopyFromScreen`.

Band pixel, sampled inside the caption band of the same window:

| Setting | `DwmSetWindowAttribute` | Band pixel |
|---|---|---|
| baseline | — | `#7e6734` |
| `BACKDROP=1` (auto) | `S_OK`, reads back 1 | `#7e6734` |
| `BACKDROP=2` (Mica) | `S_OK`, reads back 2 | `#7e6734` |
| `BACKDROP=3` (Acrylic) | `S_OK`, reads back 3 | `#7e6734` |
| `BACKDROP=4` (Tabbed) | `S_OK`, reads back 4 | `#7e6734` |
| legacy `DWMWA_MICA_EFFECT` (1029) | `E_INVALIDARG` | `#7e6734` |
| Mica + `DwmExtendFrameIntoClientArea(-1)` | `S_OK` | **`#a69368`**, title 3.0:1 |
| restored (`BACKDROP=0`) | `S_OK` | `#7e6734` |

(`#7e6734` is the debug build's T43 chrome tint; what matters is that it does
not move.)

**Wallpaper dependence, in the one state where the backdrop showed anything:**
the desktop was driven to solid black and then solid white
(`SPI_SETDESKWALLPAPER`) and the band read `#a69368` **both times** — so the
lift is GDI's missing alpha, not the material sampling the desktop. The user's
wallpaper was read first, restored in a `finally`, and the restore verified by
reading the value back (T179).

**Floor + regression, after the `win32.zig` cleanup:**

  agent#1=PASS` — ALL LANES PASS.**
- `test\win32\printclient-audit.ps1` (the guard `win32.zig` owes):
  **ALL PASS (8)**, re-stamped over 189 files.
- Chrome regression, because the edit is in the chrome's own header:
  `chrome-theme.ps1` **ALL PASS (64)**, `tab-strip.ps1` **ALL PASS (70)**,
  `caption-bar.ps1` **ALL PASS (32)**.
- `ipc-p1/p2/p3`: **ALL PASS (25 / 20 / 16)**.

`caption-bar.ps1` failed its FIRST run on a uniform capture — T303's guard
refusing to score a blank photo — and passed on an immediate re-run with

short under load, not a defect in this change; filed as **T1017**.
