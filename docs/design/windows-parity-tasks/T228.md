# T228 - Two split-divider oracles cannot be expressed off the input desktop (cursor shape, cross-pane stale-line scan)

## Summary

Migrating `split-divider.ps1` onto the test desktop (T218 batch 3) cost two
assertions that no rewrite on a background desktop can recover. Both were
replaced with narrower probes that pass today; this task exists so the
narrowing is visible rather than quietly absorbed, and so it is reconsidered
when T214 lands a real capture/input path.

Neither is a product defect. Both are limits of what a background desktop can
observe, in the same family as T214 (terminal-surface capture) and T224
(overlay z-order).

### 1. The SIZENS cursor SHAPE (T94)

`split-divider` used to assert the system cursor is `IDC_SIZENS` on the divider
line and 4 DIP either side of it, and is NOT at the pane center.

Measured on box 2026-07-31, and it **corrects a claim the harness header used
to make**: `SetCursorPos` returns FALSE on a background desktop (it requires
the calling thread's desktop to be the input desktop) and `GetCursorPos`
returns `-1,-1` there. `Window.zig`'s `WM_SETCURSOR` handler is
coordinate-driven and *must* be - `WM_SETCURSOR` carries no coordinates, only a
hit-test code and the triggering message - so with no readable cursor position
it falls straight through to `DefWindowProcW`. Measured: `SendMessageW(top,
WM_SETCURSOR, ...)` returns 0 at every point on the grab band, including
directly on the line.

Replaced by four `WM_NCHITTEST` probes sent to the PANE at the same four
points: HTTRANSPARENT (-1) across the band, HTCLIENT (1) at the pane center.
That is the fall-through the cursor feedback rides on, read at the source, and
it pins the band's extent more precisely than a glyph does. The band's AXIS
(the vertical/horizontal choice that picks SIZENS over SIZEWE) stays covered by
the drags and by the T155 section running both axes. **The literal glyph is
what is unasserted** - a regression that hit-tests the band correctly but loads
the wrong cursor would not be caught.

Note the same code path is dead in production whenever the input desktop is not
`Default` (locked workstation, UAC/secure desktop, disconnected RDP) - the T216
/ T223 class - but there it is cosmetic-only and nobody is looking at a cursor,
so it is not filed as a bug.

### 2. The cross-pane stale-line scan (T155)

`split-divider` used to scan a full scanline ACROSS both panes and count runs
of divider-colored pixels, on the premise that a stale line left under a pane
has been overpainted by that pane and so cannot be counted. **That premise is a
composited-screen fact, and there is no composite off the input desktop.**

Measured 2026-07-31: a `PrintWindow` capture of the top-level window retains
EVERY intermediate line a drag ever painted - three drags produced 13 runs
against a healthy product - because the GL child does not overpaint the
parent's backing store in that render. Forcing a full-window repaint (a window
move, and separately three resizes) does not clear them. Scored the old way the
test fails for pixels no user can see.

The scan is now confined to the parent-visible strip between the two pane
rects, asserting (a) the gap IS the band (`gap == bandPx`, geometry only - the
pre-fix ~5 DIP gap fails this outright) and (b) every pixel of that gap is
divider-colored in ONE run (a hairline in a wider gap reads as a run narrower
than the gap; a surviving stale line inside the gap reads as a second run).
**What is unasserted is a stale line that lands UNDER a pane** - invisible on
screen, so it was always a proxy, but a proxy with margin that is now gone.

## Direction

Do not "fix" either by weakening the current probes further. Options, in the
order they are worth trying:

- **Fold into T214.** If T214 lands a capture path that reflects real
  composition (child over parent), the cross-pane scan comes back for free -
  restore it from git history and re-measure the 13-run number, which should
  drop to 1.
- **Cursor shape has no test-desktop answer.** The only honest recoveries are
  an interactive-desktop lane (`-Interactive`, run by hand, never scored) or a
  unit test over the decision function rather than the glyph -
  `hitTestDivider`'s returned `layout` is pure logic and could be covered in
  the none-runtime lane, which would leave only `LoadCursorW`+`SetCursor`
  untested.

## Validation

- Whatever replaces either probe must FAIL against a product regressed in the
  way the original caught (a wider gap with a hairline; a wrong cursor id).
- `split-divider.ps1` ALL PASS x3 and its negative control still FAILS.
