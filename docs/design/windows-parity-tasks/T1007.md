# T1007 - Most acceptance harnesses have no staleness guard, so the next one that drifts goes red for months like the menu test did

## Summary

T987 measured it: 163 of the 225 scripts in test/win32 have no guard-due coverage row, so nothing ties them to the code they cover and nothing notices when one stops matching the app. menu-bar.ps1 was exactly that shape - a hardcoded model of the app's menus, one assertion red since T871 renamed a row, on every run for months. Not every harness needs a row (the floor lanes and P1-P3 run constantly, and a gate that fires on unrelated edits is noise T783 warns about), so this is a triage pass, not a bulk edit: pick out the harnesses that (a) mirror a table or model that lives in the source, or (b) are the ONLY proof of a behavior and are not in the P1-P3 floor, and give those a row. List the ones deliberately left uncovered with a reason, so the gap is a decision rather than an oversight.
