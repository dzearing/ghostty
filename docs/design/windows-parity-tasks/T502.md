# T502 - Tracker tags and a full task detail view on the dashboard

## In plain terms

The dashboard's activity feed told you THAT something landed but not what
kind of thing it was - a user-visible fix, a speed improvement, or just test
plumbing all looked the same, and clicking gave you nothing more. Now every
task can carry category tags that show on the cards, and clicking any card
or task id opens a full readable view: the goal in plain language, the run's
step-by-step log, what was validated and how, and links to every related
task.

## Goals

- [x] `tags:` frontmatter with a closed vocabulary (feature / fix / polish /
      perf / test / infra / docs / security); `new -Tags`, validate guards,
      dashboard POST support
- [x] Tag chips on activity cards, in-flight cards, the task table, and the
      detail dialog
- [x] Activity cards click through to the task detail view (headline and
      every completed/filed chip)
- [x] The detail dialog is a real L2 view: rendered markdown (headings,
      checklists as native boxes, fenced code), goals, validation criteria,
      progress log, commits - plus a Related row and inline task-id links
      built from deps + body mentions
- [x] New tasks scaffold a `## Validation criteria` checklist; go.md
      requires ticking each criterion with how it was verified

## Summary

User request (2026-08-05): tags/categories visible on activity cards so
user-facing work reads apart from perf and test updates at a glance; cards
clickable into a full L2 view of the task - the goal, what happened during
the run, what validation was done and what criteria were met, plus new tasks
created and related references, linked.

Implementation: `parity-tasks.ps1` (tags + vocabulary), `task-dashboard.js`
(tags/progress/validation in the payload, tags on activity items, stale
detection now respects dirty-file mtimes so the task being worked right now
no longer reads "stale"), `task-dashboard.page.html` (tag chips, clickable
cards, the L2 dialog: mdRender grew fenced-code + checkbox support, task-id
linkification, Related row). The markdown pipeline stays textContent-based
throughout - task bodies can never inject markup.
