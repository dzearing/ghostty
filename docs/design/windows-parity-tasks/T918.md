# T918 - relay-account section 8 skip-guard only checks the legacy macos/ client-id path

## Summary

test/win32/relay-account.ps1 section 8 (the T747 unconfigured-build case) guards itself with a Test-Path on 'macos\google-client-id.txt' at line 706 - the LEGACY path only. src/build/Config.zig:580-589 reads repo-root 'google-client-id.txt' FIRST and its own doc comment (Config.zig:575-579) calls the repo-root spelling 'the spelling to use' for exactly the Windows seat this test runs on. So a Windows checkout that follows the documented setup bakes an id in, section 8 does NOT skip, and the suite reports 6 phantom FAILs ('no account control is visible', 'the row says sign-in is not set up', both hint assertions, 'the hint does NOT point at a button', 'clicking the hidden button starts no browser flow') describing a state the build cannot be in. Observed 2026-08-17 on a build with the repo-root file present; the section's own positive control ('CONTROL: with a client id the sign-in button IS visible') PASSED in the same run, which is the tell. Instruments-that-lie class: a green suite is the point of the T747 coverage and this turns it red for doing the right thing. Fix: the guard must test BOTH paths in the same order Config.zig does (repo-root then macos/), i.e. skip when either exists. Better still, make the section not need a skip at all - if the GUI honored a 'force unconfigured' test override (an env var meaning 'resolve no client id') the unconfigured path would be measurable on every seat instead of only on seats that never set one up, which is what let T747 ship in the first place. Validation: with repo-root google-client-id.txt present the section SKIPs (or passes via the override) and relay-account.ps1 reports 0 failures; with both files absent the six T747 assertions still run and still pass.

## Validation criteria

- [ ] With repo-root `google-client-id.txt` present, `test\win32\relay-account.ps1` reports **0 failures** (section 8 skips, or passes via a force-unconfigured override).
- [ ] With BOTH client-id files absent, the six T747 assertions still run and still pass - the coverage is not silently deleted by the fix.
- [ ] The guard consults the same paths, in the same order, as `src/build/Config.zig:580-589`, so the two cannot drift again.
- [ ] Harness audit rules in `docs/claude/testing.md` satisfied (positive control retained).
