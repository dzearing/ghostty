## Re-scoped 2026-07-29 (T127)

Grown by the `+reload` server verb (`docs/design/viewer-panes-windows.md` P8) --
same code path as the watcher's re-render, so splitting it out would duplicate
the work. The client verb already exists in the shared CLI
(`src/cli/ghostty.zig`); win32 has no server implementation. Port
`ViewerView.reloadContent` (`:517`) exactly:

- web mode: re-fetch from ORIGIN bypassing caches. WebView2's `Reload()` is a
  normal reload, so use
  `CallDevToolsProtocolMethod("Page.reload", {"ignoreCache":true})` with
  `Reload()` as the fallback. A "reload" that silently serves cache is
  half-parity that gets reported as a bug months later.
- file mode: re-arm the watcher, then re-render preserving scroll.
- no completed load yet, either mode: full load.
- terminal target: `target '<name>' is a terminal pane, nothing to reload`,
  exit 1 (exact Mac string).
