# T796 - Audit acceptance scripts for test seams that mask the shipped default

## Summary

T747's defect shipped past a green suite because every GUI section of test/win32/relay-account.ps1 sets GHOSTTY_GOOGLE_CLIENT_ID=cid-e2e. The seam is legitimate (a fake relay needs a fake id), but it meant the configuration every real user runs - no id at all - was never once exercised, so a dead button read as a fully tested feature for months. The shape generalises: any env/registry/file seam a script sets to make a flow reachable is also a statement that the UNSET case is untested. Sweep test/win32/ for the seams that turn a feature ON (GHOSTTY_*/GHOZTTY_* env sets, seeded stores, staged config) and, for each, answer whether the absent case has an arm anywhere; file what is missing. Then decide whether the rule wants enforcing the way the exit-code, skip-visibility and asserted-nothing audits are - an analyzer plus a ceiling that may only fall - or whether a one-time sweep plus a note in the harness header is proportionate.
