# T1326 - The bundled ghoztty and process-feedback skills are three weeks behind main, so the image viewer Windows already has goes undocumented

## In plain terms

The instructions Ghoztty ships to Claude for driving itself still describe an
older Ghoztty. They never mention that you can open a picture in a side pane -
Windows grew that in T1183 and it works - so an agent reading them will not
offer it, and the same paragraph is stale in the feedback skill. Nothing is
broken; it is a manual that fell behind the product.

## Summary

P1: hook-json's vendor-drift section is RED on it, so the guard protecting every bundled asset shows a colour nobody can act on; and the skill text is what tells an agent the image viewer exists, which on Windows it does (T1183).

What main added and this branch has not taken:

- **`skills/ghoztty`** - the image viewer. The `--view=` rows for
  `+new-window` and `+split` gained "an **image**", and a whole `Images`
  bullet documents the picture viewer (pinch-zoom, two-finger pan,
  double-click best-fit <-> 100%, animated GIFs, Cmd-F declined). The skill
  frontmatter `description:` gained the image triggers, which is what decides
  whether the skill fires at all on "show me that screenshot".
- **`skills/process-feedback`** - one table row documenting `source.kind`
  (`file` | `web` | `image`), and that an `image` report carries no
  `selection` and no `quotes`.

The process-feedback copy is a **fork** (T1321 added the release-request
text), so it takes main's row rather than main's whole file; the ghoztty copy
is unforked and takes main's file wholesale.
