# T424 - Session-interrupted wording: 'Session interrupted: <reason>', a colon and not an em dash

## In plain terms

When a terminal's background process gets restarted out from under it, the
window tells you so. Today it says it with a long dash - "Session interrupted -
the background terminal process was restarted" - and it says it two different
ways depending on where you read it: the sticky note at the top of the pane and
the text in the scrolled-back history are worded differently from each other.
The user asked for one plain form with a colon. After this, both places say the
same sentence, the same way: "Session interrupted: the background terminal
process was restarted, so this session was closed."

## Goals

- [x] The sticky note reads `Session interrupted: ...`, no long dash.
- [x] The scrollback text reads the same sentence, in the same shape.
- [x] The "press any key to relaunch" message drops its long dash too.
- [x] The tests pin the exact wording rather than being loosened to pass.

## Summary

**User report, 2026-08-03**: *"I expected the messaging to NOT have a long
emdash in it, but rather a colon (Session interrupted: <reason>)."*

Today, `src/termio/session_notice.zig:85`:

```
**Session interrupted** — the background terminal process was restarted, so
this session was closed. Nothing was re-run.
```

Wanted:

```
Session interrupted: the background terminal process was restarted, so this
session was closed. Nothing was re-run.
```

Smallest task of the five filed from this report, and entirely inside one pure
module that already has unit tests in the none-runtime lane.

## Do both carriers, and check the whole surface

The em dash is in `formatBanner`. The in-stream `format` (line 53) uses a
different construction again — `--- session interrupted: ... ---` — so the two
carriers do not currently say the same thing in the same shape. Bring them into
line on the colon form rather than fixing only the one in the screenshot.

While there: `Remote.zig:797` has a third string in the same family,
`[ Session ended ] — press any key to relaunch`, with the same em dash. It is a
different message on a different path (the `prompt` policy), but it is the same
voice and the same user preference applies. Fix it in the same change or say
in this file why not.

The tests at `session_notice.zig:174-311` assert on substrings, so several will
need updating with the text — update them to the new wording rather than
loosening them, since pinning the exact user-visible string is the reason that
module is pure and testable at all.

## Validation

`zig build test -Dapp-runtime=none` green with the updated assertions, and no
`—` left in any of the three strings (grep the module).

## What landed (2026-08-03)

All three strings now use one shape — `Label:` and lower-case reason, no dash of
any length — and the two notice carriers open with the **same sentence**, which
they never did before.

`src/termio/session_notice.zig`:

| | before | after |
|---|---|---|
| in-stream (`format`) | `--- session interrupted: the background terminal process was restarted ---` | `Session interrupted: the background terminal process was restarted, so this session was closed.` |
| banner (`formatBanner`) | `**Session interrupted** — the background terminal process was restarted, so this session was closed. Nothing was re-run.` | `**Session interrupted:** the background terminal process was restarted, so this session was closed. Nothing was re-run; this is a fresh shell.` |
| command label | `previous command:` / `Previous command:` | `Previous command:` in both |
| closing line | `nothing was re-run; this is a fresh shell.` | `Nothing was re-run; this is a fresh shell.` |

`src/termio/Remote.zig:835` (the `prompt` policy, done in the same change rather
than deferred): `[ Session ended ] — press any key to relaunch` →
`Session ended: press any key to relaunch`. Same voice, same preference, and the
one remaining em dash in the family.

The `--- session restarted ---` divider (the `auto` policy) is deliberately
**untouched**: it is a rule, not a labelled sentence, and the user's report was
about the interrupted message.

A new unit test, `format: the label is a colon, never an em dash`, asserts on
**both** carriers at once that no em dash, en dash or `---` run survives and
that both carry `Session interrupted:` / `Previous command:` — so the two cannot
drift apart again the way they had. The existing assertions were updated to the
new text rather than loosened, per the task.

`test\win32\session-relaunch-notify.ps1`'s `Get-NoticePlacement` used
`String.IndexOf(string)`, which is case **sensitive**, against a lower-case
`'sessioninterrupted'`. Recapitalizing the in-stream copy would have silently
broken its placement assertions, so it is now `OrdinalIgnoreCase` — placement is
what that script scores; the wording is pinned in the pure lane.
