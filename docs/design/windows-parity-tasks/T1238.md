# T1238 - The session and agent acceptance scripts still open Ghoztty windows on the user's desktop (T1193 batch 1 of 4)

## Summary

T1193 measured the gap and built the sweep; this batch is 13 of the session and agent lifecycle
scripts it left declared as pending. Each one starts the app from a process
sitting on the user's desktop - a bare `Start-Process $Exe`, or a cold
`& $Exe +new-window`, which is the one verb that auto-launches - so running it
throws a window across whatever the user is reading.

The migration is mechanical and T1193's `ipc-p1.ps1` / `ipc-p2.ps1` /
`ipc-p3.ps1` are the worked examples:

1. `. (Join-Path $PSScriptRoot 'lib\TestDesktop.ps1')` and `$td = New-TestDesktop`
   before the body; `Remove-TestDesktop` in the teardown.
2. Replace every `Start-Process $Exe` with `Start-OnTestDesktop`.
3. Replace every `& $Exe <verb>` with a local one-line `Ghoz` helper over
   `Invoke-OnTestDesktop`, and read `$r.ExitCode` where the script read
   `$LASTEXITCODE`. The helper captures stdout and stderr to a file, so a
   `cmd /c "... > file"` dance for the GUI-subsystem exe (T245) goes away too.
4. DELETE the script's `# @user-desktop-launch:` line from `lib\TestDesktop.ps1`.
   A migration that leaves it behind fails `desktop-launch-audit.ps1` as a
   stale declaration - that is what makes the list burn down.

## In plain terms

Running the session and agent tests used to throw terminal windows across
whatever the user had on screen. Ten of the thirteen now open their windows on a
background desktop nobody is looking at; two of the rest can only ever be
measured on a desktop that has a shell, so they are declared as permanent
exceptions with that reason, and the last one is blocked behind a real product
defect it exposed.

## Outcome

**Migrated and green on the box (10):** `agent-autostart`, `agent-handoff`,
`agent-recovery`, `session-close`, `session-crash-recover`, `session-open`,
`session-persistence`, `session-vanished`, `sessions-agent-build`,
`single-instance-join`.

**Permanent exceptions, measured not assumed (2):** `agent-job-escape.ps1` and
`relaunch-guard.ps1`. Both assert that a process the app spawns lands OUTSIDE a
kill-on-close job. From a pane's shell job chain the breakaway tier is refused -
the app logs `breakaway spawn refused err=.ACCESS_DENIED` - so the escape that
actually happens is the SHELL-PARENT hop, and a background desktop has no shell
window: migrated, the app logs `shell-parent spawn unavailable
err=error.NoShellWindow` and spawns the agent inside the job, turning a correct
build red. Their declarations now carry that reason instead of "pending".

**Blocked (1):** `session-relaunch.ps1` -> T1265, behind T1264. Migrated, its
section A goes red because the `--- session restarted ---` divider never arrives
- which is already red in its own section B on an unmodified checkout, measured
twice. That is a product defect, not a migration artifact.

Three things the migration had to do beyond the mechanical recipe, each of which
would have made a check silently stop measuring:

- `single-instance-join.ps1` found its confirm dialog with `FindWindowW` from the
  host thread, which searches the HOST's desktop - so D0/D11, which assert the
  dialog is ABSENT, would have passed for the wrong reason. Now `Get-TestWindows`
  + `Send-TestRawMessage`, both marshalled onto the desktop's thread.
- `session-persistence.ps1` carried a private EnumWindows/MoveWindow driver for
  its geometry section; same problem, replaced with the harness helpers (which
  also make the process DPI-aware, as that driver did).
- `agent-recovery.ps1`'s surface-set oracle enumerated windows the same way, and
  an EMPTY set compares equal to another empty set - every "the surfaces were
  replaced" assertion would have passed while measuring nothing.
