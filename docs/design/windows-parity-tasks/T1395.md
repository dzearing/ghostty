# T1395 - A tab tooltip prints the full C:\Users\... path where it should read ~

## Summary

`test\win32\tab-tooltip.ps1` fails four assertions, all the same shape: the tip
renders the location as `C:\Users\David\AppData\Local\Temp\...` where the script
expects `~\AppData\Local\Temp\...`.

The derivation itself is not the bug. `tab_tooltip.tildeHome` is pure, correct
and none-lane tested (exact home, trailing separator, null/empty home, no
match). What fails is the `home` the CALL SITE hands it:
`Window.zig` (the tab-tip text derivation) takes it from
`internal_os.home()`, which on Windows is `HOMEDRIVE` + `HOMEPATH`
(`src/os/homedir.zig:79`) and returns null if either variable is missing.

So the likely cause is that the app under test is launched into an environment
where those two are not set - which would mean every user whose shell or
launcher drops them sees full paths in their tips too, not just the harness.
Establish which it is before patching: if it is real, the fix is a fallback to
`USERPROFILE` (which is always present) rather than a change in the test.

Proven pre-existing by the T584 bisect on 2026-09-06: with the tab strip's font
size forced back to the old value, the same four assertions fail identically.

## In plain terms

Hovering a tab is supposed to show a short path with `~` standing in for your
home folder. Right now it shows the whole thing, starting at `C:\Users\...`,
which is longer, harder to scan, and the opposite of what the tip is for.

## Details

- Reproduce first: launch `zig-out\bin\ghoztty.exe` by hand, hover a tab whose
  cwd is under your home, and see whether the tip abbreviates. If it does, the
  bug is the harness's launch environment; if it does not, it is the product.
- `internal_os.home()` returning null is silent by construction - `catch null`
  at the call site - so nothing distinguishes "no home" from "home did not
  match". Whatever the cause, that silence is worth removing.
- `USERPROFILE` is set by Windows for every interactive process and is what the
  rest of this codebase already reaches for (`AgentIntegration.zig:567`,
  `runtime_agent.zig`). `HOMEDRIVE`/`HOMEPATH` are a domain-login convention
  and are genuinely absent in some launch paths.
- The same abbreviation feeds the palette's jump subtitles
  (`palette_jump.zig`), which claims to abbreviate "exactly like the tab
  tooltip" - so whatever lands here should fix both, and the palette should be
  checked by hand for the same symptom.

## Goals

- [ ] A tab tip under the home directory reads `~\...`
- [ ] The home lookup does not depend on `HOMEDRIVE`/`HOMEPATH` alone
- [ ] The palette jump subtitle abbreviates the same way
