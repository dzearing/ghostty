# T838 - The T443 data-breakpoint instrument arms per integrity check, which is too slow to finish a lane - arm per page instead

## Summary

T443's corrupted value is now known to live at a heap address (Page.memory.ptr) that is stable for the life of the page, so crash-databreak.ps1 can arm once per page instead of once per verifyIntegrity call. The per-call shape cost 335,878 arm/disarm cycles at ~2ms each and timed out mid-lane without measuring anything.

## In plain terms

The tool built to catch the memory bug red-handed is currently so slow that it
never finishes a single test run — it stops and restarts its watch hundreds of
thousands of times. We now know exactly which four bytes get scribbled on, and
that address stays put for as long as the page it belongs to exists, so the
watch can be set once per page instead. That is the difference between a tool
that times out and a tool that can actually catch the culprit.

## Goals

- [x] `crash-databreak.ps1` can arm on `&page.memory.ptr` for the lifetime of a
      page instead of around every `verifyIntegrity` call — `-WatchPages`, which
      reads `self` out of the probed spill slots and arms `ba w8` on the heap
      field. It arms once and never disarms, rather than bracketing
      `Page.init`/`Page.deinit` as this file first proposed: a `ba` needs no
      teardown, and NOT disarming is what makes the entry breakpoint disposable.
      The recycled-address false positive that shape allows is handled by the
      shape guard instead (see T443 turn 4)
- [x] A run reports arm counts in the low single digits rather than 335k, and
      completes a full lane inside its timeout — **4 arm cycles**, entry
      breakpoint disabled afterwards, against 335,878 before
- [x] Only 4 hardware debug registers exist, so the design says explicitly which
      pages it watches and what it is blind to — the mode banner and the verdict
      both print the coverage statement, and the verdict refuses to imply more
      than it measured. Improving that coverage is T839

## Details

**Filed with `deps: ["T443"]`, which was a cycle** — T443 had been given
`deps: ["T838"]` the same afternoon, so each waited on the other and `next`
could never hand out either. That is why the work landed under T474 (the
hardware-write-breakpoint experiment this is the mechanism for) rather than
here; the dep was cleared when the cycle was found. A follow-up depends on its
parent, never both ways.

Background and the disassembly that established the target: T443's
"THE DAMAGED VALUE IS THE FIELD, NOT A COPY" section (2026-08-14, turn 3).
`Page.memory` is field 0 of `Page`, so the load that produced the
half-clobbered base is `mov r9,[self]` — reading the heap field directly, with
no stack temporary in the path.

## Validation criteria

- [x] An armed run against a real lane completes without hitting
      `-TimeoutSeconds` — `-Lane agent -AttachName core -WatchPages` on
      2026-08-14. The arm/disarm-parity check this line originally asked for
      does not apply and was the wrong check: nothing disarms in this design, so
      what proves the watch is live is the arm count plus the `ARMED-FULL`
      marker, both asserted in the acceptance script
- [x] The instrument is proven against a staged wild write to a page's
      `memory.ptr` high half, the way the per-call shape was proven in T458 —
      writer instruction (`mov dword ptr [rdx],11A60h`), full stack, dump.
      Section 8b of `test\win32\crash-databreak.ps1`
