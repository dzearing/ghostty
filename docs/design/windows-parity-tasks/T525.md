# T525 - Every-morning client refresh: deliver the latest build AND cleanly reboot the running app + agent

## User directive (2026-08-06, verbatim)

"I would like to at least have my client updated every morning, and if that
requires a subagent reset, that is fine, but the app needs to reboot
correctly."

## What already exists vs what is missing

- The go-loop DOES deliver most mornings (`%TEMP%\ghoztty-upgrade.log` shows
  05:56 today: exe + com + agent swapped in all three install locations,
  POST-SWAP VERIFY OK). Delivery is not the gap.
- The gap is the REBOOT: the user's open windows keep running the old exe, and
  the path that is supposed to hand them the new one - the mandatory
  agent-upgrade confirmation -> destructive refresh -> windows come back - has
  killed the app without recovery four times (T229 x2, T421, 2026-08-06).
  T524 fixes the recovery; this task makes the morning flow use it.

## Goals

- [ ] Once per morning (~5-6am, alongside the existing delivery), the user's
      running Ghoztty is restarted onto the freshly delivered build: sessions
      snapshot, app exits, new exe starts, windows/panes restore. An agent
      reset (killing pane processes) is explicitly acceptable per the
      directive - prefer session preservation when the agent protocol allows,
      fall back to reset when it does not.
- [ ] The reboot is verified, not assumed: the flow confirms a live window
      exists on the new build afterwards (+list answers and +version reports
      the delivered sha) and logs the outcome; a failed comeback triggers the
      T524 guard or an explicit relaunch, never a silent empty desktop.
- [ ] The user starting their day sees a current client without ever touching
      the upgrade dialog.

## Notes

- Depends on T524 (guard survives the app's death) - without it a failed
  morning reboot recreates the empty-desktop incident unattended, which is
  worse at 5am than interactively.
- The upgrade script's RESUME-REUSE FAIL streak (3 consecutive deliveries,
  see %TEMP%\ghoztty-upgrade.log; the resume prompt text arrives with '>'
  characters stripped) is the loop-side half of the morning flow and needs
  its own look - file separately if not absorbed here.
