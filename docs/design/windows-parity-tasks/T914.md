# T914 - The release-artifacts guard goes permanently red on a box without Docker, so its workflow half can never be cleared

## Summary

`scripts\guard-due.ps1`'s `release-artifacts` row covers eight files under ONE
stamp, and `test\win32\release-artifacts.ps1` only stamps on a run with zero
skips (correctly - a Docker-less run never looks at the packaging sections).
But two of those sections need Docker, and on this box Docker is deliberately
not started (the WSL2 backend has buried the machine before). So:

- `.github\workflows\fork-ci.yml` changes → the guard goes DUE.
- The harness runs ALL PASS, exercising exactly the sections that cover that
  file (A and E), and then declines to stamp because B skipped.
- The guard stays red forever, and every later turn's `validate` fails on
  somebody else's change until it reaches for `-NoGuardDue`.

Observed 2026-08-17 during T907: the row was already red at claim time from an
earlier turn's `fork-ci.yml` edit, the harness passed, and the commit had to go
through the hatch.

The fix is to stop pretending one stamp covers two independent claims: SPLIT the
row so the workflow/static half (sections A, C, D, E) has its own stamp that a
Docker-less run can honestly write, and the packaging half (`build-msi.sh`,
`build-portable-zip.sh`, `install-msitools.sh`) keeps a stamp only a full run
writes. Then a workflow edit is clearable here, and a packaging edit still
truthfully reports that nobody has run it.

## In plain terms

One of the checks that says "somebody has actually run the test for this code"
can never say yes on this machine, so it eventually gets ignored. Split it so the
half that CAN be checked here is checked here.

## Goals

- [ ] Two rows (or a per-section stamp) instead of one, so a Docker-less run
      clears what it genuinely covered.
- [ ] The packaging half still refuses to stamp without Docker.
- [ ] `guard-due.ps1 check` exits 0 on this box after a normal harness run.

## Validation criteria

- [ ] `test\win32\release-artifacts.ps1` with Docker down stamps the workflow
      half and NOT the packaging half.
- [ ] `scripts\guard-due.ps1 check` exits 0 afterwards on a clean tree.
- [ ] Touching `dist\windows-installer\build-msi.sh` still makes a guard due,
      and a Docker-less run does not clear it.
- [ ] `test\win32\guard-due.ps1` (or the guard's own acceptance) covers the split.
