# T1271 - update-failure-visible.ps1 still points the applier at the repo build, the way T1268 did

## Summary

T1268 gave update-apply.ps1 a throwaway install directory because arming the applier with zig-out\bin\ghoztty.exe hands a process whose job is to rename ghoztty.exe aside the one binary the turn depends on. update-failure-visible.ps1 has the same shape and runs the applier three times (lines 169, 225, 265 - the spec's third field is \$Exe). One straggler holding the exe open at any of them leaves the turn with no build. Give it the same sandbox copy, and adopt T1268's section 11 check (the repo build survived) plus Restore-RepoBuild.

## In plain terms

A test that exercises "install an update" was allowed to point the real
updater at the freshly built Ghoztty. The updater's job, when it meets a file
it cannot overwrite, is to move it out of the way - and every package these
tests install is one Windows rejects, so nothing ever puts it back. One
leftover process holding the build open at the wrong moment and the whole rest
of the session has no terminal to test with, for a reason that looks like
everything is broken.
