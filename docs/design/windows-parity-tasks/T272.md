# T272 - Two GUI scripts were missed by T212's split and still take the user's foreground, and the interactive-by-design exceptions are undeclared

## In plain terms

Running the test suite used to yank the mouse and keyboard away from whatever
the user was doing, so a batch of work moved the tests onto an invisible second
screen. That work was declared finished while two test scripts had quietly been
left behind, and nobody noticed because nothing was counting. Those two are
fixed; what lands here is the part that keeps it fixed - the handful of tests
that genuinely have to use the real screen now say so in one place, and a check
fails the moment a new test starts grabbing focus without saying so.

## Goals

- [x] Migrate `overlay-zorder.ps1` (T224) and `split-dim.ps1` (T225)
- [x] Declare each interactive-by-design script, with its reason, in one place
- [x] A check that fails on any undeclared foreground grab
- [x] The check also fails on a declaration that is no longer true

## Validation criteria

- [x] `test\win32\foreground-audit.ps1` is `ALL PASS` on a clean tree -
      **verified**: `T272 ACCEPTANCE: ALL PASS (26 assertions)`, exit 0.
- [x] The check FAILS when a foreground grab is added to a script that is not on
      the exception list - **verified twice**: once by accident (this task's own
      acceptance script tripped C1 before its stated-intent marker was added:
      `foreground-audit.ps1:66 undeclared`, exit 1), and once deliberately by
      `-TeethCheck`, which writes a real grabber into `test\win32\` and requires
      the sweep to name it.
- [x] The list the check enforces is the list a human reads - **verified**: the
      analyzer parses `lib\TestDesktop.ps1`'s header (A6/A7), and C3 asserts
      every declared script is still a real grabber, so the check cannot go
      green because the detector went blind.
- [x] No assertion had to be weakened to migrate - items 1's two scripts were
      validated in T224/T225 with their unportable assertions named there.

## Summary

T218 closed the migration at 13 of 13 and T217 at 23 of 23, so the fleet-wide
claim is now *"the acceptance scripts no longer steal the user's foreground"*.
**That claim is not true yet**, and nothing tracked the remainder - which is
how it would have gone quiet.

Swept after T218 batch 6 (2026-08-01): five scripts under `test/win32/` still
call `SendInput` / `SetForegroundWindow` and do NOT load
`lib\TestDesktop.ps1`. Three are deliberate and one is retired; **two are
plain misses.**

## The fix

1. Migrate `overlay-zorder.ps1` and `split-dim.ps1`. Both drive **layered
   overlays**, so read T218 batch 3 and `pane-banner.ps1` first - the overlay
   capture path is proven, and `Get-TestWindows -Class 'GhozttyDimOverlay'` /
   `'GhozttyBannerOverlay'` is how the overlays are found.
   - **The open question is z-order, not input.** `overlay-zorder`'s claim is
     "this popup is not above that window", and a background desktop has no
     foreground window at all (`GetForegroundWindow` returns 0), so
     `GrabForeground` has nothing to assert against. Z-order itself is still
     readable - `GetWindow(GW_HWNDPREV/GW_HWNDNEXT)` and `EnumWindows` order
     are both z-order, and `Focus-TestWindow` is the harness's activation. The
     T218 batch-3 rule applies: assert the underlying decision, and if a
     specific assertion genuinely cannot hold off the input desktop, name it
     with the measured reason rather than weakening it.
   - **DONE 2026-08-01 (T224) for `overlay-zorder`.** The open question is
     answered by measurement, not argued: `Focus-TestWindow` really does raise
     the window inside the band and really does deliver WM_ACTIVATE, so "the
     ACTIVE window" (`Get-TestActiveWindow`) is a faithful stand-in and the
     script now asserts against it. Two things could not port and are named
     with their measurements in T224 rather than weakened: the sandwich is no
     longer the section-B repro (topmosting the overlay raises its owner too,
     unopposed with no foreground), and the SWP_SHOWWINDOW lift does not
     reproduce at all. Section E is skipped pending **T277**. `ALL PASS (24)`
     x3, negative control FAILS. **`split-dim` is the remaining miss.**
   - **DONE 2026-08-01 (T225) for `split-dim` - item 1 is now complete.** Its
     input half was the easy half; the open question was the run-3 blend check,
     a `GetDC(NULL)` screen read. Answered by T214 route **1**: the dim overlay
     is not terminal content at all - the GUI thread fills it with a solid GDI
     brush (`DimOverlay.zig`), so `Get-TestWindowPixels` on the
     `GhozttyDimOverlay` reads the real fill (measured `255,0,0` under
     `--unfocused-split-fill=#ff0000`, `16,16,20` under a defaulted fill on
     `--background=#101014`). What that does NOT cover - DWM's composite of fill
     and alpha, i.e. what the eye sees - is named in the script header; both
     INPUTS to the composite are asserted. `ALL PASS (29)` x3, negative control
     FAILS. **Items 2 and 3 are what keep this task open.**
2. **Declare the exceptions in one place** - a list in `lib\TestDesktop.ps1`'s
   header (which already owns the `-Interactive` escape hatch) naming each
   interactive-by-design script and WHY. An undeclared exception is
   indistinguishable from a miss, which is this task's whole point.
3. **Make it enforceable.** A check that greps `test/win32/*.ps1` for
   `SendInput` / `SetForegroundWindow` and fails on anything not on that list,
   so the property cannot silently regrow. A new script gets it for free.

   - **DONE 2026-08-11 - items 2 and 3, which closes the task.** The list is
     `# @input-desktop-exception: <script> -- <reason>` lines in
     `lib\TestDesktop.ps1`'s header, next to the `-Interactive` hatch a reader
     already meets there, and `lib\ForegroundAudit.ps1` PARSES that header
     rather than restating it - so there is one list, not two that can drift.
     Three kinds, all enforced at zero: `undeclared`, `stale-declaration` (a
     declaration that is no longer true, which is how a real miss gets waved
     through) and `malformed-declaration` (including an EMPTY list, which would
     otherwise turn every violation into a pass).
   - **A plain grep would have been wrong**, and measurably so: 25 scripts
     match `SendInput|SetForegroundWindow`, and 22 of them are comments
     explaining that it is dead off the input desktop. Scoring those as
     violations would have put 22 innocent scripts on the exception list - the
     same rot from the other direction. So the detector reads PowerShell tokens
     and drops comments, and strips `//` / `/* */` comments inside `Add-Type`
     here-strings (where the real P/Invokes live). Token-based, the suite splits
     cleanly: exactly the three declared scripts have live sites.
   - Watched set widened past the two the task names to every user32 entry point
     that reaches the user's desktop (`keybd_event`, `mouse_event`,
     `SetCursorPos`, `SwitchToThisWindow`) - `SetCursorPos` is already in use in
     `context-menu-real-input.ps1`, so a check that only knew the two names
     could be walked around by a new script for free. A hardcoded
     `New-TestDesktop -Interactive` counts as a grab site too; forwarding the
     debug switch (`-Interactive:$Interactive`, 86 sites) does not.
   - One narrow stated-intent marker, `# foreground-audit: <reason>`, for a file
     that NAMES the APIs without calling them. Exactly one file carries it - the
     acceptance script, whose fixtures are string literals holding the very
     P/Invokes it detects. It is not an alternative to declaring an interactive
     script.
