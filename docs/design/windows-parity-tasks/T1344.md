# T1344 - Banners flicker when they expand and collapse

## In plain terms

A pane banner that expands or collapses flashes on the way. The Mac's does not.

## What the user reported (2026-09-04)

> "things flicker ... when i expand/contract banners, they flicker."

Split out of T1324. Separate from the divider-drag slowness (T1343) because it
is a different path: the T149 collapse animation, the reserved band the layout
hands the popup, and the layered popup's own repaint.

## Where to look

- `BannerOverlay.updatePosition` already reasons carefully about the animating
  case: while `collapse_anim` runs, the popup has to cover BOTH the settled
  band and the card's current height, and a resize sets `SWP_NOCOPYBITS` so a
  frame of stretched card is not blitted in. Whether that is enough is exactly
  the question.
- The terminal underneath snaps to the settled band before the card finishes
  animating, which is deliberate (it is what lets the inset snap at all) and is
  a plausible source of a one-frame gap.
- The band is reserved by `Surface.bannerLayoutInset` and applied by the
  window's layout pass; the popup is moved afterwards, in a separate
  `SetWindowPos`. Two windows changing size in two calls is a flicker shape
  even when each one is individually correct.

**Capture the flicker before theorising about it.** `banner-resize-repaint.ps1`
established that layered popups do not come back from `PrintWindow` on the
background test desktop, so a pixel oracle needs either the interactive desktop
or an in-app frame log. Say which one this used.

## Validation criteria

- [ ] Expanding and contracting a banner does not flicker - demonstrated, not
      asserted, with the capture method written down.
- [ ] Whatever intermediate state was found is covered by an assertion in
      `test/win32/` that fails if it comes back.
- [ ] No regression in `test/win32/banner-resize-repaint.ps1` or
      `test/win32/pane-banner.ps1`.
