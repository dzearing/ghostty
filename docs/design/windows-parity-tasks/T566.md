# T566 - parity-decisions.ps1 has no validate command, so a malformed decision file is only found when the dashboard renders it wrong

## Summary

parity-tasks.ps1 validate is the gate before every tracker commit and catches bad ids, statuses, seats, tags and dangling deps. The decisions directory has no equivalent: a decision with a missing Task link, a status outside open/resolved, an option list with no Pros/Cons, or more or fewer than one (Recommended) flag passes unnoticed until someone looks at the Activity feed. new already warns about the recommended-flag count at mint time; validate would apply the same rules to the whole directory.

## In plain terms

When the loop makes a call you might want to overturn, it writes it up as a decision card and the dashboard shows it at the top of the Activity feed. Nothing ever checked those cards were well formed, so one that pointed at a task that does not exist, or listed options with no pros and cons, or recommended none of them, reached you looking broken - and you were the first reader who could notice. Now the same check that runs before every tracker commit reads the decision cards too, so a malformed one is caught by the loop instead of by you.
