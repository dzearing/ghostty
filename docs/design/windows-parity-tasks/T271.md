# T271 - An acceptance script that asserted nothing must not exit 0

## In plain terms

Our test scripts finish with one line: "ALL PASS" or "N FAILURES". A few of them
could print that pass line after checking nothing at all - a port was busy, a
program was not installed, a build was missing - and still report success. So a
run that proved the feature works and a run that never looked at it were
indistinguishable, and the loop, the dashboard and anyone reading the wall of
green scored them the same. Now a run that measured nothing says
`ASSERTED NOTHING` and fails, with its own exit code so a script can tell "the
product is broken" from "the harness proved nothing".

## Goals

- [x] One place decides the verdict, so this cannot be got wrong per script.
- [x] A pass verdict with zero passing assertions is impossible through it.
- [x] "Asserted nothing" is a distinct answer from "assertions failed".
- [x] Every existing script that could score green having measured nothing is
      fixed.
- [x] A sweep keeps the suite that way, with teeth of its own.

## Summary

Found while migrating `host-settings.ps1` (T218 batch 5). Its "the fake relay
directory never came up on port $DirPort" branch printed

```
  SKIP whole run: the fake relay directory never came up on port 47941 (port in use?)
ALL PASS (0 assertions, 1 skipped)
```

and **exited 0**. A port left held by a previous run - exactly the state a
back-to-back re-run produces - therefore scored the whole T174 acceptance as
green while asserting nothing at all. Fixed in place there (it exits 1 now, and
the two foreground-grab SKIP branches are gone with the migration), but the
shape is not specific to that script and nothing prevents the next one.

This is the same family as the batch-1 finding (`if ($r -like 'ABORT*') { SKIP }`
around a whole section) and the batch-4 finding (a section that printed SKIP and
silently dropped three assertions): **a run that asserted nothing is
indistinguishable from a run that asserted everything**, because both end in
`exit 0` and a green line.

## Direction

One invariant, enforced once rather than per script: **`pass == 0` is a
failure.** A scorer that is about to print ALL PASS with no passing assertions
has proved nothing and must exit non-zero with a distinct message (`ASSERTED
NOTHING`), so a caller - the P-suite, a loop turn, a human reading a wall of
green - can tell the two apart.

Also worth deciding in the same pass:

- Whether the count belongs in a **shared scorer** in `test/win32/lib/` (every
  script already keeps `$script:pass` / `$script:fail` by hand, and a shared
  `Write-TestScore` would make this impossible to get wrong again) or as a
  per-script guard.
- Whether a **partial** skip should also be loud: a script that scores 3 of its
  30 assertions is closer to "asserted nothing" than to ALL PASS. A minimum
  expected count per script is the strong form; at least printing the skip count
  in the final line is the weak one.
- `-NegativeControl` runs already have this guard in the migrated scripts
  (`$script:negReached`, "NEGATIVE CONTROL never reached its inverted
  assertion"). Same idea, one level up.

## What landed

**The invariant lives in one place**: `test/win32/lib/TestScore.ps1`.
`Write-TestVerdict -Pass -Fail [-Skipped] [-Label] [-Unit] [-MinPass]` owns the
verdict wording AND the exit code, so a script cannot announce a pass it did not
measure:

| verdict | exit | when |
|---|---|---|
| `ALL PASS (N assertions[, K SKIPPED])` | 0 | at least one assertion passed, none failed |
| `N FAILURE(S) (...)` | 1 | assertions ran and some failed |
| `ASSERTED NOTHING (0 assertions...)` | 2 | nothing was proved either way |
| `ASSERTED TOO LITTLE (P of at least M...)` | 2 | opt-in `-MinPass` floor, the strong form |

Exit **2** rather than 1 because the two are different news: a 1 says the
product is broken, a 2 says the HARNESS proved nothing and the product is
unmeasured. Every existing consumer reads `ALL PASS` as a substring of the last
line and any nonzero code as red, so both stay correct. `-NoExit` returns the
verdict object instead of exiting, which is how P1-P3 still tee their failure
line into their transcript. `Write-TestAssertedNothing -Reason` is the sugar for
a precondition that failed before any assertion could run.

**The sweep that keeps it that way**: `test/win32/lib/AssertedNothingAudit.ps1`,
an AST analyzer (same reason VerdictExitAudit reads the parser: `exit 0` shares
a line with the verdict all over this suite). Two kinds are enforced at zero -
`zero-count` (a verdict hardcoding a zero count) and `early-green` (a pass
verdict that ends the run with exit 0 somewhere other than the final verdict,
i.e. an abort or whole-run-skip branch scoring the run green). A third,
`uncounted-final`, is reported with its number rather than asserted: 39 scripts
still print a countless `"ALL PASS"`, and converting them is **T775**.

**The four sites that had it**, each for an entirely ordinary reason, all fixed:

- `agent-instance-lineage.ps1 -Release` with no staging build - printed
  `ALL PASS (0 checks, 1 SKIPPED)` and exited 0. Measured after the fix:
  `ASSERTED NOTHING (0 checks, 1 SKIPPED) - this run proved nothing; it is not a
  pass`, exit 2.
- `agent-user-env.ps1` on a box with no usable HKCU PATH entry.
- `scrollback-narrow.ps1` when the shell flavor under test is not installed.
- `upgrade-no-fork.ps1 -PureOnly`'s mode terminus (uncounted).

`ipc-p1/p2/p3.ps1` were converted as the pattern-setters (their verdicts now
carry assertion counts: 25 / 20 / 16).

**The sibling audits were taught the new shape**, or every converted script
would have read as a regression to them: `VerdictExitAudit` accepts a
`Write-TestVerdict` call as the verdict (both directions of its rule hold by
construction there, with the `-NoExit` hole still checked), and `SkipAudit`
reads `-Skipped` on such a call as the skip count being reported.

## Validation criteria

- [x] A run that asserted nothing exits non-zero and says so, on the wire -
      section A of `test/win32/asserted-nothing.ps1` launches real fixture
      processes and reads their last line and exit code back (17 assertions).
- [x] The real precondition path, live: `agent-instance-lineage.ps1 -Release
      -Exe C:\no-such-t271.exe` prints `ASSERTED NOTHING (0 checks, 1 SKIPPED)`
      and exits 2. Before this change the identical run said `ALL PASS
      (0 checks, 1 SKIPPED)` and exited 0.
- [x] A normal run of every touched script is unchanged: `ipc-p1` (25),
      `ipc-p2` (20), `ipc-p3` (16), `agent-user-env` (20), `scrollback-narrow`
      (11), `upgrade-no-fork -PureOnly` (87) - all ALL PASS, exit 0.
- [x] No remaining site can print a pass with a zero assertion count: the
      section-C sweep over all 170 scripts reports zero `zero-count` /
      `early-green` findings, and `-TeethCheck` (a synthesized violator) proves
      that assertion can go red.
- [x] The sibling audits stay green: `verdict-exit-audit.ps1`,
      `skip-visibility.ps1`, `harness-exitcode-audit.ps1` all ALL PASS.
- [x] Floor: `scripts\floor-lane.ps1 -Lane all` (none / win32 / agent) and
      P1-P3.
