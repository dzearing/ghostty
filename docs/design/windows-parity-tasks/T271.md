# T271 - An acceptance script that asserted nothing must not exit 0

## Summary

Found while migrating `host-settings.ps1` (T218 batch 5). Its "the fake relay
directory never came up on port $DirPort" branch printed

```
  SKIP whole run: the fake relay directory never came up on port 47941 (port in use?)
ALL PASS (0 assertions, 1 skipped)
```

and **exited 0**. A port left held by a previous run - exactly the state a
back-to-back re-run produces - therefore scored the whole T174 acceptance as
green while asserting nothing at all. Fixed in place there (it exits 1 now, and
the two foreground-grab SKIP branches are gone with the migration), but the
shape is not specific to that script and nothing prevents the next one.

This is the same family as the batch-1 finding (`if ($r -like 'ABORT*') { SKIP }`
around a whole section) and the batch-4 finding (a section that printed SKIP and
silently dropped three assertions): **a run that asserted nothing is
indistinguishable from a run that asserted everything**, because both end in
`exit 0` and a green line.

## Direction

One invariant, enforced once rather than per script: **`pass == 0` is a
failure.** A scorer that is about to print ALL PASS with no passing assertions
has proved nothing and must exit non-zero with a distinct message (`ASSERTED
NOTHING`), so a caller - the P-suite, a loop turn, a human reading a wall of
green - can tell the two apart.

Also worth deciding in the same pass:

- Whether the count belongs in a **shared scorer** in `test/win32/lib/` (every
  script already keeps `$script:pass` / `$script:fail` by hand, and a shared
  `Write-TestScore` would make this impossible to get wrong again) or as a
  per-script guard.
- Whether a **partial** skip should also be loud: a script that scores 3 of its
  30 assertions is closer to "asserted nothing" than to ALL PASS. A minimum
  expected count per script is the strong form; at least printing the skip count
  in the final line is the weak one.
- `-NegativeControl` runs already have this guard in the migrated scripts
  (`$script:negReached`, "NEGATIVE CONTROL never reached its inverted
  assertion"). Same idea, one level up.

## Validation

- Every `test/win32/*.ps1` acceptance script, run with its precondition
  deliberately broken (the port held, the exe missing), exits non-zero and says
  it asserted nothing.
- A normal run of each is unchanged: ALL PASS, exit 0.
- Grep proves no remaining site prints ALL PASS with a zero assertion count.
