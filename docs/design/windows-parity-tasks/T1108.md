# T1108 - A session that survives a reboot comes back looking alive instead of as a dead tombstone

## In plain terms

After a restart, sessions from before the restart should come back listed as ended - a headstone you can see and clear, not a live session. One of them comes back claiming to still be running. Anything that trusts that flag will try to reconnect to a session that is not there.

## Summary

`test\win32\agent-autostart.ps1` scored `1 FAILURE(S)` in the T1094 sweep. Sections A and C pass in full - the Run key is written correctly, with the right pipe and file paths, and the debug gate holds. Section B, the reboot proxy, gets all the way to the last assertion:

```
PASS B3 Run command launched (CreateProcess rc=0)
PASS B4 fresh agent running from the Run command
PASS B5 pre-reboot session id came back
FAIL B6 ...as a DEAD tombstone (alive=false)
```

So the restart works, the agent comes back, and the pre-reboot session id is remembered - it is only the LIVENESS of the restored record that is wrong. B5 passing and B6 failing is a precise signal: the session record is being rehydrated without its liveness being reset, or with a default of alive.

The consequence to a user is a session that looks resumable and is not.

## Where

- `src/remote/agent/` - session rehydration from `sessions.json` at startup
- `test/win32/agent-autostart.ps1` section B

## What it turned out to be

The app was right and the test was measuring the wrong machine. `materialize()`
(`src/remote/agent/session.zig:1085`) sets `alive = false` unconditionally on
every record it loads from `sessions.json`, and nothing on that path infers
liveness from a pid. What came back alive was a session that really was alive:
since T909 a session's ConPTY, shell and kill-on-close job live in a separate
`--pty-host` holder process that deliberately escapes the agent's job (T905), so
section B's reboot proxy - kill the GUI, kill the agent - left it running with a
live shell, and the restarting agent re-adopted it (T906) exactly as designed.

A real reboot takes the holders too. The proxy now does as well.

## Goals

- [x] Read the rehydration path: a session loaded from disk whose process no longer exists must come back `alive=false`. (`materialize()` sets `alive=false` + `relaunchable=true`; nothing there reads a pid.)
- [x] Check whether liveness is persisted at all, or inferred - inferring it from a pid after a reboot is unsound, since pids are reused. (Neither: it is a re-adoption HELLO over the holder's named pipe, which answers only if the shell is really there.)
- [x] Fix and re-run; the reboot proxy now kills surviving holders, so B6 measures the reboot floor again.

## Validation criteria

- [x] a session restored after the reboot proxy reports `alive=false` - B5+B6 PASS in `test\win32\agent-autostart.ps1`, three runs
- [x] the liveness of a restored session is never inferred from a bare pid - read at `src/remote/agent/session.zig:1085`, and confirmed live by the `GHOZTTY_AGENT_PTY_HOLDER=0` control run
- [x] `test\win32\agent-autostart.ps1` is ALL PASS - 20 assertions, three runs (the last one stamping its new guard row)
