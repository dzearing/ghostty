# T1108 - A session that survives a reboot comes back looking alive instead of as a dead tombstone

## In plain terms

After a restart, sessions from before the restart should come back listed as ended - a headstone you can see and clear, not a live session. One of them comes back claiming to still be running. Anything that trusts that flag will try to reconnect to a session that is not there.

## Summary

`test\win32\agent-autostart.ps1` scored `1 FAILURE(S)` in the T1094 sweep. Sections A and C pass in full - the Run key is written correctly, with the right pipe and file paths, and the debug gate holds. Section B, the reboot proxy, gets all the way to the last assertion:

```
PASS B3 Run command launched (CreateProcess rc=0)
PASS B4 fresh agent running from the Run command
PASS B5 pre-reboot session id came back
FAIL B6 ...as a DEAD tombstone (alive=false)
```

So the restart works, the agent comes back, and the pre-reboot session id is remembered - it is only the LIVENESS of the restored record that is wrong. B5 passing and B6 failing is a precise signal: the session record is being rehydrated without its liveness being reset, or with a default of alive.

The consequence to a user is a session that looks resumable and is not.

## Where

- `src/remote/agent/` - session rehydration from `sessions.json` at startup
- `test/win32/agent-autostart.ps1` section B

## Goals

- [ ] Read the rehydration path: a session loaded from disk whose process no longer exists must come back `alive=false`.
- [ ] Check whether liveness is persisted at all, or inferred - inferring it from a pid after a reboot is unsound, since pids are reused.
- [ ] Fix and re-run; confirm the tombstone is also presentable in the chooser (a dead record the user can see and clear).

## Validation criteria

- [ ] a session restored after the reboot proxy reports `alive=false`
- [ ] the liveness of a restored session is never inferred from a bare pid
- [ ] `test\win32\agent-autostart.ps1` is ALL PASS
