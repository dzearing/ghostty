# T1321 - The feedback queue files user reports without marking them as user reports

## Summary

T1315 made `user-report: true` the thing that turns a close into a same-day
release request. The single biggest producer of genuine user reports is the
Ghoztty viewer feedback queue, drained by the `process-feedback` skill.

**Corrected on claiming (2026-09-04):** the card assumed that skill *files*
tasks with a plain `parity-tasks.ps1 new`. It does not - it fixes each report
in place, commits, and moves the folder to `complete/`, and it names no tracker
command anywhere. The consequence the card describes is real all the same, and
worse than the version it described: the fix for a report a person filed by
hand lands with nothing at all recording that a person is waiting, so it ships
on the ordinary daily cadence. That is the exact shape that cost the user twice
on 2026-09-03 (T1294).

What is left, therefore, is to wire the OUTCOMES rather than a filing step:

- the pass that COMPLETES a report records a release request
  (`daily-publish.ps1 -Request`), so the fix ships the same day;
- anything it does NOT fix in that pass - the blocked report, an adjacent gap
  it deliberately leaves - is filed with `parity-tasks.ps1 new -UserReport`, so
  closing it later files the request on its own;
- both are conditional on the tool existing, because this skill ships to every
  Ghoztty user and most checkouts have no parity tracker.

The document lives in two copies that both ship (`macos/Resources/Ghoztty/` and
the `@embedFile`d `src/apprt/win32/assets/ghoztty/`), so the change lands in
both and a harness holds them together. `upstream/` is deliberately untouched -
it mirrors tip-of-main and is expected to lag this branch.

## In plain terms

When you press the feedback button in a viewer pane and describe a problem,
an agent picks the report up, fixes it, and commits - and then nothing said
that a real person was waiting for that fix. So it sat until the next ordinary
daily release, which is how the same broken installer got downloaded twice in
one day. After this, a fix that came from your feedback asks for a release of
its own, and anything the pass could not finish is filed as your report rather
than as anonymous internal work.
