# T1321 - The feedback queue files user reports without marking them as user reports

## Summary

T1315 made `user-report: true` the thing that turns a close into a same-day release request. The single biggest producer of genuine user reports - the Ghoztty viewer feedback queue drained by the /process-feedback skill - files its tasks with a plain `parity-tasks.ps1 new` and therefore never sets the flag, so exactly the reports that came from a person keep shipping on the ordinary daily cadence. Wire `-UserReport` into that skill's filing step (it lives in the plugin cache, outside this repo, so the change needs to land in the marketplace source AND the active cache copy - see the banner-script-moved precedent), and say the same thing in docs/claude/ wherever feedback intake is described.
