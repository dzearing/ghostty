# T1019 - Nothing on the box measures which side the DWM title bar actually lands on

## Summary

chrome-theme.ps1 measures the client-painted band and dark-menus.ps1 measures the popup menus, but the immersive dark-mode attribute the standard title bar is drawn with is asserted by nothing - the one output of the light/dark decision with no oracle.

## In plain terms

When your terminal is in dark mode, the strip at the very top of the window
with the close button on it should be dark too. Nothing here ever checks that
it is. Two other tests check the colors just below it and the colors in the
right-click menus, so a title bar that came out the wrong shade would pass
every test we have and only you would notice.

## Details

Found while doing T309, which made one function
(`chrome_theme.isDark`) the single answer to "is this window light or dark".
That answer has three consumers, and only two are measured:

- the client-painted chrome band -> `test\win32\chrome-theme.ps1`
- the USER popup menus -> `test\win32\dark-menus.ps1`
- `DWMWA_USE_IMMERSIVE_DARK_MODE` on the title bar -> nothing

The attribute is write-only in practice (`DwmGetWindowAttribute` does not read
it back usefully), so the oracle has to be a pixel one: launch with
`--window-theme=dark` and `--window-theme=light`, capture the window's OUTER
rect (the frame DWM draws, not the client area `Get-TestWindowPixels` returns)
and average the caption row - the shape `dark-menus.ps1` already uses for
menus, one surface over. Note the caption is only DWM's to draw for the
explicit themes; `auto`/`ghostty` tint it to the terminal background, and that
tint is worth asserting in the same run.

Do this on the background test desktop (`test/win32/lib/TestDesktop.ps1`) like
every other GUI script, and give it a `guard-due.ps1` row (see T1018) so it is
obliged to re-run when the decision moves.

## Validation criteria

- [ ] A dark-themed launch's title bar measures dark and a light-themed one
      measures light, from a capture of the window's outer rect
- [ ] A negative control proves the capture is of the caption and not of a
      blank or client-area rect (the T303 rule)
- [ ] Runs on the background test desktop and never takes the user's
      foreground
- [ ] The script has a `guard-due.ps1` row naming the files that move its
      verdict
