# T1227 - Two guard rows watch file paths that cannot exist, so those checks can never go due

## Outcome (2026-09-01) - the premise was false, the hole underneath it was real

**The two corrupt paths do not exist.** A byte scan of `scripts\guard-due.ps1` at HEAD and in the worktree finds zero characters below 0x20, and all 118 rows' `Covers` patterns match at least one file in this tree today. What was reported as `src<BEL>pprt\win32\...` was the file's correct `src\apprt\win32\...` after a tool that halves backslashes on the way to a terminal got hold of it - the known trap, applied to the report rather than to the file.

**What was real is the hole that made the report un-answerable in the first place**: `Get-CoveredFiles` asks `Get-ChildItem` with `-ErrorAction SilentlyContinue`, so a `Covers` pattern that matches NOTHING contributes nothing and says nothing. A row whose every pattern misses is reported (`GUARD N/A`); a row with one good pattern and one broken one is not - it goes on printing `GUARD CURRENT` while watching one file fewer than it claims. Whether the break is a control byte, a typo, or a file that moved, the guard silently narrows and nothing anywhere notices.

So `check` now audits the table before it reports any verdict, and a fault fails it the way a due harness does. Two conditions, answering different questions: a path carrying a control character is a fault in any tree (no file can be named that), and a pattern matching nothing is a fault only when its row's OTHER patterns do match - which is what separates a typo from a foreign tree, and is why the fixture runs throughout this repo's own harnesses stay silent.

## Summary (as filed - see Outcome above)

Found while adding a guard row for T1162. Two `Covers` entries in `scripts\guard-due.ps1` contain CONTROL CHARACTERS where a backslash should be, so they name paths no file can ever have:

- `src<BEL>pprt\win32\install_prepare.zig` - meant to be `src\apprt\win32\install_prepare.zig` (the `\a` was eaten and left a 0x07 byte).
- `dist\windows-installer<BS>uild-msi.sh` - meant to be `dist\windows-installer\build-msi.sh` (the `\b` left a 0x08 byte).

Both are in HEAD, so they predate this turn; the shape is the known trap where a shell heredoc halves backslashes on the way into a file (the same trap corrupted T1162's own summary, fixed in that commit).

Why it matters: guard-due answers "has anybody run acceptance harness X against the code as it now stands?" by comparing the mtimes of the files a row COVERS. A covered path that cannot exist never changes, so it can never make its guard due - the check is a check that cannot fire, which is exactly what `go.md` says a gate must never be. The `install-prepare` guard is watching a source file it therefore does not watch.

The fix is two characters, but it comes with consequences to work through, which is why this is its own task and not an inline repair: correcting the paths will immediately make those guards DUE (their real files have changed since the stamp), so the turn that fixes it must also run `test\win32\install-prepare.ps1` and the release-artifacts harness (the latter needs Docker, which is user-gated on this box) before `validate` will pass.

While in there: add a check that no `Covers` path contains a control character, so the next heredoc accident is caught by the harness rather than by someone reading bytes.

## In plain terms

We have an automatic reminder that says "this test hasn't been run since the code it checks changed". Each reminder carries a list of the files it watches. Until now, if one line of that list had a typo - a path to a file that isn't there - the reminder just skipped it and carried on looking green, watching less than it said it was. Nobody would find out except by reading the lists by hand.

The report that started this said two of those lines were corrupt. They aren't; the corruption was in the report, not the file. But answering that took a byte-level check of the file, which is precisely the sign the machine should have been able to answer it. Now it does: the reminder checks its own watch list every time it runs, and refuses to pass while a line of it points nowhere.
