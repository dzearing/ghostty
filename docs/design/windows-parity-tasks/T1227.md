# T1227 - Two guard rows watch file paths that cannot exist, so those checks can never go due

## Summary

Found while adding a guard row for T1162. Two `Covers` entries in `scripts\guard-due.ps1` contain CONTROL CHARACTERS where a backslash should be, so they name paths no file can ever have:

- `src<BEL>pprt\win32\install_prepare.zig` - meant to be `src\apprt\win32\install_prepare.zig` (the `\a` was eaten and left a 0x07 byte).
- `dist\windows-installer<BS>uild-msi.sh` - meant to be `dist\windows-installer\build-msi.sh` (the `\b` left a 0x08 byte).

Both are in HEAD, so they predate this turn; the shape is the known trap where a shell heredoc halves backslashes on the way into a file (the same trap corrupted T1162's own summary, fixed in that commit).

Why it matters: guard-due answers "has anybody run acceptance harness X against the code as it now stands?" by comparing the mtimes of the files a row COVERS. A covered path that cannot exist never changes, so it can never make its guard due - the check is a check that cannot fire, which is exactly what `go.md` says a gate must never be. The `install-prepare` guard is watching a source file it therefore does not watch.

The fix is two characters, but it comes with consequences to work through, which is why this is its own task and not an inline repair: correcting the paths will immediately make those guards DUE (their real files have changed since the stamp), so the turn that fixes it must also run `test\win32\install-prepare.ps1` and the release-artifacts harness (the latter needs Docker, which is user-gated on this box) before `validate` will pass.

While in there: add a check that no `Covers` path contains a control character, so the next heredoc accident is caught by the harness rather than by someone reading bytes.

## In plain terms

We have an automatic reminder that says "this test hasn't been run since the code it checks changed". Two of its entries have a typo that makes them point at files that do not exist, so those reminders can never fire - the safety net looks present and is not connected. This reconnects them and adds a check so the same typo cannot come back unnoticed.

## Validation criteria

- [ ] Both `Covers` paths name real files (no control bytes anywhere in `guard-due.ps1`).
- [ ] `scripts\guard-due.ps1 check` reports the affected guards as due, and they are green again after their harnesses run.
- [ ] A new check fails on a `Covers` entry containing a control character, demonstrated red before it is fixed.
