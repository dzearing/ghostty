# T1339 - The Mac machine chooser still refuses to relaunch a dead-but-relaunchable session row

## Summary

Windows landed T466: a dead-but-relaunchable row in the machine chooser now
RELAUNCHES on Return instead of answering "it can't be resumed". The Mac
chooser still refuses (`MachineChooserView.swift:167-168`), so the same dialog
behaves differently on the two seats — the divergence this project does not
ship.

## In plain terms

The machine chooser lists sessions you can take over, including ones whose
program has already finished — the terminal keeps them because the folder and
the command they were running are worth seeing. On Windows, picking one of
those now reopens it: you land on a fresh prompt in that folder, with a line
naming what used to be running there. On the Mac it still says the session
cannot be resumed, so the same list offers something it will not do.

## Goals

- [ ] Return on a dead-but-relaunchable row in the Mac chooser opens a window
      the same way Windows does, rather than refusing
- [ ] The row is marked so the two kinds are tellable apart before you press
      anything (Windows uses a `can relaunch` badge beside the exit label)
- [ ] `docs/claude/sessions.md` drops its "Mac still refuses" note

## Details

The shape to mirror, all in `src/apprt/win32/chooser_sessions.zig`:

- `rowAction(session) -> .resume_session | .relaunch | .none` is the single
  place that names the verb, and it keeps the invariant **listed <=>
  actionable**: `isConnectable` (alive or relaunchable) decides what is listed,
  and every listed row acts.
- `resumeTarget` resolves a relaunchable tombstone to the SAME transport arm a
  live row uses. There is no new plumbing: the shared `termio.Remote` applies
  `session-relaunch` on finding the ATTACH target dead — by default `restore`, a
  fresh shell in the recorded cwd plus a notice naming the command it did not
  re-run (T230) — then retires the tombstone. That is already what launch-time
  restore does with a tombstone leaf on both platforms.
- `hasLiveChild` (was `isResumable`) keeps "Restore All"'s two-live-sessions
  floor honest: a tombstone is actionable but is not a live session.

Note the prerequisite the T466 evidence already names: Mac's C API omits
`relaunchable` (**T322**), which collapses its `isConnectable` to `alive` — so
on the Mac seat these rows may not be listed at all today, and T322 has to land
first or with this.

## Validation criteria

- [ ] A unit test over the Mac equivalent of `rowAction`, covering alive /
      relaunchable-tombstone / genuinely-exited
- [ ] On box: kill the agent with a live session, restart it, open the chooser,
      press Return on the tombstone row — a window opens in the recorded cwd
      with the notice, and the tombstone is gone from `ghoztty +sessions --json`
- [ ] The two seats' rosters offer the same verbs on the same rows
