# T669 - Viewer feedback carousel: a transparent PNG is flattened onto black instead of the tile's own fill

## In plain terms

Paste a picture with transparency — a logo, a cropped screenshot with rounded
corners — into a feedback report and its thumbnail shows the see-through parts
as solid black. It should show the tile's own background there, the way every
other app does.

## Summary

Filed out of T646. The tile decode goes through `gdiplus_decode.decodeBytes` →
`decodeScaled`, which calls `GdipCreateHBITMAPFromBitmap(bitmap, &hbm,
0xFF000000)` — the third argument is the background the alpha channel is
composited against, and it is opaque BLACK. That was the right answer for the
call site the function was written for (T397's hero thumbnail of a web page,
which has no transparency), and it is the wrong one for a tile sitting on the
composer's pill fill, especially in light theme.

The fix is to composite against the surface the picture will actually sit on
rather than a constant. Two shapes worth weighing before building:

- Pass the background colour down to `decodeScaled`/`decodeBytes` and hand it to
  `GdipCreateHBITMAPFromBitmap`. Cheap, but it bakes a theme colour into the
  CACHED bitmap, so a light/dark switch has to invalidate the cache — which is
  keyed by (number, tile size) today and would need the colour in the key.
- Keep the decode alpha-preserving and composite at paint time with
  `AlphaBlend`. The cache stays theme-independent, which also means a theme
  change costs no re-decode, at the cost of a per-paint blend.

The second is likely right for the same reason the tile's fill is derived and
not stored — but that is a judgement to make with the code open, not here.

Note the same constant is used by the hero-thumbnail path; whatever changes must
leave that path's behaviour alone or account for it.

## Validation criteria

- [ ] Unit test (none lane) or a pure helper asserting the composite colour is

- [ ] On-box acceptance: paste a PNG with a fully transparent region and assert
      the tile's transparent pixels are the tile fill, not black. (The existing
      carousel script runs off-desktop, so this needs either a decoded-pixel
      readback or the interactive-desktop probe recipe.)
- [ ] The hero thumbnail (T397) still renders as it did.
