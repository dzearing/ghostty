# T615 - The T400 stale-debounce viewer test compares two cache-dependent fetch counts and flakes

## In plain terms

One of the automated viewer tests fails at random, roughly a coin flip on a busy
box, even when nothing is wrong. Every time it does, somebody has to stop and
prove it was noise. It should either be reliable or say what it means.

## Goals

- [ ] The assertion no longer depends on whether WebView2 happened to serve a
      page from cache.
- [ ] The win32 lane passes repeatedly (`floor-lane.ps1 -Lane win32 -Repeat 5`).
- [ ] The claim the arm was making is still asserted, or explicitly retired with
      a reason.

## Summary

`src/apprt/win32/ViewerPane.zig`, in
`test "host floor: a real controller on a real window, on this box"`
(~line 4015):

```zig
const after_nav = reload_page.requests.load(.acquire) - before_nav;
try testing.expectEqual(nav_cost, after_nav);
```

`nav_cost` is measured earlier by navigating to the SAME url and counting the
server's requests; `after_nav` counts them for a later navigation to that url.
Both numbers are whatever WebView2's HTTP cache decided at that moment. On
2026-08-08 the first measured 1 and the second measured 0, and the lane went
red:

```
[viewer_pane] (warn): t400: a repeat navigation costs 1 fetch(es)
[viewer_pane] (warn): t400: stale-debounce window cost 0 fetch(es), expected 1
expected 1, found 0
```

An immediate re-run of the same lane on the same build PASSED, so the product is
fine. Two `viewer navigation did not complete (status=9); no content injected`
warnings land just before it, which is the kind of environment hiccup that would
shift a cache decision.

The comment above the assertion already concedes it is the weak oracle — the
strong one is the `KillTimer` line just above it, which asserts the timer was
cancelled and passed in the failing run too. So this arm is the redundant half,
and it is the flaky half.

## Options

- Assert `after_nav <= nav_cost` — the claim that matters is "no EXTRA fetch",
  and a cache hit is not an extra fetch.
- Serve the reload page with `Cache-Control: no-store` so both counts are
  deterministic, and keep the equality.
- Drop the arm, since the timer oracle above it is strictly stronger and the
  comment says so.

## Validation criteria

- [ ] `powershell -NoProfile -File scripts\floor-lane.ps1 -Lane win32 -Repeat 5`
      is PASS on every run.
- [ ] Reintroducing the T400 bug (drop the `KillTimer` from `syncWatcher`) still
      turns the section red — the arm must not have been weakened into
      uselessness.
