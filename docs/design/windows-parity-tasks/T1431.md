# T1431 - A full C: drive makes every build fail with a bare 'error: Unexpected'

## Summary

Zig's C/C++ compile steps scratch in %TEMP%, which lives on C:. On 2026-09-07 C: had 0.1 GB free and every 'zig build' died with a bare 'error: Unexpected' on glslang, oniguruma, translate-c and helpgen - no mention of disk, no mention of C:, and it reads exactly like broken code. Setting TMP/TEMP to a directory on the repo drive made the same build succeed with no other change. T1054 already solved this shape for the repo drive (scripts\build-cache.ps1 reports free space at claim time and sweeps) but it only ever looks at the CACHE drives, so the drive that %TEMP% is on is unmeasured. Two halves: point the build shells' TMP/TEMP at the repo drive so a full C: cannot stop a build, and make the claim report C: free space so the box state is visible before a turn burns its context on a fake compile error.
