# T1413 - A stray always-on-top bit on a scrollbar or dim wash is no longer cleared when the pane is resized

## Summary

Measured 2026-09-07 under T607: overlay-zorder.ps1 sections F/dim and F/scrollbar are RED. A stray WS_EX_TOPMOST injected onto a dim overlay or a themed scrollbar is not cleared by a window resize any more, so the T142 defect (a background window's chrome floating over another app) has no heal left on the reposition path. T1345 (982d1b8df) is the cause and says so in its own commit message: a live layout pass moves already-visible popups with SWP_NOZORDER and now skips the z-order walk, which is where healOverlayZOrderAfterMove used to run. Sections A-E, G and H still pass, so the banner overlay, the URL bubble and the quick terminal are unaffected - it is the popups a live pass moves. The fix has to restore the heal without giving back the drag cost T1345 bought.
