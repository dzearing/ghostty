# T459 - The tracker's order: queue field landed half-tested

## Summary

Finish and prove the order-first queue: fix the two column-shape assertions the
new Ord column broke, and add coverage for order sorting, set-order and the
next -Claim shortcut.

**Filed by the loop while the field was mid-flight in another session, and a
fair catch** - `order:` was readable by `list`/`next` before anything asserted
it. Closed by `d45bca51d`, which landed the coverage described below in the
same change as the rest of the feature.

## In plain terms

The to-do list now has a real running order - someone can say "this one is
next, then that one" instead of only sorting things into three coarse buckets.
The list already reads that way, but the test that guards the list was still
checking for the old columns and failed, and nothing at all checked that the
new ordering does what it says. So the feature worked and was unproven, which
is the state a regression sneaks in through. Now the ordering is asserted, and
the person watching the board can trust that the top item really is the next
thing.

- [x] the acceptance script passes again on the new column shape
- [x] the running order is asserted: a low order number beats a better priority
- [x] setting an order on a task that never had one is asserted

- [ ] the whole standing floor is green - NOT re-run for this change; it is

## What landed (`test/win32/parity-tasks-seat.ps1`)

Section **K** - order outranks priority:

- The fixture is deliberately inverted (the best priority gets the worst
  order), so an implementation that still fell back to priority cannot pass by
  accident.
- A decimal injects between two neighbours without renumbering, and is written
  through the invariant culture so a comma-decimal machine cannot emit
  `order: 2,5`.
- An unparseable order (`order: banana`) is treated as ABSENT, not as 0 - a
  typo must not silently seize the head of the queue.
- `list` prints in queue order.

Section **L** - `next -Claim`:

- `next` alone does not mutate anything (it stays a read-only question).
- `-Claim` marks the task `in-progress` and says so, and a claimed task is no
  longer offered.

Sections A and J were also corrected for the new column shape (`Ord`, `Id`,
`Pri`, `Status`, `Seat`; unset shows `--`).
