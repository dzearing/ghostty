# T459 - The tracker's order: queue field landed half-tested - list/next read it, but the acceptance script still asserts the old column shape and nothing covers order:, set-order or next -Claim

## Summary

Finish and prove the order-first queue: fix the two column-shape assertions the new Ord column broke, and add coverage for order sorting, set-order and the next -Claim shortcut.

## In plain terms

The to-do list now has a real running order — someone can say "this one is
next, then that one" instead of only sorting things into three coarse buckets.
The list already reads that way, but the test that guards the list is still
checking for the old columns and fails, and nothing at all checks that the new
ordering does what it says. So the feature works and is unproven, which is the
state a regression sneaks in through. When this lands, the ordering is
asserted, and the person watching the board can trust that the top item really
is the next thing.

## Goals

- [ ] the acceptance script passes again on the new column shape
- [ ] the running order is asserted: a low order number beats a better priority
- [ ] setting an order on a task that never had one is asserted
- [ ] the one-command "pick it and claim it" shortcut is asserted
- [ ] the whole standing floor is green
