# T912 - Persistent sessions spawn holder-backed by default, so the agent's self-upgrade actually reaches a real box

## Summary

T904-T907 built the whole non-destructive upgrade chain — per-session PTY
holders, holder-backed spawning, startup re-adoption, and the agent replacing
itself — and **all of it is behind `GHOZTTY_AGENT_PTY_HOLDER=1`, which is off**
(T905 shipped it flag-gated on purpose while the path was new). On a real box
today every session is still a legacy one, so T907's policy correctly reports
`draining` forever and the agent still only upgrades through the lossy paths.

Flipping the default is the last step of T705, and it is a behavior change with
real exposure — a holder is an extra process per session, and a holder-spawn
failure falls back to the in-process child. So it wants its own turn: flip the
default, keep an OFF escape hatch (`GHOZTTY_AGENT_PTY_HOLDER=0`), and re-run the
holder/adoption/handoff harnesses with the flag no longer set by the scripts.

## In plain terms

Everything needed for the background session manager to update itself without
closing your terminals is built, but switched off. This switches it on.

## Goals

- [ ] Holder-backed spawning is the default; `GHOZTTY_AGENT_PTY_HOLDER=0` is the
      escape hatch.
- [ ] The holder harnesses pass with the flag unset (they set it today).
- [ ] A session-count soak: N holder processes is not a per-session cost anyone
      notices.

## Validation criteria

- [ ] `test\win32\pty-holder.ps1`, `holder-adopt.ps1` and `agent-handoff.ps1`
      pass WITHOUT setting `GHOZTTY_AGENT_PTY_HOLDER`.
- [ ] `+sessions --agent` on this box reports `handoff: ready` with an ordinary
      pane open — i.e. the real thing, not a fixture.
- [ ] Floor green, and `test\win32\agent-recovery.ps1` +
      `session-persistence.ps1` stay ALL PASS with the new default.
