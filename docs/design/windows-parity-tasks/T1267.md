# T1267 - The desktop-launch sweep cannot see a launch assembled as a string or spawned by a script's own CreateProcessW

## Summary

`lib\DesktopLaunchAudit.ps1` states its own blind spot in its header - an
invocation assembled as a STRING and handed to another interpreter is not a
command in the AST - and T1240 walked straight into the consequence.
`cli-launch-cwd.ps1` had FOUR launch sites; the sweep saw one:

- arm A: `cmd /c "cd /d <dir> && "<Com>" ..."` via `Start-Process cmd.exe` - a
  real GUI on the user's desktop, invisible to the sweep.
- arm C: the same shape with `$Exe` instead of the `.com` twin.
- arm D: `[T506Spawn]::StartDetached($Exe, ...)`, the script's own
  `CreateProcessW` P/Invoke - the exe is an ARGUMENT to a static method, so
  neither the command-name rule nor the `$Exe`-invocation rule fires.
- arm B: `Start-Process -FilePath $Exe` - the one the sweep flagged.

So a script can be declared migrated, pass the sweep, and still put three
windows on the user's screen. The declaration list burns down on a question
narrower than the one it is read as answering.

Two shapes to consider, and the second is the one with teeth:

1. Widen the AST rules: a `cmd.exe` / `powershell` invocation whose argument
   string CONTAINS the exe reference, and a call passing an exe-shaped variable
   to a `[Type]::Method(...)`. Both are heuristics, and the header is right that
   no textual rule can be complete.
2. Ask the BOX instead of the source: run each script and assert that no
   ghoztty process from the repo build ever reports a window to the interactive
   desktop while it runs. `AnyVisibleWindowOnInteractiveDesktop` already exists
   in `lib\TestDesktop.ps1` and is exactly this measurement; the missing piece
   is a harness that applies it per-script. That answers the question the list
   is read as answering, and it cannot be defeated by how a launch is spelled.

## Validation criteria

- [ ] the four launch sites in `cli-launch-cwd.ps1` (as they stood before T1240)
      are a fixture, and the widened check reports every one of them
- [ ] a script that opens a window on the interactive desktop fails the sweep,
      demonstrated rather than asserted (a negative control that scores red)
- [ ] `test\win32\desktop-launch-audit.ps1` stays ALL PASS over the real tree
