# T924 - A restored pane comes back empty on Windows while the Mac keeps the dead session's scrollback

## Summary

After an agent restart the Mac's session-relaunch=restore RELAUNCHes the same session with a plain login-shell argv, so the agent replays the dead session's ring and the user can read what the lost process left behind under the notice. Windows' restore (T230) opens a BRAND-NEW session instead, so the pane comes up blank with only the notice. Same setting, same default, visibly different result. Found while porting T824.

## In plain terms

Reboot the machine and your terminal panes come back. On the Mac each pane still
shows everything the program that died had printed, with a line above the new
prompt explaining what happened. On Windows the same pane comes back empty — just
the notice and a bare prompt. The work you were reading is gone, which is exactly
the thing the reboot floor exists to keep.

## Goals

- [ ] a restored pane on Windows shows the dead session's scrollback above the notice
- [ ] still nothing is re-executed — the recorded command must not come back on a CPU
- [ ] the pane's working directory is still the recorded one
- [ ] the notice still survives the first prompt

## Details

Both platforms default to `session-relaunch=restore` and both promise "a fresh
shell, nothing re-run". They deliver it differently:

- **Mac** (`c76b5c89d`): `RELAUNCH` on the SAME session id, with a synthesized
  `<shell> -li` argv. The agent's `handleRelaunch` drops the recorded command
  whenever the viewer supplies argv, so the session is reused — which means the
  agent replays its on-disk ring snapshot, and the scrollback survives.
- **Windows** (T230, `src/termio/Remote.zig` `threadEnter`): retires the tombstone
  with `closeSessionNoWait` and issues a brand-new `OPEN` with `command = null`.
  A new session has an empty ring, so there is nothing to replay; the persisted
  screen snapshot is deliberately skipped too (`did_notify` excludes it, because
  the snapshot belongs to a byte stream this pane no longer shares).

Reusing the session is the obvious convergence, and it is what makes the two seats
one implementation instead of two. What has to be checked before switching: the
Windows agent ignores `Relaunch.argv` (it has no `-li` equivalent), so the "come
back as a shell, not the recorded command" signal has to keep working through the
nulled command rather than the argv, and the T532 offset bookkeeping assumes a
relaunch restarts the stream at 0.

## Validation criteria

- [ ] on-box: a reboot-equivalent cycle under the default policy leaves the pre-kill marker visible in the restored pane, above the notice
- [ ] on-box: the recorded command did NOT run again (no second process, no side effects)
- [ ] on-box: the restored shell answers from the recorded working directory
- [ ] floor green: `floor-lane.ps1 -Lane all` + P1-P3
