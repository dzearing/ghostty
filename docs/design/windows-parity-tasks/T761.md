# T761 - An explicit +split --working-directory is dropped on an agent-backed window (Mac)

## Summary

Found while checking the Mac's behavior for T515 (the Windows half of "a split
opens where its parent is"). Mac inherits the parent's cwd correctly — that is
what `BaseTerminalController.newSplit`'s `resolveRemoteInheritance` does — but
it appears to do so unconditionally on the IPC path, because the two cwd fields
never meet:

- `IPCServer.swift` (`+split`) writes an explicit `--working-directory` into
  `splitConfig.workingDirectory` (~lines 697, 733, 835).
- `BaseTerminalController.newSplit` gates the inherited value on
  `let alreadyHasCwd = effectiveConfig.remoteWorkingDirectory != nil` and then
  sets `cfg.remoteWorkingDirectory = cwd`.
- For a remote/agent-backed surface, `SurfaceView` forwards
  `remoteWorkingDirectory` as the OPEN's cwd; plain `workingDirectory` is the
  EXEC seam and never reaches the agent.

`TerminalController` does map one to the other for the window path
(`if cfg.remoteWorkingDirectory == nil { cfg.remoteWorkingDirectory =
cfg.workingDirectory }`), which is exactly the line `newSplit` is missing. So
on a session-persistence (or remote) window, `ghoztty +split
--working-directory=X` looks like it opens in the parent pane's directory
instead of X.

Not verified on a Mac — this is a read of the Swift, filed from the Windows
seat so the thread is not lost. Confirm first; if it reproduces, the fix is the
same one-line mapping `TerminalController` already makes, applied before
`alreadyHasCwd` is computed.

## In plain terms

On a Mac, if you split a pane and tell the new pane which folder to start in,
that instruction may be ignored — the new pane starts in the same folder as the
pane you split. Explicitly asking for a folder should always win.

## Validation criteria

- [ ] Reproduced (or disproved) on a Mac: `+split --target=<pane> --working-directory=<other dir>` on a session-persistence window, cwd read back from `+list --json`
- [ ] If it reproduces: an explicit `--working-directory` wins; a split with no explicit path still inherits the parent pane's cwd (the T515 rule, unchanged)
- [ ] Regression coverage on the Mac side (the same three shapes Windows asserts in `test/win32/local-split-no-command-rerun.ps1` sections 4-6)
