# T834 - The data-breakpoint probe cannot read Page.verifyIntegrity's prologue any more - T443's own diagnostic pushed the frame over 4 KB and zig switched it to a __chkstk prologue

## Summary

`Invoke-DataBreakProbe` (`scripts\lib\DataBreak.ps1`) parses one prologue
shape: `push rbp` / `sub rsp,X` / `lea rbp,[rsp+Y]`. On 2026-08-06 that read
`Page.verifyIntegrity` in the real test binary fine. It no longer does:

```
databreak: expected 'sub rsp,X' second: push rsi
ghostty_test!verifyIntegrity:
  push  rbp
  push  rsi
  push  rdi
  mov   eax,1020h
  call  ghostty_test!__chkstk
  sub   rsp,rax
  lea   rbp,[rsp+80h]
```

The frame is now `0x1020` bytes, i.e. **over 4 KB**, so the compiler emits a
`__chkstk` stack probe and saves two more registers before it. That growth is
this hunt's own doing: `210c763f4` and today's `Page.mapPtrDamage` widened the
diagnostic `verifyIntegrity` calls, and the frame crossed the page threshold.

The probe is not wrong about anything except its assumption that there is one
prologue shape. It needs to accept the `__chkstk` form: skip any run of
`push <reg>`, recognise `mov eax,<imm>; call __chkstk; sub rsp,rax` as the
frame allocation of `<imm>` bytes, and then read the `lea rbp,[rsp+Y]` exactly
as it does today. Everything downstream (spill attribution, arm point, return
slot, the `@rbp` expressions) is unchanged, because the frame is still
`rbp`-based.

## In plain terms

The tool that watches for whatever is scribbling on memory during the tests
cannot aim at its target any more. The extra diagnostics added while chasing
that bug made the function it watches bigger, and past a certain size the
compiler writes its opening instructions differently - a shape the tool was
never taught to read. It refuses rather than aiming wrong, which is the right
failure, but it means the hunt cannot take its next step.

## Details

Found while validating T832, on a live build-runner attach: the mode itself
works (it started the lane, waited for `ghostty-test.exe`, attached to pid
4908, and probed the running image). The same refusal happens standalone, so
this is not a build-runner problem.

Proof that only THIS function's shape is the blocker, from the same session:
the same command against `terminal.Screen.assertIntegrity` - a small frame -
armed and disarmed **84,356 times** across a real `zig build test
-Dapp-runtime=none` run and exited 0.

Note the ambiguity too: `verifyIntegrity` has two overloads
(`(terminal.PageList *)` and `(page.Page *, mem.Allocator *)`), so the run
needs `-SignatureFilter page.Page`. That part already works and is not a
defect.

## What the fix is

The prologue walk had one shape hardcoded at fixed instruction indices
(`insns[0..2]`). It is now a cursor:

1. `push rbp`, as before.
2. **Any run of `push <reg>`** — callee-saved registers. Each one moves the
   return-address slot 8 bytes further from `rbp`, and that slot is where the
   one-shot disarm breakpoint goes, so miscounting them would leave every
   armed slot live after the function returned. Counted into `ExtraPushes`.
3. The frame allocation, in **either** shape: `sub rsp,X`, or
   `mov eax,X` / `call __chkstk` / `sub rsp,rax`. Both allocate `X`; only the
   instruction count differs. Recorded as `FrameShape` = `sub` / `chkstk`.
4. `lea rbp,[rsp+Y]`, as before, and the spill run starts wherever the cursor
   now is.

The return-slot math generalises to
`ret = rbp + 8 + 8*ExtraPushes + FrameSub - FrameLea`, which is the old
formula at `ExtraPushes = 0`. `-DisasmLength` defaults to 40 rather than 32,
because a `__chkstk` prologue spends four more instructions before the spill
run and the run still has to end inside the window.

**The acceptance fixture needed a second ingredient.** A frame over 4 KB gets
the `__chkstk` allocation on its own, but it does **not** get the `push rsi` /
`push rdi` pair — measured: a 0x1690-byte frame and a 0x2c70-byte frame both
came out with `ExtraPushes = 0`. Since those pushes are the half of the change
that moves the return slot, the fixture forces them deterministically with an
inline-asm clobber (`asm volatile ("nop" ::: .{ .rsi = true, .rdi = true })`),
which reproduces the exact seven-instruction prologue this task quotes.

### Measured, on the real lane binaries

Both agent-lane binaries now parse where they refused, with exactly the frame
this task quoted:

| binary | shape | pushes | frame | lea | ret slot | armed slots |
|---|---|---|---|---|---|---|
| `ghoztty-agent-test.exe` | `chkstk` | 2 | `0x1020` | `0x80` | `0xfb8` | rcx, rdx, r8 |
| `ghoztty-agent-core-test.exe` | `chkstk` | 2 | `0x1020` | `0x80` | `0xfb8` | rcx, rdx, r8 |

The fixture proves the frame math rather than asserting it: 40 calls of a
`__chkstk` function armed and **disarmed** 40 times, which can only happen if
the computed return-address slot is right.
