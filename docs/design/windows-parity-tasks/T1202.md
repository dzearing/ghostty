# T1202 - A release updates the live download page but leaves the in-repo mirror behind, and only a harness notices

## Summary

release-windows.yml runs dist/website/publish-windows-links.sh, which retargets gh-pages at the new version. Nothing retargets relay/deploy/ghpages/index.html, the in-repo mirror that section F of test\win32\website-windows-download.ps1 asserts is identical to it. So every Windows release makes that harness red by construction, and it stays red until a human happens to run the same python rewrite on the mirror by hand - which is what T1179's turn did for 1.35.0. Two ways out worth weighing: have the release job commit the rewritten index.html back to the Windows branch in the same run, or stop keeping a mirror and have section F fetch the deployed page. Either removes a standing red that trains people to explain away a failing check.
