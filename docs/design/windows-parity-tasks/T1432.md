# T1432 - A test binary the lane's leak sweep kills reads as a bare red lane - no crash, no leak count, no diagnosis

## In plain terms

Nobody but the loop sees this one. When a test binary wedges and the lane's own
sweeper kills it, the lane just goes red with an exit code and no explanation —
so the next turn cannot tell "the code you just wrote is broken" from "the
box's ghost bit us again", and burns context finding out.

## Summary

On 2026-09-07 10:33 the `none` lane died at **exit 255** in
`font.Collection.test.add full`. Everything the harness printed about it was:
the exit code, `leaked test binaries: 0`, no CrashDiag block, and
`solo confirm: skipped - the log names no failing test`. What had actually
happened was that the lane's leak sweep attached to a still-running
`ghostty-test.exe`, dumped it (`.dumps/lane-leak-30468-20260907-103320.log` —
main thread live inside freetype's autofitter, not faulted) and killed it; 255
is the kill. The only reason anyone knows that is that a turn went looking at
`.dumps` by hand and read the stack.

The sweep KNOWS it killed a test binary and it knows which one. The lane verdict
does not say so, and the leak counter — the one number that would have said it —
printed `0` for the same run.

This is T877's lesson one step further out: that task taught the soak that an
exit-code-only death is still a crash. A sweep-kill is a THIRD outcome, and the
harness currently has no word for it.

## Details

- Where: `scripts\floor-lane.ps1` (the leak sweep, its counter and the verdict
  line) plus whatever writes `.dumps\lane-leak-*.log`.
- The needed answers, in the lane's own output: **that** a binary was swept,
  **which** one, and **where its main thread was** — the sweeper already has the
  dump, so the top user frame is free to print.
- The leak counter reading `0` for a run in which a binary was swept is a bug on
  its own; find out which of the two is lying before changing either.
- A swept binary should not be reported as a plain product FAIL: the run is
  UNMEASURED past the sweep, which is the shape `Write-TestVerdict` already
  distinguishes (exit 2, `RUN DID NOT FINISH`) for acceptance scripts.
