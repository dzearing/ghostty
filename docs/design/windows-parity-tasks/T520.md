# T520 - Chooser roster marks live sessions the local layout does not reference, so 'left over' is distinguishable from 'another window has it'

## Summary

Item (2) of T411 ("Make them reachable without hunting"). T411 shipped the
cheap half: the launch restore now LOGS how many live agent sessions no
restored pane attached to. But a log line is for whoever greps; the chooser
roster (Ctrl+Shift+N → session cards, T318/T320) is where a user could actually
DO something about an orphan — resume it into a window or kill it — and today
its cards give no hint that a session is left over rather than owned by some
open window.

Fix: when building the roster for the LOCAL machine, mark each live session
that the current window set does not reference (compare against the live
windows' attached session ids, the same set T411's counter uses at restore —
but computed live, since windows open and close after launch). Render the mark
as a visible "not in any window" badge/label on the card, per the win32 design
system (no invented spacing/colors — see docs/design/win32-design-system.md).
`attached` alone is NOT the signal: a session can be detached momentarily
during a reconnect swap, and a session attached by ANOTHER machine's viewer is
not "left over" either. The mark should mean precisely "no local pane holds
this session".

Mac parity: the Mac chooser wants the same affordance — file the sibling when
this lands (or extend T519's scope deliberately).

## In plain terms

The background service can end up holding a running terminal session that no
window shows — it just sits there using memory and a process slot. The session
list (Ctrl+Shift+N) does show every session, but nothing tells you which ones
are orphaned like this versus simply belonging to another open window. A small
"not in any window" label would let you spot one at a glance and resume or
kill it.

## Goals

- [x] The roster computes "left over" precisely: live on the local agent, no
      local pane holds it, no other viewer attached (`chooser_sessions.orphaned`).
- [x] The card renders a "not in any window" badge (warn tone, openness slot),
      geometry unit-tested at 1.0/1.25/1.5/2.0 scaling.
- [x] Acceptance against a real agent proves the mark absent while panes hold
      the sessions, present for a directly-opened session no pane holds, and
      cleared by resuming the session (`test/win32/chooser-orphan-badge.ps1`,
      ALL PASS, 16 assertions).
- [x] Mac sibling filed (T881).

## Validation criteria

- [x] With a live session opened directly against the agent (no pane holds
      it), the chooser's local roster shows the "not in any window" mark on
      exactly that card. — `chooser-orphan-badge.ps1` step 2:
      `remote-test-client --hold` opens+detaches one; the roster's oracle line
      counts exactly 1, cross-checked against `+sessions --json` (alive &&
      !attached == 1). Which CARD carries it is pinned by the unit tests
      (`orphaned` + badge-run tests in `chooser_sessions.zig`, none lane).
- [x] Sessions attached to open panes never carry the mark, including across a
      split/close churn. — step 1: after a `+split`, both pane sessions yield
      "0 session(s) not in any window", said out loud, not assumed; the
      reconnect-swap and attached-elsewhere cases are unit-tested
      (`orphaned:` test).
- [x] Resuming the marked session from the roster clears the mark (it now has
      a window). — step 3: Right/Down/Return resumes the marked id (attach log
      names it, agent reports it ATTACHED), and the reopened roster counts 0
      again past the earlier zero-line baseline.
- [x] Geometry/label placement asserted in the pure layout module at 1.0 /
      1.25 / 1.5 / 2.0 scaling, per the design system. — the badge-capsule
      test in `chooser_sessions.zig` now loops all four scales (width = text +
      2×pad, height = badge_h, radius = h/2, centered on and inside the title
      line box); `zig build test -Dapp-runtime=none` green via floor-lane.
