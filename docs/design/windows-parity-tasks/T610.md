# T610 - win32 machine pill: name the machine and open the Activity Monitor on click

## In plain terms

On a Mac, a window running on another machine says which machine, right in the
titlebar, and clicking that label opens the Activity Monitor for it. On Windows
the same window now shows a coloured dot telling you the connection is fine,
but it never says WHOSE connection, and clicking it does nothing. If you have
three remote windows open you cannot tell them apart without reading the title
the shell happened to set.

## Goals

- [x] A remote window's pill shows the machine's name while the link is up
- [x] Clicking the pill opens the Activity Monitor for that machine, on the
      connection the window already holds
- [x] The broken pill still re-dials, and still says `Reconnect`
- [x] The name is one derivation, shared with the close confirmation and the
      tooltip - not a second one invented here
- [x] The drag-band trade the interactive pill makes is written down where the
      next chip that wants to be clickable will read it

## Summary

Split out of T367 (2026-08-08). T367 built the win32 connection pill — the
green/amber/red status affordance plus the Reconnect button — and deliberately
stopped there. Mac's `MachinePillView.swift` is really TWO controls: a
`MachinePillCapsule` (dot + machine NAME, clickable, opens the Remote Activity
Monitor on the window's existing connection) and a `ConnectionStatusPill`
(the textual status, hidden while connected). T367 merged the status half into
one win32 capsule; this task adds the identity half.

## Details

Two pieces of work, in this order:

1. **A machine display name that is worth showing.** `Window.remote_machine` is
   a `RemoteMachine` union: `.tcp` carries a host (fine to show verbatim) and
   `.relay` carries a device ID, which is stable but not human-readable. Mac
   shows a friendly name from its machine record. The chooser
   (`chooser_rows.zig`) already renders machine names for the same devices —
   whatever it uses is the source to share, not a second derivation.
2. **The pill grows a name, and a click.** The connected state is currently
   wordless by design (see `remote_pill.zig`'s header); a machine NAME is the
   one label that earns its place there, because it identifies the window
   rather than restating that it works. Clicking a connected pill should open
   the Activity Monitor for that connection (`ActivityMonitor.zig` already
   opens against a remote connection — the chooser does it).

   That makes the pill interactive in every state, which simplifies
   `caption_layout.Pill.interactive` — but check the drag-band consequence
   first: T367 kept the quiet pill inside the drag region precisely so a window
   whose titlebar is mostly tab strip does not grow a dead patch. A named,
   clickable pill is wider AND non-draggable; decide deliberately whether that
   trade is right, and if it is, say so in the design system doc.

Tooltips are the other half of the identity story and win32 has none on the
caption band yet — `remote_pill.tooltip()` already produces the text (it names
the machine and the attempt count) and has nothing to show it. Either add a
caption tooltip host here or file it separately.

## What landed

`remote_pill.label` takes the machine name and returns it as the CONNECTED
pill's label; the two loud states keep their status wording, with the name in
the tooltip (D93 puts that choice to the user). The label is clamped to
`max_label_dip` (128 DIP) so a long hostname cannot eat the band the tab run
lives in, and an over-long name is cut on a UTF-8 character boundary rather
than mid-sequence.

`remote_pill.clickAction` is the new answer to "what does a click do here":
`.activity` while the window has a link to look at, `.reconnect` when it does
not. `caption_layout.Command.reconnect` became `.pill` to match - the caption
knows the pill was clicked, and asks `remote_pill` what that means at the
moment of the release, because the ladder runs on a timer and the link can come
back between the press and the release.

`Surface.openActivityMonitor` moved to `Window.openActivityMonitor`: two entry
points reach it now (the command palette, which has a surface, and the pill,
which is caption chrome), and one derivation of the source id is what keeps the
two from opening two panels on one machine. The panel is now also handed the
machine NAME, so it titles itself with the same string the pill paints.

Every state with a machine behind it is a button, so `ink` lights the quiet
modes on hover and press too - shaded in the direction the band is not, with
the mark and label re-resolved against the shaded fill so the contrast floors
hold in the state the pixels are actually in.

## Validation criteria

- [x] A remote window's pill shows the machine's display name in the connected
      state, at 1.0/1.25/1.5/2.0. `test\win32\remote-pill.ps1` section 2 reads
      the label off a live window (`label=127.0.0.1 w=92` at 1.25) and measures
      the capsule wider than the wordless 24 DIP it used to be; the geometry at
      all four scales is `remote_pill.zig`'s own none-lane tests.
- [x] The name comes from one derivation, not a second one. It is
      `RemoteMachine.displayName()` (T1390) - the same call the close
      confirmation and `remote_pill.tooltip()` make. A `.relay` machine is
      therefore named by its DEVICE ID today, which is what that call answers
      and what the chooser's own `dev.id` is; carrying the relay's FRIENDLY
      name to a window that never fetched a directory needs a name cache and is
      filed as **T1418**.
- [x] Clicking a connected pill opens the Activity Monitor on that window's
      existing connection. `remote-pill.ps1` section 2b sends the real
      `WM_NCLBUTTONDOWN`/`UP` pair on `HTOBJECT`, waits for a
      `GhozttyActivityMonitor` window, and asserts the app logged
      `activity monitor: reusing caller's connection` rather than dialing.
- [x] `remote_pill.tooltip()` is reachable from the UI, or its absence is filed
      as its own task -> filed as **T1417** (the win32 caption band has no
      tooltip host at all; the tab strip's is wired to the strip alone).
- [x] Floor green: `floor-lane.ps1 -Lane all` ALL LANES PASS (lib, none 302s,
      win32 391s, agent 402s); `ipc-p1` 25, `ipc-p2` 20, `ipc-p3` 16.
- [x] `remote-pill.ps1` ALL PASS (11), `-NegativeControl` red as it must be.
      Re-stamped after the Window.zig/Surface.zig edits: `remote-disconnect`
      49, `close-confirm` 58, `viewer-close` 44, plus the ten static audits.
