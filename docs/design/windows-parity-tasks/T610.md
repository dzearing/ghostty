# T610 - win32 machine pill: name the machine and open the Activity Monitor on click

## In plain terms

On a Mac, a window running on another machine says which machine, right in the
titlebar, and clicking that label opens the Activity Monitor for it. On Windows
the same window now shows a coloured dot telling you the connection is fine,
but it never says WHOSE connection, and clicking it does nothing. If you have
three remote windows open you cannot tell them apart without reading the title
the shell happened to set.

## Summary

Split out of T367 (2026-08-08). T367 built the win32 connection pill — the
green/amber/red status affordance plus the Reconnect button — and deliberately
stopped there. Mac's `MachinePillView.swift` is really TWO controls: a
`MachinePillCapsule` (dot + machine NAME, clickable, opens the Remote Activity
Monitor on the window's existing connection) and a `ConnectionStatusPill`
(the textual status, hidden while connected). T367 merged the status half into
one win32 capsule; this task adds the identity half.

## Details

Two pieces of work, in this order:

1. **A machine display name that is worth showing.** `Window.remote_machine` is
   a `RemoteMachine` union: `.tcp` carries a host (fine to show verbatim) and
   `.relay` carries a device ID, which is stable but not human-readable. Mac
   shows a friendly name from its machine record. The chooser
   (`chooser_rows.zig`) already renders machine names for the same devices —
   whatever it uses is the source to share, not a second derivation.
2. **The pill grows a name, and a click.** The connected state is currently
   wordless by design (see `remote_pill.zig`'s header); a machine NAME is the
   one label that earns its place there, because it identifies the window
   rather than restating that it works. Clicking a connected pill should open
   the Activity Monitor for that connection (`ActivityMonitor.zig` already
   opens against a remote connection — the chooser does it).

   That makes the pill interactive in every state, which simplifies
   `caption_layout.Pill.interactive` — but check the drag-band consequence
   first: T367 kept the quiet pill inside the drag region precisely so a window
   whose titlebar is mostly tab strip does not grow a dead patch. A named,
   clickable pill is wider AND non-draggable; decide deliberately whether that
   trade is right, and if it is, say so in the design system doc.

Tooltips are the other half of the identity story and win32 has none on the
caption band yet — `remote_pill.tooltip()` already produces the text (it names
the machine and the attempt count) and has nothing to show it. Either add a
caption tooltip host here or file it separately.

## Validation criteria

- [ ] A remote window's pill shows the machine's display name in the connected
      state, on both `.tcp` and `.relay` machines, at 1.0/1.25/1.5/2.0.
- [ ] The name comes from the same source the machine chooser renders, not a
      second derivation.
- [ ] Clicking a connected pill opens the Activity Monitor on that window's
      existing connection (acceptance script, real click path).
- [ ] `remote_pill.tooltip()` is reachable from the UI, or its absence is
      filed as its own task.
- [ ] Floor green: both zig test lanes, `test-agent`, P1-P3.
