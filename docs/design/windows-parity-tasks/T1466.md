# T1466 - A restored pane is still 1.55x slower than a plain one at bulk output, and closing it needs D94
## Summary

T1465 measured the cause of the agent-held pane's ingest deficit and shipped the
half of the remedy that costs nothing: the pty holder and the conhost it creates
are kept off the CPU's efficiency cores, which took the burst ratio from
1.84-2.02x of a local pane down to 1.51-1.58x. `test\win32\pane-ingest-ab.ps1`'s
`$relayRatioBound` came down 2.50 -> 1.75 to hold that.

The remaining ~0.5x needs the USER's shell subtree on the performance cores too.
Measured as a one-off experiment (the whole holder tree pinned): **1.05x and
1.14x**, i.e. level with conhost. It is not shipped because process affinity is
inherited by everything the pane starts, so a build run in a persisted pane
would be confined to 16 of this box's 32 logical CPUs - a trade the user has to
make, not the loop. That is **D94**.

## In plain terms

A pane that keeps its session alive still takes about half again as long as an
ordinary one to scroll a big burst of text. We know exactly how to close the
rest of it and we know what it would cost: anything you RUN in that pane would
get about half the machine. The question is out with the user.

## Details

- Do NOT re-investigate the relay, the parser, the message count or the ACKs -
  T1463/T1464/T1465 each measured one of those and each came back negative. The
  reader is 96% blocked in `ReadFile` and its peek finds an empty pipe every
  time; the SOURCE is the whole story.
- The lever is `internal_os.power` (`src/os/power.zig`): `preferPerformanceCores`
  pins the calling process (inherited by its children), `allowAllCores` hands one
  child the full mask back with a soft CPU-set preference. Today `pty_host.zig`
  calls the first for itself and the second for the shell. Option B of D94 is
  simply not making that second call.
- If D94 comes back "leave commands on the whole machine", this task closes as
  `skipped(D94: ...)` and `pane-ingest-ab`'s 1.75 bound is the permanent one.
- A third option nobody has costed yet: pin the conhost the ConPTY spawns
  WITHOUT pinning the shell. It needs conhost's handle, which
  `CreatePseudoConsole` does not hand back - `descendants.zig` could find it.
  Partial evidence says this alone is worth little (the soft-preference variant
  landed at 1.49-1.62x), so cost it before building it.
