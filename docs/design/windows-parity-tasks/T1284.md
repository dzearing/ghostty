# T1284 - The chooser close-chord check fails its own positive control, so it can say nothing about the chord

## In plain terms

There is a check that Ctrl+W closes the machine chooser without also closing a
terminal pane behind it - the mistake that would throw away someone's work. On
the hidden test desktop the keystroke never seems to arrive, so the check's own
warm-up fails and it can say nothing either way. Either make the keystroke land
there, or have the check say plainly that it could not press the key.

## Goals

- [ ] the positive control passes on the background desktop, or the missing capability is declared
- [ ] `chooser-close-chord.ps1` is green there, or skips with a named capability
- [ ] the red is re-attributed in writing: harness or product

## Summary

chooser-close-chord.ps1 fails its mandatory positive control (Ctrl+W closed one pane (2 -> 2)) on the background test desktop - the shape of a chord that never arrived rather than one that was mishandled. Decide whether the posted-chord route can carry it there; if it cannot, declare the missing capability so the script SKIPs (lib\DesktopCapability.ps1) instead of reporting a red against T603.
