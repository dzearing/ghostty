# T537 - viewer-panes.ps1 regression: +reload window-target string assert fails in the harness but passes live

## Summary

`test\win32\viewer-panes.ps1` fails its `+reload on a terminal-focused window
reports the OTHER Mac string` assert (script line ~517), reproducibly (3/3
runs on 2026-08-06), at HEAD 10f10a582 with a freshly built exe — this is NOT
a T392 regression (reproduced with T392's changes reverted). The exit code is
right (nonzero); only the STRING assert fails.

The confusing part: the same case passes when driven by hand. A manual run
against a fresh debug instance (`GHOZTTY_PIPE_SUFFIX=t392dbg`, `+new-window
--target=vpterms` then `+reload --target=vpterms`) printed exactly
`focused pane of 'vpterms' is a terminal pane, nothing to reload` with exit 1.
So the server string is correct and the defect is in how the case unfolds
inside the harness — either `$r.Out` captures something else there (a
different resolution path answering, e.g. the registry handing back a .pane
entry so the OTHER string `target '...' is a terminal pane` is printed, which
is what the assert name hints at), or the harness's output capture drops it.

## In plain terms

One automated check for the viewer "reload" command fails every run, but when
a person does the same steps by hand the product behaves correctly. Either
the product behaves differently under the test harness (a real bug hiding in
a rarely-taken path) or the test is mis-measuring (a broken check that will
mask real failures later). Either way the red must be explained and fixed.
