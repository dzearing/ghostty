# T891 - The win32 command palette has no 'Recent' section and no alphabetical sort (Mac surfaces the 10 most recently used commands first, then sorts the rest)

## Summary

Found while landing T555. The Mac palette (`TerminalCommandPalette.swift`
`commandSections`) sorts all options with a locale-aware case-insensitive
compare (normalizing `:` so prefixed families group together), and keeps a
"Recent" section: `PaletteHistory.shared` records each command's use and the
10 most recently used surface at the top in recency order, with the rest
under "All Commands". The win32 palette (`Surface.zig`
`filterPaletteEntries`) shows registry order with user entries and the T555
jump entries appended — no sections, no sort, no history.

Shape of the fix: a pure ordering/history module (none-lane tested, the
`palette_jump.zig` pattern), a small persisted MRU (the DPAPI/state-dir
conventions do not apply — Mac uses UserDefaults; a JSON in the state dir
matches), and section headers in `paintPalette`.

## Validation criteria

- [ ] Entries are sorted alphabetically (case-insensitive) when there is no
      filter, matching the Mac normalization of `:`-prefixed titles
- [ ] Executing a command records it; the next palette open lists up to 10
      recent commands first, in recency order, under a "Recent" header
- [ ] The MRU survives an app relaunch
- [ ] Pure ordering/history logic unit-tested in the none lane; behavior
      covered by an on-box acceptance script; floor stays green
