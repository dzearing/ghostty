# T975 - After a reboot nothing comes back: the panes that were open are replaced by one empty window

## Summary

Found 2026-08-18 validating T922, and reproduced twice outside the acceptance harness. Shape: build a 2-window / 3-pane layout with persistent sessions, then kill the app, the session manager AND every --pty-host holder (what a reboot does since T909 put each session's ConPTY in a holder that outlives its manager). Relaunch the app against that state: it opens ONE fresh default window with a brand-new pane - a new pane id, cwd C:\Users\David, no notice - and the second window with its two commanded panes never returns. Both windows and all three sessions are present in session-layout-debug.json and in the agent's sessions.json (each with a holder_pid whose process is gone). Evidence: test\win32\session-relaunch-notify.ps1 arm A now scores 'A2 the layout restored (3 panes)' FAIL with 1 leaf; its app stderr shows 'local agent did not become dialable within 2000ms' then repeated ConnectionRefused, yet a hand-started ghoztty-agent.exe with the SAME --listen-pipe/--port-file/--sessions-file against that exact state dir is listening in 0.3s - so the agent binary handles dead holder_pids fine and the failure is on the app side (or in what the app spawns). Not caused by T922: its code only runs inside the did_notify branch of an attach that never happens here. Until this is fixed a reboot loses the user's whole layout, and every restore-path acceptance arm is unscoreable.
