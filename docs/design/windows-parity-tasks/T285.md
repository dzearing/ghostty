### What the acceptance run caught, before this shipped

**The sort indicator was inside the ellipsis.** The arrow was appended to the
header title (`"% CPU ▼"`), and `% CPU` plus an arrow does not fit the 60-90 DIP
CPU column — so `DT_END_ELLIPSIS` ate the arrow and the panel showed
`"% CPU…"` with **no indicator on the very column it was sorted by**. The
indicator now gets its own reserved slot at the cell's trailing edge and the
title ellipsizes inside what is left; it is a filled `Polygon` triangle rather
than a text glyph (§4 — glyphs are filled shapes).

It was found by LOOKING at a `PrintWindow` capture of the panel, not by an
assertion — no assertion in the script would have caught it, because both the
title and the arrow are things the script never reads back. **A new pixel
surface deserves one human look at a capture**, in addition to whatever the
probes assert.

**Secondary text on a selected row was 2.8:1.** The Path column paints in
`COLOR_SECONDARY` (150,150,150), which clears §2.3's 4.5:1 floor against the
panel (5.4:1) and fails it against the selection fill `COLOR_SELECT`
(38,79,120). Selected rows now take the primary color for that column. The
lesson is the one §2.3 already states and is still the easiest to miss: **the
floor is checked against the fill the text actually sits on**, not against the
window background.

### Test-harness traps this run re-paid for

- **`Get-TestChildWindows -Class 'BUTTON'` matches nothing.** The harness
  compares class names EXACTLY and the button class is `Button`.
- **A one-element array return unrolls in PS 5.1**, so `(Get-Panels).Count` was
  `$null` and the "exactly ONE panel" assertion failed against a correct app.
  Wrap at the CALL SITE: `@(Get-Panels).Count`. (Already in memory as a known
  trap; it still cost a run.)
- **`Send-TestMouse` takes SCREEN coordinates**, not client — it `SetCursorPos`es
  them and `ScreenToClient`s them itself. Passing client coords put the header
  click 20 px past the table's right edge, where `columnAt` correctly returns
  null, and the sort simply never changed.
- **A channel-dominance pixel probe is not a tint probe.** "Bluer than it is
  red" passes on ClearType's color fringes, which appear wherever there is text
   — so the first version of the chart probe passed on a panel whose charts had
  not drawn yet. GDI fills solid brushes with no antialiasing, so the tint lands
  as its literal constant; the probe now matches `COLOR_CPU` / `COLOR_MEM`
  exactly, with control probes asserting each tint is absent from the other
  gauge's half and from the table.
- **A chart with one sample paints nothing** — correctly, there is no segment to
  stroke. The probe now waits for a third poll first, or it reads a correct
  panel as a broken one.

### Decisions worth carrying into T286/T287

- **"New Process…" is created DISABLED, not omitted.** The layout module
  reserves its rect, so creating it now means the control bar has the geometry
  the module describes from day one (which the acceptance script measures), and
  a disabled control is an honest state (§2.2) where a live button that does
  nothing is not. T286 enables it; the Kill button is absent entirely
  (`has_kill = false`) because it only exists while rows are selected.
- **The carousel is off** (`has_carousel = false`) until T287 gives it a second
  source: chrome that controls nothing does not appear (§6).
- **Sampling is off the GUI thread, and `close` JOINS it.** A poll enumerates
  ~300 processes and opens each one; Mac runs the equivalent on a background
  queue. Exactly one sample is in flight at a time, so the two persistent
  samplers are only ever touched by that worker, and the snapshot is arena-backed
  so adopting one is a pointer swap. A dropped tick is deliberate — a machine
  slow enough to miss one must not accumulate a backlog of enumerations.
- **Selection is keyed by PID, never by row index** (Mac keys its `Set` on
  `ProcRow.id`). A row that moves under a re-sort or the next 1.5 s poll stays
  selected, which is the whole reason T286's Kill can trust it.
- **Sort ties break on pid ascending in BOTH directions**, so equal rows do not
  reshuffle under a stationary cursor every poll.
