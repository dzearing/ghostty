# T961 - The release-artifacts guard can never be satisfied on this box: two of its sections need Docker, which is prohibited here

## Summary

scripts\guard-due.ps1 marks release-artifacts DUE, and running test\win32\release-artifacts.ps1 exits 0 with 'ALL PASS (2 skipped)' - B1 (FILEVERSION single source) and B2 (portable ZIP layout) both SKIP with 'Docker is not running'. A run with skipped sections deliberately does not stamp, so the guard stays DUE forever. Starting Docker is not an option on this box: the WSL2 backend has buried the machine at 28 GB RAM before, and the standing rule is that Docker-down is a SKIP path and never a prerequisite to fix. The consequence is that every turn from now on must reach for parity-tasks.ps1 validate -NoGuardDue, which is exactly the loud-excuse hatch losing its meaning through routine use - and once it is routine, a genuinely stale harness will slip past unnoticed. Fix the guard, not the box: either B1/B2 get a Docker-free path (msitools in a container is a convenience, not a requirement, for reading a FILEVERSION or a ZIP entry list), or the guard's coverage row learns that a section skipped for a documented environment reason still counts toward the stamp. First observed 2026-08-18 during T879, whose commit had to use -NoGuardDue for a docs-only change.
