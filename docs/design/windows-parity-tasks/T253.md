# T253 - A turn longer than the 45 min staleness window draws a nudge that types a prompt into the working session

## In plain terms

The safety net that restarts the work loop when it dies was judging "dead" by a
check-in that only happens between tasks — so a single long task looked like a
dead loop, and the safety net would type a new instruction into a session that
was busy working, quietly queueing up a second job where only one belongs. Now
the loop is judged alive by the work it is visibly doing (the session's own
activity log, which updates by itself), the double-check reads a whole screen
instead of five lines, and even a mistaken wake-up call now says "reset first",
so it can never pile a second job onto a working session. Nobody sees a change
day-to-day; what disappears is the loop occasionally doubling up on itself
after a long build.

## Goals

- [x] A session that is working is never nudged, even 46+ minutes into a task
      — its liveness follows the transcript Claude Code writes automatically.
- [x] The still-producing backstop samples enough (60 lines over 20s) to tell
      "compiling" from "wedged".
- [x] A nudge that fires anyway is reset-first, so it costs a context reset,
      never a second task in the same context.
- [x] Old locks and unresolvable transcripts degrade to exactly the old
      behaviour — the pulse is additive, never load-bearing.

## Summary

The watchdog's staleness window (`-StaleMinutes 45`) is measured against a
heartbeat that **only a human-followed step refreshes**. go.md step 6 says to
call `go-loop-lock.ps1 heartbeat` during a long task, and even when that step IS
followed, the remainder of the turn (build + acceptance run + staging release +
`launch-upgrade.ps1`) can still outrun the window. When it does, the watchdog
concludes the loop is stuck on a session that is in fact working, and its
re-entry action is to type `read go.md and go` + Enter into that live pane.

That is not a free action. Text submitted to a Claude Code TUI mid-turn is
**queued**, so it re-enters the loop the moment the current task ends - which
starts a SECOND task in the SAME context instead of the `/reset-context` that
step 7 requires. That is precisely the failure the context rule exists to
prevent (the 716k-token session).

The watchdog is not wrong to act; its input is wrong. A turn that is making
progress should be beating the heartbeat without anybody remembering to.

## Evidence (VERIFIED on the box, 2026-07-31, during the T233 delivery)

`scripts\go-loop-lock.ps1 status -Json` after the delivery:

```
"claude_pid": 13060, "heartbeat": "2026-07-31T16:31:19", "state": "stale-heartbeat",
"owner_alive": true, "turn": 9, "mine": true
```

`%TEMP%\ghoztty-go-loop-watchdog.log` - healthy for 45 min, then the nudge:

```
2026-07-31 17:12:49 healthy: pane=6C13A7F3-... pid=13060 age=41.5m remaining=63
2026-07-31 17:17:50 pane 6C13A7F3-... occupant=claude (lock owner_alive=True)
2026-07-31 17:17:58 re-entering: nudge live session in pane 6C13A7F3-... (state=stale-heartbeat, occupant=claude, remaining=63)
2026-07-31 17:17:58   send-keys exit=0
```

Nothing beat the heartbeat between 16:31:19 and 17:17:50 - 46 minutes of
T233 build, `test/win32/split-divider.ps1`, staging release, and upgrade. The
session (pid 13060) was alive and correct the whole time; the watchdog's own
pane probe said so in the same tick (`occupant=claude`, the T241 fix working
exactly as designed).

`Test-PaneProducing` did not catch it: it compares `+read --lines=5` against
itself 8 seconds later (`scripts/go-loop-watchdog.ps1:163-170`). Five lines is
a thin sample, and a session between phases - or one whose bottom five lines
are a static prompt box - reads as "not producing" even though the turn is
alive.

## Two things are wrong

1. **The liveness signal is manual.** The heartbeat is refreshed by a step in a
   markdown file. Any signal that depends on a model remembering to emit it
   will go missing exactly when the turn is busiest, which is when it matters.
2. **The freshness probe is too narrow to be the backstop.** Five lines over an
   8-second gap cannot distinguish "wedged" from "compiling", so the fallback
   that is supposed to make a false nudge impossible does not.

## The fix (sketch - decide during the task)

- **Beat the heartbeat automatically from the session's own activity.** The
  cheapest source is a Claude Code hook already firing on this box (the
  `UserPromptSubmit` / banner hook path): have it call `go-loop-lock.ps1
  heartbeat` when the lock is `mine`. Then any turn that is running tools is
  visibly alive, and staleness once again means what it claims to mean.
- **Widen the producing probe** so it is a real backstop: more lines, a longer
  gap, or compare a hash of the whole visible pane rather than the tail.
- **Make the nudge safe even when it is wrong.** `read go.md and go` typed into
  a mid-task session should not be able to start a second task in that context.
  Consider a resume prompt that is explicitly reset-first (the prompt this loop
  already uses at relaunch: `/reset-context read go.md and go`), so a spurious
  nudge costs a context reset rather than a rule violation.

## Validation

- Unit: with a lock whose heartbeat is older than `-StaleMinutes` and a pane
  whose tail IS changing, `go-loop-watchdog.ps1 -Once -DryRun` must report
  `none`, not `nudge`. Extend `test/win32/go-loop-guard.ps1` (section N is the
  right neighbour - it already builds a stand-in TUI in a pane).
- Unit: with the heartbeat hook installed, a simulated tool call must move the
  lock's `heartbeat` forward without touching `turn` or `claude_pid`.
- On-box: a turn that runs longer than 45 minutes must leave NO
  `re-entering: nudge` line in `%TEMP%\ghoztty-go-loop-watchdog.log`. The
  T233 delivery above is the negative control - it produces one today.

## Resolution (2026-08-05)

Three changes, matching the sketch's three findings:

1. **The liveness signal is automatic now.** `go-loop-lock.ps1` records the
   session's Claude Code transcript path (`~\.claude\projects\<proj>\<session-id>.jsonl`,
   resolved from `$env:CLAUDE_CODE_SESSION_ID`) at `acquire` — and adopts it at
   `heartbeat` for locks written before this change. Freshness everywhere
   (`status`, and `acquire`'s stale-takeover rule) is now the NEWER of the
   manual heartbeat and the transcript's mtime, which Claude Code advances on
   every message and tool result. The transcript approach was chosen over the
   sketch's UserPromptSubmit-hook idea because it needs no per-box installation
   and cannot be forgotten — receipt filed as D16. `status` reports
   `age_minutes` (last sign of life) with `activity_by`/`activity_at` saying
   which signal answered, plus `heartbeat_age_minutes` for readers that want
   the checkpoint specifically; an absent/unresolvable transcript falls back to
   heartbeat-only, byte-for-byte the old behaviour.
2. **The producing probe is a real backstop**: 60 lines over 20s (was 5 lines
   over 8s), so a spinner, an elapsed counter, or scrolling build output
   anywhere on screen counts as alive.
3. **The nudge is reset-first**: the watchdog's default `-ResumePrompt` is now
   `Before starting any task, run /reset-context read go.md and go` — typed
   into a live session it queues a context reset, not a second task; typed into
   a `--continue`-resumed session it clears the dead turn's context first,
   which is what go.md step 7 wanted anyway. Deliberately not slash-first (a
   leading `/` opens the command menu and the first Enter selects instead of
   submitting).

Validation on the box (2026-08-05): `test\win32\go-loop-guard.ps1` **ALL
PASS**, including new section R (R1–R18): moving transcript + 2h-old heartbeat
reads `held` and the watchdog answers `ACTION none` before ever probing the
pane; a rival `acquire` gets BUSY off the same rule; transcript-gone-quiet and
no-transcript-at-all both fall back to stale + re-entry (positive controls);
`heartbeat` adopts the pulse for a pre-T253 lock without touching turn/pid;
prompt + probe-width defaults asserted from the param block. Floor: P1–P3 ALL
PASS, all three zig lanes PASS via `floor-lane.ps1` (scripts-only change).
Live negative control observed mid-task: the pre-fix watchdog nudged THIS
session 46 min into this very turn — the queued prompt that arrived was the
new reset-first text, exercising the safe-nudge path for real.
