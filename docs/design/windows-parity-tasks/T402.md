# T402 - Mac seat: verify the chooser Kill reports success now that T96 fixed the shared CLOSE_SESSION_RESULT dispatch

## Summary

T96 fixed a defect in **shared** Zig (`src/remote/connection.zig`), so it lands
on both platforms with no Mac-side code change: `close_session_result` was the
one A→C reply type with no arm in `handleControlInternal`, so every
`Connection.closeSession` RPC died on its timeout and returned `ok = false` over
a session the agent had in fact killed ~30 ms earlier.

Mac reaches that same call through `ghostty_remote_connection_close_session`
(`src/apprt/embedded.zig:3145`), which is the chooser's **Kill**. So the Mac
chooser's Kill has been reporting failure — after burning the full RPC timeout —
for as long as the feature has existed, exactly as the Windows one did.

Nothing needs implementing. This is the **verification half** the platform
symmetry rule asks for, and it can only be run on a Mac.

## Validation (Mac seat)

1. With a local agent holding at least one live session, open the machine
   chooser, Kill a session, and confirm it now:
   - returns promptly (no multi-second stall on the button), and
   - reports success rather than a failure the roster then contradicts.
2. Check the Mac-side log for the equivalent of the win32
   `chooser roster: close session confirmed=true` line.
3. If the Mac chooser has no acceptance coverage for Kill, file that gap.

## Evidence from the Windows seat

- `remote-test-client --close-session=<id>`: **10054 ms → exit 1** before,
  **59 ms → exit 0, `ok=true`** after.
- `test/win32/chooser-sessions.ps1` now asserts
  `chooser roster: close session confirmed=true` (it previously documented that
  assertion as unreachable, blaming a slow agent teardown that measurement
  disproved).
