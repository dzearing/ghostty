# T781 - persistence-flag.ps1 is red: 4 undeclared launch sites in agent-attach-refused.ps1 and url-scheme.ps1

## In plain terms

There is a check that makes every test script say, out loud, whether it wants
the app to reopen the windows a previous run left behind. Four launches in two
test scripts never say, so the check has been failing — and a failing check
teaches everyone to ignore it, which is how the thing it guards comes back.

## Summary

Found while running the harness sweeps for T279 (the failure predates that
work — neither file is touched by it):

```
FAIL  A1 no launch leaves persistence unstated (undeclared: 4 of 176)
  agent-attach-refused.ps1:276
  url-scheme.ps1:359
  url-scheme.ps1:368
  url-scheme.ps1:381
```

Each site needs one of T158's three declarations: the flag in the launch
statement, the flag through a variable the sweep resolves, or a
`# persistence: <reason>` marker for a site where neither fits. Decide per
site what the launch actually WANTS — several `url-scheme.ps1` launches are
activation processes that open no terminal at all, which is a marker case, not
a flag case.

## Validation criteria

- [ ] `powershell -NoProfile -File test\win32\persistence-flag.ps1` ends ALL PASS.
- [ ] Each converted site states an intent that matches what it does — a marker
      that claims "opens no window" is only correct if that launch opens none.
- [ ] `test\win32\url-scheme.ps1` and `test\win32\agent-attach-refused.ps1`
      still pass after the change.
