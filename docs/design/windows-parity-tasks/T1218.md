# T1218 - No Windows installer can be built: a comment inside the MSI package contains a double hyphen, which XML forbids

## In plain terms

Nobody can download and install Ghoztty for Windows right now. The step that
packages the installer stops with "Failed to parse XML" and produces nothing,
so the website keeps offering the previous version and any new fix is stuck on
the build machine. The cause is a note somebody wrote inside the installer's
own source file, not anything about the terminal itself.

## Goals

- [x] The installer builds again, and a release publishes both artifacts.
- [x] The same mistake cannot reach the packaging tool a second time: it is
      caught where it is made, with a message that names the trap.
- [x] That catch is provable without Docker, on this box.

## Summary

The `win-v1.36.0` release run (33428859097) failed after a ten-minute
ReleaseFast build:

```
:2543: parser error : Double hyphen within comment: <!-- T1207: make room ...
         `--pty-host` holder per live session keep the user's shells running
Failed to parse XML
```

T1207's explanatory comment in `dist/windows-installer/build-msi.sh` quotes two
flags, `--pty-host` and `--install-prepare`. XML forbids `--` inside a comment,
so the whole document is rejected and no `.msi` and no `.zip` are produced. The
`Verify artifacts`, `Publish` and `Update website` steps were all skipped, so
nothing shipped and nothing was corrupted - the failure is total and loud, but
it lands ten minutes into a release run rather than on the box.

## Why nothing caught it

`test\win32\release-artifacts.ps1` is the harness that covers this file, and
its only section that COMPILES a package (B1) needs Docker and the
`msitools-local` image. Docker is deliberately never started on this box
(T1189), so `release-artifacts-packaging` had been sitting GUARD DUE since the
packaging commit that introduced this - the guard was right, and the answer to
it was "Docker is down", which is honest and was not enough.

## The fix

Two parts, both in `dist/windows-installer/build-msi.sh`:

1. The comment no longer contains a double hyphen (the flags are written
   without their leading dashes), and it now says so in its own text, so the
   next person to edit it is told the rule where the rule applies.
2. The WXS generator parses what it just produced with
   `xml.etree.ElementTree` before handing it to `wixl`, and fails with a
   message that names the double-hyphen trap. It is pure python, runs wherever
   the script runs, and costs nothing.

And a check that runs here, with no Docker: section B5-B7 of
`test\win32\release-artifacts.ps1` extracts that generator, runs it against a
fixture, asserts the output parses as XML, and then - B7, the negative control
- puts the exact `--pty-host` defect back and asserts it goes red.

## Validation criteria

- [x] The WXS generator refuses a document with `--` inside a comment, with a
      message naming the cause. — verified standalone: the unmodified generator
      exits 0 and writes a well-formed document; the same generator with
      `--pty-host` restored exits 1 with `not well-formed (invalid token)` plus
      the double-hyphen hint.
- [x] That refusal is exercised by the on-box harness without Docker. —
      `test\win32\release-artifacts.ps1` B5/B6/B7 all PASS on this box with
      Docker down (ALL PASS, 1 skipped = B1, the Docker-only FILEVERSION
      check).
- [x] A release run publishes both artifacts again. — see the progress log.
