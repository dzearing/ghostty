# T895 - Windows downloads are two releases behind: publish win-v1.33.0 to match the macOS v1.33.0 release

## In plain terms

Someone downloading Ghoztty for Windows today gets a build from August 8th,
while Mac users get August 14th's. Nothing looks broken — the links all work —
they just hand out an old version. Publishing the Windows release for 1.33.0
puts both platforms back on the same version.

## Summary

T579's new parity check found the drift live: the newest macOS release is
`v1.33.0` (2026-08-14), the newest Windows release is `win-v1.31.0`
(2026-08-08) — `v1.32.0` and `v1.33.0` were never given their Windows half.
Until this is closed, fork-ci's `release-parity` job is red on every push to
the Windows branch (that loudness is by design).

The fix is one tag push on this branch, per the runbook in
`.github/workflows/release-windows.yml`: push `win-v1.33.0` at a
commit whose tree is green, and the workflow builds/publishes the MSI +
portable ZIP onto a `win-v1.33.0` release and moves the website's Windows
links. Skipping `win-v1.32.0` is correct — the channel's contract is "newest
win-v", and 1.32's Windows half is subsumed by 1.33.

## Validation criteria

- [ ] `win-v1.33.0` release exists with `Ghoztty-1.33.0-x64.msi` and
      `Ghoztty-portable-1.33.0-x64.zip` assets.
- [ ] `scripts\check-release-parity.ps1` reports IN STEP (exit 0).
- [ ] fork-ci's `release-parity` job is green on the next push.
- [ ] The website's Windows download links point at win-v1.33.0.
