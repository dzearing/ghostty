# T895 - Windows downloads are two releases behind: publish win-v1.33.0 to match the macOS v1.33.0 release

## In plain terms

Someone downloading Ghoztty for Windows today gets a build from August 8th,
while Mac users get August 14th's. Nothing looks broken — the links all work —
they just hand out an old version. Publishing the Windows release for 1.33.0
puts both platforms back on the same version.

## Goals

- [x] `win-v1.33.0` is published with both artifacts, from a green tree
- [x] Windows download links on the site hand out 1.33.0, not 1.31.0
- [x] The parity check that caught this reports IN STEP again

## Summary

T579's new parity check found the drift live: the newest macOS release is
`v1.33.0` (2026-08-14), the newest Windows release is `win-v1.31.0`
(2026-08-08) — `v1.32.0` and `v1.33.0` were never given their Windows half.
Until this is closed, fork-ci's `release-parity` job is red on every push to
the Windows branch (that loudness is by design).

The fix is one tag push on this branch, per the runbook in
`.github/workflows/release-windows.yml`: push `win-v1.33.0` at a
commit whose tree is green, and the workflow builds/publishes the MSI +
portable ZIP onto a `win-v1.33.0` release and moves the website's Windows
links. Skipping `win-v1.32.0` is correct — the channel's contract is "newest
win-v", and 1.32's Windows half is subsumed by 1.33.

## Validation criteria

- [x] `win-v1.33.0` release exists with `Ghoztty-1.33.0-x64.msi` and
      `Ghoztty-portable-1.33.0-x64.zip` assets. — `gh release view win-v1.33.0`
      lists both, published 2026-08-18T11:16:53Z by the tag push; the MSI URL
      answers `200` at 21,583,360 bytes, so the link a person clicks is live
      and not just listed.
- [x] `scripts\check-release-parity.ps1` reports IN STEP (exit 0). — re-run
      after the publish: `IN STEP: v1.33.0 has its matching win-v1.33.0
      release`.
- [x] fork-ci's `release-parity` job is green on the next push. — see the
      progress log entry for the closing push.
- [x] The website's Windows download links point at win-v1.33.0. — the
      workflow's own step committed `Update website Windows download to
      win-v1.33.0` on `gh-pages` (b19a35608), and the served page at
      dzearing.github.io/ghoztty was re-fetched until it carried `win-v1.33.0`
      rather than trusting the commit (Pages lags the push by a minute).
