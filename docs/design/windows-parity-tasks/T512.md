# T512 - cmd.exe panes never update their title or emit prompt marks: consider PROMPT-based $E integration (OSC 2/7/133)

## In plain terms

A pane running cmd never changes its tab title as you move around, the way
PowerShell panes do — it says "cmd" (or whatever it started as) forever, so a
strip of cmd tabs is a row of identical labels. cmd also never tells the
terminal "a prompt starts here", so prompt-jumping features don't work in it.

## Summary

cmd.exe has no profile/rcfile hook, so `shell_integration.zig` treats it as
non-integrable ("cmd.exe cannot support integration at all — it has no prompt
hook"). But cmd's `PROMPT` variable supports `$E` (ESC), which is enough to
emit OSC sequences at every prompt render — Windows Terminal uses exactly this
for its cwd tracking (`$e]9;9;%cd%$e\`). Ghoztty could inject a `PROMPT` env
var at spawn (append to the inherited value or the `$P$G` default):

- `$E]2;$P$E\` — title = current directory (OSC 2)
- `$E]7;kitty-shell-cwd://%COMPUTERNAME%$P$E\` — cwd (OSC 7; the win parser
  already normalizes `/D:\x` shapes, `stream_handler.zig reportPwd`)
- `$E]133;A$E\` / `$E]133;B$E\` — prompt marks (partial: no C/D possible)

Note the CWD half is already solved by T185's live process-cwd fallback
(`os/process_cwd.zig`) — the remaining user-visible value here is the TITLE
(and partial prompt marks). If this lands, the OSC 7 it emits would set
`pwd_reported` and the T185 fallback stands down automatically, so the two
mechanisms compose rather than conflict.

Hazards to design around: a user's own `PROMPT` customization must be
preserved (append, don't replace); `set PROMPT=` inside the session loses the
integration (acceptable, same as any shell unsetting its hooks); nested cmd
inherits the var (fine — still correct).

## Validation criteria

- [ ] A cmd pane's tab title follows `cd` (shows the current directory)
- [ ] A user-customized PROMPT still renders (integration appends, not replaces)
- [ ] `pwd_reported` flips true for cmd panes (OSC 7 arriving), fallback stands down
- [ ] Acceptance script or extension of an existing one, ALL PASS on the box
