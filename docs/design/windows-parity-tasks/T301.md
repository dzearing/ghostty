# T301 - Switching to a machine a remote WINDOW is already connected to re-dials through the relay instead of borrowing

## Summary

`switchToCard` always dials a **fresh, owned** relay connection for a remote
target (`ActivityMonitor.zig`, T296). That is the correct default — a borrowed
connection belongs to a window whose lifetime the panel cannot see — but it
produces one visibly wrong outcome:

**Open the Activity Monitor from a remote window's palette (it borrows that
window's connection), switch to Local, then switch back to that same machine.**
The panel now re-dials through the relay, so:

- with no signed-in account it simply **fails** — "Couldn't connect" — while a
  perfectly good live connection to that machine sits one window away;
- with an account it opens a **second** connection to a machine we are already
  talking to.

The direct-TCP case (`+new-remote-window --host/--port`) is the sharper one: a
`127.0.0.1:PORT` source has no relay device id at all, so the re-dial cannot
even be attempted correctly.

## Evidence

Reproduced as part of T296's acceptance work on this box:
`test/win32/activity-monitor-remote.ps1` section E switches a borrowed-connection
panel to Local and asserts the remote window's session survives (it does — the
borrowed connection is dropped, never freed). Switching BACK is the case this
task covers and the script deliberately does not assert it, because the current
behavior is the defect.

## The shape of the fix

When the switch target names a machine some live **window** is already connected
to, borrow that window's connection (`openReusing`'s ownership: `dialed == null`,
never freed by the panel) instead of dialing. That needs:

- a lookup from a card's identity to a window's connection — and cards are keyed
  by relay device id while a direct-TCP window is keyed by `host:port`, so the
  identity question has to be answered first (it is the same question T146's
  cross-machine session browse has to answer);
- a rule for what happens when that window CLOSES while the panel is borrowing —
  today only `openReusing` can create that state, and it is bounded because the
  panel is opened from the window and typically closes with it.

Mac does not have this problem in the same form: its `switchTo` dials
`host`/`port` from a local `MachineRegistry`, so a re-dial always succeeds and
the cost is only a duplicate connection.

## Validation

- Both `zig build test` lanes plus `zig build test-agent` green; P1-P3 ALL PASS.
- `test/win32/activity-monitor-remote.ps1`: a panel opened from a remote window,
  switched to Local and switched BACK, samples the machine again (root pid ==
  the agent's) with **no new connection** to the agent, and the window's session
  still round-trips afterwards.
