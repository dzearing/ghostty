# T318 - T146a: chooser session roster - the LOCAL machine's live sessions, richer labels, and Kill

First child of the **T146 split (2026-08-01)**. See T146 for the parent framing
and the four Mac commits; this file owns the first of them, `040c6a959`
(master-detail redesign: live sessions, Kill, richer labels).

## Summary

The Ctrl+Shift+N chooser on Windows has a master-detail layout (T172-T176,
T310-T312) and, since T295/T296, a real remote data plane - but it has **no
session roster at all**. Measured: `MachineChooser.zig` (108 KB) contains
exactly **four** matches for `session`, and all four are the string
`"Session expired - sign in again above."` in relay error mapping
(`:728`, `:1567`, `:1577`, `:1579`). There is no roster, no expander, no Kill.
Mac's chooser expands each machine row into a per-session list with liveness,
activity, badges, cwd/command sublines and Show/Resume + Kill
(`MachineChooserView.swift:544`, `:608-730`).

This task ports the **local** half only: the "This Machine" row expands into
the local agent's roster. Remote machines are T319.

## The data plane already exists - do NOT rebuild it

Verified by reading, all cross-platform Zig, all reachable from win32 today:

- `Connection.requestSessions(timeout_ns) !OwnedSessions`
  (`src/remote/connection.zig:1598`). The row type is at `:564` and carries
  `id, alive, exit_code, attached, activity, pid, cwd, argv, title,
  created_at, last_activity, pinned, relaunchable`.
- `Connection.closeSession(session_id, timeout_ns) !bool` (`:2114`), gated on
  `supportsCloseSession()` - an older agent returns `error.Unsupported`, which
  is a **disabled Kill**, not an error dialog. `closeSessionNoWait` (`:2143`)
  exists for the fire-and-forget case; Kill wants the confirmed one.
- The local agent connection is already warm and already used for exactly this
  RPC: `App.zig:1263` (`self.local_agent.sharedConnection()` then
  `conn.requestSessions`), and `:1517` has the warm-only variant
  (`sharedConnectionIfWarm`) for the restore probe.

So this is a **UI + threading task**, not a systems task - the same shape T295
had.

## Mac reference (cite lines when implementing)

- `SessionBrowserProbe.swift:8-79` - the row model. Port `label()`
  (`:68-75`) exactly: `liveTitle` -> agent `title` -> `persistedTitle` ->
  cwd basename -> argv -> `"pid <n>"`. The last fallback is deliberate and
  documented: an opaque session id *reads like* a pid and means nothing, so
  the real pid is shown instead.
- `SessionBrowserProbe.swift:56` - `isConnectable = alive || relaunchable`,
  the client-side backstop that hides unreconnectable dead tombstones (Mac
  commit `e5da5d02b`). **Read T322 before implementing this line**: the field
  is absent from the C API Mac decodes, so Mac's filter is currently
  `alive` alone, and Windows reads the Zig struct directly and *will* have the
  real value. Decide the divergence deliberately, do not inherit it silently.
- `SessionBrowserProbe.swift:150-230` - the probe's `State` machine
  (`loading` / `failed` / loaded), per-key expand/collapse, `count(for:)`,
  `markKilled`, `primeLocal` / `toggleLocal` / `fetchIfNeededLocal` /
  `refreshLocalInPlace`.
- `MachineChooserView.swift:608-730` - the row itself (activity + status
  badges, cwd/command sublines, Show/Resume + Kill, `exitedLabel` at `:726`).
- `MachineChooserView.swift:836-878` - confirm-then-Kill, and the
  "is this session open in one of our windows" lookup that makes Kill mean
  *end the session on the agent*, not *close the pane*.

## Threading rule (inherited from T295, non-negotiable)

The RPC blocks. It runs OFF the GUI thread and posts back; a reply that lands
after the row collapsed, the selection moved, or the dialog closed frees what
it fetched instead of adopting it. A failed or slow fetch resolves to a
`failed` state **on that row** - never a modal, never a blocked chooser
(`SessionBrowserProbe.swift:142-149` states the same rule for Mac).

### What it is on Windows

The roster lives in the **detail pane**, not behind an expander on the row -
which is what Mac does too. `MachineChooserView.swift:544` is
`detailSessions(target)`, rendered for the SELECTED machine; the machine list
has no per-row disclosure. So on Windows selecting the Local row IS the expand,
and the parent task's "the row expands" is the Mac shape restated, not a
different design. `T319` puts a remote machine's roster in the same region.

Three new pieces, split on the line the rest of the surface uses:

- `src/apprt/win32/chooser_sessions.zig` (new, pure): the label ladder, the
  connectable filter, the badge run, the card geometry, the scroll clamp and
  the tone->pixel color resolution. 16 unit tests in the none-runtime lane,
  including one that asserts every spacing number is on the 4 DIP scale and one
  that walks 1.0/1.25/1.5/2.0 checking nothing escapes the card and the text
  column clears the Kill button's PAINTED edge.
- `src/apprt/win32/SessionRoster.zig` (new): the RPC, the state, the painting
  and the hit testing. Kept out of `MachineChooser.zig`, which was already
  106 KB.
- `chooser_layout.sessions` - the region, taking the whole detail pane below
  the action row, sharing the header's margin exactly (asserted).

Plus `LocalAgent.dialProbe`, the free-function "dial the agent that is already
running, never spawn one" that the worker uses when the app has no warm
connection - Mac's `LocalAgentManager.dialExisting` rule, and the reason
browsing a roster cannot start a daemon.

### The two decisions worth recording

**`isConnectable` is `alive or relaunchable`, deliberately diverging from Mac's
current behavior.** T322 established that Mac's C API drops `relaunchable`, so
its filter collapses to `alive` and hides the resumable reboot-floor tombstones
the term was written to keep. Windows reads the Zig struct directly and has the
real value, so it does what both codebases' comments say the rule is.

**A pane's live session id comes from `core_surface.remoteSessionId()`, not
`Surface.remote_session_id`.** The latter is only set when a pane ATTACHES to a
restored session, so a freshly OPENed persistent pane has none - and the first
build badged every pane on screen `attached` ("someone else holds it") instead
of `open` ("you do"). Caught by looking at the thing (screenshot), not by a
test; the acceptance now scans for the green badge with the no-agent run as its
negative control. `captureLeaf` in `App.zig:1114` already used the right source.
