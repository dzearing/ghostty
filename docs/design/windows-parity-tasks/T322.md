# T322 - Mac seat: the C API drops relaunchable, so the chooser's dead-tombstone filter is dead code

Found 2026-08-01 while scoping the T146 split (T318-T321), by reading both
sides of the session-roster wire.

## The defect (VERIFIED by reading, both ends)

`BrowsedSession.isConnectable` is `alive || relaunchable`
(`macos/Sources/Features/Remote/SessionBrowserProbe.swift:56`), and its comment
says exactly what the second term is for: *"a relaunchable reboot-floor
tombstone (resumable via RELAUNCH)"* should stay listed, while a dead,
non-relaunchable tombstone is filtered out.

`relaunchable` never arrives.

- On the wire it exists: `protocol.zig:576` and `:718`
  (`SessionInfo.relaunchable`), round-tripped by the test at `:2094-2107`, and
  it reaches the client struct at `connection.zig:564`.
- The C API that Swift decodes **omits it**. `SessionJsonRow` in
  `src/apprt/embedded.zig:2820-2833` emits `id, alive, exit_code, attached,
  activity, pid, cwd, argv, title, created_at, last_activity, pinned` - twelve
  fields, no `relaunchable`.
- Swift decodes it with `?? false` (`SessionBrowserProbe.swift:49`), so the
  term is a constant. `isConnectable` collapses to `alive`.

Consequence: the Mac chooser hides every relaunchable reboot-floor tombstone -
the exact rows `wp4_e2e.zig:868-875` proves are legitimately resumable ("the
survivor came back as a resumable relaunchable tombstone"). The filter that was
written to keep them is what removes them.

`src/cli/sessions.zig:237-255` omits the field too, so `+sessions --json` has
the same hole; the CLI's human output at least prints nothing misleading.

## Why it blocks nothing but must be decided before T318

Windows reads `OwnedSessions` natively - `connection.zig:564` - so a win32
roster **will** have the real `relaunchable` and will show rows Mac hides.
That is a platform divergence created by an omission, not by a decision. T318
must not silently inherit either behavior; whichever way this lands, both
platforms should agree.

## Fix

Add `relaunchable` to `SessionJsonRow` (`embedded.zig`) and to
`src/cli/sessions.zig`'s JSON row. Both are additive - a new key that older
readers ignore - so the agent-contract rule in CLAUDE.md is satisfied without a
protocol version bump.

## Validation

- Unit: assert the serialized row contains `relaunchable` for a session with
  the flag set (the `+sessions --json` shape has a test lane already).
- Mac seat: a relaunchable tombstone appears in the Cmd-Shift-N roster and a
  dead non-relaunchable one does not - which is `isConnectable` finally doing
  what it says.
