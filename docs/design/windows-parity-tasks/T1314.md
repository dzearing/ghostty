# T1314 - ghoztty.com is a PE file with a .com extension, which is a heuristic trigger on its own

## In plain terms

The `ghoztty` command you type in PowerShell is really a file called
`ghoztty.com` that is a normal Windows program wearing an old-fashioned
extension. That mismatch is a decades-old signal antivirus tools watch for, and
it may be part of why Defender took against the download.

## Summary

T245 ships `ghoztty.com` beside `ghoztty.exe` for a good reason: Windows
resolves `.com` before `.exe` on `PATHEXT`, and the `.com` copy is built as a
console-subsystem binary, so `ghoztty +list` from PowerShell waits for output
and honours redirection instead of returning instantly like the GUI twin. It is
load-bearing, and the command line is worse without it.

It is also, in file-format terms, a PE32+ executable with an extension that
historically meant a flat 16-bit MS-DOS image. Scanners have watched for
extension/format mismatch for a very long time, and T1293 lists it as one of two
properties of this release that make it an ideal false-positive candidate (the
other being that it is unsigned). The user's report named `ghoztty.com` first.

**This is a hypothesis, not a finding.** Nothing has isolated which file drove
the verdict, and on this box neither file is detected at all. T1312 is the
experiment that could tell them apart, which is why this waits on it.

## What to do

1. From T1312's per-engine results, check whether `ghoztty.com` is flagged by
   engines that leave `ghoztty.exe` alone. If both are treated identically, the
   extension is not the driver and this closes as not-the-cause.
2. If it IS the driver, weigh shapes that keep T245's behaviour without the
   mismatch. Note that shrinking the twin does not help: a small
   console-subsystem launcher forwarding to the GUI binary would still be a
   `.com`. The alternatives worth comparing are ones that change what sits on
   `PATH`. T1077 already wants this 33 MB duplicate gone for size reasons, so
   the two tasks share a fix.
3. Whatever is chosen must keep the acceptance that already exists: bare
   `ghoztty` from PowerShell writes to a redirect and to a pipe, and the caller
   waits for it.

## Validation criteria

- [ ] The per-engine evidence says whether the `.com` twin is treated
      differently from the `.exe`, and this task records the answer.
- [ ] If the shape changes, `ghoztty +list` from PowerShell still writes its
      output to a redirect and to a pipe, on the existing harness.
- [ ] If the shape does not change, the reason is recorded here rather than the
      task being left open as a standing worry.
