# T1057 - Make the push non-optional: a turn cannot end with HEAD ahead of origin

## Summary

The rule already exists - go.md step 4 ("push immediately after each commit... an
unpushed commit is invisible to the other seat") - and `git-commit-guard.ps1`
can do it. But `-Push` is an opt-in switch (`scripts/git-commit-guard.ps1:79`,
`:346`), and a plain `git commit` bypasses the guard entirely. So the rule is
honour-system, and the user has now had to state it twice (2026-08-07, and again
2026-08-21). Close it mechanically instead.

## In plain terms

Work that is committed but still sitting on this machine may as well not exist.
The other seat cannot see it, a dead box loses it, and the branch that is
supposed to be the shared record of what has been built is quietly behind what
was actually built. We already agreed to push every time. It should not be
possible to forget.

## Goals

- [ ] `-Push` is the default in `git-commit-guard.ps1`; opting OUT is the
      explicit flag, and it says why on the way past.
- [ ] Something checks, at the turn boundary, that `HEAD` is not ahead of its
      upstream - and says so loudly enough that the loop cannot narrate a
      finished task over an unpushed commit.
- [ ] A rejected push is handled, not just reported: pull/rebase and push, per
      go.md step 4, with the failure surfaced if that does not resolve it.

## Validation criteria

- [ ] With a local commit and no push, the guard reports the unpushed state and
      fails; after a push it is clean. Both directions demonstrated on the box.
- [ ] `git-commit-guard.ps1 commit` (no flags) pushes; the opt-out path is
      covered by a test and prints its reason.
- [ ] A teeth-check proves the new check can go red - a planted unpushed commit
      is caught, not waved through.
- [ ] Floor lanes green.
