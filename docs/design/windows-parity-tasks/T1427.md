# T1427 - A pending revocation only completes if the APP is launched again - the agent keeps the machine online meanwhile

## Summary

T1424 arms a pending revocation and retries it from the app: at launch and on a backoff while the app runs. The agent is not in that loop, and it is the process that actually keeps this machine online - it holds the same relay.env credential and keeps its control link up. So between a Sign Out Anyway and the next time the user opens Ghoztty, the machine is still listed and still reachable, and if they never open it again (they signed out because they are done with this box) it stays that way forever. The agent should complete an armed revocation itself - it is already long-lived, already reads the same directory, and already knows when the relay came back, which is the signal the app has to approximate with a backoff. Watch the ordering: whichever side wins must clear the record and the credential exactly once, and a 401 must stay as narrow as it is in relay_revoke_pending.nextAfter.
