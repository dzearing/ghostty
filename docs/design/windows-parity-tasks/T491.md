# T491 - Mac acceptance runs have the same build-mode endpoint trap as Windows, with no guard

## Summary

Symmetry half of T350. On macOS the IPC socket is \/ghostty[-debug]-<uid>.sock and the local agent's socket is ~/.config/ghoztty/local-agent[-debug]/agent.sock - both derived from build_config.is_debug, exactly as on Windows. So a Mac test run against a non-debug build talks to the socket the user's installed Ghoztty.app owns, opens windows in their terminal, and passes. Windows now refuses that before launching anything (test/win32/lib/BuildMode.ps1, acceptance test/win32/build-mode-guard.ps1, reading the 'build mode' line +version already prints). The Mac seat needs the same pre-flight in whatever its scripts share, plus the note next to the build incantation. Mac seat because only it can validate the Swift-side harness.
