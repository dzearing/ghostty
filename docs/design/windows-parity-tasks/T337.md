# T337 - Layout blobs are lineage-shaped: a Mac viewer cannot decode a win32 blob and vice versa

Filed out of the **T321 split (2026-08-02)**. Not a blocker for T334/T335/T336
(each machine restores itself, and Windows-to-Windows works end to end), but it
is a real hole in the cross-machine story and it should be decided rather than
discovered.

## The gap

`GET_LAYOUTS` blobs are **opaque to the agent by design** (`layout_meta.zig:9`:
"the agent is DELIBERATELY topology-agnostic"), which means the SCHEMA is a
contract between two VIEWERS - and the two viewers do not share one:

- Mac pushes a `SessionLayoutManifest.Entry` JSON
  (`SessionBrowserProbe.swift:109-135`, camelCase, `sessionID`).
- win32 will push a `session_layout.Window` JSON (T334) - snake_case,
  `session_id`, a FLAT `nodes` array with `left`/`right` indices where Mac
  nests. `session_layout.zig:29-33` already states the assumption that made
  this fine: the file "is never decoded by the macOS app", so "there is no
  cross-lineage key-compatibility constraint".

That assumption holds for the LOCAL restore file it was written about. It does
NOT hold for a blob pushed to an agent that a viewer on the other lineage can
pull. Restore All on a Mac pointed at a Windows machine gets N blobs it cannot
parse; the failure mode is the good one (`compactMap { $0.entry }` drops them,
so it shows "nothing to restore" rather than crashing) but the feature is
silently absent.

## What to decide

Three options, in rough order of preference:

1. **A blob envelope**: `{"lineage":"win32"|"macos","version":1,"body":{...}}`,
   each side decoding its own and ignoring the other's - honest, additive, and
   it makes the gap visible in the data instead of in a bug report. Costs a
   read-side tolerance bump on both sides (an old peer sees an unknown shape,
   which is exactly today's behavior).
2. **One shared schema** both viewers write - the most correct, the most work,
   and it has to survive the app<->agent compatibility rules in CLAUDE.md (an
   old Mac viewer's blobs stay in a live agent across an upgrade).
3. **Document the limit** and stop: cross-machine Restore All works within a
   lineage only. Cheapest, but it leaves a feature that looks present and is
   not.

Whichever is chosen, `layout_meta.zig`'s header should say what the blob's
schema contract actually is, since it is the file that calls it opaque.

## Validation

- Whatever the decision, a unit test that a blob of the OTHER lineage's shape is
  skipped without error (the failure that must stay non-fatal).
- If option 1 or 2: a round-trip test over the envelope/shared schema, and a
  note in `docs/design/session-persistence.md` §5.4.
