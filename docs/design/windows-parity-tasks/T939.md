# T939 - The release-artifacts guard can never be satisfied on this box, so every turn has to excuse it

## Summary

Measured 2026-08-17 (T837's turn). `go-loop-exec.ps1 claim` reported
`GUARD DUE release-artifacts` over four files nobody on this turn had touched.
The harness was run as instructed and finished `ALL PASS (2 skipped)` — but the
two skips are `B1 FILEVERSION single source` and `B2 portable ZIP layout`, both
gated on `Docker is not running`, and a run with skipped sections deliberately
does not stamp. So `guard-due.ps1 check -Guard release-artifacts` still exits 1
after a clean green run, and step 6's `validate` still fails.

On this box that is permanent, not transient: starting Docker here is
explicitly off-limits (the WSL2 backend has buried the machine at 28 GB of
RAM), so those two sections can never run and this guard can never re-stamp.
The only exit is `validate -NoGuardDue` on every turn — which is exactly the
habit the hatch was not supposed to create, since a turn in the habit of
excusing a guard will excuse the next one that is genuinely stale.

## In plain terms

The safety check that asks "has anyone tested this since it changed?" is stuck
permanently on "no" for one area, because part of that test needs a tool we
refuse to start on this machine. Every session now has to override the check to
get any work committed, and an override that gets used every time stops being a
signal.

## Details

Three candidate shapes, in rough order of preference:

1. **Stamp what actually ran.** The stamp records which sections ran; a section
   skipped for a NAMED environmental reason (Docker down) does not block the
   stamp, but the stamp carries the skip so `check` can report
   `CURRENT (2 sections never run here)` rather than silently claiming full
   coverage. The gate keeps its teeth for a code change and stops lying about
   an environment gap.
2. **Split the row.** The Docker-gated sections become their own guard row
   covering only the files they exercise; what this box CAN prove re-stamps
   normally.
3. **De-Docker B1/B2.** They read a FILEVERSION and a ZIP entry list — if that
   is reachable without a container image, the gate needs no special case.

Whichever lands, the acceptance is the same: a clean run on this box, with
Docker down, leaves `guard-due.ps1 check` exiting 0.

## Validation criteria

- [ ] With Docker NOT running, `test\win32\release-artifacts.ps1` finishes
      green and `guard-due.ps1 check -Guard release-artifacts` exits 0
- [ ] What was not proven here is still visible — a stamped-with-skips row says
      so in `check`/`list` output rather than reading as full coverage
- [ ] A real edit to a covered file still makes the row DUE again
