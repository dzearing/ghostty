# T288 - Hoist containsIgnoreCase: MachineChooser and activity_rows keep private twins of the same ASCII case-fold search

## Summary

Two filter surfaces now carry their own copy of the same ASCII case-insensitive
substring search:

- `MachineChooser.zig:175` `containsIgnoreCase` (T172, filters machines)
- `activity_rows.zig` `containsIgnoreCase` (T285, filters processes)

Filed from T285 rather than fixed there, so a cross-module rename did not ride
along with a brand-new panel. But the T257 lesson applies verbatim: *copies mean
copies of the chance to be wrong, and no way to notice.* Both of these are
ASCII-only on purpose (they fold with `std.ascii.toLower`), which is a decision
that deserves ONE place to live and one place to revisit — a user filtering a
process list for `Ð` or `İ` gets nothing from either today.

## Scope

One small module (`src/apprt/win32/text_search.zig`, or fold it into an existing
pure module if a better home exists), both call sites switched to it, both
private copies deleted. Move the tests along with it.

While there, decide and record whether the fold stays ASCII: the substring
search is used against process names and machine names, which are not
necessarily ASCII on either platform.

## In plain terms

Two search boxes in the app — the one that filters machines, and the one that
filters running processes — each had their own private copy of "does this text
contain what was typed, ignoring capitals". Nothing was broken, but two copies
means a fix or a change to one silently misses the other. They now share a
single one. Nobody sees a difference today; what changed is that the next
change to how searching works only has to be made once.

While merging them the same question had to be answered for both: which
alphabet does "ignoring capitals" cover? Ours covers English letters only, and
the Mac's covers every language — so a machine or program with an accented or
non-Latin name can be searched for on the Mac and not here. That is now written
down in one place, filed as T790, and the approach is D71 for the user to pick.
