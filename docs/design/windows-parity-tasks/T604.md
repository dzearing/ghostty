# T604 - src/cli/send_keys.zig has diverged from main: main rewrote prompt submission while this branch built bracketed-paste framing

## In plain terms

Both seats independently fixed the same problem - an agent's prompt arriving in
a pane but never actually submitting - and both rewrote the same file to do it.
Whichever way that gets merged, one of the two fixes could be lost silently, and
the symptom (a prompt sitting unsent in a composer) is the exact failure that
kills the automation loop. This reconciles them into one implementation before
the merge, rather than during it.

## Summary

Upstream: `a7f7476e1` "feat(send-keys): make submitting a prompt unambiguous"
(merged `9c74bdbbb`) - 471 changed lines in `src/cli/send_keys.zig`, 18 in
`CLAUDE.md`, plus the bundled skill doc.

This branch's side: the bracketed-paste run framing documented in `CLAUDE.md`
("Text and keys stay distinguishable"), the single-write frame rule, and the
`Get-LoopSubmitArgs` trailing-space convention from T438.

Do this as a real reconciliation, not a `git checkout --theirs`:

1. Read both implementations and write down what each actually guarantees.
2. Decide one design that keeps every guarantee both sides established.
3. Land it here with tests for both sets of behaviors, and record it so the Mac
   seat can take the same file (file a `seat: mac` follow-up if the Mac needs a
   companion change).
