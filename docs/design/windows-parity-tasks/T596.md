# T596 - T400's end-to-end debounce assertion compares two cache-dependent fetch counts, so the host-floor test flakes red

## In plain terms

One of the automated checks fails at random — roughly every other full test
run — even when nothing is wrong. It is not testing what it thinks it is: it
compares how many times a page was fetched against a number it measured
earlier, and both numbers depend on whether the browser happened to have the
page cached at that moment. A test that cries wolf is worse than no test,
because the next real failure gets waved through as "that one again".

## Summary

`ViewerPane.zig`'s "host floor" test ends its T400 section with an end-to-end
companion assertion:

```zig
const nav_cost = reload_page.requests.load(.acquire) - t400_base;   // ~:3963
...
const after_nav = reload_page.requests.load(.acquire) - before_nav; // ~:4010
try testing.expectEqual(nav_cost, after_nav);                       // ~:4015
```

Both sides count HTTP fetches the test server saw for a REPEAT navigation to
the same URL, so both depend on whether WebView2's HTTP cache served that
navigation. They are measured at different points with different cache warmth,
and nothing makes them agree.

**Evidence — one `floor-lane.ps1 -Lane all` run, 2026-08-08, identical source:**

| lane | log line | result |
|---|---|---|
| win32 (03:44) | `a repeat navigation costs 0 fetch(es)` / `window cost 0, expected 0` | PASS |
| agent (03:49) | (nav_cost 1) / `window cost 0 fetch(es), expected 1` | **FAIL** |

Five minutes apart, same binary logic. The failure is non-deterministic by
construction, so it cannot be a code regression — it is the assertion.

## Details

The comment directly above the assertion already records why counting fetches
is the weak oracle here ("a stale timer that fires while the destination is
STILL LOADING hits `reloadPlan`'s `full_load` branch, not `refetch` … the
mutation is invisible at the server in both cache states"). The line above it —
`expectEqual(0, KillTimer(...))`, the timer oracle — is the assertion that
actually proves T400's fix and is fully deterministic. The fetch-count
companion adds the user-visible framing but pays for it with a coin flip.

Options, for whoever takes this:

1. **Make the baseline deterministic.** Warm the cache before measuring
   `nav_cost` (navigate to `reload_url` and settle once more, discarding the
   count) so both measurements are taken in the same cache state.
2. **Assert the bound instead of the equality.** The claim is "the page they
   opened is loaded once, not twice" — `after_nav <= nav_cost` (or
   `after_nav <= 1`) states that without depending on which side the cache
   fell on.
3. **Drop the companion.** The timer oracle above it already turns red when
   the bug is restored, which the comment says explicitly.

Whichever is chosen, keep the log line: it is what made this diagnosable.
