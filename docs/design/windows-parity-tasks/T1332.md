# T1332 - Nothing checks that the agent lane runs the tests it compiles (test-reach, for src/remote)

## In plain terms

The Windows chrome has a check that catches a unit-test file nobody runs
(T1191's `test-reach-audit.ps1`). The agent and remote code has no such check,
and its absence already cost us: the shared test-wait helpers in
`src/remote/test_util.zig` had four of their own tests that executed in NO
build lane at all. They compiled, they read as covered, and a deliberately
broken assertion inside one of them went green through the entire agent lane.

When this lands, a test file added under `src/remote/` either runs somewhere or
the lane says so out loud.

## Goals

- [ ] An audit names every `src/remote/**.zig` with a `test` block whose tests the agent test binary does not run
- [ ] A negative control proves the audit goes red when a file is dropped from the reference list

## Summary

Zig runs a file's tests only when the file's CONTAINER is referenced from an
analyzed one. Re-exporting decls (`pub const waitUntil = shared.waitUntil;`)
references the decls, not the container - so `src/remote/test_util.zig`'s `test`
blocks were skipped in silence. T436 fixed that one instance by adding
`_ = @import("../test_util.zig");` to the agent test root's reference list in
`src/remote/agent/main.zig`, but nothing stops the next one.

The win32 answer already exists and is the model: build the lane, read the
compiled test binary's string table, and compare it against the set of files
that contain `test` blocks. `test/win32/lib/TestReachAudit.ps1` explains why
the oracle has to be the binary rather than a PowerShell model of Zig's
reachability rules.

## Where

- `test/win32/test-reach-audit.ps1` + `test/win32/lib/TestReachAudit.ps1` - the existing win32 audit to generalize
- `src/remote/agent/main.zig` - the agent test root's reference list

## Validation criteria

- [ ] The audit reports an empty missing-set over today's tree.
- [ ] Teeth check: drop one known-good entry from the reference list, rebuild, and require the audit to go red naming that file.
