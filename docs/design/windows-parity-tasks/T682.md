# T682 - a focused viewer still cannot reach reset_window_size or the tab-overview chord

## Summary

T126 found toggle_hero_mode missing from viewer_accel.forwards() and added it; the same sweep shows two more window-scoped actions win32 IMPLEMENTS that a focused viewer pane cannot reach, because the chord is not in the forwarded set and WebView2 keeps it: reset_window_size and toggle_tab_overview (both have App.zig arms). The rule the list is meant to encode is 'window- or app-scoped, and meaningful with no terminal underneath', and both qualify - a viewer-only window has no terminal to press them from at all. Wanted: add them to forwards(), give each an arm in Window.performViewerBindingAction (the else arm logs a drift warning today, which is how this class of gap stays quiet), and extend the unit test in viewer_accel.zig so the list and the switch are asserted together. Not in scope for T126: neither is hero navigation, and shipping them under a hero-mode task would hide them.
