# T1306 - The viewer handler drift scan reads only ViewerView.swift, so a handler registered from another Mac file escapes it

## Summary

T385's detector embeds macos/Sources/Features/Viewer/ViewerView.swift and asserts the viewer registers exactly one message handler. The viewer's WKWebViewConfiguration is built in that one file today, so the scan sees every registration - but if Mac moves or splits that construction, the scan keeps passing while seeing nothing. Widen it (scan every Swift file under macos/Sources/Features/Viewer/, or assert the configuration is still built where the scan looks) so a file move cannot silently disarm the detector.
