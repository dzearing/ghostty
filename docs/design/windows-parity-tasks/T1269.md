# T1269 - update-real-msi flakes when the staged package does not appear inside its 120s poll

# Summary

Section C of `test\win32\update-real-msi.ps1` starts the installed throwaway
1.35.0 product, points it at a canned `file://` feed, and polls the staging
directory for a `*.msi` once a second for 120 seconds. When nothing shows up it
fails with "the app downloaded and staged a package into …", sections D and E
skip, and the run is red.

It went red exactly that way on 2026-09-01 during T1243's guard sweep and then
passed 30/30 on an immediate re-run with no change in between. The suspect is
the same one the script's own comment names for the recheck knob — a box busy
with the rest of a floor run — but the failure says nothing about what the app
actually did, because a released build is GUI-subsystem and its log is not
captured here.

## In plain terms

A test that proves an update really installs sometimes reports failure when the
machine is merely busy. Someone then has to re-run it to find out whether
anything is actually wrong, which is the one thing a test is supposed to answer.

## Goals

- [ ] A slow box no longer reads as "the app never staged the package"
- [ ] When section C does fail, the message says what the app was doing
- [ ] The flake is reproducible on demand, so the fix can be shown to work

## Details

Two halves, and the second is the one that matters:

- **Capture the app's side.** Redirect the launched product's stderr to a file
  the way the other update harnesses do, and print its tail on a section C
  failure. Then a red run distinguishes "the check never fired", "the download
  failed" and "it staged after the deadline".
- **Make the deadline honest.** Poll against the app's own progress rather than
  a flat 120s: fail early once the log says the download failed, and keep
  waiting while it is still moving.

## Validation criteria

- [ ] Under synthetic load, section C either passes or fails with the app's own log attached
- [ ] A download that genuinely fails is reported as a failure without waiting out the full poll
- [ ] `test\win32\update-real-msi.ps1` passes twice in a row on an otherwise busy box
