# T505 - Task dashboard: activity summary cards with hover state opening an L2 details page

## Summary

User request (2026-08-05, verbatim): "the activity should have summary cards.
the cards should have a hover state to open an l2 details page on them."

Today the Activity view's timeline (`activityView`,
`scripts/task-dashboard.page.html:981`) renders each event as a flat `ev` row
(rail + dot + title/meta/summary/chips), not a card. There is already an L2
surface — `openTask` opens the task dialog — but it is reachable only from the
task chips and from the headline (and only when the event finished or filed a
task), and the event itself has no details page of its own: an event's full
story (commit, duration, summary, every task touched, tags) has no L2.

## Details

Interpretation (recorded as the working assumption — overturn via a decision if
wrong):

- **Summary cards**: each timeline event renders as a card in the dashboard's
  existing card language (same corners/spacing as `decisionCard` /
  `blockedCard`), replacing the bare `ev` rows — headline, time/duration/sha
  meta, one-line summary, task/tag chips.
- **Hover state**: the whole card gets a visible hover treatment (background
  shift + cursor) signalling it is clickable — today only the title underlines.
- **L2 details page**: clicking anywhere on the card (Enter with focus, too)
  opens an event-level L2 — the full commit message/summary, links to every
  completed/filed task (each still opening the existing task L2), tags,
  duration, sha. Follow the existing `openTask` dialog pattern; keep hash/state
  handling consistent with it so back/close behaves the same.
- Task chips inside a card keep their current behavior (stopPropagation +
  `openTask`).

All of this is dashboard page code (`scripts/task-dashboard.page.html` +
`scripts/task-dashboard.js` payload if the L2 needs fields not yet emitted,
e.g. the full commit body). No app/zig changes.

## In plain terms

The Activity view used to show each day's work as flat list rows: you could
see a headline, but the full story of a change — what the commit actually
said, everything it finished and filed — had no page of its own. Now every
event is a card that visibly lights up under the mouse, and clicking it opens
a details view with the whole commit message and links to every task it
touched. Anyone skimming the dashboard can drill into any landing without
opening the repo.

## Validation criteria

- [x] Activity timeline events render as summary cards with the shared card
      styling (visually consistent with decision/blocked cards). — headless-Edge
      screenshots at side-pane width, dark + light themes.
- [x] Hovering a card shows a clear hover state on the whole card. — `.ev` gets
      `cursor: pointer` + `:hover` background/border shift (same tint language
      as `.opt:hover`); asserted by `test\win32\task-dashboard.ps1` A3.
- [x] Clicking a card (and Enter with keyboard focus) opens an L2 details page
      for that event; closing it returns to the Activity view with scroll
      preserved. — real-browser click path driven by `?selftest=event` under
      headless Edge (section E of the harness): click opens the dialog, the
      commit message loads, close removes it; the dialog is a modal overlay, so
      the view underneath never scrolls. Enter/Space share the same handler
      (harness A4).
- [x] Task chips still open the task L2 without also triggering the event L2.
      — chips keep their pre-existing stopPropagation + openTask handler; the
      card handler is on the card element itself.
- [x] Events with no linked task still open their event L2 (no dead cards). —
      every card's click handler is unconditional; decision events (no sha, no
      chips) show their summary and decision link instead of a commit fetch.
