# T1122 - 26 of 237 launch paths leave session persistence unstated

## In plain terms

Every way of opening a terminal should say plainly whether that terminal is meant to survive being closed. Twenty-six of them say nothing either way, which means their behaviour is whatever the default happens to be rather than a decision anyone made.

## Summary

`test\win32\persistence-flag.ps1` scored `1 FAILURE(S) (19 passed)` in the T1094 sweep:

```
FAIL  A1 no launch leaves persistence unstated (undeclared: 26 of 237)
```

This is an audit assertion, so the number is the finding: 26 of 237 launch paths do not declare persistence. It is not a crash or a regression - it is a gap that has presumably been growing as launch paths were added, since nothing forced each new one to declare.

The user-facing stake: whether a pane's session survives closing the window should be a property someone chose, not a default that varies by which code path opened it.

19 assertions pass, so the mechanism works where it is declared.
