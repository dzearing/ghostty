# T860 - The agent lane intermittently fails benchmark.OscParser.decltest.OscParser with a leak through an async WebView2 popup callback - build-runner mode only, ~13 percent under load

## Summary

Caught red-handed by the 2026-08-15 T443 active-window probe: 2 of 15 loaded build-runner agent-lane runs failed the same way (soak label boost-on-baseline, logs in %TEMP%\ghoztty-soak and %TEMP%\floor-lane-agent-20260815-130157-606.log / -131348-619.log). Shape, identical both times: test 'benchmark.OscParser.decltest.OscParser' fails, stderr carries '[terminal_apc] (warn): kitty graphics protocol error: error.InvalidFormat', and the run reports 1 leaked with the trace ViewerPane.ensureNav <- ViewerPane.start <- testPopupOpen <- adoptPopup <- onNewWindowRequested <- comInvoke2 <- EmbeddedBrowserWebView.dll. That trace is an ASYNC WebView2 COM callback from a ViewerPane popup test landing while a LATER test is running and allocating with the current test's std.testing allocator - cross-test contamination, with OscParser as the bystander victim. Consistent with that: the failing seed replays clean standalone (ghoztty-agent-core-test.exe --seed=0xa9d599b3 direct = exit 0, all pass), so the failure needs mainServer()'s one-test-per-pipe-message timing, the same build-runner-only signature T832 measured for T443. Fix direction: make the ViewerPane popup test (testPopupOpen / adoptPopup path) drain or cancel its WebView2 async callbacks before the test returns, so nothing fires into a later test's allocator; then soak the agent lane in build-runner mode to confirm the rate drops to 0. This is the same defect T776 could not read the text of - it now has a face.
