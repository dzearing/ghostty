# T435 - macOS floor lanes have no wedge detector - the Mac half of T430

## In plain terms

On Windows the automated check suites now always finish — if one freezes, a
watcher notices, explains what it was stuck on, and stops it. The Mac side has
no such watcher. Nobody has reported a frozen run there, so this is a question
to answer rather than a bug to fix: does the Mac seat want the same safety net?

## Goals

- [ ] A decision, recorded: build the Mac equivalent, or state why it is not
      needed
- [ ] If built: `PASS` / `FAIL` / `STALL` with a diagnostic, same contract

## Summary

T430 gave the three Windows zig lanes `scripts\floor-lane.ps1`: a wrapper that
watches CPU as well as the clock, so a lane that is *blocked* (zero CPU delta,
no new output) is reported as `STALL` with a diagnostic instead of hanging
indefinitely with nothing to read. Filed per the standing "land both, or file
the other half" rule.

Two reasons it may not need a Mac twin, both of which the Mac seat is better
placed to judge than this one:

- The **root cause fixed alongside it was Windows-specific**: `closesocket`
  does not signal a blocking `accept()` pending in another thread, so
  close-then-`join()` hangs. On macOS closing the listener does wake the accept,
  so `ViewerPane.zig`'s two loopback test servers could not have hung there —
  and those files are win32-only anyway.
- No macOS lane hang has been reported.

What might still argue for it: the watchdog is a *general* safety net, not a fix
for one bug, and the agent lane's own wedge (T434) has no established cause yet
and runs the same agent sources on both platforms.

## Validation

If built: the equivalent of `-SelfTest` — the three verdicts proven on synthetic
commands (`exit 0`, a nonzero exit, and a command that blocks forever on a
signal that never arrives).
