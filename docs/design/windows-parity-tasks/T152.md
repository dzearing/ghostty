# T152 — parity sweep evidence (2026-07-29)

## In plain terms

Every so often the Mac side of this project ships something the Windows side
never hears about, and nobody notices until the user does. The checks we ran
before were written as summaries — "this merge brought the viewer work" — and
a summary can't be checked for holes. This adds a command that reads the list
of Mac changes for a stretch of history and prints exactly which ones nothing
on the Windows side has ever mentioned. If that list isn't empty, the check
fails, so the gap has to be written down as work before the day moves on.
What changes for a user: fewer Mac features that quietly never arrive here.

## Goals

- [x] A checked-in script enumerates every Mac-side commit in a range and
      reports which have no reference anywhere in the Windows parity docs.
      (`scripts\parity-sweep.ps1`)
- [x] It exits non-zero when anything is unmapped, so it can be used as a gate.
- [x] It emits a pasteable `## Parity coverage` block, so the enumeration is
      evidence rather than prose. (`-Format markdown`)
- [x] The daily main-intake step in `go.md` runs it, so it is wired in rather
      than merely available. (go.md step 0.6, "Gate the intake on the sweep")
- [x] It has an acceptance test with a deterministic oracle.
      (`test\win32\parity-sweep.ps1`)

## Validation criteria

- [x] Running the sweep over a known-clean historical range reports 0 unmapped
      and exits 0. Verified on `cda6e5191..4a41394b2` once its 7 findings were
      dispositioned: `commits: 54  mapped: 54  unmapped: 0`, `SWEEP CLEAN`,
      exit 0.
- [x] Running it against a fixture docs tree that references only some of the
      commits reports exactly the remainder as unmapped and exits 1. Arms
      2a-2d of `test\win32\parity-sweep.ps1`, which assert the unmapped list is
      exactly the un-referenced three - both that the three are present and
      that the referenced three are absent.
- [x] The `markdown` format emits a `## Parity coverage` block with the
      commit/subject/filed-as table. Arms 6a-6e.
- [x] `test\win32\parity-sweep.ps1` prints `ALL PASS` (20/20 arms).
- [x] The gate has teeth, not just a green run: breaking the sweep's sha-prefix
      re-check turned arms 4a/4b red (`mapped: 6  unmapped: 0`) and nothing
      else moved; restored, all 20 pass again.
- [x] The standing floor stays green: `scripts\floor-lane.ps1 -Lane all` ->
      `FLOOR SUMMARY: none#1=PASS win32#1=PASS agent#1=PASS / ALL LANES PASS`,
      and P1/P2/P3 each `ALL PASS` (run after the lanes, never overlapped).

## Outcome

Landed as `scripts\parity-sweep.ps1`, gated into go.md step 0.6, with the
evidence trail in `docs/design/windows-parity-sweeps.md`.

**The first real run proved the leak was still live.** Sweeping the 2026-08-08
intake range found 7 of its 54 commits uncited. None was a missing feature -
all six substantive ones are later content of T598 (the banner hook's state
mutex and untrusted-field escaping, the de-attributed `process-feedback`
skill, the load-bearing `TERM_PROGRAM=ghostty` spelling), and the seventh is a
macOS-only XCTest deadline with no parity owed. Uncited, the six would have
been invisible when T598 is picked up and T598 would have vendored the
pre-hardening copies. They are now dispositioned in the sweeps ledger and
named in T598 with what each requires; the range sweeps clean.

That is the same failure mode as `538f4fd64` in this task's own table -
*"behavior covered, commit was uncited"* - which is the argument for keying
the gate on shas rather than on whether someone believes the area is covered.

## Summary

**Make the parity sweep systematic — the per-merge sweeps have been leaking.** Filed 2026-07-29 after the user found three gaps by hand (viewer panes, the menu bar, the banner table width) and a full re-audit then found **16 Mac commits from the last 3 weeks with ZERO references in ANY Windows doc** (T145–T151 above). The T88 and T117 sweeps were narrative summaries, not enumerations, so a commit could be merged and never mapped to a row. Fix the PROCESS: a checked-in script that, for a given merge range, lists every commit touching `macos/` or `src/viewer/` and reports which have no task-id reference in `docs/design/windows-parity-*.md`; run it as a gate at every `origin/main` merge (T88/T117 pattern) and file a row for every unmapped commit before the merge task can be marked done. Also add a `Parity coverage` note to the merge task template so the enumeration is evidence, not prose
