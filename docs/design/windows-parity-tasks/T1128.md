# T1128 - hero-mode.ps1 overwrites a tracked screenshot artifact on every run, and the new one looks blank

## In plain terms

One of the automated checks takes a photo of a window and saves it into the
project as a reference image. It overwrites that image every single time it
runs, so the project always looks like it has unsaved changes after a test run.
Worse, the new photo is a third the size of the old one - which is what happens
when a photo is mostly one flat colour - and the check still reports success.

## Summary

Found during T1094's full suite sweep. `test\win32\hero-mode.ps1` scored
**`pass` in 36.3 s**, and left this behind:

```
 M test/win32/artifacts/hero-mode-t59b.png
   Bin 133921 -> 41165 bytes
```

The file is TRACKED (not gitignored - `git check-ignore` says nothing), last
changed deliberately in `4312d369b` ("The main-window chrome tests now
photograph a window that poses for the camera", T941). The write is
unconditional:

```
test\win32\hero-mode.ps1:780:
    Save-WindowShot $top (Join-Path $artifacts 'hero-mode-t59b.png')
```

Two separate defects, and the second is why this is P1 rather than tidy-up.

**1. A test mutates tracked state.** Every suite run leaves the working tree
dirty. The go-loop treats a dirty tree at claim time as STRANDED WORK from a
dead turn and fails `validate` on it, so a routine test run now manufactures a
false stranded-work report for the NEXT turn. It also means an artifact could
be committed by accident, replacing a deliberate reference with whatever the
last run happened to capture.

**2. The replacement is 31% of the original's size, and nothing checked.**
133921 -> 41165 bytes on a PNG of the same dimensions is a large drop in visual
content - which is exactly what a near-uniform image compresses to. That is the
same signature `caption-bar.ps1` reports outright (`the capture is UNIFORM`) and
`test-desktop-spike.ps1` measures directly (`PrintWindow(PW_RENDERFULLCONTENT)
returns real content` FAILS) - see [[T1100]].

So this script is very likely photographing a blank window, saving it over the
good reference, and passing. A green verdict over a blank picture is worse than
a red one, because it actively destroys the evidence that would have shown the
problem.

## Reproduced alone

Not applicable, and recorded so the answer is not merely missing (T1137):
`hero-mode.ps1` PASSED the sweep. What this task is about is what the script
writes over while passing, which a re-run cannot discriminate - the artifact is
rewritten on every run, green or red.

## Where

- `test/win32/hero-mode.ps1` line 780 - the unconditional `Save-WindowShot`
- `test/win32/artifacts/hero-mode-t59b.png` - the tracked artifact
- `test/win32/lib/` - `Save-WindowShot` and the capture path behind it

## Goals

- [ ] Compare the committed artifact against a freshly captured one and confirm
      whether the new capture is blank. That is the finding; do it first.
- [ ] Stop the script writing into tracked paths on an ordinary run - write
      captures to the run's own temp/output directory, and update the tracked
      reference only under an explicit `-UpdateBaseline`-style switch.
- [ ] If the artifact is a REFERENCE the script compares against, make it
      actually compare - a saved-and-never-read reference is not doing anything.
      If it is only a debugging aid, it does not belong in git.
- [ ] Add the blankness check the size drop would have caught: a capture whose
      distinct-colour count or entropy is below a floor fails, rather than being
      saved.
- [ ] Sweep the other scripts for the same shape - any `Save-*` into
      `test/win32/artifacts/` on a normal run.
- [ ] Restore the committed artifact once the capture is trustworthy again.

## Validation criteria

- [ ] whether the new capture is blank is recorded here, with the measurement
- [ ] a full `scripts\suite-run.ps1` pass leaves `git status` clean
- [ ] no acceptance script writes into a tracked path without an explicit
      baseline-update flag
- [ ] a blank or near-uniform capture FAILS rather than being saved over the
      reference
- [ ] `test\win32\hero-mode.ps1` is ALL PASS and its artifact is intact
