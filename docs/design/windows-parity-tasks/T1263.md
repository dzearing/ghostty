# T1263 - Something is still writing backslash escapes into task files as control characters - find the writer

## Summary

T1231 repaired fifteen files and added a commit-time guard, but not the SOURCE. Two of the fifteen (T1251, T1252) were filed AFTER T1231 was written and had picked up the same damage, so whatever writes it was still active. The signature is a Windows path written with a backslash escape that some tool interpreted on the way in: 0x07 for a, 0x08 for b, 0x0c for f. The guard now refuses such a commit, so the next occurrence is loud rather than silent - the work here is to catch one, identify the writing path (a printf or echo -e in a shell helper is the likeliest shape, since PowerShell does not interpret those escapes), and fix it there.
