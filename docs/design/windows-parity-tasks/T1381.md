# T1381 - The REMOTE Activity Monitor panel never asserts that Kill leaves and re-enters its Tab cycle

## Summary

Found while doing T570. `test/win32/activity-monitor-remote.ps1` section F4
*relies* on Kill being out of the Tab cycle — its comment says "Tab back round
to the carousel first (Kill is out of the cycle with nothing selected)" and its
Tab count is chosen accordingly — but it never ASSERTS it. So the one arm that
depends on the rule would fail with a misleading message ("F4 Tab walks back
round to the carousel") if Kill ever started appearing in the remote panel's
cycle unselected, and the rule's other half (a selection puts Kill BACK in)
is not exercised on the remote panel at all.

The local script covers both halves (section L2 for the skip, L5 for the
re-entry), and the panel is one implementation, so this is confirmation rather
than a first look — hence P3. But the remote panel has an extra focus stop the
local one does not (the machine carousel), which is exactly the thing that makes
a cycle-position claim worth re-asserting where the cycle is different.

Safe to do without touching a live process: SELECTING a row is not killing one.
The arm is (a) assert Kill is not a stop with an empty selection, (b) select a
row with Down from the table, (c) assert Kill is now a stop, (d) Tab past it
without pressing it, and leave the machine's processes alone. D29's resolution
stands — nothing here presses Kill on a sampled machine; T570 asserts Kill's key
path on the LOCAL panel, where the victim is one the test spawned.

## In plain terms

The Activity Monitor hides its Kill button until you pick a process, and the
keyboard skips over it while it is hidden. When the panel is showing another
machine, nothing checks that. One test already leans on the behaviour without
checking it, so if it broke, the failure would point at the wrong thing.

## Validation criteria

- [ ] With nothing selected on the remote panel, Kill is not a Tab stop, asserted
      directly rather than implied by a Tab count
- [ ] Selecting a row from the keyboard puts Kill back into the cycle
- [ ] The arm presses Kill at no point, and the sampled machine's processes are
      all still running when the section ends
- [ ] `test\win32\activity-monitor-remote.ps1` green as a whole
