# T695 - ghoztty:// focus-only URL scheme has no Windows half - a link that raises a window or pane is dead here

## Summary

main c36456863 added a focus-only ghoztty:// URL scheme on macOS: ghoztty://focus/<target> raises the window or pane named by anything --target accepts. Windows registers no URL scheme at all, so such a link is dead here. Needs the win32 half: HKCU scheme registration (ghoztty:// release / ghoztty-debug:// debug, mirroring the pipe-name split), a strict parser shared with the Mac's shape (path form, one percent-decoded target, unknown verb/empty target/bare host all yield nothing), dispatch through the existing resolveTarget so the untrusted caller shares one naming system with --target, focus-only (no spawn, no type, no consolation focus), a coalesced not-found warning, and the three in-app link paths (banner links, WebView2 viewer navigation interception, viewer popup) handled in process so they never round-trip through the shell.

## In plain terms

On a Mac, a document can carry a link that jumps you straight to a terminal
window — click it in a build report or a dashboard and that window comes to the
front. On Windows nothing happens: the link is dead, because Windows was never
told that `ghoztty://` addresses belong to Ghoztty. When this lands, the same
link works on both machines, and it can still only ever raise a window — never
run anything.

## Goals

- [ ] Windows knows `ghoztty://` (and `ghoztty-debug://` for a dev build) belongs
      to Ghoztty, and clicking such a link raises the named window or pane
- [ ] The target is anything `--target` already accepts, resolved by the same code
- [ ] A link that names nothing that exists says so once, and never creates or
      focuses something else instead
- [ ] Links clicked inside Ghoztty (banner links, viewer pages) are handled in
      process, without a round trip through the shell

## Validation criteria

- [ ] `ghoztty://focus/<window>` from outside the app (e.g. `start ghoztty://focus/dev`)
      raises that window; verified on box
- [ ] A pane name and a pane id both work as `<target>`; verified on box
- [ ] A malformed link (unknown verb, empty target, bare `ghoztty://name`) does
      nothing but warn — no window created, no other window focused; unit tests
      in the `none` lane over the parser
- [ ] A debug build registers only `ghoztty-debug://` and does not steal the
      user's `ghoztty://` links; verified on box
- [ ] Clicking a `ghoztty://` link in a banner and in a viewer page focuses the
      target without leaving the app; acceptance script
- [ ] Floor green: both `zig build test` lanes, `test-agent`, P1-P3
