# T1288 - A second strip test can still blame the chord for a confirmation dialog it never looked for

## Summary

tab-strip-autohide.ps1 closes a tab with Ctrl+W (line ~225) without first establishing that the pane's shell is descendant-free, and without reading GhozttyConfirmDialog back. That is the same condition T1284 reproduced in chooser-close-chord.ps1: a busy shell gets the modal instead of a close, and the script reports 'closing back to one tab hides the strip again' as red with no mention of the dialog. Its 8-second retry loop hides most of it, which makes the eventual red rarer and harder to attribute rather than impossible. Use Wait-PanesIdle / Get-CloseConfirmDialog from test\win32\lib\PaneIdle.ps1.
