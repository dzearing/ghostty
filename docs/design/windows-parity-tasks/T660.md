# T660 - The bundled ghoztty SKILL.md (macos/Resources/Ghoztty/skills/) does not exist on this branch at all

## In plain terms

Ghoztty ships an instruction sheet that teaches an AI agent how to drive its
windows and panes. Main has one; this branch does not have the file at all, so
anything we change about the CLI never reaches the agents that use it here.

## Summary

`macos/Resources/Ghoztty/skills/ghoztty/SKILL.md` (and
`.../skills/process-feedback/SKILL.md`) exist on `origin/main` and are absent
from this branch — `git ls-tree -r --name-only origin/main` lists them, `git
ls-files` here does not. They arrived on main after this branch's last merge.

Found while doing T604: main's `a7f7476e1` updated the send-keys section of
that skill doc alongside `CLAUDE.md`, and the doc half could not be ported
because the file does not exist here. `CLAUDE.md` got the full merged text
(T604); the skill doc got nothing.

Two questions this task has to settle, which is why it is not a plain copy:

- **Does the win32 build ship a skill bundle at all?** The path is
  `macos/Resources/…`. `src/build/GhosttyResources.zig` was touched by
  `19cf1efbc` on this branch, so there may already be a win32 resource path to
  hang it off; if there is not, that is the real work here.
- **Whose copy wins at the cutover?** The doc describes CLI behavior that this
  branch has changed and extended (`--keys-file=`, motion `--when-idle`, the
  peel exemption in D52), so a straight `checkout --theirs` would ship a doc
  that contradicts the binary.
