# T1265 - session-relaunch.ps1 still opens Ghoztty windows on the user's desktop (deferred out of T1238)

## In plain terms

One of the session tests still starts the terminal on the desktop the user is
looking at, so running it throws windows across whatever they are reading. It was
left behind when the rest of its batch moved to a background desktop, because
moving it turns up a real product defect (the missing "session restarted" line)
that has to be fixed first.

## Summary

T1238 migrated 11 of the 13 scripts in its batch. `session-relaunch.ps1` is one of
the two it could not finish, and unlike `agent-job-escape.ps1` / `relaunch-guard.ps1`
(which are permanent exceptions - the job-escape they measure needs a desktop with
a shell window) this one is only BLOCKED.

Migrated, its section A goes red on A10/A11: the relaunched pane replays its
pre-kill scrollback and starts its fresh shell, but the
`--- session restarted ---` divider never appears. That is T1264's defect, which
is ALREADY red in this script's section B on an unmodified checkout - the
migration only makes it reproducible in section A too.

So: fix T1264, then apply the mechanical migration.

## Details

The migration itself is the same shape as the 11 that landed:

1. `. (Join-Path $PSScriptRoot 'lib\TestDesktop.ps1')` + `$td = New-TestDesktop`
   after the isolation setup, `Remove-TestDesktop` in the cleanup.
2. `Start-Process -FilePath $Exe -WindowStyle Minimized -ArgumentList $launchArgs`
   -> `[void](Start-OnTestDesktop -Exe $Exe -Arguments $launchArgs)`.
3. `Run-Cli`'s `cmd /c "... > file 2>&1"` -> `Invoke-OnTestDesktop`, writing
   `$r.Output` to `$out` and returning `$r.ExitCode` ($null on `TimedOut`).
4. DELETE the `# @user-desktop-launch: session-relaunch.ps1 ...` line from
   `lib\TestDesktop.ps1`, or `desktop-launch-audit.ps1` fails it as stale.

## Validation criteria

- [ ] `test\win32\session-relaunch.ps1` is ALL PASS on the box after the migration
- [ ] `test\win32\desktop-launch-audit.ps1` is ALL PASS with this entry gone
- [ ] no ghoztty window appears on the user's desktop while it runs
