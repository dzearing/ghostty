# T878 - Upstream the Windows owner/liveness fork of ghoztty-activity-state.sh to main

## In plain terms

The script that drives the pane's idle/busy/waiting indicator now exists in two
copies: main's original and a Windows build that adds a few guarded lines so it
works under Git Bash. If main adopts those lines, both platforms go back to
sharing one identical file, and future edits cannot drift apart.

## Summary

T605 found that main's `ghoztty-activity-state.sh` is broken under Git Bash /
MSYS (how agent hooks run on Windows): `kill -0` answers "No such process" for
a LIVE native pid, and a hook spawned by a native agent sees `PPID=1` — so
every subagent marker was recorded with owner pid 1 and reaped the moment the
next sweep ran, dropping the pane to idle while background subagents were
still in flight (exactly the regression c182302e3 exists to prevent).

The win32 bundled copy (`src/apprt/win32/assets/ghoztty/hooks/
ghoztty-activity-state.sh`) now carries OSTYPE-guarded additions, written to
be upstreamable verbatim:

- `is_windows` detection (`case "${OSTYPE:-}" in msys*|cygwin*)`).
- `owner_winpid()`: the owner walk over the NATIVE process tree —
  `/proc/$$/winpid` names the shell's Windows pid, one `powershell.exe`
  Get-CimInstance walk finds the nearest ancestor named like the runtime,
  else the immediate parent. Only runs on agent-start, never the hot path.
- `pid_alive()` / `snapshot_live_pids()`: liveness by membership in ONE
  `ps -W` snapshot per reap (both PID and WINPID columns count, so MSYS pids
  from the test oracle and native winpids from production both resolve).

Everything else is byte-identical to main's copy; the POSIX paths are
untouched (kill -0 and the ps comm walk still serve macOS/Linux). Main's own
oracle (`scripts/test-activity-state.sh`) passes 16/16 against the fork under
Git Bash (`test/win32/activity-state.ps1` section B), so upstreaming it is a
no-op for Mac behavior by the same oracle.

Once it lands on main, re-vendor: the win32 `upstream/` mirror updates, the
live copy collapses back to byte-identical, and the fork tripwires
(`GhosttyAssets.zig` test "activity-state fork carries the Windows owner and
liveness probes", `test/win32/hook-json.ps1` section A) flip back to
byte-identity assertions.

## Validation criteria

- [ ] Main's `macos/Resources/Ghoztty/hooks/ghoztty-activity-state.sh` carries
      the OSTYPE-guarded Windows probes.
- [ ] `scripts/test-activity-state.sh` still passes on macOS (16/16).
- [ ] The win32 vendored copies re-converge (live == upstream mirror) and the
      fork tripwires are updated to assert identity again.
