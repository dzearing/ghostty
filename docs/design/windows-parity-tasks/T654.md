# T654 - macOS half of T532

## In plain terms

A bug where restored terminal windows came back looking perfect and completely
dead was found and fixed. The fix is in code both Macs and PCs share, so the
Mac is already fixed. What the Mac does not have is the test that catches it
coming back — and this is a failure nobody notices until they try to type.

## What landed on Windows (and what to mirror)

T532's fix is in `src/remote/connection.zig` + `src/termio/Remote.zig` — shared
core, so macOS builds carry it already. The gap is coverage:

- `test/win32/session-reattach-zombie.ps1` **section D** ages the on-disk
  session-layout manifest's recorded offset to a phantom value while the app is
  dead, relaunches, and then requires the restored pane to ECHO a typed token.
  Against a build with the clamp neutered it reproduces the original incident
  exactly (log says restored + attached, pane paints, pane is dead).
- Sections A–C do the same across a hard kill with an ALTERNATE-SCREEN fixture,
  which is what drives the agent's `skip_replay` branch.

## Where to start

- The Mac equivalent of the manifest is `SessionLayoutManifest` (camelCase,
  one blob per TAB); the field to age is the leaf's snapshot offset.
- The liveness probe is the same on both platforms: `+send-keys` a token, then
  `+read` and require the CHILD's answer back — not the token itself, which a
  local echo also produces and a frozen pane can therefore show.
- The alt-screen fixture needs no ConPTY equivalent: any program that emits
  `\x1b[?1049h` and echoes stdin lines will do.

## Validation criteria

- [ ] A macOS arm restores a pane from a manifest whose recorded offset is
      ahead of the agent's stream head, and asserts the pane is LIVE.
- [ ] Its teeth are verified, not assumed: with the clamp neutered the arm goes
      RED, and the failure is the liveness assertion (not a setup error).
- [ ] The arm also asserts the app SAYS it clamped (the `ahead of the agent's
      stream head` warning), so a future silent regression is still visible in
      a log.
