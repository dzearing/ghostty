# T592 - floor-lane -Lane all can fail the second WebView2 lane with environment creation hr=0x80004005

## Summary

On 2026-08-08 'floor-lane.ps1 -Lane all' reported agent#1=FAIL on apprt.win32.ViewerPane.test 'host floor: a real controller on a real window, on this box', preceded by two '[webview2] (warn): environment creation failed hr=0x80004005 env=null' lines. Re-running '-Lane agent' alone passed in 164s. Both the win32 and the agent lane stand up a REAL WebView2 environment, and -Lane all starts the next lane the instant the previous one exits (win32 finished 01:53:29, agent started 01:53:29) - so the outgoing lane's msedgewebview2 tree is still tearing down when the incoming one asks for an environment. TestProfile (T430) already keeps each lane off the USER's profile; what is missing is settling between two TEST profiles. Same family as T407/T416, which saw this as a HANG rather than a failed environment. Fix candidates: have -Lane all wait for the previous lane's webview host tree to exit before starting the next (floor-lane already counts and sweeps them), and/or give the host-floor test a bounded retry on hr=0x80004005 so a transient environment refusal is not read as a broken ABI. A red floor that is really a scheduling artifact costs a turn each time and teaches the loop to distrust its own gate.

## In plain terms

The command that runs all the automated checks before a change ships sometimes
reports a failure that is not real: two of the check suites each start a small
embedded browser, and running them back-to-back means the second one asks for a
browser while the first one's is still shutting down. It gets turned away and
the whole run is marked failed. Re-running the same suite on its own passes.
Every occurrence costs a wasted cycle and, worse, makes a genuinely red result
easy to dismiss.

## Goals

- [ ] Running all lanes in one command gives the same answer as running them one at a time
- [ ] A transient browser-environment refusal is distinguishable from a real failure in the output

## Validation criteria

- [ ] `floor-lane.ps1 -Lane all -Repeat 3` is ALL LANES PASS on a box where the
      individual lanes pass, i.e. the back-to-back ordering no longer changes
      the verdict.
- [ ] The host-floor test still FAILS loudly on a box with no WebView2 runtime
      (its existing contract — a quiet skip is a test reporting success for
      work it never did), so any retry added must not swallow that.
- [ ] The floor lanes and P1-P3 stay green.
