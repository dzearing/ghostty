# T597 - test-agent lane is flaky: ViewerPane's T400 stale-debounce assertion intermittently sees 0 fetches where it wants 1

## In plain terms

One of the automated checks we run before every change occasionally reports a
failure that has nothing to do with the change being tested. That is worse
than a slow check: it teaches whoever is watching to re-run and shrug, which
is exactly the habit that lets a REAL failure through. This is about making
that check either reliable or honest about what it can measure.

## Summary

Found while landing T191 (2026-08-08). `zig build test-agent` failed on

```
[viewer_pane] (warn): t400: stale-debounce window cost 0 fetch(es), expected 1
expected 1, found 0
error: 'apprt.win32.ViewerPane.test.host floor: a real controller on a real
window, on this box' failed
```

and PASSED on an immediate re-run of the same lane with the same binary and
the same working tree (`scripts\floor-lane.ps1 -Lane agent`, 212s). Neither run
overlapped another lane or an acceptance script, so this is not the T401
contention shape — it is intermittency inside the test itself.

The assertion belongs to T400 (`d2930e6ef`, "Leaving a document cancels the
re-render the viewer had queued for it"): it drives a real WebView2 controller,
queues a re-render, leaves the document inside the debounce window, and expects
the cancelled render to have cost exactly one fetch. Counting fetches inside a
timing window that a real browser engine owns is the suspect — under load the
window can close before the fetch it is counting is issued.

## Details

- Failing test: `apprt.win32.ViewerPane` — `"host floor: a real controller on a
  real window, on this box"`, the arm that logs `t400: stale-debounce window
  cost N fetch(es)`.
- The log line the test emits already carries the measured count, so a repro
  run does not need new instrumentation.
- Fix direction (not yet chosen): make the arm wait on the fetch it is counting
  rather than on wall-clock, or assert the INVARIANT T400 actually cares about
  (the stale render never lands) instead of the fetch count that happens to
  imply it.

## Validation criteria

- [ ] The failure reproduces deliberately (e.g. `scripts\floor-lane.ps1 -Lane
      agent -Repeat 10 -Filter "host floor"`) before any fix — a flake nobody
      can summon is a flake nobody can prove fixed.
- [ ] Root cause named from the test's own timing, not inferred from the
      symptom.
- [ ] 10 consecutive agent-lane runs green after the fix.
- [ ] The arm still fails when T400's behavior is reverted (it must keep being
      a real oracle, not one relaxed into always passing).
