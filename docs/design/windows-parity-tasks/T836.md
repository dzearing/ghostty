# T836 - An armed data-breakpoint run that runs out of time reports the same verdict as a clean one

## Summary

crash-databreak.ps1's closing line reads 'no wild write observed -- N arm cycle(s), N disarm(s)' whether the program finished or the tool killed it at -TimeoutSeconds. Measured 2026-08-14 on the first real armed run against Page.verifyIntegrity: 335,878 arm cycles, then TIMEOUT after 1200s, and the verdict a reader would quote from the transcript is indistinguishable from a lane that ran to the end clean. A timeout is 'we did not look at all of it', which is the opposite conclusion, and the T443 hunt is exactly where that mistake gets made.

## In plain terms

A tool that watches memory for a bug can be stopped by its own clock before it
has seen everything. Right now, when that happens, its closing summary looks
exactly like the summary it prints when it watched the whole run and found
nothing. Someone reading the transcript later concludes the bug is not there,
when what actually happened is that nobody finished looking.

## Goals

- [x] A timed-out run has an exit code of its own (5), distinct from clean (0),
      hit (1), and the stopped-early code (4)
- [x] Its verdict line says the window closed early and never says "no wild
      write observed" / "no implausible write observed"
- [x] The evidence a partial run did produce -- arm cycles, coverage, the
      transcript -- is kept and reported
- [x] A caller that reads the result object can tell the two apart (`TimedOut`)
- [x] The acceptance harness covers both modes with a fixture that outlives a
      short `-TimeoutSeconds`

## Details

Observed on the first real armed run (T834's validation), verbatim:

```
databreak: TIMEOUT after 1200s -- killing
databreak: no wild write observed (mode=build-runner) -- 335878 arm cycle(s),
           335878 disarm(s), program ran 1200s (cdb exit -1)
```

The `TIMEOUT` line is printed, so the information is not lost — but it is
eleven lines above the verdict, and the verdict is the line that gets quoted
into a task file. The exit code is the clean-run one too, so an automated
caller cannot tell the two apart either.

What "done" looks like: a timed-out run is its own outcome end to end — a
distinct exit code, a verdict line that says the window closed early and how
much of the program it covered, and the same wording in whatever the driver
returns to a caller. Everything else about the run (the arm/disarm counts, the
transcript, the probe report) is already good evidence and should stay.

Worth pairing with a `-TimeoutSeconds` default that a real instrumented lane
can actually finish inside: at ~2 ms per armed call, the agent lane spent
335,878 arm cycles and was still going at 20 minutes.

**The default was deliberately left at 1200s** (2026-08-17). The 20-minute
window was not the problem — the per-call arm/disarm round trip was, and T838's
`-WatchPages` already removed it: the same agent lane that ran out of clock at
1200s now completes in 231s. Raising the default would buy a longer wait for the
one shape that is known to be the wrong instrument for the job, and it would do
nothing for the actual defect here, which is that the reader could not tell a
clock from an all-clear. So the fix is the verdict, and the CUT SHORT line names
both remedies — a bigger window, or `-WatchPages` — rather than picking one
silently on the caller's behalf.

## Validation criteria

- [x] A run killed by `-TimeoutSeconds` exits with a code of its own, distinct
      from both the clean-run code and the hit code — exit **5**; proven by
      `test\win32\crash-databreak.ps1` section 8c ("a timed-out run exits 5, not
      the clean-run code", and the same for `-WatchPages`), and measured by hand
      on the fixture in both modes.
- [x] Its last line says the run was cut short, not "no wild write observed" —
      the harness asserts the CUT SHORT wording is present AND that neither
      clean-run phrase (`no wild write observed`, `no implausible write
      observed`) appears anywhere in the output.
- [x] `test\win32\crash-databreak.ps1` covers it with a fixture that outlives a
      short `-TimeoutSeconds` — `sleepy.zig`: 200 armed calls, then a 600s
      sleep, run with `-TimeoutSeconds 25` in both modes. 10 new checks.
- [x] The clean-run and hit verdicts are unchanged (the existing sections stay
      green) — whole harness **ALL PASS, 93 checks** (was 83), including the
      clean-loop, hit, crash, attach, page-watch hit and arm-gate sections.
