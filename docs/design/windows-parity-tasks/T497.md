# T497 - Chrome glyphs are chunky hand-drawn marks; render Segoe Fluent Icons with drawn fallback

## Summary

User report (2026-08-05, with screenshots of our banner chevron vs Windows
Explorer's chevrons):

> "I also think our icons look chunky and don't really feel native to the
> platform. Chevrons are chunky for example. We should absolutely feel native
> like it was built by microsoft using their design language from an icons
> perspective and window chrome."

Every chrome glyph is hand-drawn as filled 2 DIP-stroke quads
(`icon_button.glyphQuads` + `icon_button_paint.glyph`). That bought symmetry
(the asymmetric-plus bug) and font-missing safety, but a 2 DIP stroke with
square-cut ends is visibly heavier than the 1 px-stroke Segoe Fluent Icons
every native Win11 surface uses - the chevron comparison makes it obvious.

`icon_button.zig` already anticipated this: "Names follow the Fluent icon they
stand in for (ChromeClose, Add, GlobalNavButton) so a later switch to a real
icon font is a substitution rather than a redesign." This task is that switch.

## In plain terms

The small icons in the window chrome — the plus, the hamburger menu, the
chevrons on banners, the close X — are drawn by hand with thick strokes, so
they look chunky next to the thin, crisp icons in File Explorer and other
Windows 11 apps. When this lands, the app draws those icons from Windows' own
icon font (the same one Explorer uses), so they look like Microsoft drew them —
and machines missing that font still get the hand-drawn versions instead of
broken squares.

## The fix

One place - `icon_button_paint.glyph` - gains a font path tried FIRST, so
every caller (tab strip, caption, banner chevron) converts at once:

- Face: **Segoe Fluent Icons** (ships Win11) -> **Segoe MDL2 Assets** (ships
  Win10) -> the existing drawn quads. Presence is verified by selecting the
  font and comparing `GetTextFace` to what was asked for (the font mapper
  substitutes silently); the verdict is cached.
- Codepoints (same in both faces): ChromeMinimize E921, ChromeMaximize E922,
  ChromeRestore E923, ChromeClose E8BB, Add E710, GlobalNavButton E700,
  More E712, ChevronUp E70E, ChevronDown E70D.
- Sizes: caption cluster (min/max/restore/close/"...") 10 DIP - Windows' own
  caption glyph size; strip/banner marks (add, hamburger, chevrons, tab close)
  keep their current optical extents. Grayscale AA (`ANTIALIASED_QUALITY`),
  transparent background, glyph color from the existing state machine.
- The drawn-quad geometry and all its tests STAY - they are the fallback and
  the negative-control world.

## Where

`icon_button_paint.zig` (the font path), `icon_button.zig` (carry the scale so
DIP font sizes resolve), `win32.zig` (CreateFontW/GetTextFaceW if missing),
`docs/design/win32-design-system.md` section 4 (glyphs: icon font first, drawn
fallback). Caption-slab geometry is T496; the two land separately but were one
user report.
