# T1396 - A tab launched with a long shell-set title is the same width as a short one

## Summary

Section 7 of `test\win32\tab-strip.ps1` fails:

```
INFO  long title: left=6 right=177 w=171 runW=1103 cap=551
INFO  short title: left=184 right=355 w=171; long slot=179
FAIL  T235: the long title is no longer pinned to the retired 200 DIP cap (171 > 245)
```

The number in the failing assertion is the least interesting part. **The long
tab and the short tab measure exactly the same width (171 px).** The fixture
launches tab 1 with
`-e cmd.exe /K title TabTitleLongEnoughToHaveBeenTruncatedByTheOldTwoHundredDipCap`
and opens tab 2 on the default shell; under T235's content sizing those two
tabs must be visibly different widths. They are identical, which means the long
title is not reaching the strip at all - so the tab is sized from whatever short
title it does have.

Proven NOT to be a font-size effect (T584 bisect, 2026-09-06): with the strip's
size forced back to the old off-ramp `16.0 * scale`, both tabs measure 183 and
the assertion fails the same way. Only the absolute numbers move with the font;
the equality does not.

## In plain terms

A tab is supposed to grow to fit its title, which is what stopped titles being
chopped to ". Fix background p...". Right now a tab whose program set a long
title is exactly as narrow as a tab with a short one - so the growing does not
happen, and the original complaint is back.

## Details

- Establish first whether the TITLE is missing or the WIDTH is: run the fixture
  by hand and read the tab. `ghoztty +list --json` names each tab's title, which
  answers it in one command.
- If the title is missing, the suspect is the `-e cmd.exe /K title <x>` path -
  a title set by `cmd`'s own `title` builtin arrives as an OSC through the
  ConPTY, and something between that and `tab_titles[i]` is dropping it.
- If the title is present, the suspect is the measure/layout seam:
  `measureTitleText` -> `Metrics.preferredWidth` -> `layoutN`
  (`tab_strip_layout.zig`), all of which are none-lane tested in isolation, so
  the break is in what the window feeds them.
- The assertion that FAILED is the weakest of the three in that section; the
  two that still pass (`the long-titled tab is WIDER`, `tab 2's left edge is
  exactly tab 1's slot`) pass on a 3 px margin that is inside noise. Whatever
  fixes this should also tighten that first one, because it is currently
  capable of passing on two identical tabs.

## Goals

- [ ] A tab with a long shell-set title is measurably wider than a short one
- [ ] The "wider than" assertion cannot pass on two equal widths
- [ ] `tab-strip.ps1` section 7 is green for the right reason
