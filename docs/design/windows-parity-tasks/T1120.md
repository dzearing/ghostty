# T1120 - morning-refresh.ps1: only one of the two routes to the restart prompt is deferred

## In plain terms

The daily automatic update is meant to never interrupt you - in particular it must never pop up a box asking about restarting the background helper, since nobody is there to answer it. There are two ways that box can be triggered and only one of them is being suppressed.

## Summary

`test\win32\morning-refresh.ps1` scored `1 FAILURE(S)` in the T1094 sweep:

```
FAIL E3 both routes to that modal are deferred (staleness and skew)
```

The assertion names its own scope: there are TWO ways to reach the agent-restart modal - staleness and skew - and the deferral only covers one. T525's whole contract is that the morning refresh delivers the app and defers anything that would end the loop or require an answer, because it runs unattended in the user's session at 5am.

This is the same family as [[T1098]] (a delivery-time dialog that can block an unattended run), and the two should be checked against each other: any prompt reachable from the refresh path is a defect, regardless of which check raises it.

## Where

- `scripts/morning-refresh.ps1` and the deferral it passes down
- `scripts/upgrade-ghoztty-windows.ps1` - the agent-restart confirmation and both routes to it
- `test/win32/morning-refresh.ps1` section E

## Goals
