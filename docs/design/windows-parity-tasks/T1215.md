# T1215 - The soak's grow pane now finishes its 150k lines early, so it is never graded

## In plain terms

One of the soak's three load generators now finishes its work in the first few
minutes and then sits idle for the rest of the run. It is still described as a
pane under load, but for most of the soak it is doing nothing - so nothing is
being checked there.

## Summary

`soak-grow` prints 150k lines and stops. T1147's report (2026-08-31) shows it
finishing inside a **5-minute** run as well as the 30-minute one:

```
big-scrollback +read latency: 88ms (baseline 87ms; grow finished: True)
  pane soak-grow  LOADED  samples 1486  min 1  median 1  p90 1  max 24  fps<=1 share 1
```

When T1147 was filed (2026-08-23) the same pane did NOT finish in 30 minutes
(`grow finished: False`), so the machine or the build has got materially
faster at this. Good news, with a cost: T1147's grader skips `soak-grow`
whenever it has finished, because after that its samples are idle samples and
grading them would be the very thing T1147 removed. In practice the pane is
now **never** graded and its floor is dead code.

The fix is to give it a load that lasts the run - scale the line count with
`-Minutes`, or loop it - so a big-scrollback pane is under real load for the
whole soak and can be graded like the other two. Keep the already-finished
exclusion either way: it is what stops an idle tail from reading as a renderer
stall.

## Where

- `test/win32/soak.ps1` - the `soak-grow` `+split` command, `$growDone`, and
  `$script:PaneFpsFloors`

## Goals

- [ ] The scrollback-growth pane is under load for the whole run at any
      `-Minutes`.
- [ ] It is graded like the other loaded panes, with a floor measured on a
      healthy build.

## Validation criteria

- [ ] a 30-minute run reports `grow finished: False` and grades `soak-grow`
- [ ] a 5-minute run does the same, so the smoke path is graded too
- [ ] `soak.ps1 -SelfTest` still goes red when that pane's fps drops
