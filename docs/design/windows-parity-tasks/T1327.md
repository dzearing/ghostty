# T1327 - The embedded ghoztty skill teaches Windows agents Mac gestures, shells and shortcuts

## In plain terms

The Ghoztty app ships a instruction document that an AI agent reads to learn
how to drive the terminal. On Windows it ships the Mac copy, word for word, so
the document tells the agent about trackpad pinch-to-zoom, `Cmd-F`, `Cmd+R`,
`Cmd+Z`, and shells that do not exist on this machine. The agent then repeats
those instructions to the person sitting in front of a Windows PC. Nothing is
broken, but the terminal is describing somebody else's computer.

## Summary

Filed from T1325, which re-vendored `skills/ghoztty/SKILL.md` from
`origin/main` and had to decide what to do about the Mac wording arriving with
it.

`src\apprt\win32\assets\ghoztty\skills\ghoztty\SKILL.md` is the copy the
Windows app writes into an agent's skill directory, and it is deliberately
UNFORKED: `test\win32\hook-json.ps1` section A asserts it is byte-identical to
the vendored mirror of tip-of-main, which is what makes re-vendoring a copy
rather than a merge. The alternative is a fork, and a fork of a 1000-line
document that main edits every week is a maintenance surface, so the choice is
not "fork one paragraph".

The Mac wording is not one paragraph either. Measured 2026-09-04 in the copy as
shipped:

| line | what it says | what Windows does |
| --- | --- | --- |
| Images bullet | trackpad pinch-to-zoom, two-finger pan, two-finger double-tap | ctrl+wheel notch zoom, ctrl+plus/minus/0, double-click; panning is the scroll container's, with precision-touchpad support (`src\apprt\win32\viewer_image.zig` header) |
| Images bullet | "**Cmd-F is declined** in an image pane" | Ctrl+F |
| `+reload` prose | `+reload`/Cmd+R | Ctrl+R |
| `+rearrange` | "undo (Cmd+Z restores the previous layout)" | Ctrl+Z |
| banner links | "the usual Cmd / Cmd-Shift modifiers" | Ctrl / Ctrl-Shift |
| `--shell` rows | invoked with `-lic`, falls back to `/bin/zsh` | per-flavor: `pwsh -NoExit -Command`, `cmd /K`, `wsl --` |
| examples | `--command=zsh`, `exec zsh -l` | a Windows shell |

So this is one coherent pass over the whole document, not a patch to the newest
paragraph, and it needs a mechanism decision first: either a Windows fork of
the whole file with the drift compare re-pointed at a *diff* rather than a
blob, or a small build-time transform applied to the mirror (a table of
platform substitutions) so the vendored copy stays unforked and the SHIPPED
copy is Windows-true.

## Goals

- [ ] Decide the mechanism (fork vs. build-time transform) and record why.
- [ ] Every row of the table above reads true on Windows in the copy the app
      writes out.
- [ ] Re-vendoring from `origin/main` stays a mechanical act - a future main
      edit must not need a hand merge of Windows wording.

## Validation criteria

- [ ] `test\win32\hook-json.ps1` is ALL PASS with the new arrangement, and its
      section A still detects a stale mirror (proved, not assumed).
- [ ] The written-out `skills/ghoztty/SKILL.md` contains no `Cmd-`, no
      `Cmd+`, no `trackpad`, no `two-finger` and no `zsh`, checked by the
      harness rather than by reading.
- [ ] Each replacement is TRUE of the shipped Windows build - the zoom and pan
      inputs cross-checked against `src\apprt\win32\viewer_image.zig` and
      `test\win32\viewer-image.ps1`, the shortcuts against the keybind table.
- [ ] The guard row still reopens when `origin/main` moves (T1325's `Upstream`
      watch survives whatever this changes).
