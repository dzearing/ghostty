## Summary

Resuming one session (T320) gets you one pane. **Restore All** rebuilds a
machine's whole window/tab/split topology locally, by reading the layout blobs
the *agent* stores - which is what makes the move work when the machine that
authored the layout is not the machine replaying it.

Three parts:

1. **The layout roster.** `Connection.requestLayouts(timeout_ns) ![]u8`
   (`src/remote/connection.zig:1693`) - the `GET_LAYOUTS` RPC. Mac decodes it
   as `{layouts: [{key, blob}]}` where `blob` is an opaque
   `SessionLayoutManifest.Entry` JSON (`SessionBrowserProbe.swift:109-135`).
   The Windows manifest code (`session-layout.json`, the pane-id/banner
   persistence) is the decoder side.
2. **The button.** `chooser_layout.Composition.restore_all` already exists and
   is *never set* (`chooser_layout.zig:458-467`), and `MachineChooser`'s
   `layoutActions` already skips it because no HWND exists. T177 built the
   action row as a packed RUN precisely so this button could appear without
   moving anything - so the UI half is: create the button, set the flag. Mac's
   order is `[New Window] [Restore All] [Activity] [...]`
   (`MachineChooserView.swift:456-494`), which is the order `actionRow` packs.
3. **The availability rule.** Mac offers Restore All only when the highlighted
   expanded row has **>= 2 ALIVE sessions**
   (`MachineChooserView.swift:145-155`), and the reason is written down: one
   pane is already covered by per-session resume, and there is no topology to
   rebuild. Port the rule *and* the reason - a Restore All that lights up on a
   single session is a button that does nothing a simpler button already did.

## The CLAUDE.md correction belongs here

CLAUDE.md's Session Persistence section still says cross-machine session move
is *"scoped but not yet built - see tasks T16-T18"*. That has been false since
the Mac shipped it on 2026-07-16, and it stays misleading on Windows until this
task lands. Correct it as part of THIS commit, so the doc flips at the moment
the statement becomes true on both platforms - and name the real entry point
(Ctrl+Shift+N -> expand a machine -> Resume / Restore All), not the task ids.
