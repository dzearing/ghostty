# T280 - Retire ConvertTo-SendKeysLiteral: the watchdog shim and every escaper can use --keys-file instead

## In plain terms

When the loop dies, a supervisor restarts it by typing a file path into the
terminal pane where it used to live. Typing is not as simple as it sounds: the
terminal treats a backslash as the start of a code, so a path belonging to a
user called "tom" arrived with a tab character in the middle of it and the
restart failed. That was patched by doubling every backslash before typing.
There is now a better way to hand text over — a file, whose contents are typed
exactly as written — and this switches to it, so the restart works for any path
without anybody remembering to escape it first.

## Goals

- [x] the supervisor's restart types the path through the safe transport
- [x] no other caller is left reaching for the old escaper
- [x] the escaper survives in exactly one named place, unreachable by hand
- [x] a test proves the path arrives character for character, with the old way
      as the control that must still arrive broken

## Summary

`scripts/go-loop-pane-probe.ps1` carries `ConvertTo-SendKeysLiteral`, added by
T241 because `+send-keys` interprets `\n`/`\t`/`\r`/`\e`/`\\` inside its
POSITIONAL text arguments — so typing the shim's own path
`C:\Users\tom\AppData\...` put a literal TAB in it and cmd said "cannot find the
path". The escaper works, but it exists only because the text was travelling as
a positional argument.

T210 added `--keys-file=<path>`, which sends bytes **verbatim**: no key
notation, no escape processing. That makes the escaper redundant at every call
site, and redundant-but-still-there is worse than absent — a future caller has
two transports to choose between and only one of them is safe for arbitrary
text.

## Deliverables

1. `scripts/go-loop-watchdog.ps1`'s shim branch (`restart-in-pane`) sends the
   shim path through `--keys-file` instead of `ConvertTo-SendKeysLiteral`.
2. Any other caller of `ConvertTo-SendKeysLiteral` moves the same way.
3. Delete `ConvertTo-SendKeysLiteral` once it has no callers, OR keep it with a
   header saying it is only for the case where a file is genuinely impossible —
   and name that case. A helper with no named use is a trap.
4. `docs/design/windows-parity-tasks/T241.md` gains a pointer: the latent bug it
   found is now fixed at the transport instead of by escaping.

## What landed

Deliverable 3 took the second option, and the named case is real rather than
defensive: **an installed ghoztty that predates T210's `--keys-file`**. These
scripts run against whatever is installed — the watchdog especially, a
long-lived HKCU Run process — and `New-LoopSendKeysText` already probes for the
flag and degrades to argv when it is missing. On argv the escaping is still
required, so the escaper moved into `scripts/loop-session.ps1` as the private
tail of that degraded branch and left `go-loop-pane-probe.ps1` (the pane-occupancy
classifier, which never needed to own a transport concern) entirely.

That also fixed a latent hole rather than merely relocating one: before this,
the degraded branch put the text on argv **unescaped**, so an old exe would have
mangled a `\n` or `\t` in the resume PROMPT as surely as it mangled a path.
`M23` is the arm that pins it.

Nothing calls the escaper by hand any more — `Select-String` over `scripts\`,
`scripts\lib\`, `test\win32\` and `test\win32\lib\` finds the definition and its
one internal use, and every `+send-keys` site in `scripts\` that carries
generated text now goes through `New-LoopSendKeysText` (the rest are key
notation: `C-u`, `Escape`, `Get-LoopSubmitArgs`).

**Found on the way, filed as T783 (P1):** the guard was already 26 assertions red
before this task touched it. `b64c3e8aa`, earlier the same day, prefixed every
`go-loop-lock.ps1` message with an ISO timestamp and did not move the guard's
`^ACQUIRED` / `^held` / `^stale-dead` anchors. Repaired here in one place —
`Lock-Run` strips the leading stamp and keeps the whole line as `Raw`, with a new
`A2b` asserting the prefix is genuinely on the wire so the normalization can
never paper over a missing verb — because T280's own validation criteria require
section N green. The gap that let it stay red for a day is what T783 covers.
