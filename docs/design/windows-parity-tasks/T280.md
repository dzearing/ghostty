# T280 - Retire ConvertTo-SendKeysLiteral: the watchdog shim and every escaper can use --keys-file instead

## Summary

`scripts/go-loop-pane-probe.ps1` carries `ConvertTo-SendKeysLiteral`, added by
T241 because `+send-keys` interprets `\n`/`\t`/`\r`/`\e`/`\\` inside its
POSITIONAL text arguments — so typing the shim's own path
`C:\Users\tom\AppData\...` put a literal TAB in it and cmd said "cannot find the
path". The escaper works, but it exists only because the text was travelling as
a positional argument.

T210 added `--keys-file=<path>`, which sends bytes **verbatim**: no key
notation, no escape processing. That makes the escaper redundant at every call
site, and redundant-but-still-there is worse than absent — a future caller has
two transports to choose between and only one of them is safe for arbitrary
text.

## Deliverables

1. `scripts/go-loop-watchdog.ps1`'s shim branch (`restart-in-pane`) sends the
   shim path through `--keys-file` instead of `ConvertTo-SendKeysLiteral`.
2. Any other caller of `ConvertTo-SendKeysLiteral` moves the same way.
3. Delete `ConvertTo-SendKeysLiteral` once it has no callers, OR keep it with a
   header saying it is only for the case where a file is genuinely impossible —
   and name that case. A helper with no named use is a trap.
4. `docs/design/windows-parity-tasks/T241.md` gains a pointer: the latent bug it
   found is now fixed at the transport instead of by escaping.

## Validation

- `test/win32/go-loop-guard.ps1` section M's escaper cases become `--keys-file`
  cases: a path with a `\t`, `\n` and a trailing `\` in it must arrive intact.
  Keep the pre-fix oracle (the raw positional send mangles it) as the negative
  control, the way sections M/N already do.
- The T241 negative control (dead pid + live claude in the pane → `nudge`, not
  `restart-in-pane`) must stay green — this touches the branch it guards.
