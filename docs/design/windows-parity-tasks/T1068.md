# T1068 - Nothing tells you a background-process update is waiting, now that Ghoztty stops asking

## Summary

T1056 removed the dialog that used to appear when the agent (the background process that keeps sessions alive) was older than the app: it offered to end every live session for a binary refresh, which is not a trade worth offering. The newer build is now adopted silently at the next quiet moment. The consequence is that a pending agent update is completely invisible - on a box whose last window never closes and whose agent is a pre-T907 generation (no self-handoff), it can wait indefinitely with nobody able to see it or take it deliberately. Mac has the same gap. Wanted: a non-modal, non-destructive way to see it and act on it - the agent's own '+sessions --agent' already reports handoff state (unsupported/ready/draining), so the missing half is a user-facing surface (a quiet notice, a menu item, or a line in the connection pill) that says an update is ready and installs when your sessions close, plus a deliberate 'install it now' that is opt-in rather than offered. Must never become the old dialog by another name: nothing that interrupts, and nothing that ends a session without the user having gone looking for it.
