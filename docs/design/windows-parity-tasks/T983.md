# T983 - Ctrl+Z does not take a quote or an image chip back out of the composer

## Summary

On the web composer (T934) a quote and an image chip are put in by replacing the whole document with a seed message, so the browser's undo stack sees one opaque replacement rather than an edit - and Ctrl+Z either does nothing or walks past it. The RichEdit path used EM_REPLACESEL with wparam TRUE, which made both undoable, so this is a regression against what T641/T637 shipped. T935 (quotes as CSS blocks) and T936 (chips as DOM nodes) are expected to fix it by making both the page's own edits; this task exists so that expectation is checked rather than assumed, and carries the acceptance if they do not.

## In plain terms

Quote a passage into the feedback box, or paste a screenshot into it, and then
change your mind: Ctrl+Z does nothing. The quote and the picture chip stay put,
and the only way back is to select them and delete them by hand — which is not
what anyone reaches for first. After this, Ctrl+Z takes the quote or the chip
back out the way it takes back anything else you typed, and Ctrl+Y (or
Ctrl+Shift+Z) puts it back if you undid one too many.

## Goals

- [x] Ctrl+Z removes a quote that was just inserted, restoring the box exactly
      as it was — text, caret and the report's own list of quotes
- [x] Ctrl+Z removes an image chip the same way, so the picture leaves the
      report with it
- [x] typing since the quote landed still undoes keystroke by keystroke first;
      the quote comes out only once the engine has nothing left
- [x] Ctrl+Y / Ctrl+Shift+Z redoes, with the quote's identity intact
- [x] an undo can never resurrect a report that was already sent

## Validation criteria

- [x] the host floor test in `ViewerPane.zig` drives a REAL composer through
      quote → Ctrl+Z → Ctrl+Y and asserts the buffer returns byte-for-byte to
      the pre-quote document with zero live quotes, then comes back with the
      block carrying the same registry id (win32 test lane).
- [x] `viewer_feedback_page.zig` unit tests: a seed says whether it is an edit
      (`"undo":true`) or a replacement, and the page reads that flag and takes
      the chords itself (`none` + `win32` lanes).
- [x] the floor is green: `scripts\floor-lane.ps1 -Lane all`, plus
      `test\win32\viewer-composer.ps1` and P1-P3.
