# T511 - macOS: +list/window-inherit report a frozen cwd for shells that never emit OSC 7 (T185's Mac half: live process-cwd fallback)

## In plain terms

On macOS the default shells (zsh/bash) tell Ghoztty where they are on every
`cd`, so new windows open in the right place and `+list` answers correctly.
But a pane running a shell WITHOUT that integration (integration disabled in
config, `dash`, a bare REPL, an `-e`-launched program) reports the directory
it STARTED in forever — the exact defect Windows had for cmd.exe until T185.
Windows now falls back to asking the OS where the shell process really is;
the Mac should do the same, or the platforms diverge in Windows' favor.

## Summary

T185 (win seat, 2026-08-06) fixed the frozen-cwd defect on Windows with a
two-part rule:

1. A `pwd_reported` flag on the apprt surface, set only when a REAL OSC 7
   report arrives (the initial termio seed pushes no `.pwd` action, so the
   flag cleanly separates "shell tracks its cwd live" from "frozen seed").
2. When the flag is false, `+list` and the new-window/tab/split inherit path
   read the shell process's real cwd from the OS instead of the cached seed
   (`src/os/process_cwd.zig` on Windows — PEB read on the shell pid).

The Mac machinery already exists: `pty_child.zig`'s `queryCwdMacos` does the
same read via `proc_pidinfo(PROC_PIDVNODEPATHINFO)`, and the Swift side knows
each pane's shell pid. Port the same policy: OSC 7 owns the answer once it has
ever arrived; until then the process cwd is the live truth. (Caveat mirrored
from Windows: a shell that changes its logical location without chdir-ing —
the pwsh case — only gets live values from integration, which macOS default
shells already have, so there is no regression surface.)

## Validation criteria

- [ ] A pane running `dash` (or zsh with `shell-integration = none`): `cd`
      somewhere, `+list --json` reports the NEW directory
- [ ] Cmd+N from that pane opens in the new directory
- [ ] zsh with integration keeps its current behavior (OSC 7 wins)
- [ ] macOS unit/UI test or scripted check recorded here
