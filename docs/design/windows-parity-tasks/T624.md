# T624 - no bundled release notes and no What's New window on Windows

## Summary

Split out of T125 on 2026-08-08. Windows ships no release notes and has no
"What's New in Ghoztty" window; macOS has both. `release-notes/{client,agent}/
<version>.json` is repo-shared, so what is missing here is the *presentation*
plus the last-seen-version tracking that decides which notes are "new".

## In plain terms

After Ghoztty updates itself on Windows, nothing tells you what changed. On a
Mac there is a "What's New in Ghoztty" window with two tabs -- one for the app
and one for the background session process -- listing what landed since the
version you were last running. On Windows that window does not exist, so the
only way to find out what an update did is to go read the release page on
GitHub.

## Goals

- [x] The bundled notes reach a Windows build (macOS copies them into
      `Contents/Resources/ghostty/release-notes/`; a Windows exe has no
      Resources dir, so they need embedding at build time or installing
      beside the exe). -- `src/build/GhosttyReleaseNotes.zig` enumerates
      `release-notes/{client,agent}` at configure time and generates a
      `release_notes_data` module that `@embedFile`s each one; wired through
      `SharedDeps.add`, so a notes file that EXISTS is a notes file that
      ships and there is no hand-kept list to forget on release day.
- [x] A pure `release_notes.zig` that parses the JSON and partitions versions
      into "new since your last version" / "already installed", mirroring
      `ReleaseNotesStore.partitioned` (cap "new" at the running version).
- [x] Last-seen-version tracking: snapshot the stored version once at launch,
      then advance it -- the win32 analogue of `WhatsNewTracking`
      (`UserDefaults` -> a file under `%LOCALAPPDATA%\ghoztty\`).
      `whats_new_seen.zig` is the pure half; `WhatsNewWindow.snapshotAtLaunch`
      (called from `App.init`, before anything can show notes) is the IO half.
- [x] A native "What's New in Ghoztty" window with Client and Agent tabs,
      reachable from the menu, rendering the notes with the inline markdown
      subset the banner already supports (`banner_markdown.zig`).

## Details

Mac implementation to port:

- `macos/Sources/Features/Update/ReleaseNotesStore.swift` -- decode + partition
  (`isNewer` compares dotted-numeric versions; "new" is capped at the running
  version so a bundle carrying newer notes never shows them).
- `macos/Sources/Features/Update/WhatsNewTracking.swift` -- `previousSeenVersion`
  snapshotted once at launch, before anything can show a dialog.
- `macos/Sources/Features/Update/WhatsNewWindowView.swift` -- the tabbed window.
- `macos/Sources/Features/Update/WhatsNewNotesView.swift` -- `WhatsNewNotesContent`
  is shared by the window, the update popover and the restart-dialog accessory,
  with a `Density` knob between them. Windows should keep the same
  one-renderer-two-densities shape so T625's accessory cannot drift from the
  window.
- `AppDelegate.showWhatsNew` + `MainMenu.xib` -- the menu action.

Windows chrome is subject to `docs/design/win32-design-system.md`: put the
geometry in a pure module and assert it at 1.0/1.25/1.5/2.0.

## Validation criteria

- [x] Unit tests in the `none` lane cover parse + partition (including a
      version newer than the running build being dropped, and newest-first
      ordering) and the last-seen snapshot/advance. -- `release_notes.zig`
      and `whats_new_seen.zig`, registered in `src/apprt.zig` so they run in
      every app-runtime lane.
- [x] Geometry asserted at 1.0/1.25/1.5/2.0 in a pure layout module.
      -- `whats_new_layout.zig`: the spacing scale resolves exactly at 100%,
      every step is monotonic in DPI, the tab run holds a body line box, and a
      window squeezed below its floor still yields non-negative boxes.
- [x] An acceptance script opens the window from the menu and confirms both
      tabs render notes for the current version. -- `test/win32/whats-new.ps1`,
      ALL PASS (46 assertions), `-NegativeControl` scores red. It drives the
      real anchor store and the real app: the window exists as one top-level
      `GhozttyWhatsNew` with Mac's title however many times it is asked for,
      both tabs answer with lists of their own, and the split is asserted from
      the same store the window paints (section F proves the cap by running at
      a version BELOW the newest bundled note).
- [x] Both zig test lanes, `test-agent`, and P1-P3 stay green.
