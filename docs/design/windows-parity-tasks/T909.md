# T909 - Holder-backed sessions become the default, so surviving an agent restart is not opt-in

## Summary

T905 landed the holder-backed spawn path behind `GHOZTTY_AGENT_PTY_HOLDER=1`,
deliberately: with the flag off the spawn path is bit-identical to what has
shipped all along, which is what makes any regression in the new path
attributable. That gate has to come off, or the feature only exists for whoever
sets an environment variable.

Flip it once the survivors are actually picked back up (T906 adoption) and the
upgrade choreography rides on them (T907) — before that, a default-on holder
means every agent restart leaves a living shell that nothing re-attaches to,
which is a worse user experience than today's honest teardown.

## In plain terms

Right now the improvement that keeps your terminal sessions alive when the
background manager restarts is switched off unless you know to turn it on. This
turns it on for everyone.

## Goals

- [ ] Holders are the default for new persistent sessions on Windows.
- [ ] The old in-process path stays reachable as an explicit off-switch (an
      escape hatch for a box where holders misbehave), not as the default.
- [ ] Adoption (T906) is proven at the same time, so a default-on holder is
      never an unadopted orphan.

## Validation criteria

- [ ] `test\win32\pty-holder.ps1` passes with NO flag set — sections A/B are
      the default behavior, and the flag-OFF control arm becomes an explicit
      opt-OUT arm.
- [ ] `test\win32\session-persistence.ps1` ALL PASS with no flag set.
- [ ] All four floor lanes + P1-P3 green.
- [ ] No holder is left behind after a full app+agent teardown (the leak this
      makes universal if it exists).
