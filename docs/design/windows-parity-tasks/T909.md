# T909 - Holder-backed sessions become the default, so surviving an agent restart is not opt-in

## Summary

T905 landed the holder-backed spawn path behind `GHOZTTY_AGENT_PTY_HOLDER=1`,
deliberately: with the flag off the spawn path is bit-identical to what has
shipped all along, which is what makes any regression in the new path
attributable. That gate has to come off, or the feature only exists for whoever
sets an environment variable.

Flip it once the survivors are actually picked back up (T906 adoption) and the
upgrade choreography rides on them (T907) — before that, a default-on holder
means every agent restart leaves a living shell that nothing re-attaches to,
which is a worse user experience than today's honest teardown.

## In plain terms

Right now the improvement that keeps your terminal sessions alive when the
background manager restarts is switched off unless you know to turn it on. This
turns it on for everyone.

## Goals

- [x] Holders are the default for new persistent sessions on Windows.
- [x] The old in-process path stays reachable as an explicit off-switch (an
      escape hatch for a box where holders misbehave), not as the default.
- [x] Adoption (T906) is proven at the same time, so a default-on holder is
      never an unadopted orphan.

## What landed

- `pty_holder_child.enabledFor` inverted: unset (and empty) is ON;
  `0`/`false`/`off`/`no` — trimmed, case-insensitive — is the escape hatch. A
  near-miss (`00`, `nope`) stays ON deliberately: a typo must not return a box
  to the lossy path silently, which is the exact failure this task ends.
- The three holder harnesses stop setting the flag and CLEAR it instead, so
  each one measures what a real box does rather than an opt-in arm that would
  keep passing on the day the default regressed. `pty-holder.ps1`'s negative
  control now sets `=0`, which also makes it the proof that the escape hatch
  still works.
- `agent-recovery.ps1` C5 flipped with the behavior: killing the manager no
  longer takes the shells, so the arm asserts the SAME pids came back (adopted)
  where it used to demand two new ones. Its rebuild oracle was never the pids —
  it is the terminal-surface set (E7/G/H6) — so nothing weakened.
- New harness `test\win32\holder-soak.ps1` + a `holder-soak` row in
  `scripts\guard-due.ps1` (it also covers `src\remote\agent\pty_child.zig`,
  which no guard covered): the cost of one process per session is now measured
  at a realistic fleet size, and a per-session teardown leak shows up as a pile
  rather than as one process nobody notices.

**Platform symmetry**: the flip is Windows-only because the holder itself is —
`enabledFor` returns false on POSIX regardless of the variable, and the Mac half
is the already-filed T908 (seat: mac), which carries the default with it when it
lands. Nothing here is a Windows-only *feature*; it is the Windows half of T705.
