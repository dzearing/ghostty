# T488 - macOS drops a -e launch command the same way when session restore rebuilds windows (T406 Mac half)

## In plain terms

On the Mac, `ghoztty -e some-command` runs the command — unless you had windows
open last time, in which case those come back and the command silently doesn't
run. This is the Mac half of a Windows bug that has now been fixed; the two
seats should behave the same.

## Goals

- [ ] A launch command opens its window even when restore rebuilds windows
- [ ] The requested surface — not a restored one — is the one that consumes
      `initial-command`
- [ ] The requested window ends up frontmost
- [ ] A test that fails without the fix

## Summary

The win32 half is T406 (fixed 2026-08-04). The Mac side has the identical shape,
found while diagnosing it — the code was read, not run, so reproducing it on the
Mac is step one:

- `AppDelegate.applicationDidBecomeActive` opens the initial window only when
  `TerminalController.all.isEmpty && derivedConfig.initialWindow && !hasPendingIpc
  && !hasPendingSessionRestore` (`macos/Sources/App/macOS/AppDelegate.swift`).
- `SessionLayoutRestore.sessionLayoutRestoreFinished()` opens one only when the
  restore ended with **zero** windows (`macos/Sources/Features/Remote/
  SessionLayoutRestore.swift`).

So a restoring launch opens no requested window at all, and the shared core rule
(`app.first` consumes `initial-command`, `src/Surface.zig`) hands the command to
a restored pane, which ATTACHes to an existing session and cannot run it.

The Mac restore is **asynchronous** (it dials the agent off the main thread),
which is the one real difference from win32's synchronous `restoreSessionLayout`
— so "create the requested window first, then restore" is available here too and
is probably still the simplest ordering.

## The rule to match (decided for T406)

Restore rebuilds what the user left behind AND the requested window opens; the
requested window is created first so it is the surface `app.first` names, and is
raised to the front afterwards. See `docs/design/windows-parity-decisions/` for
the reasoning and the alternatives considered.

## Validation

Reproduce first (launch with a layout to restore + `-e <marker>`; the marker
must be missing). Then a test that fails without the fix, matching section D of
`test/win32/gui-launch-command.ps1`.
