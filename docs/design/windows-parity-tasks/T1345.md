# T1345 - The app paints heavier than the Mac build because every piece of chrome is its own layered popup

## In plain terms

Everything the app draws on top of the terminal - the banner strip, the dimming
over unfocused panes, the scrollbar, the read-only badge, the key-state pill -
is its own separate little window that Windows has to composite and that
repaints itself independently. The Mac draws all of that into one layer tree.
That difference is the likeliest reason the whole app feels heavier, and it is
a redesign rather than a fix.


## Background

Split out of T1324. `WS_EX_LAYERED` popups are created by `BannerOverlay`,
`DimOverlay`, `Scrollbar`, `KeyStateIndicator`, `ReadonlyBadge`,
`RegionSelector`, `ViewerPane`, `App` and `Window`. The design is deliberate -
a plain child window cannot reliably sit above the OpenGL surface, which is why
the chrome works at all - but a layout change fans out into many window
repositions and many independent GDI paints.

The repositions are already batched (`BeginDeferWindowPos` in `Window.zig`,
T1031). The **paints** are not, and every one of these popups is re-glued on
every layout pass through `updateDimOverlays`.

## Why this is behind T1343

Nothing here should be attempted until T1343 has numbers. If the drag cost is
dominated by the per-surface frame wait, this fan-out may be a small term and a
large rewrite. If it is not, this is where the time goes. Deciding that from a
reading of the code is exactly the guessing T1324 was filed to stop.

## Candidate directions, all unproven

- Batch the overlay paints the way the repositions already are.
- Ask whether the overlays that do not need per-pixel alpha could be plain
  child windows, or drawn by the owner instead of owning a window.
- Collapse several per-pane popups into one per-pane chrome window.

## Validation criteria

- [ ] The cost of the fan-out is measured (paint count and time per layout
      pass) before any structural change is made.
- [ ] If the answer is "this is not where the time goes", that is recorded and
      the task is closed as such - a measured no is a result.
- [ ] Any change keeps every overlay above the GL surface in the cases the
      current design was built for: z-order healing (T142), hero mode, tab
      switches, DPI changes and window moves.
- [ ] The existing overlay acceptance scripts stay green.
