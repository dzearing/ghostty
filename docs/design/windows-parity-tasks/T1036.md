# T1036 - An acceptance script can launch ghoztty-agent.exe with no build-mode pre-flight of its own

## In plain terms

The test suite has a gate that refuses to run when the terminal it is about to
drive is the one the user actually uses. T1033 made that gate cover every test
that starts the terminal app. It still does not cover tests that start the
background helper that keeps sessions alive: if that helper is built the wrong
way, a test run can reach in and disturb the user's own live sessions, and
nothing would say so.

## Summary

Split out of T1033. `Assert-GhozttyIsolatedBuild` reads the build mode off
`ghoztty.exe +version` and refuses a build whose endpoints are the user's.
`ghoztty-agent.exe` derives its guard mutex, heartbeat, pipe and state dir from
the same build mode (`LocalAgent.pipeName`), so a release agent launched by a
test owns exactly the sessions the user's installed Ghoztty is holding - but the
agent exe answers `--version` with a `YYYYMMDD-<hash>` build STAMP, not a mode,
so the existing assert cannot speak for it and `launch-preflight-audit.ps1`
leaves agent-only launchers out of scope on purpose.

About 10 scripts launch only the agent (agent-adopt, agent-pipe, agent-user-env,
agent-sharing-uplink and friends). Most already isolate with
`GHOZTTY_AGENT_INSTANCE`, which is honored in release builds too - so this is a
gap in what is CHECKED, not a live leak.

Wanted, in rough order of preference:

- teach `ghoztty-agent.exe --version` to print its build mode (one line, the
  same shape the app prints), then an `Assert-GhozttyIsolatedAgent` that reads
  it, or
- assert on the app exe that sits beside it in the same output prefix, which is
  a proxy rather than a measurement, and say so where it is used.

Then widen `launch-preflight-audit.ps1`'s trigger to agent launches and fix
whatever it names.

## Validation criteria

- [ ] a launcher of a release-lineage `ghoztty-agent.exe` is refused before the
      launch, with a message naming the build mode - proved by a stub, the way
      `build-mode-guard.ps1` proves the app half
- [ ] `test\win32\launch-preflight-audit.ps1` flags an agent launch with no
      claim (its A6 fixture inverts) and the real tree is clean under the wider
      trigger
- [ ] the scripts the widened sweep names are fixed, and each still passes
