# T978 - After a crash or reboot the Mac restores a stale screen, because the manifest only refreshes on quit

## In plain terms

When your terminal comes back after a crash or a reboot, each pane is supposed
to show what was on screen when it died. On the Mac it shows what was on screen
the last time you moved, split or renamed a window - which could be hours
earlier - because the record of each pane's screen is only refreshed when the
window layout changes, or when you quit on purpose. A reboot never gets to do
the "on purpose" part.

## Summary

`SessionLayoutManifest` persists each pane's WP-D3 screen snapshot, but the
sync is debounced off LAYOUT mutations only. The file says so itself, above
`syncAllTrackedNow` (`macos/Sources/Features/Remote/SessionLayoutManifest.swift`):

> Called at quit: a session that changed only via output (the common case)
> never triggers the debounced sync, so without this the persisted snapshot
> would be stale and the agent's delta replay large - defeating the fast-restore.

A quit-time flush covers a clean quit. It does not cover the crash, the power
cut or the reboot, which is precisely the case D78 ("Bring back what was on
screen") is about - and on the Mac the same staleness also inflates the agent's
delta replay on every unclean restart.

T922 fixed the Windows half: `App.tickLayoutRefresh` polls the summed, lock-free
`Remote.appliedOffset` across panes every 2s, captures on the first tick after
the output goes quiet, forces a capture after 30s of unbroken streaming, and
`session_layout.writeIfChanged` skips the disk write when the serialized body is
unchanged - so an idle terminal costs one atomic load per pane and no I/O.
Translate that shape, don't port the code: the Mac's equivalent of the poll is
whatever it can read without taking the render lock, and its cadence should stay
in step with the agent's 30s ring-snapshot rhythm for the same reason.

## Goals

- [ ] A Mac pane that has only produced OUTPUT since the last layout change has
      its screen snapshot refreshed without the user quitting.
- [ ] An idle terminal writes nothing: no manifest rewrite while nothing paints.
- [ ] A pane streaming without pause still gets its screen persisted on a
      bounded interval.

## Validation criteria

- [ ] With a pane left printing after the last window/split/rename, killing the
      app hard (not quitting) and relaunching brings back a screen from seconds
      before the kill, not from the last layout change.
- [ ] An idle app leaves the manifest's mtime alone across several minutes.
- [ ] The Mac session-restore tests stay green.
