# T745 - Banner table columns truncate instead of using full pane width (table appears capped at ~50% width)

## Summary

Reported interactively 2026-08-11 with a screenshot of a pane banner rendering a
markdown pipe table (the tracker session's status banner: rows `Prompt` /
`Status`). The long cell text ("Read C:/Users/David/AppData/Local/Temp/…")
is tail-truncated with an ellipsis while roughly half the pane's width sits
empty to the right of it — the truncation fires long before the content column
has consumed the available width, as if the table's total width were capped at
~50% of the pane rather than derived from the pane's full content width.

Expected per CLAUDE.md's banner contract: "Column widths derive from the pane's
current width" — a cell should word-wrap (up to the 3-wrapped-line cap, then
ellipsize) only after the column has actually been given the pane's available
width. A cell truncated at half-width is neither wrapping nor honoring the
pane width.

Suspect area: the win32 banner table layout in `banner_layout.zig` (column
width distribution vs. `contentWidth`) — check whether the content column's max
width is being computed from the wrong base (e.g. half the pane, a stale width,
or a per-column cap that ignores unused sibling-column slack).

## Validation criteria

- [ ] A two-column banner table with one short label column and one long text cell in a wide pane (~1900px) uses the full content width: the long cell extends until pane width (minus gutters/chevron reservation) is exhausted before wrapping or ellipsizing.
- [ ] Column-width distribution asserted in the pure layout module at 1.0/1.25/1.5/2.0 scaling: unused width from narrow columns is granted to the wide column rather than stranded.
- [ ] Existing banner-table behavior unchanged: 3-wrapped-line cell cap, narrow-pane reflow, and `test/win32/pane-banner.ps1` still ALL PASS.
