# T885 - Mac: surface long-unattached live agent sessions as a user notification with resolve actions (T534 sibling)

## Summary

The Mac half of T534 (which shipped the Windows seat's implementation and the
SHARED agent groundwork — nothing agent-side is left to do):

- The agent already tracks `Session.unattached_since_ms` (stamped at create and
  on every bound→false transition, cleared on ATTACH) and reports it additively
  as `SessionInfo.unattached_since`, only while a session is alive and
  unattached. Old agent ⇒ field absent ⇒ no notification (no capability needed;
  readers tolerate absence). See `src/remote/protocol.zig` /
  `src/remote/agent/server.zig`, test
  "T534: unattached_since stamps the detach…".
- The Windows app polls the local roster (15 min cadence), and a session
  continuously unattached past a hard-coded generous threshold (24 h — D18
  ruled out config knobs) earns ONE notification naming it (cwd + command);
  clicking it opens the machine chooser where the orphan badge (T520/T881) and
  Resume/Kill live. Ignoring/dismissing IS "Keep": a per-EPISODE stamp file
  (episode = session id + its `unattached_since` instant) suppresses
  re-announcement for 7 days, and an attach resets the agent-side clock so a
  later orphaning is a fresh episode. Policy is pure in
  `src/apprt/win32/orphan_notify.zig`; translate the policy, not the plumbing.

Mac translation: an `NSUserNotification`/`UserNotifications` banner from the
app (the native analog of the Windows tray balloon), click → open the machine
chooser (Cmd-Shift-N surface) with the session roster visible; same threshold,
same per-episode keep stamps (a small JSON beside the app's other local state),
same "never unpin/reap/alter anything without an explicit user action".

## In plain terms

If a terminal session keeps running in the background but no window has shown
it for a day or more, the Mac app should point it out once — "this is still
running, click to review" — instead of leaving the user to stumble on it in the
session list weeks later. Windows already does this; this task brings the same
notification to the Mac app.

## Validation criteria

- [ ] A live session continuously unattached past the threshold produces a
      user notification naming it (working dir + command), validated with a
      debug agent and a shortened threshold (the debug-only env seams
      `GHOZTTY_ORPHAN_NOTIFY_AFTER_MS` / `GHOZTTY_ORPHAN_CHECK_MS` or a Mac
      equivalent).
- [ ] Clicking the notification opens the chooser where the session can be
      resumed or killed; resuming resets its clock (`unattached_since` back to
      null in `+sessions --json`).
- [ ] Ignoring/dismissing the notification suppresses re-announcement of that
      episode (per-episode stamp), and the keep-forever default behavior is
      unchanged when the user does nothing.
- [ ] Old agent + new app degrades to no notification (field absent), no error.
