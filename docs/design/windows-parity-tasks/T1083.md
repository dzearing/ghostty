# T1083 - Re-vendor the ghoztty skill doc: main documented the caller-anchor default and the Windows copy still taught the old rule

## In plain terms

Ghoztty ships an instruction file that tells an AI agent how to drive it. Since
T1079, asking for a side pane from a script opens it beside that script even if
you have clicked another window in the meantime - and main updated the
instruction file to say so. The Windows copy still carried the OLD text, telling
agents that a plain split "goes to the most recently focused window" and that
they must name their own pane to be safe. The behavior changed; the instructions
the app hands out did not.

## Summary

`test\win32\hook-json.ps1` section A is the vendor-drift check: the mirror under
`src\apprt\win32\assets\ghoztty\upstream\` must be blob-identical to
`origin/main:macos/Resources/Ghoztty/<path>`, and the unforked live copy
blob-identical to the mirror. It went red on
`skills/ghoztty/SKILL.md` - main's version documents the caller-anchor default
(the same feature this branch landed as T1079, commit 3097d14e6), and the
vendored copy predated it.

Found while re-running the guards T351's sweep made due: the guard had been
CURRENT since 2026-08-20 and had no reason to run again until an edit touched
`hook-json.ps1`, so a drift that landed in between was invisible. That is the
guard system working, one edit late.

Remedy is the one the harness's own header names: re-vendor. The mirror was
replaced from `origin/main` and the live copy re-copied from the mirror.
