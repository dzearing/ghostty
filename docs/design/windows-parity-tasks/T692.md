# T692 - macOS: the local agent has no GHOZTTY_AGENT_INSTANCE lineage suffix

## In plain terms

On Windows, an automated test can now ask for its own private copy of the
background helper that keeps terminal sessions alive, instead of shutting down
the one the developer is using. The same knob exists in the shared code on the
Mac but the Mac app itself does not read it yet, so Mac test runs still have to
interrupt real sessions.

## Summary

T167 (win seat) added `GHOZTTY_AGENT_INSTANCE=<suffix>`, which forks the whole
local-agent lineage so a test sandbox coexists with the box's real agents rather
than being refused by the single-instance guard (exit 183) and silently falling
back to non-persistent panes.

The parts that are shared Zig already work on macOS:

- `src/remote/agent_lineage.zig` — the pure sanitize/compose rules,
- `src/remote/agent/single_instance.zig` — the guard key, which on POSIX keys
  the `flock` file `~/.config/ghoztty/agent-<key>.lock` and the sibling
  `agent-<key>.heartbeat`,
- `src/cli/sessions.zig` — `+sessions` reads
  `~/.config/ghoztty/local-agent[-debug][-<suffix>]/port.json`.

What is NOT wired is the Swift side: `LocalAgentManager`'s own derivation of the
agent state dir and the `agent.sock` path (the Mac analog of win32
`LocalAgent.agentDir` / `pipeName`), and the LaunchAgent plist label (the analog
of the HKCU Run value name). Until those honor the suffix, a Mac sandbox that
sets it gets a private guard and then fights the box's agent for one socket
path — the half-isolated state T167 exists to remove.

## Details

Mirror the win32 shape (`src/apprt/win32/LocalAgent.zig`, T167):

- state dir `~/.config/ghoztty/local-agent[-debug][-<suffix>]/`,
- socket `<state dir>/agent.sock` (so it follows the dir automatically),
- LaunchAgent label suffixed the same way, so a forced-autostart sandbox can
  never clobber the real per-user LaunchAgent,
- unset ⇒ every existing path byte for byte unchanged.

Read the suffix through the shared `agent_lineage` rules rather than
re-implementing them in Swift (same whitelist, same 24-char cap, same
reject-don't-truncate), so the two lineages of one sandbox cannot disagree about
their own name.

## Validation criteria

- [ ] With `GHOZTTY_AGENT_INSTANCE` unset, every Mac agent path is byte-for-byte
      what it is today
- [ ] Two Mac sandboxes with different suffixes each run their own live agent,
      with the developer's own agent untouched and still holding its sessions
- [ ] `+sessions` inside a sandbox lists that sandbox's agent
- [ ] A Mac equivalent of `test\win32\agent-instance-lineage.ps1`'s arms, or the
      same claims folded into the existing Mac harness
