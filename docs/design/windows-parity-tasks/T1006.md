# T1006 - The composer forgets its undo history when the pill is closed or written to from outside

## Summary

T983 gave the web composer an undo journal for the quotes and image chips native splices in, and that journal lives on the PAGE - created when the pill opens, destroyed when it closes (D43's own renderer-cost mitigation). So a quote inserted before a close cannot be undone after a reopen, even though the text it produced is still sitting there: the buffer outlives the page and the history does not. The same edge shows up when native rewrites the buffer for any other reason - every seed that is not an insertion clears the journal deliberately, because an undo must never resurrect a report the user already sent - but what the user sees is just that Ctrl+Z stopped working, with nothing saying why. Two shapes worth weighing when this is picked up: keep the journal on the BAR (native), where it outlives the controller and can be seeded back down to a fresh page; or accept the page's lifetime and make the difference legible instead of silent. Not urgent: the common case - quote or paste, change your mind, Ctrl+Z - is covered and tested.
