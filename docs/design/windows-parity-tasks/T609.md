# T609 - Expose a remote window's connection state in +list --json so reconnect is observable without log scraping

## Summary

The remote reconnect ladder (T366) has real per-window state — connected /
reconnecting(attempt N) / disconnected(self-healable or terminal) — and today
the ONLY way to read it from outside the process is to grep the app log. Give it
a field in `+list --json`.

## In plain terms

A window connected to another machine now knows whether that connection is
healthy, retrying, or given up. Right now nothing outside the app can ask. This
puts the answer where every other window fact already lives, so a script — or a
person debugging — can see it without reading log files.

## Details

Filed out of T366, whose driver holds the state in `Window.reconnect.ladder`
(`RemoteReconnect.State`). Two things want it:

- **T368**, the reconnect acceptance script, currently has nothing to assert
  against but log lines. A log line is a weak oracle: it is a side effect of the
  implementation rather than a contract, and it moves whenever the message is
  reworded.
- **T367**'s pill paints exactly this state, so a JSON field and the pill would
  read one source instead of two.

Shape: a `connection` object on a remote window's `+list --json` entry —
`{"state": "connected" | "reconnecting" | "disconnected", "attempt": N,
"self_healable": bool}` — absent entirely for a local window, which is what
already distinguishes them. Additive, so no existing consumer breaks.

Do it on BOTH platforms per the standing symmetry rule: the Mac holds the same
ladder state in `BaseTerminalController` and its `+list` has the same gap. File
the Mac half as its own `seat: mac` task if it cannot land here.

## Validation criteria

- [ ] `+list --json` reports `connection` for a remote window and omits it for a
      local one
- [ ] The field tracks a real drop: connected -> reconnecting(N) ->
      connected again across an agent kill/restart
- [ ] T368's acceptance script asserts against the field rather than log text
- [ ] Both zig test lanes and `test-agent` green; P1-P3 ALL PASS
