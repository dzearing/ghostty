# T640 - Viewer feedback composer: the pill's two actions need tooltips and keyboard reach

## In plain terms

The feedback box has two round buttons in it — one adds a screenshot, one
sends. Right now you can only find out what they do by clicking them, and you
can only click them: there is no way to reach either one from the keyboard, and
nothing tells you which one has focus. On a Mac both buttons say what they are
when you hover, and both can be tabbed to.

## Summary

Fallout from T634, which shipped the composer's chrome. Two gaps, both of them
things the win32 design system already requires of every other chrome control
and this one does not yet have:

- **No tooltips.** Mac puts `Add a screenshot of the screen (⇧⌘S)` and
  `Send feedback (⌘↩)` on the two buttons via `.help`. The win32 pattern for
  this already exists one file over — `ViewerNavBar.tipEnsure`/`syncTip`, a
  comctl32 rect tool in `TTF_SUBCLASS` mode — so this is following a pattern,
  not inventing one.
- **No keyboard reach and no focus ring.** Design system §2.2: a control that
  can be tabbed to draws a 2 DIP accent ring inset 1 DIP, and *keyboard focus
  is always visible*. Neither action can be reached from the keyboard at all
  today, so neither draws one. Tab inside the composer should walk
  text → snapshot → send and back out.

Deliberately NOT folded into T635: that task owns the TEXT control (decision
D43) and its IME/undo/accessibility surface. These two buttons are ordinary
chrome and their treatment is decided already.

## Details

Sites: `src/apprt/win32/ViewerFeedbackBar.zig` (the composer window and its
paint), `viewer_feedback_layout.zig` (already hands out both buttons' painted
rects and hit boxes, so nothing new is needed from the geometry).

Watch for the ordering trap the nav bar's tooltip documents: the tip is a
POPUP owned by the bar, not a child of it, so it has to be destroyed before
the window it subclassed.

The focus ring needs a focus MODEL first (which of the three things inside the
composer has it), which is the only real design work here. Keep it in the bar
rather than in the layout module — the ring is a paint state, and the rects are
already there.
