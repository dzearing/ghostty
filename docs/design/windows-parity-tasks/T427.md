# T427 - Mac half of the agent-refresh relaunch guard: the app must come back if it dies mid-refresh

## Summary

The Windows half shipped in **T421**: the app supervises the seconds it spends
restarting its local agent, so a process that ends inside that window is started
again instead of leaving the user with an empty desktop. The Mac has the same
destructive path (`LocalAgentManager` → terminate the agent → rebuild the
windows in place) and the same promise on the same dialog, so it needs the same
guarantee. Filed rather than skipped, per CLAUDE.md's platform-symmetry rule.

## What to translate (the concept, not the implementation)

- **The mechanism is deliberately env-var driven, not a new CLI verb**, so the
  `ghoztty` command set stays identical on both platforms. `GHOZTTY_RELAUNCH_GUARD`
  = `<pid>|<marker>|<exe>` is already platform-neutral; the Mac side can read the
  same variable.
- The Windows guard is a detached copy of the app that holds the app's process
  handle (`OpenProcess(SYNCHRONIZE)` + `WaitForSingleObject`). The macOS
  equivalents are `kqueue`'s `NOTE_EXIT` or simply `waitpid`-free polling of
  `kill(pid, 0)`; `NSWorkspace` relaunch is NOT the right tool (it is for
  termination the user initiated).
- Keep every property the Windows one is built around: the marker window is
  seconds wide, it relaunches at most once, the child must not inherit the
  variable, and there is a hard cap on the guard's life.
- Shared logic worth lifting rather than rewriting: `parseSpec` /
  `shouldRelaunch` in `src/apprt/win32/relaunch_guard.zig` are pure and
  unit-tested; a Swift port should match them assertion for assertion.

## Validation

The Mac analog of `test/win32/relaunch-guard.ps1`: kill the app with the marker
present and assert a new instance comes up and answers IPC, plus the three
negative controls (cleared marker, disarm-while-alive, malformed spec).
