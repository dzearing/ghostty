# T1294 - Surface.pane_view back-pointer has no test: nothing proves it still names a leaf while Surface.deinit forgets its IPC name

## Summary

T371 unit-tested the split-tree leaf reference COUNTING (src/apprt/win32/pane_refcount.zig). What it could not reach is the ordering contract the comments in PaneView.unref describe: Surface.unref runs hide/deinit/destroy first, Surface.deinit reaches back into the IPC registry to forget a name keyed on the PaneView, and only then does PaneView free itself. Nothing anywhere asserts that order, so an edit that frees the PaneView first would read as correct and crash only under a close.
