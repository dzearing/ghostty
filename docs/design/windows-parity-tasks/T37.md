# T37 — CLAUDE.md symmetry mandate + dual-arch dev instructions

## Summary

CLAUDE.md symmetry mandate + dual-arch instructions

## Details

User directive 2026-07-13: **all new features must land in BOTH the
Windows and Mac builds — the two are to be kept symmetric.** Update the
repo CLAUDE.md to state this as a standing rule, and add clear
instructions for starting and debugging each architecture: Mac (zig build
+ Ghoztty-Debug.app, debug socket) and Windows (native Debug build with
`ZIG_GLOBAL_CACHE_DIR` on the repo drive, Console-subsystem stderr, debug
pipe, release builds via `-Dtarget=x86_64-windows-gnu`, installed-release
layout under `%LOCALAPPDATA%\Programs\Ghoztty`). Fold in the test lanes
(none/win32) and the P1–P3 acceptance scripts so either seat can validate.

*Validation:* CLAUDE.md review — a fresh session on either OS can build,
run, and debug from CLAUDE.md alone.

## Outcome (2026-08-02)

CLAUDE.md gained three things.

**1. `## Platform symmetry is a standing rule`, at the very top** — ahead of
everything, because a rule buried under 700 lines of CLI reference is a rule
nobody reads before writing code. It states the 2026-07-13 directive as a
standing rule and then makes it actionable rather than aspirational: translate
the *feature*, not the implementation (with the six pairs this repo has already
settled — AF_UNIX socket -> named pipe, LaunchAgent -> HKCU Run, Keychain ->
DPAPI, `+list --tty` -> `+list --pid`, `-lic` -> per-flavor shell invocation);
the CLI surface is identical on both platforms, with the removed
`+relay-login`/`+relay-logout` pair (T141) as the worked example of what "we do
not ship divergence" cost in practice; and **land both or file the other half**,
naming `parity-tasks.ps1 new` and `seat: mac` so the escape hatch is a documented
action instead of an intention.

**2. `## Build, run & debug`, replacing the four-line macOS-only `## Build &
Test`.** The old section told a Windows seat nothing and actively misled it: its
one command produces no Windows app, and the `-Doptimize=Debug` it names omits
the runtime selector. Now there is a macOS subsection, a Windows subsection, and
a shared test-lane subsection.

Facts were read out of source rather than recalled:

- `-Dapp-runtime` defaults to `none` on macOS and `win32` on Windows
  (`Runtime.default`, `src/apprt/runtime.zig:18`). So `zig build test` with no
  selector is a *different lane on each platform* — the doc now says to name the
  lane explicitly, which is the actual reason go.md insists on "both lanes".
- Debug builds link the **Console** subsystem, release builds the GUI subsystem
  and append `info`+ to `%LOCALAPPDATA%\ghoztty\ghoztty.log`
  (`src/build/GhosttyExe.zig:58`, `src/main_ghostty.zig:180`), with
  `-Dwindows-console=true` to give a release build a console
  (`src/build/Config.zig:194`).
- The Windows IPC endpoint is `\\.\pipe\ghoztty[-debug]-<USERNAME>`
  (`src/os/ipc_client.zig:106`), not a socket path; `GHOZTTY_PIPE_SUFFIX`
  overrides the suffix and `GHOZTTY_IPC_SOCKET` the whole endpoint.
- The macOS app name is `Ghoztty-Debug` only in the Debug configuration
  (`src/build/GhosttyXcodebuild.zig:60`).
- P2 is `+split`/`+rename`/`+send-keys` and P3 is
  `+read`/`+set-state`/OSC 7777/`+rearrange` — read off the script headers,
  because the first draft guessed and guessed wrong.

**3. Platform-correct Architecture and intro.** Both said "Unix domain socket"
unconditionally; the Architecture list had no win32 apprt entry and no
`ghoztty-agent` entry at all. Both transports are now named, along with the
single client-side resolution site (`apprt.ipc.socketPath()`, which delegates to
`ipc_client.endpointPath()` on Windows) so the "one place" property survives
being written down.

One gotcha was found by *being* the fresh session rather than by remembering:
running the documented build cold failed with `unable to update file …
ghoztty-agent.exe: AccessDenied`. A `ghoztty-agent.exe` left running from
`zig-out\bin` by an earlier test run holds its own exe open — the agent outliving
the app is by design, so this is a permanent property of this repo, not a one-off.
It is now documented with a kill snippet that matches on `ExecutablePath`,
because matching by name would kill the installed release's agent and take the
user's live sessions with it.

*Evidence (every command run verbatim as written in the new section):*

- `zig build -Dapp-runtime=win32 -Doptimize=Debug` exit 0 (after clearing the
  stale agent — which is how the gotcha above was found).
- `zig build test -Dapp-runtime=none` exit 0; `zig build test -Dapp-runtime=win32`
  exit 0.
- `zig build test-agent` exit 0. The first attempt failed on
  `remote.agent.server.test.unknown channel DATA is ignored`; it passed 3/3 under
  `-Dtest-filter` and 1/1 on a clean re-run of the whole lane. Not this change
  (docs only) — a load-sensitive fixed-spin wait in the test. Filed **T346**.
- `ipc-p1.ps1` / `ipc-p2.ps1` / `ipc-p3.ps1`: ALL PASS.

Not validated here: the **macOS** subsection, which no Mac has run since it was
written. Filed **T347** (`seat: mac`) rather than claiming it — which is exactly
what the "land both or file the other half" rule this task just added requires.
