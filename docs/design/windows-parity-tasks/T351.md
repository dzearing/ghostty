# T351 - Finish the CleanSlate sweep: ~29 test/win32 scripts still carry private kill helpers

## Summary

T248 hoisted the pre-fixture reset into `test\win32\lib\CleanSlate.ps1`
(`Reset-GhozttyTestState`: exact-exe kill of the app AND its sibling agent,
plus the debug session-layout manifest) and converted 19 scripts to it - the
15 `Stop-DebugGhoztty` copies plus the four inline kills in `ipc-under-load`,
`profile-latency`, `soak`, `wheel-scroll`.

The sweep is not finished. Roughly 29 scripts still carry private helpers
under other names - `Kill-RepoInstances` (7+ copies), `Stop-TestProcs`,
`Stop-RepoInstances`, `Stop-AppOnly`, `Stop-RepoProcesses` - each with its own
filter, its own settle time, and its own answer to "does the agent go too".

This is the T257 shape exactly: N copies of one datum means N chances to be
wrong and no way to notice. Two known divergences already live in these
copies:

- `$_.CommandLine -like '*zig-out*'` matches a detached instance running from
  `zig-out-release` (T53b) and kills it; exact-exe does not.
- none of them drop the debug session-layout manifest, so a previous run's
  window is restored under its old target name (the T248 defect).

## What to do

- Convert the remaining scripts to `Reset-GhozttyTestState`, keeping each
  script's own extra litter (e.g. `focus-defer.ps1`'s FD-LOAD flood shells)
  local and only the shared part shared.
- The session-* family and the agent upgrade/recovery scripts need
  `-AppOnly` - their subject IS the running agent - but they still want the
  manifest cleared, which is why that is not gated on the switch.
- Grep for a private `Get-CimInstance Win32_Process` kill afterwards; a
  script that still has one is either unconverted or deliberately different,
  and if it is deliberate it should say so in a comment.

## In plain terms

Every one of the test scripts that drives the Windows app has to put the box back
to an empty state before it starts - close the app, close the background service
that keeps terminal sessions alive, forget the saved window layout. Each script
had written that step out by hand, in its own way. There were 133 hand-written
copies, and they disagreed: some closed the background service and some did not,
some matched the app by a loose pattern that also caught a completely different
build the developer had running, and four of them had quietly redefined the
shared helper's own name so their version won.

The visible cost is a test that measures the wrong thing and passes: a window
left over from the previous run gets reused, the script never actually launches
the build it is supposed to be checking, and the result is green. After this,
there is one copy of that step, every script calls it, and a new hand-written
one fails a check rather than sitting there for three weeks.
