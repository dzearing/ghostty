# T1368 - Nobody has watched Repair and Cancel answered against a real MSI over a real install

## In plain terms

When you run the installer for a version you already have, Ghoztty asks
whether to repair it or cancel. Both answers have been checked in every way
short of the real one: the dialog is driven live, and the package's tables are
read back at build time, but nobody has yet double-clicked an actual installer
over an actual install and watched Repair repair and Cancel leave the machine
alone. That last step is what the previous two installer bugs needed and did
not have.

## Summary

T1367 found the Repair/Cancel question sequenced at 6605 — five past
`InstallFinalize` — so it was being asked once the install had already run.
Every existing assertion missed it because they all read the *source* or the
*compiled tables*, and the number that gave it away only appeared when somebody
printed it.

The fix is landed and the tables now assert the whole band. What is still owed
is the walk: `test\win32\install-walkthrough.ps1` act D already installs a
re-identified copy of a PUBLISHED package into
`%LOCALAPPDATA%\Programs\GhozttyT1299Test`, re-runs it, and asserts the dialog
appears and Cancel ends at 1602. Two gaps in it:

- It only answers **Cancel**. Repair — the answer that actually re-runs the
  install — is never pressed, so `REINSTALL=ALL` being armed correctly is still
  unobserved outside the table check.
- Its subject is the newest published release, which until the release carrying
  T1367 goes out is a package whose prompt is sequenced at 6605. The act would
  pass against it, because a same-version reinstall of an identical payload
  looks "untouched" either way — which is exactly the blind spot T1367 was.

fork-ci builds an MSI on every push but uploads no artifact, so the package
that carries the fix arrives through the daily publish. This task is therefore
gated on that release existing.

## Goals

- [ ] Run `install-walkthrough.ps1` against the first published release that
      carries T1367 and record act D's outcome
- [ ] Extend act D to answer **Repair** as well as Cancel, asserting the
      install is re-written (not merely left alone) and msiexec ends at 0
- [ ] Assert the thing T1367 could not: that the question is asked BEFORE the
      files move — e.g. a file stamped between the prompt appearing and the
      answer being given is still the pre-install one
- [ ] Green run stamps the `install-walkthrough` guard, which has never had one

## Validation criteria

- [ ] `powershell -NoProfile -File test\win32\install-walkthrough.ps1` is green
      on this box, act D included, against a package carrying T1367.
- [ ] Act D asserts both answers, and the Repair arm fails if `REINSTALL` is
      not armed.
- [ ] `scripts\guard-due.ps1 check` no longer reports `install-walkthrough` as
      unstamped.
