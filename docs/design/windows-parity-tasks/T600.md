# T600 - The Windows first-launch setup dialog does not disclose that Ghoztty writes agent config files

## In plain terms

Ghoztty will be modifying files that belong to your coding agent - its settings
and its hooks. The first time it offers to do that, it should say so plainly and
let you decline. On the Mac it does. Windows must not quietly write into someone
else's config.

## Summary

Upstream: `d839b3f4a` ("macos: disclose agent-config writes in the first-launch
setup dialog"). Depends on T598 existing at all - there is nothing to disclose
until Windows installs something.

Also in scope: `de290d93a` bounded and throttled the Stop-hook PR staleness
check, because a hook that runs on every stop and reaches the network is a cost
the user pays without being told. Whatever the Windows hook does on stop gets
the same bound.

## Goals

- [x] The first-launch offer discloses what an integration writes and where,
      and that it is removable, before anything is written
- [x] The disclosure reads as fine print (caption size, secondary color),
      matching the Mac note's presentation
- [x] The stop-path hook work is bounded and throttled (verified already
      vendored from de290d93a)

## Validation criteria

- [x] The first-launch dialog names the files that will be written, in plain
      language, before anything is written. — `test\win32\claude-integration.ps1`

      config folder (`.claude`), and names the removal path, all before any

- [x] Declining leaves every agent config file untouched, and the app still
      runs. — same harness, case 1: Escape declines, no claude command runs,

- [x] The stop-path hook work is bounded and throttled - no unbounded network

      throttle, and `ClaudeHookSpec.zig` puts `timeout: 10` on every hook

      command", green in both lanes this run).
- [x] Acceptance script covers accept and decline paths. — cases 1 (decline)
