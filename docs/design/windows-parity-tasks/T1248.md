# T1248 - update-real-msi's final sweep arm flakes when the applier is still exiting

## Summary

Arm E ('the next launch swept everything the update left') failed once on 2026-09-01 with ghoztty-updater.exe still in the staging directory, and passed on an immediate re-run with the same build. The applier holds its own image until it exits, so the 30x1s poll is racing the applier's exit rather than the sweep. A red that clears on a re-run reads as a broken change to whoever hits it; the arm should wait for the applier pid to be gone before it judges the sweep.
