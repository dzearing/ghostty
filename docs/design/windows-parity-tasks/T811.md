# T811 - The agent lane intermittently panics in Connection.destroy at the end of T739's repaint test (DebugAllocator free)

## Summary

One run in a handful of `zig build test-agent` dies instead of finishing: 9432/9512 tests pass and then ghoztty-agent-core-test aborts. T460's first-chance capture got the stack on the occurrence that failed, so this is not a suspicion - .dumps/ghoztty-agent-core-test-20260812-182923-0.log names the faulting thread: std.heap.debug_allocator's `free` PANICS (abort via defaultPanic) under `Allocator.destroy` under `Connection.destroy` (src/remote/connection.zig:1603), called from `test 'T739: an injected repaint is rendered like DATA but advances no offset'` (connection.zig:4004). The args register row is 0xaaaa..., zig's undefined fill, so the shape is a free of memory the connection had already released or overwritten - i.e. a double free or a destroy racing one of the connection's own threads, not a leak. Reproduction is intermittent: the identical lane passed on the immediately following run (221s) and was green earlier the same day, which is why this needs the dump rather than a re-run to diagnose. Found while validating T461 (whose diff touches no shared or agent code: src/apprt/win32 only), so it is neither caused nor masked there. Next step is the dump, not a guess: `scripts\crash-catch.ps1 -FromDump .dumps\ghoztty-agent-core-test-20260812-182923-0.dmp` and the other threads' stacks in the same transcript, which is what will say WHICH thread was still inside the connection when destroy ran.
