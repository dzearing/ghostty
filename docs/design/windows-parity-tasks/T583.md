# T583 - The pane banner still draws its body at the retired 15px, off the type ramp

## Summary

T310 counted **seven** copies of `font_h = px(15, scale)` and T313 retired the
last of them — but only in the dialogs. `BannerOverlay.zig:59` has an eighth,
spelled differently:

```zig
const FONT_H: f32 = 15.0;
const heading_px = [6]f32{ 21.25, 20.0, 18.75, 17.5, 16.25, 15.0 };
```

So as of T313 the pane banner — which sits directly above the terminal, the
most-looked-at surface in the app — is the ONE piece of Ghoztty text still set
at the size every dialog just moved off. Open the banner editor
(Ctrl+Shift+B) over a banner and the editor's text and the banner's text are
different sizes.

## In plain terms

The sticky note Ghoztty draws above a terminal pane is set in a slightly bigger
font than everything else in the app now. Nobody chose that difference; it is
the last survivor of a size the rest of the app has moved off. Fix it and the
banner reads as part of the same app as the dialogs.

## Goals

- [x] The banner's body, line box and face come from `type_ramp`, not from a
      number of its own
- [x] The six markdown heading levels are anchored to the ramp instead of
      being a second scale beside it
- [x] The reasoning is written down where the next person will look for it
      (`win32-design-system.md` §2.4)

## Details

- The BODY is the straightforward half: `FONT_H` should be
  `type_ramp.body_dip`, and the face literal at `BannerOverlay.zig:492` should
  be `type_ramp.face`. `code` spans keep Consolas — that is a deliberate face
  choice, like the Activity Monitor's numeric columns.
- The HEADING scale is the real question and should be answered, not assumed.
  `heading_px` is a 6-step ratio scale (h1 21.25 down to h6 15.0) that exists
  because a banner renders markdown and markdown has six heading levels; the
  ramp has three sizes total and says so on purpose ("the divergence bought
  three sizes, not a licence to invent more"). Two defensible answers:
  1. Anchor the scale to the ramp — h6 becomes body, h1 becomes subtitle, the
     middle interpolates — so the banner's own scale MOVES when the ramp moves
     even though it keeps six steps.
  2. Declare the markdown heading scale a second, named ramp with its own
     module and its own reasoning, the way the terminal font is not the UI
     font.
  Whichever is chosen, write the reasoning into `win32-design-system.md` §2.4
  so the next person does not have to re-derive it.
- Watch the knock-on: `banner_layout.zig` derives line and block heights from
  these numbers, and the display cap counts LINES, so a size change moves how
  much text fits in a banner before it is truncated. Assert the new numbers at
  1.0/1.25/1.5/2.0 like the other geometry modules.
