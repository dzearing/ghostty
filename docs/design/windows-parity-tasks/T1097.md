# T1097 - Rename the 'merge-back' terminology to 'upstream pull' in the live docs - the phrase reads backwards and caused a real misunderstanding

## Summary

In this repo 'merge-back' has always meant 'merge upstream's changes back into our fork'. It reads as the opposite - merging our fork back into ghostty-org - and on 2026-08-22 a digest sentence built on it ('The merge back to upstream Ghostty actually began') made the user believe the loop was preparing pull requests against ghostty-org. That is the one thing that must never happen, and the wording alone is what suggested it. Rename the operation to 'upstream pull' (or 'upstream sync') everywhere a future reader could act on it: docs/design/windows-parity-merge-back-plan.md including its filename, windows-parity-tasks.md, windows-parity-ship-workflow.md, CLAUDE.md and docs/claude/*, and any task file whose status is not done. Leave the dated digests and windows-parity-log.md alone - both are history-only by charter - but append a one-line correction to the 2026-08-21 digest where the misleading sentence lives. Also make the direction explicit wherever the term appears: FROM ghostty-org INTO ghoztty, never the reverse. Acceptance: git grep -i 'merge.back' returns hits only in dated digests and the log.
