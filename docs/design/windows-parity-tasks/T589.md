# T589 - Mac: viewer-only windows are dropped on restore when the local agent is unreachable (T398's Mac half)

## In plain terms

Same defect T398 fixed on Windows, still live on the Mac: when the background
piece that keeps your shells alive can't be reached, reopening the app throws
away every recorded window — including the ones that were only showing a file,
a web page or a diff, which never needed that piece at all.

## Summary

`SessionLayoutRestore` (`macos/Sources/.../SessionLayoutRestore.swift:53-64`)
resolves the local agent first:

```swift
LocalAgentManager.shared.sharedConnectionAsync { [weak self] connection in
    guard let connection else {
        // "keeping N manifest entries for next launch"
        self.sessionLayoutRestoreFinished()
        return
    }
```

That gate is correct for terminals — without a connection there is nothing to
ATTACH to — and applies to no VIEWER leaf at all: re-opening its recorded
location IS a viewer's restore (T90h; the Swift side already knows this, see
the "Viewer leaves have no agent session" arm further down the same file). So a
manifest whose windows are viewers is dropped for a reason true of none of its
panes.

## Details

Found while landing T398 (the win32 half) — the Swift gate was read directly and
has the same shape. **One difference worth keeping:** Mac deliberately does NOT
overwrite the manifest on this path ("keeping N manifest entries for next
launch"), so the layout survives to the next launch; win32 does overwrite it,
which is T590. Fix the drop here without giving up that property.

The win32 fix to mirror (`src/apprt/win32/App.zig`): make the connection
optional through the restore walk, and treat "no agent" as an EMPTY attach set
rather than a null/unknown one — so the never-all-dead rule reads exactly as it
does against an agent that knows none of the recorded sessions. Viewer-bearing
windows come back (terminals beside them opening as fresh local panes);
terminal-only windows are still dropped.

## Validation criteria

- [ ] With the agent binary made unspawnable, a relaunch restores a viewer-only
      window at its recorded location.
- [ ] A mixed window restores too, its terminal opening as a fresh local pane.
- [ ] A terminal-only window is still dropped (the never-all-dead rule).
- [ ] The manifest entries are still kept for the next launch (do not regress
      the property win32 lacks — see T590).
- [ ] macOS test lanes green.
