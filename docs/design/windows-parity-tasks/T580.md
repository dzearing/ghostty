# T580 - Mac paints split-divider-color with no contrast floor - the same hole T251 closed on Windows

## In plain terms

On Windows, a divider color you pick that would be invisible against your panes
is quietly lifted just far enough to be seen. On the Mac it is still painted
exactly as typed, so the same config makes the line you grab to resize a split
disappear there. Same setting, same file, two different outcomes.

## Summary

Found while doing **T251**, which closed this on Windows.
`macos/Sources/Ghostty/Ghostty.Config.swift:535` (`splitDividerColor`) returns
`split-divider-color` verbatim whenever it is set, with no contrast check —
so `split-divider-color = #0a0a0a` on a black terminal is a 1.10:1 divider,
which is what T251 filed as a defect on the Windows seat.

T251's divergence is recorded in `docs/design/win32-design-system.md` §5, and
it is a divergence in the FLOOR, not in the CLI or config surface — but the
project's standing rule is that a behavior difference between the seats is the
defect. The two options are to port the floor to Mac (making the divergence
disappear) or to decide the floor is a Windows-only judgement; either way the
call should be made deliberately rather than left as an accident of which seat
noticed first.

Note Mac's *default* (used only when `split-divider-color` is unset) is
`background.darken(by: 0.08/0.4)`, which has its own version of this problem:
darkening a black background leaves black. Windows' fallback is a fixed
`#808080` — see **T581** for that half.

## Where

- `macos/Sources/Ghostty/Ghostty.Config.swift:535` — `splitDividerColor`.
- `macos/Sources/Features/Splits/SplitView.Divider.swift` — the fill site.
- Reference implementation: `src/apprt/win32/split_geometry.zig`
  `dividerPaint` / `floored` / `hoverShade`, and its unit tests.

## Validation criteria

- [ ] A near-background `split-divider-color` paints a divider that clears 3:1
      against the pane background on macOS (or a recorded decision that it
      deliberately does not).
- [ ] The config value round-trips unchanged — the floor is applied at paint
      time, not written back.
- [ ] Swift tests mirroring `split_geometry.zig`'s adversarial sweep.
