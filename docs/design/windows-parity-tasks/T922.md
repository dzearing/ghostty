# T922 - A pane restored after a reboot comes back empty instead of showing what was lost

## Summary

Under session-relaunch=restore the Windows client OPENs a brand-new session for a dead tombstone, and deliberately paints neither the agent ring replay nor the app's own WP-D3 screen snapshot above the fresh prompt (termio/Remote.zig excludes did_notify from both). Main's restore (c76b5c89d) keeps the dead session's scrollback so the user can read what the process left behind. So after a reboot a Mac pane shows the last output of the thing that died and a Windows pane shows only the notice and an empty prompt.

## Validation criteria

- [ ] A pane restored under the default `restore` policy comes back showing what the dead session left on screen, instead of an empty prompt.
- [ ] That restored screen sits ABOVE the session-interrupted notice, and both are in the pane's own scrollback - the fresh shell's opening repaint does not erase either.
- [ ] A pane with nothing to bring back (no snapshot, an empty one, or one recorded at stream offset 0) restores exactly as it did before, with no blank filler above the notice.
- [ ] A pane whose snapshot was taken inside a TUI comes back on the PRIMARY screen with a scrollback the user can scroll, and the dead program's modes (mouse tracking, bracketed paste, autowrap) do not leak onto the fresh shell.
- [x] The standing floor stays green: all four `floor-lane` lanes (lib / none / win32 / agent all PASS, 2026-08-18, after healing a ZIR cache entry the reboot tore - see T973). The P1-P3 acceptance scripts and this task's own restore arms are held by T975: with the reboot shape restoring nothing, no pane reaches the restore path to be scored.
