# T747 - Machine chooser 'Sign in with Google' button does nothing

## Summary

User report 2026-08-11: clicking the Sign in (with Google) button in the machine chooser's account row does not work - no browser opens / no sign-in flow starts. Expected: the relay-brokered OAuth flow launches the default browser with the PKCE authorization URL and completes sign-in. May be related to T746 (Ctrl+Shift+N chooser not opening) if the chooser itself is broken; verify independently. Relevant code: src/remote/relay_signin.zig, src/apprt/win32/RelayAccountRow.zig.

## In plain terms

The machine chooser offered a "Sign in with Google" button that could never
work. The shipped build carries no Google sign-in credential, so every press
failed instantly - no browser opened, nothing on screen changed, and the log
line explaining it was somewhere the user would never look. A button that does
nothing reads as a broken app, so the whole remote-machines feature looked dead.

Now the chooser tells the truth: with no credential configured there is no
button at all, the row says sign-in is not set up in this build, and the strip
underneath says what would fix it. Supplying the credential is a separate,
one-time build step (see the decision filed with this task) - what this change
guarantees is that the user is never again left pressing something that cannot
work.

## Goals

- [x] the dead button is gone: an unconfigured build draws no sign-in control
- [x] the row and the footer hint say what state this is and what fixes it

Two things to fix rather than one: (a) the delivery/build must carry a client id, and (b) a missing client id must SAY so in the UI instead of failing silently - a dead button is the worst possible presentation of a build-configuration problem.
