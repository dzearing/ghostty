# T347 - Verify the macOS half of CLAUDE.md's build/run/debug section on a Mac (T37 follow-up)

## Summary

T37 rewrote CLAUDE.md's `## Build, run & debug` section so either seat can
build, run and debug from CLAUDE.md alone. The **Windows** half was validated by
running every documented command verbatim on the box. The **macOS** half was
written from source (`src/build/GhosttyXcodebuild.zig` for the app name,
`src/apprt/ipc.zig` for the socket path, `src/main_ghostty.zig` for the log
predicate) and from the pre-existing CLAUDE.md text — nobody has run it on a Mac
since. This task closes that gap.

## Details

Per the symmetry rule T37 itself added: land both halves, or file the other.
This is the other half.

On a Mac, follow CLAUDE.md's `### macOS` subsection *literally*, as a fresh
session with no prior knowledge would, and fix whatever is wrong or missing:

- `zig build -Doptimize=Debug` really produces `zig-out/Ghoztty-Debug.app`
  (the Xcode build writes `macos/build/<config>/Ghoztty-Debug.app` — confirm
  what the documented path actually is after an install step, and correct the
  doc if it is the `macos/build` path rather than `zig-out`).
- `open -na zig-out/Ghoztty-Debug.app` launches it alongside the release app.
- The debug instance really binds `$TMPDIR/ghostty-debug-<uid>.sock`, and the
  `ghoztty` CLI from that build drives *it* and not `/Applications/Ghoztty.app`.
- `sudo log stream --level debug --predicate 'subsystem=="com.dzearing.ghoztty"'`
  shows the app's log output.
- `zig build test` is the `none` lane on macOS (`Runtime.default` returns
  `.none` for non-Linux/non-Windows) — confirm, since the doc now tells readers
  to name the lane explicitly because of this.

Anything that turns out to be wrong is a doc fix in the same section, not a new
section.

*Validation:* each command above run on a Mac with its real output; CLAUDE.md
amended for anything that did not match.
