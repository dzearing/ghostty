# T1375 - The command palette and the search bar answer to the terminal's window class, so no probe can tell them apart

## Summary

Both popups are created with App.TERMINAL_CLASS_NAME, so by class they ARE a terminal surface. Two consequences, both found while validating T563: Get-TestWindowPixels refuses to capture anything of that class (T214's rule about the GL surface returning a flat fill), so measuring the palette needs -AllowTerminalSurface, which is the hatch reserved for measuring the limit itself; and every script that waits for a popup does Wait-TestWindow -Class GhozttyTerminal, which cannot distinguish the palette from the search bar from a second terminal window. Registering GhozttyCommandPalette and GhozttySearchBar against the SAME wndproc fixes both (role is already resolved from the HWND by surface_window_role, not from the class), and it lets the capture guard keep its teeth for the surface it was written about. The cost is every acceptance script that keys on the old class name, which is why this is its own task.
