# T841 - The T443 hunt only gets a handful of runs per turn - soak it unattended between turns instead of spending turns on it

## Summary

T443 is the top P0 and it is starved of RUNS, not of instruments. A turn can
afford about five lane runs (a compile-loaded agent lane is ~190-340s each), the
signal appears in ~19% of runs on the days it appears at all, and it has now
gone quiet for 28 consecutive build-runner runs across three different box
conditions. Turns are the scarce resource; wall-clock between turns is not —
the box sits idle whenever a turn is thinking, and completely idle whenever the
loop is between tasks.

Make the soak run itself: an unattended, low-priority, INTERRUPTIBLE T443 soak
that accumulates runs in the background and gets out of the way the moment a
turn needs the box.

## In plain terms

We are waiting for a rare crash to show up again, and we can only afford to look
for it a few minutes at a time. The machine is idle most of the day. This is
about letting the search run in that idle time, so the odds accumulate without
costing us working sessions.

## Details

Constraints that make this non-trivial, and are why it is a task rather than a
one-liner:

- **It must never be the thing that wedges a turn.** An acceptance script takes
  the per-user pipe and kills agents; a lane run starved by a background soak
  wedges (T401), which is the exact failure the soak is supposed to measure
  around. So the background soak has to be killable on demand and must not hold
  the lane's zig cache — the isolation `-LoadKind build` already composes for
  its load workers is the pattern.
- **Its results must land somewhere durable**, appended as data points (runs,
  crashes, condition) rather than lost with the process — a crash it catches is
  the whole point, and T443's unblock rule expects a named occurrence.
- **A crash must actually be captured**, not merely counted: the run needs the
  crash-catch path armed so the next occurrence yields a dump and the sweep's
  panic text naming the corrupting test.
- Candidate hosts: the go-loop watchdog (already a per-user scheduled task that
  ticks every 10 minutes), or a separate scheduled task gated on the box being
  idle and no lane running.

## Validation criteria

- [ ] Runs accumulate without a turn spending time on them, and the count is
      visible somewhere a turn can read in one command
- [ ] A turn that starts while the soak is running is not slowed or wedged by it
      (the soak yields; demonstrated, not asserted)
- [ ] A crash the background soak catches produces the same evidence a
      foreground one would (dump + panic text + lane log), and T443's log gains
      the data point
