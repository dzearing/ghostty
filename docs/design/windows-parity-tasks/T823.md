# T823 - A Windows pane comes back as a shell, not a re-run, after a reboot

## Summary

Port main's session-relaunch=restore|rerun|prompt policy (default restore) to the Windows client: a restored pane opens the recorded cwd in a plain login shell of the pane's flavor instead of re-executing its recorded --command. Upstream c76b5c89d.

## In plain terms

Right now, rebooting the machine brings your windows back by re-running
whatever command each pane was started with — so a pane that was running an AI
coding session comes back as a brand-new session that has forgotten
everything. After this lands, a restored pane comes back as an ordinary shell
sitting in the folder it was in, under a short notice saying the previous
session was lost. Anyone who reboots with work open notices.

## Goals

- [ ] a `session-relaunch` setting with `restore` / `rerun` / `prompt`, defaulting to `restore`
- [ ] `restore` asks for a login shell of the pane's Windows flavor (pwsh / cmd / wsl), not `<shell> -li`
- [ ] the restored shell starts in the session's recorded working directory
- [ ] `rerun` still re-executes the recorded command, as an explicit opt-in

## Details

Upstream `c76b5c89d` (main, 2026-08-12) made the policy client-side: the
agent's synthesized relaunch OPEN already drops the recorded command when the
viewer supplies `Relaunch.argv`, so `restore` is "ask for a login shell". The
Windows translation is the shell-flavor invocation this repo already uses
elsewhere (`pwsh -NoExit -Command`, `cmd /K`, `wsl --`) in place of the Mac
`<shell> -li`.

That commit also fixed the agent never writing `Session.cwd` (only
`materialize` set it, so it was permanently null and every reboot respawn
landed in whatever cwd the agent happened to have). The agent is one codebase
for both platforms, so the fix arrives with the merge — but a restored Windows
pane landing in the right directory is a validation check here, not an
assumption.

## Validation criteria

- [ ] `session-relaunch` parses all three values and defaults to `restore` (unit test, `none` lane)
- [ ] on-box: a reboot-equivalent cycle restores a pane as a live shell with a fresh pid, in the recorded cwd, with the recorded command NOT re-run
- [ ] on-box: `session-relaunch=rerun` still re-executes the recorded command
- [ ] the "previous session was lost" notice is visible after restore (see T824 for the notice plumbing)
- [ ] floor green: both zig lanes + `test-agent` + P1-P3
