# T465 - A window waiting on the user reads (needs_input) in its title instead of (question)

## In plain terms

When an agent in a pane stops to ask you something, the window title says
`(needs_input)`. That is the name the machine uses, not a word anyone would
write in a title bar. The Mac now shows `(question)` there. Windows should
read the same.

## Goals

- [x] A window in the `needs_input` state shows `(question)` in its title
- [x] `idle` and `busy` are untouched
- [x] The machine tokens stay exactly as they are: `+set-state --state=`,
      the OSC 7777 payload, and the accessibility attribute all keep
      `needs_input` — pinned by a test so a later tidy-up cannot break live
      hook config

## Evidence

`src/apprt/win32/Window.zig:3231` interpolates the raw token:

```zig
.needs_input => std.unicode.utf8ToUtf16LeStringLiteral(" (needs_input)"),
```

The Mac fix (d0c056ee5) split the two names apart rather than renaming
anything: `ActivityState.displayLabel` is the human-facing string and is the
only thing the title uses, while `rawValue` stays the machine token. The
commit is explicit that the three token consumers are a public API — user
hooks invoke the CLI, and external tools (ztabby) read
`AXWindowActivityState` — so they must not follow a change made for
readability. `ActivityStateLabelTests.swift` asserts both halves; the win32
equivalent should assert both too.

Note `src/cli/set_state.zig` also gained two lines in that commit and
arrived with the merge — check what it says before duplicating it.

## Validation

- [x] Unit tests in `src/terminal/osc.zig` assert both halves: `displayLabel()`

      Green in both `none` and `win32` lanes (`floor-lane.ps1 -Lane all`:
      lib/none/win32/agent all PASS).
- [x] `test\win32\ipc-p3.ps1` ALL PASS (16 assertions) — including

- [x] `test\win32\conformance.ps1` ALL PASS — `needs_input beats busy`,

- [x] `ipc-p1.ps1` / `ipc-p2.ps1` ALL PASS; `guard-due.ps1 check` exits 0
