# T1310 - An acceptance script can throw halfway through and still print ALL PASS - the sections after the throw never run and nothing says so

## Summary

Found while adding the rotation section to test\win32\log-append.ps1 (T410). The script sets ErrorActionPreference=Continue and wraps its body in one try/finally, so a .NET exception raised in a late section (a path that stopped resolving, a file that could not be written) is TERMINATING: it abandons every remaining section, runs the finally, and then prints the summary - which, with zero recorded failures, is ALL PASS and exit 0. Observed directly: a broken seed helper reported ALL PASS (12) while the whole rotation section had silently not run. Worse, an exit 0 STAMPS the T783 harness guard, recording that the harness was run over code it never looked at. T410 fixed its own script with an explicit section-completed assertion; the shape is generic - most scripts in test\win32 have exactly one try/finally around many sections. Wanted: a rule the harness auditors can enforce (each script proves its sections ran, e.g. a completion assertion per section or a catch that records a failure), plus a sweep of the existing scripts for the same hole.
