# T1137 - A red acceptance script is filed as a user-facing defect without anyone re-running it alone

## In plain terms

When the full test sweep runs, every test that comes back red is written up as
a broken feature — "opening a second window silently does nothing", "attaching a
screenshot loses the picture". Some of those tests are red because the test
itself is wrong, not the app. Nobody checks which before writing it up, so work
that is really a five-minute test repair arrives at the top of the queue
described as a user-facing outage, and the person who picks it up spends their
whole turn discovering the feature was fine.

## Summary

T1094's sweep (242 scripts) filed 31 tasks from red logs. The two worked so far
were both defects in the HARNESS, not the product:

- **T1102** — four feedback scripts drove a control the app was no longer using,
  and typing into it silently emptied the real one. The feature worked.
- **T1103** — `viewer-popup.ps1` snapshotted the popup into the set of windows it
  had been told to ignore, so it could never find it again. The feature worked;
  the same run's later sections located the popup by its window title and closed
  it.

Both were filed as P1 with a user-facing symptom sentence, because a red log
reads like a broken feature and nothing in the filing path distinguishes the two.

The missing step is cheap: **re-run the red script once, on its own, before
filing**, and record the outcome in the task. A script that is green alone and
red in the sweep is a harness or isolation defect and should be titled and
priced as one; a script red both times is a product defect and keeps its P1.

## Where

- the sweep's filing path (whatever `T1094` used to turn a red log into a task)
- `docs/claude/testing.md` — the rule belongs beside the other harness rules

## Goals

- [ ] Re-run each still-open sweep-filed task's script once, alone, and record
      `reproduced alone: yes/no` in the task file.
- [ ] Re-title and re-price the ones that do not reproduce — a harness defect is
      not a P1 user-facing outage.
- [ ] Make the check part of the filing path, so the next sweep files the answer
      rather than leaving it to be discovered.
- [ ] Write the identity rule the T1103 defect broke into `docs/claude/testing.md`:
      a window under test is identified by the name the test GAVE it, never by
      "the one that was not there a moment ago" — the second form races anything
      the page under test does on load.

## Validation criteria

- [ ] every open task filed by T1094's sweep carries a `reproduced alone:` line
- [ ] at least the ones that are green alone are re-titled and re-priced, with
      the re-priced ones named in the task's progress log
- [ ] `docs/claude/testing.md` carries both rules (re-run before filing; identity
      by name), and a sweep of `test/win32/` finds no other script computing "the
      window that is not in a set snapshotted after something could have created it"
