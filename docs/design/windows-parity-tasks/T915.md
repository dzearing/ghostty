# T915 - Observe a real Google sign-in completing in a delivered Windows build

## Summary

T795 made the bake real and observable - a build's client id is now printed by +version, the release pipeline bakes the GOOGLE_CLIENT_ID secret on both seats, and a delivery warns when it is shipping a build that cannot sign in. What has still never been seen is the end of the flow: a DELIVERED Windows build (installed release or portable) opening a browser, completing consent against a real relay, and coming back signed in with the account row showing the email. That needs the actual client id, which only the user has (D72's resolution asks for it in a git-ignored google-client-id.txt at the repo root) and a reachable relay with brokered sign-in configured. Until then this seat can prove everything except that the credential is the RIGHT credential. When the file exists: rebuild, deliver, and run test\win32\relay-account.ps1 without GHOSTTY_GOOGLE_CLIENT_ID so the shipped configuration is the one under test (see T796).
