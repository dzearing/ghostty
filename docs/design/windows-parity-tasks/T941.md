# T941 - The tab strip and caption probes still take the torn photo - convert the main-window chrome scripts to the synchronous capture

## Summary

T843's second half for the main `Window` class, unblocked by T940's
`WM_PRINTCLIENT` handler. Switch every `Get-TestWindowPixels` call that
photographs the top-level app window to `-Sync`, and re-run each script several
times to confirm the flake is gone rather than moved.

Scripts, from the T843 survey: `tab-strip.ps1`, `tab-color.ps1`,
`caption-bar.ps1`, `chrome-theme.ps1` (the `$g.Top`/`$h` sites),
`chrome-merged-row.ps1`, `close-glyph-white.ps1`, `hero-mode.ps1`,
`hero-viewer-tile.ps1`, `hover-capture.ps1`, `menu-bar.ps1` (the `$g.Top`
site), `remote-pill.ps1`, `split-divider.ps1`, `title-font.ps1`,
`title-jitter.ps1`, `window-color.ps1`, `readonly-badge.ps1`, and the shared
`lib/ChromeGeometry.ps1` helper.

`lib/ChromeGeometry.ps1` is the leverage: it captures on behalf of several of
those scripts, so converting it converts them together — do it first and see
what is left.

## In plain terms

Most of the tests that check how the window's chrome looks are working from a
photograph that can come out half-taken. This points them at the steady one.

## Validation criteria

- [ ] No `Get-TestWindowPixels` call targeting the top-level window is left
      without `-Sync` (or a comment saying why it cannot have it)
- [ ] Every converted script is ALL PASS over at least 3 consecutive runs
- [ ] The measured flake rate before and after is written into this file, so
      "the flake is gone" is a number rather than an impression
