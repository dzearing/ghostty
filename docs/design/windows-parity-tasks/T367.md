# T367 - T56c: win32 remote connection status affordance (green/yellow/red pill + Reconnect)

## In plain terms

When a Ghoztty window is running its shells on another machine and that machine
goes away — laptop lid, VPN drop, the other box rebooting — the window on your
screen looks exactly the same as it did a second earlier. You find out by typing
into it and watching nothing happen. This puts a small coloured chip in the
titlebar: green while the connection is fine, amber while it is retrying (with
how many tries are left), and a red **Reconnect** button once it has given up,
which dials again the moment you click it.

## Goals

- [x] A remote window's titlebar shows a connection chip; a local window does not.
- [x] Green when connected, amber while the ladder retries, red when it is down.
- [x] The red state is a button and clicking it re-dials immediately.
- [x] Every ladder transition repaints the chrome, so the chip cannot go stale.
- [x] Geometry and contrast asserted at 1.0/1.25/1.5/2.0 in a pure module.
- [x] The chip never costs a terminal row, and never eats a patch of the drag band.

## Validation criteria

- [x] `caption_layout.zig` unit tests: the pill's placement, its group gap, the

## What this task does NOT fix

The Reconnect button correctly reaches `RemoteReconnect.manualReconnect` and the
dial goes out immediately — but if the remote SESSION is gone (a restarted
agent, a rebooted machine), the driver takes its `.terminal` arm instead of
opening a fresh shell, so the pill stays red. The policy already models the
right answer (`onProbeOutcome`'s `fresh_session_on_gone`); the driver calls it
with a hardcoded `false` and asserts the case away. That is T366's half, this
task is its first caller, and it is filed as **T611** with the measured log
evidence. The acceptance script asserts the ATTEMPT rather than the recovery
for exactly this reason, and says so in its header.

## Summary

Split out of T56 (WP-D1 remote reconnect on win32), 2026-08-02. The user-facing
half: a Windows-native equivalent of Mac's machine status pill.

## Details

Mac's `MachinePillView.swift` renders the WP-D1 state as a coloured dot in the
titlebar - green connected, **yellow reconnecting (with the attempt number)**,
red disconnected - and once retries are exhausted the pill grows a prominent
**Reconnect** button wired to `manualRemoteReconnect()`. Windows has nothing:
a dropped remote window looks the same as a live one until you type into it.

Build the win32 equivalent against
`docs/design/win32-design-system.md` (mandatory): the caption/tab band already
hosts the menu "..." button since T234/T205, so the affordance has a home that
costs no terminal rows. Colour alone must not carry state (design-system rule)
and the contrast floor for chrome glyphs is 3:1.

*Validation:* geometry asserted in the pure layout module at 1.0/1.25/1.5/2.0,
plus an on-box pixel/behaviour script driving the state through T365's policy.

## Both halves this plugs into already exist (T366, 2026-08-08)

Nothing here has to invent state or drive a dial. The driver landed with both
seams cut:

- **What to paint** is `Window.reconnect.ladder`, a
  `remote_reconnect.WindowState` — `connected` / `reconnecting{attempt}` /
  `disconnected{self_healable}`. The pill's three colours map onto exactly those
  three cases and the attempt number is already in the payload. It changes only
  on the GUI thread, so reading it in a paint handler needs no locking; repaint
  on change is what is missing (the driver mutates it without invalidating any
  chrome).
- **What the Reconnect button calls** is
  `RemoteReconnect.manualReconnect(app, window)`. It already does the whole
  manual contract: starts from ANY disconnected tier including terminal, resets
  the poisoned-session breaker (a click is fresh evidence), and dials
  immediately instead of waiting out a backoff. It has no caller yet — this task
  is its caller.

Two things worth deciding here rather than inheriting: the pill should only
appear on a window with a `remote_dialed` transport (a local window has no
machine to be connected to), and `disconnected` covers both the still-hoping and
the terminal tiers — `self_healable` is what tells them apart, and Mac shows the
Reconnect button prominently once the fast ladder is exhausted.
