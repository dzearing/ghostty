# T927 - Test harness: no way to synthesize a real user input event into a WebView2 page

## Summary

The host-floor viewer test drives pages with ExecuteScript, which carries user activation of its own - so it can stand in for a click but cannot tell a click apart from a page navigating itself. T825 needed exactly that distinction and both DevTools routes tried (Runtime.evaluate with userGesture:true, and Input.dispatchMouseEvent) returned S_OK from CallDevToolsProtocolMethod and had no effect on the page, which cost a context to discover. T825 worked around it with a page that navigates itself at load time. Find out why the CDP input path is inert (session/domain enable? a completion handler the null argument skips?) and give the harness a real press, so the next test that needs one does not re-derive this.
