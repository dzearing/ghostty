# T667 - session-persistence.ps1 cannot be run from inside a Ghoztty pane

## In plain terms

One of the big automated checks refuses to start when it is launched from a
Ghoztty window — which is where every session on this box runs. It stops with
an ABORT that reads like the app is broken, when in fact the check is pointing
at the wrong terminal and (correctly) refusing to touch it.

## Summary

`test/win32/session-persistence.ps1` guards hermeticity by running
`& $Exe +list` and aborting if anything answers:

```
ABORT: a Ghoztty instance is ALREADY answering on the endpoint '...\zig-out\bin\ghoztty.exe' uses.
```

The guard is RIGHT — but it fires for the wrong reason. Run from inside a
Ghoztty pane, the CLI resolves the pane's baked `$GHOZTTY_IPC_SOCKET` (T118
instance addressability) and dials the USER'S release instance, which answers.
The script never sets a `GHOZTTY_PIPE_SUFFIX`, and the suffix is the one thing
that outranks the baked value, so its every CLI call really would be aimed at
the user's terminal.

Every other restore script in `test/win32/` already solves this by calling
`Set-GhozttyTestIsolation` (`lib/Isolation.ps1`, T441). This script predates it
and was never converted; T652 had to set `$env:GHOZTTY_PIPE_SUFFIX` by hand to
run it at all.

## Details

- Fix: `. lib/Isolation.ps1` + `[void](Set-GhozttyTestIsolation -Tag 'sessionpersist')`
  before the existing guard, then `Assert-GhozttyPrivateEndpoint -Exe $Exe`, so
  the guard measures the endpoint the harness will actually use.
- Keep the existing build-mode refusal (T350) exactly as it is — the agent pipe
  is build-mode-derived and no suffix makes a release run safe.
- Worth checking the same gap in any other script that guards with a bare
  `+list` rather than through `Isolation.ps1`.

## Validation criteria

- [ ] `powershell -NoProfile -File test\win32\session-persistence.ps1` runs to
      completion when launched from inside a Ghoztty pane, with no
      hand-set environment variable.
- [ ] It still ABORTS when pointed at a release exe (the T350 guard is intact).
- [ ] The endpoint it drives is the private one — asserted by
      `Assert-GhozttyPrivateEndpoint`, not inferred.
