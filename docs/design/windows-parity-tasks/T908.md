# T908 - Mac: non-destructive agent upgrade - carry live sessions across an agent restart (holder mode or SCM_RIGHTS handoff)

## Summary

The Mac seat's half of T705 (design + constraint table:
`docs/design/agent-nondestructive-handoff.md`). Same defect as T662/T705: the
running agent only advances at zero live sessions or via the mandatory
confirmation.

POSIX changes the trade: the PTY master **fd is fully transferable** over
`SCM_RIGHTS` (no HPCON wall), but child-reaping is NOT - the new agent is not
the parent, so `waitpid` is lost and exit must be observed via
`kqueue`/`EVFILT_PROC NOTE_EXIT`, with the exit code degraded. The Mac seat
picks the mechanism:

- **fd handoff** (old agent passes master fds + metadata to the new agent over
  a unix socket, then exits), or
- **holder mode**, matching the Windows architecture one-for-one (also buys
  crash survival), at the cost of a process per session.

Either way the choreography rules from the design doc hold: READY-gated
takeover, a failed handoff leaves the ORIGINAL agent serving, additive
`sessions.json`/protocol evolution, lazy drain for sessions that cannot be
carried.

## Validation criteria

- [ ] A running Mac agent adopts a newer build with live sessions open, no
      dialog, no session lost (type into a pane before and after).
- [ ] A failed handoff leaves the original agent running and its sessions
      reachable.
- [ ] Skew both ways degrades per the agent contract.
