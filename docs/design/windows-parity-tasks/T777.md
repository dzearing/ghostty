# T777 - Nothing runs the six static harness audits, so a property that 'cannot silently regrow' regrows until somebody remembers to type the script

## In plain terms

Over the last months six small checks were written that read the test suite
itself and catch a test that lies - one that reports a pass having measured
nothing, one that prints a failure but exits success, one that steals the user's
focus without saying so. Each of them works. None of them is run by anything: a
person has to remember to type the command. So the guarantee they were built to
give lasts exactly as long as somebody's memory.

## Summary

Six static analyzers under `test\win32\` score the SUITE rather than the
product:

| script | property it keeps at zero | filed by |
| --- | --- | --- |
| `harness-exitcode-audit.ps1` | no `Start-Process -PassThru` exit code read without caching `.Handle` | T197 |
| `skip-visibility.ps1` | a section the run SKIPPED is named in the verdict line | T219 |
| `verdict-exit-audit.ps1` | a script that PRINTS failure EXITS failure | T221 |
| `asserted-nothing.ps1` | a run that asserted nothing is not a pass | T271 |
| `foreground-audit.ps1` | an undeclared foreground grab is a finding | T272 |
| `build-mode-guard.ps1` | an acceptance run refuses a release `zig-out` | T350 |

**Measured 2026-08-11**: grepping the whole repo for their names finds only the
scripts themselves and their own libraries. No suite driver, no lane, no
`floor-lane.ps1` mode and no CI step invokes any of them. Each one is therefore
a snapshot: it proved the property on the day it was written, and says nothing
about today unless a turn happens to run it.

That is the same failure shape each of them was filed for. T272's own history is
the clearest case - the migration closed at 23 of 23 and 13 of 13 while two
scripts sat outside both buckets, because nothing counted the remainder.

## The fix

1. One driver - `test\win32\harness-audits.ps1` - that runs every static audit
   and prints ONE verdict through `lib\TestScore.ps1`. It must enumerate the
   audits from a list it owns and FAIL when an audit script exists that the list
   does not name, or the driver becomes the next thing that silently misses one.
2. Wire it into the standing floor so it runs with the lanes rather than on
   memory: `scripts\floor-lane.ps1` is the natural home (it already ends with a
   PASS/FAIL/STALL verdict), most likely as a fast lane of its own so it does
   not pay for a zig build.
3. It is static analysis - no GUI, no app launch, seconds to run - so there is
   no reason for it to be opt-in.

## Validation criteria

- [ ] `test\win32\harness-audits.ps1` runs all six and reports one verdict.
- [ ] It FAILS when any single audit fails (prove it by breaking one).
- [ ] It FAILS when a new `*-audit`-shaped script is added that its own list
      does not name.
- [ ] The standing floor runs it, and a red audit turns the floor red.
