# T846 - Nothing runs the test suite at ReleaseSafe, so build-mode-only defects reappear silently

## Summary

Every lane in the floor — `none`, `win32`, `agent` — builds the tests at
**Debug**. `-Dtest-optimize=ReleaseSafe` exists (T473 added the knob) but
nothing runs it, so a defect that only Debug masks lives in the tree
indefinitely.

T477 is the proof that this is not hypothetical. Two real defects were sitting
in the tree at once, both invisible to 26 consecutive green Debug runs:

- `free()` on an `undefined` slice in `src/renderer/cell.zig` — UB that
  ReleaseSafe compiles to an `int 3`, and which the *shipping* renderer also
  executes on its first `resize()`.
- A test returning a pointer into a dead stack frame in
  `src/apprt/win32/App.zig` — Debug left the memory intact, ReleaseSafe reused
  it and segfaulted 10/10.

Both are the same class: code whose correctness Debug's allocation and frame
behavior accidentally provides. The suite is clean at ReleaseSafe as of T477,
so this is the cheap moment to nail that down — a clean baseline is what makes
a future red run mean something.

## In plain terms

Our tests are only ever compiled one way. Two genuine bugs — one of them in
code that ships to users — hid behind that for weeks, because the way we
compile tests happens to paper over them. Running the same tests compiled the
way real builds are compiled catches that class of bug, and right now nothing
does.

## Goals

- [ ] The ReleaseSafe test binary gets built and run somewhere that fails
      loudly — a `floor-lane.ps1` lane, or a scheduled/periodic sweep
- [ ] Decide and record whether it belongs in the per-turn floor (it costs a
      full extra build plus ~85s a run) or on a slower cadence
- [ ] A red ReleaseSafe run names the victim test, as `test-binary-soak.ps1`
      already does

## Details

- Build knob: `zig build -Dapp-runtime=win32 -Demit-test-exe
  -Dtest-optimize=ReleaseSafe --prefix zig-out-t473\win32-releasesafe`.
- Runner: `scripts\test-binary-soak.ps1 -Exe … -Runs N` already reports
  `pass/fail/crash` and names the victim test on a crash.
- Note the diagnostic gap this class has: these crashes take an `int 3` with
  **no stderr message**, and `crash-catch.ps1` reports them as a clean run
  (T478). A lane that only checks for output would call a crash a pass; gate on
  the exit code (`0x80000003` → exit 3), which is what `test-binary-soak.ps1`
  does.

## Validation criteria

- [ ] Running the new lane/sweep against HEAD is green.
- [ ] Reverting either T477 fix locally makes it red, and the red run names the
      test that died.
- [ ] The floor's wall-clock cost is measured and recorded in the task, so the
      cadence decision is made on a number rather than a guess.
