# T1118 - One fewer U-file reproduces from the fork point than fork-identity.ps1 requires

## In plain terms

A check that confirms this fork's own branding files still match what they should, expects 28 of them and found 27. Either a file legitimately changed and the number needs updating for a good reason, or something was genuinely lost.

## Summary

`test\win32\fork-identity.ps1` scored `FORK-IDENTITY: 1 FAILURE(S) / 48 passed` in the T1094 sweep:

```
FAIL C4 at least 28 of the U-files reproduce from the fork point reproduced=27 baseline=28
```

48 assertions pass. The one that fails is a THRESHOLD (`at least 28`) against a measured 27, which is a brittle shape: any legitimate edit to one of those files moves the number and reds the script without saying which file or why.

The triage is therefore two-part and the second part matters more than the first: find out WHICH file stopped reproducing and whether that is correct, then decide whether a bare count is the right assertion at all. A failure that cannot name the thing that changed costs a whole investigation every time it fires.
