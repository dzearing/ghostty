# T558 - Mac seat: confirm the shared selection.js hide-quote flag edit (T162) keeps Mac viewer quote/selection tests green

## In plain terms

The little Copy/Quote toolbar that pops up when you select text in a viewer
pane is one shared piece of code used by both the Mac and Windows builds.
Windows just changed it slightly (it hides the Quote button there until
Windows has somewhere to send a quote). The change is designed to leave the
Mac exactly as it was — this task is the Mac-side check that it really did.

## Summary

T162 added one additive guard to `src/viewer/selection.js`: the Quote button
is only appended when `window.__ghozttyHideQuote` is NOT set. Only the win32
injected blob (`src/apprt/win32/viewer_bridge.zig`) sets the flag; Mac never
does, so Mac keeps both buttons. This is the first edit to that shared file
made from the Windows seat, and the standing rule is that a shared-file
change is validated on both platforms — the Windows half was proven live
(win32 lane, `copy[md]`/`copy[web]` clipboard round trips); the Mac half is a
test run only the Mac seat can do.

## Goals

- [ ] Run the Mac viewer test suite (at minimum `ViewerFeedbackQuoteTests`)
      on a tree containing the T162 edit.
- [ ] Confirm the selection toolbar still shows BOTH Quote and Copy in a Mac
      viewer (the flag is never set there).

## Validation criteria

- [ ] Mac test suite green on a checkout that includes the `selection.js`
      edit (name the run).
- [ ] A live Mac viewer selection still offers Quote and Copy (manual check
      or existing automated coverage — say which).
