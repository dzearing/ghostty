# T880 - Document +send-keys --busy-marker in the ghoztty SKILL.md (macos/Resources source of truth)

## Summary

T517 removed the last tool-specific pattern-match from product code:
`+send-keys --when-idle` no longer bakes in Claude Code's "esc to interrupt"
busy marker. Busy detection is now motion-based by default (tail unchanged
across ~1s = idle), and a new repeatable `--busy-marker=<text>` flag lets a
caller that knows its program's busy chrome supply the marker itself.

The ghoztty skill document still describes the old behavior ("until it no
longer shows `esc to interrupt`"). Its source of truth is
`macos/Resources/Ghoztty/skills/ghoztty/SKILL.md` on main — the win32 vendored
copies (`src/apprt/win32/assets/ghoztty/{skills,upstream/skills}/ghoztty/SKILL.md`)
are asserted byte-identical to origin/main's copy by `test/win32/hook-json.ps1`,
so the Windows seat cannot edit them unilaterally.

## In plain terms

The instructions that teach an AI agent how to drive Ghoztty still describe an
old behavior of the "wait until the pane is idle before typing" feature. The
feature now works for any program, not just one specific tool, and grew a new
option; the instructions should say so. The file that feeds those instructions
lives on the Mac side of the project, so the Mac seat makes the edit.

## What to change

In `macos/Resources/Ghoztty/skills/ghoztty/SKILL.md`, the `+send-keys` flag
table:

- `--when-idle`: poll every 500ms until the tail is unchanged across ~1s (a
  working TUI animates spinners/timers; an idle prompt is static) and no
  `--busy-marker` text is present. Sends anyway on timeout or unreadable pane.
- Add `--busy-marker=<text>`: extra busy signal; while the text appears in the
  pane's last lines the pane counts as busy even if static. Repeatable. Only
  needed for a program that shows busy chrome without animating (e.g. old
  Claude Code < 2.1.207 rendered "esc to interrupt"; current versions animate,
  which motion detection already catches).

Once the edit lands on main, the Windows vendored mirror + live copies converge
on the next asset refresh (the hook-json harness flags the drift).

## Validation criteria

- [ ] After the Windows asset refresh, `test/win32/hook-json.ps1` is green with the updated copies.
