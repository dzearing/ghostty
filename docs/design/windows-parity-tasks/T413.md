# T413 - Cross-machine Restore All still uses the full-ring replay: layout blobs carry no WP-D3 snapshot

## In plain terms

When you pull another machine's terminal windows onto this one, each pane has to
re-send its recent history before it settles, rather than coming up instantly
the way a pane does when this machine restores its own windows. The question was
whether to fix that by storing a picture of each pane's screen alongside the
saved window layout. The answer is no — the pane already comes back showing the
right thing, the picture would be someone else's and out of date, and the part
that is genuinely still slow is fixed better elsewhere. What changes here is
that the reasoning is written down and checked by a test, so nobody re-opens it
by guessing.

- [x] settle the design question and record it where the next reader will look
- [x] pin the decision with a test on both sides — the decode path and the box

## Summary

T109 gave the LOCAL session-layout manifest a per-pane screen snapshot, so a
same-machine re-attach paints our own repaint and asks the agent for a delta.
"Restore All" (T321/T334/T336) rebuilds a topology from the AGENT-held layout
blobs instead, and `layout_blobs.serializeWindow` deliberately STRIPS the
snapshot fields - so every blob-sourced pane still takes the pre-T109 full-ring
replay, with the mixed-geometry loss T109 exists to remove.

## Details

The strip is a considered decision, not an oversight, and any fix has to beat
the reasons for it:

- A blob is re-serialized and pushed to the agent on **every layout mutation**,
  and `blobHash` skipping the unchanged ones is what keeps that mirror cheap. A
  snapshot changes on every capture, so every window would re-upload forever.
- A blob is ~1 KB of topology. A 600-row VT repaint is two orders of magnitude
  larger, per pane, held on the agent's disk.

So this is not "un-strip it". The shapes worth weighing:

1. **A separate, less chatty channel.** Push the snapshot on its own cadence
   (on detach / on a long idle, not on every mutation) under its own key, so the
   topology blob stays small and hash-stable. Costs a new agent-side store.
2. **A much smaller snapshot for the blob** - viewport only, no scrollback -
   accepting a smaller win for a much smaller blob.
3. **Close as won't-fix**, on the grounds that a cross-machine Restore All is
   already re-attaching over a network where a ring replay is the smaller of the
   costs. If so, say it in the design doc rather than leaving the asymmetry
   looking accidental.

Whichever way it goes, the local manifest path must not regress: it is not
pushed anywhere and should keep carrying the full snapshot.

## Resolution (option 3, with evidence)

Keep the strip. Blobs stay topology-only.

The premise had aged. A blob-sourced attach today is not the pre-T109 smear:

- **T106** reflows the client grid to the agent-reported CAPTURE geometry for
  the replay and back to the live grid once it is fully applied
  (`termio/Remote.zig`, the `attach_offset == 0` branch).
- **FIX 2** has the agent append its OWN grid snapshot after the gap-fill — a
  self-contained VT repaint of the visible screen, generated at the geometry the
  attaching client just asked for (`agent/server.zig` `want_snapshot` →
  `agent/session.zig gridSnapshotAlloc`, which `ensureSize`s to the just-applied
  attach dimensions).

So the visible screen is already exact cross-machine. What remains is the
replay's wire cost and imperfect scrollback for ring segments drawn at older
geometries.

And a stored snapshot could not close that: it would be whatever viewer last
pushed the blob, at that viewer's geometry and offset — stale by construction for
a machine still in use, and a stale offset makes the agent emit its "bytes of
scrollback lost" marker for bytes it still holds. The agent's own snapshot is
fresh, correctly sized and free. The single thing it lacks is scrollback, because
its emulator runs `max_scrollback = 0`. That is where the remaining gap belongs,
and it fixes cross-machine Resume-one too — a session this viewer never had open
has no local manifest entry either, so no blob change could ever have helped it.
Filed as **T621**. Decision receipt: **D40**.

## Validation

`test/win32/session-snapshot-reattach.ps1` is the shape to copy - its C section
reads the app's own `attach: session=... offset=N snapshot=M` line to tell the
delta path from the full-ring path, which is the only way to tell them apart
from outside. A cross-machine arm asserts the same line for a Restore All
against a relay/loopback agent.
