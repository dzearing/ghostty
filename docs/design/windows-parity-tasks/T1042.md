# T1042 - 32 acceptance harnesses have been DUE since the body-complete sweep, so every commit since routes around the staleness gate

## Summary

abc2de0f3 (T1039) added the Complete-TestBody marker to ~30 test\win32 harnesses. Each harness's guard row covers its own file, so every one of them went DUE the moment it was edited and none has been re-run: guard-due check reports 32 DUE (job-escape-startup, the pty-host/holder family, agent-*, upgrade-*, activity-*, machine-chooser, task-dashboard, test-desktop, docs-routing and the rest). parity-tasks validate FAILS on that, which means every turn since has had to pass -NoGuardDue - so the one mechanism that makes an unrun harness visible is being routed around on every commit, which is exactly the state T783 exists to prevent. The work: re-run each DUE harness against HEAD (a clean green run re-stamps), fix whatever the sweep's mechanical edit actually broke, and land the stamps. Some of these are long GUI runs, so it is likely several turns - split it if so. docs-routing is due for a different reason (docs/claude/testing.md changed) and is a one-minute run.

## In plain terms

There is a check that asks "has anybody actually run this test since the code it
watches changed?" - and right now it is answering "no" for 32 of them, so every
commit has to switch it off to get past. Nobody is doing anything wrong; a single
mechanical edit touched all those test files at once and none has been re-run
since. Until they are, the alarm is permanently muted, which is the one state it
was built to prevent.

## Validation criteria

- [ ] `powershell -NoProfile -File scripts\guard-due.ps1 check` exits 0
- [ ] every re-run that went green re-stamped (the stamp files are in the commit)
- [ ] anything the sweep's edit actually broke is fixed rather than stamped over
      - a harness that comes back red stays red and gets its own task
- [ ] `scripts\parity-tasks.ps1 validate` passes with NO `-NoGuardDue`
