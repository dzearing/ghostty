# T1408 - A torn zig PACKAGE directory fails every lane, and the cache heal does not recognize its shape

## Summary

The JetBrainsMono package under D:\zig-global-cache\p\ lost its whole fonts\ subtree (only AppleDouble ._fonts metadata left), and every one of the four floor lanes then failed in 5 seconds with 'error: failed to check cache: <...>\JetBrainsMono-Regular.ttf file_hash FileNotFound'. scripts\lib\CacheHeal.ps1 recognizes a torn cache ENTRY - a compile error or declaration note whose file location sits inside .zig-cache or the global cache - and this is a torn fetched PACKAGE, named by a 'failed to check cache' line with no file:line:col, so Get-TornCacheEntry returned nothing and the lane read as a code failure. Remedy once known: delete the package directory and re-run (zig re-fetches). Add the shape to Get-TornCacheEntry, with the delete aimed only at <global-cache>\p\<hash>, and a planted-log fixture in test\win32\floor-lane-cache-heal.ps1.
