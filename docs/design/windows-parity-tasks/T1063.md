# T1063 - The MSI packaging guard can only be cleared by starting Docker, which this box is not allowed to do

## Summary

`release-artifacts-packaging` is stamped only by a zero-skip run of
`test\win32\release-artifacts.ps1`, and its one Docker-gated check (B1, the
FILEVERSION rule under `msitools-local`) cannot run here: the user has
standing-directed that Docker Desktop and WSL are never started on this box
(2026-08-16, "you are murdering the computer" - the WSL2 backend took 28 GB).
So any edit to `dist/windows-installer/build-msi.sh` leaves a row that no turn
can clear, and the commit goes out under `-NoGuardDue`. T1052 was the first.

## In plain terms

There is a safety check that asks "has anybody tested the installer builder
since it changed?" On this machine the answer can never become yes, because the
only tool that can answer it is one we are not allowed to run here. So the
check is permanently red, and the habit it teaches is to wave it through -
which is exactly the habit it exists to prevent.

## Details

The evidence the row wants already exists somewhere else: `fork-ci.yml`'s
`windows-cross` job runs `dist/windows-installer/build-release-artifacts.sh` on
a Linux runner with msitools installed, on every push to
`users/dzearing/windows-amd64` (asserted by sections E1-E5 of the same
harness). That job builds the real MSI from the real script. A green run of it
is stronger evidence than a local Docker run of one static assertion.

Shapes worth weighing:

- Let a green `windows-cross` run for the current commit stamp the row -
  `scripts\guard-due.ps1` would grow a "stamped by CI" source (e.g. `gh run
  list --workflow fork-ci.yml --commit <sha>`), which makes the stamp depend on
  the network but on nothing this box has to launch.
- Move B1's substance into the CI job itself and drop the local Docker path,
  so the row's `RunArgs` names something runnable here.
- Keep the row as-is and accept `-NoGuardDue` on MSI edits, documented at the
  row - the status quo, and the reason this task exists.

T1052 already split the ZIP half onto its own row
(`release-artifacts-zip`), which needs only bash + python3 and is clearable
here; this is the remaining half.

## Goals

- [ ] An MSI-builder edit can be validated and committed on this box without
      `-NoGuardDue`
- [ ] Whatever clears the row is real evidence that the MSI was built from the
      edited script, not a weaker substitute

## Validation criteria

- [ ] `test\win32\guard-due.ps1` ALL PASS with a check covering the new
      clearing path
- [ ] Edit `dist/windows-installer/build-msi.sh`, run the sanctioned command,
      and `scripts\guard-due.ps1 check` exits 0 with Docker never started
