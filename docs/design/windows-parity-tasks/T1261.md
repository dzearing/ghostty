# T1261 - The first automatic end-of-day publish has to be watched end to end, from the release to the update landing on the user's terminal

## In plain terms

From now on the loop publishes a Windows release at the end of each working
day, and your terminal picks it up through its own update notification. That
whole chain has never actually run by itself: T1220 built and tested the
decision, the version scheme and the skip paths, but the box it was built on
had Docker down, so nobody has yet watched an automatic publish go all the way
from "the loop finished a task" to "the update offer appeared and installing it
gave me that version".

## Summary

T1220 added `scripts\daily-publish.ps1` and its harness
(`test\win32\daily-publish.ps1`, hermetic: fake `docker`/`gh`, no build,
nothing released). What the harness deliberately does NOT cover is the real
run, because it needs Docker Desktop up (wixl packages the MSI inside the
msitools image) and starting Docker is the user's call. So the first real
firing is unobserved, and the failure modes it would expose are the expensive
ones: a version the publish script rejects, an MSI whose upgrade ordering does
not advance, an update check that does not see the new tag.

## Goals

- [ ] Watch one real end-of-day publish run to completion and record the tag,
      the FILEVERSION and the elapsed time in this file.
- [ ] Confirm the installed terminal offers that release and that applying it
      leaves `+version` reporting the published semver.
- [ ] Confirm the NEXT day's publish walks to the following patch rather than
      colliding, re-publishing or restarting the walk.

## Validation criteria

- [ ] A `win-v*` release exists that was created by `daily-publish.ps1` firing
      on its own, with no publish command typed by hand.
- [ ] The installed terminal's update path took it, and `+version` afterwards
      reports that release's semver.
- [ ] The watermark at `%LOCALAPPDATA%\ghoztty\daily-publish` names that tag,
      commit and `published`, and the following day's run picks the next patch.
