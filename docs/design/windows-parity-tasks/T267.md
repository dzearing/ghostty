# T267 - GUI acceptance scripts inherit window_placement-debug, so their conditions depend on run order

## Summary

Every GUI script clears `%LOCALAPPDATA%\ghoztty\session-layout-debug.json`
before launching (the T131 lesson). **None of them clears
`%LOCALAPPDATA%\ghoztty\window_placement-debug`** - the separate file T85 uses
to remember a window's outer size and maximized flag - so a script that sets no
size opens at whatever the LAST debug window happened to be, including
maximized.

That makes a script's setup a function of what ran before it, which is the same
family as T248 (a reused `--target` silently probing last run's pane) and just
as invisible: nothing fails, the geometry is simply different.

## Evidence (VERIFIED on the box, 2026-07-31, during T205)

Two distinct failures, both against a build that was behaving correctly:

1. **`chrome-merged-row.ps1` failed its own second run.** Its section 7
   maximizes; `savePlacement` recorded that on exit; the next run's window
   opened MAXIMIZED, where there is no resize edge and the client top sits
   `sysFrameY` below the window top - so `the window's top edge still resizes`
   read `HTCAPTION` instead of `HTTOP`. Fixed in that script by removing the
   file at launch AND in `finally`, so a script that maximizes leaves no trace.

2. **`tab-strip.ps1` failed three assertions once the file was clean.** It never
   called `Set-TestWindowSize`, so it had been running against a leftover
   placement all along. On a default-sized window (782 client px at 1.25) the
   tab run is 557 px and three preferred 281 px tabs no longer fit, so
   `+ : clicking at its NEW position creates tab 3` and both `many tabs`
   assertions went red. Every condition that script sets up is a RATIO of the
   run, and it was not controlling the input the ratio is taken of. Fixed there
   by sizing the window to 1400x800; ALL PASS (37) afterwards.

The second one is the important half: the script was **not failing because of
the placement file, it was failing because it had never controlled its own
window size** and the file had been hiding that. Any script in the same
position is one run-order change away from the same red.

## The fix

- Sweep `test/win32/*.ps1` for GUI scripts that launch a window and never call
  `Set-TestWindowSize`. Each either sizes its window explicitly or documents why
  the default is the point (a script that tests the placement memory itself
  legitimately must NOT have it cleared).
- Put the `window_placement-debug` removal next to the `session-layout-debug`
  removal in `lib/TestDesktop.ps1`'s launch helper rather than in each script,
  so a new script gets it for free - with an opt-out for the script that is
  testing the placement memory.
- Any script that maximizes must clear the file in `finally` too, or it poisons
  every later script in the suite, not just its own next run.

## Validation

- Run the GUI suite twice back to back, and then in reverse order: same
  assertion counts, same pass/fail, every time. Run order must stop mattering.
- `chrome-merged-row.ps1` immediately followed by `tab-strip.ps1` (the exact
  pair that produced the evidence above) is the specific regression case.
