# T267 - GUI acceptance scripts inherit window_placement-debug, so their conditions depend on run order

## Summary

Every GUI script clears `%LOCALAPPDATA%\ghoztty\session-layout-debug.json`
before launching (the T131 lesson). **None of them clears
`%LOCALAPPDATA%\ghoztty\window_placement-debug`** - the separate file T85 uses
to remember a window's outer size and maximized flag - so a script that sets no
size opens at whatever the LAST debug window happened to be, including
maximized.

That makes a script's setup a function of what ran before it, which is the same
family as T248 (a reused `--target` silently probing last run's pane) and just
as invisible: nothing fails, the geometry is simply different.

## Evidence (VERIFIED on the box, 2026-07-31, during T205)

Two distinct failures, both against a build that was behaving correctly:

1. **`chrome-merged-row.ps1` failed its own second run.** Its section 7
   maximizes; `savePlacement` recorded that on exit; the next run's window
   opened MAXIMIZED, where there is no resize edge and the client top sits
   `sysFrameY` below the window top - so `the window's top edge still resizes`
   read `HTCAPTION` instead of `HTTOP`. Fixed in that script by removing the
   file at launch AND in `finally`, so a script that maximizes leaves no trace.

2. **`tab-strip.ps1` failed three assertions once the file was clean.** It never
   called `Set-TestWindowSize`, so it had been running against a leftover
   placement all along. On a default-sized window (782 client px at 1.25) the
   tab run is 557 px and three preferred 281 px tabs no longer fit, so
   `+ : clicking at its NEW position creates tab 3` and both `many tabs`
   assertions went red. Every condition that script sets up is a RATIO of the
   run, and it was not controlling the input the ratio is taken of. Fixed there
   by sizing the window to 1400x800; ALL PASS (37) afterwards.

The second one is the important half: the script was **not failing because of
the placement file, it was failing because it had never controlled its own
window size** and the file had been hiding that. Any script in the same
position is one run-order change away from the same red.

## Two more instances, found while finishing T218 (2026-08-01)

Neither is failing today, and that is the point - they are the same latent
shape, found by looking rather than by a red run:

- **`hero-mode.ps1`** never sizes its window. Every T58 layout assertion is a
  RATIO of the client size, so those survive any placement; the ones that do
  not are the absolute ones underneath - the divider drag moves a fixed 150 px
  and then requires the hero to have narrowed by >= 100, and the carousel pixel
  signature samples from `y = 40` to `Height - 10`. On an inherited small or
  maximized window those change meaning.
- **`window-color.ps1`** never sizes its window either. It has no geometry
  assertion, but its picker section right-clicks the pane CENTRE and its banner
  probe reads an overlay whose card margin is DPI- and width-derived.

Both are in the "sizes its window explicitly" bucket of the sweep below.

## The fix

- Sweep `test/win32/*.ps1` for GUI scripts that launch a window and never call
  `Set-TestWindowSize`. Each either sizes its window explicitly or documents why
  the default is the point (a script that tests the placement memory itself
  legitimately must NOT have it cleared).
- Put the `window_placement-debug` removal next to the `session-layout-debug`
  removal in `lib/TestDesktop.ps1`'s launch helper rather than in each script,
  so a new script gets it for free - with an opt-out for the script that is
  testing the placement memory.
- Any script that maximizes must clear the file in `finally` too, or it poisons
  every later script in the suite, not just its own next run.

## Validation

- Run the GUI suite twice back to back, and then in reverse order: same
  assertion counts, same pass/fail, every time. Run order must stop mattering.
- `chrome-merged-row.ps1` immediately followed by `tab-strip.ps1` (the exact
  pair that produced the evidence above) is the specific regression case.

## What landed (2026-08-02)

**The clear happens at LAUNCH, in one place.** `Start-OnTestDesktop`
(`test\win32\lib\TestDesktop.ps1`) calls the new `Clear-TestWindowPlacement`
before every `ghoztty.exe` launch, so a script that dies mid-run cannot poison
the next one and a new script gets the isolation for free. All 52 GUI scripts
already go through that helper - verified, not assumed - so no per-script edit
was needed to get the guarantee. `-KeepWindowPlacement` is the opt-out, used by
the two scripts whose SUBJECT is that memory (`window-size-memory.ps1`, and
documented as unnecessary for `reset-window-size.ps1`, whose header had already
asked for exactly this isolation between its two launches and was not getting
it).

It lives in the launch helper rather than beside `Clear-DebugSessionLayout` in
`lib\CleanSlate.ps1` because every GUI script loads TestDesktop.ps1 while only
some dot-source CleanSlate.ps1. CleanSlate carries a pointer comment so the two
debug state files stay findable together.

**The path is derived from `$env:LOCALAPPDATA` at call time**, which is the
value `CreateProcessW` is about to hand the child - so the
throwaway-LOCALAPPDATA scripts resolve to THEIR dir, not the user's, with no
extra plumbing.

**Per-script sweep.** `hero-mode.ps1` now sizes its window (1400x900): its
absolute conditions - a fixed 150 px divider drag requiring a >= 100 px
narrowing, and a carousel signature sampled from `y = 40` to `Height - 10` -
change meaning on an inherited window. `window-color.ps1` deliberately does NOT
size: nothing in it is a ratio of the window (section 7 right-clicks the pane's
own centre, the banner probe locates its overlay by HWND), so what it needed was
determinism, not a size - which is now written into the script rather than left
as an accident.

## Evidence (VERIFIED on the box, 2026-08-02)

New acceptance script **`test\win32\window-placement-isolation.ps1`** - ALL PASS
(9). It poisons `window_placement-debug` with `300 250 1` (tiny + MAXIMIZED, the
exact shape that broke chrome-merged-row's second run) and launches twice:

- `-KeepWindowPlacement` -> `window opened maximized = True`, file survives.
- default -> `window opened maximized = False`, file gone.

The first case is the **positive control for the second**: a lone "not
maximized" assertion is green for entirely the wrong reason if the poison is
inert (the empty-rather-than-absent trap of T214/T303). Only the pair says the
clear is doing work.

The named regression pair, run both ways, twice: `chrome-merged-row.ps1` ALL
PASS (19) / `tab-strip.ps1` ALL PASS (56) forward, and identical counts in
reverse. `hero-mode.ps1` ALL PASS (63). `window-color.ps1` ALL PASS (22) with
the poison in place - it consumed it at launch.

Two pre-existing PRODUCT failures surfaced, in `reset-window-size.ps1` and
`window-size-memory.ps1`, both `reset_window_size` landing the client at
`800,638` instead of `800,600`. No `src/` file was touched this turn, so they
predate it: `Window.setClientSize` still predicts the frame with
`AdjustWindowRectEx(WS_OVERLAPPEDWINDOW)` while T254 took over `WM_NCCALCSIZE`.
Filed as **T360**.

Floor: `zig build test -Dapp-runtime=none` exit 0, `-Dapp-runtime=win32` exit 0
(**on the second run** - see T362), `zig build test-agent` exit 0, P1/P2/P3 ALL
PASS.

## What this task did NOT discharge

Its own Validation asks for the GUI suite forward, forward again, and reverse.
**That was attempted and abandoned**: a throwaway runner completed two scripts in
~18 minutes, so one pass is hours. There is no suite runner in the repo and the
suite's wall-clock had never been measured. **T361** owns both.

So the order-independence claim here is argued for 52 scripts and MEASURED for
eight (the regression pair both ways twice, hero-mode, window-color,
window-size-memory, reset-window-size, the two activity-monitor scripts the
abandoned run reached - and the last two matter most, because neither sizes its
window and both are green at the new deterministic default).

What is unconditionally true either way, and is the actual point of the change:
the remaining risk is now a **loud, deterministic** red assertion in a script
that needs more than 800x600, not a silent geometry difference that depends on
what ran before it. That is a strictly better failure mode, and T361 converts it
from argued to measured.
