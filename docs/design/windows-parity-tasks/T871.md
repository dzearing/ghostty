# T871 - win32 agent integrations (7/8): there is no Agent Integrations window on Windows - build the win32 dialog with per-agent state rows and Set Up / Update / Remove actions

## In plain terms

The Mac has a small "Agent Integrations" window: one row per coding agent
showing whether it is detected and whether its Ghoztty setup is current,
with Set Up / Update / Remove buttons. Windows has nothing — you cannot see
the state or fix it without hand-editing files. This builds that window,
Windows-native.

## Summary

Seventh slice of the T598 split. Windows counterpart of
`AgentIntegrationsView/ViewModel/Controller` on the T869 service layer.

- One row per runtime (Claude Code, Copilot CLI): detected?, integration
  state (not installed / installed / update available), per-row action
  button (Set Up / Update / Remove), busy indicator while working, inline
  error text on failure. States refresh after every action and on window
  open, OFF the GUI thread (probes touch disk/PATH; the Mac freezes were
  caused by inline probes — same trap here).
- Honest copy for the special states, from the Mac model: plugin-managed
  Claude ("managed by the ghoztty plugin" — offer nothing destructive);
  shared banner ("removing this leaves shared scripts used by <other>").
- Windows-native construction per the win32 design system
  (`docs/design/win32-design-system.md` + `docs/claude/win32-ui.md` are
  REQUIRED reading before any pixel): follow the existing dialog patterns
  (HostSettingsDialog is the closest sibling — rows, buttons, theming,
  DPI). Entry points: the palette (replacing the old "Install Claude Code
  Integration" entry per T870) and wherever the Mac menu parity slot is.
- No jq row: the Mac shows a "jq missing" warning; Windows' T866 decision
  removes the dependency, so this row must NOT exist here. If T866 landed
  a dependency of its own, surface that instead, same pattern.

## Validation criteria

- [ ] Window opens from the palette, lists both runtimes with correct
      detected/state values on this box, and never blocks the GUI thread
      while probing (verify with the watchdog/no-freeze harness pattern).
- [ ] Set Up on a sandboxed home installs and the row flips to installed;
      corrupting a managed file flips it to Update; Remove clears it —
      driven by the GUI-level acceptance script where feasible, else
      documented manual pass with screenshots.
- [ ] Plugin-managed and shared-banner rows show the honest copy and
      disable the destructive action.
- [ ] View-model logic (row derivation from statuses, action gating) unit
      tested in the win32 lane; both lanes green via
      `scripts\floor-lane.ps1 -Lane all`.
