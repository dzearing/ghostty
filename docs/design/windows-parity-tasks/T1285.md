# T1285 - P3 fails 9 of 15 when it runs straight after P2 in one shell, and is ALL PASS on its own

## In plain terms

Three checks are run before every change ships. The third one fails badly when
it runs right after the second, and passes completely when run on its own -
which means the failure is about the order they were run in, not about anything
being broken. A check that cries wolf gets ignored, and then it stops protecting
anything.

## Goals

- [ ] find what P1/P2 leave behind that P3 reads
- [ ] P3 is green whether it runs alone or third, ten runs each way
- [ ] the fix is in the harness, not in a retry

## Summary

Observed 2026-09-02 while running the standing floor for T1100: 'ipc-p1; ipc-p2; ipc-p3' in one PowerShell session ended with 'P3 ACCEPTANCE: 9 FAILURE(S) (6 assertions passed)', and ipc-p3.ps1 re-run alone immediately afterwards was 'ALL PASS (16 assertions)'. P1-P3 are the floor CLAUDE.md names for every change, so a red that depends on being run after its neighbour is a floor that cries wolf - and the shape (green alone, red in sequence) is state one script leaves behind for the next, not a product defect. Find what leaks between them and either clear it or make P3 immune.
