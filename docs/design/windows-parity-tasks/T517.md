# T517 - Sweep product code for Claude-specific pattern-matching and move it into loop scripts (D11 directive)

## Summary

User directive from D11 (2026-08-04): *no Claude Code specifics in a general
terminal app beyond skills that make it work with Ghoztty*. Some product
code pattern-matches one particular tool's UI — e.g. `+send-keys
--when-idle`'s "esc to interrupt" busy marker, and any pane-probe logic that
identifies "a pane running claude" by its transcript glyphs or chrome
wording. Sweep the product source (`src/`, `macos/`) for tool-specific
heuristics, then either generalize them (behavior-based, like the
motion-based idle detection that already backs up the marker) or move them
out into the loop's own scripts (`scripts/`), which are allowed to know
about Claude.

## In plain terms

Ghoztty is a general-purpose terminal, but a few features currently
recognize one specific AI tool by the exact text it prints. If that tool
changes its wording, the feature silently breaks — and other tools never
benefit. This task finds every such special-case and replaces it with
behavior that works for any program, keeping the tool-specific knowledge in
our own automation scripts where it belongs.

## Where

- Grep product code for Claude-specific strings ("esc to interrupt",
  "claude", transcript-glyph probes) — `src/`, `macos/`, excluding
  `scripts/`, `test/`, docs.
- Known sites to check: `--when-idle` marker in the send-keys path; the
  watchdog pane probe (T244/T440 — verify the probe logic lives in
  `scripts/`, not the product); anything found by the sweep.
