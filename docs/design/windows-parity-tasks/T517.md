# T517 - Sweep product code for Claude-specific pattern-matching and move it into loop scripts (D11 directive)

## Summary

User directive from D11 (2026-08-04): *no Claude Code specifics in a general
terminal app beyond skills that make it work with Ghoztty*. Some product
code pattern-matches one particular tool's UI — e.g. `+send-keys
--when-idle`'s "esc to interrupt" busy marker, and any pane-probe logic that
identifies "a pane running claude" by its transcript glyphs or chrome
wording. Sweep the product source (`src/`, `macos/`) for tool-specific
heuristics, then either generalize them (behavior-based, like the
motion-based idle detection that already backs up the marker) or move them
out into the loop's own scripts (`scripts/`), which are allowed to know
about Claude.

## In plain terms

Ghoztty is a general-purpose terminal, but a few features currently
recognize one specific AI tool by the exact text it prints. If that tool
changes its wording, the feature silently breaks — and other tools never
benefit. This task finds every such special-case and replaces it with
behavior that works for any program, keeping the tool-specific knowledge in
our own automation scripts where it belongs.

## Where

- Grep product code for Claude-specific strings ("esc to interrupt",
  "claude", transcript-glyph probes) — `src/`, `macos/`, excluding
  `scripts/`, `test/`, docs.
- Known sites to check: `--when-idle` marker in the send-keys path; the
  watchdog pane probe (T244/T440 — verify the probe logic lives in
  `scripts/`, not the product); anything found by the sweep.

## Goals

- [x] Sweep `src/` and `macos/` for tool-specific heuristics and record every hit's disposition
- [x] Remove the one real violation: `send_keys.zig`'s hard-coded "esc to interrupt" busy marker
- [x] Generalize the mechanism (`--busy-marker=<text>`, repeatable) so any caller can supply its tool's chrome
- [x] Keep marker behavior tested (acceptance passes the marker as test data) and add a negative control proving the default knows no tool chrome

## Sweep results (2026-08-16)

Method: case-insensitive grep for `claude`, `esc to interrupt`, and spinner/
transcript-probe patterns across `src/` and `macos/` (excluding `scripts/`,
`test/`, docs). Every hit read in context before disposition (claim-verification
rule). Dispositions:

**Generalized (the one real violation):**

- `src/cli/send_keys.zig` `waitForIdle` — hard-matched the literal
  `"esc to interrupt"` (older Claude Code's busy chrome) as a busy signal.
  Fixed: the CLI now bakes in no tool's marker. Busy = tail motion (the T46
  mechanism, which already catches any working TUI) OR any caller-supplied
  `--busy-marker=<text>` (new flag, repeatable, empty value rejected). The
  Claude-specific string moved out of the product into callers that are
  allowed to know it (test scripts pass it as test data; `scripts/`
  loop tooling can pass it if ever needed — currently none needs it, since
  current Claude Code animates and motion detection covers it). Shared CLI,
  so the change lands on both platforms at once.

**Justified as-is (structural, behavior-based — no tool matching):**

- `src/apprt/win32/title_spinner.zig` — the split rule is structural (a single
  non-ASCII symbol codepoint + space + text, symbol ranges by Unicode block);
  Claude Code appears only in comments as the motivating example. ✓ read.
- Watchdog pane probe — the Claude-recognizing probe logic lives in
  `scripts/go-loop-pane-probe.ps1` (scripts are allowed to know Claude);
