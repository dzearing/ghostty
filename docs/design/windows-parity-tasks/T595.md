# T595 - diff.css still names macOS-only fonts, so a win32 diff pane will render in Arial and Courier New

## In plain terms

The git-diff viewer isn't drawn on Windows yet. When it is, its text will come
out in Arial and its code in a typewriter font, because its styling only names
Mac fonts — the same defect T386 just fixed for the markdown viewer and the
selection popover. Doing it now, before the diff pane ships here, means nobody
ever sees the wrong version.

## Goals

- [x] Nothing in `diff.css` leads with the macOS-only family list; one shared
      sheet, no Windows fork
- [x] A diff pane's chrome draws in the same system font as the window around
      it, and its code in a real Windows monospace
- [x] The fonts are MEASURED on a diff page rendered on this box, not asserted
      from the stylesheet text
- [x] A unit test fails if a future edit puts the Mac-only spelling back in
      front

## Summary

T386 gave `src/viewer/selection.js` and `src/viewer/viewer.css` stacks that
resolve on both platforms — `system-ui` first (San Francisco on macOS, Segoe UI
on Windows), with `"Segoe UI"` and `Consolas`/`"Cascadia Mono"` behind the SF
entries as insurance. `src/viewer/diff.css` was deliberately left out of that
change: the win32 viewer has no diff mode yet (T463 renders the diff, T464 the
file-tree side panel), so the sheet ships but nothing on Windows reads it.

Six declarations still name the macOS-only stacks:

- `diff.css:51`, `diff.css:334` — `-apple-system, BlinkMacSystemFont,
  "SF Pro Text", …` with a generic `sans-serif` behind them (Arial here).
- `diff.css:112`, `:132`, `:165`, `:173` — `ui-monospace, "SF Mono",
  SFMono-Regular, Menlo, …, monospace`, whose generic tail is Courier New here.

## Details

Apply exactly T386's treatment — one shared sheet, no fork:

```css
font-family: system-ui, -apple-system, BlinkMacSystemFont, "SF Pro Text",
  "Segoe UI", sans-serif;
font-family: ui-monospace, "SF Mono", SFMono-Regular, Menlo, Monaco,
  "Cascadia Mono", Consolas, monospace;
```

Do it WITH T463 rather than before it: the canvas-width font probe in
`ViewerPane.zig`'s "host floor" test (T386) is the oracle that proves the
result on this box, and it can only measure a diff page once a diff page
renders here. Land the CSS edit and extend that probe to the diff document in
the same change.
