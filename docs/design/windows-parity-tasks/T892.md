# T892 - Flipping a blocked task to todo from the CLI needs evidence: set-status must require a source note and restate the unblock condition when it un-blocks

## Summary

On 2026-08-16 09:26 a turn folding decision D76 also ran bare 'set-status T443/T857 -Status todo' with no source note and no check of either task's unblock condition (T857's is machine-checkable: powercfg PROCTHROTTLEMAX must read 99, and it read 100). The next turn spent its context re-verifying and re-parking - the second no-evidence reopen of T443's armed watch (D27 was the first). T564 closed this hole for the dashboard by stamping 'dashboard: <button>' into the progress log; the CLI path still journals a naked transition. Fix: when set-status moves a task OUT of any blocked(...) state, require -SourceNote (or an explicit -NoNote-style opt-out for bulk passes), and echo the task's unblock: text in the command output so the caller sees the condition they are claiming is satisfied.
