# T41 — Skip close confirmation when the shell is idle (Phase I)

## Summary

Skip close-confirm when shell is idle

## Details

User report 2026-07-13: closing a tab that is just cmd.exe sitting at a
prompt shows the "Processes are still running" confirmation. The Mac asks
only when something beyond the shell is running (`needsConfirmQuit` /
config `confirm-close-surface`). On Windows the shell itself is always a
live child over ConPTY, so the naive check always says "running".
Investigate: enumerate the shell's child processes (ProcessTree.zig from
T31 already walks Toolhelp32 ancestry — reuse) and confirm only when the
shell has descendants (or the foreground process differs from the shell).

*Validation:* close an idle cmd/pwsh tab → no dialog; close a tab running
a child (e.g. `ping -t`) → dialog appears.

## Done (2026-08-02)

The investigation's guess was right — descendants, via `ProcessTree` — and the
work was in the two things it did not name.

**The fix.** `ProcessTree.hasDescendants` (pure, unit tested) plus
`Surface.shellPid` / `shellIsIdle` / `shellIsIdleNow` in the win32 apprt. Both
close paths consult it: `Surface.close` (Ctrl+Shift+W) and
`Window.confirmCloseIfNeeded` (title-bar X / Alt+F4 / `close_window`), the
latter taking ONE Toolhelp32 snapshot for every pane in the window rather than
one per tab. The core's `needsConfirmQuit` is unchanged and still the first
gate; the process table is only the tiebreaker for the case it cannot see.

`shellIsIdle` answers FALSE whenever it cannot know, which is the direction that
shows a dialog that wasn't needed rather than skipping one that was: no shell
pid, a shell missing from the snapshot (`ProcessTree.contains` — `snapshot`
returns an EMPTY map when Toolhelp32 fails, and an empty map otherwise reads as
"nothing is running"), `readonly`, or `confirm-close-surface = always`.

**What the task did not know: the pid was fake.** With session-persistence ON —
the DEFAULT, so this is what every user runs — a pane is `remote`-backed and the
app only knows the pid the agent reports. `PtySpawner.spawnFn` reported
`@intFromPtr(pc.pid)` on Windows: `posix.pid_t` is a HANDLE there, and the
comment said as much (*"the OS process id is not separately tracked"*). So the
number in `+list --json`, in `+sessions`, and in `Remote.child_pid` named
nothing at all. Measured: the acceptance script's section B failed with
`shell pid 492 names a live process`. Fixed with `GetProcessId(pc.pid)`.

Without that, T41 would have been green in test and dead for users — the exec
backend the obvious test uses is the one nobody runs. **Test the default
configuration, not the convenient one.**

Two consequences fell out of the same pid:

* `IpcHandlers.surfaceShellPid` kept a private copy that returned 0 for EVERY
  remote pane, so `+list --pid` — how a process finds its own pane, and what
  `/reset-context` runs on — could not resolve a pane with persistence on. It
  now calls `Surface.shellPid`; asserted in both sections of the new script,
  which is also the ONLY on-box coverage `--pid` has ever had.
* A cross-machine pane still always confirms, deliberately: its pid indexes
  another machine's table. **T356.**

**Tests.** `ProcessTree` unit tests (idle leaf, direct child + grandchild,
siblings, empty snapshot / pid 0, stale cycle) in the win32 lane. On box:
`test/win32/close-confirm-idle.ps1`, ALL PASS (23), run over BOTH backends —
A/exec (`--session-persistence=false`) and B/agent (the default) — each with the
busy case first as the positive control for the idle case, an independent
`Win32_Process` oracle for busy/idle, and the "the window actually closed"
half so a swallowed chord cannot pass as a skipped confirmation.
`-NegativeControl` inverts the idle verdict and fails, as required.

`confirm-dialogs.ps1` (T80) needed its premise repaired, not its assertions: its
`Launch-Gui` left cmd.exe idle, which after this change is precisely the case
that shows NO dialog. It now starts a `ping` and waits for the process table to
confirm it, then runs its 27 assertions unchanged — ALL PASS.

**Floor:** `zig build test -Dapp-runtime=none|win32`, `test-agent`, P1–P3 all
green. Follow-ups: **T355** (the agent lane never checked that its pid is a real
pid), **T356**, **T357** (the forced-confirm branches have no coverage).
