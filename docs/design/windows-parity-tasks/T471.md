# T471 - Cross-OS remote panes pick the scrollback guard from the LOCAL os, not the child's pty flavour

## In plain terms

Making a terminal window taller used to silently delete some of the output you
had scrolled past. That is fixed for panes running on this machine (T431), but
the fix decides whether to switch itself on by looking at the operating system
the *window* is running on, not the one the *shell* is running on. So a Mac
window showing a shell that lives on a Windows box still loses history when it
is made taller, and a Windows window showing a shell on a Mac or Linux box
turns on a protection it does not need — harmless, but it means new blank rows
appear at the bottom instead of previously-scrolled output sliding into view.

Nobody hits this unless they use remote panes across two different operating
systems, which is why it was not fixed at the same time: closing it properly
means the two machines telling each other what kind of terminal they have,
which changes the protocol between them.

## Goals

- [ ] Carry the child's pty flavour (ConPTY vs POSIX) across the agent HELLO
      handshake, additively, so an old peer degrades rather than breaks
- [ ] Choose the scrollback guard from that, per pane, instead of from
      `builtin.os.tag`
- [ ] Cover a cross-OS remote pane in an acceptance test, both directions

## Summary

T431 fixed a real data-loss bug: growing a pane's row count imported scrollback
rows into the active area, where a ConPTY child's post-resize repaint erased
them — permanently, because the import is a move and not a copy. The guard is
`src/termio/history_guard.zig`, and it is switched on by

```zig
pub const enabled: bool = builtin.os.tag == .windows;
```

That constant answers "does the LOCAL machine run ConPTY children", which is the
right answer for every local pane and for the common remote case (a Windows app
driving a Windows agent). It is the wrong answer for a **cross-OS remote pane**:

- **macOS app + Windows agent** — the child IS a ConPTY and DOES repaint after
  every resize, but the guard is compiled out. Growing the window eats history,
  exactly as it did on Windows before T431. This is the half that still loses
  data.
- **Windows app + POSIX agent** — the child does NOT repaint, so the guard is
  unnecessary. It costs nothing but correctness of feel: a taller window shows
  blank rows instead of pulling previously-scrolled content down.

## The shape of the fix

The pane's terminal needs to know its child's pty flavour, and only the agent
knows that. Per the agent contract in `CLAUDE.md`, this is an **additive**
protocol change: a new capability/field on the HELLO handshake, absent from
older peers, with the reader falling back to today's `builtin.os.tag`
derivation rather than failing. Then `Termio` selects the guard per pane from
the negotiated value instead of from a compile-time constant.

`history_guard.arm` / `hold` already take no position on this — they are pure
terminal moves. Only the `enabled` gate and its call sites in `Termio` change.
