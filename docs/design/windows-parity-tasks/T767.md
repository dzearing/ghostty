# T767 - tab-strip-autohide.ps1 aims its caption hit tests with the pre-T496 button arithmetic, so the '...' probe lands on minimize

## Summary

Section 4/5 of test/win32/tab-strip-autohide.ps1 derives the caption button x's as a 28 DIP square plus pad_sm per step (\ = \ + \; \ = \.Width - \ - \). T496 made the system trio three NATIVE 46 DIP slabs flush to the client's right edge with zero gaps, which caption-bar.ps1 and CaptionGeom now use. The stale arithmetic puts the '...' probe one slab to the right, so WM_NCHITTEST answers HTMINBUTTON (8) and the assertion 'the ... button hit-tests as HTSYSMENU' fails - against a build whose caption is correct (caption-bar.ps1 asserts HTSYSMENU at the properly derived point, and passes). Found red during T263's regression sweep; the script contains no Send-TestMouse call at all, so it is untouched by that change and this was already failing. Fix: derive the points from Get-TestChromeMetrics the way caption-bar.ps1's CaptionGeom does, or share that helper.
