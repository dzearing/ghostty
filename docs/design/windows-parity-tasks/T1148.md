# T1148 - agent-instance-lineage's live-session check fails about half the time on a clean box

## In plain terms

One of the automated checks opens a terminal pane and then asks "is this pane
really connected to a live shell?". About half the time it answers "no" even
though the pane is fine, so the check goes red for no reason. A test that cries
wolf every other run is worse than no test: the next person to see it red will
assume it is the test again and move on.

## Summary

`test\win32\agent-instance-lineage.ps1` section D2 - `D2 the pane is backed by a
LIVE session (got 0 alive)` - is intermittent. Measured on 2026-08-23 during
T1127, twice in a row on a box swept clean beforehand (`0` processes running out
of `zig-out` at start of each run):

| run | verdict |
|---|---|
| 1 | `FAIL D2 the pane is backed by a LIVE session (got 0 alive)` - 1 FAILURE(S) (23 checks passed) |
| 2 | `PASS D2 the pane is backed by a LIVE session (got 1 alive)` - ALL PASS (24 checks) |

So it is not the T1127 leak (that is fixed, and both runs above started from a
clean box) and it is not a poisoned neighbour: it is a race inside the script,
almost certainly between the pane being created and the agent publishing the
session it backs.

The T1094 sweep scored this script `pass`, which is the same coin landing the
other way - it is not reliably red either, so nothing has ever had to look at
it.

## Where

- `test\win32\agent-instance-lineage.ps1` - section D, the D2 assertion
- whatever it polls for session liveness (a `+list --json` / sessions-file read)

## Goals

- [ ] Run it enough times to get a real failure rate rather than "about half".
- [ ] Find what D2 reads and whether it waits for it at all - a bare
      `Start-Sleep` in front of a published-state read is the usual shape.
- [ ] Replace the wait with a poll-until-true with a stated timeout, so a slow
      box is slow rather than red.
- [ ] Confirm the fix by repetition, not by one green run.

## Validation criteria

- [ ] The script passes N consecutive runs (N >= 10) on this box, logged.
- [ ] The failure mode is understood and named in the script's own comments -
      not just papered over with a longer sleep.
