# T649 - The t400 stale-debounce test calibrates on a COLD cache and asserts against a warm one, so it flakes

## In plain terms

One of the automated checks fails at random, roughly one run in several, with
nothing wrong in the product. A red test that is sometimes red for no reason is
worse than no test — the next person to see it has to spend a context proving
it is not their change.

## Summary

`apprt.win32.ViewerPane.test."host floor: a real controller on a real window,
on this box"` (T400 section, `ViewerPane.zig` ~4588–4663) failed on
2026-08-09 with

```
t400: a repeat navigation costs 1 fetch(es)
t400: stale-debounce window cost 0 fetch(es), expected 0
```

and passed on an immediate re-run with `nav_cost` = 0 both times. Nothing in the
change under test (T637, image paste) touches navigation.

## Details

The test knows a repeat navigation's fetch cost is Chromium's cache's business
and calibrates rather than assumes — the comment says so. The flaw is WHICH
navigation it calibrates on: `nav_cost` is measured on the FIRST navigation to
`reload_url` in that section, which may still be cold, and then asserted against
a LATER navigation to the same URL, by which time the cache is warm. Cold-then-
warm gives `expected 1, found 0` and the test goes red for a cache transition it
was written to be immune to.

Two candidate fixes, and the second is probably right:

1. **Warm before calibrating** — navigate to `reload_url`, settle, THEN take
   `t400_base` and do the calibration navigation. Both measurements are then in
   the same cache state.
2. **Drop the fetch-count companion entirely.** The test's own comment already
   says the KillTimer oracle above it is the strong one and that "counting
   fetches cannot do this job" — it is kept as the user-visible claim. A weaker
   assertion that flakes is a net negative next to a strong one that does not.

Whichever is taken, `-Repeat` the lane a few times against it: a flake that
reproduces once in six runs is not proven fixed by one green run.

## Validation criteria

- [ ] `powershell -NoProfile -File scripts\floor-lane.ps1 -Lane agent -Repeat 6`
      is green, with the t400 log lines showing the same cache state on both
      measurements (or the fetch-count assertion gone).
- [ ] The KillTimer oracle — the assertion that actually pins T400's bug — is
      untouched and still fails when `syncWatcher`'s `KillTimer` is removed.
