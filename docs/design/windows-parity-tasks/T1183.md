# T1183 - An image opened in a Windows viewer pane shows as text instead of a picture

## In plain terms

Open a screenshot or a PNG in a side pane today on Windows and you get a wall
of garbled characters, because the pane treats every file as source code. It
should show the picture, let you zoom and pan it, and snap between "fit the
pane" and "actual size" the way any image viewer does.

## Summary

Main intake 2026-08-30 (range `772e4fc3a..origin/main`). Upstream commit
**fc7e36356** *"feat(viewer): native image panes, and an always-pinned nav
bar"* added `macos/Sources/Features/Viewer/ViewerImageView.swift` (+581) plus
`ViewerSplitLeaf.swift` / `ViewerView.swift` wiring, with
`macos/Tests/Ghostty/ViewerImageTests.swift` (+429) as proof.

The Mac behavior to carry across, from that commit's own reasoning:

- A dedicated image surface, NOT an `<img>` in the web view - the Mac chose
  native because trackpad feel was the requirement and WebKit's magnification
  has no notion of the image's natural size. On Windows the equivalent
  question is GDI+/Direct2D in the pane vs. a WebView2 document; read the
  Swift diff before deciding, and record the call in this file (mechanism, so
  it is this seat's decision, not a D-decision).
- **100% means one image pixel per DEVICE pixel** - the only definition where
  nothing is resampled, and most of what these panes show is screen capture.
- **Best-fit never upscales**, so a small icon stays crisp at its real size;
  when fit and 100% coincide the first double-click goes to 200% so the toggle
  always toggles.
- Zoom is anchored at the gesture centroid; pan has elastic edges and
  momentum; double-click (or two-finger double-tap) toggles fit vs 100%.
- The pane keeps a real history entry, its address, Home, `+list`'s url,
  session restore, and the same in-page error card every other file mode uses.

The Windows split half of the nav-bar change in the same commit is T1185.

## Validation criteria

- [ ] `+split --view=<file>.png` (and .jpg/.gif/.webp) shows the image, not
      text.
- [ ] Zoom anchors where the gesture is; pan is bounded with elastic edges.
- [ ] Double-click toggles best-fit and 100%; 100% is one image pixel per
      device pixel at every display scale; best-fit never upscales; the
      fit==100% case toggles to 200%.
- [ ] The pane still reports its url in `+list --json`, restores with the
      session, and shows the standard error card for a missing/corrupt file.
- [ ] An on-box acceptance script in `test/win32/` covers the above, with a
      `-NegativeControl` arm that scores red.
- [ ] Floor lanes green (`scripts\floor-lane.ps1 -Lane all`) plus P1-P3.
