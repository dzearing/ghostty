# T1324 - A stale plugin-cache copy of the process-feedback skill shadows the one the app installs

## Summary

Found while landing T1321. This box carries TWO installed copies of the
`process-feedback` skill and they are not the same document:

- `~/.claude/skills/process-feedback/SKILL.md` - the ghoztty-managed copy the
  app installs from its embedded asset, carrying the `<!-- ghoztty-managed -->`
  marker. Current.
- `~/.claude/plugins/cache/dzearing-claude-marketplace/ghoztty/0.10.0/skills/process-feedback/SKILL.md`
  - a plugin-cache copy, registered as `ghoztty:process-feedback`. It is CRLF,
  it still points the banner at `~/.claude/scripts/ghoztty-banner.sh` (moved to
  `~/.config/ghoztty/hooks/` by T870, so that path is dead), and it predates the
  T1321 user-report wiring. Its source is not in the marketplace repo, which
  carries no `process-feedback` skill at all - so nothing regenerates it and
  nothing ages it out.

Two skills with the same name and different instructions is a coin flip over
which rules an agent follows. Decide which delivery path owns this skill (the
app-managed install is the one with a source of truth and a staleness check),
then make the other one stop existing rather than merely be older.
