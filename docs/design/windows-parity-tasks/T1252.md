# T1252 - Ghoztty ships the fallback graphics driver it needs on a remote desktop

## In plain terms

[[T1251]] teaches Ghoztty to reach for a second graphics driver when the
machine's own is too old. This is the task that puts that second driver in the
box, so that installing Ghoztty on a remote machine is all a user has to do.

## Split from

[[T1250]].

## What was decided, and why

**Mesa, not ANGLE.** ANGLE speaks GL ES 3.x; the renderer is desktop GL 4.3,
so ANGLE would be a shader and pipeline port rather than a second module the
existing code can open. Mesa's Windows `opengl32.dll` is desktop GL 4.5 and a
drop-in for the loader [[T1251]] already built.

**The `d3d12` build of Mesa, not `llvmpipe`.** The failure this exists for is a
Remote Desktop session, and an RDP session has a working Direct3D 12 device -
so the `d3d12` gallium driver reaches the real GPU and the fallback is a
working renderer there rather than a slideshow. It is also a quarter of the
size: 17.1 MB on disk against `llvmpipe`'s 58.9 MB. `llvmpipe` would be the
pure-CPU floor for a machine with no D3D12 device at all; that machine is rare
(D3D12 has WARP as a software device on every supported Windows), it would
quadruple the download for every user who never needs any of this, and when the
fallback cannot draw either, [[T1249]]'s honest refusal is still the right
ending. The reasoning is written down in `vendor/mesa-gl/README.md` so the next
person to look at the size can see what was traded.

**The bytes are IN THE REPO, not fetched at package time.** Upstream ships
`.7z`, which uses the BCJ2 filter that no Python library can decode, so a
build-time fetch would put a 7-Zip binary and a network round trip on the
critical path of every release, every CI run and every offline build - to
re-derive a file that changes once or twice a year. `vendor/mesa-gl/` holds it
with `PINNED.json` recording the upstream release, the archive's SHA-256 and
the extracted file's, and `dist/windows-installer/fetch-mesa-gl.sh --verify`
re-downloads and proves the tree byte for byte.

## What changed

- `vendor/mesa-gl/` (new): `x64/opengl32.dll` (Mesa 26.2.1, `d3d12`,
  17,092,608 B), the composed Mesa `LICENSE`, `PINNED.json` (provenance +
  hashes), and a `README.md` covering the subdirectory rule and the size
  trade.
- `dist/windows-installer/fetch-mesa-gl.sh` (new): `--verify` re-downloads the
  pinned asset, checks the archive hash, extracts and compares byte for byte;
  `--version X.Y.Z` bumps and rewrites `PINNED.json` and the licence from what
  actually arrived. A maintenance tool, deliberately not a build step.
- `src/build/GhosttyExe.zig` + `build.zig`: Windows **win32 x86_64** targets
  install `bin/gl/opengl32.dll` and `bin/gl/LICENSE-Mesa.txt`, guarded by
  `InstallUnlock` like the exe (an instance that took the fallback holds the
  module open). The `none` runtime and non-x64 Windows targets install nothing,
  so the `lib` lane does not copy 17 MB it will never open.
- `dist/windows-installer/build-msi.sh`: refuses to package without the
  fallback and its licence, and emits a `gl` Directory - never a component in
  INSTALLDIR.
- `dist/windows-installer/build-portable-zip.sh`: same refusal, copies the
  tree, requires `Ghoztty/gl/opengl32.dll` in the read-back, and FAILS on any
  `opengl32.dll` entry outside `Ghoztty/gl/`.
- `scripts/delivery-manifest.ps1`: new pure `Get-DeliveryTreeSet` naming the
  content trees a delivery mirrors (`share`, `bin\gl` -> `gl`);
  `scripts/deliver-windows-build.ps1` mirrors from that list instead of a
  hardcoded `share\`.
- `src/renderer/gl_loader.zig`: no behaviour change; the `GHOZTTY_GL_FALLBACK_DLL`
  seam's REPLACE semantics are now documented, because they are what lets a test
  build the "no fallback at all" state now that every build ships one.

## Sizes

Measured on the same tree, portable ZIP built before and after:

| | bytes |
|---|---|
| portable ZIP before | 48,976,335 |
| portable ZIP after | 52,722,972 |
| **delta** | **+3,746,637 (+3.6 MB)** |

The MSI carries the same payload under the same cabinet compression, so the
installer grows by the same ~3.6 MB. On disk an install grows by 17.1 MB.

## Not in this task

`scripts/upgrade-ghoztty-windows.ps1` mirrors `share\` into the dev install and
does not yet mirror `gl\` - filed as [[T1254]]. No user has a dev install; the
cost of doing it here was three more acceptance harnesses.

## Validation criteria

- [x] The fallback files land in the install tree and the portable zip, in a
      subdirectory, with the license alongside. `zig-out\bin\gl\` holds
      `opengl32.dll` + `LICENSE-Mesa.txt` after a plain
      `zig build -Dapp-runtime=win32`; the portable ZIP carries
      `Ghoztty/gl/opengl32.dll` and `Ghoztty/gl/LICENSE-Mesa.txt` (its own
      read-back requires both); the WXS puts them under a `gl` Directory -
      sections B8/B9 of `release-artifacts.ps1` read that out of the generated
      package and B9 fails on any `opengl32.dll` installed anywhere else.
- [x] `deliver-windows-build.ps1` passes with the new shape rather than being
      excused, and its manifest names the new entries.
      `test\win32\deliver-windows-build.ps1`: ALL PASS. The manifest names it
      as a TREE (`Get-DeliveryTreeSet`: `share`, `bin\gl` -> `gl`), mirrored
      with `/MIR` like `share\`, so a Mesa bump cannot leave the old DLL
      behind for the loader to find.
- [x] The vendored binary's version and hash are recorded, and re-running the
      fetch reproduces the same hash. `PINNED.json` records mesa 26.2.1
      (`d3d12`), archive `42c6bbcc...`, dll `fc5821c7...`;
      `fetch-mesa-gl.sh --verify` re-downloaded and printed **REPRODUCED ...
      byte for byte** (exit 0).
- [x] A launch on this box with the T1249 seam forcing the system context below
      the floor now reaches the SHIPPED fallback (no env override) and renders.
      `startup-failure.ps1` arm H (H0-H5): window open, no dialog, and the
      log naming `OpenGL implementation: fallback (...\gl\opengl32.dll)` plus
      `impl=fallback` - with `GHOZTTY_GL_FALLBACK_DLL` unset. ALL PASS, 42
      assertions.
- [x] Installer size before/after recorded here - see **Sizes** above:
      +3,746,637 bytes (+3.6 MB) on the portable ZIP, +17.1 MB on disk.

## Also proven

- Arm E (T1249's honest refusal) still fires. Shipping a fallback BROKE it -
  the app now recovers where it used to refuse - which is the fix working, and
  it is why arm E now builds the no-fallback state through the seam. Both
  endings of the same condition are still scored.
- Standing floor: `floor-lane.ps1 -Lane all` ALL LANES PASS (lib, none, win32,
  agent); ipc-p1 (25), ipc-p2 (20), ipc-p3 (16) ALL PASS.
