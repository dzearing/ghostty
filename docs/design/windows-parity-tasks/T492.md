# T492 - win32 panes of an auto-named window do not export $GHOZTTY_WINDOW_NAME

## In plain terms

Every window has a name, even the ones you never named yourself ("window-1",
"window-2"). A script running inside a window is supposed to be able to read
that name out of its environment and use it to talk to its own window. On
Windows that only works if the window was opened with an explicit name -
windows you open with Ctrl+N, or with a plain `ghoztty +new-window`, hand their
programs a meaningless internal id instead. So a script that works in one
window silently targets nothing in another.

## Summary

CLAUDE.md ("Naming"): *"A window opened without an explicit `--target=` (Cmd-N,
or a bare `+new-window`) still gets an auto name - `window-1`, `window-2`, ... -
which is exported to its panes as `$GHOZTTY_WINDOW_NAME`."* On win32 that is
true only for the `--target=` path.

Verified by reading both sites:

- `IpcHandlers.handleNewWindow` appends `GHOZTTY_WINDOW_NAME`/`GHOZTTY_PANE_NAME`
  to the surface env **only** `if (args.target) |t|` (`src/apprt/win32/IpcHandlers.zig`,
  ~line 222). Nothing else in the win32 apprt writes the variable for a window's
  own panes.
- With no apprt override, core `Surface.zig` (~line 923) falls back to
  `GHOZTTY_WINDOW_NAME = 0x<surface id>` - a per-surface hex id, not the
  window's target name.

So a bare `+new-window`, a Ctrl+N window, and every restored window's panes
carry a `$GHOZTTY_WINDOW_NAME` that names no IPC target. Mac does not have this
gap: `BaseTerminalController.init` injects its own `windowName` into the
surface config whenever the env var is absent.

Related: T121 fixed the *other* half of window-name identity (adopted names
reserving their number). Its Mac counterpart `565b77a58` explicitly lists
"inherited `GHOZTTY_WINDOW_NAME`" as an adoption path; win32 has no such path
precisely because it never exports the variable, which is how the hole was
found.

## Details

The fix belongs where the name is decided - `Window.init` already computes the
canonical `ipc_name` for every non-quick-terminal window (T121 rework). The
surface env must be seeded from `self.ipc_name` for panes the window creates
itself, with an explicit `--env` / `--target` value still winning. Watch:

- The name is claimed inside `Window.init` **after** the first tab's surface is
  created in some paths - check the ordering rather than assuming.
- Splits and new tabs inherit from the window, not from the parent pane's baked
  env (a pane's baked env can be from a previous run after a session restore).
- Restored panes: the agent replays the pane env on RELAUNCH, so a restored
  pane's variable should still match the window it is now in.

## Validation

- Acceptance: open a bare `+new-window` (no `--target`), read
  `$GHOZTTY_WINDOW_NAME` back out of the pane, and assert it equals the
  `target` `+list --json` reports for that window - then assert
  `+set-banner --target=$GHOZTTY_WINDOW_NAME` actually reaches it.
- Repeat for a Ctrl+N window and for a pane that came back from a session
  restore.
