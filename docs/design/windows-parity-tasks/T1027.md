# T1027 - The fork-identity overlay never learns a new identity string the fork adds after its rules were written

## Summary

The fork-identity overlay detects only the UPSTREAM spelling of each rule, so it can report that no upstream identity survives while being blind to a NEW fork identity string this side introduces after the rules were written - a new branded URL, a second bundle-id-shaped constant, another apprt switch shape. Nothing re-derives the rule set from the live fork delta, so the overlay degrades silently between merge stages: it would take an upstream file whole, leave the new string un-applied, and check would be green about it. Wanted: a coverage sweep (a verb on scripts\fork-identity.ps1, or a section in its harness) that diffs the fork point against HEAD, extracts the identity-looking line pairs, and reports any that no rule accounts for - so a rule set the fork has outgrown is red rather than quiet.
