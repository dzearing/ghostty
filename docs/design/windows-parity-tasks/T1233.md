# T1233 - Zooming an image pane by hand is never exercised by a real gesture

## Summary

T1183 renders images in a viewer pane and decides every zoom in viewer_image.zig, which the none lane asserts exhaustively. What no harness on this box touches is the GESTURE path: a double-click, a ctrl+wheel notch and a touchpad pinch all die on the background test desktop (T233), so viewer-image.ps1 asserts the load-time fit and the reload and stops there. A regression that broke the wheel listener, the anchor arithmetic or the imageZoom bridge call would be invisible to every lane. Wanted: an interactive-desktop arm (the kb-actions.ps1 GrabForeground pattern) that double-clicks an image pane and reads the pane's own 'viewer image ... event=toggle' line back, plus a ctrl+wheel arm, with the usual positive control.
