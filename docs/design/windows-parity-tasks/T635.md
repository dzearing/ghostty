# T635 - Viewer feedback: composer text model and quote insertion (un-hide Quote)

## In plain terms

Select some text in a viewer pane on a Mac and a small Quote button appears;
pressing it drops that passage into the feedback box as a quoted block, so you
can say "this bit here is wrong" and type your comment underneath. On Windows
that Quote button is hidden on purpose, because there is nowhere to put the
text. This task builds the editable message box and the quoted block, and turns
the Quote button back on.

## Summary

Third of the T384 split, and the one that makes the page's Quote button real.
Two halves: the composer's **editable text model** (caret, selection, editing,
IME, undo, the standard Ctrl+C/V/X/A already routed to viewer fields), and
**quote insertion** — `viewer_bridge.Quote` arriving from `selection.js`
becomes its own indented block with a tinted panel and an accent bar down the
left, carrying an id so deleting it drops its metadata.

Ends with **deleting `viewer_bridge.hide_quote_js`** (`viewer_bridge.zig:69`),
which is documented there as this task's job. Its unit test asserts the flag is
present; that assertion inverts here.

## Details

**The control is a fork, and it is filed as a decision** (see the linked
decision on this task). Mac's `[Image #N]` chip is an `NSTextAttachment` — one
atomic `U+FFFC` character that selects, copies and deletes as a unit. A win32
`EDIT` cannot carry attachments at all. The two real candidates are RichEdit
(`MSFTEDIT.DLL`, which brings OLE objects, IME, undo and accessibility for
free but drags in a control whose styling we do not own) and an owner-drawn
composer built on the machinery the banner overlay already has (full control of
the accent bar and chip drawing, at the cost of hand-rolling caret, selection,
IME and accessibility). Take the decision's answer; do not re-open it silently.

Quote behavior to match, all of it from CLAUDE.md's feedback section:

- The Quote button opens the composer if it is closed, then inserts the passage
  **at the caret as its own block** — indented, tinted panel, accent bar down
  the left. On Mac the bar is drawn in `drawBackground(in:)` precisely because
  a background-color attribute paints tight line boxes with no bar and no
  rounding; the win32 owner-drawn equivalent has the same requirement.
- The run carries a quote id (`feedbackQuoteID` on Mac), and the report derives
  its `quotes` array **from the storage**, not from a side list — so deleting
  the block drops its metadata. Same rule as the image carousel.
- **Typing never inherits quote styling.** AppKit's failure mode was
  `typingAttributes` carrying over from deleted text, which trapped the user
  writing inside the quote and resurrected its metadata. Whatever the win32
  control, the equivalent trap is a run-attribute inherited at the caret;
  refuse quote attributes at the source, and test select-all + delete + type.
- The message already arrives fully parsed (`viewer_bridge.Quote`, landed in
  T375) with `headingId`/`headingText`, `blockSelector`/`blockText`,
  `offsetInBlock`, `documentOffset`. Store all of it against the quote id — the
  report writer (T636) needs it. `sourceLine` is deliberately NOT in the
  message and is resolved natively at send time; that is T636's job.

## Validation criteria

- [ ] `viewer_bridge.hide_quote_js` is gone and its unit test now asserts the
      injected blob does NOT set `window.__ghozttyHideQuote`.
- [ ] Unit tests (none lane): inserting a quote at the caret produces one
      block with its id; deleting the block removes its metadata from what the
      report would serialize; typing immediately after a quote produces plain
      text (the select-all/delete/type trap).
- [ ] On-box acceptance: select text in a markdown viewer pane, press Quote —
      the composer opens with the passage as a quoted block, and the block's
      recorded context matches the passage's heading and containing block.
- [ ] On-box acceptance: the standard editing chords (Ctrl+C/V/X/A) work
      inside the composer, and IME composition produces the composed text.
