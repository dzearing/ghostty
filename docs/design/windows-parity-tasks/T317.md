# T317 - The win32 test lane segfaults intermittently in terminal.PageList (page.verifyIntegrity -> hash_map.get)

## Summary

`zig build test -Dapp-runtime=win32` — a standing floor lane — **segfaulted on
the first run of the T312 turn and passed on an immediate re-run of the same
tree, unchanged.** That is the same failure shape T258 filed for `test-agent`,
one lane over, and it has the same cost: it trains every turn to re-run a floor
lane until it goes green, which is exactly how a real regression gets waved
through as "the flake again".

Filed from T312 (2026-08-01), which hit it and had to establish by re-run that
its own change was not the cause. It is not: the change is confined to
`chooser_rows.zig` / `MachineChooser.zig`, and the crash is in the terminal
core.

## Details

Two threads worth pulling, in this order:

1. **Is it the seed?** The runner prints `--seed=0x...` and it differs per run.
   `growRows` → `grow` → `assertIntegrity` → `lookupHyperlink` reads the page's
   hyperlink map; a segfault *inside* the map's `get` on a page that was just
   grown points at a stale/uninitialized map pointer after a page realloc,
   not at a data race. Re-run the failing seed explicitly (`zig build test
   -Dapp-runtime=win32 --seed 0xefa4b814`) before anything else — a
   deterministic repro turns this from a flake into a bug.
2. **Is it Windows-only, or is it upstream?** `page.zig` / `PageList.zig` are
   shared core, not win32 code. Check whether the none-runtime lane can produce
   it too (it passed in the same turn) and whether upstream Ghostty has the
   same test. If it reproduces off-Windows this belongs upstream, and the
   deliverable here is the repro plus the report.

Do NOT "fix" this by retrying the lane or by marking the test flaky. The floor
lanes are the evidence the whole loop rests on; a lane that fails 1 run in N is
a lane whose green means nothing.

## Validation

- The failing seed reproduces on demand, or is proven not to (state which).
- Root cause named in terms of the page/hyperlink-map lifetime, with the source
  line that owns it.
- `zig build test -Dapp-runtime=win32` green over **10 consecutive runs** with
  varying seeds — one green run is what made this invisible for a turn.
- Floor: both `zig build test` lanes, `test-agent`, P1-P3.
