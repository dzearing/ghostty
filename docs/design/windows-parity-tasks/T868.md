# T868 - win32 agent integrations (4/8): no hook registration exists - port ClaudeHookSpec (settings.json merged fragment) and CopilotHookSpec (dedicated hooks file) with native JSON

## In plain terms

Hooks are what let a coding agent tell Ghoztty "I'm busy", "I need input",
or "update my status banner" automatically. On the Mac, Ghoztty writes those
hook registrations into each agent's settings for you — carefully, without
disturbing anything you configured yourself. Windows gets that machinery
here: the part that edits Claude Code's shared settings file safely, and the
part that drops Copilot's dedicated hook file.

## Summary

Fourth slice of the T598 split. Port `HookSpec.swift`, `ClaudeHookSpec.swift`,
`CopilotHookSpec.swift`, `HookComponent.swift`. All JSON via `std.json` (the
task's standing rule: native parsing, no jq, no shelled-out tools).

- **HookPurpose / HookCommand**: nine purposes — banner three (`session-start-
  hook`/`prompt-hook`/`stop-hook` verbs) + activity six (`session-start`,
  `pause`, `tool-tick`, `agent-start`, `agent-stop`, `settle`). The command
  string invokes the T866-decided script flavor with the verb and
  `--runtime=<claude|copilot>`; payload arrives on stdin, NEVER interpolated.
  Single-quote shell-quoting of the script path (or the T866 equivalent).
- **ClaudeHookSpec** (merged fragment into `%USERPROFILE%\.claude\
  settings.json`): the event map is Mac's exactly — SessionStart (banner
  element matcher `startup|clear` + unmatched activity sweep element),
  UserPromptSubmit, PreToolUse (matcher `AskUserQuestion|ExitPlanMode` →
  pause), Notification, PermissionRequest (→ pause), PostToolUse (tool-tick),
  SubagentStart/SubagentStop, Stop (banner + settle). Each command carries
  `"timeout": 10`. Ownership signature = the hooks DIRECTORY substring in a
  deterministically-serialized element (sorted keys, literal slashes) — the
  directory, not the banner path, so activity elements match too. `merge`
  replaces only signature-matched elements within our events;
  `removeFragment` prunes empty events and the empty `hooks` map;
  `fragmentState` compares OUR elements as sets, installed/outdated/absent.
- **CopilotHookSpec** (dedicated `%USERPROFILE%\.copilot\hooks\ghoztty.json`):
  version-1 envelope, `_comment` = marker token, camelCase events —
  `sessionStart` (banner + activity), `userPromptSubmitted`, `agentStop`
  (banner stop + settle), `"timeoutSec": 10`, `"bash"` command key. Mac
  deliberately wires only the three empirically-verified events; keep that
  (guessed event names silently never fire — worse than absent).
- **HookComponent**: dedicated-file path = ManagedFile write/state/remove.
  Merged-fragment path: absent-or-empty settings → empty base; present but
  non-object/unparseable → typed refusal, NEVER clobber (and state reports
  OUTDATED, not not_installed — a destructive "Set up" must not be offered);
  one-time `.ghoztty.bak` backup before the first rewrite; write through the
  reparse-refusing atomic writer. Deterministic output: sorted keys, pretty,
  unescaped slashes — byte-stable across install runs (std.json stringify
  options; verify determinism in a test).
- Keep Mac's known debt (H9): the merged-fragment branch may call the
  concrete Claude spec directly; generalize only when a second
  merged-fragment runtime exists.

## Validation criteria

      replaces stale Ghoztty elements, and round-trips byte-stably (unit

- [ ] removeFragment leaves a user-only file untouched shape-wise and prunes

- [ ] An unparseable settings.json: state = outdated, install = typed error,

- [ ] First rewrite creates `settings.json.ghoztty.bak` once; later rewrites
      never touch the backup.
- [ ] Copilot rendered file matches the Mac schema (version, `_comment`
