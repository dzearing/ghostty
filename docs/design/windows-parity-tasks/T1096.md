# T1096 - Scope the de-Ghostty rename sweep: 13,705 references across 1,234 files, and decide which ones are safe to rename

## Summary

User directive 2026-08-22: 'maybe even remove every possible reference to ghostty'. A repo-wide grep finds 13705 matches in 1234 files (src 360, macos 254, docs 213, test 113, example 102). Most are free renames. Three classes are NOT, and a blind sweep would break the product or the license, so this task is to inventory and classify before anything is renamed. (1) LICENSE and copyright headers: Ghostty is MIT, which requires the copyright notice and permission text be retained in all copies - the attribution stays, permanently, and no sweep may touch it. (2) Wire and OS identifiers that other software already knows: the xterm-ghostty terminfo entry name and the TERM value it sets (remote hosts that already installed xterm-ghostty stop matching if it is renamed), macOS bundle identifiers and the com.mitchellh.ghostty domain in defaults/keychain/LaunchAgent entries, and any config or state directory name a user's existing install already writes to - each needs a migration story or it silently orphans user state. (3) Vendored and generated files (vendor/**, build.zig.zon.*, po/**) where the name is upstream data rather than our prose. Deliverable: a classified inventory (safe / needs-migration / never) plus a decision doc for class 2, then the safe bucket renamed in one mechanical pass with the floor lanes green. Do NOT start renaming before the inventory is written.
