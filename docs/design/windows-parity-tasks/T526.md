# T526 - viewer-panes.ps1 web-viewer cwd-fallback assert is red at HEAD: +split into a non-active window never becomes the focused surface

## In plain terms

One check in the viewer test suite fails every run, and it exposes a real
quirk: when a terminal pane is split off a web-page pane, its shell can start
in a folder belonging to a completely different window — whichever window was
created most recently — instead of the folder of the terminal the user was
just working in. Until this is fixed, the whole viewer test script reports
red, which can hide any NEW viewer regression.

## Summary

`test\win32\viewer-panes.ps1` fails one assert at HEAD, deterministically,
with no local changes (verified 2026-08-06 against a clean Debug build,
`1 FAILURE(S) (110 passed)`):

```
FAIL  a web viewer contributes no cwd, so the fallback stands (got 'D:\git\ghoztty\')
```

Root cause (proven with app-side logging of `performDeferredFocus`, T388
investigation):

- A terminal split created by `+split` gets keyboard focus via
  `App.deferSetFocus` → `performDeferredFocus`, which deliberately DROPS the
  focus assert when the pane's top-level window is not the active window
  (T105/T89f2 ping-pong guard; on the background test desktop the proxy is
  `GetActiveWindow`, T211/T223).
- Window creation DOES activate the new window, even on the background test
  desktop. So after the script creates the `vpterms`/`vpy` windows, the `vp`
  window is no longer active, and every subsequent `+split --target=vp` has
  its deferred focus dropped (`perform=false` observed for all three T395
  splits).
- Therefore `t395base` never becomes `core_app.focused_surface`, and the
  terminal split off the WEB viewer inherits its cwd from the focused
  terminal of the most recently created window
  (`src/apprt/surface.zig:194-201`), which is `D:\git\ghoztty` — hence the
  assert's message.

Minimal repro (no viewers needed): window A → `+split` a terminal into A with
`--working-directory=X` → create window B (any) → `+split --view=about:blank`
into A → `+split --pane=<that viewer>`: the new terminal starts in B's cwd,
not X. With no window B, it starts in X.

## Details

Two intertwined halves; decide the split when picking this up:

1. **Product question**: is "a split off a viewer inherits the cwd of a
   terminal in ANOTHER window" the intended fallback? A user splitting inside
   window A almost certainly expects a cwd from window A. A window-scoped
   fallback (the window's own most-recently-focused terminal pane) would be
   more predictable than the global `focused_surface`. Check what the Mac
   does in the same multi-window shape before changing shared semantics — if
   the Mac has the same behavior, this becomes a parity-neutral design
   decision, not a straight bug fix.
2. **Test integrity**: the T395 section's premise ("the base terminal is the
   last focused core surface") stopped holding when later sections
   (`vpterms`, `vpy` windows — added after T395 landed) started leaving a
   different window active. Whatever the product answer, the script must go
   back to ALL PASS so a red run means a new regression again.

Note the T105/T211/T223 focus-guard behavior itself is carefully tuned and
has its own tests; the fix here should not weaken the ping-pong guard.
