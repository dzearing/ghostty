# T1257 - asserted-nothing is red at HEAD: soak.ps1 scores a zero-assertion abort green and the uncounted-final ceiling is 3 over

## In plain terms

One of the checks that keeps the test suite honest is itself failing, and has
been for a while. Nothing is broken in the terminal - but a red check is a
check people learn to scroll past, and this particular one exists to catch a
test run that announced success without testing anything.

## Evidence (measured 2026-09-01, at `9aa532901`, before this turn's changes)

```
FAIL C1 no acceptance script can score green having asserted nothing
     soak.ps1:179 early-green - a pass verdict ends the run green before the
     final verdict: 'ALL PASS'
FAIL C3 the uncounted-final count did not grow past 37
     (40 script(s) still print an UNCOUNTED final verdict - T775 converts them)
```

Confirmed pre-existing by stashing this turn's work and re-running against a
clean HEAD: identical verdict, `2 FAILURE(S) (26 assertions passed)`.

## What to do

- `soak.ps1:179` is the `early-green` kind: a branch that prints a pass verdict
  and ends the run before the final verdict. This is the same defect [[T962]]
  fixed for `job-escape-startup`; follow it.
- The uncounted-final ceiling is a ratchet that [[T775]] is meant to walk down,
  and it has walked UP by three instead. Either convert the three scripts that
  grew one, or - if they are legitimate - move the ceiling deliberately, in a
  commit that says which three and why. Do not simply raise the number.

## Validation criteria

- [ ] `test\win32\asserted-nothing.ps1` reports `ALL PASS` at HEAD.
- [ ] The three new uncounted-final scripts are each named, and each either
      converted or accounted for.
- [ ] `soak.ps1`'s abort path exits nonzero rather than green.
