# T1234 - An HEIC or AVIF photo may open as an error card where Mac shows the picture

## Summary

T1183's extension table is Mac's, byte for byte, and includes .avif/.heic/.heif. macOS decodes all three through ImageIO with no extra install. On Windows the decode belongs to whatever codecs the box has: WebView2 decodes AVIF, but HEIC/HEIF need the HEIF Image Extensions from the Store, and .tif/.tiff and .icns are not web image formats at all - so a photo straight off an iPhone can open as 'Cannot display this image' on one machine and as a picture on the next. The card is honest, but it is not parity. Wanted: decide per format whether to decode natively on the host side (GDI+/WIC already ships gdiplus_decode.zig, and WIC covers TIFF and - with the extension - HEIF) and hand the page a PNG, or to say so in the card ('Windows needs the HEIF Image Extensions to show this') rather than the generic message. Either way the answer should be the same on both seats for the same file.
