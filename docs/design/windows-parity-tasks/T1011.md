# T1011 - Clicking a process row in the activity monitor draws a focus outline Windows would have kept hidden

## Summary

Windows hides focus rectangles until the user navigates by keyboard (the UI-state bit behind UISF_HIDEFOCUS, which an owner-drawn control reads as ODS_NOFOCUSRECT). The machine chooser's listbox reads it, so clicking a row there selects it without drawing a rim. The Activity Monitor's table is an owner-drawn REGION rather than a control and has no such bit, so it paints the caret rim the moment the table takes focus - including when the table took it from a mouse click. T1008 made that rim neutral ink so it is no longer a second accent mark, and left this half: the panel should read its own WM_QUERYUISTATE and honour it in paintTableFocus, exactly as chooser_rows.RowState.focus_visible does. Section C of test/win32/activity-selection.ps1 pins the state today and would extend to cover the pointer-driven one.
