# T974 - Nothing proves a pane stays alive when only the session manager restarts

## Summary

Since T909 a persistent session's ConPTY lives in a holder process that outlives the session manager, so an agent crash or upgrade should end with the panes re-attached to LIVE sessions and NO session-interrupted notice. test/win32/session-relaunch-notify.ps1 now kills the holders too (T922), because its subject is the REBOOT shape - which means the agent-restart shape it used to stand for is now measured by nothing. Add an arm (or a sibling script) that kills ONLY the manager and asserts the opposite outcome: the recorded command is still running, no notice appears in banner or scrollback, and the pane takes input on the same session.
