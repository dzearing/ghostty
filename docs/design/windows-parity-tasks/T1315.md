# T1315 - Closing a task the user reported does not itself ask for the release that carries the fix

## Summary

T1294 made a same-day release possible: a turn records daily-publish.ps1 -Request and step 6.5 ships it. But a turn still has to REMEMBER to do that, and the failure mode of a forgotten step here is the exact user-visible thing T1294 was filed for - a fix the user cannot get. Make it structural: a task filed from a user report carries that fact (a frontmatter flag set by new/set-priority), set-status done on such a task files the publish request itself, and gate-negatives demonstrates the arm where it does not.

## In plain terms

When you tell us about a bug and we fix it, the fix does not reach you until a
release goes out - and asking for that release was something whoever closed the
task had to remember. On 2026-09-03 nobody did: you downloaded the same broken
installer a second time and reported the same bug again. Now a task that came
from you is marked as such, and closing it asks for the release by itself. If
anything stops that from happening, the tracker refuses the close instead of
letting it pass quietly.

## Goals

- [x] a task can record that a USER reported it (`user-report: true`)
- [x] closing such a task files the publish request itself, with a receipt
- [x] closing an ordinary task still files nothing - the one-a-day cadence stands
- [x] a closed user report with no request is a `validate` failure, not a silence
- [x] both arms, and the failed-request path, are demonstrated in gate-negatives

## Validation criteria

- [x] `new -UserReport` writes `user-report: true`; an ordinary `new` does not
      (gate-negatives F0/F1, ALL PASS 58).
- [x] `set-status <id> -Status done` on a flagged task runs
      `daily-publish.ps1 -Request`, names the task in the reason, and writes the
      receipt into the progress log (F3/F4/F5).
- [x] Closing an ordinary task files no request and prints no PUBLISH REQUESTED
      (F2) - the arm where it does NOT fire.
- [x] `validate` fails `UNSHIPPED USER REPORT` on a closed user report with no
      receipt, and a recorded request clears it (F6/F7).
- [x] A request that cannot be written scores PUBLISH REQUEST FAILED and leaves
      the close failing validate rather than passing (F8/F9).
- [x] `set-priority -UserReport` retro-flags a task triage recognises (F10).
- [x] Registry completeness: the three new labels are declared and each gate
      names its demonstration (gate-negatives A2/A5).
- [x] Standing floor green: the nine harnesses `guard-due` named for these
      files, plus the four zig lanes via `floor-lane.ps1 -Lane all`.
