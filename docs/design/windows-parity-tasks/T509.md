# T509 - test-binary-soak.ps1 loses the first binary's per-run logs when a lane soaks two binaries - the second reuses the same log filenames

## In plain terms

The script that re-runs a test program many times to catch rare crashes keeps
a log file for every run — but when it soaks two programs back to back, the
second program's logs silently overwrite the first's. If the first program had
a failure, the evidence of *what* failed is gone by the time anyone looks.
That exact loss happened during the T238 investigation and cost an extra
20-run soak just to re-learn what a kept log would have said.

## Summary

`scripts\test-binary-soak.ps1 -Lane agent` soaks both agent test binaries "in
turn", but the per-run log name is `{label}-{stamp}-{NN}.log` where `$stamp`
is taken ONCE per invocation (line ~85) and `NN` restarts at 1 for each
binary (`$idx = $started + $k` inside the per-target loop). So run 07 of
binary 2 overwrites run 07 of binary 1.

Observed 2026-08-06 during T238: `-Lane agent -Runs 20 -Concurrency 5`
reported `runs=40 ... fail=3`, but only 20 log files existed afterwards — the
two FAILs from `ghoztty-agent-test.exe` were unrecoverable and the binary had
to be re-soaked alone to identify them.

Fix shape: include the exe basename (or a per-target index) in the log
filename, e.g. `{label}-{stamp}-{exeName}-{NN}.log`. The final summary should
also name which binary each FAIL/CRASH belonged to.

## Validation criteria

- [ ] `-Lane agent -Runs 2` produces distinct, surviving log files for BOTH
      binaries (4 files total)
- [ ] A forced failure in the first binary's run is still readable after the
      second binary finishes
- [ ] The end-of-soak summary attributes fails/crashes per binary
