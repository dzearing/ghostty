# T1253 - Prove Ghoztty starts and draws over a real Remote Desktop session

## In plain terms

[[T1251]] and [[T1252]] make Ghoztty run when the graphics driver is too old,
proven by pretending the driver is too old. This proves it where the user hit
it: inside an actual Remote Desktop session, where the driver really is that
old and a dozen other things about the desktop are different too.

## Split from

[[T1250]].

## Why the seam is not enough

`GHOZTTY_GL_FORCE_VERSION` moves the reported version only. An RDP session
changes more than a number: the display driver is GDI Generic, the desktop is
encoded and shipped over the wire, DPI and monitor topology are the client's,
and window composition behaves differently. A pass under the seam says the
fallback path runs; it does not say the terminal is usable there.

## What to do

- Establish a repeatable RDP session against a Windows box (the user reached
  this one from a MacBook with Microsoft's Windows App on 2026-09-01).
- Run the acceptance suite - at minimum a launch, a render, `ghoztty +list` and
  a session restore - inside that session and record which renderer was chosen.
- Record what the experience is actually like: does it draw at a usable rate,
  and does the app say clearly that it is on the fallback?
- File whatever that turns up. Slow-but-working is a result, not a failure, and
  belongs in a follow-up task rather than blocking this one.

## Resolution: split (2026-09-01)

The task as written is two things with two different owners, and only one of
them is this seat's.

The **checklist** - a script that launches the terminal in whatever session it
finds, reads the renderer's account of the OpenGL context back, measures frame
pacing, and checks `+list` and session restore - is ordinary work and it landed:
[[T1255]].

The **run** is not. Windows 11 Pro serves one interactive session at a time, so
an RDP connection from anywhere (localhost included) takes over the console
session rather than joining it; this box cannot originate a remote session
against itself without blanking the desktop the loop runs on. Windows Sandbox
and Hyper-V both need an elevated feature install and a reboot. It takes a
second machine and a person on it, which is [[T1256]].

Splitting rather than parking the whole thing is what keeps the P0 honest:
[[T1256]] still carries the priority, and it is now a task whose whole content
is "connect and run one command" rather than one that also hides a script
nobody has written.

## Validation criteria

- [ ] Ghoztty launches and renders inside a real RDP session, with the log
      naming the fallback renderer and the session's actual GL report.
- [ ] `ghoztty +list` and session restore behave there the same as locally.
- [ ] Frame pacing over RDP measured and written down here (`GHOZTTY_PERF`).
- [ ] Follow-ups filed for anything the session turned up.
