# T1373 - Test-ExactPixel spends about 2.5 seconds to answer 'no', which makes it useless as a poll

## Summary

The shared pixel probes exit early when the color IS present and walk every pixel of the box when it is NOT - about 60k GetPixel calls for a full-width bottom band, ~2.5s per answer on this box (measured in T561: a wait loop built on it reported 2626ms for a dismissal that actually takes ~140ms). Any wait-for-condition oracle built on the negative answer therefore measures its own cost and burns wall clock on every acceptance run. Give the harness a sampled-grid probe (step in x and y, sized against the smallest feature it must not miss) and point the polling callers at it.
