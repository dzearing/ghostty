# T383 - Viewer panes have no title: +list prints an empty view: row and the tab reads Ghoztty

## Summary

T374 made viewer panes real, and they arrive with `title = null`. So
`+list` (human) prints `view:   <url>` with an empty title where the Mac prints
the document's, and the tab strip shows the default `Ghoztty` for a pane that
knows exactly what it is displaying.

## Details

`ViewerPane.title` is allocated and freed and never SET — nothing subscribes to
`DocumentTitleChanged`, and nothing falls back to the file basename or the host
for a pane that has no document title yet. `+list --json` reports
`"title": ""`, and `PaneView.title()` returns null so `updateWindowTitle` uses
the tab default.

Titles belong to **T90g** ("chrome & command integration: titles, hero
exclusion, accelerator forwarding, dim walk, split-from-viewer cwd, palette
entries"), so this is not new scope — it is filed so the gap is VISIBLE between
T374 and T90g rather than living only in a reader's head. Fold it into T90g when
that starts, or take it here if T90g slips.

What it needs: `add_DocumentTitleChanged` + `get_DocumentTitle` (slots 46 and 48
of `ICoreWebView2`, right after `add_NewWindowRequested` — the opaque block T374
declared shrinks by two), pushed through `setTitle` and then
`updateWindowTitle`. The pre-load fallback should be the Mac's: the file
basename in file mode, the host in web mode, so a pane is never nameless while
its page loads.

*Validation:* `viewer-panes.ps1` — a `+split --view=<url>` pane reports a
non-empty `title` in `+list --json`, the human `view:` row carries it, and the
tab caption is not the default; a pane still loading reports the fallback rather
than an empty string.
