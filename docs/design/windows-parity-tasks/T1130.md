# T1130 - A viewer pane squeezed narrow on Windows spills its chrome outside the pane

## In plain terms

Drag a viewer pane (a rendered README, a diff, a web page) narrow enough and its
contents stop respecting the pane's edges - toolbar or body draws past the
divider instead of shrinking or clipping. The Mac build was fixed on 2026-08-21;
Windows still needs it.

## Summary

Main intake, 2026-08-22 (range `22c9c6d8a..origin/main`). Upstream commit
**463dcb0b4** *"fix(viewer): a squeezed viewer pane stays inside its pane"*
added narrow-pane handling to `macos/Sources/Features/Viewer/ViewerSplitLeaf.swift`
and `ViewerView.swift`, with `macos/Tests/Ghostty/ViewerNarrowPaneTests.swift`
(84 lines) as its proof.

First step is to reproduce on Windows and characterise it: which chrome
overflows, at what width, and whether the fix belongs in the viewer's own layout
pass or in how the split leaf reports its available width. Read the Swift diff
for what "stays inside" is defined to mean at each breakpoint.

## Validation criteria

- [ ] A viewer pane dragged to its minimum width draws entirely inside the pane
      rect - nothing overlaps the divider or the neighbouring pane (pixel-probed).
- [ ] The same holds for each viewer flavor Windows ships (markdown, HTML,
      website, code, git-diff).
- [ ] Navigation chrome degrades the way the Mac build does at narrow widths
      rather than being clipped mid-control.
- [ ] An on-box acceptance script in `test/win32/` covers the narrow case.
- [ ] Floor lanes green (`scripts\floor-lane.ps1 -Lane all`) plus P1-P3.
