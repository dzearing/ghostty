# T651 - parity-tasks.ps1 new should warn when a similar task already exists (one flake was filed three times)

## In plain terms

The same broken test got written up as three separate pieces of work on three
different days, because nothing checked whether it had already been reported.
Every duplicate makes the backlog look bigger than it is and costs somebody a
fresh investigation of a problem that was already understood.

## Goals

- [x] Filing a task that looks like an existing one says so, before the file is
      written. `new` prints a `SIMILAR:` block naming each candidate, its
      status and the tokens that matched, and only then allocates the id.
- [x] The check never blocks filing - it warns, and the agent decides. `new`
      always creates the file; `-NoSimilarCheck` silences the warning for a
      deliberate near-twin and changes nothing else.
- [x] Deliberately similar titles (a split's children, a mac/win pair) do not
      drown the signal: idf weighting flattens the backlog's common words, the
      report is capped at the 3 best matches, and ties break toward the OLDEST
      id so the original cannot be pushed off the list by its own children.

## Summary

`scripts\parity-tasks.ps1 new` allocates an id and writes a file with no lookup
of any kind. On 2026-08-08/09 the SAME defect - the T400 stale-debounce fetch
count flaking in the win32 lane - was filed as **T615**, then **T643**, then
**T649**, by three different turns, each of which had just watched the lane go
red and had no cheap way to ask "is this known?". T643 and T649 are now
`skipped(duplicate of T615)`.

## Details

The cheap version is a title-token overlap check against open tasks: normalise
the title (lowercase, drop stopwords and punctuation), and warn when an existing
open task shares enough distinctive tokens. Distinctive is the operative word -
`viewer`, `windows`, `test` and `pane` are in half the backlog, so raw overlap
would fire constantly. Weighting tokens by inverse frequency across the corpus
(a crude idf over the ~680 titles) is enough to make `stale-debounce` and `t400`
carry the match while `test` carries almost nothing.

Warn, never block: `new` is called by agents mid-turn and a false positive that
refuses to file would lose work. Print the candidate ids with their titles and
carry on, so the filing agent can close its own duplicate in the same breath.

Worth also matching on the identifiers a defect carries in its title (a symbol
name, a test name, an existing task id in parentheses), since those are exactly
the tokens that make two reports of one defect look alike.

## Validation criteria

- [x] Filing a task titled like T615's prints a warning naming T615, and still
      creates the file with a fresh id. Verified against the REAL tracker:
      `similar -Title "T400 stale-debounce fetch count flakes in the win32
      lane"` returns T643 (0.85), T615 (0.72), T596 (0.58), T649 (0.43) - the
      whole real cluster, best first. Section S1/S2 of
      `test\win32\parity-tasks-seat.ps1` is the hermetic version.
- [x] Filing a title that shares only common words with the backlog prints no
      warning. Verified against the real 1450-title tracker with five invented
      titles (tab strip / split divider / keybinding / session restore /
      installer shortcut): all five silent at the 0.42 threshold. A 14-title
      random sample of real cards produced hits on 2 of 14, and both were
      genuine - T377 matched its own near-duplicate wording, and T726 surfaced
      an EIGHT-way duplicate cluster (now T1453). Section S4/S6.
- [x] A unit or script-level check covers both cases, so the heuristic cannot
      silently rot: section S of `test\win32\parity-tasks-seat.ps1` (S1-S10),
      which probes both sides of the threshold with `-MinScore` and closes
      against the real tracker. Full harness: ALL PASS, guard `parity-tasks`
      re-stamped.
