# T651 - parity-tasks.ps1 new should warn when a similar task already exists (one flake was filed three times)

## In plain terms

The same broken test got written up as three separate pieces of work on three
different days, because nothing checked whether it had already been reported.
Every duplicate makes the backlog look bigger than it is and costs somebody a
fresh investigation of a problem that was already understood.

## Goals

- [ ] Filing a task that looks like an existing one says so, before the file is
      written.
- [ ] The check never blocks filing - it warns, and the agent decides.
- [ ] Deliberately similar titles (a split's children, a mac/win pair) do not
      drown the signal.

## Summary

`scripts\parity-tasks.ps1 new` allocates an id and writes a file with no lookup
of any kind. On 2026-08-08/09 the SAME defect - the T400 stale-debounce fetch
count flaking in the win32 lane - was filed as **T615**, then **T643**, then
**T649**, by three different turns, each of which had just watched the lane go
red and had no cheap way to ask "is this known?". T643 and T649 are now
`skipped(duplicate of T615)`.

## Details

The cheap version is a title-token overlap check against open tasks: normalise
the title (lowercase, drop stopwords and punctuation), and warn when an existing
open task shares enough distinctive tokens. Distinctive is the operative word -
`viewer`, `windows`, `test` and `pane` are in half the backlog, so raw overlap
would fire constantly. Weighting tokens by inverse frequency across the corpus
(a crude idf over the ~680 titles) is enough to make `stale-debounce` and `t400`
carry the match while `test` carries almost nothing.

Warn, never block: `new` is called by agents mid-turn and a false positive that
refuses to file would lose work. Print the candidate ids with their titles and
carry on, so the filing agent can close its own duplicate in the same breath.

Worth also matching on the identifiers a defect carries in its title (a symbol
name, a test name, an existing task id in parentheses), since those are exactly
the tokens that make two reports of one defect look alike.

## Validation criteria

- [ ] Filing a task titled like T615's prints a warning naming T615, and still
      creates the file with a fresh id.
- [ ] Filing a title that shares only common words with the backlog prints no
      warning (checked against a handful of real recent titles).
- [ ] A unit or script-level check covers both cases, so the heuristic cannot
      silently rot.
