# T605 - The pane activity-state machine still lives in the external plugin on Windows; main moved it into the app

## In plain terms

The dot that tells you whether a pane is idle, working, or waiting on you is
driven by a hook script. Until now that script came from a separately installed
plugin, so the behavior depended on which version of the plugin you had. The Mac
now ships the state machine inside Ghoztty itself. Windows should too, so the
indicator means the same thing on every box.

## Summary

Upstream: `c182302e3` "feat(activity-state): own the pane state machine, from
plugin 0.10.0" - adds `macos/Resources/Ghoztty/hooks/ghoztty-activity-state.sh`,
extends `HookSpec`/`ClaudeHookSpec`/`CopilotHookSpec` and
`BannerScriptInstaller`, and lands `scripts/test-activity-state.sh` as the
oracle.

Windows translation: the hook is a `.sh`; this box needs a PowerShell (or direct
`ghoztty +set-state`) flavor, installed by the same mechanism as T598, with a
PowerShell equivalent of `test-activity-state.sh`.

The machine tokens are a public API (`idle`/`busy`/`needs_input`, OSC 7777,
`AXWindowActivityState`); this task must not change them. See also T465 (the
win32 title still interpolates the raw token instead of the human label).

## Validation criteria

- [ ] The state machine ships with the app on Windows and drives the pane
      indicator with no external plugin installed.
- [ ] The transitions match the Mac oracle case for case (a Windows port of
      `scripts/test-activity-state.sh` passes).
- [ ] An externally installed plugin does not double-drive the state.
- [ ] `idle`/`busy`/`needs_input` tokens unchanged on the wire and in
      `+set-state`.
