# T605 - The pane activity-state machine still lives in the external plugin on Windows; main moved it into the app

## In plain terms

The dot that tells you whether a pane is idle, working, or waiting on you is
driven by a hook script. Until now that script came from a separately installed
plugin, so the behavior depended on which version of the plugin you had. The Mac
now ships the state machine inside Ghoztty itself. Windows should too, so the
indicator means the same thing on every box.

## Goals

- [x] The bundled activity-state hook actually works under Git Bash on
      Windows (it was broken: every subagent marker was reaped instantly).
- [x] Main's own 16-case oracle runs on this box and passes case for case.
- [x] The native-pid semantics the oracle cannot see are proven with real
      native processes.
- [x] The fork is tripwired against re-vendor and covered by guard-due.

## Summary

Upstream: `c182302e3` "feat(activity-state): own the pane state machine, from
plugin 0.10.0" - adds `macos/Resources/Ghoztty/hooks/ghoztty-activity-state.sh`,
extends `HookSpec`/`ClaudeHookSpec`/`CopilotHookSpec` and
`BannerScriptInstaller`, and lands `scripts/test-activity-state.sh` as the
oracle.

Windows translation: the hook is a `.sh`; this box needs a PowerShell (or direct
`ghoztty +set-state`) flavor, installed by the same mechanism as T598, with a
PowerShell equivalent of `test-activity-state.sh`.

The machine tokens are a public API (`idle`/`busy`/`needs_input`, OSC 7777,
`AXWindowActivityState`); this task must not change them. See also T465 (the
win32 title still interpolates the raw token instead of the human label).

## Validation criteria

- [x] The state machine ships with the app on Windows and drives the pane
      indicator with no external plugin installed. — Shipped by T866/T867/T868
      (embedded asset, installed to `~/.config/ghoztty/hooks`, all six Claude
      events registered); this task made the shipped machine actually WORK on
      Windows: the vendored script's owner/liveness recovery was broken under
      Git Bash (measured: MSYS `kill -0` reports a live native pid as "No such
      process", and a hook spawned by a native agent sees PPID=1), so every
      subagent marker was reaped the moment it was written and a pane with
      live background subagents reported idle. Fixed with OSTYPE-guarded
      `owner_winpid` (native-tree CIM walk from `/proc/$$/winpid`) and
      `pid_alive` (one `ps -W` snapshot per reap); POSIX paths untouched.
- [x] The transitions match the Mac oracle case for case. — Main's
      `scripts/test-activity-state.sh` is vendored pristine at
      `test/win32/lib/upstream/` (blob-identical to origin/main, asserted) and
      run VERBATIM under Git Bash against the live win32 asset by
      `test/win32/activity-state.ps1` section B (the only edit is the SCRIPT=
      line, asserted to be exactly one line): 16/16 oracle cases pass, plus
      native-pid arms the oracle cannot see (section C). ALL PASS (28
      assertions).
- [x] An externally installed plugin does not double-drive the state. — Two
      layers, both pre-existing and unit-tested: `claude_plugin_manifest.zig`
      (T869) withholds BOTH components while an external ghoztty plugin is
      registered, and the machine namespaces its markers per runtime (oracle
      case "runtime namespacing keeps two agents' state apart", passing).
- [x] `idle`/`busy`/`needs_input` tokens unchanged on the wire and in
      `+set-state`. — The fork touches only owner/liveness resolution; the
      oracle's expected-state sequences are main's own strings and pass
      unmodified, and P3's +set-state/OSC 7777 sections stay green.
