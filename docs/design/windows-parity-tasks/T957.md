# T957 - Stage 0 merge prep: a permanent upstream remote, and union-merge drivers for the append-only files

## Summary

Two pieces of Stage 0 from docs/design/windows-parity-merge-back-plan.md, both landing no upstream code. (1) Upstream head ad6e72ddc is only in the object store because divergence-inventory.ps1 fetched it; no ref keeps it alive, so every sha in the merge plan can be garbage-collected out from under the doc. Add a permanent 'upstream' remote (https://github.com/ghostty-org/ghostty.git) and fetch it. (2) Add .gitattributes merge drivers for the files where both sides only ever append - .gitignore is the known one - so those never present as conflicts in any merge stage at all.

## In plain terms

Ghoztty is a fork of Ghostty, and the plan for catching up with the original
project names six specific points in its history to merge from, one at a time.
Those six points were being remembered by nothing: git had the commits sitting
loose in its database and was free to delete them at any cleanup, which would
have left a plan full of references to history nobody could find any more. This
pins them properly, and it does it in a way that survives a fresh copy of the
repo instead of living in one machine's local settings.

The second half is about the files both projects keep adding lines to - the
ignore list, and the two running logs both machines append to. Those produce a
merge conflict every time, and the answer is always "keep both sets of lines",
so git is now told to do exactly that instead of stopping to ask.

## Goals

- [x] a permanent `upstream` remote, fetched, with every sha the merge plan
      cites reachable from a real ref
- [x] that remote re-asserts itself on any clone, not just this one
- [x] `.gitignore` merges by union instead of conflicting, losing nothing from
      either side
- [x] the same for the two ledgers both seats append to
- [x] a harness that would notice if any of it silently stopped working
