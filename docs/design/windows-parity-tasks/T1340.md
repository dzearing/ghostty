# T1340 - Nothing on the box notices if a full tombstone table starts costing hundreds of megabytes again

## Summary

T470 measured the agent at 524.7 MB with 256 seeded tombstones and 13.8 MB after the lazy-ring fix, using scripts\t470-ring-measure.ps1 - a tool that is run by hand and asserts nothing. The unit test in session.zig counts REQUESTED bytes for a materialized table, which is the right regression guard for the ring itself, but it cannot see a future change that makes a tombstone expensive some other way (an eagerly-built emulator, a per-session buffer, a copy of the manifest). test\win32\agent-session-cap.ps1 already seeds exactly this roster and starts a real agent, so it is one Assert away from bounding the agent's working set on box. Give it that assertion with a generous ceiling - the point is to catch a 40x regression, not to police 2 MB of noise - and fold the standalone measurement script into it.
