# T310 - T227a: chooser metrics, type ramp and secondary contrast floor (findings 4,7,8,9,12)

## Summary

First of three splits of **T227** (the Ctrl+Shift+N polish pass). This one is
the arithmetic half: everything in `chooser_layout.zig` / `chooser_rows.zig`
that `docs/design/win32-machine-chooser.md` §3.2 says is off target, plus the
one color defect that lives in the same module.

Scope is §4 findings **4, 7, 8, 9, 12** (and **13** as a verify):

| # | What | Target (§3.2) |
|---|---|---|
| 4 | `font_h = 15`, no caption role | body **14**, caption **12**, subtitle **20 semibold** |
| 7 | row `fill_radius = 6` | **4** (design system §3.1: list items are the smallest surface) |
| 8 | icon column 20 wide | **28** box, mark drawn at `SM_CXSMICON` (16) scaled |
| 9 | five off-scale spacings: `fill_inset_y=1`, `title_y=7`, glyph gap 6, text gap 10, `text_pad_right=10` | 2/4/8/12/16/24 only |
| 12 | `secondary_gray` is a fixed `#999999` with no contrast floor | derived, >= 4.5:1 against the surface it lands on |
| 13 | status strip caps at 4 lines and steals from the list | verify the list still holds 5 rows at 200% |

Findings 1, 2, 3 are NOT here: 2 and 3 were already fixed by **T305** (the
washes are `color_math.wash` and the accent is a parameter), and 1 (the
hardcoded dark constants in `MachineChooser.zig` / `HostSettingsDialog.zig`) is
**T308**. Findings 5/6 are **T311**, finding 10 is **T312**, finding 11 is T146.

## Details

### The type ramp has to be hoisted, not edited in place

`font_h = px(15, scale)` is written out SEVEN times — `chooser_layout`,
`HostSettingsDialog`, `ActivityMonitor`/`activity_layout`, `BannerDialog`,
`ConfirmDialog`, `NewProcessDialog`, `RenameDialog`. Changing the chooser's copy
to 14 would make the chooser the one dialog that disagrees with the rest, which
is the *inconsistency* defect the design system exists to stop.

So the ramp becomes a module — `src/apprt/win32/type_ramp.zig`, pure and
tested — and this task points the **Ctrl+Shift+N surface** at it (chooser +
Host Settings, which is the surface T227 owns). The remaining five dialogs are a
follow-up, not silently left behind.

The ramp is a deliberate divergence from `SPI_GETNONCLIENTMETRICS` (12 px body)
and §3.2 already records why: Win11's own modern apps are at 14, and matching
the 9 pt GDI font would make the surface look like a 2009 dialog next to
Settings. It is 12/14/20 and nothing else.

### `secondary_gray` is the same defect T305 fixed one module over

`#999999` is 2.8:1 on `#F3F3F3` — under the 4.5:1 text floor and under the 3:1
chrome floor — so on a light surface the sublines, the offline ring and the
machine glyph all go illegible together. The fix is the one `chrome_theme`
already makes for the bar's own de-emphasized text: wash the surface toward its
own contrasting side, then clamp by search. `chrome_theme.resolve` does this
inline for `text_secondary`; hoisting it to `textSecondaryOn(surface)` (beside
`textOn` / `accentOn`) is what lets the chooser consume it instead of
re-deriving it — the T206 rule.

### Validation

- `chooser_layout` / `chooser_rows` / `type_ramp` unit tests in the none lane,

- A **spacing-scale test** that walks the layout's gaps and fails on any value

- Colors asserted as relationships and as contrast RATIOS, never as literals.
- `test/win32/ipc-machine-chooser.ps1` gains pixel assertions for the new row

- Floor: both `zig build test` lanes, `test-agent`, P1-P3.

## What landed

**New module `src/apprt/win32/type_ramp.zig`** — caption 12 / body 14 / body
strong 14@600 / subtitle 20@600, plus the face. It exists because the number did
not: `font_h = px(15, scale)` was written out in **seven** dialogs, a size
nobody chose. Editing the chooser's copy to 14 would have made the chooser the
one dialog that disagrees with the rest, which is the *inconsistency* the design
system exists to stop — so the ramp is hoisted and the Ctrl+Shift+N surface
(chooser + Host Settings) is pointed at it. The other five are **T313**, filed
rather than silently left behind. `win32-design-system.md` gains §2.4 so the
ramp is stated once outside the code too.

**`chrome_theme.textSecondaryOn(surface)`** — hoisted out of `resolve`, beside
`textOn`/`accentOn`, so the chooser can consume the de-emphasized ramp instead
of re-deriving it (T206). `resolve` now calls it, which is what keeps the bar's
answer and the chooser's from drifting.

**Geometry, all in the pure modules:**

| Finding | Before | After |
|---|---|---|
| 4 | `font_h = 15`, no caption role, detail subtitle drawn at body | ramp 12/14/20; detail subtitle and status strip at caption |
| 7 | `fill_radius = 6` | `4` (§3.1 — a list item is the smallest surface) |
| 8 | a 20-wide mark WAS the column | a **28 reserved column** with a **16** mark centered in it |
| 9 | `fill_inset_y=1`, `title_y=7`, gaps 6 / 10 / 10 | rhythm 2 (inset derived), `4`, gaps 4 / 12 / 8 |
| 12 | `secondary_gray = #999999`, no floor | `secondaryOn(bg)` (4.5:1) and `onlineOn(bg)` (3:1) |

Two things beyond the finding list, both on the same surface and both one line:

- **`filter_pad` 14→12 and `gap` 10→8** — §3.2's mapping names those two Mac
  numbers explicitly; they were copied here verbatim and are what the new
  layout-side scale test fails on.
- **One control height (28) across the surface** — the filter field and the
  account control were 26 while Cancel and the action row were 28. A 2 px
  difference does not read as a hierarchy, it reads as nobody having decided.

**The status strip now renders in the caption font, and is MEASURED in it.**
`hint_line_h` is derived from the caption role, so `measureHintLines` had to
select the same font — measuring the wrap with the body font while the STATIC
renders in caption is how a reserved height quietly stops being the height that
gets used, which is the T140 clipped-footer defect coming back by a side door.

- Unit: `type_ramp` (4 tests), `chooser_rows` (+5), `chooser_layout` (+4),

  module — that walk every gap and fail on any value outside {2,4,8,12,16,24}

- Contrast is a **sweep**, not a pair: `secondaryOn` clears 4.5:1 and `onlineOn`

  `tab-strip` (56), `activity-monitor` (82).

### The one thing that could NOT be validated on box, and why

**Finding 12 has no pixel oracle today.** The defect is a light-theme defect —
`#999999` is 2.8:1 on `#F3F3F3` and 5.2:1 on the dark wash the chooser actually
paints — and the chooser is still hardcoded dark (finding 1, **T308**). So a
pixel probe for the contrast floor would be measuring a surface this build
cannot produce. Per T305's rule (*a validation step a correct build cannot
satisfy is a defect in the task*) the claim is scored where it is real: the
96-background unit sweep. When T308 lands, the light theme becomes reachable and
the probe becomes worth writing.

The pixel claim T310 *can* make is finding 8's, and it does: the row's text
column moved 8 DIP right, measured as the first bright column in row 0's band
(**87 px at 1.25**, against ~78 for the retired geometry — the threshold is on
brightness, so the dim glyph beside it is not mistaken for the title). Writing
that probe turned up **T314**: this script keeps a private banker's-rounding
`Dip`, the T257 divergence in the one script T257 did not sweep, which is why
the bounds are a band rather than an equality.
