# T29 — Mac-side: fix action fallthroughs to showChildExited (Phase I)

## Summary

Mac-side: action fallthroughs to showChildExited

## Details

Audit found `toggle_window_decorations`, `size_limit`, `quit_timer`, and
`toggle_tab_overview` in the Mac app's action dispatch falling through to
`showChildExited` (apparent bad merge in `Ghostty.App.swift` switch).
Verify against the Mac source; if real, fix the switch. Win32 is
unaffected (it implements these properly).

*Validation:* Mac build: toggling window decorations via keybind works;
`quit-after-last-window-closed` delay still honored. Run the Mac
regression build.

## Verification (2026-08-02)

**The finding is REAL** — ✓ VERIFIED by reading
`macos/Sources/Ghostty/Ghostty.App.swift:672-681` (pre-fix): four cases
chained by `fallthrough` into

```swift
case GHOSTTY_ACTION_SHOW_CHILD_EXITED:
    return showChildExited(app, target: target, v: action.action.child_exited)
```

**It is NOT a bad merge in this fork.** `git log -L` on the region names the
cause exactly: upstream **`38e64c370`** ("macOS: add bottom bar when child
exits", 2026-04-12, on `main`) replaced the shared body

```swift
Ghostty.logger.info("known but unimplemented action action=\(action.tag.rawValue)")
return false
```

with the `showChildExited` call and **left the four preceding `fallthrough`s
attached to it**. Before that commit all five cases shared the unimplemented
body, which is why the chain looks deliberate — it was, for the body it used
to have. The task summary's "apparent bad merge" is corrected here; this is
an inherited upstream defect.

### Why it is a real bug and not a cosmetic one

Every case in that switch reads `action.action` as a **different member of the
same C union**. Falling into `SHOW_CHILD_EXITED` reads
`ghostty_surface_message_childexited_s` no matter which action arrived:

- `size_limit` (`SizeLimit`: 4 x `u32`) overlays `child_exited`
  (`exit_code: u32` @0, pad, `timetime_ms: u64` @8). `Surface.zig:1132` emits
  it on **every surface creation** with `max_width = max_height = 0`, so
  `timetime_ms` reads 0, the `v.timetime_ms > 0` guard at
  `Ghostty.App.swift:1751` fails, and it returns false — the same answer the
  unimplemented body gave. Harmless by luck, which is why nobody noticed.
- `toggle_window_decorations`, `toggle_tab_overview`, `quit_timer` are
  **void-payload** actions. `Action.cval` (`src/apprt/action.zig:496`) builds
  the C union with `@unionInit(CValue, tag, {})`, which leaves the union's
  remaining bytes **undefined** — so `child_exited.timetime_ms` is garbage. A
  nonzero read calls `surfaceView.setExitCode(garbage)` and
  `setChildExitedMessage(...)`, i.e. **a bogus "process exited" bar over a
  live surface**, from a keybind the user pressed to toggle decorations.
  (`quit_timer` targets the app, so it lands in `showChildExited`'s
  `default: return false` and is only mis-dispatched, not visibly wrong.)

## Fix

`macos/Sources/Ghostty/Ghostty.App.swift` — `SHOW_CHILD_EXITED` becomes its
own case; the four unimplemented actions get their own chain ending in the
restored `known but unimplemented ... return false` body, with a comment
naming `38e64c370` and the undefined-union-bytes hazard so the chain is not
re-merged.

Returning `false` for `quit_timer` is correct on macOS and matches upstream's
pre-`38e64c370` behavior: ✓ VERIFIED that `quit-after-last-window-closed` is
handled natively by
`AppDelegate.applicationShouldTerminateAfterLastWindowClosed`
(`macos/Sources/App/macOS/AppDelegate.swift:500`), not by the action.

## Win32 is unaffected — ✓ VERIFIED

All four have their own arms in `src/apprt/win32/App.zig`: `.quit_timer`
(:3213), `.toggle_tab_overview` (:3447), `.toggle_window_decorations`
(:3534), `.size_limit` (:3818). More structurally: the win32 apprt switches
on a **Zig tagged union**, where the compiler binds each arm's payload to its
own tag. This defect class is only reachable across the C-union boundary — it
cannot be written in the Zig apprt.
