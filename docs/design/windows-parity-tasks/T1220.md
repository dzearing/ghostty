# T1220 - The loop publishes at the end of a day's work

## In plain terms

Your terminal now only ever runs published builds, which is what you asked for.
The trade you accepted was that a fix reaches you once it is released rather
than within the hour - and the promise attached to that trade was that the loop
publishes at the end of a day's work, so "today's fixes" still arrive today.
Right now nothing does that automatically: the day's work lands in the branch
and sits there until someone publishes by hand.

## What has to change

- **A publish happens once a day, at the end of the day's work**, carrying
  everything that landed since the last one. The trigger should be the same
  shape as the old morning refresh's: a real signal (the last task-boundary push
  of the day) rather than a clock alone, and once per day with a durable
  watermark.
- **It runs `scripts\publish-windows-release.ps1`**, which already builds the
  ReleaseFast staging prefix, packages the MSI + portable ZIP and creates the
  `win-v<Version>` release. Two things it needs that the loop cannot assume:
  **Docker Desktop must be up** (wixl does not run on Windows) and `gh` must be
  authenticated. A publish that cannot run is a SKIP with a named reason, never
  a silent no-op and never a failure that stalls the loop.
- **Version choice has to be decided, not defaulted.** `-Version` currently
  tracks the newest macOS `vX.Y.Z` tag, which is right for a release that
  accompanies a Mac one and wrong for a daily Windows-only publish that would
  keep re-publishing the same tag. Decide the daily-publish version scheme
  (a patch bump? a build number? re-publishing the same win-v tag?) and make the
  script refuse to clobber an existing release by accident.
- **The digest says what shipped.** The morning read should be able to answer
  "is what I am running the work I read about yesterday?".

## Validation criteria

- [x] A day's work ends with a published `win-v*` release containing that day's
      commits, without anyone typing a publish command. **How:** go.md step 6.5
      now runs `scripts\daily-publish.ps1` on every turn; it fires on the first
      task-boundary push at or after 17:00 local and runs
      `publish-windows-release.ps1` once. Section G of
      `test\win32\daily-publish.ps1` drives the due path live (sandbox
      watermark, sentinel publish script) and asserts the day is stamped and the
      tag chosen; the real firing against Docker is T1261.
- [x] A box with Docker down, or `gh` unauthenticated, SKIPS with the reason
      named in the log and the loop continues normally. **How:** section F runs
      the real script with a fake `docker`/`gh` ahead of PATH and asserts exit 0,
      the reason in the log, an untouched watermark and an uninvoked publish
      script. Confirmed live on this box: `-Check -Now 18:30` printed
      `SKIP: due (...) but Docker Desktop is not running`.
- [x] The publish never re-publishes over an existing release by accident; the
      version scheme is written down and enforced by the script. **How:**
      `Resolve-DailyPublishVersion` derives the version from the releases that
      exist (gh, unioned with local tags) - track the newest Mac `vX.Y.Z` line,
      walk the patch from the newest `win-v` above it. Section B covers all six
      arms plus the property that the chosen version is never one already
      released; `publish-windows-release.ps1` still refuses an existing tag.
      Scheme documented in go.md 6.5 and the script header; filed for the user
      as D88.
- [ ] The installed terminal offers that release through the in-app updater, and
      after applying it reports the published version. **Not validated here:**
      the real publish needs Docker Desktop, which is down and is the user's call
      to start. Carried in full by T1261.
- [x] An acceptance script covers the due/not-due decision and the skip paths
      the way `morning-refresh.ps1`'s harness covered its own. **How:**
      `test\win32\daily-publish.ps1`, 7 sections, ALL PASS; `-NegativeControl`
      scores 57 failures / 0 passes, so it can go red. Gated by a new
      `daily-publish` row in `scripts\guard-due.ps1`.
