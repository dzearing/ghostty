# T1220 - The loop publishes at the end of a day's work

## In plain terms

Your terminal now only ever runs published builds, which is what you asked for.
The trade you accepted was that a fix reaches you once it is released rather
than within the hour - and the promise attached to that trade was that the loop
publishes at the end of a day's work, so "today's fixes" still arrive today.
Right now nothing does that automatically: the day's work lands in the branch
and sits there until someone publishes by hand.

## What has to change

- **A publish happens once a day, at the end of the day's work**, carrying
  everything that landed since the last one. The trigger should be the same
  shape as the old morning refresh's: a real signal (the last task-boundary push
  of the day) rather than a clock alone, and once per day with a durable
  watermark.
- **It runs `scripts\publish-windows-release.ps1`**, which already builds the
  ReleaseFast staging prefix, packages the MSI + portable ZIP and creates the
  `win-v<Version>` release. Two things it needs that the loop cannot assume:
  **Docker Desktop must be up** (wixl does not run on Windows) and `gh` must be
  authenticated. A publish that cannot run is a SKIP with a named reason, never
  a silent no-op and never a failure that stalls the loop.
- **Version choice has to be decided, not defaulted.** `-Version` currently
  tracks the newest macOS `vX.Y.Z` tag, which is right for a release that
  accompanies a Mac one and wrong for a daily Windows-only publish that would
  keep re-publishing the same tag. Decide the daily-publish version scheme
  (a patch bump? a build number? re-publishing the same win-v tag?) and make the
  script refuse to clobber an existing release by accident.
- **The digest says what shipped.** The morning read should be able to answer
  "is what I am running the work I read about yesterday?".

## Validation criteria

- [ ] A day's work ends with a published `win-v*` release containing that day's
      commits, without anyone typing a publish command.
- [ ] A box with Docker down, or `gh` unauthenticated, SKIPS with the reason
      named in the log and the loop continues normally.
- [ ] The publish never re-publishes over an existing release by accident; the
      version scheme is written down and enforced by the script.
- [ ] The installed terminal offers that release through the in-app updater, and
      after applying it reports the published version.
- [ ] An acceptance script covers the due/not-due decision and the skip paths
      the way `morning-refresh.ps1`'s harness covered its own.
