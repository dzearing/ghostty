# T545 - +sessions and LIST_SESSIONS never show what a plain-shell session is running: surface the sampled fg_cmd in the roster

## In plain terms

`ghoztty +sessions` lists the background terminal sessions with their working
directory and command — but for a normal terminal (one where the user typed
their command at the prompt) the command column is empty, because the recorded
label only exists for panes opened with an explicit `--command`. Since T429 the
agent already samples what is actually running (`Session.fg_cmd`); this task
shows it in the roster, so a user scanning their sessions can see "this one is
running claude" at a glance.

## Summary

- Agent: `handleListSessions` (`server.zig`) adds `fg_cmd` to
  `protocol.SessionInfo` (additive/optional, same precedent as
  `Attached.foreground_cmd` — no capability gate).
- CLI: `+sessions` rendering shows the fg command when `argv` is null (or both,
  with a marker distinguishing "opened with" from "currently running" — pick
  one presentation and keep `--json` carrying both fields verbatim).
- The machine chooser's session roster (win32 + mac) could show the same value
  on its cards; keep that in scope only if it is a small change, otherwise file
  it separately when this lands.

## Goals

- [x] the agent's roster carries what the session is running (`SessionInfo.fg_cmd`)
