# T726 - test\win32\persistence-flag.ps1 is red: 4 launch sites declare no session persistence

## In plain terms

The test suite has a rule that every test which opens a terminal window must say
out loud whether it wants the previous run's windows restored on top of it. Four
places now break that rule, so the check that enforces it reports a failure - and
a check that is always red is a check nobody reads. Until it is green again, a
test can quietly inherit another test's windows and fail for reasons that have
nothing to do with what it is testing.

## Summary

`test\win32\persistence-flag.ps1` (T158) enumerates every GUI launch across
`test\win32\` and requires each to DECLARE its session-persistence intent - by
passing `--session-persistence=`, by passing something built from it, by having
every caller of its helper pass it, or by carrying a `# persistence: <reason>`
marker. As of 2026-08-10 it reports:

```
FAIL  A1 no launch leaves persistence unstated (undeclared: 4 of 164)
      declared by: literal=69, marker=62, =4, callers=5, var=24
```

The four sites (from `Get-GhozttyLaunchSites -Root test\win32`):

- `agent-attach-refused.ps1:276`
- `url-scheme.ps1:359`
- `url-scheme.ps1:381`
- `url-scheme.ps1:368`

Found while running the sweeps for T198, which touched none of those files - so
this is a pre-existing regression from whichever turn added them, not fallout
from that work. Sections B1-B4 of the sweep still pass, so the enumerator itself
has teeth; it is the corpus that drifted.

## Details

Each site needs the same judgement T158 describes: decide what the launch WANTS
and say it. The `url-scheme.ps1` launches are activation-and-exit second
instances in a suite whose subject is the `ghoztty://` handler, which is very
likely the `# persistence: <reason>` case rather than a flag; the
`agent-attach-refused.ps1` one is in a family that deliberately wants
persistence ON, so it probably wants the flag written explicitly. Read each
before assuming.

## Validation criteria

- [ ] `powershell -NoProfile -File test\win32\persistence-flag.ps1` prints
      `ALL PASS` (A1 back to 0 undeclared).
- [ ] Each of the four sites got a deliberate declaration, not a blanket marker:
      the reason recorded matches what that launch actually wants.
- [ ] `test\win32\url-scheme.ps1` and `test\win32\agent-attach-refused.ps1` are
      still green afterwards.
