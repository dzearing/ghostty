# T360 - reset_window_size lands the client 38 px too tall: setClientSize predicts the frame with AdjustWindowRectEx, but T254 took over WM_NCCALCSIZE

## In plain terms

The "reset window size" action is supposed to snap the window back to its
default size, but on Windows it came back 38 pixels taller than it should
every time — and the very first window of a session opened slightly too tall
for the same reason. The code was estimating how thick the window's title bar
and borders are instead of measuring them, and the estimate stopped being true
when Ghoztty started drawing its own title bar. Now the window measures its
own frame, so resets and new windows land at exactly the size they promise.

## Goals

- [x] `reset_window_size` returns the client area to exactly the asked-for
      size (800×600 fallback included), not 38 px over.
- [x] The window-setup `initial_size` (same code path) lands exactly too.
- [x] The conversion arithmetic lives in a pure geometry module asserted at
      1.0/1.25/1.5/2.0 scaling.
- [x] Every other `AdjustWindowRectEx` caller audited for the same stale
      assumption.

## Validation criteria

- [x] `test\win32\reset-window-size.ps1` → ALL PASS (14 assertions; was

- [x] `test\win32\window-size-memory.ps1` → ALL PASS (30 assertions; was

- [x] Neither script's expected numbers were edited — the product moved, not

- [x] Standing floor: `scripts\floor-lane.ps1 -Lane all` → none/win32/agent

- [x] P1–P3 acceptance scripts → ALL PASS, run sequentially after the lanes.

## Summary

`Window.setClientSize` (`src/apprt/win32/Window.zig`) turns a wanted CLIENT
size into an outer size with

```zig
_ = w32.AdjustWindowRectEx(&rect, w32.WS_OVERLAPPEDWINDOW, 0, 0);
```

That asks Windows for the frame of a **standard** `WS_OVERLAPPEDWINDOW`. Since
T254 the window handles `WM_NCCALCSIZE` itself and draws its own caption INSIDE
the client area, so the real frame is nothing like the one being predicted. The
client therefore lands 38 px taller than asked, and `reset_window_size` - whose
whole job is "return to the default size" - does not.

It is the same site that applies the window-setup `initial_size`, so the miss is
not confined to the reset action.

## Evidence (VERIFIED on the box, 2026-08-02, while validating T267)

No `src/` file was modified in that turn, so this is a pre-existing product
defect that T267's run-order work simply exposed. Two independent scripts, two
independent fixtures, the same wrong number:

- `test\win32\reset-window-size.ps1` - `FAIL  fallback: reset with no configured
  size went to 800x600 (was 1002,731, got 800,638)`. 1 FAILED / 13 passed.
- `test\win32\window-size-memory.ps1` - `FAIL  C: reset_window_size still resets
  to the default client size (got 800,638)`. 1 FAILED / 29 passed.

800 wide is exactly right and 638 is 38 too tall, which is the caption band the
prediction does not know about. Both scripts' CONFIGURED-size cases still pass
(`cfg: reset returned to configured size (1158,460 == 1158,460)`), because those
compare a client size against a client size measured through the same wrong
frame - only the absolute 800x600 fallback states the number outright.

## The fix

- Derive the outer size from the window's OWN frame, not from
  `AdjustWindowRectEx(WS_OVERLAPPEDWINDOW)` - the delta between `GetWindowRect`
  and `GetClientRect` for this hwnd, or the same metrics `caption_layout.zig`
  uses, so a caption-owning window and a plain one both land exactly.
- Check the other `AdjustWindowRectEx` callers in `src/apprt/win32/` for the
  same stale assumption; the T254 takeover invalidated the prediction
  everywhere, not just here.
- Put the pure arithmetic in a geometry module and assert it at 1.0/1.25/1.5/2.0
  scaling, per the design-system rule.

## Validation

- `powershell -NoProfile -File test\win32\reset-window-size.ps1` -> ALL PASS.
- `powershell -NoProfile -File test\win32\window-size-memory.ps1` -> ALL PASS.
- Neither script's expectation changes: 800x600 client IS what the action
  promises, and the product is what is wrong. Do not "fix" this by editing the
  number in the test.
