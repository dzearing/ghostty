# T685 - The parity sweep watches only macos/ and src/viewer/, so main's changes to shared src/ are ungated

## Summary

scripts\parity-sweep.ps1 (T152) enumerates commits touching macos/ or src/viewer/, which is what the 2026-07-29 audit measured and therefore what the gate inherited. But parity obligations also arrive through the SHARED core: T604 exists precisely because main rewrote src/cli/send_keys.zig while this branch built bracketed-paste framing on top of it, and nothing flagged the divergence - a shared-path sweep would have. The reason it is not simply a wider -Paths default is that this branch's own win32 work lives in src/ too, so a naive sweep would report several hundred of our own commits as unmapped and the gate would be ignored within a day. Evaluate the shape that works: probably restricting the enumeration to commits reachable from origin/main but not from the merge-base (the incoming side only), which is well-defined for the intake range and is what the intake actually cares about. Then decide which shared subtrees are worth watching (src/cli/, src/termio/, src/apprt/ipc/ are high-signal; src/apprt/win32/ is ours). Ship it with acceptance arms in test\win32\parity-sweep.ps1 proving our own commits are not reported.
