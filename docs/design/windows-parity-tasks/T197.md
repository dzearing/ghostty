# T197 - Harness audit: Run-CliArgs exit codes are unreadable unless .Handle is cached first

## Summary

`Start-Process -PassThru` + a TIMED `WaitForExit(ms)` leaves `$p.ExitCode`
**empty** unless the process handle was cached (`$null = $p.Handle`) *before the
process exited*. The idiom copied around `test/win32/` touches `.Handle` AFTER
the wait, which is too late whenever the child exits quickly — so every caller
that gates on `if ($code -ne 0) { fail }` scores a **working** CLI as a failure.
Caught live building `agent-upgrade.ps1` (T147): six assertions failed against a
build whose complete, correct `+list --json` output was sitting in the redirect
file. The log already records this trap once (T145, "the harness lied three
times"), and it recurred anyway — which is the argument for auditing it out of
every script rather than re-learning it per harness.

## Details

Two fixes, and the second matters more than the first:

1. **Cache the handle first.** `$null = $p.Handle` immediately after
   `Start-Process`, before any wait. (Done in `agent-upgrade.ps1`.)
2. **Do not gate an outcome on an exit code when the OUTPUT is the answer.**
   `Get-List` should parse the JSON it got; `+read` oracles should look for the
   marker. A harness that discards a complete answer over a shell-plumbing
   detail is a harness that fabricates failures — and a fabricated failure costs
   more than a missed one, because it sends the next session hunting a defect
   that isn't there.

Audit every `test/win32/*.ps1` that starts the CLI with `-PassThru` and reads
`ExitCode`, and either cache the handle first or re-gate on the output. Note
that some scripts pass today only because their child is slow enough to still be
running when `.Handle` is touched — i.e. they are timing-dependent, not correct.

## Validation

- Grep the suite for `WaitForExit(` + `ExitCode` and show each site is either
  handle-cached-first or output-gated.
- Re-run the touched scripts ×1 each; ALL PASS unchanged (this is a harness
  correctness change and must not move a single product verdict).
