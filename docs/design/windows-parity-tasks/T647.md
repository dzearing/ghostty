# T647 - Viewer feedback: screenshot capture from the + button and Ctrl+Shift+S

## In plain terms

The feedback box has a `+` button that should let you grab a picture of what
you are complaining about. On Windows it currently does nothing. This makes it
take a screenshot — and, critically, without wiping whatever you had on your
clipboard, which is what every built-in Windows snipping tool does.

## Summary

Split out of T637, which landed the image half of the composer (storage, stable
chip numbering, clipboard paste, images written into the report). What is left
is the CAPTURE primitive behind the `+` action and Mac's ⇧⌘S — on Windows,
Ctrl+Shift+S while the composer has focus.

Everything downstream already exists: a captured PNG goes through
`ViewerFeedbackBar.attachImage`, which allocates the chip number, inserts the
`[Image #N]` chip and puts the file in the report. This task only has to
produce the bytes.

## Details

- **Take D44's answer.** The decision (`docs/design/windows-parity-decisions/D44.md`)
  is filed and open; its recommended option is a ghoztty-drawn region selector
  over a screen snapshot, because it matches what Mac's `screencapture -i -o`
  actually does and touches no clipboard. `ms-screenclip:` / `SnippingTool /clip`
  are ruled out precisely because they publish through the clipboard.
- **The user's clipboard must come back byte-identical.** That is a validation
  criterion, not a footnote — put a known string on the clipboard, capture, and
  read it back.
- The layered-overlay and DPI-aware screen-capture machinery from the pixel-probe
  work is the starting point; multi-monitor and per-monitor DPI are ours to get
  right (a virtual-screen-sized overlay, not a primary-monitor one).
- Escape cancels with nothing added to the composer; a zero-area drag is a
  cancel, not an empty image.
- PNG encoding is already there and is pure: `png_encode.encode` takes top-down
  RGB/RGBA pixels, and `clipboard_image.normalize` is the worked example of
  getting those out of a GDI bitmap.

## Validation criteria

- [ ] On-box acceptance: capture a screenshot from the `+` button and from
      Ctrl+Shift+S; a chip and an image file result.
- [ ] On-box acceptance: the clipboard's contents before and after a capture are
      byte-identical (put a known string on it first and read it back).
- [ ] On-box acceptance: Escape during a capture cancels — no chip, no file.
- [ ] Unit tests (none lane): the selector's rect math (drag in any direction
      yields a normalized non-empty rect; a zero-area drag yields none).
