# T759 - A terminal split off a viewer with no file inherits the app-global focused surface, so it can open in another window's directory (Mac half of T538)

## Summary

The Mac half of T538. `BaseTerminalController.splitConfigFromViewer` sets a
working directory only when the viewer has a `fileURL`; a website, a blank
browser pane or a diff pane leaves it nil, and the answer then comes from the
core's `apprt/surface.zig` `newConfig`, which reads **`app.focusedSurface`** —
an APP-GLOBAL value. When the focused surface is a pane in a different window
(or there is none), the new terminal opens in that other window's directory, or
in the shell's home.

win32 fixed this in T538 by asking the window being split instead: the focused
surface when it belongs to THAT window, else the nearest terminal pane in the
viewer's own tab, found with the new `SplitTree.nearestLeaf` (pure, tested in
the none lane, so the Mac side can reuse the same search through the shared
`datastruct/split_tree.zig` — Swift's own `SplitTree` is a separate
implementation, so this is a port of the rule, not of the code).

## In plain terms

On the Mac, open a website or blank browser pane, click into a different
window, then split a terminal off that browser pane: it opens in the other
window's folder instead of the one you were working in beside it.
