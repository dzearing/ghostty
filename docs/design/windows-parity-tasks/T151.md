# T151 — Agent-backed panes may not get shell integration injected

## Summary

**Agent-backed panes may not get shell integration injected.** `173320776` (inject shell integration for local-agent panes, Mac, ZERO references) — without it an agent-backed pane never emits OSC 7, which silently breaks cwd inheritance (T144), `+list` cwd reporting, and the shell-integration prompt features. T27 shipped PowerShell shell integration for the DIRECT spawn path only; verify whether the T89d agent OPEN path injects it at all, on every supported shell flavor

## In plain terms

With session persistence on (the default), every normal terminal pane runs its
shell under the background agent — and on Windows those panes silently lose the
shell integration a direct pane gets: a PowerShell pane opened with
`--shell=pwsh` starts bare, so the terminal never learns your current directory
as you `cd` around, prompt jump/navigation marks are missing, and new splits
can't inherit where you are from the shell itself. The fix makes the agent
honor the integration startup arguments the app already sends, so an
agent-backed PowerShell pane behaves exactly like a direct one.

## Goals

- [x] Verify whether agent-backed panes get shell integration today (they get the env half only; the shell-specific half is dropped)
- [x] Windows agent honors the integration argv the app forwards (`OPEN.argv`)
- [x] Shell detection mirrors what the agent will actually spawn (no more `/bin/zsh` fallback on Windows, no `$SHELL` mismatch)
- [x] Validated on the box: an agent-backed `--shell=powershell` pane starts with ghostty.ps1 dot-sourced; a default pane stays clean cmd.exe
