# T1177 - Ghoztty never silently fails to start: a startup failure raises an error dialog immediately, not a timeout message minutes later

## Summary

Launching Ghoztty with a missing or unstartable agent produced NO window, NO dialog and no feedback at all - eventually surfacing some agent error long after the user gave up. That is the unacceptable case. Every startup precondition (agent binary present, agent spawnable, named pipe reachable, config loadable) must fail LOUD and FAST: a dark ConfirmDialog/MessageBox naming what failed and what to do, raised on the spot rather than after a probe timeout. Shorten the first-run agent probe so the feedback arrives in seconds, and make silent-exit-on-startup-error impossible by construction (no bare log.warn path that returns without a window).
