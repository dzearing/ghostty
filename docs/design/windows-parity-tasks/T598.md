# T598 - Windows never sets up agent-runtime integrations: main installs Claude Code and Copilot CLI skills plus hooks, win32 installs nothing

## In plain terms

On the Mac, Ghoztty now sets up your coding agent for you: it installs the
Ghoztty skill and the hooks that let Claude Code (and GitHub Copilot CLI) drive
panes, set banners and report activity state. On Windows none of that happens —
you wire it up by hand, or you do not get it at all. When this lands, a Windows
user gets the same working-out-of-the-box agent setup a Mac user does.

## Summary

Upstream arc on `origin/main`, filed as ONE task because from the Windows seat
it is one feature; expect to split it when claimed. The macOS decomposition is
the map, not the requirement:

- `c199cf8c4`, `61d9572f1`, `c6af67cf7` - design + implementation plan for
  multi-runtime agent integration.
- `f935538a7` bundled assets (skills + banner script); `9bc808d5e` de-Claude-ified
  the banner script and moved it to a stable install path; `cff76588c`,
  `b56615ed8`, `a69be71d6` refcount and make it runtime-aware.
- `335d4d1b7` RuntimeAgent registry + install-state enums; `7e06e5496` collapsed
  the duplicate enum and centralized the marker.
- `2090445ea`, `06a851b99` ManagedFile: a marker-guarded atomic writer;
  `8c7559291` made it refuse symlinks; `81c4ce87f` stopped it wiping an
  unparseable `settings.json`.
- `dcda38102`, `5a02af531`, `261de0390`, `dfa54ff3c` SkillComponent: per-runtime
  skill install, rollback on partial install, plugin-manifest gating.
- `61b2a2af0`, `0a36a5e0b`, `ac420a7aa`, `e5fa14e2b` HookSpec: dedicated-file
  hooks (Copilot) and merged-fragment hooks (Claude `settings.json`), plus
  external-plugin detection; `222f5165c` builds the Copilot hooks file with
  JSONSerialization; `05f9bf652` parses hook payloads with `jq`.
- `364130630`, `aae212bce`, `3264e54fe`, `0188f14b5`, `814ff1352`, `3c1f02d85`
  RuntimeIntegration + factory: aggregate state, gated install, rollback,
  Claude/Copilot coexistence.
- `823becf39`, `824d21630`, `5bd426ba2`, `271676604`, `95235da9b` scoping fixes,
  the handover from the standalone Claude plugin, and re-enabling Copilot.

**Windows-native translations required** (do not port the Mac mechanism):

- `jq` is not on a Windows box. Hook payload parsing must be native (the app's
  own JSON, or PowerShell), not a shelled-out unix tool.
- The bundled hook scripts are `.sh`. Windows needs a PowerShell/`.cmd` flavor,
  or the hooks must invoke `ghoztty` directly.
- Config locations: `%USERPROFILE%\.claude\settings.json` and the Copilot CLI's
  Windows config path, not `~/.config`.
- The marker-guarded atomic write must survive Windows file locking and must
  refuse a reparse point the way the Mac writer refuses a symlink.

## Validation criteria

- [ ] A clean Windows box with Claude Code installed gets the Ghoztty skill and
      hooks written by the app, and `ghoztty +set-banner`/`+set-state` driven by
      an agent works with no manual wiring.
- [ ] Install is atomic and marker-guarded: a partial failure rolls back and
      leaves no half-written agent config.
- [ ] An unparseable or symlinked/reparse-pointed `settings.json` is refused,
      never overwritten.
- [ ] Uninstall removes exactly what was installed, and nothing a user hand-added.
- [ ] Unit tests in the `none`/`win32` lanes for the writer, the specs and the
      aggregate state; an acceptance script for the end-to-end install/uninstall.
