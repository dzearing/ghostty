# T839 - The T443 page watch covers four addresses out of thousands - aim it at the pages the known victim tests use

## Summary

`crash-databreak.ps1 -WatchPages` (T474) arms four hardware data breakpoints on
`&page.memory.ptr` and then gets out of the way, so it finishes a full lane
cheaply. What it cannot do is choose WHICH four: it takes the first four
distinct pages `Page.verifyIntegrity` is called on, which are whatever the lane
happens to start with. A lane touches thousands of pages. A clean run therefore
rules out a corrupting write to those four addresses and nothing else — the
verdict says so out loud, but saying so does not fix it.

## In plain terms

The trap is built and it works, but it is set in four spots of a very large
field, chosen more or less at random. The bug we are hunting turns up somewhere
else almost every time. This is about putting the traps where the animal has
actually been seen.

## Goals

- [ ] The armed run can aim at pages used by a NAMED test rather than the first
      four the lane reaches (T443's recorded victims are the
      `terminal.PageList resize reflow …` and `Page exactRowCapacity …` families)
- [ ] Coverage is reported as a number a reader can act on — how many distinct
      pages the lane created versus how many were watched
- [ ] A run's verdict distinguishes "watched the pages the crash uses" from
      "watched four arbitrary pages", because only the first makes a clean
      result mean anything

## Details

Ideas worth weighing, in the order they look promising:

- **Arm late, not early.** The corruption is detected during page-heavy tests;
  arming on the first four pages of the run watches whatever the earliest tests
  allocated. Skipping N calls before arming, or arming only once a named test is
  running (the test name is already available — `Get-LastProgressLine` reads it
  off the runner's stderr), would put the watch inside the right neighbourhood.
- **Re-arm on a rotation.** Nothing forces the four to be permanent. Re-arming
  every K calls of `verifyIntegrity` samples far more of the population, at a
  cost of K round trips per rotation — with the entry breakpoint re-enabled
  briefly rather than left live, which is what made the old shape unusable.
- **Watch the pool slot, not the page.** Pages are recycled through a small set
  of pool addresses, so the four addresses already cover many page generations.
  Measuring how many is the cheap first experiment, and it may show coverage is
  already much better than four-of-thousands.
- **Recycling already costs coverage, measured.** A watched address whose page
  dies can be recycled into memory something writes constantly; T474 bounds that
  with `-HotLimit`, which DROPS the breakpoint after N ordinary writes. So the
  four can quietly become three partway through a lane. Re-arming would recover
  the slot as well as widen the sample, which is a second reason to prefer the
  rotation over the late arm.

Note the interaction with the shape guard (T474): a rotation or a late arm must
re-capture `memory.len` at each arm, and a page that dies while watched is
exactly the recycling case the guard exists to reject.

## Validation criteria

- [ ] An armed run reports the distinct-page count it saw and the fraction it
      watched, measured rather than asserted
- [ ] A run can be aimed at a named test and demonstrably arms on a page that
      test created (the transcript names both)
- [ ] `test\win32\crash-databreak.ps1` stays ALL PASS with the aiming covered
      by a fixture

## Progress log

- 2026-08-14 16:34: 2026-08-14 (T443 turn 5): the premise is refuted by measurement. An armed agent-lane run under the build runner armed 2 addresses, BOTH went hot and were dropped, and 0 were watched to the end of a 183s lane. Pages are MemoryPool slots and most are short-lived, so a watched address is freed and recycled into hot memory within seconds - aiming at the victim tests' pages does not help, because those pages die and recycle too. Four debug registers cannot cover a churning pool. T443 now detects the damage with a software sweep instead (PageList.verifyIntegrity checks every live page's memory.ptr). What this task is still worth: the sweep cannot name the WRITING INSTRUCTION. Re-scope it to arming the watch at a code path once the sweep names one, rather than at four arbitrary pages.
