# T1026 - The merge stages have no pre-flight gate: upstream-remote.ps1 check is never run by anything

## Summary

T957's 'check' verb is the assertion that every sha docs/design/windows-parity-merge-back-plan.md pins still resolves and is reachable from upstream/main, and today nothing calls it except its own acceptance script. The claim runs 'ensure' (which repairs and fetches, and is deliberately never fatal so an offline box cannot wedge the loop), and parity-tasks.ps1 validate does not know about it at all - correctly, since a turn that touches no merge machinery should not fail because GitHub is unreachable. The gap is the moment it DOES matter: the start of S1..S6. Give the stages a pre-flight - a script or a documented step that runs upstream-remote.ps1 check, floor-lane -Lane all and guard-due check before a stage branch is cut - so a stage cannot begin against a plan whose shas have gone missing. Depends on T957; wanted before S1 is attempted.
