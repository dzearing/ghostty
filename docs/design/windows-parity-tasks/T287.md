# T287 - T226d: Activity Monitor remote sources - card carousel switcher, dial/reuse, chooser Activity button

## Summary

Last of the four-way split of **T226**, and the task that closes **T177**
(the chooser detail row's missing Activity button - it is this panel's entry
point, and a button that opens nothing was never worth landing alone).

Mac's three entry styles
(`macos/Sources/Features/Remote/RemoteActivityMonitor.swift`) all have to
exist, because they differ in who OWNS the connection:

- `presentLocal` - in-process, no connection (landed in T285).
- `presentReusing` - rides a remote window's existing `RemoteConnection` and
  does **not** own it, so closing the panel must not tear that window's
  session down.
- `presentDialing` - dials a fresh connection off the UI thread and owns it.
  This is what the chooser's Activity button calls
  (`MachineChooserView.swift:1488`).

Plus the **in-panel machine switcher** (the card carousel, 160x56 cards,
Local first then every registered machine): once open, the panel moves to any
other source in one click, dialing and freeing owned connections, WITHOUT
opening a second window. The registry governs only the initial open. Keyboard:
left/right move a focus ring, Return/Space commits - so arrowing never dials.

The wire already carries it: `src/remote/protocol.zig` has `HostMetrics` and
the proc list, so a remote source works the moment the UI asks.

## Update 2026-08-01: T177 landed the entry point, so what is left here is the DIAL

T177 is done, and it built everything on this task's path except the
connection:

- The chooser's **Activity button exists and works** - it dismisses the chooser
  and calls `ActivityMonitor.open(window, .{ .remote = .{ .id, .name } })`.
  That entry point does not need revisiting.
- `Source.remote` is now `Remote{id, name}` (registry identity vs display
  label, Mac's split), and the panel instance OWNS both strings in `id_buf`/
  `name_buf` - the chooser's arena is gone by the time the panel opens.
- **The one line to replace is `buildSnapshot`'s first statement**:
  `if (self.source == .remote) return error.RemoteSourceNotConnected;`. Until
  the dial exists the panel refuses to sample and paints "Couldn't connect" -
  deliberately, because sampling THIS machine under another machine's name is a
  lie the user cannot catch. Swap that branch for the real remote provider.
  `sampleWorker` also silences the repeat of that one error
  (`logged_sample_error`); the flag can go with the branch.
- `test/win32/chooser-menu.ps1` already asserts the button, the panel's title,
  the chooser dismissing first, the one-panel-per-machine registry rule, and
  the refusal-to-sample. When the dial lands, the refusal assertion is the one
  that must be replaced (it is a claim about the gap, not about the feature).

## Update 2026-08-01: SPLIT into T295 (data plane) + T296 (carousel)

Too big for one context, and the seam is clean because the two halves answer
different questions. **T295** makes a remote panel show real data (dial owned /
reuse borrowed, remote proc snapshot + metrics subscription + kill/spawn) - that
alone closes the gap the note above describes and is independently shippable.
**T296** is the in-panel switcher, and its bulk is not the cards: the panel has
no machine list (the chooser's is a synchronous HTTPS GET a non-modal window
cannot make) and win32 has **no `MachineMetricsProbe` equivalent at all**, so
the per-card summaries are a subsystem, not a paint pass.
