# T730 - Sweep guard: fail the suite when product code compares GetForegroundWindow directly instead of using window_active

## In plain terms

The app now has one correct way to ask "is this window the one in front", and
the old, subtly-broken way still compiles fine. Nothing stops the next feature
from reaching for it again, and the breakage it causes is invisible — no
error, no log line, just a feature that quietly never happens on the test
desktop. A sweep that fails the suite when the old spelling reappears is what
makes T215's fix hold.

## Summary

T215 replaced every product read of `GetForegroundWindow` with
`window_active.isActive` / `shouldForwardFocus` via `w32.activation()`. The
rule is documented in `src/apprt/win32/window_active.zig`, but a rule that
lives only in a doc comment is one a new site can miss — and this particular
mistake is undetectable at runtime, which is what made the original four sites
survive so long.

Add a sweep in the shape of `test\win32\harness-exitcode-audit.ps1` /
`lib\PersistenceSweep.ps1`: enumerate `src/apprt/win32/*.zig`, flag any
`GetForegroundWindow` or `GetActiveWindow` reference outside the two files
allowed to have one (`win32.zig`, which declares and calls them, and
`window_active.zig`, which documents them), and require a
`// foreground-audit: <reason>` marker to exempt a site — the same
state-your-intent convention the `# persistence:` markers use. The sweep must
be at zero when it ships, and its own acceptance script must prove it goes red
on a planted violation.

Note the exemptions that exist today and are legitimate: `QuickTerminal`'s
`forceForeground` genuinely needs the raw foreground window (it is doing the
`AttachThreadInput` dance to BECOME foreground), and every
`SetForegroundWindow` call is an action rather than a guard.

## Validation criteria

- [ ] The sweep reports zero violations across `src/apprt/win32/` at HEAD
- [ ] Its acceptance script proves it goes red on a planted bare
      `GetForegroundWindow` comparison, and green again with the marker
- [ ] Every existing legitimate site carries a `// foreground-audit:` reason
- [ ] Both zig lanes still green; ALL PASS x3
