# T917 - mac: confirm double-click still selects the whole link after the T802 same-pin drag guard

## In plain terms

Windows fixed a bug where double-clicking a link handed back only a fragment.
Part of that fix lives in code the Mac app shares, so someone with a Mac
should double-click a few links and confirm nothing about selecting text got
worse there.

## Summary

T802 added `samePin` to `src/Surface.zig`: `dragLeftClickDouble` and
`dragLeftClickTriple` now return early when the drag event resolves to the
very cell the click landed on, instead of recomputing the word/line selection
from that cell.

On Windows that was load-bearing — every mouse message carries a point, so a
double-click's button-up arrived as a zero-distance drag and collapsed the
link selection to the bare word. macOS never had the deterministic form
(`mouseUp` sends no position), but it shares the guard, and it has the same
latent case: a trackpad double-tap that wobbles a pixel inside the clicked
cell used to collapse the selection there too.

The change can only preserve a richer selection — it removes work rather than
adding behavior — but it is untested on a Mac build.

## Validation criteria

- [ ] Double-clicking a URL in a Mac pane still selects the whole URL and
      ⌘C copies it
- [ ] Dragging OUT of a double-clicked word still extends the selection one
      word at a time, in both directions
- [ ] Triple-click still selects the line, and ctrl+triple-click still selects
      the whole command output — including when the pointer does not move
- [ ] A trackpad double-tap that wobbles inside the clicked cell keeps the
      whole link selected (the improvement the guard brings to this seat)
- [ ] `zig build test` green on macOS, including
      `Surface: samePin only matches the identical cell`
