# T1073 - Close the behind gap: merge main's 93 commits into the windows branch

## Summary

`scripts\ship-readiness.ps1` reports `behind` as the first hard blocker on the
cutover: as of 2026-08-21 `origin/main` carries 93 commits this branch does not
have, while this branch carries 1397 main does not. Those 93 are the Mac seat's
merged feature branches (`users/dzearing/pane-resize-fixed-edges`,
`users/dzearing/session-restore`, `users/dzearing/url-protocol`, ...) plus the
v1.31-v1.34 release notes.

The merge must run in THIS direction first - main into the branch, on the branch
- because that is where the floor lanes and P1-P3 can judge the resolution. A
three-way resolution performed inside the merge *to* main lands straight on the
trunk with nothing to test it against.

## In plain terms

The Mac side has kept shipping while the Windows side worked on its own copy.
Before the Windows work can be merged in, the Mac work has to be pulled across
and everything still has to run. This is that step, done where it can be tested
safely.

## Breakages the merge itself produced (all caught by the floor, all fixed here)

- **`src/cli/rearrange.zig` had no `apprt/ipc.zig` import.** Main's commit added
  the `ipc.seedCallerPane` call; ours owned the import block. Auto-merge took
  each half from the side that lacked the other.
- **`src/cli/send_keys.zig` had two `const Split` definitions** - a conflict
  boundary left main's copy standing as context beside ours.
- **`seedCallerPane` called `std.posix.getenv`, a hard compile error on
  Windows.** POSIX-only code arriving through shared `src/` is exactly what the
  `lib` lane exists to catch, and it did. Now guarded with the same
  `comptime builtin.os.tag == .windows` branch `socketPath` uses ten lines above
  it, reading the variable with `std.process.getEnvVarOwned` instead.
- **A dangling doc citation** in main's new `LocalAgentManagerTests.swift` (and
  in `scripts/e2e/session-persistence.py`) naming a `CLAUDE.md` section that
  lives under `docs/claude/` on this branch - caught by
  `test\win32\docs-routing.ps1`, which is why that harness exists.
