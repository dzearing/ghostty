# T1073 - Close the behind gap: merge main's 93 commits into the windows branch

## Summary

`scripts\ship-readiness.ps1` reports `behind` as the first hard blocker on the
cutover: as of 2026-08-21 `origin/main` carries 93 commits this branch does not
have, while this branch carries 1397 main does not. Those 93 are the Mac seat's
merged feature branches (`users/dzearing/pane-resize-fixed-edges`,
`users/dzearing/session-restore`, `users/dzearing/url-protocol`, ...) plus the
v1.31-v1.34 release notes.

The merge must run in THIS direction first - main into the branch, on the branch
- because that is where the floor lanes and P1-P3 can judge the resolution. A
three-way resolution performed inside the merge *to* main lands straight on the
trunk with nothing to test it against.

## In plain terms

The Mac side has kept shipping while the Windows side worked on its own copy.
Before the Windows work can be merged in, the Mac work has to be pulled across
and everything still has to run. This is that step, done where it can be tested
safely.

## Goals

- [ ] `origin/main` fully merged into `users/dzearing/windows-amd64`
- [ ] Every conflict resolved with a recorded reason, not a default
- [ ] The four floor lanes and P1-P3 green AFTER the merge (green before it says
      nothing about after it)
- [ ] `ship-readiness.ps1` reports `behind` as PASS

## Validation criteria

- [ ] `git rev-list --count HEAD..origin/main` is 0
- [ ] `scriptsloor-lane.ps1 -Lane all` green post-merge
- [ ] `test\win32\ipc-p1.ps1`, `ipc-p2.ps1`, `ipc-p3.ps1` ALL PASS post-merge
- [ ] `scripts\ship-readiness.ps1` no longer lists `behind` in its unmet set
