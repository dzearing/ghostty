# T145 — Agent-crash recovery has no Windows equivalent

## Summary

**Agent-crash recovery has no Windows equivalent — 2 Mac commits, ZERO references in any Windows doc.** `03f0f1f30` (in-place agent-crash recovery: rebuild local windows from the agent WITHOUT an app relaunch) and `20e505aaf` (recover crash-orphaned windows from the agent's authoritative layout). Windows has only T89f2 launch-time restore, so if the agent dies while the app is running the panes are simply dead until the user quits and relaunches — the failure mode session persistence exists to prevent. Port both: treat the agent's layout blob as authoritative, rebuild in place on reconnect, and reconcile against the local session-layout manifest. Note `e65cfa4d5`'s lesson (recovery must not kill the sessions it recovers) — that is T128's mirror-image bug and the two should be validated together

## Scope (narrowed 2026-07-30)

**Split.** The row named two Mac commits that are two independent mechanisms,
and the second needs machinery win32 does not have at all (win32 never calls
`SET_LAYOUT`, so there is no agent-side layout roster to reconcile against).
`20e505aaf` — crash-orphaned windows from the agent's authoritative layout — is
now **T194**. This row keeps the in-place half: `03f0f1f30` plus the app-side of
`e65cfa4d5`.

## Findings

- The agent-side half of `e65cfa4d5` is ALREADY on Windows: it landed in shared
  core (`src/remote/agent/server.zig:1059` refuses a CLOSE for a session bridged
  to a different connection, with tests at `:3854` / `:3920`). Only the app side
  is missing.
- **A live use-after-free gates this work.** `LocalAgent.sharedConnection`
  (`src/apprt/win32/LocalAgent.zig:108-115`) drops a dead cached connection with
  `d.deinit()`, and `tcp_dial.Dialed.deinit` calls `conn.destroy(alloc)` — it
  FREES the `Connection`. But that pointer is borrowed by every persistent
  surface (`Surface.remote_conn`, `Surface.zig:245`, explicitly documented at
  `:620` as "owned by the parent Window and outlives this surface") and by
  `Window.local_agent_conn` (`Window.zig:320`). So today, agent dies + user
  opens any new window/split ⇒ the old surfaces' connection is freed underneath
  them. The comment there ("surfaces still riding it keep their own reference
  alive via the core") is not true — nothing is refcounted. Recovery must
  retire the old connection only once no surface still points at it.

## Outcome (2026-07-30) — DONE

In-place recovery works: kill the agent out from under a running app and the
panes come back on the SAME app process, in the same window, at the same
topology, responsive again.

What landed:

- **`agent_recovery.zig`** — the two decisions, pure and unit-tested in both
  lanes: `isDown` + `evaluate` (the settle-window verdict) and `sessionSpared`
  (the invariant a tree swap may not violate). Ported from Mac's
  `SharedLinkDropVerdict` / `SessionCloseIntentPolicy` including its 5s settle
  window and its four verdicts, so `transport_down` (same agent, broken pipe)
  reads differently in the log from `agent_restarted`.
- **Detection is event-driven, not polled.** The connection FSM already has a
  state handler; it fires on the reader thread under `state_mutex`, so it posts
  `WM_APP_AGENT_LINK_DOWN` and returns — the T190 "post, don't track inline"
  pattern. The settle timer is armed only while a down link is being judged, so
  an idle app does no work at all.
- **`LocalAgent`** gained the pieces the policy needs (`linkState`,
  `sharedPid`, `liveAgentPid`, `reconnectForRecovery`) and a re-appliable state
  observer, so the connection recovery dials is watched exactly like the first.
- **`App.recoverLocalAgentInPlace`** captures the live topology into the same
  `session_layout` structs the manifest uses, re-dials, and replays each tab
  through the EXISTING restore walker (`restoreFirstLeaf` /
  `restoreAttachOverride` / `restoreBuildSubtree`). Ratios, tab colors, hero
  ratios, pinned titles, IPC pane names and pane ids therefore come back
  through code every restore test already covers.
- **`Window.replaceTabRootSurface`** is the one new primitive: swap a tab's
  whole tree for a fresh root, and never mark close intent.

Three things this had to get right beyond the port:

- **A live use-after-free was fixed on the way in, not worked around.**
  `sharedConnection` freed a dead cached connection (`Dialed.deinit` →
  `conn.destroy`) while `Surface.remote_conn` / `Window.local_agent_conn` still
  held that raw pointer, with a comment claiming the core kept it alive.
  Nothing refcounts it. Replaced connections are now RETIRED (shut down, kept
  allocated) and freed only in `LocalAgent.deinit`, which `App.terminate`
  already runs after every window is gone.
- **A file-only pid read would have misdiagnosed every crash.** A dead agent
  leaves its `port.json` behind, so comparing the recorded pid against the file
  would have matched and reported `transport_down` — "same agent, transport
  failed" — about a process that no longer exists. `liveAgentPid` gates on the
  pid being a RUNNING process (Mac gates the same read on `kill(pid, 0)`);
  access-denied counts as alive, because a process we cannot open is still a
  process.
- **Background tabs had to be re-hidden.** Fresh surfaces start visible, so
  rebuilding a window's non-active tabs painted them over the active one until
  `setTabSurfacesVisible` was added to the swap.

**Validation.** New `test/win32/agent-recovery.ps1` **ALL PASS (25) ×3**:
baseline 2-pane window with both panes proven responsive, agent-only kill with
the app pid asserted UNCHANGED (what makes it in-place), the trap proven ARMED
(panes are genuinely broken before recovery is asserted), recovery asserted by
a marker round-tripping through the rebuilt pane on NEW child pids, the
e65cfa4d5 check that the recovered sessions are still alive after the departing
surfaces finish tearing down, and topology/IPC-name/pane-id preservation.

**Negative control, run for real:** with `installLocalAgentWatch` disabled, the
script failed **exactly** the six recovery assertions (C1, C2, C5, C6, D1, D2)
and nothing else — no agent respawned, no sessions back, panes dead — while A,
B and E still passed. That E still passes in the broken build is the point:
the topology survives a dead agent, so only the RESPONSIVENESS assertion
separates recovered from frozen.

**Harness lessons worth carrying** (three separate ways it scored a working
pane as broken before it scored the product):

- `Start-Process -PassThru` + timed `WaitForExit(ms)` leaves `ExitCode`
  unreadable — you must touch `$p.Handle` first AND call the argument-less
  `WaitForExit()`. Gating on that empty value failed every send.
- A quoted argument routed through `cmd /c` arrives WITH its quotes, so
  `+send-keys ... "echo MARK"` made cmd answer *"not recognized as an internal
  or external command"*. Space-free positionals plus the `Space` key name
  remove the quoting problem entirely.
- The test window is minimized, so a split pane is a couple of columns wide and
  the terminal WRAPS the marker one character per row. At `--lines=25` the
  marker fell off the top of the read window. The oracle now collapses
  whitespace and reads 300 lines, measuring "did the shell run it?" instead of
  "how wide is the pane?".

**Floor:** both test lanes + `zig build test-agent` green; P1–P3 ALL PASS;
regressions `session-reattach`, `session-open`, `session-close`,
`session-relaunch` ALL PASS, plus `split-divider` (25) and `pane-banner` (54)
because the swap touches tab visibility and surface lifetime.

Filed **T194** (the split-out `20e505aaf` half) and **T195** (the settle-window
policy has no on-box test — the pure verdict is unit-tested, but nothing on the
box proves a link BLIP is survived without a rebuild).
