# T457 - Rebase onto origin/main and fold in the Mac new-window dialog work as Windows tasks

## In plain terms

A lot of Mac work merged over the last day - the machine chooser now measures
what each remote session is doing, and it stops listing sessions that could
never be restored. None of it is on this branch yet, so the Windows side is
being judged against a Mac that no longer exists. Pull it in, look at what
landed, and turn each piece into its own Windows task.

## Goals

- [ ] `users/dzearing/windows-amd64` is rebased onto `origin/main`
- [ ] The floor lanes are green after the rebase (`scripts\floor-lane.ps1
      -Lane all`)
- [ ] Every Mac feature in the inventory below has either a Windows task filed
      against it or a written reason it needs none
- [ ] `docs/design/windows-parity-tasks.md` and CLAUDE.md reflect anything the
      rebase changed about the shared contract

## Do the rebase at a turn boundary

**The working tree is shared with a live loop.** Rebasing rewrites every local
sha, so it must happen while nothing else holds the tree - at the start of a
turn, before any other work, with `git status` clean. Confirm the loop lock is
yours (`scripts\go-loop-exec.ps1 claim`) first.

As of filing (2026-08-04), `HEAD..origin/main` is **20 commits**.

## Inventory to explore (from `git log HEAD..origin/main`)

### 1. One warm connection per machine + per-session CPU (60ccd4f45)

The one the user named. Touches both halves:

- Mac: `MachineConnectionPool.swift` (**new, 534 lines**),
  `SessionCPUProbe.swift`, `SessionBrowserProbe.swift` (+200),
  `RemoteActivityMonitorView.swift`, `MachineChooserView.swift`.
- **Shared:** `src/remote/agent/server.zig` (+235) and
  `src/remote/protocol.zig` (+133) - new messages and a **`cpu_pct`
  capability gate**.

The shared zig arrives with the rebase; the win32 chooser UI does not. Expect
at least: a connection pool behind `MachineChooser.zig`/`SessionRoster.zig`, a
CPU column in the roster, and the probe that feeds it.

**This is also an agent-protocol change**, so it lands on the compatibility
boundary CLAUDE.md describes: a running agent is routinely a different build
from the app. Check that the new messages are gated on the negotiated HELLO
capability and that an old agent degrades rather than breaks.

### 2. Sessions that cannot be restored are no longer listed

The user's second half: "process cleanup so that we don't show you a bunch of
sessions in the dialog that can't be restored." Look in
`SessionBrowserProbe.swift` and `src/remote/agent/server.zig` from the same
merge for how a dead or unrestorable session is now filtered or reaped, and
mirror it in the win32 roster (`chooser_sessions.zig`, `SessionRoster.zig`).

### 3. Git diff viewer panes with a native file tree (69eb4aeb0)

A whole new viewer mode: `ViewerDiffPanel`, `ViewerDiffSpec`, `ViewerDiffTree`,
`ViewerGit`, `ViewerSidePanel` (all new), plus a large `ViewerView` rework and a
`ViewerTOC` refactor. Windows has none of it. Almost certainly its own task, or
several.

### 4. `needs_input` renders as "(question)" (d0c056ee5)

Small and self-contained: `BaseTerminalController`, `TerminalWindow`,
`Ghostty.Action`. The win32 title/activity-state path needs the same label.

### 5. Auto-named windows resolve without a prior `+list` (de932e4d7)

`IPCServer.swift`. This is CLI surface, which CLAUDE.md says must be identical
on both platforms - so win32's `IpcRegistry` needs the matching resolution.

### 6. Already shared, arrives with the rebase

`fix(remote): elide null optionals from the HELLO encoding` (04c854450,
`src/remote/protocol.zig`) and the v1.29.0 release notes. Verify rather than
re-implement.
