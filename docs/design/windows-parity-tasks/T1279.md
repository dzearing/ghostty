# T1279 - The digest health check counts a one-section digest as present, so steps 0.6 and 0.7 can be skipped in silence

## In plain terms

Every morning the project writes a short briefing with three tabs: what
happened, what the backlog looks like, and new product ideas. A check exists to
notice when that briefing is missing entirely. It does not notice when only one
of the three tabs got written — so two thirds of the briefing can quietly stop
happening and everything still reads green. That is what happened on
2026-09-01: the Commentary tab was written and the other two were not, and
nothing said so.

## Summary

`scripts\go-loop-health.ps1` reports `digest=present` on the mere existence of
`docs/design/windows-parity-digests/<today>.md`. go.md steps 0.6 (Task triage)
and 0.7 (Feature ideas) each write their own H2 category into that same file,
and neither is checked. The 2026-09-01 digest contains only `## Commentary`;
the run read healthy.

This is the identical shape T1223 closed one level up — a step with no
enforcement is a step that gets skipped the first busy day — and the remedy is
the same: report it, never write it. A generated triage section would destroy
the only thing the signal measures.

**Fix:** `digest=` grows a third value between `present` and `missing` —
`partial:<missing categories>` — computed by scanning today's file for the three
required H2 headings (`## Commentary`, `## Task triage`, `## Feature ideas`).
Partial reads DEGRADED with a line naming which categories are absent, exactly
as `missing` does today. The `not-due` path is unchanged.

**Gate:** per the "a new gate ships with the demonstration that it can fail"
rule, register the condition in `test\win32\gate-negatives.ps1` and construct a
one-category digest to prove it goes red.

## Validation criteria

- [ ] `go-loop-health.ps1` reports `digest=partial:...` naming the missing
      categories for a digest that has `## Commentary` only, and DEGRADED with
      it.
- [ ] It still reports `present` for a digest carrying all three categories, and
      `missing` / `not-due` unchanged on their existing paths.
- [ ] `test\win32\gate-negatives.ps1` carries the new condition with a negative
      control that constructs a one-category digest and observes it go red.
- [ ] `gate-negatives.ps1` is ALL PASS with the new section in place.
