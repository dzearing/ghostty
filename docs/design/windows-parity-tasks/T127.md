## Outcome (2026-07-29)

Re-scope DONE. The refreshed design is
`docs/design/viewer-panes-windows.md`; it supersedes `T90a.md`'s pins where the
two disagree and leaves everything it does not contradict alone.

What it decided, and why the ship/defer line falls where it does:

- **v1 ships "a viewer pane you can live in"**: every mode, the navigation
  chrome + address bar the user named, the markdown TOC the user named, zoom,
  pane-scoped chords, `+reload`, the blank browser pane, live reload, link
  routing, dark mode, titles, and session restore.
- **Three cuts, each a row**: popups-as-ghoztty-windows (T163), worktree
  feedback capture (T164, design-first), and `.md` file association (already out
  of scope in T90a).
- **T90b-T90h were NOT silently widened.** Each got an explicit
  "Re-scoped 2026-07-29" note; the new v1 surface became its own tasks
  (T159 nav chrome/address bar, T160 TOC, T161 zoom + chords, T162 selection
  toolbar Copy), and T90g was NARROWED to say so.

Five findings that changed the plan, none of which the commit-subject inventory
would have surfaced -- they came from reading the code:

1. **The shared viewer JS is WebKit-shaped, not portable.** `viewer.js:115-127`
   and `selection.js:132-146` post through
   `window.webkit.messageHandlers.viewerTOC`. The "it came free with T117"
   assumption in this task's own Summary was half true: the RENDERING is free,
   the BRIDGE is not. Pinned fix is a ~6-line shim over
   `chrome.webview.postMessage` with zero edits to the shared JS (design P1/P2).
2. **The TOC's expensive half is already built.** Mac's TOC card and pane banner
   share one `GlassCardBackground`, and T131 already ported that to
   `src/apprt/win32/banner_card.zig`. T160 reuses it instead of growing a second
   card renderer -- which is what moved the TOC from "big" to "v1".
3. **Feedback capture is not a port, it is a design problem.** Its three hard
   parts are all platform-specific: `lsof` port->cwd has no Windows analog
   (`GetExtendedTcpTable` gives the pid, not the cwd), the `[Image #N]` chip is
   `NSTextAttachment`-shaped, and the obvious Windows snip tools clobber the
   clipboard that Mac's `screencapture -i -o` deliberately protects. Hence T164
   is design-first, and T162 hides Quote rather than shipping a dead button.
4. **The pane-scoped chords cannot be copied, only their structure can.**
   Windows defaults differ (ctrl+d = split right, ctrl+shift+b = banner), so
   the mapping is ctrl+r = reload (free: a viewer pane has no shell) and
   ctrl+d/ctrl+l/alt+d = address bar, with terminal panes unchanged (design P7).
5. **`isFilePath` is the same bug as `resolveViewArgument`.** Mac tests `/` and
   `~/`; the CLI tests `rest[0] == '/'` (`src/cli/split.zig:212`,
   `src/cli/new_window.zig:319`, both still live). Windows needs `C:\`, `C:/`,
   `\server\share`, `~\` in both places -- one is T90b's, one is T159's.

Also corrected: this task's Summary claimed `--view` on Windows returns T90b's
"viewers are not yet supported on Windows" error. It does not -- `VerbArgs`
(`src/apprt/ipc/args.zig`) has no `view` field at all, so the flag is silently
dropped as unknown. T90b is still the fix; the interim error was never built.

Confirmed the inventory is current: `origin/main` has no viewer commits missing
from this branch (`git log HEAD..origin/main -- macos/Sources/Features/Viewer
src/viewer` is empty), so the 27-commit inventory is the whole delta. The 12
unmerged non-viewer commits produced T165 and a scope note on T125.
