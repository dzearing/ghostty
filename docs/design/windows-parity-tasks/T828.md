# T828 - Machine chooser selected row is a loud purple pill instead of the quiet WinUI selection treatment

## Summary

User report (2026-08-14, with screenshot): the selected "Local" row in the
machine chooser draws as a bright purple pill with a thick purple outline. A
native Windows 11 dialog (Settings was the comparison screenshot) marks the
selected list item with a QUIET treatment: a subtle neutral fill and a thin
accent bar on the left edge — the accent is a small mark, not the whole row's
border.

Why it looks the way it does (traced, not guessed):

1. The accent is the user's system accent, `#680081` on this box
   (`system_colors.accent()` reads `HKCU\...\DWM\AccentColor`). That dark
   purple fails the 3:1 chrome floor against the dark chooser surface, so
   `chrome_theme.accentOn`'s contrast search brightens it into the vivid
   violet in the screenshot. Working as designed, but it means dark accents
   always paint LOUDER than the color the user picked.
2. `chooser_rows.rowPaint` gives a selected+focused row the maximum-weight
   treatment: accent fill at 0.25 (`selectionFill`), accent border at 0.7
   (`selectionBorder`), PLUS the §2.2 focus ring — a 2 DIP accent ring inset
   1 DIP inside the pill (T312). Border + ring in the same accent reads as
   one very thick outline.
3. The pill shape itself follows the Mac chooser's rounded accent selection
   (`MachineChooserView.row(for:)`), per the file header of
   `chooser_rows.zig`. Parity of INTENT is right, but the Mac original is an
   accent-tinted fill with no heavy border — the win32 rendering is louder
   than both the Mac source and the WinUI convention.

The fix direction (to be designed against `docs/design/win32-design-system.md`
§2.2/§3.2, decision doc if the focus-ring rule needs amending): keep the
selected-vs-unfocused-vs-hover ordering and the 3:1 floors, but drop the
selected row's weight to the platform's quiet convention — neutral/low-alpha
fill with a restrained accent mark (left edge bar, or a hairline border), and
don't stack the focus ring on top of an accent border in the same hue. The
focused-caret ring must stay distinguishable per T312; the defect is the
doubled full-perimeter accent, not the existence of focus indication.

Files: `src/apprt/win32/chooser_rows.zig` (`selectionFill`, `selectionBorder`,
`rowPaint`), consumed by `MachineChooser.zig`; same treatment is shared by
`chooser_sessions.zig` rows and `ViewerTOCPanel.zig` — audit all consumers so
the chooser doesn't diverge from the other selection surfaces.

## Validation criteria

- [ ] Selected+focused row in the machine chooser no longer draws a
      full-perimeter high-alpha accent border stacked with the inner accent
      focus ring; side-by-side screenshot against Windows 11 Settings reads as
      the same family of treatment.
- [ ] The three list states stay ordered by weight (hover < unfocused
      selection < focused selection) — existing `chooser_rows.zig` unit tests
      still pass, updated to the new weights.
- [ ] All boundary/ink colors still clear the 3:1 floor
      (`chrome_theme.ui_contrast_target`) — asserted in unit tests, not
      eyeballed.
- [ ] Other selection surfaces sharing `rowPaint` (chooser sessions list,
      viewer TOC) audited and updated in the same change, or explicitly
      recorded here as intentionally different.
- [ ] `zig build -Dapp-runtime=win32 -Doptimize=Debug` green and the chooser
      visually verified on-box via screenshot.
