# T1330 - A wixl-dependent packaging script run outside Linux fails somewhere inside wixl instead of saying so up front

## Summary

T419's decision draws the fence around wixl, not around .sh: build-portable-zip.sh and sign-artifacts.sh already run under Git Bash natively on Windows and are expected to, while build-msi.sh and build-release-artifacts.sh cannot compile an MSI anywhere but Linux/macOS. Nothing states that. The 2026-08-03 report that prompted T419 was an .sh being executed on Windows, and the failure it produced said nothing useful. Add an explicit host check to the wixl-dependent scripts that names the supported invocations (CI on ubuntu-latest, or the msitools image) and exits with a usage error, and cover it in release-artifacts.ps1 alongside the existing sign-artifacts usage-error cases (G14-G16).
