# T546 - Agent serves the local transport and the relay uplink from one process over one session store

## In plain terms

Today, the terminals you actually work in can only be reached from this
machine: the background helper that keeps them alive has no connection to your
account's relay, and the separate helper that DOES talk to the relay keeps its
own empty list of sessions that vanishes when it stops. So "install Ghoztty on
two machines and open one machine's terminals from the other" quietly doesn't
work. After this change, one helper does both jobs over one saved list: when
you flip "Share this machine" (the switch itself is the next task), other
devices signed into your account will reach the real terminals on this one -
and anything opened remotely survives reboots just like local sessions do.

## Goals

- [x] The local session helper can raise the relay connection inside the same
      process, serving the same saved session list.
- [x] Whether to serve is a small saved setting next to the session data - no
      new command-line flags, no autostart rewrite - and flipping it takes
      effect within seconds, no restart.
- [x] Sharing off (or the setting absent) means byte-for-byte today's
      behavior: no dialing, no chatter.
- [x] Sharing on without a signed-in credential degrades to local-only with
      one clear explanation, and the local terminals keep working.
- [x] No tray icon, no self-updater in this mode - the app owns both.

## Summary

Core of the T417 one-installer plan: the session-persistence agent grows an optional relay uplink in the SAME process, so the one persisted SessionStore (sessions.json, layouts.json, rings) is reachable over the local pipe/unix socket AND, when sharing is enabled, over the relay. Uplink state comes from persisted sharing config in the agent state dir (hot enable/disable via the existing relay.env watcher pattern); the single-instance guard stays the local one; self-update and the tray stay OUT of this mode (the app owns the binary, the GUI owns the UI). See docs/design/one-installer-agent-consolidation.md.
