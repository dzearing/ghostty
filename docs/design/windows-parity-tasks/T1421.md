# T1421 - Signing out of the relay account does not revoke this Windows machine's enrollment

## In plain terms

When you sign out of your account in Ghoztty on a machine, you expect that
machine to stop being yours - gone from the machine list on your other
computers, no longer reachable, no longer streaming whatever was on screen. On
Mac that is now true. On Windows, signing out very likely only forgets *you*:
the machine itself stays enrolled, stays listed, stays online, and a session
already bridged to another computer keeps sending bytes. Sign-out looks like
"this machine is no longer mine" and isn't.

## Goals

- [ ] Confirm what the Windows client actually does on sign-out today (does it revoke the device enrollment, or only the user session?)
- [ ] Signing out revokes this machine's device enrollment, so it disappears from the machine list on every other client
- [ ] Any session already bridged from this machine stops carrying bytes on sign-out
- [ ] The device credential no longer authenticates against the relay after sign-out
- [ ] The edge cases main's follow-up closed are covered here too (see f3b1e5fb5)

## Summary

Main intake, 2026-09-07. `origin/main` commits `0c3a19764` ("signing out of the
account revokes this machine") and `f3b1e5fb5` ("close the edge cases in
sign-out machine revocation") fixed this on the Mac seat. The relay's semantics
are deliberate - an account may own headless hosts with no app signed in - so
the revocation belongs in the client, and the Windows client is a separate
client.

Mac's fix touched `macos/Sources/Features/Remote/{RelayAccount,MachineEnrollment,RelayDirectoryClient}.swift`
and `MachineChooserView.swift`, with `relay/signout_revoke_test.go` as the
relay-side reproduction. The Windows counterparts live under `src/remote/`
(the relay account / enrollment store) and the win32 machine chooser.

Start by reproducing: enroll this box, bridge a session to a second client,
sign out here, and check whether the machine is still listed and still
streaming. `relay/signout_revoke_test.go` (`TestSignoutAloneLeavesMachineReachable`)
is the shape of the assertion.

## Validation criteria

- [ ] A reproduction that shows the pre-fix behavior (machine still listed / bridge still carrying bytes after sign-out) and goes red on the fix
- [ ] After sign-out, the machine is absent from `+sessions` / the machine chooser on another client on the same account
- [ ] After sign-out, the stored device credential is gone from the DPAPI store and does not authenticate
- [ ] `scripts\floor-lane.ps1 -Lane all` green; the relay-account acceptance harness re-stamped
