# T523 - Mac IPC server: emit outcome/note on +new-window existing-target focus (T135 parity)

## Summary

T135 (win32, done 2026-08-06) fixed the silent flag drop on `+new-window
--target=<existing>`: the win32 server now replies
`{"success":true,"outcome":"focused","note":"target 'x' already exists;
focused it. Ignored: --command, --working-directory. +close it first to
recreate."}` (outcome is `created` on the create paths), and the SHARED CLI
(`src/os/ipc_client.zig` `sendAction`) already prints any `note` field to
stderr while keeping exit 0. The Mac server (`IPCServer.swift`
`handleNewWindow`, the idempotent block at ~line 390) still returns a bare
`.ok`, so on macOS the drop is still silent — the CLI half of the fix is live
there but the server never sends a note.

Bring the Mac server to the same contract:

- The idempotent focus path returns `outcome: "focused"` and, when the caller
  passed create-only flags (`--command`/`-e`, explicit `--working-directory`,
  `--view`, `--title`, `--split`, `--split-command`, `--split-color`,
  `--name`, `--color`, `--shell`, `--env`), a `note` naming them — byte-match
  the win32 wording: `target '<t>' already exists; focused it. Ignored:
  <flags>. +close it first to recreate.`
- The create paths return `outcome: "created"`.
- Honor the `--cwd-implicit` marker flag the CLI now inserts alongside its
  auto-inserted `--working-directory` (see `src/cli/new_window.zig`): an
  implicit cwd never counts as a dropped flag, so a bare
  `+new-window --target=x` re-focus stays silent. Unknown-flag tolerance
  already makes this additive for older CLIs.
- Reference implementation: `droppedOnExistingTarget` in
  `src/apprt/ipc/args.zig` (unit-tested in the none lane) and
  `successResponse` in `src/apprt/win32/IpcHandlers.zig`.

## Validation criteria

- [ ] On macOS: `+new-window --target=x --command=foo` against an existing
      `x` exits 0, focuses the window, and prints the note to stderr
- [ ] Bare `+new-window --target=x` re-focus prints nothing
- [ ] Explicit `--working-directory` alone triggers the note; the CLI's
      auto-inserted cwd does not
- [ ] Note wording byte-matches the win32 server's
- [ ] Win32 acceptance analog for reference: `test/win32/ipc-target-exists-note.ps1`
