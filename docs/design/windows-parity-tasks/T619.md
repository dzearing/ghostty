# T619 - Machine chooser rows carry no live CPU/mem (Mac's MachineChooserView probe)

## Outcome: the parity claim is false, and the idea is refiled (2026-09-07)

**Closed `skipped`, no code.** The premise this card was filed on — "Mac's
chooser rows carry live CPU/mem and Windows' carry none" — does not survive
reading the Mac source, in either direction. See the two evidence notes in the
progress log; the short version:

- Mac paints metrics on **direct-TCP rows only**. `MachineChooserView` starts
  its probe as `probe.start(registry.machines.filter { !$0.isRelay })`
  (MachineChooserView.swift:2014), and `probe.readings` is read only from
  `tcpSublineText`, called only in the non-relay branch of `subline(for:)` and
  `detailSubtitle`. A relay row shows `(hostname)` and never a metrics line —
  the comment there is explicit that status is carried by the leading shape
  indicator alone.
- **And that list is always empty.** Nothing in `macos/Sources` ever adds a
  direct-TCP machine to the registry: `MachineRegistry.add(_:)`
  (Machine.swift:343) has no callers, `refreshFromRelay`/`rebuild` produce relay
  rows only, and Machine.swift:262 still carries
  `TODO(wp4): load TCP machines from ~/.config/ghostty`.
- Windows' chooser lists Local plus relay devices and nothing else
  (`MachineChooser.Row` is `local | device`), so the rows the two platforms
  actually show carry the same things: name, status shape, hostname subtext.

So there is no Mac behaviour missing here, and building it on Windows alone
would have been a divergence shipped off a false premise — the shape the T404
"CHECK FIRST" path exists to catch.

The UX idea underneath is still a good one, and it is what
`MachineMetricsProbe`'s own header says the probe was written for. It is refiled
honestly, as a feature rather than a parity gap, on **both** seats:

- **T1440** (win) — the chooser's rows show live CPU/mem, built on T298's probe
  policy and T461's connection pool.
- **T1441** (mac) — the same rows on Mac, where the probe exists already and
  only its input list and its relay branch need to change.

## Original summary (kept for the record; its Mac claim is wrong)

Mac's picker owns a `MachineMetricsProbe`
(`MachineChooserView.swift:45`, created at `:1711`) and puts each machine's
live reading on its row for the lifetime of the presentation — which is what
that class was originally written for; the Activity Monitor's card carousel
borrowed it afterwards. Windows' `MachineChooser` has no equivalent: its rows
carry the directory's `online` flag and nothing else.

Noted as a known gap while doing T298, and checked rather than assumed:
`chooser_rows.RowText` is `title` / `subtitle` / `status` / `glyph` and nothing
else (`chooser_rows.zig:43-49`), and every `Metrics` in `MachineChooser.zig` is
`rowMetrics`, i.e. row GEOMETRY.

*(What was checked in 2026-08 was the WINDOWS half — accurately. What was
assumed was the Mac half.)*

## In plain terms

Ctrl+Shift+N lists the machines you can open a window on. Each row shows a
name and an address and nothing about the machine itself, so picking one is a
guess: you cannot tell which box is idle and which is pinned until you are
already on it. The Mac was believed to show each machine's CPU and memory
live on the same list — it does not, for any machine a user actually has, so
nothing is missing here and the improvement is tracked as T1440 / T1441
instead.
