# T289 - Activity Monitor: no visible keyboard focus anywhere in the panel (design system 2.2)

## Summary

T285's panel is keyboard-**operable** — Escape closes it, and Up/Down/PageUp/
PageDown/Home/End move the table's selection through `ActivityMonitor.handleKey`
— but nothing on screen says where the keyboard is. The design system is
explicit about this (§2.2): *"Keyboard focus is always visible. If a control can
be tabbed to, it draws the ring. Missing focus rings are an accessibility
defect, not a polish item."*

Three concrete gaps:

1. **No Tab order.** Tab does not cycle filter -> Show all -> New Process ->
   table the way `MachineChooser.nextFocus` (a pure, unit-tested cycle) does for
   the chooser. The panel has the same shape and should reuse that pattern.
2. **The table has no focus indicator.** Selection is painted (`COLOR_SELECT`),
   but selection is not focus, and nothing on screen says which of the two the
   arrow keys will move.

   The *routing* half of this already landed with T285 and does not need
   redoing: `handleKey` refuses the navigation keys while the caret is in the
   filter EDIT, because Home/End/arrows inside a text box belong to the text
   box. The consequence is that the table is reachable by keyboard only after a
   click — which is precisely what a Tab order plus a visible ring fixes.
3. The native EDIT/BUTTONs draw the theme's own ring, so they are fine; the
   owner-drawn table region is the hole.

## Scope

- A pure `Focusable` cycle + `nextFocus` in `ActivityMonitor.zig`, mirroring
  `MachineChooser.Focusable` (:1624-1655), unit-tested.
- Route Tab/Shift-Tab through `handleKey`.
- Paint a focus ring on the table region when it holds focus, and make the
  keyboard row-movement keys apply only then (today they apply unconditionally,
  which is why the missing indicator is confusing rather than merely plain).
- Decide the row-focus vs row-selection distinction and record it: Windows list
  views draw a focus rect on the focused row separately from the selection fill.

## Validation

- Both `zig build test` lanes plus `zig build test-agent` green; P1-P3 ALL PASS.
- `test\win32\activity-monitor.ps1` grows a section: Tab moves focus through the
  cycle (asserted on `Get-TestFocusedWindow` for the native controls) and the
  table's focus ring is visible in a `Get-TestWindowPixels` capture. The panel is
  a native window, so the capture reads it faithfully.
- A `-NegativeControl` inversion for the new load-bearing claim.
