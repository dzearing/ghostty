# T460 - Crash details still cost a whole red lane to obtain: nothing captures a stack on the FIRST crash, so every intermittent crash is diagnosed by re-running it

## Summary

D6 follow-up (user, 2026-08-04): make crash details easy and fast to get. Today a crash is diagnosed by re-running the binary under cdb after the fact, which only works if the crash reproduces. Investigate always-on first-chance capture (AeDebug/WER LocalDumps scoped to our test binaries, or launching every lane's test binary under cdb from the start) so the first crash is the one that yields the stack.
