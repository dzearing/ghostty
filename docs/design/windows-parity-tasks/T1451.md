# T1451 - Nothing makes anyone run the manual pre-release IME checklist

## In plain terms

Some things about typing Japanese into Ghoztty can only be checked by a person
with a Japanese keyboard installed. That checklist now exists, but nothing asks
anyone to run it, so in practice it will not be run.

## Summary

T642 wrote `docs/design/windows-parity-ime-manual.md`: the IME checks that
cannot be automated on this box (the candidate window, the underlined
intermediate string, reconversion, where the caret rests after a commit)
because they are drawn and read by the input method through the input context,
and this machine has one input method installed.

A checklist nobody is prompted to run is the same as no checklist. Windows
releases are published automatically by `scripts/daily-publish.ps1`, and there
is no pre-release human step anywhere for it to hang off.

Pick a home for it and wire it, rather than adding a document nobody opens:

1. A `docs/design/windows-parity-release-checklist.md` that the publish script
   NAMES in its release notes or its log line, so the checklist is visible at
   the moment a release exists.
2. Or a periodic prompt: a row in the daily digest's Commentary when the manual
   check has not been recorded for the current Mac version line.

The check itself needs a box with a Microsoft IME installed, which this one
deliberately is not — so whatever the mechanism, it has to survive being
deferred rather than blocking a publish.

## Validation criteria

- [ ] Running a publish (or a dry-run of one) surfaces the manual IME checklist
      where a human will see it, and that is demonstrated rather than asserted.
- [ ] Deferring the check does not block or fail a publish.
