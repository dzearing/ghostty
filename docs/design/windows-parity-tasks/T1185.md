# T1185 - Markdown and code viewer panes on Windows still hide their address bar until you hover

## In plain terms

In a markdown or code pane, the bar with the address, Back and Home is not
there until you move the mouse to the top of the pane - and when it appears
the text underneath it shifts. The way out of the pane should never have to be
hunted for. The bar should just always be there, in every kind of viewer pane.

## Goals

- [x] The address bar is on screen from the first layout in every viewer mode
      — markdown, code, diff, website, local HTML page
- [x] The page is inset below the bar rather than covered, so nothing moves
      when the pointer crosses the top of the pane
- [x] The hover-peek machinery is deleted, not flagged off — no poll, no
      reveal strip, no hide timer, no pin state to get out of step
- [x] The acceptance harness measures presence in all five modes, and its
      negative control proves it can score red

## Summary

Main intake 2026-08-30 (range `772e4fc3a..origin/main`). The second half of
upstream commit **fc7e36356**: the nav bar is now pinned open in **every**
viewer mode, and the peek/auto-hide machinery is **deleted** rather than
flagged off. Mac's stated reason: markdown and code were the last hover-peek
modes, and they are the one place where content reflowed under the pointer
while the only way out of the pane had to be found with the mouse first.

T1131 brought the live-page half of this across (`Pin` / `pinned()` in
`viewer_nav_layout.zig`, `navPin()`/`updateNavPin()` on `ViewerPane`). This
task finishes it: pin unconditionally, then remove the 150 ms hover poll and
the peek path it drives. Two loose ends T1131's log named that this should
settle at the same time:

- The contents-card (TOC) half still rides the poll rather than the choke
  point, because pinning from inside `syncBounds` would re-enter it through
  `setNavVisible`. With the poll gone that constraint changes.
- A **diff** pane's own pin, with the change/layout controls that make it
  worth pinning, is T817's - do not absorb it here, but make sure the diff
  pane keeps a visible bar under the new unconditional rule.

- [x] Content is not overlapped: `viewer-nav-pin.ps1` A/C/D measure the

- [x] Nothing reflows when the pointer enters or leaves the top of the pane:
