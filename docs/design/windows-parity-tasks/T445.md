# T445 - Read-only panes have no visual indicator on Windows: port Mac's readonly badge

## In plain terms

You can put a terminal pane into read-only mode so stray keystrokes cannot
reach whatever is running in it. On Windows, nothing on screen tells you that
you did. The pane just silently stops accepting typing, which reads as a
frozen terminal, and the only way to find out is to open a menu and look for
a checkmark. On a Mac the pane wears a small "Read-only" badge in its corner
that you can click to turn the mode back off.

## Goals

- [x] A read-only pane is visibly marked, per-pane, without opening a menu
- [x] The mark appears and disappears the moment read-only is toggled
- [x] There is a way back out of read-only from the mark itself
- [x] Geometry asserted at 1.0 / 1.25 / 1.5 / 2.0 scaling, plus an on-box
      acceptance script

## Validation criteria

- [x] A read-only pane shows a badge; a pane that is not read-only shows none
      — `test/win32/readonly-badge.ps1` sections A/B/H
- [x] In a split, the badge marks the READ-ONLY pane and not its neighbour;
      two read-only panes wear two badges — sections E/F
- [x] The badge is anchored at the design-system inset from the pane's top
      and right edges, recomputed from the live DPI (not eyeballed), and
      re-anchors when the pane resizes — section C/E; `-NegativeControl`
      inverts exactly those two anchor assertions and fails, so they can fail
- [x] Clicking the badge leaves read-only, and only that pane's — section G
      (a real WM_LBUTTON pair through `Send-TestMouse`)
- [x] The badge window is layered, non-activating, and NOT click-through —
      section D
- [x] Geometry, card pixels and both WCAG contrast floors asserted at

      with the contrast pair swept over the whole 0–255 background ramp
- [x] Both `zig build test` lanes, `zig build test-agent` and P1–P3 stay

## Summary

Split out of T28 (2026-08-04). The core's `.readonly` apprt action is an
acknowledged no-op on win32 (`App.zig:4037-4049`), so toggling read-only
changes behavior with no visual feedback at all.

## Details

**What exists today.** The state itself is wired: `Surface.zig:1283` drops
input when `core_surface.readonly` is set, and both the context menu
(`context_menu.zig:101`, `.checked = state.readonly`) and the menu bar
(`menu_bar.zig:348`) render the checkmark. What is missing is anything on
the pane.

**Mac's version** is `Ghostty.SurfaceView.ReadonlyBadge`
(`macos/Sources/Ghostty/Surface View/SurfaceView.swift:1249-1300`), attached
at `SurfaceView.swift:237` when `surfaceView.readonly`:

- Top-right of the pane, 8pt inset.
- `eye.fill` glyph + "Read-only" text, 12pt medium.
- Rounded rect, radius 6, `.regularMaterial` fill, orange 0.6-alpha 1.5pt
  border; foreground `Color(hue: 0.08, saturation: 0.5, brightness: 0.8)`.
- Click opens a popover (`ReadonlyPopoverView`) whose action disables
  read-only.
- Accessibility label "Read-only terminal", children ignored.

**Judgement calls this task must make and record.** Whether Windows gets the
same corner badge or a different affordance is the open question — T28's own
note suggested a *tab-title glyph* instead. A tab glyph is cheaper and reads
as Windows-native, but it cannot say WHICH pane in a split is read-only,
which is the whole point of a per-pane mode. Recommend the corner badge for
that reason, and file a decision (`parity-decisions.ps1`) rather than
quietly picking.

**Design system is mandatory** (`docs/design/win32-design-system.md`): the
badge is a card, so radius 8 and elevation rules apply rather than Mac's 6;
spacing on the 4 DIP scale; >= 4 DIP from the pane edge; the orange border
must clear the 3:1 chrome-boundary floor against BOTH light and dark pane
backgrounds, and the label the 4.5:1 text floor. Put the numbers in a pure
geometry module next to `banner_layout.zig` and assert them at 1.0, 1.25,
1.5 and 2.0.

**Landmarks.** `BannerOverlay.zig` (1433 lines) and `DimOverlay.zig` (188)
are the two existing per-pane overlay patterns; `overlay_zorder.zig` owns
the stacking order and will need the badge slotted into it. `banner_card.zig`
is the existing glass-card paint. The action lands in
`App.zig`'s `.readonly` arm, which today falls through to `return true`.

*Validation:* unit tests for the geometry module at the four scales; an
on-box acceptance script in `test/win32/` that toggles read-only via the
command palette or `toggle_readonly` and asserts the badge appears on the
right pane and disappears on untoggle. Both `zig build test` lanes,
`zig build test-agent`, and P1-P3 stay green.
