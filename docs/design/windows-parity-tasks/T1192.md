# T1192 - The go-loop watchdog task and its HKCU Run entry launch powershell.exe on the desktop, so a restart flashes a focus-stealing console

## In plain terms

Every so often - at sign-in, or whenever the background process that keeps this
work moving has to be restarted - a black console window flashes onto the
screen, takes the keyboard focus for a fraction of a second, and vanishes. If
you were typing at that moment, your keystrokes went somewhere else. After this
the same restart happens with nothing on screen at all.

## Goals

- [x] The scheduled task that revives the supervisor launches it with no
      console.
- [x] The sign-in entry that starts it does the same.
- [x] The installer produces that shape, so re-installing cannot put the flash
      back.
- [x] The launcher is not tied to one machine's folder layout.
- [x] A check that goes red if any of that regresses, watched failing.

## Summary

Same defect class as the dashboard keep-alive fixed on 2026-08-30, in the loop supervisor. go-loop-boot.ps1 registers GhozttyGoLoopWatchdog with New-ScheduledTaskAction -Execute powershell.exe under an Interactive principal, and go-loop-watchdog.ps1 adds an HKCU Run value of the same shape. -WindowStyle Hidden does not prevent the flash (powershell reads it only after its console exists). It is not the every-5-minutes flasher the user reported, because the watchdog is a long-running process whose 10-minute relaunch is refused (0x800710E0) while it is alive - so it only steals focus when it actually restarts, and at every sign-in via the Run entry. Move both to the argument-free wscript launcher pattern (scripts/dashboard-keepalive.vbs), which needs no elevation. Do it deliberately with the watchdog stopped rather than by hand-editing the supervisor while it supervises: S4U was tried for the dashboard and its failure DELETED the task, which is exactly the accident to avoid on the process that revives the loop.

## Validation criteria

- [x] `go-loop-boot.ps1 install` registers `wscript.exe` on a generated
      launcher, and READS THE ACTION BACK - a `powershell.exe` action is now a
      `WARNING ... a revival will flash a console` and exit 2, not a success.
      Verified on this box: `verified: atLogon=True repeats=True
      batteryGate=False timeLimited=False windowless=True`.
- [x] The HKCU Run entry carries the same command. `go-loop-watchdog.ps1
      -Install` re-wrote it from the powershell form to
      `wscript.exe //B //Nologo "...\go-loop-watchdog-launch.vbs"`, and asks
      `go-loop-boot.ps1 launcher` for it rather than re-deriving the naming
      rule, so the two hooks cannot drift into different launch shapes.
- [x] The launcher is GENERATED next to the watchdog it launches, with that
      clone's paths baked in. The first one was committed with `D:\git\ghoztty`
      hardcoded, which is wrong in any other checkout and wrong for the
      harness's temp fixture; it is now `.gitignore`d as the build artifact it
      is.
- [x] The live supervisor was not disturbed: `Register-ScheduledTask -Force`
      replaces the registration only, and the running watchdog (pid 34676) kept
      its lock through both installs.
- [x] `test\win32\go-loop-guard.ps1` covers it on both sides and is ALL PASS:
      P12/P12b on the REAL task (it ends up running the watchdog, through
      whichever host; and that host is GUI-subsystem), V13a-V13e on a temp
      FIXTURE (install writes a launcher beside the watchdog it was given, the
      launcher names that watchdog, it passes window style 0, the action is
      wscript, and install reports `windowless=True`).
- [x] The new gate has been watched failing (T1133). A copy of
      `go-loop-boot.ps1` with `-Execute 'wscript.exe'` mutated back to
      `powershell.exe`, run against a throwaway task, printed `WARNING the
      action is powershell.exe, not wscript.exe - a revival will flash a
      console` and exited 2; `Get-ScheduledTask` confirmed `powershell.exe` was
      what got registered, which is exactly the state V13d/V13e and P12b score
      red.
- [x] Floor lanes green.
- [ ] **Not in scope, deliberately**: the `Start-Process powershell
      -WindowStyle Hidden` inside `-Install` itself, and the watchdog's own
      re-exec. Both flash the same way, but both run with a human already at
      the keyboard - unlike the two autostart hooks, which fire when nobody is
      watching. Filed as T1198.
