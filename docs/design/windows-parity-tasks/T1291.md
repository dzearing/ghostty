# T1291 - Nothing proves a relay window ever comes BACK after its agent restarts - only that it gives up cleanly

## Summary

T368 added ipc-relay.ps1 section 6b, which restarts the agent under a live remote window and accepts either arm: the window re-ATTACHes, or it reports a clear disconnected state. Measured on box, only the disconnected arm is reachable - a hard-killed agent loses its session records (T1278), so the ladder is told session_gone and goes terminal. The re-attach arm's assertions (the +send-keys/+read round-trip through the restored transport) have therefore never executed, and nothing anywhere on this box proves a relay window actually comes back. A GRACEFUL agent restart should preserve the session records and drive that arm; add it as a second variant in 6b (or fix T1278 and let the hard-kill path reach it).
