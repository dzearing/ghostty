# T1291 - Re-running the installer for an already-installed version quits silently

## In plain terms

You run the installer when you already have that exact version. Nothing
happens - the window disappears and you are told nothing. You cannot tell
whether it worked, whether it did nothing on purpose, or whether it broke.

## What the user hit (2026-09-03)

> "I also tried installing the msi with a version already installed and it just
> silently quit. I think this is the case if 1.36 is already installed. there
> should be some message to ask what to do (reinstall, cancel) that's a
> standard dialog to let you know you're already good, not just silently fail."

This is the same-version case, distinct from the two already filed:

- **T1204** is installing over a *running* Ghoztty (no Restart Manager path).
- **T1205** is not being able to tell *which build* is installed.
- **This** is Windows Installer's own already-installed behaviour: with the
  same `ProductCode` and the same `ProductVersion`, a plain `/i` finds nothing
  to do and exits, and in the default UI sequence that can pass without a
  visible word.

## What it should do

Windows already has the convention, and the user named it: when the product is
present at the same version, the installer should offer **Repair** and
**Cancel** (the standard maintenance dialog) rather than vanishing. "You are
already up to date" is a fine answer - being told it is the point.

Worth handling in the same pass, since they are the same branch of the MSI's
UI sequence:

- Same version installed → maintenance dialog (Repair / Cancel).
- Older version installed → upgrade, which already works.
- **Newer** version installed → say so plainly and refuse, rather than a raw
  1638 ("Another version of this product is already installed").

Note this interacts with T1178's in-app updater, which runs the MSI on the
user's behalf: whatever dialog appears must not block a silent/managed install.
Gate the UI on `UILevel` so the updater's quiet path stays quiet.

## Validation criteria

- [ ] Running the MSI when the same version is installed shows a maintenance
      dialog offering Repair and Cancel; neither choice leaves the existing
      install damaged.
- [ ] Cancel exits without changing anything, and says nothing alarming.
- [ ] Running an OLDER MSI over a newer install explains that a newer version
      is present instead of surfacing error 1638.
- [ ] The in-app updater's install path is unaffected - no dialog appears for a
      silent install.
- [ ] An acceptance script in `test/win32/` drives the same-version case and
      fails if the outcome is silent.
