# T1080 - Some Zig sources are not zig-fmt clean and nothing in the floor notices

## Summary

Found while landing T1079: `zig fmt --check src\apprt\ipc\args.zig` fails
against **HEAD**, not just against the working tree. Running `zig fmt` on the
file to tidy that task's own additions therefore also re-aligned two unrelated
multiline argument tables in tests nobody was editing, and those hunks had to be
hand-reverted so the commit stayed focused.

Nothing in the floor asks the question: `scripts\floor-lane.ps1` builds and runs
tests, and `zig build` does not gate on formatting, so a file can drift out of
`zig fmt` shape and stay there indefinitely. `src\apprt\ipc\args.zig` is one
confirmed case; the size of the set is unknown until something enumerates it.

## In plain terms

Nobody sees this in the terminal — it is a housekeeping gap. But every time
somebody edits one of these files and tidies their own change, the tidy also
reshuffles lines they never touched, so the change is harder to read than it
should be and the next reviewer has to work out which hunks are real.

## Goals

- [ ] Enumerate which files under `src/` fail `zig fmt --check` today
- [ ] Reformat them in ONE commit of their own (`chore(fmt): …`), so the churn
      is isolated and never rides someone's feature diff
- [ ] Add the check to the floor so the set cannot grow again — a `fmt` lane in
      `scripts\floor-lane.ps1`, or a step in the `lib` lane, whichever keeps the
      run cheap (it is a source scan, about a second)

## Validation criteria

- [ ] `zig fmt --check` over `src/` exits 0 on a clean tree
- [ ] The floor FAILS on a deliberately misformatted file and passes once it is
      reformatted (teeth checked, not assumed)
- [ ] `scripts\floor-lane.ps1 -Lane all` green
