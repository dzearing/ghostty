# T622 - A Mac viewer cannot decode a win32 layout blob, so cross-machine Restore All pointed at a Windows machine still shows nothing

## In plain terms

Ghoztty can rebuild another machine's whole set of terminal windows on the
machine you are sitting at. As of T337 that works when you are on Windows and
the other machine is a Mac. It still does nothing in the other direction: sit at
a Mac, point Restore All at a Windows box, and it reports there is nothing to
restore even though that box has six windows open. Nobody notices anything
break — the feature just quietly isn't there.

## Goals

- [ ] A Mac viewer rebuilds a Windows machine's windows, tabs and splits
- [ ] A blob it cannot read is still skipped without failing the others

## Summary

The Mac half of **T337**. Layout blobs are opaque to the agent, so the schema is
a contract between two VIEWERS — and the two lineages never shared one. T337
closed the Windows-reads-Mac direction by translating on read
(`src/apprt/win32/mac_layout_blob.zig`); this is the mirror.

**What a win32 blob looks like** (`src/apprt/win32/session_layout.zig`):
snake_case keys, ONE blob per WINDOW (not per tab), a `tabs` array, and each
tab's split tree stored FLAT as a `nodes` array whose `split` nodes carry
`left`/`right` INDICES into that same array (`nodes[0]` is the root). Mac's
`SessionLayoutManifest.Entry` is camelCase, one blob per TAB (grouped by
`tabGroupID`, ordered by `tabIndex`), with a NESTED `tree`.

Field map (win32 → Mac): `session_id`→`sessionID`, `title`→`title`,
`ipc_name`→`ipcName`, `pane_id`→`surfaceID`, `banner`→`banner`, `kind`→`kind`,
`viewer_location`/`viewer_home_location`/`viewer_origin_directory` →
`viewerLocation`/`viewerHomeLocation`/`viewerOriginDirectory`. `Split.layout`
and Mac's `direction` are the same two spellings from the same core
`SplitTree.Split.Layout`, so directions and ratios map 1:1. One win32 window
with N tabs becomes N entries sharing a fresh `tabGroupID`, `tabIndex` = tab
order, `Tab.title`→`titleOverride`, `Window.title_override`→
`windowTitleOverride` on the first entry only.

Two rules T337 arrived at that apply here unchanged:

- **Detect by SHAPE, never by a tag.** The blobs already in live agents were
  written before any tag could exist, and an agent outlives the app that wrote
  it by design. A win32 window has `tabs` and no `tree`; a Mac entry has `tree`
  and no `tabs`.
- **Drop the WP-D3 pair** (`screen_snapshot`/`screen_snapshot_offset`). win32's
  `serializeWindow` already strips its own on the way out, so there is nothing
  to carry — but do not reintroduce one: another viewer's screen painted into
  this pane, attached at that viewer's stale offset, is the failure T413 exists
  to prevent.

**The frame converts now — T623 (landed on the win32 seat) defined the
cross-lineage contract, and this task's Mac writer/reader must speak it:**

- One additive field beside `frame`: the full height of the PRIMARY display of
  the machine that wrote the blob, in the same units as the frame. Spelling is
  per-lineage: win32 writes `primary_screen_height` (already shipping, read it
  when decoding a win32 blob), Mac writes `primaryScreenHeight`
  (`NSScreen.screens.first!.frame.height` — the FULL frame, not
  `visibleFrame`: both global coordinate spaces are anchored at the primary's
  full frame, and a work-area flip is off by the menubar/Dock).
- The conversion is one formula, its own inverse, exact for every monitor of
  the source arrangement: `y' = primary_screen_height - y - h`. x, width and
  height pass through. Reading a win32 blob on Mac: apply it to get Cocoa's
  bottom-up y. Writing a Mac blob: just record the field; the win32 reader
  (`mac_layout_blob.frameFrom`) applies the same formula.
- Absent or degenerate (`<= 0`, non-numeric) field ⇒ pass the origin through
  verbatim exactly as before, and let
  `SessionLayoutRestore.reanchoredFrame` catch anything off-screen. Never
  substitute the LOCAL screen's height — that invents information.

The win32 ends of the contract (writer + reader + unit tests + the C5
assertion in `test/win32/layout-blob-cross-lineage.ps1`) are in T623's commit;
mirror the same three unit-test shapes on the Mac side.

## Validation criteria

- [ ] A unit test that a real win32-shaped blob (flat `nodes`, `left`/`right`
      indices, snake_case) decodes into an `Entry` tree with the same topology,
      ratios and session ids
- [ ] A unit test that one win32 window with 2+ tabs becomes that many entries
      sharing a `tabGroupID`, in `tabIndex` order
- [ ] A unit test that a malformed / unrecognized blob is still skipped without
      costing the other blobs (the non-fatal rule)
- [ ] A unit test that a win32 blob's `primary_screen_height` flips the frame's
      y (`y' = h - y - height`), that an absent field passes through, and that
      the Mac writer emits `primaryScreenHeight` beside every frame (T623
      contract)
- [ ] On the box: Restore All on a Mac pointed at a Windows machine rebuilds its
      windows with panes attached to the live sessions
