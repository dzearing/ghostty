# T1459 - floor-lane refuses on low commit instead of waiting for the headroom to come back

## Summary

2026-09-08 (T665 turn): scripts\floor-lane.ps1 preflight FAILED with 1.6 GB of commit free - a user application was holding 88 GB - and gave up immediately. Two minutes later there was 29 GB free and every lane passed. The GATE is right (a lane started there dies mid-compile in a fault that reads as broken code); the give-up is not, because free commit is a whole-machine number another process moves by tens of GB and the loop's only recovery is a turn improvising a poll loop by hand. It should WAIT for the headroom - bounded, saying what it is waiting on and who is holding it - and refuse only when the wait runs out. Never by closing anything itself: the committers are the user's apps.
