# T981 - The agent-adopt harness cannot clear its own guard - a green run leaves the row due

## Summary

test\win32\agent-adopt.ps1 has a guard-due row (src/remote/agent/adopt.zig + the harness) but no stamping tail, so a clean green run does not re-stamp it and the row can only be satisfied by hand with 'guard-due.ps1 update -Guard agent-adopt'. That is the same shape T883 fixed for lane-leak-sweep and T898 for release-artifacts: a permanently-due row trains the loop to reach for the -NoGuardDue hatch, which is how the hatch stops meaning anything. Wanted: the standard tail (stamp only when there are zero failures AND zero skips, so a run that skipped a section never vouches for the half it did not look at), plus a sweep for any other row whose harness never stamps.
