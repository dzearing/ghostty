# T1450 - The composer's IME evidence retires with the RichEdit fallback (T937)

## In plain terms

The proof that someone typing Japanese into the feedback box gets their text
intact currently runs against the OLD text box, which is still there as a
backup. When that backup is removed, the proof goes with it and nobody notices
until a Japanese user files a report that comes out mangled.

## Summary

T642 added section K to `test/win32/viewer-feedback.ps1`: it posts a real IME
composition (`WM_IME_STARTCOMPOSITION`, composed characters as `WM_IME_CHAR`,
`WM_IME_ENDCOMPOSITION`) at the composer's RichEdit and asserts the pane's
mirrored buffer is byte-exact once the composition ends.

That whole suite is pinned to the RichEdit **fallback**
(`GHOZTTY_COMPOSER_SURFACE=richedit`), because window messages cannot reach a
Chromium window from the background test desktop. T937 removes the fallback.
When it does, section K has nothing to drive and the evidence for the LIVE
surface — the WebView2 contenteditable, whose IME is Chromium's — does not
exist anywhere.

Land this WITH T937, not after it. Options, in the order they should be tried:

1. Drive the composition through the web composer's own script bridge (the
   in-process `host floor` test in `ViewerPane.zig` already drives a real
   controller end to end), asserting the same mirror invariant on text that
   arrives by an insertion path rather than a keystroke — the code-owned half
   is identical.
2. If nothing can synthesise a composition into a WebView2 from here, move the
   composer's IME row into `docs/design/windows-parity-ime-manual.md` and say
   so in the suite's header, so the boundary stays written down rather than
   silently moving.

Whatever the answer, the same mirror invariant must still be asserted for text
that reaches the composer WITHOUT a `WM_CHAR` — that is the failure mode a
keystroke-only test cannot see.

## Validation criteria

- [ ] After T937, the composer still has an assertion that text arriving by a
      non-keystroke path ends up byte-exact in the pane's buffer, OR the manual
      checklist carries the row and the suite header names the move.
- [ ] `test/win32/viewer-feedback.ps1` is green with no dead IME arm left in it.
