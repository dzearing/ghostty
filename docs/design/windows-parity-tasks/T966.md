# T966 - The release-artifacts guard can never go current on this box, so every turn's commit gate runs in hatch mode

## Summary

guard-due's release-artifacts row has been DUE since at least 2026-08-18 and cannot be cleared here: test\win32\release-artifacts.ps1 refuses to stamp unless zero sections skipped, and its section B needs Docker, which is a standing SKIP on this box (starting it buried the machine once - WSL2 backend to 28 GB). The consequence is worse than a stale stamp: parity-tasks.ps1 validate FAILS on any due guard, so a turn that only touched PowerShell has to pass -NoGuardDue to commit at all, and that hatch disables the gate for EVERY other harness in the same breath. A permanently-red gate trains the loop to bypass it, which is exactly how T783's defect comes back. Options to weigh: split the Docker-dependent packaging sections into their own guard row so the Docker-free sections can stamp; or let a run stamp the subset of Covers it actually exercised; or give guard-due a per-row 'needs Docker' marker that reports rather than fails. Whichever way, the invariant to restore is that a clean turn on a Docker-less box can commit without a hatch.
