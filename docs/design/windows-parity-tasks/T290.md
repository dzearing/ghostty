# T290 - Activity Monitor keeps enumerating every process while minimized or hidden

## Summary

T285's panel polls on a `SetTimer` every `trend_gauge.sample_interval_ms`
(1500 ms) for as long as it is open, and each poll is a **full process
enumeration**: `CreateToolhelp32Snapshot` plus an `OpenProcess` and two
`QueryFullProcessImageName`/times calls per pid. Measured on this box that is
**~300 processes every 1.5 s, forever** — including while the panel is
minimized, fully occluded, or on another virtual desktop, where not one of those
samples can be seen.

The work is off the GUI thread (a worker per sample, joined on close), so it
never stalls the UI. What it does spend is CPU and process-handle churn, on a
panel a user is likely to leave open for hours. That collides directly with the
standing bar for this fork: *"Reliable and fast under long-context use ... no
slowdowns, tuned for hours-long Claude Code sessions."*

Mac has the same shape (a `Timer` that runs while the window is open), so this
is a Windows-side improvement rather than a parity gap — worth doing anyway, and
worth recording as a deliberate divergence if it lands.

## Scope

- Suspend the sample timer when the panel is minimized (`WM_SIZE` /
  `SIZE_MINIMIZED`) or hidden, and resume — with an immediate catch-up sample —
  when it is restored, so the table is never stale on the frame the user sees it.
- Decide what happens to the trend ring across a suspension: a gap in a chart
  whose X axis is "sample index" would silently misrepresent time. Either clear
  the ring on resume (the honest, cheap answer, and what a source switch already
  does on Mac) or carry a gap marker. Record the decision.
- Consider the same treatment for full occlusion; `WM_SIZE` alone does not
  cover a window buried behind another. Do NOT guess — measure whether
  `DwmGetWindowAttribute(DWMWA_CLOAKED)` / `IsIconic` is enough before adding
  anything more exotic.

## Validation

- Both `zig build test` lanes plus `zig build test-agent` green; P1-P3 ALL PASS.
- `test\win32\activity-monitor.ps1` grows a section: minimize the panel
  (`Send-TestSysCommand`), assert the state-line count in the app's stderr STOPS
  growing over several intervals, restore it, assert the count resumes AND that
  a fresh sample landed promptly rather than on the next tick.
- That assertion needs its own negative control: the counter must be proven to
  grow while the panel is open, or "it stopped" is true of a dead oracle.
