# T854 - wp4_e2e bug-2 proof can false-PASS: the 500ms 'let the DETACH land' sleep races the stale-DETACH delivery

## In plain terms

One of the freeze/thaw safety tests can quietly pass without actually testing
the thing it exists for. It proves that an old window's teardown can't silence
a reconnected session — but it only waits half a second for the teardown
message to arrive before checking, so on a slow or busy machine the check can
run before the message lands, and the test passes without the dangerous event
ever happening. Nobody sees a failure; the coverage just silently evaporates.

## Summary

Found during T498's load-flake audit. `src/remote/wp4_e2e.zig`
`runFreezeThawProof` (bug 2, the stale-DETACH proof): after
`dialed_a.conn.detachChannel(pane_a)` it does
`std.Thread.sleep(500ms) // let the DETACH land`, then asserts the re-attached
pane_b still round-trips. If the DETACH has NOT been processed by the agent
before the echo runs, the assert passes vacuously — a false PASS, the inverse
of the flaky-red shapes T498 fixed (a load problem still: a loaded box makes
the race MORE likely). The fix needs an observable "agent processed the
DETACH for that channel" signal to wait on (e.g. poll `LIST_SESSIONS` /
`requestSessions` for the session's attach state, or an agent-side counter
surfaced over the protocol) instead of a fixed sleep — pick whatever the
protocol already exposes before adding anything.

Also noted for the same seat: the harness's other deadlines
(`waitForListening` 5s, `drainForMarker` 8s) are wall-clock-bounded (good
shape) but tight by T183's standard (10s of liveness bound proved spendable
under load); consider widening while in the file.

`seat: mac` because the harness is POSIX-only (SIGSTOP/SIGCONT) and cannot be
run or validated from the Windows box.

## Validation criteria

- [ ] The bug-2 proof waits on an observable DETACH-processed effect, not a
      fixed sleep.
- [ ] A deliberate delay injected before the DETACH delivery makes the proof
      WAIT (not pass vacuously) — negative control run on a Mac/Linux box.
- [ ] `zig build wp4-e2e` harness run passes on the Mac seat.
