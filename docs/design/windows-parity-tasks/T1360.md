# T1360 - macOS never samples what a session is running, so the Mac +sessions roster stays blank

## Summary

T429's foreground-command sampler has a Windows arm (the shell's most recent direct child, read via its PEB) and a Linux arm (/proc/<pid>/cmdline off tcgetpgrp), but the macOS arm was deferred and returns null - see the switch in queryForegroundCommandFn (src/remote/agent/pty_child.zig) and its holder twin. T545 surfaced fg_cmd in +sessions and the chooser reads the same field, so on Mac both stay blank for every plain-shell session while Windows names the command. Implement the macOS arm (proc_pidinfo / KERN_PROCARGS2 off the tcgetpgrp leader) so the feature is real on both platforms.
