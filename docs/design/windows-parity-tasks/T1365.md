# T1365 - A Repair tells every open window a newer build is installed when nothing changed

## In plain terms

If you run the installer for the version you already have and choose Repair,
every Ghoztty window you have open starts saying a newer build is installed and
offering to restart. Nothing newer was installed. Restarting gets you the same
build you were already running, and the offer comes back the next time somebody
repairs.

## Summary

`image_freshness.isStale` (T1205) compares two runtime facts: when this process
started, and when the file it was launched from was last written. That is the
right comparison for an upgrade - a version string cannot tell two builds of the
same version apart - but it answers "the file changed" rather than "the build
changed", and a Repair rewrites the same bytes with a fresh mtime.

So after a repair:

- the tray balloon fires on every open window,
- About turns into a "Restart Now" offer,

and both are false. T1352's installer-side offer deliberately does not fire on
this path (its condition is `NOT Installed AND OLDERVERSIONFOUND`, the true
upgrade only), which is why this is visible as a difference: the installer says
nothing and the app nags anyway.

## Where

- `src/apprt/win32/image_freshness.zig` - the comparison.
- `src/apprt/win32/provenance.zig` - where the two timestamps are collected.
- `src/apprt/win32/App.zig`, `Surface.zig` - the balloon and the About offer.

## Likely shape

Keep the mtime test as the cheap trigger, and confirm it before speaking: read
the build stamp out of the on-disk exe and compare it against this process's
own. Equal stamps mean the file was rewritten with the same build, which is not
news. That is strictly more information than the mtime alone and does not
reintroduce the version-string weakness the module's header rejects, because a
build stamp is per-build rather than per-release.

## Validation criteria

- [ ] A repair or same-version reinstall leaves open windows saying nothing.
- [ ] A genuine upgrade still raises the balloon and the About offer (the T1205
      behaviour is unchanged).
- [ ] The comparison is unit-tested in the `none` lane, the way the rest of
      `image_freshness.zig` is.
