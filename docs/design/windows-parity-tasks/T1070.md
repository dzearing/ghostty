# T1070 - The older copy still cannot start itself: the question offers no way to switch builds for you

## In plain terms

Start a Ghoztty that is a different version from the one already running and it
now asks what you meant: open a window in the one that is running, or open
nothing. If what you actually wanted was to run the copy you double-clicked,
you have to go and quit the other Ghoztty yourself, then start this one again.
The app knows both of those steps; it could just do them.

## Summary

T1023 built the question (`App.handoffChoice` → `ConfirmDialog`, with
`ipc_handoff.mismatchPrompt` writing the text). It deliberately stopped at two
answers, because the third one needs the running instance to shut down on
request and this one to take the endpoint afterwards, and neither exists yet.

What a third button would take:

- **A way to ask the running app to quit.** There is no `quit` IPC action
  today, and it cannot simply be assumed: the whole point of this path is that
  the other instance is a DIFFERENT build, so it may be one that predates the
  action. The launcher has to handle "it does not understand the question"
  (fall back to today's two answers plus the sentence telling them to quit it
  by hand) as a normal outcome, not an error.
- **A bind retry.** After the other app exits, this process is already alive
  and part-way through `App.init` — it can simply re-run `IpcServer.init`
  instead of relaunching itself. Bounded, with a fallback to handing off if the
  endpoint never frees.
- **An answer to what the user loses.** Terminals survive it: sessions live in
  `ghoztty-agent`, and the layout is persisted continuously, so a quit and a
  restart is the same shape the morning refresh already performs. That should
  be verified rather than assumed, and the button's text should say it ("your
  terminals will reopen").

## Validation criteria

- [ ] A third answer on the T1023 question quits the running instance and
      starts the copy the user launched, with no second app and no second tray
      icon at any point
- [ ] A running instance too old to understand the request degrades to the
      two answers that exist today, and says why
- [ ] The user's terminals come back: the sessions live before the switch are
      attached again after it
- [ ] `test\win32\single-instance-join.ps1` grows the arm and stays ALL PASS
