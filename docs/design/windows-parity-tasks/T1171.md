# T1171 - The installed release refreshes once a day, so a fix landing after 5am does not reach the terminal the user works in until tomorrow

## Summary

Measured 2026-08-23. The always-visible address bar (T1131) landed on Windows at 08:00 today, commit bb29caa50. At 15:30 the user reported it missing. It was not missing: the three install locations were at Desktop portable 13:35 (has it), network share 13:35 (has it), and %LOCALAPPDATA%\Programs\Ghoztty 05:10 (does NOT). Location 1 is the one on PATH, the one that owns the ghoztty-<user> pipe, and the one the user actually types in. The cause is structural, not a miss: deliver-windows-build.ps1 covers locations 2 and 3 and runs at task boundaries, while location 1 is refreshed ONLY by upgrade-ghoztty-windows.ps1 via morning-refresh.ps1, which by design fires once per day on the first push after 5am. Every user-visible fix that lands after the morning refresh therefore waits up to 24 hours in the one copy that matters. This is the SECOND time this exact failure has been reported about this exact feature - morning-refresh.ps1's own header records the user saying 'still no address bar' on 2026-08-07 for a fix already at HEAD and simply undelivered. The once-a-day cadence came from a real constraint (an app restart interrupts the session, and an agent update ends the loop), so the fix is not simply 'refresh more often' - see the decision this task carries. Acceptance: a user-visible fix that lands at any hour is in %LOCALAPPDATA% within one task boundary, or the user is told in the pane that a newer build is waiting and how to take it.

## In plain terms

A new version of Ghoztty could be published while you were working, and the
window you were typing in would never mention it - it asked "is there a newer
version?" once, when it started, and then never again. If you keep a terminal
open for days (most people do), that is a fix you cannot get without noticing
on your own and restarting. Now the app keeps asking in the background, so a
release published at any hour offers itself to you within the hour - and once
you have said "Later" to a version, it stops bringing that one up again.

## Goals

- [x] A release published while the app is running is found without a restart
- [x] A version already offered is not re-announced (or re-downloaded) on every check
- [x] The existing gates still hold: dev/portable copies never phone home, `auto-update = off` is honored, and the network is still asked at most once an hour
- [x] The update-check harness covers the repeat, and is wired to a guard-due row so it cannot rot unnoticed
