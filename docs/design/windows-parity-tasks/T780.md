# T780 - The input-desktop audit does not sweep test\win32\lib\, so a harness helper can make every consumer input-desktop-only for free

## Summary

T276 widened the audit to a second family (screen-DC reads) but not its SCOPE: Get-ForegroundAuditFindings sweeps test\win32\*.ps1 non-recursively, and lib\ is excluded on the grounds that TestDesktop.ps1 legitimately owns a SendInput for its -Interactive hatch. That reasoning covers the foreground family and does not transfer to the screen-DC one: a new lib\ helper that reads the composited screen would make EVERY script that calls it input-desktop-only, and not one of them would be flagged, because the site is not in a swept file. Same miss shape T272 and T276 both closed, one level up - a mechanism the sweep cannot see. No known instance today (measured 2026-08-11: zero screen-DC sites under lib\), which is why this is P2 rather than a defect. Likely shape: sweep lib\ too, with a per-file stated-intent marker for the harness's own hatch instead of a blanket directory exclusion, so the exemption is one line a reader can find rather than an absence.
