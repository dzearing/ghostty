# T1116 - The scrollback holder misses its periodic flush and loses the buffer on a crash

## In plain terms

The part that keeps a copy of your scrollback on disk is supposed to save regularly, so a crash costs you at most a few seconds of history. The check said the regular save never happens and the history is gone after a simulated crash. The saving turned out to be working - it lands within about a second - and the CHECK was asking for something impossible: it pushed so much output through the pane that the line it went hunting for had long since been dropped from the very buffer a save writes. The check now measures the real volume as it goes, so it can only ask for scrollback that still exists.

## Summary

`test\win32\holder-volume.ps1` scored `HOLDER-VOLUME: 2 FAILURE(S) (14 assertions passed)` in the T1094 sweep:

```
FAIL B4 the marker reached a .ring file inside the periodic interval (the volume trigger fired)
FAIL C3 the marker is still on disk after the crash
```

The two are almost certainly one fault: if the periodic/volume-triggered flush (B4) never fires, then there is nothing on disk to survive the crash (C3). Fourteen other assertions pass, so the holder is running and doing its other work.

The user-visible consequence is real: scrollback written shortly before a crash is lost, and the crash is precisely when you want it.

## Where

- `src/remote/agent/` (or the holder module) - the periodic and volume-triggered flush to `.ring`
- `test/win32/holder-volume.ps1` sections B and C

## Goals

- [x] Check whether the volume trigger fires at all - it does, every run: the marker reaches a `.ring` file about a second after the flood starts.
- [x] Fix B4 first and re-run; C3 followed, as the task predicted - one fault, not two.
- [x] The fault was in the harness rather than the flush: the flood was sized in TYPED bytes (256 KB), a ConPTY re-rendered it into more than 2 MB, and the marker was evicted from the agent's own ring before any snapshot could carry it.
- [x] The flood is now driven to a MEASURED volume read off the snapshot file, and both edges of the window the marker has to sit in are asserted rather than assumed.
