# T684 - 126 already-merged Mac commits have never been cited by any Windows work item

## Summary

The T152 sweep, run over already-merged history (680a07ed3..HEAD, i.e. everything since 2026-06-01), reports 210 commits touching macos/ or src/viewer/ of which 126 are cited nowhere in docs/design/windows-parity*. The 2026-07-29 hand audit that filed T152 only covered --since=2026-07-08, so this is the tail it never reached, plus everything the T88/T117 merges brought in before that. Most are expected to be no-parity-owed (Swift-only fixes, macOS test harness changes, doc scrubs) or covered-but-uncited the way T598's six turned out to be - but that is a prediction, and the entire point of T152 is that a prediction about coverage is not evidence of it. Work it in slices (a month at a time), dispositioning each commit into docs/design/windows-parity-sweeps.md as filed / covered-by-Tnnn / no-parity-owed-because-X, and file real tasks for the ones that turn out to be genuine gaps. Done when scripts\parity-sweep.ps1 -Range 680a07ed3..HEAD exits 0.

## In plain terms

Ghoztty on Windows is built by following what the Mac version does. Over the
last two months 210 changes landed on the Mac side, and nobody had ever
checked 126 of them against the Windows list — so a Mac feature could have
been built, merged, and quietly never arrived on Windows, with nothing
anywhere saying so. This goes through all 126 one by one and writes down, for
each, either which piece of Windows work already covers it or why Windows owes
nothing. Seven turned out to be real holes and are now on the list. Nobody
sees a new button today; what changes is that the Windows list can now be
trusted to be complete.
