# T1106 - Resuming a session from the chooser does not attach it, so its 'not in any window' mark never clears

## In plain terms

The session chooser marks sessions that are running but not shown in any window. Picking one and pressing Return is supposed to bring it back into a window and drop the mark. The mark stays, and the session is not actually reconnected - so the list keeps telling you something is orphaned after you have just reclaimed it.

## Summary

`test\win32\chooser-orphan-badge.ps1` scored `4 FAILURE(S) (12 passed)` in the T1094 sweep. Sections 1 and 2 pass in full - marking works. Section 3, taking the mark AWAY, does not:

```
PASS  the marked row is rendered to resume (index 1 of 3)
FAIL  Return resumes the marked row
FAIL  the resumed session is the marked one ( vs 66aa672cd9933dc915b649c130dc8d80)
PASS  the chooser dismissed onto the resumed window
FAIL  the agent reports the resumed session ATTACHED
PASS  the chooser reopens once more
FAIL  the resumed session dropped its mark (count back to 0)
```

The empty session id in assertion 2 (`'' vs 66aa672c...`) says the resume produced no session at all, and the chooser still dismissed onto A window - so the user gets a window that is not the session they picked. The agent agreeing it is still unattached, and the mark persisting, are both downstream of that.

This overlaps `orphan-notify.ps1`, which fails on the same two facts (`the agent reports the resumed session ATTACHED`, `the attach reset unattached_since to null`) - see that task; a single attach-path defect may close both.
