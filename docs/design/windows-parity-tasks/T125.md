`win-v*` tags), and `LocalAgent.zig:264` states outright that "the listen-pipe
agent never self-updates".

**Split this by risk, because the two halves are not equally important.**

- **The notes UI is nice-to-have.** `release-notes/*.json` is repo-shared, so
  only presentation + last-seen tracking need porting.
- **The agent-upgrade confirmation is a correctness requirement.** CLAUDE.md's
  agent-contract section mandates that when a protocol skew means live sessions
  cannot be carried across, the app shows an explicit *"Upgrading will reset all
  windows. Continue?"* before resetting — and prefers a lazy, non-destructive
  upgrade when sessions CAN be carried. Windows has no implementation of either
  path. Since the win32 agent already outlives the app (HKCU Run entry, survives
  app upgrade), the skew this protects against is reachable on Windows today.

Treat the second bullet as the real T125 and the notes viewer as a follow-on.

## In plain terms

The background process that holds your terminal sessions can end up speaking a
different language than Ghoztty itself -- after an update, or after a rollback.
When that happens today, Ghoztty simply cannot reach it: it quietly gives up,
your new windows lose session persistence, and nothing on screen says why. It
should do what it already does for a merely out-of-date background process:
say what is wrong, tell you that fixing it will close your existing sessions,
and ask before doing it.

## Goals

- [x] An incompatible handshake is told apart from every other dial failure
      (today `error.HandshakeFailed` covers a garbled HELLO, a transport error
      and a genuine version mismatch alike).
- [x] The app knows WHICH side is older, so it never kills a newer agent to
      install an older one (the existing "never downgrade" rule).
- [x] An older agent + a skew takes the mandatory-update path: the existing
      confirmation dialog, with copy that names the skew rather than staleness.
- [x] A newer agent + a skew does NOT restart anything; it says the app is the
      one out of date.
- [x] The decision is pure and unit-tested, like `agent_upgrade.evaluate`.

## What landed

- `src/remote/tcp_dial.zig` — a failed handshake now returns
  **`error.ProtocolIncompatible`** when (and only when) the peer's HELLO parsed
  and `negotiate` disagreed with it, plus a `DialReport` carrying the peer's
  `proto_version` out of the failure. The discriminator matters: the control
  reader raises `error.Incompatible` for EOF-before-HELLO, a malformed frame and
  an unparseable payload as well, and mapping those to a protocol disagreement
  would hand the app a destructive answer to a torn socket.
- `src/remote/connection.zig` — `peer_proto_version`, captured before
  `negotiate` runs so it survives the failure it exists to explain.
- `src/apprt/win32/agent_upgrade.zig` — `evaluateSkew` (pure), three new
  `Reason`s, and `formatSkewConfirmText`. No idle arm: liveness lives inside the
  agent we cannot talk to, so there is no state in which a silent destructive
  restart is justified.
- `src/apprt/win32/LocalAgent.zig` — records the skew instead of swallowing it,
  stops spawning over a live skewed agent (it holds the single-instance guard,
  so the spawn could only ever burn the deadline on the GUI thread), and clears
  it on a good dial or a restart.
- `src/apprt/win32/App.zig` — `handleAgentProtocolSkew`, checked before the
  "nothing dialed, nothing to judge" bail, reusing T147's dialog, refresh guard,
  relaunch guard and failure notice.
- `src/remote/agent/{main,server}.zig` — `GHOZTTY_AGENT_PROTO_VERSION`, a
  debug-only test seam (the app's `GHOZTTY_AGENT_BUNDLED_VERSION` mirrored),
  because both ends compile the same `proto_version` constant and a skew is
  otherwise unreproducible from one tree.
