# T388 - A leading ~ in a --view path is not expanded, so ~/x.md resolves to <cwd>\~\x.md

## In plain terms

Asking Ghoztty to open a file from your home folder using the `~` shortcut —
for example "open ~/notes.md in a side pane" — shows an error page instead of
the file, because the `~` is taken literally as a folder named `~`. On the Mac
the same command works. After this lands, `~` means your home folder on
Windows too, whichever slash you type.

## Goals

- [x] `--view=~/x.md` (and `~\x.md`) opens the file under the user's home directory
- [x] A bare `--view=~` resolves to the home directory itself
- [x] `~foo/x` and a `~` mid-path stay ordinary relative paths (never half-expanded)
- [x] The classification is a pure, unit-tested function the address bar can reuse (`tildeRemainder` in `src/cli/view_arg.zig`)

- [x] `viewer-panes.ps1` opens a real file under `%USERPROFILE%` through `~` (both `~/` and `~\` forms) and the pane's `url` comes back absolute — section 8a2, all 6 asserts PASS on 2026-08-06

## Summary

`ghoztty +split --view=~/notes.md` opens a viewer showing "Cannot read file"
for a path that literally contains a `~` directory.

`src/cli/view_args.zig`'s `needsResolution` asks only `isAbsolute` and "does it
have a scheme", so `~/notes.md` is classified relative and `std.fs.path.resolve`
glues the caller's cwd onto its front. Mac does not have this bug: its
`ViewerView.expandFilePath` (`ViewerView.swift:373`) runs
`expandingTildeInPath` before the path is ever used, and it is the function
T90e's `viewer_content.filePath` was ported from — `~` was the one leg of it
that did NOT come across, because the CLI resolves paths before the server sees
them and the gap is upstream of the port.

## Details

The fix belongs in `view_args.zig`, not in the viewer: every `--view` consumer
wants the same answer, and expanding it at the CLI keeps the server's location
absolute the way `+list --json` and the session manifest already assume.

- `~` and `~/…` expand against `%USERPROFILE%` (`~\…` too — a Windows user
  types a backslash).
- A `~` that is not the whole first component (`~foo/x`) is POSIX's
  "another user's home", which Windows has no answer for; leave it alone
  rather than half-expanding it.
- The address bar (design P4) will need the same classification, so put the
  test on the pure function.

*Validation:* unit tests in `view_args.zig` (none lane) for `~/x.md`, `~\x.md`,
a bare `~`, `~foo/x`, and a `~` in the MIDDLE of a path (untouched). Plus one
`viewer-panes.ps1` case opening a real file under `%USERPROFILE%` through `~`
and asserting the pane's `url` came back absolute.
