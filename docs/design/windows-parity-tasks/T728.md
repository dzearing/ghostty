# T728 - Four launches added on 2026-08-10 do not declare session persistence

## In plain terms

Every test that starts the terminal has to say whether it wants the previous
run's windows to come back. Four tests written today forgot to say, so the
automatic check for it is failing - and a check that is always red is a check
nobody reads.

## Summary

`test\win32\persistence-flag.ps1` section A (the T158 sweep) fails today:

```
FAIL  A1 no launch leaves persistence unstated (undeclared: 4 of 166)
```

The four sites are all from work that landed 2026-08-10, and none of them are
the sweep's fault - the sweep is doing exactly its job:

- `test\win32\agent-attach-refused.ps1:276` (d545a15ca, T657) - section C's
  control launch. It plainly WANTS persistence on (it is the arm that proves an
  unedited manifest restores a live pane), so `--session-persistence=true`
  spelled out is the fix, not a marker.
- `test\win32\url-scheme.ps1:359, 368, 381` (6ecea2507) - three
  `ghoztty-debug://open/urlwin` activations. An activation is answered and the
  process exits without opening a terminal, which is the forward-and-exit shape
  the sweep's `# persistence: <reason>` marker exists for.

Found while running the sweep as part of T199 (which added a launch of its own
to the same directory and is declared).

## Details

- Both fixes are one line each; the judgement is only which form applies, and
  the two cases above are the two canonical answers.
- Re-run `powershell -NoProfile -File test\win32\persistence-flag.ps1` after -
  A1 must read `undeclared: 0`, and sections B and C must stay green (B is the
  teeth check that the sweep can still say no).

- [ ] `url-scheme.ps1` still ALL PASS.
