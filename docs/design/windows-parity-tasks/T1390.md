# T1390 - Closing a remote window kills the session - there is no Disconnect

## Summary

Main intake of `830ba93cd` (merge `669b39b68`, 2026-09-04): the Mac close
confirmation for a window whose terminals run on a **remote machine** now offers
a third button - **Disconnect** (rightmost, and the default), then Close, then
Cancel. Disconnect skips the CLOSE-on-free marking, so the remote process keeps
running and the session stays resumable from the chooser. Windows has no such
button: closing a remote window always terminates the remote child.

## In plain terms

Right now, closing a window that is running on another machine kills whatever is
running there. There is no way to step away from a long build on a remote box and
come back to it later - shutting the window is the same as ending the work. Mac
just grew a Disconnect button for exactly this; Windows has not.

## Details

Points the Mac change makes that the Windows port has to carry, not just the
button:

- **The answer is recorded as a PIN, not a one-shot intent.** A single close
  marks CLOSE-on-free from more than one path, in an order that varies by how
  the window was closed, and a later marking would silently kill the session the
  user asked to keep. The pin refuses later CLOSE markings and is released on
  re-adoption into a live tree (an undone close, a pane moved between windows);
  a rebuild swap deliberately does NOT release it.
- **A remote window is confirmed even when IDLE** - ending a process on another
  machine is not the recoverable thing an idle local shell is. Widen the gate at
  each INTERACTIVE caller only.
- **Not inside the programmatic close path.** IPC `+close`, viewer panes and any
  scripted close must never raise a modal, or every later `ghoztty +...` command
  wedges behind it.
- **Excluded on purpose:** local session-persistence windows (whose "closing a
  pane ends its session" contract the CLI documents), viewer and exited panes,
  and users who set `confirm-close-surface = false`.
- A tab group can mix machines, so a group-scoped close merges the affected
  surfaces into one prompt.

Read `830ba93cd` in full before starting; the Windows seat owns the win32
confirmation dialog and its own surface-free path.

## Goals

- [ ] Closing a remote window offers Disconnect / Close / Cancel, Disconnect default
- [ ] Disconnect leaves the remote session running and resumable from the chooser
- [ ] The keep-alive answer survives every close path (pin, not one-shot)
- [ ] Scripted / IPC closes stay modal-free

## Validation criteria

- [ ] An acceptance script in `test\win32\` closes a remote window, takes
      Disconnect, and finds the session still listed and resumable
- [ ] The same script proves Close still ends it
- [ ] `ghoztty +close` against a remote window raises no dialog and returns
- [ ] `confirm-close-surface = false` still closes without a prompt
