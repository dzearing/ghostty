# T418 - Banner plain-text lines never wrap on Windows, and the first line runs under the chevron

## Summary

A `.text` block is painted as exactly one line and the content width ignores
the chevron box, so a long banner line is clipped at the card edge and
collides with the collapse chevron. Mac wraps paragraph lines; on Windows
only TABLE CELLS wrap. Reported from a live pane 2026-08-03: a one-paragraph
banner ran off the right edge and pushed the chevron out of reach, where the
user expected the text to wrap and stay fully readable.

## Root cause (verified 2026-08-03 by reading the paint path)

Two independent defects in `src/apprt/win32/BannerOverlay.zig`, both visible
in the same screenshot:

1. **No paragraph wrap.** `renderContent` handles a `.text` block as

   ```zig
   .text => |segs| blk: {
       _ = self.drawInlineLine(hdc, x0, y, line_h, segs, 0, false, draw);
       break :blk line_h;
   },
   ```

   One `drawInlineLine`, height hard-coded to exactly `line_h`. There is no
   wrap and no measure-then-split. The overrun is then CLIPPED by the card's
   rounded region (`cardClipRegion`, selected in `paint`), so the text simply
   disappears at the card edge - it does not even ellipsize. The wrapping
   machinery already exists and is used one branch away: `renderTable` calls
   `markdown.wrapTokens` for body cells, with `maxCellWrapLines` +
   ellipsis-tail behavior (`banner_layout.zig`). Headings have the same
   one-line assumption and the same bug.

2. **Content width ignores the chevron.** `paint` computes
   `content_w = client.right - inner * 2` and `renderContent` draws the first
   line from `x0` across that whole width, while `paintChevron` paints the
   toggle afterwards at `chevronBox(client.right)` - the card's top-right
   corner, vertically centered on the FIRST content line. So the first line
   and the chevron are laid out over the same pixels; the chevron is painted
   last and lands on top of the text, which reads as the text pushing the
   chevron off.

## What to build

- Wrap `.text` (and `.heading`) blocks the way table cells already wrap, so a
  paragraph flows onto as many lines as it needs and the block reports its
  real height (the band already regrows on rewrap - T123 - so a taller block
  should just work). Reuse `markdown.wrapTokens`; do not write a second
  wrapper.
- Subtract the chevron's box from the width available to the FIRST line only
  (or to every line, if that measures simpler and looks right) whenever
  `self.collapsible` is true, so text never runs under the toggle. The
  chevron box is already a single definition (`chevronBox`) shared by paint
  and hit test - keep it that way.
- Respect the existing 10-line display cap and the collapsed-band behavior.

## Validation

- Unit tests in the pure geometry module (`banner_layout.zig`) for paragraph
  wrap: a line longer than the content width yields >1 wrapped line, the
  reported height is `n * line_h`, and the first line's usable width is
  reduced by the chevron box when collapsible. Assert at 1.0, 1.25, 1.5 and
  2.0 scaling per the design-system rule.
- Acceptance: set a banner with a long single-paragraph string on a narrow
  pane and confirm every word is visible and the chevron is clickable. The
  reported string is a good fixture: `/reset-context FAILED - the
  continuation text never appeared in the pane. Recover by hand: press
  ctrl+u, run /clear, then re-send the prompt. Log: <path>`.
- P1-P3 stay ALL PASS.
