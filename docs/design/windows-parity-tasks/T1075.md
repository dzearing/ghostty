# T1075 - Prove the ship workflow end to end: one feature through worktree, PR, review and merge

## Summary

T1058 built and tested the lifecycle - `scripts\ship-feature.ps1 new|list|pr|done`
- against a throwaway repo pair. Every refusal is asserted and every command
works, but no real feature has been through it: no PR has been opened on
`dzearing/ghoztty`, no CI has run on one, and no review (T1060) has gated one.

This task is that first real pass, deliberately on a small feature so the
subject of the exercise is the workflow and not the change.

## In plain terms

The new way of shipping has been rehearsed but never used for real. This is
doing it once, start to finish, on something small - so that the first time it
carries something important is not also the first time it runs.

## Goals

- [ ] One real feature developed in a worktree created by `ship-feature.ps1 new`
- [ ] A PR opened by `ship-feature.ps1 pr`, against `dzearing/ghoztty` - verified
      by reading the PR's repository back, not by the command exiting 0
- [ ] Fork CI (`.github/workflows/fork-ci.yml`) runs on it and is green
- [ ] The adversarial review (T1060) runs and its verdict is on the PR
- [ ] It merges, and `ship-feature.ps1 done` tears the worktree down cleanly

## Validation criteria

- [ ] The PR url recorded here, and its base repository confirmed as the fork
- [ ] CI status read from the PR checks, not inferred from a local run
- [ ] `ship-feature.ps1 list` shows the feature while it is open and drops it
      after `done`
- [ ] A written note in this file on anything the real pass caught that the
      sandbox harness did not - that gap is the whole value of the exercise
