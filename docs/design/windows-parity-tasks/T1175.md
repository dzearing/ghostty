# T1175 - One Windows installer, not two: retire the standalone agent MSI from the website, the relay download endpoint and install.ps1

## In plain terms

The download page offers two Windows downloads: Ghoztty, and a separate "Remote
Agent" installer. Pick the wrong one and you have installed half a product -
and it fails silently, with no window and no message, until something times out
minutes later. There is no reason for the second one: installing Ghoztty
already puts the agent on the machine. After this there is one download, and
remote machines are turned on inside Ghoztty with a switch instead of a second
install.

## Goals

- [x] Nothing on either landing page offers a second installer, a raw agent
      download, or an install one-liner.
- [x] The standalone MSI pipeline is deleted, not disabled.
- [x] The hosted one-liner URL keeps answering, as a signpost that says where
      Ghoztty is - an old pasted command must inform, not 404.
- [x] Remote agent support itself is untouched: the agent still ships inside
      Ghoztty and the machine chooser still shares the machine.
- [x] A harness holds the shape, and has been watched failing.

## Summary

The download page offered a Ghoztty MSI AND a separate Remote Agent MSI
(`/dl/ghoztty-agent.msi` plus an `irm | iex` one-liner), so a new user could
install half a product. `ghoztty-agent.exe` has been a required sibling of
`ghoztty.exe` inside the Ghoztty MSI since T89h, so the second installer added
nothing to a box that had Ghoztty and everything to a box that did not. One
installer is the only supported Windows install path.

Removed: the agent download card, the one-liner, the raw-exe link and the
cross-origin agent-version fetch from `relay/deploy/ghpages/` and
`relay/deploy/www/`; `relay/deploy/msi/` (wxs + build script); the MSI half of
`publish-agent.sh`.

**Three bullets of the original scope had no target, and one was inverted:**

- CI never built or published the standalone agent - `.github/workflows/` only
  embeds the agent into the *macOS bundle*, which stays.
- `dist/website/update-windows-links.py` only ever touched the Ghoztty MSI and
  the portable ZIP, so there was nothing to remove there.
- `install.ps1` and `publish-agent.sh` are **kept**, not retired. The hosted
  `/dl/install.ps1` must keep answering (Decision 5 of the consolidation note):
  an old pasted one-liner must inform rather than 404, so it is now a signpost
  that installs nothing. `publish-agent.sh` still ships `ghoztty-agent.exe` and
  `version.json`, which the `--relay` agent's self-updater reads; those retire
  with the updater in **T550**, which this change re-scoped to exactly that.

Design: `docs/design/one-installer-agent-consolidation.md`.
