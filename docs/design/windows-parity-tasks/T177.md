# T177 - Machine chooser: the detail action row is missing Activity (and Restore All)

## Summary

Found while building T176's `...` menu, by reading the Mac detail header the
menu lives in. Mac's action row (`MachineChooserView.detailHeader`,
`MachineChooserView.swift:456-494`) is:

```
[ New Window ]  [ Restore All ]?  [ Activity ]?  [ ... ]
```

- **New Window** - shipped (T175).
- **`...`** - shipped (T176).
- **Restore All** (`resumeAllAvailable`) - "Rebuild this machine's full window
  layout here". Belongs with cross-machine session browsing, i.e. **T146**;
  this task does NOT claim it, it just records that the row is short two
  buttons, not one.
- **Activity** (`onActivityMonitor(machine)`) - "Open Activity Monitor for
  \<machine\>". **Not filed anywhere before this task.** That is the gap.

So the Windows detail row is currently `New Window` + `...` where Mac has up to
four controls, and the layout in `chooser_layout.zig` only reserves slots for
the two that exist.

## Update 2026-07-31: the tracing question is ANSWERED, and the panel is T226

The "read the Mac side first" instruction below has been carried out, so do not
redo it:

- `onActivityMonitor` calls `RemoteActivityMonitor.presentDialing(machine:)`
  (`MachineChooserView.swift:1488-1492`), which dials a fresh connection and
  opens a **non-modal per-machine panel** -
  `RemoteActivityMonitor.swift` + `RemoteActivityMonitorView.swift`: CPU/memory
  trend gauges, a selectable process table (pid, name, CPU%, memory, command),
  a filter, Kill + New Process, and an in-panel machine switcher.
- It does **NOT** depend on cross-machine session browsing, so it does **not**
  fold into T146. It is process/metrics monitoring; T146 is sessions.
- Windows has none of it, so the panel is filed as its own task: **T226**.

**Order: T226 first, then this task.** This is the button that opens it, and
landing a button that opens nothing is not useful. The command palette entry is
the second entry point (T189 gave win32 one command list, so it is one row).

## Details

Scope this to the **Activity** button. The Mac tracing it asked for is done -
see the update above; the panel is T226 and this task wires the row to it.

`chooser_layout.layout` currently hardcodes `primary_btn` then `menu_btn` at a
fixed 8 DIP gap. Adding a third and fourth conditional button means the action
row wants to be laid out as a *run* (leading edge + gap, each button sized to
its own caption) rather than as named slots, so `menu_btn` stops being pinned
to `primary_btn.right`. That refactor is part of this task, and it is pure -
`chooser_layout` is fully unit-tested in the none lane.

## Resolution (2026-08-01)

Done as scoped: the row is a run, Activity is in it, and it opens a panel keyed
to the machine it names.

**The row is a run, not slots.** `Layout.primary_btn`/`Layout.menu_btn` are
gone; `Layout` now carries the BAND (`action_row`) plus the three numbers the
packing needs (`action_gap` 8, `action_btn_pad` 12, `action_min_btn_w` 96 - all
on the design system's 4 DIP scale, §1), and `chooser_layout.actionRow(l, comp,
text)` packs `[primary] [restore_all]? [activity]? [menu]?` left to right.
`Composition` names `restore_all` even though T146 has not built it: the point
of a run is that the row can grow by one without moving anything else, and a
name that is never set is how that stays true.

**The module stays text-free.** `ActionText` carries measured CAPTION widths
and the module adds the padding and the floor - T235's lesson, applied before
it could be re-learned: a width that comes from text metrics cannot be
re-derived by anyone who does not measure. `MachineChooser.measureCaption`
does the `DT_CALCRECT` with the dialog's own font.

**Composition follows the machine, so PLACEMENT has to as well.** Mac gates
Activity and the `...` menu on the same `if case .remote(let machine)`
(:474-491), so both are hidden on the Local row - and dropping Activity MOVES
the menu button beside it. `refreshDetail` therefore re-packs the row on every
selection change, not only on a DPI change. Tab order grew one stop
(`primary -> activity -> menu`) and the existing skip-hidden loop covers it.

**What Activity opens.** Mac dismisses the chooser and then opens the panel
(`finish(nil)` then `presentDialing`, :1488-1492). Windows does the same, and
here dismissing first is load-bearing rather than cosmetic: the chooser
DISABLES its owner window, so a panel opened over it would come up behind a
dead window. The device id and name are copied to the stack BEFORE the close -
`close` frees the arena the device list is parsed into.

**The one thing that is deliberately NOT here: the dial.** `ActivityMonitor`
had `Source.remote` as an id-only placeholder; it is now `Remote{id, name}`
(identity for the registry, display name for the title - exactly Mac's split,
so renaming a machine focuses the panel already open on it instead of opening a
second one), and the instance OWNS both strings, because the chooser that
passed them is already closing. `buildSnapshot` returns
`error.RemoteSourceNotConnected` for a remote source, so the panel reports
"Couldn't connect / The E2E-Box source is unreachable." **A remote panel must
never sample THIS machine and caption it with another machine's name** - that
is a lie the user has no way to catch. **T287** replaces that one branch with
the real dial.

Evidence, on the box:

- `chooser_layout` unit tests: composition, one gap, per-caption sizing, the
  overflow shrink, DPI, and the 4 DIP scale itself.
- `MachineChooser` unit tests: `compositionFor` (Activity and the menu appear
  together, remote rows only), the packed order, the widened Tab cycle.
- `test/win32/chooser-menu.ps1` **ALL PASS (55 assertions**, was 38): the Local
  row's action row is `New Window` alone; a remote row packs three, in order,
  square glyph button last, one gap, each sized to its own caption, whole run
  inside the pane; Activity opens a `GhozttyActivityMonitor` titled
  `Activity - E2E-Box`; the chooser dismissed itself first; a second press
  focuses the same panel (one window, the registry rule); and the panel refuses
  to sample the local machine (the log is the oracle - the empty state is
  painted text, not a control).
  Its `Get-MenuButton` had to change: "the first button right of New Window"
  is Activity now. It finds the SQUARE button in the row - shape, which the
  design system fixes, rather than a label that is a non-ASCII ellipsis.
- `test/win32/activity-monitor.ps1` ALL PASS (82); P1-P3 ALL PASS; both `zig
  build test` lanes, `zig build test-agent`, and the full win32 GUI link green.
