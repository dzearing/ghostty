# T365 - T56a: win32 remote-reconnect ladder POLICY module (pure FSM + backoff + poison breaker)

## Summary

Split out of T56 (WP-D1 remote reconnect on win32), 2026-08-02. The pure
DECISIONS of the per-window reconnect ladder, in a testable module with no
GUI and no sockets — the same shape as `agent_recovery.zig` is for local
in-place recovery.

## Details

Mac's ladder lives in `BaseTerminalController.swift` (~400 lines, `MARK:
Remote Reconnect (WP-D1)`), tangled with AppKit notifications, dispatch
queues, and the surface tree. Porting it wholesale into `Window.zig` (5.6k
lines already) would be a mega file and untestable off-box. So the policy
comes out first:

- The per-window state (`connected` / `reconnecting(attempt)` /
  `disconnected(self_healable)`), distinct from the transport
  `connection.LinkState.State`.
- The mapping transport-state -> window-state, including the two edges that
  are easy to get wrong: `degraded` is NOT a drop, and a self-healable
  `disconnected` must recover on a genuine link-up.
- The backoff schedule (Mac: 1, 2, 4, 8, 15s -> ~30s over 5 attempts) and
  what "budget exhausted" means.
- The poisoned-session circuit breaker: N consecutive swaps that die within
  the poison window means stop the fast ladder and go terminal, or the
  ladder loops dial/probe/swap/die forever.
- Generation-based cancellation semantics (a stale attempt must be a no-op).

*Validation:* unit tests in the `-Dapp-runtime=none` lane covering every
edge above, including the blip-heals and poison cases.

Follow-ons: T366 (driver), T367 (status affordance), T368 (acceptance).

## Evidence (done 2026-08-02)

`src/apprt/win32/remote_reconnect.zig`, 20 tests, registered in `src/apprt.zig`'s
test block alongside `agent_recovery.zig` — its only non-std import is the
shared-core `remote/connection.zig` link-state enum, so it builds and tests in
EVERY lane rather than only the win32 one.

What the module decides, and why each is a decision rather than a constant:

- `classify()` collapses the five-state transport FSM to `live`/`dropped`/
  `terminal`. `degraded` is LIVE: §5.1 returns it to `connected` on any
  authentic packet, so treating it as a drop would ladder on every busy moment.
  A compile-time `inline for` over `LinkState.State` fails the build if a new
  FSM state is ever added without being classified deliberately.
- `onLinkChange()` — a drop only starts a ladder from a live window (a window
  already reconnecting has one, and its generation owns the retries); a live
  link recovers a `reconnecting` window AND a self-healable `disconnected` one
  (its surfaces still ride that connection, so a thawed agent means the window
  works again) but NOT a terminal one; `dead` is terminal from every state.
- Schedule: 1/2/4/8/15s, asserted to total exactly 30s across 5 attempts.
  `immediate` skips only the FIRST wait — a click dials now, the retries behind
  it still pace themselves. Out-of-range attempts clamp rather than read past
  the schedule, so `backoffMs` can never become a second, disagreeing opinion
  about when the ladder ends.
- **Exhaustion is not terminal.** `onAttemptFailed` at the budget yields
  `self_healable = true` plus a background re-dial armed only when there IS a
  session to re-ATTACH. Terminal is reserved for verdicts retrying cannot
  change: session gone, evicted, signed out.
- `onProbeOutcome` — only a MANUAL reconnect may answer `session_gone` with a
  fresh shell. The automatic ladder goes terminal, because silently replacing a
  user's dead grid with an empty prompt is a surprise, not a recovery.
- `Breaker` — the observed poison shape (a stale session that probes ALIVE and
  then kills the link ~300ms after every ATTACH, looping every ~2.4s forever).
  Judged at most once per swap, so two drops for one completion cannot condemn
  a healthy session in a third of the evidence; a swap that outlives the 10s
  window clears the count; a saturating subtract keeps a non-monotonic clock
  from reading as a quick-death storm.
- `Generation` — cancellation cannot be a bool: two ladders can overlap and the
  older one must lose.

Two end-to-end passes are asserted as tests: drop -> attempt 1 unreachable ->
attempt 2 alive -> swap -> live, and drop -> five failures -> exhausted, still
self-healable, then recovered by a thawed agent with no click.

Floors: `zig build test -Dapp-runtime=none` exit 0, `-Dapp-runtime=win32`
exit 0, `zig build test-agent` exit 0, P1/P2/P3 ALL PASS. The new tests were
confirmed to actually RUN (not merely compile) by `-Dtest-filter`: "Breaker"
raises the count by exactly 5 over the unfiltered baseline, and the single
"Breaker: three swaps that die fast condemn the session" by exactly 1.
