# T1179 - Clean-machine proof: website -> one installer -> a working Ghoztty, verified end to end before anything else proceeds

## Summary

The acceptance gate for the install epic. On a machine with no prior Ghoztty, go to the published site, download the single Windows installer, run it, and get a working terminal with sessions and the agent alive - no second download, no script, no silent failure. Then publish a newer build and take the in-app update. This task is the user-verified checkpoint; the cutover to `main` does not start until it passes.

## This task BLOCKS on the user. The loop does not install.

User directive 2026-08-30: "block on me closing this Ghoztty and running the
latest msi". The loop prepares and then STOPS; the human performs the install
and confirms. The loop may not run the MSI on the user's behalf, because the
whole point of the gate is to exercise the path a real user walks.

The handoff has a constraint that is easy to miss and fatal to get wrong:
**the go-loop and the controller chat both run inside Ghoztty panes.** Closing
Ghoztty to run the installer kills the loop, the controller, the task
dashboard and the agent. So the handoff cannot be "ask and wait" - there is no
process left to wait. It must be a durable, resumable checkpoint.

### The protocol

1. **Prepare.** Publish the release the user will install. Confirm the website
   offers exactly one Windows installer (T1175) and the link resolves to the
   new version.
2. **Inventory and clean.** Run the T1188 cleanup screen. The user removes the
   temporary and dev installs; the screen re-audits and prints a clean verdict.
   Record that verdict in this task's progress log - it is the evidence that
   "no prior Ghoztty" was true, not assumed.
3. **Write the checkpoint before stopping.** The resume instructions, the
   download URL, the expected version and the checks to perform must be on
   DISK (not only in a pane's scrollback), because every pane is about to die.
   The go-loop stop switch is held so the watchdog does not revive a loop into
   a machine mid-install.
4. **Hand off and stop.** Tell the user plainly: close every Ghoztty window,
   run the downloaded MSI, and confirm. Then stop.
5. **The user installs.** Ghoztty launches itself on completion (T1176).
6. **Resume from the checkpoint.** The user restarts the loop; it reads the
   checkpoint, verifies the install (version, agent alive, sessions, PATH,
   the `ghoztty` CLI, no error dialog), then publishes a newer build and takes
   the in-app update (T1178) as the second half of the proof.

## Validation criteria

- [ ] The cleanup screen's clean verdict is recorded here, with the four known
      install locations each shown gone or deliberately kept.
- [ ] Exactly one Windows installer is offered on the published site.
- [ ] A fresh install from that installer produces a working terminal: window
      opens, agent alive, sessions work, `ghoztty` resolves on PATH.
- [ ] Ghoztty launched itself when the installer finished.
- [ ] No silent failure and no error dialog on first run.
- [ ] A subsequent published build is taken via the in-app update, with no
      script and no manual file copying.
- [ ] The user has confirmed each of the above; the loop did not self-certify.
