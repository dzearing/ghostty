# T1419 - The Activity panel names a direct-host machine two different ways depending on how it was opened

## Summary

Opened from a remote window's palette the panel titles itself 'Activity - 127.0.0.1'; switched to from its own carousel it titles itself '127.0.0.1:47913'. Same machine, same panel, two names - and sections A and B of test\win32\activity-monitor-remote.ps1 are RED on it.

- [ ] TODO: the observable checks that prove this is done, ticked with evidence of how each was validated.

## In plain terms

Open the Activity Monitor on a window that is running on another machine and
the panel is titled `Activity — 127.0.0.1`. Move its machine carousel to Local
and back, and the same panel — same machine, same connection — is now titled
`127.0.0.1:47913`. Two names for one box, a click apart. On a host running more
than one agent the shorter name cannot even tell them apart.

## Goals

- [ ] One name for a direct-host machine, whichever way the panel was opened.
- [ ] `test/win32/activity-monitor-remote.ps1` sections A and B green again.

## Evidence

Measured 2026-09-07 while validating T614, on `activity-monitor-remote.ps1`:

```
FAIL  A the panel is titled for the MACHINE (got 'Activity — 127.0.0.1')
      state: source=127.0.0.1 total=359 shown=1 root=18728
FAIL  B the sample is attributed to the remote source
...
PASS  G2 the panel switched BACK to the machine (source=127.0.0.1:47913)
```

Where it came from: before **T610** (`f0fa80620`, 2026-09-07) the palette path
opened the panel with `.remote = .{ .id = id }` and no `name`, so `Source.label`
fell back to the id — `host:port`. T610 moved the entry onto the window and
added `.name = self.machineDisplayName()`, and `RemoteMachine.displayName`
(T1390) answers the bare host for a `.tcp` machine, deliberately: the close
confirmation wants the box the user typed, not a port. The carousel path still
labels by the id, so the two entries now disagree.

## The shape of the fix

Decide which of the two names an Activity panel should carry for a direct-host
machine, then make BOTH entry points produce it — the point is one derivation,
not a second special case:

- keep `displayName` as it is for the pill and the close confirmation, and give
  the panel the identity string (`host:port`) from both entries; or
- give the carousel the display name too, and accept that two agents on one host
  are named identically in the panel.

Either way the harness's A/B expectation is the contract to restate, and
`remote-pill.ps1` names the pill's own label — check it does not move.
