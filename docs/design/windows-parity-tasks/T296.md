# T296 - T287b: Activity Monitor in-panel machine carousel - switch source without a second window

## Summary

Second half of the split of **T287** (2026-08-01). Once the panel is open it
must move to any other source in one click - Local first, then every
registered machine - dialing and freeing owned connections, WITHOUT opening a
second window. The registry governs only the INITIAL open
(`RemoteActivityMonitor.swift:18-20`).

Mac: `RemoteActivityMonitorModel.switchTo` (`RemoteActivityMonitorView.swift:307`)
plus the card carousel at :788-860 and `MachineCard` at :1400.

## Why this is its own task, not a paint pass

The geometry is already done (**T284**: `activity_layout.cardRect`,
`cardIndexAt`, `carouselContentWidth`, and a `has_carousel` band the panel
currently passes `false` for). What is NOT done is everything that feeds it:

- **The machine list.** The panel has none. `MachineChooser` gets its devices
  from `relay_directory.listDevices`, a synchronous authenticated HTTPS GET it
  can afford because it is a modal dialog with a spinner. A non-modal panel
  cannot block its own message loop on it, so the fetch has to move off the
  GUI thread.
- **Per-card summaries.** Mac's cards carry a status dot, uptime, and a tiny
  cpu/mem readout for EVERY machine, live - fed by `MachineMetricsProbe`,
  which dials every registered machine and subscribes each one's metrics
  stream (`RemoteActivityMonitorView.swift:153-155, 227-262`). **win32 has no
  equivalent at all** (verified: no probe in `src/apprt/win32/`; the chooser
  rows carry no metrics either). That subsystem is the bulk of this task.
- **`switchTo`.** Tear down the current source (unsubscribe, free iff owned,
  race-safe against an in-flight snapshot RPC), reset every published field so
  one machine's trend history can never bleed into another's
  (`RemoteActivityMonitorView.swift:312-323`), then begin the new one.

## Keyboard

Left/right move a FOCUS RING; Return/Space commits. Arrowing must never dial -
a carousel that dials on focus would open a connection per keystroke.

## What landed (2026-08-01)

The carousel, the machine list and the switch. **Live per-card metrics for
INACTIVE machines did not land and are `T298`** - see "The scope call" below;
this is a named deferral, not a silent one.

### The pieces

- **`activity_cards.zig`** (new, pure, none-lane tested): the card model. Card
  ordering, `indexOf` (identity is the id, not the label - a rename cannot split
  a machine across two cards), `moveFocus` (clamped, never wrapped),
  `hasCarousel`, `scrollToShow`/`clampScroll`, and the three lines of card text
  plus the status dot. 13 tests.
- **`activity_layout.cardContent`** (new): one card's interior - dot + three text
  rows - with the text block **centered vertically**, so the padding above and
  below is symmetric by construction rather than by two constants somebody has
  to keep equal (§0.3). Asserted at 1.0/1.25/1.5/2.0 that nothing touches
  anything and that the dot rides the label's optical center.
  `activity_layout.cardMargin` hoists the inset that both PLACES card 0 and ENDS
  the scroll extent, so the two cannot drift.
- **The machine list, off the GUI thread.** `relay_directory.listDevices` is a
  synchronous authenticated HTTPS GET; the chooser can afford it on the GUI
  thread because it is a modal dialog with a spinner, and a non-modal panel
  cannot. It runs on a detached thread and lands as `WM_APP_ACTIVITY_MACHINES`
  on the **app's** message-only window - the same reasoning as the T295 dial,
  because `DestroyWindow` discards a window's queued messages. Devices are
  copied BY VALUE into fixed buffers (`MachineEntry`) before the parse arena
  dies.
- **`switchToCard` / `teardownSource` / `resetForNewSource`.**

### The three decisions worth keeping

1. **The ACTIVE source always has a card**, even when the directory does not
   list it - a borrowed connection, a signed-out account, a failed fetch, or a
   machine deleted while the panel sat open. A carousel that cannot show you
   where you are is lying, and (with Local always at index 0) it also guarantees
   there is always a way home.
2. **A stale sample is dropped by GENERATION, not by joining.** `source_gen` is
   bumped on every switch and the worker tags its result with the generation it
   began under. Joining instead would freeze the GUI for up to `rpc_timeout_ns`
   (5 s) on a BORROWED connection - which cannot be `shutdown` to cut the wait
   short, because it is a live window's shell. Adopting instead would paint one
   machine's processes under another's name.
3. **The switch BUMPS `serial`.** That routes an in-flight dial for the
   abandoned source onto `onDialed`'s panel-is-gone path, where it frees the
   connection it just opened - reusing T295's existing mechanism instead of
   inventing a second one. The registry is also re-keyed
   (`open_keys[slot] = new source`), and a switch to a machine ANOTHER panel is
   already showing focuses that panel instead, because two panels keyed alike
   would leave one of them unreachable by `open` forever.

### The scope call

Mac's inactive cards are fed by `MachineMetricsProbe`, which dials **every**
registered machine and holds a metrics subscription on each for the panel's
lifetime. That is a connection-budget design (N dials, N threads, N teardown
paths, on a window the user may leave open for hours), not a paint pass, so it
is **T298**. What shipped instead is honest rather than decorative:
`activity_cards.State` has a fourth state, `.idle`, meaning "we have not dialed
this machine", and an inactive card reports the relay directory's own `online`
flag - `online` / `offline` - and prints no CPU or memory number it does not
have. The gap is missing information, not wrong information.

**The script can fail.** The first run of section E was red - 5 FAILURE(s) -
because `Send-TestMouse` takes SCREEN coordinates (it `SetCursorPos`es before
posting) while the carousel's logged rects are CLIENT coordinates. The clicks
landed nowhere, and E1/E2 said so while E3 (which asserts a NON-event) stayed
green. That is a live demonstration that these assertions are not vacuous, and
it is also the lesson below.

## Lessons

- **The oracle is the painter's own arithmetic.** The panel logs
  `carousel cards=N focus=i active=j scroll=x rects=l,t,r,b;...`, and the script
  clicks the rect the PAINTER reported. A script that re-derived card geometry
  would be asserting a layout against itself - the T257 lesson, applied before
  it could bite.
- **`Send-TestMouse` is SCREEN coordinates.** `Get-TestWindowRect -Client`
  returns the client rect already in screen space, so its origin is the whole
  conversion. Getting this wrong produces a run that looks like a product
  failure and is not.
- **A one-source panel could not have tested any of this** - the same shape as
  T235's "a one-title window cannot test a width rule". The carousel needs a
  second source to exist at all, which is why the acceptance lives in
  `activity-monitor-remote.ps1` (where a loopback agent supplies one) rather
  than in the local script the task originally named.
