## Summary

**The session chooser is functionally a stub next to the Mac's — 4 Mac commits, ZERO references.** `040c6a959` (master–detail redesign: live sessions, Kill, richer labels), `c066f8681` (cross-machine session BROWSE in the Cmd-Shift-N chooser), `236a217ca` (resume a single browsed session on the local machine), `43bfb8e4a` (agent-owned layout blobs + cross-machine "Resume all"), plus `e5da5d02b` (reap dead tombstones so only connectable sessions are listed). ## Update 2026-08-01 (from T177): the action row already has a slot for Restore All

T177 turned the detail header's action row into a packed RUN, and named the
button this task owns while it was there: `chooser_layout.Composition` has a
`restore_all` flag that is never set, and `MachineChooser.layoutActions`
already skips it because no HWND exists yet. So this task's UI half is: create
the button, and set that flag when `resumeAllAvailable` is true. Nothing has
to move — the run re-packs, which is the reason it is a run.

Mac's order is `[New Window] [Restore All] [Activity] [...]`
(`MachineChooserView.swift:456-494`), which is the order `actionRow` packs in.

## SPLIT 2026-08-01 into T318 -> T319/T320 -> T321

This task is four of Mac's commits behind one title, and go.md's context rule
says a task that will not fit one context gets split before it is started, not
after. The evidence that it will not:

- Four upstream commits, each a distinct capability, plus a fifth
  (`e5da5d02b`, tombstone reaping) that is a rule inside the first.
- The Windows chooser has **zero** of it. `MachineChooser.zig` is 108 KB and
  matches `session` exactly four times - all four the string *"Session
  expired - sign in again above."* in relay error mapping (`:728`, `:1567`,
  `:1577`, `:1579`).
- Mac's supporting code is ~19.5 KB (`SessionBrowserProbe.swift`) + ~30 KB
  (`SessionLayoutManifest.swift`) + ~38 KB (`SessionLayoutRestore.swift`).
- Precedent on this exact surface: T226 split into four, T227 into three,
  T203 into three. This is the same size class.

The good news, and the reason the children are UI tasks rather than systems
tasks: **the data plane is already cross-platform Zig and already reachable
from win32.** `Connection.requestSessions` (`connection.zig:1598`),
`requestLayouts` (`:1693`), `closeSession` (`:2114`); `App.zig:1263` already
calls the first one against the local agent's warm shared connection. Mac
reaches the same functions through the C API in `embedded.zig:2802/:2913` -
win32 calls them directly.
