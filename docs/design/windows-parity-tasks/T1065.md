# T1065 - Windows downloads are a release behind again, and win-v1.34.0 is the first one that would carry a working command line

## Summary

`Ghoztty v1.34.0` was published 2026-08-21T14:08Z with no matching
`win-v1.34.0`, so `check-release-parity.ps1` is red on every push
(`GAP: newest macOS release v1.34.0 has no matching win-v1.34.0 release`,
newest Windows release `win-v1.33.0`, 1 behind). This is the recurrence T579's
checker exists to make loud and T895 last worked off.

## In plain terms

The download page is offering last week's Windows build. That matters more than
usual this time: the fix that gives a downloaded install a working `ghoztty`
command line landed today, and nobody gets it until a Windows release is cut.

## Details

Cutting it is a tag push on this branch (`win-v1.34.0`), which
`release-windows.yml` picks up and turns into the MSI + portable ZIP; the
process is T577/T895's and is documented in that workflow. The publish is an
outward-facing act, so it wants a human's go-ahead rather than a loop turn
doing it unattended.

Two things to confirm on the resulting artifacts, because this is the first
release built after T1052:

- Both assets exist at the same version as the macOS `v1.34.0` release.
- The published ZIP contains `Ghoztty/ghoztty.com`, and the MSI's File table
  lists `ghoztty.com` with a version. The second is the check that has never
  been made on a real MSI from this box (T1063) - a published artifact is one
  place it can be made without Docker.

Every red `release-parity` job on this branch until then is this task, not a
regression from whatever commit the run happened to land on.

## Goals

- [x] `win-v1.34.0` is published with both artifacts
- [x] `check-release-parity.ps1` is green again
- [x] The published artifacts are read back and shown to carry the console twin
