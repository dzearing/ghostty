# T1406 - printclient-audit does not defend the paint probe's one load-bearing asymmetry: nothing stops a WM_PRINTCLIENT handler from counting a paint

## In plain terms

A test added in T1405 can finally tell whether the app redraws the screen by
itself when your accent colour changes. The whole thing works because the app
counts a redraw only when it draws for ITSELF, never when the test takes a
photograph. That distinction lives in two hand-written lines and nothing
guards it: whoever adds the counter to the photograph path next year turns the
test back into one that cannot fail, and nothing will say so.

## Summary

`src/apprt/win32/paint_probe.zig` is counted from `WM_PAINT` and deliberately
NOT from `WM_PRINTCLIENT`. That asymmetry IS section G's oracle in
`test/win32/chrome-theme.ps1` - a paint the camera asked for must not read as
the app repainting itself. Add it to a `WM_PRINTCLIENT` handler and every G
assertion goes permanently green, which is exactly the failure mode T1405 was
filed to end (T585's measurement, restated one layer up).

`test/win32/printclient-audit.ps1` already walks every `WM_PRINTCLIENT` handler
in the win32 frontend, so the check belongs there and costs one assertion: no
`WM_PRINTCLIENT` arm may reach `paint_probe.record`. Per T1133 it ships with
its own good/bad fixture pair, the way `chrome-theme.ps1`'s F3 analyzer does.

Worth deciding while implementing: whether the same audit should assert the
POSITIVE half too - that each declared `paint_probe.Surface` is recorded from a
`WM_PAINT` arm somewhere - so a probe that quietly stops counting is caught by
something other than a red G1/G2 nobody is looking at.

## Where

- `test/win32/printclient-audit.ps1` - the audit and its fixtures.
- `src/apprt/win32/paint_probe.zig` - the module comment states the rule the
  audit would enforce.
- `src/apprt/win32/Window.zig`, `src/apprt/win32/ViewerTOCPanel.zig` - the two
  call sites today.

## Validation criteria

- [ ] `printclient-audit.ps1` fails on a fixture whose `WM_PRINTCLIENT` arm
      calls `paint_probe.record`, and passes on the real tree - the bad
      fixture RUN, not asserted.
- [ ] The audit names `paint_probe.zig` in its guard-due coverage row, so an
      edit to the probe re-arms it.
- [ ] `printclient-audit.ps1` ALL PASS on the tree as it stands.
