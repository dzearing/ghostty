# T1102 - Image chips never appear in the feedback composer, taking four viewer-feedback scripts red

## In plain terms

When you send feedback from a viewer pane you can attach screenshots, and each one should show up in the message box as a little '[Image #1]' tag. Right now no tag ever appears, the pictures do not reach the saved report, and deleting them misbehaves. Four separate automated checks all fail on it, which means attaching a picture to feedback is effectively broken.

## Summary

Four scripts in the T1094 full sweep fail on the same mechanism - the composer's image chip. Filed as one task because the failing assertion is literally the same string in three of them.

`viewer-feedback-capture.ps1` - `6 FAILURE(S) (57 passed)`:

```
FAIL  the composer shows an '[Image #1]' chip (holds '')
FAIL  the folder holds images/image-1.png
FAIL  report.json carries the one captured image (got 0)
FAIL  ...at the size that was dragged (x, want 160x120)
FAIL  the body links the screenshot as a markdown image reference
FAIL  the keyboard capture attaches a chip (composer holds '')
```

`viewer-feedback-images.ps1` - `6 FAILURE(S) (19 passed)`:

```
FAIL  the composer shows an '[Image #1]' chip (holds '')
FAIL  ...and only IT is live -- the deleted one left the report (2)
FAIL  ...and two images are now live (3)
FAIL  the folder holds images/image-2.png
```

`viewer-feedback-carousel.ps1` - `6 FAILURE(S) (32 passed)`:

```
FAIL  the composer holds both chips (holds '')
FAIL  the strip dropped to one tile with the chip (got '2')
FAIL  the survivor is image #2 -- numbers are stable, never renumbered to #1
FAIL  ...and the band is exactly as tall as it was before any picture (175 vs 95)
```

`viewer-feedback-utf16.ps1` - `4 FAILURE(S) (25 passed)`:

```
FAIL  the chip lands EXACTLY at the caret, with no doubled space
      (got 'eee <emoji> YZ', want 'eee [Image #1] <emoji> YZ')
FAIL  one Backspace removes the WHOLE chip after non-ASCII text
```

The composer text is EMPTY where a chip is expected in every case, and the picture never reaches `images/` or `report.json`. That points at insertion, not at rendering or at the UTF-16 caret arithmetic the fourth script is actually about - utf16's caret assertions are almost certainly collateral, and should go green on their own once a chip is inserted at all.

Note the healthy assertion counts (57, 32, 25, 19 passing): the feedback flow as a whole works. It is the image attachment that does not.
