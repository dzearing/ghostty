# T1174 - go-loop-guard J4/J5 flake under load: a busy pane must emit output inside a 2s window for the no-nudge arm to hold

## Summary

Seen 2026-08-24 while validating T1173. Section J's last two arms send a for/l echo loop into a real GUI pane, sleep 2 seconds, then run the watchdog with -ProbeGapSeconds 3 and assert it decides ACTION none because the pane is still producing output. On a loaded box - several harness runs and background builds in flight - the pane had not produced enough output inside that window and both arms failed; an immediate re-run with nothing else running was ALL PASS (251). So the arms are timing-sensitive rather than wrong, and the flake costs a full harness re-run each time it lands, which on this suite is minutes. Fix by making the arm wait for evidence instead of assuming it: poll +read until the busy output actually appears (the same shape J3 already uses to wait for the resume prompt) before running the watchdog, and fail with a SKIP rather than a FAIL if the pane never gets going, so a slow box reports 'not measured' instead of 'broken'.
