# T369 - FLAKE: terminal.search.screen 'simple search with history' aborted with a recursive panic in the win32 lane

## Summary

`zig build test -Dapp-runtime=win32` failed once during T60's floor run
(2026-08-02) in a test that has nothing to do with the change under test, and
passed on an immediate re-run with no edits in between.

## Details

Observed output:

```
aborting due to recursive panic
error: while executing test 'terminal.search.screen.test.simple search with history',
the following command exited with code 5 (expected exited with code 0)
Build Summary: 48/50 steps succeeded; 1 failed; 3659/3696 tests passed; 37 skipped
```

The same lane had passed earlier in the same session and passed again
immediately afterwards (exit 0), so this is intermittent rather than a
regression from the T60 change (which touches only
`src/apprt/win32/title_spinner.zig` and the two title paint sites in
`Window.zig` — nothing reachable from `terminal.search`).

"aborting due to recursive panic" is a panic raised while another panic was
already unwinding, so the reported test name may be the victim rather than the
cause: the real failure's message was swallowed. That is the first thing to
recover — a lane that can eat its own diagnostic is worse than the flake.

This is the same class as T136 (`zig build test-agent` flaked once on
`remote.agent.server.test "RESIZE ..."`), and the two should probably be
investigated together: both are intermittent aborts in a test lane rather than
in shipped code.

## Validation

Reproduce by running the win32 lane in a loop (say 20 iterations) and capturing
the full log of any failing run — the recursive-panic text plus whatever
preceded it. A run that cannot reproduce it in 20 tries should say so and raise
the count rather than close the task on one clean pass.
