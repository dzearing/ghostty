# T316 - Signed-out account row shows a sentence Mac does not: decide the parity delta and record it

## Summary

`docs/design/win32-machine-chooser.md` §2.4 records Mac's signed-out account
row as **"a plain bordered 'Sign In with Google' button"** — the button alone.
The win32 row also carries a "Not signed in" sentence to its left, and while
signing in a "Finish signing in in your browser…" one. T311 recomposed the row
around Mac's signed-IN block (email over a link, monogram beside them) and left
the sentence where it was, because removing it is a product decision and not
part of finding 5 or 6.

It is a real delta and it is not written down anywhere as intentional, which is
the actual problem: an undocumented divergence reads as an oversight to the next
person, and the next polish pass will either delete it or keep it by accident.

## Details

The case FOR keeping it: "Not signed in" is a state, and Windows dialogs
generally label state rather than leaving the user to infer it from a button's
caption. The busy sentence in particular carries information Mac carries too
(Mac shows a spinner + "Waiting for browser sign-in…", §2.4) — so the busy state
is arguably already parity and only the signed-out one is extra.

The case AGAINST: "Sign in with Google…" already says you are signed out, so the
sentence is the same fact twice, and it is the only text on the surface that
exists in no Mac state.

Whichever way it goes, §2.4 (or §3.1's "take from Mac" list) must say so with
the reason, the way the 32-vs-34 avatar and the flat-vs-gradient monogram fill
are recorded in T311.

## In plain terms

Open the machine chooser before you have signed in and the top of the dialog
tells you the same thing three times: a button offering to sign you in with
Google, a "Not signed in" label sitting next to it, and a line under the empty
machine list saying "Not signed in — use Sign in with Google above to list your
machines." The Mac version says it once, with the button. After this, so does
Windows: the label goes, the button and the fuller sentence under the list stay.
Nobody loses information; the row just stops repeating itself.

## Goals

- [x] Decide whether the signed-out sentence stays or goes, and why
- [x] Record the ruling in `win32-machine-chooser.md` with its reason
- [x] Make the code match the ruling in every account state
- [x] Turn the acceptance script's assertions around to match

## The ruling (2026-08-20)

**The sentence goes.** The signed-out row is the bordered button alone, which
is Mac's composition (§2.4). The state is still named twice without it — by the
button's own caption and by the footer hint under the empty list, which carries
the remedy the band's one line has no room for. The Windows convention of
labelling state is real and is what kept the sentence through T311; it is
satisfied here by the hint, which is this surface's designated state line.

The other three states KEEP their sentence, because Mac has one in each: the
email signed in, "Finish signing in in your browser…" against Mac's "Waiting
for browser sign-in…", and the setup pointer an unconfigured build shows in
place of a button it could not honour (T747). That last one is why this is a
rule about the *button*, not about the band: with no button drawn, a silent
band would be a dead end.

Not filed as a decision for the user: go.md 5b's experience test asks whether
the Mac→Windows translation is genuinely ambiguous, and it is not — Mac's
answer is explicit in §2.4 and win32 already has somewhere else to put the
state. "Look just like the Mac experience" is standing policy.
