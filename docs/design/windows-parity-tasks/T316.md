# T316 - Signed-out account row shows a sentence Mac does not: decide the parity delta and record it

## Summary

`docs/design/win32-machine-chooser.md` §2.4 records Mac's signed-out account
row as **"a plain bordered 'Sign In with Google' button"** — the button alone.
The win32 row also carries a "Not signed in" sentence to its left, and while
signing in a "Finish signing in in your browser…" one. T311 recomposed the row
around Mac's signed-IN block (email over a link, monogram beside them) and left
the sentence where it was, because removing it is a product decision and not
part of finding 5 or 6.

It is a real delta and it is not written down anywhere as intentional, which is
the actual problem: an undocumented divergence reads as an oversight to the next
person, and the next polish pass will either delete it or keep it by accident.

## Details

The case FOR keeping it: "Not signed in" is a state, and Windows dialogs
generally label state rather than leaving the user to infer it from a button's
caption. The busy sentence in particular carries information Mac carries too
(Mac shows a spinner + "Waiting for browser sign-in…", §2.4) — so the busy state
is arguably already parity and only the signed-out one is extra.

The case AGAINST: "Sign in with Google…" already says you are signed out, so the
sentence is the same fact twice, and it is the only text on the surface that
exists in no Mac state.

Whichever way it goes, §2.4 (or §3.1's "take from Mac" list) must say so with
the reason, the way the 32-vs-34 avatar and the flat-vs-gradient monogram fill
are recorded in T311.

## Validation

- The decision lands in `win32-machine-chooser.md`, not only in a task file.
- If the sentence goes: `test/win32/relay-account.ps1` asserts on it today
  (`signed-out status says 'Not signed in'`, `status back to 'Not signed in'`),
  so those become assertions about its ABSENCE, and the busy sentence keeps its
  own.
