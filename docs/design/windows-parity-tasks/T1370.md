# T1370 - The composer discriminator misses an unsent slash command

## In plain terms

The watchdog has a rule that says "if there is text typed but not sent, and no
work has finished, the loop is stuck - poke it sooner." The rule is right. It
just looks in the wrong place, so it did not notice a stalled loop with `/rc`
waiting to be sent.

## What happened (2026-09-05)

An API transport error truncated turn 136 at 15:45 ("The response stopped
arriving. The response above may be incomplete."), leaving `/rc` unsent. The
health line called it DOWN at `turn_age=1h 07m`. The watchdog logged, every
five minutes:

```
healthy: ... age=30.84m(by=transcript) turn_age=65.5m(limit=180m)
```

`limit=180m` is the tell. `-TurnSuspectMinutes` is **45**, deliberately equal to
the health line's threshold - so if the composer had been read as non-empty the
watchdog would have nudged at 45 minutes, and the two would have agreed. It used
the 180-minute bar instead, which means the discriminator saw an *empty*
composer.

## Why it missed

The unsent text is not in the composer box. Reading the pane at the time:

```
──────────────────────────────────────────────>            <- composer box, empty
──────── ctx: 168k/1000k (17%) | files: 3 changed ...  /rc  <- the unsent text
```

`/rc` is rendered at the right-hand end of the **status line**, as a
pending-command indicator, while the composer box above it is drawn empty. A
check that reads the composer box therefore correctly reports "nothing typed" -
the text is one line down and at the other end of the row.

Note this is the *second* stall with exactly this signature (2026-09-04 was the
first, and is what prompted T1319), so it is the common shape rather than an
oddity: an interrupted turn leaves a slash command pending, and pending slash
commands live on the status line.

## What to do

- **Look where the text actually is.** Detect a pending command on the status
  line as well as text in the composer box. Both mean the same thing - input
  typed and not sent.
- **Assert it against a real capture.** The reason this shipped broken is that
  the detection was never tested against a pane in this exact state. A fixture
  built from the 2026-09-05 capture (or a live pane with `/rc` pending) is what
  turns the rule from plausible to proven.
- **Log what it saw.** The watchdog line already names its clock and limit,
  which is how this was diagnosed in one read. Add whether it considered the
  composer non-empty, so a future miss is visible in the log rather than only
  in the limit it chose.

## Validation criteria

- [ ] A pane with a pending slash command and no turn progress is nudged at
      `-TurnSuspectMinutes`, not at `-TurnStaleMinutes`.
- [ ] The exact 2026-09-05 pane shape is a fixture, and the check is
      demonstrated red against it before the fix.
- [ ] A genuinely long, working turn is still not nudged - the 180m bar must
      keep protecting a slow build.
- [ ] The watchdog log states whether it saw pending input, so the next miss is
      readable.
