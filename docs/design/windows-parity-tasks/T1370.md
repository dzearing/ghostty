# T1370 - The composer discriminator misses an unsent slash command

## In plain terms

The watchdog has a rule that says "if there is text typed but not sent, and no
work has finished, the loop is stuck - poke it sooner." The rule is right. It
just looks in the wrong place, so it did not notice a stalled loop with `/rc`
waiting to be sent.

## What happened (2026-09-05)

An API transport error truncated turn 136 at 15:45 ("The response stopped
arriving. The response above may be incomplete."), leaving `/rc` unsent. The
health line called it DOWN at `turn_age=1h 07m`. The watchdog logged, every
five minutes:

```
healthy: ... age=30.84m(by=transcript) turn_age=65.5m(limit=180m)
```

`limit=180m` is the tell. `-TurnSuspectMinutes` is **45**, deliberately equal to
the health line's threshold - so if the composer had been read as non-empty the
watchdog would have nudged at 45 minutes, and the two would have agreed. It used
the 180-minute bar instead, which means the discriminator saw an *empty*
composer.

## Why it missed (corrected 2026-09-05 while working it)

The composer arm was RIGHT and the pane really was empty. Reading the pane at
the time:

```
──────────────────────────────────────────────>            <- composer box, empty
──────── ctx: 168k/1000k (17%) | files: 3 changed ...  /rc  <- the unsent text
```

The card read that right-hand `/rc` as the unsent text. It is not. It is Claude
Code's **last-slash-command indicator**, and it sits on every pane all the time:
measured on two live panes at once on 2026-09-05, `/rc` on this loop's own pane
*while it was demonstrably mid-turn*, and `/rc failed` on the other window.
`go-loop-guard.ps1` BB3d already refuses it as pending text for exactly that
reason, and doing what this card originally asked would have nudged every
working session that ran past 45 minutes.

What actually happened is simpler and worse: the API transport error ended the
turn before anything was typed, so there was no unsent text to find. The
composer arm cannot see this shape at all.

## What to do

- **Ask whether Claude is WORKING, not whether text is waiting.** A Claude Code
  TUI with a request in flight renders a spinner carrying the elapsed time
  directly above the composer; an idle one renders nothing there. Idle, plus a
  turn clock that has not moved, is a stalled turn whatever the composer holds.
- **Three answers, never two.** A pane with no recognisable composer reads as
  `unknown`, which is NOT idle - idle is the answer that types into somebody's
  session.
- **Assert it against a real capture.** Fixtures for both shapes, built from
  panes measured on this box.
- **Log what it saw.** `composer=` and `session=` on every decision line, so the
  next miss is readable in the log rather than only in the limit it chose.

## Validation criteria

- [x] An idle session with no turn progress is stalled at `-TurnSuspectMinutes`,
      not at `-TurnStaleMinutes` - `go-loop-guard.ps1` BB30/BB31.
- [x] The exact 2026-09-05 pane shape is a fixture (BB24), and the check was
      demonstrated red against it before the fix: the run before the third arm
      landed reported `FAIL BB30`, `FAIL BB31` and `Get-PaneWorkingState is not
      recognized`.
- [x] A genuinely long, working turn is still not nudged - BB32, plus a live
      check: `Read-PaneState` against this loop's own pane mid-turn, through the
      watchdog's own exe default, answered `working`.
- [x] The status line's `/rc` is still not read as pending input (BB3d) and its
      pane's composer still reads empty (BB25) - the fix does not re-introduce
      the false positive this card asked for.
- [x] The watchdog log states what it saw: `composer=none session=unknown` on the
      healthy line and on the STALLED line - BB22b.
