# T1239 - The pty-holder acceptance scripts still open Ghoztty windows on the user's desktop (T1193 batch 2 of 4)

## Summary

T1193 measured the gap and built the sweep; this batch is 5 of the pty holder
scripts it left declared as pending. Each one starts the app from a process
sitting on the user's desktop - a bare `Start-Process $Exe`, or a cold
`& $Exe +new-window`, which is the one verb that auto-launches - so running it
throws a window across whatever the user is reading.

The migration is mechanical and T1193's `ipc-p1.ps1` / `ipc-p2.ps1` /
`ipc-p3.ps1` are the worked examples:

1. `. (Join-Path $PSScriptRoot 'lib\TestDesktop.ps1')` and `$td = New-TestDesktop`
   before the body; `Remove-TestDesktop` in the teardown.
2. Replace every `Start-Process $Exe` with `Start-OnTestDesktop`.
3. Replace every `& $Exe <verb>` with a local one-line `Ghoz` helper over
   `Invoke-OnTestDesktop`, and read `$r.ExitCode` where the script read
   `$LASTEXITCODE`. The helper captures stdout and stderr to a file, so a
   `cmd /c "... > file"` dance for the GUI-subsystem exe (T245) goes away too.
4. DELETE the script's `# @user-desktop-launch:` line from `lib\TestDesktop.ps1`.
   A migration that leaves it behind fails `desktop-launch-audit.ps1` as a
   stale declaration - that is what makes the list burn down.

Scripts in this batch:

- `test\win32\holder-adopt.ps1`
- `test\win32\holder-durable.ps1`
- `test\win32\holder-soak.ps1`
- `test\win32\holder-volume.ps1`
- `test\win32\pty-holder.ps1`


## In plain terms

Running the terminal's own test suite used to throw terminal windows across
whatever you were reading: five of the tests that exercise persistent sessions
started the app on your desktop. They now start it on a background desktop you
never see, so a test run is invisible while it happens - and they still check
exactly what they checked before.
