# T425 - The dead session's recorded command and cwd never reach the fresh shell: no 'Previous command' line and the pane opens in the wrong directory

## Summary

**User report, 2026-08-03**: *"I expected 'Previous prompt:' to be preserved
and the last known CWD to be restored in the shell."*

Both symptoms, one suspected root cause, which is why they are one task: the
notify path reads **both** values off the same tombstone, at
`src/termio/Remote.zig:568-572`:

```zig
notice_command = if (outcome.argv) |v| aa.dupe(u8, v) catch null else null;
const cwd: ?[]const u8 = if (outcome.cwd) |c| ... else self.working_directory;
```

The code is already written to do what the user expects — the notice names the
command when there is one (`session_notice.format`, "previous command:") and
the fresh shell is placed in the dead session's recorded directory. CLAUDE.md
documents exactly that. The user's screenshot shows the notice with **no
previous-command line at all**, and reports the shell came up in the wrong
directory. So the likely failure is upstream of this file: `outcome.argv` and
`outcome.cwd` are both null.

**Split this task the moment the two stop sharing a cause.** They are filed
together only because one `outcome` feeds both; if argv is present and cwd is
not (or vice versa) they are separate bugs and deserve separate files.

## Where to look

- `src/remote/agent/server.zig:757` already comments on a case where cwd was
  *"never written to `sessions.json`"* — start there.
- `server.zig:3395`, `test "RELAUNCH respawns in the RECORDED cwd, not the
  agent's (T132)"`, proves the RELAUNCH verb honors a recorded cwd. **Notify is
  not relaunch** — it opens a brand-new session — so that test passing tells us
  nothing about this path, and the gap between them may be the bug.
- Whether the agent that served this upgrade was an OLDER build than the app
  (the standing agent-contract hazard): an agent too old to report argv/cwd
  degrades to null here, which would be correct-by-design rather than a bug,
  and would change the fix to "make the app say so" instead.

## Read T421's log evidence first

The 2026-08-03 upgrade log records `pre-kill agent sessions: 0` and
`SESSIONS-SURVIVE SKIP: no agent sessions before the kill`. A null argv and a
null cwd are the *expected* output of a restore with nothing persisted behind
it — so this may not be a bug in `Remote.zig` at all, but the downstream
symptom of an agent that held no sessions. Establish which before touching the
notice path; **T422** carries the same caveat and the same contradiction (the
notice only fires for a tombstone, so something was there).

## On the wording

The user wrote *"Previous prompt:"*; the code writes `previous command:`. Treat
that as the user naming the field loosely rather than a rename request — but
the label is user-visible text on the same surface **T424** is rewording, so
settle it there in one pass rather than twice.

## Validation

`test\win32\session-relaunch-notify.ps1` extended: a pane whose session had a
known command and a known non-default cwd, put through an agent restart, must
come back with the command named in the notice and the shell's `cd`/`pwd`
reporting that same directory.
