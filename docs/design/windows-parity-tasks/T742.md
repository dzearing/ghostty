# T742 - Positioning the palette or search bar resizes the terminal grid to the popup's size

## In plain terms

Every time you open the command palette or the find bar, the terminal
underneath is told it just became the size of that little popup, and reflows to
match. The next real resize puts it back, so what you see is a flicker or a
scrambled line rather than a lasting wrong size — but the text you were reading
moved for no reason.

## Summary

`App.surfaceWndProc` serves three windows — the terminal child HWND, the
search-bar popup and the command-palette popup — because all three store the
same `*Surface` in their `GWLP_USERDATA`. T613 fixed the `WM_DESTROY` arm of
that confusion (a popup's destroy cleared `Surface.hwnd`, which crashed the
process). The rest of the switch is still unrouted:

- `WM_SIZE` calls `surface.handleResize(w, h)` with **the popup's** dimensions.
  `positionCommandPalette` and `positionSearchBar` both call
  `MoveWindow(popup, …, 1)`, which sends `WM_SIZE` — so this fires on every
  palette open and on every window move while the search bar is up.
- `WM_ENTERSIZEMOVE`/`WM_EXITSIZEMOVE` set `surface.in_live_resize` for a popup
  the user is not resizing.
- `WM_DPICHANGED` runs `surface.handleDpiChange()` off the popup's DPI.
- The key/char arms (`WM_KEYDOWN`, `WM_CHAR`, …) route to the terminal from a
  popup window; the popups normally give keyboard focus to their child EDIT, so
  this may be unreachable in practice — establish that rather than assume it.

## Where

- `src/apprt/win32/App.zig` — `surfaceWndProc`, the `switch (msg)` arms.
- `src/apprt/win32/surface_window_role.zig` — T613's pure role classifier; the
  `role` is already computed at the top of the procedure, so each arm can
  simply ask.
- `src/apprt/win32/Surface.zig` — `positionCommandPalette` (~2367),
  `positionSearchBar` (~2120), the two `MoveWindow` calls.

## Validation criteria

- [ ] Opening the palette does not resize the terminal grid: the pane's
      reported rows/cols are unchanged across a palette open/close.
- [ ] Same for the search bar, including while the window is moved with the bar
      up.
- [ ] Each remaining arm of `surfaceWndProc` either routes by role or carries a
      comment saying why it is correct for all three windows.
- [ ] Pure assertions extend `surface_window_role.zig` where a new routing rule
      is added; `zig build test -Dapp-runtime=none` and `-Dapp-runtime=win32`
      green, plus P1-P3.
