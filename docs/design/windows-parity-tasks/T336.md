# T336 - T146d-3: cross-machine Restore All over the relay (per-window transport ownership)

Third child of the **T321 split (2026-08-02)**, and the one that closes T146.
Mac commit `43bfb8e4a`.

## Summary

T335 restores a machine's whole topology from the LOCAL agent's blobs. This is
the same thing pointed at a REMOTE machine over the relay - and it is separated
because of one structural difference that has no Mac analog:

**Mac hands every rebuilt window ONE `RemoteConnection`
(`SessionLayoutRestore.swift:659-675`, `presentResumedTopology(connection:)`).
win32 windows each OWN their transport** - `openDialedWindow` stores
`window.remote_dialed = dialed` (`App.zig:2202`) and `openRemoteWindowFrom`
re-dials the same machine for a new window from a remote one (T68). So
restoring N windows from a relay machine is N dials, or a deliberate decision to
share one - and whichever it is, the ownership/free rule has to be stated and
tested, not inherited by accident. T295's dial-off-thread + ownership discipline
is the pattern to reuse.

Everything else is T335's machinery pointed at a dialed connection: the same
`requestLayouts` decode, the same `requestSessions` attach set, the same
`App.restoreWindow`. The double-attach guard does NOT apply (the entry ids
belong to the other machine - Mac says so at
`SessionLayoutRestore.swift:696-698`), and frames should be re-clamped onto a
visible LOCAL monitor (Mac's `reanchor`), since a frame authored on a
4K portrait monitor can otherwise restore off-screen here.

Also owns:

- The relay token resolution + "not signed in" messaging the T320 remote resume
  already shapes (`MachineChooser.resumeRow`'s `.remote` arm).
- Retiring the "local-only" caveat T335 puts in CLAUDE.md, in the commit that
  makes the cross-machine statement true.
