# T569 - Shift+Tab through the Activity Monitor panel is untested on the box

## Summary

handleKey's backwards Tab walk reads GetKeyState(VK_SHIFT), and Shift+Tab is the ONE-step route from the filter field to the machine carousel (forward Tab takes four). Nothing on the box asserts it. The harness posts WM_KEYDOWN and fakes modifier state with SetKeyboardState, which is exactly the mechanism this repo has already recorded as unreliable for GetKeyState reads across processes - so the backwards half of the cycle may be broken in the product, broken in the harness, or fine, and today no evidence distinguishes those. Establish which, then either assert the walk in test/win32/activity-monitor.ps1 section L or record the mechanism limit the way TestDesktop.ps1 records its others.

## In plain terms

Shift+Tab is how you walk a panel's controls backwards, and in the Activity
Monitor it is the short way from the search box to the process table - one key
instead of four. Nothing on the box had ever checked that it works, and the
test rig's way of holding Shift down was already known to be unreliable, so
"does Shift+Tab work here" had no answer at all. It does work, and now a test
says so - and says which half is broken when it stops.

## Goals

- [x] settle whether the harness can deliver Shift to a panel's child control
- [x] settle whether the panel's backwards Tab walk is correct
- [x] leave either an assertion or a recorded mechanism limit behind

## Validation criteria

- [x] The backwards walk is asserted on the box: section L2b of
      `test/win32/activity-monitor.ps1` walks the whole ring backwards -
      filter -> table (over the absent carousel) -> "New Process..." -> "Show
      all" (over the hidden Kill) -> filter - and all four steps PASS in a full
      green run (`ACTIVITY MONITOR ACCEPTANCE: ALL PASS`).
- [x] The mechanism question is answered by measurement, not assumption: the
      same four steps re-run through `Send-TestControlKey -Modifiers shift`
      land on the FORWARD neighbour ("focus landed on Show all - the Shift
      never reached the app"), so the attachment in `Send-TestKeys` is what
      carries the modifier. Recorded in `Send-TestControlKey`'s doc comment in
      `test/win32/lib/TestDesktop.ps1`.
- [x] A future failure is self-diagnosing: each step names its forward
      neighbour, so a red line distinguishes "the harness lost the modifier"
      from "the walk is wrong".
