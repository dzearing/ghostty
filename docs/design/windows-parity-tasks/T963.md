# T963 - verdict-exit-audit.ps1 is red at HEAD: release-parity.ps1 exits 0 on its failure path and tab-tooltip.ps1 falls off the end

## Summary

Two harnesses can PRINT failure and EXIT 0, which is the exact defect T221 closed: release-parity.ps1 L194 (exits-zero) and tab-tooltip.ps1 L346 (fallthrough). A suite driver or a guard reading the exit code sees green over a red run. Found by T883 running the meta-audits; neither file is in T883's diff.

## In plain terms

We have a self-check that reads every test script in the suite and answers one
question: if this script says it failed, does it actually REPORT failure to
whoever ran it? A script that prints "2 FAILURES" and then quietly hands back a
success code is how a broken build gets waved through. That self-check was
itself failing, so nobody could trust its answer.

It turned out the script it was accusing was innocent. The self-check was
reading the wrong `if` — the one that picks the wording of the success line
rather than the one that decides success from failure — and would have gone
silent over the real defect in a script shaped that way. The reader is fixed,
and the self-check now leaves a stamp, so the loop notices the day it goes red
instead of a human noticing weeks later.
