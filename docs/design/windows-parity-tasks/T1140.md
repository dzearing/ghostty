# T1140 - The reboot shape is copied per script, so the next test that needs one kills too little and scores the app broken

## In plain terms

Several tests pretend the machine restarted so they can check what your
terminal sessions look like on the way back. Pretending correctly means
stopping everything a restart would stop, and each of those tests works that
out for itself. Two of them have got it wrong so far, and each time the result
was a report that a working feature was broken.

## Summary

Since T909 a session's ConPTY, shell and kill-on-close job live in a separate
`--pty-host` holder process that deliberately outlives the session manager, so
"kill the agent" stopped being a reboot. Two harnesses have paid for that:

- `session-relaunch-notify.ps1` — every notice arm scored FAIL against a correct
  build on 2026-08-18; the restored panes had re-attached to LIVE sessions and
  there was nothing to notify about. It grew a private `Stop-AgentAndHolders`.
- `agent-autostart.ps1` (T1108) — section B's `B6 ...as a DEAD tombstone` was
  red from the T1094 sweep, filed as a P1 user-facing defect, and the app was
  fine: the surviving holder was re-adopted exactly as designed. It grew its own
  copy of the same kill plus a survivor count.

So the shape now exists twice, written independently, with the same comment
explaining the same lesson beside each. That is the pattern T1107 fixed one
level up by extracting `test\win32\lib\ChooserCursor.ps1`: a walk every script
re-derived, wrong in two of them.

The fix is one shared helper — a `Stop-RebootShape` beside `Stop-RepoGhoztty`
in `test\win32\lib\CleanSlate.ps1` that kills the app, the manager and every
repo-path holder, and RETURNS the survivor count so the caller can assert
nothing is left. Both existing copies go through it. The helper is the place
the "a reboot takes the holders too" reasoning lives, so the next script needing
a reboot gets it right by reaching for the obvious name.

Worth deciding while there: whether the helper should also assert
non-vacuousness (that at least one holder was there to kill), which is what
tells a green run apart from one where holders were switched off by an inherited
`GHOZTTY_AGENT_PTY_HOLDER=0`.

## Where

- `test\win32\lib\CleanSlate.ps1` — where `Stop-RepoGhoztty` already lives
- `test\win32\session-relaunch-notify.ps1` — `Stop-AgentAndHolders`
- `test\win32\agent-autostart.ps1` — section B's inline copy (T1108)

## Goals

- [ ] the shared lib in the covering guards' `Covers`, so an edit to it makes them due

## Validation criteria
