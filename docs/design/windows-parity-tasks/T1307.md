# T1307 - No guard-due row covers the client side of the remote protocol (connection.zig / protocol.zig)

## In plain terms

Every acceptance script here records which source files it has been run
against, so the loop can tell you when a script is stale. The client half of
the remote-machine protocol is not on any of those lists — so you can rewrite
the code that decides how a remote machine's answers reach the app and nothing
will say "the end-to-end test has not seen this". That is the same file whose
one missing line made every remote session-close look like a hang.

## Summary

`scripts/guard-due.ps1` has no `Covers` entry for `src/remote/connection.zig`
or `src/remote/protocol.zig` (verified 2026-09-03 while closing T403: the whole
T403 diff touched only those two files, and `guard-due.ps1 check` afterwards
reported nothing newly due — only the three pre-existing advisory rows). The
agent-side files are covered in several rows — `agent-relay-session`,
`remote-reconnect-relay`, `ipc-relay` — but the client side of the same wire is
not, even though those e2e scripts drive it on every run.

## Fix direction

Add both files to the `Covers` set of the row(s) whose script actually
exercises them end to end — `agent-relay-session` (OPEN/ATTACH/close over a real
link) is the natural home, and `remote-reconnect-relay` covers the reconnect
path through the same client. Then run the named harness once so the stamp is
real rather than assumed.

## Validation criteria

- [ ] `src/remote/connection.zig` and `src/remote/protocol.zig` appear in at least one `Covers` set
- [ ] Touching either file makes `guard-due.ps1 check` report that harness DUE (constructed and observed, not assumed)
- [ ] The named harness runs green on box and stamps
- [ ] `test/win32/go-loop-guard.ps1` still ALL PASS
