# T1018 - Nothing obliges test\win32\chrome-theme.ps1 to be run when the color math it measures changes

## Summary

The chrome color harness has no guard-due row, so a chrome_theme.zig / color_math.zig edit can ship without anyone running the script that measures the colors it moves - the T783 staleness gap, one harness later.

## In plain terms

There is a test that photographs the app's window chrome and checks the colors
are the ones the code says they should be. Nothing makes anyone run it. Change
the code that decides those colors and the test just sits there, still green
from a week ago, and a wrong color can ship looking measured.

## Details

Found while doing T309. `scripts\guard-due.ps1` is the "has anybody run harness
X against the code as it now stands?" gate, and its coverage table has no row
for `test\win32\chrome-theme.ps1`. T309 edited `chrome_theme.zig`,
`DarkMode.zig`, `Window.zig` and `App.zig`; the only guard that went DUE was
`printclient-audit`, which watches all 189 win32 sources and is not about color
at all.

The row wants to be NARROW, per the warning already in `guard-due.ps1` (~line
629) that a gate firing on every chrome edit is the noise T783 warns about. The
files that actually move what `chrome-theme.ps1` measures:

- `src/apprt/win32/chrome_theme.zig` (the palette and, since T309, the
  light/dark decision)
- `src/apprt/win32/color_math.zig` (the wash, the contrast floors)
- `src/apprt/win32/panel_theme.zig` and `system_colors.zig` (the panel palette
  and the live accent/theme reads the harness's B oracle exercises)
- the harness itself

Worth checking the same question for the other color/paint harnesses while in
here (`pane-banner`, `hover-capture` etc. already have rows; confirm their file
lists still name the modules they measure).

## Validation criteria

- [ ] `guard-due.ps1 check` reports `chrome-theme` DUE after a touch of
      `chrome_theme.zig`, and CURRENT again after a clean green run of the
      harness re-stamps it
- [ ] A touch of an unrelated win32 file does NOT make `chrome-theme` due
      (the row is narrow, not another all-of-`src/apprt/win32` watch)
- [ ] `test\win32\guard-due.ps1` (or whichever harness covers the gate's own
      table) stays green
