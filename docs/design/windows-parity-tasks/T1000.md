# T1000 - The floor wrapper can die mid-lane with no verdict and still exit 0

## Summary

Observed 2026-08-19 during T973's floor run: the win32 lane aborted with 'Cannot bind argument to parameter Tree because it is null', no PASS/FAIL/STALL for that lane, no FLOOR SUMMARY, and the process still exited 0 - so a caller reading the exit code sees success for a floor that never finished. Root cause is a PowerShell unroll: Get-ProcessTree (scripts\floor-lane.ps1:183) returns an ArrayList, and an EMPTY one unrolls to nothing, so the poll loop's $tree is $null whenever the CIM snapshot comes back empty (a transient Get-CimInstance miss, or the root exiting between the HasExited check and the query). Get-SelfSpawnedTestPids then refuses $null: its parameter is [Mandatory][AllowEmptyCollection()], which permits @() but not $null. Fix the return (comma-wrap or force an array at the call site), let the sweep accept null, and make the wrapper's own failure end in a verdict rather than an abort - a wrapper that exists so a wedge cannot look like a slow run must not be able to look like a pass.
