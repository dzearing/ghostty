# T161 - Viewer page zoom + pane-scoped chords (ctrl+r reload, ctrl+d/ctrl+l address bar)

## Summary

Filed 2026-07-29 by the T127 re-scope. Two Mac viewer capabilities with no
T90b-T90h row: browser-style page zoom (Cmd +/-/0 plus pinch) and PANE-SCOPED
chords -- Cmd+R and Cmd+D mean something different while a viewer holds
keyboard focus and their global meanings are untouched everywhere else. The
override STRUCTURE ports as-is; the chords do not, because the Windows defaults
differ. Mapping pinned in `docs/design/viewer-panes-windows.md` P6/P7.

## Details

Mac sites: `ViewerView.PaneChord` (`:2110`), `handle(_:)` (`:2139`),
`paneHoldsFocus`, `ZoomAction` (`:2190`), `zoomFactor`, `pushZoomToWebView`,
`handleZoom`, `isViewerContentFocused`, `allowsMagnification = true`,
`focusAddressBar`.

Windows mapping (while a VIEWER pane holds focus; terminal panes keep every
global meaning, which is the invariant to test):

| Chord | In a viewer | Globally (unchanged) |
|---|---|---|
| ctrl+r | reload the pane | belongs to the shell |
| ctrl+d | focus the address bar | split right |
| ctrl+l, alt+d | focus the address bar | clear-screen / n/a |
| ctrl+plus/minus/0 | page zoom | font size |

Rationale on the record: `ctrl+r` is free precisely because a viewer pane has
no shell, so the reason the banner editor had to take `ctrl+shift+b`
(`src/config/Config.zig:7012-7019`) does not apply, and every Windows browser
already means reload by it. `ctrl+d` mirrors Mac's Cmd+D relationship exactly
(globally split-right, `Config.zig:6992-6996`); `ctrl+l` / `alt+d` are added
as Windows-native aliases because `ctrl+d`-for-address-bar is Mac muscle
memory.

Scope:

- `put_ZoomFactor` on the controller for keyboard zoom; copy Mac's step and
  clamp values exactly so the two clients zoom identically. Pinch / ctrl+wheel
  is Chromium's own -- no code, but assert it does not ALSO change font size.
- `add_AcceleratorKeyPressed` (T90a section 11) checks the pane-scoped table
  first, then the app keybind table, then lets the page have the key. Handler
  stays non-blocking (the browser process waits synchronously on it).
- Focus rule: the chords are live only while keyboard focus is inside the
  viewer pane -- its page or its nav bar (Mac also counts its feedback
  composer, which Windows v1 does not have; see T164).

*Validation:* `viewer-panes.ps1` grown, with POSITIVE CONTROLS mandatory
(T157's lesson: a keybind script that cannot prove it delivered the chord
proves nothing). ctrl+r with a viewer focused reloads; with a terminal focused
it reaches the shell. ctrl+d with a viewer focused puts the caret in the
address field; with a terminal focused it splits right. ctrl+plus with a viewer
focused zooms the page and leaves the terminal font size alone, and vice versa.
Zoom clamp is unit-tested in both lanes.
