# T294 - Hoist the chooser control locators: three scripts each keep a private copy of 'find the management button'

## Summary

**T257's finding, in a different subsystem.** Four acceptance scripts drive the
machine chooser, and each one re-implements how to FIND its controls:

- `test/win32/chooser-menu.ps1` - `Get-Controls` + `Get-MenuButton`
- `test/win32/host-settings.ps1` - its own `Get-Controls` + `Get-MenuButton`
- `test/win32/relay-account.ps1` - `Get-ChooserControls` + `Get-AccountButton`
- `test/win32/ipc-machine-chooser.ps1` - inline button lookups

T177 added an **Activity** button to the detail pane's action row and broke two
of them at once, in the quietest possible way: both `Get-MenuButton` copies
were "the first button to the right of New Window", which is Activity now, so
`host-settings.ps1` would have CLICKED Activity - opening an Activity Monitor
panel - while asserting about a management menu. `relay-account.ps1` identified
the account button by *excluding* the labels it is not (`New Window`, `Open`,
`Cancel`), an exclusion list that grows silently and had just gained a fourth
member.

Both were repaired in T177 against something the design system fixes rather
than against a label (the menu button is the SQUARE button in the action row;
the account button is the TOPMOST button in the dialog), so the scripts are
green. What is NOT fixed is the shape of the problem: the next control added to
that row gets the same three chances to be wrong.

## Details

Do for the chooser what `test/win32/lib/ChromeGeometry.ps1` did for chrome
geometry (T257): one module, dot-sourced from `TestDesktop.ps1` (which every
script already loads), owning the chooser's control vocabulary -

- `Get-ChooserControls`, one implementation (the three today differ in which
  fields they project: Left/Right/Bottom, Visible, Enabled - the union is
  cheap).
- `Get-ChooserActionRow` (the packed run, left to right), `Get-ChooserMenuButton`
  (the square one), `Get-ChooserActivityButton`, `Get-ChooserPrimaryButton`,
  `Get-ChooserAccountButton`, `Get-ChooserCancelButton`.
- The split T257 named: what is DERIVED from the layout rule (positions, the
  gap, the square) versus what must be MEASURED off the live window (button
  widths, which come from text metrics and cannot be re-derived - T235).

Then delete the private copies. Four scripts, mechanical, and the win is that
the NEXT change to the action row (T146's Restore All) touches one file.

## Validation

- `chooser-menu.ps1`, `host-settings.ps1`, `relay-account.ps1` and
  `ipc-machine-chooser.ps1` all still ALL PASS with no private locator left in
  any of them (`grep -n "New Window" test/win32/*.ps1` should only match
  assertions ABOUT the label, not lookups keyed on it).
- Each script's negative control still goes red.
