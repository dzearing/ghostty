# T782 - Sweep scripts/ and test/win32 for ghoztty CLI calls that put non-literal text on PowerShell's argv (the T279 hazard), as a checked audit

## In plain terms

A previous fix taught our scripts the right way to hand text to the terminal's
command line, and repaired the places that were doing it wrong. Nothing stops
the next script from doing it wrong again — and when it does, the symptom is
text that silently arrives with pieces missing. This adds the check that
notices.

## Summary

T279 established the rule (build the command line yourself; see
`scripts\lib\NativeArgv.ps1` and the CLAUDE.md block) and converted the sites
it enumerated by hand: the loop's relaunch in `upgrade-ghoztty-windows.ps1`
and `watchdog-ghoztty-windows.ps1`, and the `Ghoz` / `Invoke-Ghoztty` helpers
in `go-loop-exec.ps1` and `go-loop-watchdog.ps1`. A hand enumeration is a
snapshot; the four sibling audits in this suite (`ExitCodeAudit`, `SkipAudit`,
`VerdictExitAudit`, `AssertedNothingAudit`, `ForegroundAudit`) exist because a
snapshot is exactly what stops holding.

The hard part is not finding native ghoztty invocations — it is telling a
HAZARDOUS argument from a safe one without producing a wall of noise. Most
interpolations here are pane ids, GUIDs, `$PID`-derived names and repo paths,
none of which can carry a `"` or end in `\`. Shape of a workable rule, to be
settled by the task:

- flag a `& $exe`/`Start-Process`/`cmd /c` ghoztty call whose argument
  interpolates a variable AND whose flag is one of the free-text carriers
  (`--title=`, `--command=`, `--working-directory=`, a `+set-banner` /
  `+send-keys` positional), rather than every interpolation;
- exempt via the stated-intent marker convention the other audits use
  (`# argv-audit: <reason>`), for a site whose text is provably an id;
- `-TeethCheck` plants a real violator in the swept directory, as
  `verdict-exit-audit.ps1` and `foreground-audit.ps1` do.

The AST is the right reader (see `VerdictExitAudit.ps1`'s reasoning): the
question "is this string interpolated" is structural, and a line-oriented
matcher cannot tell `"--title=$label"` from a comment mentioning `--title=`.

## Validation criteria

- [ ] An analyzer under `test\win32\lib\` reports the hazardous shape and
      nothing else across `test\win32\` and `scripts\`, at zero.
- [ ] Its acceptance script passes and its `-TeethCheck` catches a planted
      violator.
- [ ] The sites T279 already converted are NOT reported, and the naive shape
      section D of `cli-argv-fidelity.ps1` uses IS (it is a deliberate control,
      so it carries the exemption marker).
