# T1123 - A script violates the skip-visibility rule without being a named exception

## In plain terms

There is a rule that a check which quietly skips something must say so out loud, so a skipped check can never look like a passing one. One of the checks breaks that rule and is not on the list of known exceptions.

## Summary

`test\win32\skip-visibility.ps1` scored `1 FAILURE(S)` in the T1094 sweep:

```
FAIL  B1 no script violates the rule without being a named exception
```

This is a meta-audit over the whole suite, which makes it more important than its one-line failure suggests: the rule it enforces is what stops a silently-skipped assertion from reading as a pass. While it is red, the suite's own honesty guarantee is not being enforced.

The script must be re-run to name the violator - the sweep log records the verdict but not the offending script.

## Where

- `test/win32/skip-visibility.ps1` section B

## Goals

- [ ] Run it and get the name of the violating script.
- [ ] Fix that script to declare its skip visibly - do NOT simply add it to the exception list, which would defeat the rule.
- [ ] Add it to the exceptions only if there is a real reason, recorded here.

## Validation criteria

- [ ] the violating script is named here
- [ ] it declares its skip visibly, or its exception is justified in writing
- [ ] `test\win32\skip-visibility.ps1` is ALL PASS
