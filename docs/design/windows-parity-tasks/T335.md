# T335 - T146d-2: Restore All button, the >=2-alive rule, and LOCAL rebuild from the agent's blobs

Second child of the **T321 split (2026-08-02)**. Mac commit `43bfb8e4a`.

## Summary

The user-visible half, for the LOCAL machine only (the relay half is T336):

1. **The button.** `chooser_layout.Composition.restore_all` already exists and
   is never set (`chooser_layout.zig:484`), and `layoutActions` already skips it
   because no HWND exists (`MachineChooser.zig:1077`). T177 built the action row
   as a packed RUN precisely so this could appear without moving anything, so
   the UI half is: create the button, set the flag, hide/show it in
   `refreshDetail` beside the other two (`MachineChooser.zig:1434-1443`), and
   give it a place in the Tab/focus order. Mac's order is
   `[New Window] [Restore All] [Activity] [...]`
   (`MachineChooserView.swift:456-494`) - the order `actionRow` already packs.
2. **The availability rule.** Mac offers Restore All only when the highlighted
   expanded row has **>= 2 ALIVE sessions**
   (`MachineChooserView.swift:145-155`), and the reason is written down: one
   pane is already covered by per-session resume, and there is no topology to
   rebuild. Port the rule *and* the reason - a Restore All that lights up on a
   single session is a button that does nothing a simpler button already did.
   Note the predicate is `alive`, not `isConnectable`: the same distinction T320
   drew for `isResumable`.
3. **The rebuild.** Pull the blobs (T334), probe the roster with
   `requestSessions`, and hand each decoded window to the EXISTING
   `App.restoreWindow(win, conn, attach)` (`App.zig:1379`) - the same rebuild
   launch-time restore uses, which is the point: a Restore All is a
   restore-from-the-agent's-copy rather than from the local file. Mac states the
   same property (`SessionLayoutRestore.swift:586-588`): sourcing from the AGENT
   is what makes it work with an empty local manifest.
   Skip a window already bound to an open local window (Mac's double-attach
   guard, `SessionLayoutRestore.swift:695-699`).

## What landed

- **`chooser_sessions.restoreAllAvailable(alive)`** + `aliveCount`, with Mac's
  reason for the number carried over, and `SessionRoster.aliveCount()` counting
  off the same rows `visible` renders (an optimistically-killed session is gone
  from both, so the button cannot outlive the rows that justify it).
- **The button** in `MachineChooser.zig`: created hidden, packed by the existing
  `actionRow` run, in the Tab order between New Window and Activity, reachable by
  keyboard and mouse. `compositionFor` gained the `alive` argument and the
  `r == .local` clause that T336 deletes.
- **`refreshSessions` now re-applies the action composition**, not just the
  repaint. This is load-bearing: the roster arrives ASYNCHRONOUSLY, so a
  composition computed only on selection change is computed before the data it
  derives from exists, and the button would never appear at all.
- **`App.restoreAllLocalSessions`** - GET_LAYOUTS, decode, probe, and replay each
  window through the SAME `restoreWindow` launch-time restore uses. The liveness
  probe both paths take is now one `AttachProbe` struct rather than two copies.
- **The double-attach guard** (`windowIsOpenLocally` / `paneForSession`): the
  agent rebinds a session to the newest ATTACH, so rebuilding a window whose
  panes are already on screen would steal them out of the window that has them.
- Fixed in passing: the chooser's Tab ladder never recognised `activity_btn`, so
  focus on Activity read as `.filter` and Tab from it jumped back to the list.
  Nothing caught it because no test had ever walked past the first Tab stop (see
  the harness note below).
- CLAUDE.md's "cross-machine session move is scoped but not yet built" paragraph
  is replaced with what is actually shipped, and says plainly that Restore All is
  local-only on Windows until T336.

## Three things it turned up

1. **`Send-TestKeys` SetFocus()es its `-Target` before posting**, so a Tab walk
   aimed at the filter walks the SAME first step every time and focus never
   leaves the list - measured, not guessed (a probe printed the focused HWND
   after each Tab: `filter, list, list, list, list`). Each Tab has to be re-aimed
   at whatever now holds focus. This is why the missing `activity` ladder entry
   above survived: no test had ever taken a second Tab.
2. **A Restore All that lit up would still be untested without the HIDDEN
   assertion.** `Find-TestWindowEx` sees hidden windows, so the script asserts the
   control EXISTS and is not visible - a probe that could only see visible windows
   would report "no button" for a defect and for correct behavior alike.
3. **The blob key is not stable across app runs, so the crash case eats the
   previous run's first window** - `window-N` is allocated from a per-process
   counter. Filed as **T338** with a direct before/after reading of the agent's
   store; this script names its fixture window to work around it, which the fix
   should delete.
