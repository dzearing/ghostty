# T758 - A banner's dot-relative autolinks keep the cwd they were parsed with; Mac re-resolves on render

## In plain terms

A banner can carry a path written relative to the pane's folder (`.\out\
build.log`). Ghoztty turns that into a real path when the banner text is
set. If you then `cd` somewhere else, the link still points where it pointed
when the banner was written — even though the same text, re-read now, would
mean somewhere else. On a Mac it follows the `cd`. Nobody has reported this;
it is the loose end T539 left.

## Summary

T539 gave `banner_markdown` an autolink pass whose `PathContext` (`cwd`,
`home`) is supplied by `BannerOverlay.setText` and baked into the link
target at PARSE time. Mac's parser takes `cwd` on every render pass
(`SurfacePaneBanner`, `parseInline(_:cwd:)`), so a pane that `cd`s re-resolves
the same banner text against the new directory — CLAUDE.md's Autolinking
section says exactly that ("resolve against the pane's current working
directory **at render time**").

Absolute paths, UNC paths and URLs are unaffected — they need no context at
all. This only touches `.\`, `..\` and `~\` forms, and `~` does not move.

## Where

- `src/apprt/win32/BannerOverlay.zig` — `setText` is the only place the
  context is read; the blocks are cached in the overlay's arena until the
  text changes.
- `src/apprt/win32/banner_markdown.zig` — `PathContext`, `autolink`.
- The cheap shape is to re-parse when the pane's cwd changes (the `.pwd`
  action already lands in `Surface.setPwd`), not to re-parse on every paint:
  the overlay repaints far more often than the cwd moves, and parsing on the
  paint path is what the cached blocks exist to avoid.

## Validation criteria

- [ ] A banner set to `.\a.txt` in one directory, then a `cd` in that pane,
      resolves to the NEW directory (on-box: the ctrl+click viewer `url`, the
      T539 oracle in `test\win32\pane-banner.ps1`)
- [ ] A banner with no relative link does not re-parse on a cwd change (no
      new work on a path nothing asked for)
- [ ] Absolute/UNC/URL links are byte-identical before and after a cwd change
