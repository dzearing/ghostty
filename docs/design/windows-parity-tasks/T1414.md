# T1414 - A Float on Top asked for while no window has focus can be refused outright

## Summary

Measured 2026-09-07 under T607. win32.setTopmost retries a band change three times (overlay_zorder.band_change_attempts) but all three run back to back with no message pump between them, so when there is no foreground window at all - a background desktop, a locked session, a disconnected RDP session - a whole burst can be refused and the action silently does nothing; a press moments later lands. On an ordinary interactive desktop this never fires, which is why float-on-top.ps1 is green and the acceptance harness works around it by pressing again (overlay-zorder.ps1 Set-Float). The product-side hardening would be to yield between attempts rather than spin, so a float asked for from a script or a keybind in a locked session still takes. P3: no user has hit it, and the state it needs is one no interactive user is in.
