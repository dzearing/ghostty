# T363 - tab-strip.ps1 hardcodes the chrome bar's R range (10..40): a private absolute restatement of a derived color

## Summary

`tab-strip.ps1:340` asserts

```powershell
Assert ($px.R -ge 10 -and $px.R -le 40) "strip: dead space right of the tab is bar background, not tab or accent (R=$($px.R))"
```

The claim is *"this pixel is bar background, not a tab and not an accent"* —
a claim about which SURFACE the pixel belongs to. What it actually checks is
that the bar's red channel is a dark grey, which is only true because the
script's `--background` happens to be black and `chrome_theme.bar_wash` happens
to be 0.08. It is the color-domain twin of the geometry duplication T257 spent
a task deleting: a datum the app DERIVES, restated privately as a literal.

## Details

**How it surfaced (T43).** With the debug chrome marker live the bar is amber,
so `R = 102` and the assertion went red on a build that was painting exactly
what it was told to. T43 shipped with the marker disabled for the acceptance
harness (`GHOZTTY_DEBUG_MARKER=0` in `test/win32/lib/TestDesktop.ps1`), so the
literal survives — but it will fail again for any change that legitimately
moves the bar: a different `--background` in this script, a `bar_wash` tune, a
`window-theme` case, or anyone who runs the suite with the marker on.

The failure mode is worse than a false red. The range 10..40 also *passes* for
colors that are not the bar at all — any dark tab fill lands in it — so the
assertion is weak in the direction it claims to be strong.

**The fix.** Score the claim the way `Get-TestTabExtents` already scores the
same question: sample the bar somewhere that can belong to no tab and no
button, and assert this pixel EQUALS that one. That is exact, needs no
constant, and cannot be satisfied by a coincidentally-dark tab.
`chrome-theme.ps1`'s `Get-Wash` shows the derived alternative if an absolute
value is ever really wanted.

Audit the rest of the GUI scripts for the same shape while here — a literal RGB
or channel range standing in for a color the app derives. Absolute constants
are legitimate where the app itself spells one (`tab-color.ps1`'s
`(255,69,58)`, an accent the user picked); they are not where the app computes
one.

*Validation:* `tab-strip.ps1` ALL PASS, and ALL PASS again with
`GHOZTTY_DEBUG_MARKER=1` (which is what proves the assertion stopped depending
on the bar being dark grey).
