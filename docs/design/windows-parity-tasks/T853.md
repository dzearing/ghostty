# T853 - test-binary-soak.ps1's two 'return , procs' sites make an EMPTY worker list count as 1 at @() call sites - audit callers for the phantom-element trap

## Summary

Found during T494: PS5.1 'return , (array)' wraps the array as ONE pipeline object, so an @() call site sees Count 1 even when the array is EMPTY (the element is the empty array). In CacheHeal.ps1 this manifested as a phantom cache-corruption detection until fixed (commit 3e84827aa). scripts\test-binary-soak.ps1 lines ~483 and ~568 use the same 'return , $procs' shape; if any caller wraps in @() or counts the result, zero started workers could read as one (the element being an empty array), which would misreport load or skip the kill sweep. Audit each caller: either the comma is load-bearing (caller assigns directly, no @()) and deserves a comment saying so, or it is the trap and needs the plain-return + @()-at-call-site pair. Validation: targeted assertions in test\win32\test-binary-soak.ps1 covering the zero-workers path.
