# T346 - test-agent flake: server.zig spin-waits a fixed 10k yields, so DATA/detach tests fail under CPU load

## Summary

`zig build test-agent` failed on 2026-08-02 with
`remote.agent.server.test.unknown channel DATA is ignored (no crash, no child
write)`: expected `real`, found a zero-length slice. Nothing was wrong with the
code under test — the same test passed 3/3 in isolation
(`-Dtest-filter="unknown channel DATA"`) minutes later. The lane was running
while a `zig build -Doptimize=Debug` and two other test lanes had just churned
the box.

## Details

The tests wait for a cross-thread effect with a **fixed iteration count**, not a
deadline:

```zig
var spins: usize = 0;
while (spins < 10_000) : (spins += 1) {
    const got = try fc.inputCopy(alloc);
    defer alloc.free(got);
    if (std.mem.eql(u8, got, "real")) break;
    std.Thread.yield() catch {};
}
```

`src/remote/agent/server.zig:3627` (the DATA test) and `:3591` (the preceding
detach test) both use this shape. 10,000 `Thread.yield()` calls is a duration
only if the scheduler cooperates: on a loaded box every yield returns almost
immediately, so the budget can burn through in well under the time the server
thread needs to be scheduled at all. `got` came back **empty**, not partial —
the reader thread had not run once.

That makes the agent floor (`test-agent` green, per go.md step 3)
load-sensitive, which is exactly the wrong property for a gate every turn has
to pass. It has already cost one turn a re-run.

Fix: replace the spin budget with a wall-clock deadline (e.g. a 5s
`std.time.Timer` loop with a short `std.Thread.sleep` between polls) so the test
fails on "never happened" and not on "the box was busy". Audit the file for the
other `while (spins < …)` waiters and convert them the same way; a shared
`waitUntil(pred, timeout)` helper in the test harness is preferable to N copies
of the loop.

*Validation:* `zig build test-agent` green x3, including one run started while a
full `zig build -Dapp-runtime=win32 -Doptimize=Debug` is in flight (that is the
condition that produced the failure). Confirm the new waiters actually fail —
temporarily break the code path and check the test reports a timeout rather than
hanging.
