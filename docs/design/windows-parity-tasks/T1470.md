# T1470 - Screenshot window picker: Tab cycles between windows, so a keyboard user does not have to aim a caret at one

## In plain terms

You can now press Space in the screenshot picker and take a picture of a whole
window. Without a mouse, though, you have to steer an invisible point onto the
window you want with the arrow keys — which means knowing roughly where it is
on screen before you start. Pressing Tab to step through the open windows one
at a time, watching each light up, would be the way somebody who cannot see
where a window is would actually find it.

## Summary

T670 built the window picker and gave it a keyboard path: arrows move the
caret, and the window under the caret is what a click or Enter takes. That is
enough to be usable and it reuses the region mode's aiming, but it is aiming —
a keyboard user has to already know where the target is.

Tab (and Shift+Tab) stepping through the candidate list in z-order is the
answer that does not need that knowledge, and it is the shape the T671 note
argued for: "window-picking with Tab/Space would be a much better keyboard
answer than nudging a rectangle 32 px at a time."

## Details

- The candidate enumeration already exists: `RegionSelector.windowUnder` walks
  `EnumWindows` front-to-back and hands the list to `region_select.pickWindow`.
  What Tab needs is that list WITHOUT the containment filter — every candidate
  on the desktop, not only those under a point — plus an index into it.
- The selected index is the new state; `pickWindow`'s "topmost containing"
  rule stays for the pointer. A pure `stepWindow(list, index, direction)` in
  `region_select.zig` keeps the wrap-around and the empty-list case testable in
  the `none` lane, the way the rest of that module is.
- Aiming with the pointer or the arrows must re-sync the index, so the two
  input paths cannot disagree about which window is picked.
- The status line already announces the picked window's origin and size, so a
  screen reader follows a Tab step for free. It should probably also name the
  window (its title), which is the one thing the current line does not carry
  and the one thing that tells a blind user WHICH window they are on.

## Validation criteria

- [ ] Unit tests (`none` lane): stepping forward and backward wraps at both
      ends, an empty candidate list steps to nothing rather than faulting, and
      a list of one stays put.
- [ ] On-box acceptance in `test\win32\viewer-feedback-capture.ps1`: with the
      selector in window mode and no mouse message of any kind, Tab moves the
      announced selection off the window it started on and Shift+Tab brings it
      back, read out of the overlay's window text.
- [ ] On-box acceptance: Enter after a Tab captures the window the readout
      names, at that window's own measured frame.
