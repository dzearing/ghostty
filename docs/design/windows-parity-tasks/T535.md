# T535 - viewer-panes.ps1 second red at HEAD: +reload on a terminal-focused window does not report the window-flavored Mac string

## In plain terms

One more check in the viewer test suite fails on every run, independent of
any new work: asking a window full of terminals to "reload" is supposed to be
refused with a message that names the window, and the message that comes back
is a different one. Until the message (or whatever produces it) is fixed, the
viewer suite reports red even when nothing new broke — the same problem T526
describes for its sibling assert.

## Summary

`test\win32\viewer-panes.ps1` section 8b fails one assert at git HEAD,
deterministically, with no local changes (verified 2026-08-06 against a clean
Debug build of 8d2d2a918 — `2 FAILURE(S) (115 passed)`, the other being
T526's):

```
FAIL  +reload on a terminal-focused window reports the OTHER Mac string
```

The assert creates a fresh single-terminal window (`vpterms`) and expects
`+reload --target=vpterms` to exit nonzero with
`focused pane of 'vpterms' is a terminal pane, nothing to reload`. The exit
code IS nonzero (that assert passes); only the STRING differs, so the server
is refusing with some other message. T526's root cause is likely the same
family — the T105/T89f2 deferred-focus guard never grants focus inside a
non-active window on the background test desktop, so "the focused pane of
this window" may resolve to nothing (or to another window's pane) and take a
different error path. First step is to capture the actual string (the script
discards `$r.Out` on pass); then decide whether the defect is the resolution
or the message.

Note T526 was filed at `1 FAILURE(S) (110 passed)` on the same day, so either
this assert flaked green then, or something between that run and 8d2d2a918
turned it red. Both reds were reproduced back-to-back on 2026-08-06 during
T159 validation (clean-HEAD control run).
