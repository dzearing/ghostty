# T330 - Mac resumes a session that is already open in one of its own windows, stranding that pane

Mac-side. Found building T320 (resume ONE browsed session on Windows).

## Summary

Mac's chooser guards resume on `session.alive` and nothing else
(`MachineChooserView.swift:167-170`), so a row the app ALREADY has open in one
of its own panes is resumable — and resuming it opens a SECOND viewer on the
same session.

The agent rebinds a session to its newest ATTACH: `remote/agent/server.zig`
(around `:1026-1067`) documents the reconnect/rebuild swap where "the NEW
connection ATTACHes (rebinding the bridge to itself)". So the second window
does not clone the pane — it takes it, and the window that had it is left with
a pane whose PTY now streams somewhere else.

The roster already knows this is the case: the row carries the `open` badge
precisely because one of our panes holds it (`SessionBrowserProbe` /
Windows' `open_locally`).

## What Windows does instead (the divergence to reconcile)

`MachineChooser.resumeRow` (`src/apprt/win32/MachineChooser.zig`) short-circuits
on `row.open_locally`: it dismisses the chooser and FOCUSES the pane that
already has the session rather than attaching a second time. "Show me that
session" is what the user asked for either way, and it cannot strand a pane.
Asserted by `test/win32/chooser-resume.ps1` step 4.

## The work

1. Confirm on a Mac that a second resume of an open session really does steal
   the stream (open a session, resume it from the chooser, type into the first
   pane). Empirical, not inferred — the T246 lesson.
2. If it does, give Mac the same short-circuit: `resume` should activate the
   window/pane already bound to the session instead of producing a
   `resumeSession` target.
3. If it does NOT (some Mac-side path already handles the rebind), record why,
   and re-decide whether Windows should keep focusing or start attaching — one
   answer, both platforms.

## Validation

- Mac: the manual repro above, before and after.
- Windows: `test/win32/chooser-resume.ps1` stays ALL PASS (its step 4 is the
  focus path).
