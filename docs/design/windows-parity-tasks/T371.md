# T371 - PaneView ref/unref ownership has no test: the terminal arm needs a live Surface, so a leak or double-free only shows up as a crash

## Summary

`PaneView` (T90c) is now the split tree's view type, so ITS reference count is
what keeps every pane alive. Nothing tests that counting. The `.terminal` arm
needs a real `*Surface` (which needs an App, a Window and a child HWND), so a
unit test cannot construct one, and the only signal for a leak or a
double-free is a crash or a slow bleed under a long session - exactly the
class of defect the T53 bar exists to keep out.

## Details

What is untested today:

- `createTerminal` takes exactly ONE surface reference, and `unref` at zero
  releases exactly that one.
- `destroyUnowned` (the "never made it into a tree" path taken by `addTab`,
  `replaceTabRootSurface` and `newSplitAt` when `SplitTree.init` fails) frees
  the pane AND the leaf under it, and cannot underflow the count.
- The viewer arm frees its `ViewerPane` outright.
- The back-pointer contract: `Surface.pane_view` stays valid across
  `Surface.deinit` (the IPC-registry forget reads it) and dangles only on
  memory that is being destroyed anyway.

Two approaches, either acceptable:

1. **Make the counting generic.** Move ref/unref/eql onto a tiny
   `RefCounted(V)` mixin that `PaneView` composes, and test the mixin in the
   none-runtime lane with a fake leaf that records ref/unref calls. Cheapest,
   and it tests the arithmetic - which is where the underflow lives.
2. **A test-only constructor.** A `PaneView.createForTest` that wraps a stub
   leaf, exercised in the win32 lane. Tests more of the real type but needs a
   third union arm or a comptime seam, which the design deliberately does not
   have.

Prefer (1) unless it distorts `PaneView`.

Related: the viewer branches T90c added to `IpcHandlers.buildNode`
(`"type": "viewer"` + `url`) and to `App.captureLayout` (`kind` /
`viewer_location`) are likewise unreachable until T90d constructs a viewer -
their coverage belongs to T90d/T90h, not here.

*Validation:* new unit test(s) green in the named lane; `zig build test
-Dapp-runtime=none` and `-Dapp-runtime=win32` both green.
