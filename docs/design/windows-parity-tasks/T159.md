# T159 - Viewer nav chrome: hover strip, back/forward/reload/home, editable address bar

## In plain terms

A viewer pane on Windows is a dead end today: once it opens a file or a page,
there is no way to go anywhere else — no address bar to type into, no back or
forward, no reload button, no way home. On the Mac, moving the mouse to the
top of a viewer pane slides in a small browser-style bar with all of that.
This task builds the same bar for Windows: hover the top edge and it appears,
type a web address or a file path and the pane goes there, and Back even works
across the file/website boundary.

## Goals

- [x] A hover strip at the pane's top reveals a native nav bar (auto-hides
      after 2s, stays while the address field has focus)
- [x] Back / Forward / Reload / Home buttons that reflect real browser history
      (disabled when there is none)
- [x] Back from a website re-renders the file the pane was on before
- [x] An editable address field: bare hosts complete to https://, Windows
      paths (C:\, \\server, ~\) open as files, click selects the whole address
- [x] Home returns to the location the pane was opened with

## What shipped (2026-08-06)

- **Pure half, none-lane tested on both seats:** `src/apprt/win32/viewer_nav.zig`
  (Windows-shaped `isFilePath` — `file://`, `/`, `\\`, `~/`, `~\`, `C:\`,
  `C:/`; `completeAddress` ported case-for-case from Mac's omnibox including
  the localhost/127.0.0.1 http:// rule and dotless-word `.com`; `resolveInput`
  passing diff specs and `about:` through untouched; `addressText` display
  rules) and `src/apprt/win32/viewer_nav_layout.zig` (bar/strip geometry
  asserted at 1.0/1.25/1.5/2.0, plus the whole reveal policy as a pure
  `hoverTick` decision table — 2s strip delay, 0.7s drift, 0.5s leave,
  deadlines only ever pulled in, `held` never hides).
- **The bar:** `src/apprt/win32/ViewerNavBar.zig` — owner-painted child window
  (`GhozttyViewerNav`) with four icon buttons (new `back`/`forward`/`refresh`/
  `home` glyphs in `icon_button.zig` + Fluent codepoints E72B/E72A/E72C/E80F,
  quad fallbacks passing the shared symmetry sweep) and a real `EDIT` with
  cue banner, dark-mode theming derived from the pane background via
  `banner_card.fillColor`/`chrome_theme.textOn`. Enter/Escape route through
  the main loop (`ViewerNavBar.owningEdit`, the popup-edit house pattern);
  click-select-all posts from the loop's `WM_LBUTTONUP` intercept so the
  selection lands AFTER the EDIT's own click tracking (Mac's
  `selectAddressWhenClickCompletes`, translated).
- **The pane:** hover poll (`GetCursorPos` at 150ms — WebView2's Chromium
  children eat the mouse, same reason Mac uses an event monitor), foreground
  gate, content inset while visible, `goBack/goForward/goHome/
  reloadFromChrome/navigateFromAddress/cancelAddressEdit/focusAddressBar`,
  tilde expansion via `view_arg.tildeRemainder` + `internal_os.home`, and
  `syncCommitted` — the port of Mac's `didCommit` mode reconciliation that
  makes Back from a website re-render the file (`file_location` survives web
  moves for exactly this).
- **The vtable:** `webview2_iface.zig` names `add_SourceChanged` (11),
  `add_HistoryChanged` (13), `get_CanGoBack` (38), `get_CanGoForward` (39),
  `GoBack` (40), `GoForward` (41) with offsets asserted; two new handler IIDs
  proven by the live test (the events firing IS the proof — no WebView2.h
  exists on this box to check against).
- **Also fixed en route:** leaving file mode for the web now clears the TOC
  headings on the pane-initiated path too (they used to survive
  `navigate()` to a website); `onNavigationCompleted`'s failure log now
  names the `WebErrorStatus` ordinal, which is what separated a routine
  superseded-navigation abort from a genuine load failure during this task's
  own debugging.

## Summary

Filed 2026-07-29 by the T127 re-scope. The Mac viewer's navigation chrome
(hover-revealed bar with back / forward / reload / home and an EDITABLE address
field with omnibox completion) postdates the T90a design and is in NO T90b-T90h
row, yet the user named it by hand: *"the address bar we added in macos ...
missing"*. Ships in Windows viewer v1. Design: `docs/design/viewer-panes-windows.md`
pins P3 (native child window, not web content) and P4 (Windows-shaped path
classification).

## Details

Mac sites: `ViewerView.setChromeVisible`, `scheduleChromeHide` (2s),
`chromeRevealHeight = 20`, `goBack/goForward/reloadPage/goHome`,
`navigate(to:)`, `completeAddress` (`ViewerView.swift:727`),
`addressText(for:)`, `focusAddressBar`, `addressClickSelectsAll`,
`selectEntireAddress`, `isFilePath` (`:562`), and the `canGoBack`/`canGoForward`
/`url` observations in `setupWebView`.

Scope:

- Owner-painted native child window hosting a real `EDIT` control for the
  address field (P3). Precedents: `RenameDialog.zig`, `BannerDialog.zig`,
  `MachineChooser.zig` -- house dark-mode + per-monitor-v2 DPI handling.
  Rejected alternative (recorded in the design): rendering the bar as injected
  page content, which would fight arbitrary sites' CSS and put the address
  field inside the content it navigates.
- Hover reveal at the pane's top strip, 2s auto-hide, held open while the field
  has focus. Held open unconditionally once the narrow-TOC overlay exists
  (T160) -- `chromeAlwaysVisible`.
- Back/forward reflect real history (`add_HistoryChanged`, `get_CanGoBack`,
  `get_CanGoForward`), disabled when there is none, and work ACROSS the
  file<->web boundary: Back from a website re-renders the file.
- Home returns to the pane's `homeLocation` (where it was OPENED), which is
  tracked separately from where the user navigated to and is persisted by T90h
  (design P12 reserves `viewer_home_location`).
- Address field: current URL displayed Mac-style (`about:blank` shows empty,
  `file://` shown as a path), click selects the whole address, a second click
  inside just moves the caret, submit hands focus to the page.
- Omnibox completion: bare `example.com` -> `https://example.com`. Port
  `completeAddress` into a pure Zig module so it unit-tests in the
  none-runtime lane.
- P4: `isFilePath` must accept `C:\`, `C:/`, `\\server\share`, `~\` and
  `file://` -- not just `/` and `~/`. Same pure module. NOTE the same defect
  class is live in the shared CLI (`src/cli/split.zig:212`,
  `src/cli/new_window.zig:319` test only `rest[0] == '/'`); that fix belongs to
  T90b, and this task must not duplicate it.
