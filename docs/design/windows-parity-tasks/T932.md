# T932 - A harness that needs Docker can never re-stamp its guard on this box

## Summary

test\win32\release-artifacts.ps1 stamps only on a run with zero skips, and its section B needs Docker + the msitools-local image. Docker is deliberately kept down here (its WSL2 backend has buried the box), so the release-artifacts guard goes DUE the moment a release workflow file changes and can never be cleared - every later turn then has to reach for validate -NoGuardDue, which is the hatch for a harness that cannot run, not for one that runs 90 percent. Wanted: a guard row can declare which sections are environment-gated, so a run that is green everywhere the environment allows re-stamps and says which parts it could not cover, and only a RED run or a skipped non-gated section keeps the guard due.
