## In plain terms

Somewhere along the way a tool wrote real control characters into repository
files wherever a Windows path contained a backslash followed by `a`, `b` or `f`
- so `zig-out\bin` became `zig-out<BS>in` and `test\win32\floor-...` became
`test\win32<FF>loor-...`. Thirteen files carry it. In documentation it is
invisible (a reader sees the two halves run together and assumes a typo); in a
script it is a path that quietly does not exist.

## Summary

Found while editing `scripts\guard-due.ps1` for T1170: the `install-prepare`
guard row's `Covers` list named `src<BEL>pprt\win32\install_prepare.zig`, so
that guard could never resolve the file it claims to cover. `docs\claude\testing.md` had `<repo>\zig-out<BS>in\ghoztty.exe`.
