# T1093 - ipc-version.ps1 goes red on every turn that commits, because it compares the build's baked commit against HEAD

## In plain terms

One of our automated checks asks the app "which version of the code are you?"
and fails unless the answer is the very latest commit. But we build the app,
then test it, then commit - so by the time anyone looks, the app is honestly
reporting the commit before the one that just landed, and the check calls that
a defect. It cries wolf on almost every session, which is how a check stops
being read.

## Summary

`test\win32\ipc-version.ps1` asserts `commit matches HEAD` and
`build.commit matches`. Measured 2026-08-22 during T361's first suite sweep:
2 FAILURE(S) against an exe that was correct, because HEAD had moved to a
tracker chore commit after the build.

This is the exact reasoning `test\win32\lib\BuildFresh.ps1` already records
for choosing mtime over the baked commit:

> red on a commit that changed nothing - the loop builds, tests, and THEN
> commits, so at step 6 the exe's baked commit is the parent of HEAD while its
> bytes are exactly what HEAD's sources produce. A hard refusal there would
> fire on every turn, and a gate that cries wolf daily gets an `-Allow` bolted
> onto every caller within a week.

`ipc-version.ps1` is asking the delivery question (`upgrade-staleness`'s
question) in the turn's own working tree, where it is the wrong one.

## The fix

Assert what the version surface must actually get right - that `+version`
reports a well-formed commit, that it matches what the binary was built from,
and that the JSON shape is stable - without requiring that commit to be HEAD.
If a HEAD-equality arm is wanted at all it belongs behind an explicit switch
used by the delivery checks, not in the default run.

## Validation criteria

- [ ] `ipc-version.ps1` is green against a build made from the working tree
      when HEAD has since moved to a commit that changed no source
- [ ] it still fails when `+version` reports a commit the binary was not built
      from (a planted mismatch, so the arm is proved to still bite)
