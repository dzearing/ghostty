## Summary

Filed 2026-07-29 while working T127. Not a viewer item -- found by checking
whether the Mac viewer inventory was current: `origin/main` is 12 commits ahead
of this branch, and `d6f1c1de5` ("feat(banner): hover affordance + action menu
for banner links", merged as `7cd580963`) is a NEW Mac banner capability with
zero references in any `windows-parity-*` doc. Filing it now rather than at

leaked parity work precisely because nobody enumerated the incoming commits.

Pending merge into `users/dzearing/windows-amd64`, so scope it from the Mac
implementation once merged; the row exists so it cannot be lost in the meantime.

## Details

Windows already renders clickable banner links (`[text](url)` in
`banner_markdown.zig` + `BannerOverlay.zig`), so this is an affordance gap on
top of a shipped feature, not a new subsystem:

- hover affordance on a banner link (the Mac commit's first half)
- an action menu for the link (the second half) -- on Windows the natural
  surface is the existing win32 context menu (`context_menu.zig`), which T129
  already taught to label rows `Title\tChord` from the live keybind set.

Read the merged Mac implementation before designing: the two halves may share
one hit-test path, and the win32 overlay already has a hit-test for link
activation to extend rather than duplicate.

Related: the same 12-commit band adds CLIENT-scoped "What's New" (pre-update
dialog + tabbed menu window, `68d9299a9`), which belongs to the existing T125
rather than a new row -- noted there.

*Validation:* `pane-banner.ps1` grown -- hovering a banner link changes its
rendering (pixel probe, per the T131/T155 pattern, and launch with
`--session-persistence=false`), and the action menu opens with the expected
rows. Both lanes + P1-P3 green.
