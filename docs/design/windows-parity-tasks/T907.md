# T907 - The running agent adopts a newer on-disk build with sessions open: handoff choreography, rollback, and the handoff_now policy arm

## Summary

Final Windows increment of the T705 split (design:
`docs/design/agent-nondestructive-handoff.md`). With holders (T904-T906) in
place, the actual upgrade:

1. Old agent spawns the newer on-disk binary; the new agent adopts holders,
   binds nothing public, and reports READY over a private pipe.
2. Only on READY does the old agent close its listener and exit; the new agent
   takes the single-instance guard and public pipe (existing
   `--force-replace` machinery in `single_instance.zig`).
3. Any failure before READY: the new process exits, the OLD agent keeps its
   listener and sessions. "Neither agent" is unreachable by construction.

Policy (`agent_upgrade.zig`): a third arm `handoff_now` — stale AND every live
session holder-backed AND capability advertised. Asks nobody, loses nothing,
never deferred. Mixed-generation agents (legacy direct-ConPTY sessions still
alive) DRAIN LAZILY: the handoff waits, and `+sessions --agent` names how many
legacy sessions are holding it back; the forced path remains the existing
explicit confirmation.

## In plain terms

The background session manager can finally update itself while you keep
working: a new copy starts, quietly takes over the caretakers holding your
sessions, and the old copy bows out — no dialog, no lost session. If anything
goes wrong mid-swap, the old copy simply stays in charge.

## Goals

- [ ] READY-gated handoff with rollback that always leaves the original agent
      serving on failure.
- [ ] `handoff_now` policy arm + capability gating; `+sessions --agent`
      reports handoff-readiness and legacy-session drain count.
- [ ] Lazy drain for mixed-generation agents; confirmation stays the only
      forced path.
- [ ] End-to-end acceptance (carried from T705's validation criteria).

## Validation criteria

(Carried verbatim from T705.)

- [ ] A running agent adopts a newer build with live sessions open, no dialog,
      and no session lost - measured with an acceptance script that types into
      a pane before and after (`Test-PaneLive`).
- [ ] A handoff that fails leaves the ORIGINAL agent running and its sessions
      reachable; it never lands on "neither agent".
- [ ] `+sessions --agent` reads `current` afterwards, from the same box, with
      the same pane still alive.
- [ ] Skew both ways still degrades exactly as the agent contract requires.
