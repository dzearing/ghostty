# D13 - Should an empty terminal pane make +read succeed with empty output, or fail with its own distinct error?

## Why this needs a call

A pane that has printed nothing is the normal state of EVERY pane for the first fraction of a second of its life, and the permanent state of a pane running something silent. The old behaviour reported it with the same message as a missing or wedged pane, so a caller that reads once records 'no output' as a verdict. Both options remove the ambiguity; they differ in whether an empty pane is still an error condition at all.
