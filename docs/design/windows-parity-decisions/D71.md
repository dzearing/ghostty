# D71 - Should the win32 filter boxes fold Unicode case the way macOS does, and if so with Windows' linguistic search or an in-tree fold table?

## Why this needs a call

The two win32 filter boxes hand-rolled an ASCII fold each; T288 merged them into one function and had to record whether ASCII is the intended alphabet. Checking the Mac sources showed it is not: both mirrored filters there use localizedCaseInsensitiveContains, so Windows silently finds nothing for needles the Mac matches. Which way to close that is a product and architecture call - the platform-native answer costs the pure test lane, and the pure answer does not fully match the Mac - so it is filed rather than assumed.

## Resolution

Chosen: Use Windows' own linguistic search, FindNLSStringEx with LINGUISTIC_IGNORECASE (Recommended)

Resolved by Claude (user delegated technical calls, 2026-08-14). The experience is settled by parity - the Windows filter must match what the Mac filter matches, including non-ASCII. Among mechanisms, the platform linguistic fold (FindNLSStringEx) tracks Windows own casing rules without vendoring case data; the policy stays pure behind one function as T288 prepared.
