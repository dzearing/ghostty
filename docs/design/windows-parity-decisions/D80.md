# D80 - Should Ghoztty start absorbing upstream Ghostty's last three months of terminal improvements, and in stages?

## Why this needs a call

Ghoztty forked from Ghostty in May. Since then upstream shipped 764 commits of terminal-engine work - faster scrollback, rendering changes, reworked OSC and ssh handling - none of which this build has. Taking them is not free: upstream also moved to a new Zig compiler, and that one change touches more than half the files where both projects have edited the same code, so the app has to move with it. The user would notice either way - either the terminal gradually gains upstream's improvements with a disruptive stretch in the middle, or it keeps behaving exactly as it does today and quietly falls further behind.

## Resolution

Chosen: **Stop taking upstream at all - treat this as a hard fork.**

First resolved 2026-08-19 as o1 (staged absorption). Stage 0 landed - an
`upstream` remote, union merge drivers, and a fork-identity overlay script -
and no upstream code was ever merged.

**Reversed 2026-08-22 by explicit user directive**, in the user's own words:

> We will NEVER EVER EVER merge back to ghostty. I don't even want that to be a
> question. I think we should even remove ghostty as an upstream, maybe even
> remove every possible reference to ghostty.

> We ONLY push changes to my dzearing personal account ghoztty github repo!

Ghoztty is a permanent hard fork. The `upstream` remote pointing at
ghostty-org/ghostty had a **push** URL configured and has been removed
(2026-08-22T12:11:50Z). `origin` (github.com/dzearing/ghoztty) is the only remote, and the
only place anything is ever pushed.

This decision is **closed permanently**. It is not to be re-opened, re-asked,
or re-litigated by a future turn, and no task may depend on absorbing upstream.
The cons listed under o2 - that upstream's engine work never arrives and
already-fixed bugs get re-found here - are accepted costs, not open questions.

Follow-up: T961 (rip out the Stage 0 merge plumbing), T962 (scope the
de-Ghostty reference sweep, which needs its own call because terminfo,
bundle ids, and MIT attribution are not free to rename).
