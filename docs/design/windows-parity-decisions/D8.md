# D8 - Should T278 have also shipped the protocol change that tells a pane WHY its shell was refused?

## Why this needs a call

T278 lists two defects: the cap counting dead sessions, and the refusal being silent at the pane. The first is the P0 the user hit and is a self-contained agent-side fix with unit + acceptance coverage. The second needs a new wire opcode, which per the agent-contract rules must be capability-gated on both sides and touched into the RPC core - a materially riskier change with a different blast radius. With the cap fixed, the silent path is only reachable at 256 genuinely LIVE sessions, which nobody hits.
