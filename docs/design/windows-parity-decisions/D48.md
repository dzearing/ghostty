# D48 - How should a Windows report capture what the user had SELECTED in the page?

## Why this needs a call

WebView2 has no synchronous script evaluation, so reading the selection at send time means an async continuation on the path that files the report. Mac guards that with a 1.5s timeout; on win32 the same shape would mean holding a composer snapshot across the round trip and inventing a timer for a case that produces one string. Tracking moves the failure from 'the send hangs' to 'the report has no selection', which the format already allows.
