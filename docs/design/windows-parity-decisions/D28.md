# D28 - Should the Activity Monitor's process list have a keyboard caret that can move WITHOUT changing the selection?

## Why this needs a call

T289 asked for a decision on the row-focus vs row-selection distinction, because Windows list views draw a focus rect on the focused row separately from the selection fill. The panel needed A caret regardless - a focus ring has to go somewhere - but whether that caret is independently movable is a product question, not an implementation detail, and I could not settle it by reading the code: Mac's panel has no keyboard multi-select either, so parity does not answer it.
