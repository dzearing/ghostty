# D23 - Should the session-layout manifest keep carrying per-window geometry, or defer to the placement memory on restore?

## Why this needs a call

T220 reproduced a restored window forgetting a resize after a force-kill: the manifest write was debounced 250ms while the placement memory wrote synchronously, so restore replayed a stale frame. Fixing it required deciding which store is authoritative for restored geometry before closing the race.

## Resolution

Chosen: Manifest keeps per-window frames; write both stores at the gesture, manifest first (Recommended)
