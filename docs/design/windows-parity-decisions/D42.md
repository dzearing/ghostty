# D42 - Should the win32 startup restore be moved into the message loop, or is pumping IPC from where it blocks enough?

## Why this needs a call

T188 prescribes the T48 pattern - post restoreSessionLayout into the message loop and run it from there. Reading IpcServer shows that cannot work: a listener thread accepts the connection, posts WM_APP_IPC and then BLOCKS until the GUI thread runs the handler, so a request is served exactly when the GUI thread pumps. Deferring the restore changes when it starts, not whether anything pumps while it runs. The choice was therefore between a fix that matches the filed prescription and one that matches the measurement.

## Resolution

Chosen: Pump IPC where startup blocks (Recommended)
