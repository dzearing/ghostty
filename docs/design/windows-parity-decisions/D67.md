# D67 - How should a content-sized tab strip cope with a shell that retitles itself on every command?

## Why this needs a call

T235 made a tab's width its title's width, which is what the user asked for. The consequence, measured on 2026-08-11: with no configuration at all, cmd.exe retitles itself to '<cmd.exe path> - <command>' while a command runs, so one ordinary ping moved tab 2 and the '+' 186 px out and 186 px back, and mid-command the point that had been tab 2's centre sat inside tab 1 - a click there selects the wrong tab. Something had to give, and every candidate gives up something different.

## Resolution

Chosen: Grow-only ratchet, released at a structural relayout (Recommended)

Resolved by Claude (user delegated technical calls, 2026-08-14). The experience goal is settled - tabs must stop dancing while a shell retitles itself - and among mechanisms the grow-only ratchet measured strip motion falling from 1349 px to 200 px and removed the wrong-tab click, while never ellipsizing a title with strip to spare. The pointer-freeze follow-up stays filed for the residual case.
