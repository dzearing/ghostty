# D59 - How should a long-lived box adopt a newer local agent?

## Why this needs a call

The running agent advances only two ways: a silent restart when zero sessions are live, or a mandatory confirmation. A box that always has a pane open never reaches the first, and the morning app-only refresh deliberately defers the second - and the check that would ask later re-runs only at launch and when the last persistent window closes. So on this box the agent can sit on an old build indefinitely while the app advances daily. Nothing misbehaves today (the wire contract is forward-compatible both ways); the risk is an agent-side fix that never reaches the user.
