# D58 - For a WSL pane, should the command run in /bin/sh and then hand off to the user's login shell, or in the login shell itself?

## Why this needs a call

wsl is the one --shell row that takes an argv rather than a command string, so unlike every other flavor we must NAME the interpreter inside the distro rather than being handed one. Windows cannot see what the user login shell in the distro is, so running the command in it requires wrapping the user own text in a second layer of quoting. Measured on this box: /bin/sh is dash, $SHELL is /bin/bash, and dash accepts -lic.

## Resolution

Chosen: Run the command in /bin/sh, then exec into the login shell (Recommended)

Resolved by Claude (user delegated technical calls, 2026-08-14). Shell plumbing: /bin/sh exists in every distro and one quoting layer means a command with quotes arrives exactly as typed; the pane the user sits in is still their real login shell. The bash-alias limitation is documented; a user needing bash semantics spells bash into the command.
