# D91 - A session whose program already exited is listed in the machine chooser. Should picking it reopen that session, or should it not be listed at all?

## Why this needs a call

The chooser's session list shows the sessions on a machine. Some of them have already finished - the program exited, or the box rebooted - but the terminal still remembers the command and the folder they were in. Today those rows sit in the list looking exactly like the ones you can take over, and pressing Return on one says it cannot be resumed. That is the gap: the list is offering something it will not do. Either it should honour the offer by reopening the session - a fresh prompt in the folder it was in, and a line naming the command that was running - or it should stop making it. (Actually re-running the old command is a separate question the terminal already answered no to by default, and this does not reopen it.)

## Resolution

Chosen: the list represents the processes still alive. If we don't have a ghoztty window for something still running in the agent, we should list it, otherwise if it's a dead process and not working we don't.
