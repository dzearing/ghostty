# D4 - Should a lone --keys-file= text run be framed as a paste, even with no Enter after it?

## Why this needs a call

The fix works by carrying the argument boundary through to the pty, so it only helps when one +send-keys call holds both the text and the Enter. The upgrade script splits them on purpose - it verifies the prompt arrived before submitting, because a post-submit check races /reset-context clearing the pane. Framing a lone --keys-file run would fix that path with the gate intact, but --keys-file is documented as a byte-exact transport and some callers may be using it to run shell commands, where a paste no longer executes.

## Resolution

Chosen: Leave it unframed (assumed)
