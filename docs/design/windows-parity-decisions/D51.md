# D51 - When a restore's resume point is clamped as stale, should the viewer still paint the screen it persisted?

## Why this needs a call

The T532 clamp creates a case the snapshot-paint condition was never written for: an ATTACH that is live and correct, but whose persisted screen belongs to a previous incarnation of the same session id. The code's own comment says painting an old screen under a new stream 'would be a lie about what the pane is' - which argues for skipping - while the reason the paint exists at all is that a restored pane must never come up blank. Both principles are the project's; they disagree here and nothing in the tracker settles it.
