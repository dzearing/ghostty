# D57 - Should a trailing CRLF submit once, diverging from upstream main's byte-counting peel?

## Why this needs a call

T604 ported main's trailing-newline peel verbatim, including its byte-by-byte walk, so a Windows-style line ending counts as two Enter presses. Fixing it means our shared CLI no longer matches upstream main until main takes the same change.

## Resolution

Chosen: Fix it in shared core and offer it upstream (Recommended)

Resolved by Claude (user delegated technical calls, 2026-08-14). A CRLF-terminated prompt means one submit in every caller intent, and Windows is where CRLF text comes from. The upstream divergence is one small hunk with unit tests, offered upstream, and T701 has the Mac seat verify it.
