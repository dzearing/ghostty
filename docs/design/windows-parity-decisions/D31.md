# D31 - Should the Windows key-state pill be draggable between the pane's bottom and top edge, the way the Mac one is?

## Why this needs a call

Mac's KeyStateIndicator can be dragged between the pane's top and bottom edge, and the position is view state that does not persist. The information - which table, which keys, still waiting - is the feature; the draggability is an interaction habit. The Windows design system has no vocabulary for a chrome control that the user repositions by hand, and making the pill draggable means making it clickable, which means it stops being click-through and starts eating mouse input at the bottom-center of the terminal. I could not settle from the code whether the covered-content case actually bites in practice.
