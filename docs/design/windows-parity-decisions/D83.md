# D83 - When a viewer pane is too narrow for its toolbar, should the extra buttons vanish or be sliced in half?

## Why this needs a call

Drag a viewer pane narrow enough - a rendered README beside a terminal, squeezed to a sliver - and its little toolbar runs out of room. Today on Windows the row simply runs off the edge: you get one whole button, then a sliced one, then nothing, and the address box has already collapsed. The Mac build lets the pane edge cut through the row the same way, so there is no established look to copy here - both platforms are showing an accident rather than a choice, and this is the moment to pick one. What you would see under each option is different enough that it should be your call: fewer buttons that all look right, buttons cut in half, or a whole row of very small buttons.

## Resolution

Chosen: I'd love for it to look designed as you suggest so collapsing them into a ... button is fine, but i'm quite unsure how an address bar is going to look in a tiny condensed mode. 1 button and 1 tiny input? So i guess try option 1. But make sure it looks polished and consistent.
