# D11 - Should the pane probe identify Claude Code by its transcript GLYPHS, or only by its chrome wording?

## Why this needs a call

Probing this very pane on 2026-08-04 returned 'unknown': every existing marker belongs to the IDLE composer, and a Claude Code that is working scrolls all of them off. Goal 3 of T440 depends on the classifier answering correctly for a live claude pane, so shipping without a fix would have shipped a feature that does not work on this box. The choice is between a marker set that drifts with each Claude Code release and a structural signal that has not.

## Resolution

Chosen: I do not want claude code specifics in a general terminal app other than registering skills that make it work with ghoztty. It is unclear to me why you would need to even identify that a pane is running claude code.
