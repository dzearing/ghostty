# D6 - Should a red test lane spend up to ~20 extra minutes re-running the crashed binary under a debugger?

## Why this needs a call

The crash this exists for lands on about half of runs, so capturing it means re-running the binary - which costs real minutes on an already-failing lane. Opt-in is cheaper but has a track record: T443 spent two contexts with no stack because nobody had the tooling armed at the moment it happened.

## Resolution

Chosen: On by default, but 1 attempt, and identify ways to find crash details faster in the future, if possible. We want it to be easy to diagnose crashes so that we can capture and fix them faster.
