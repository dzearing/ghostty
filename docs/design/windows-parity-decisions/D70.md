# D70 - How should PowerShell hand free text (window titles, banners, commands) to the ghoztty CLI?

## Why this needs a call

PowerShell 5.1 mangles any argument containing a double quote or ending in a backslash, silently and at exit 0. Measured with a GetCommandLineW oracle, no escaper can fix the general case: for text whose first space is preceded by an odd number of quotes, PowerShell declines to quote the argument at all and the CRT splits it. So the choice was between fixing it in our scripts or growing the CLI a file-based flag per field.

## Resolution

Chosen: Build the command line in PowerShell (Recommended)

Resolved by Claude (user delegated technical calls, 2026-08-14). The defect is PowerShell 5.1 quoting in our own scripts, so the fix sits there: building the command line ourselves fixes every flag of every verb at once with no new CLI surface, no cross-platform obligation and no version skew.
