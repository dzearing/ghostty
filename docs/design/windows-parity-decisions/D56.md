# D56 - How should the win32 server tell a resolved +send-keys payload from a legacy one?

## Why this needs a call

The server has to decide whether a newline in --keys= is content or an Enter, and the two cases produce byte-identical payloads: today's CLI peels a trailing newline to CR and leaves interior ones as content, while a pre-T604 CLI meant Enter by a bare newline. A single all-text send carries no --segments= to key off, so nothing already on the wire distinguishes them. Guessing wrong in one direction mangles a multi-line paste; guessing wrong in the other stops an older CLI's sends from submitting at all.

## Resolution

Chosen: Add a --keys-resolved= marker argument (Recommended)

Resolved by Claude (user delegated technical calls, 2026-08-14). Wire-protocol versioning: an explicit additive marker beats guessing intent from byte-identical payloads; every version skew degrades to current behavior and the Mac parser is untouched. No user-visible difference between options when both ends are current.
