# D9 - Should the scrollback-loss fix change terminal core, or sit in the Windows termio layer?

## Why this needs a call

Growing a pane's row count made ghostty import scrollback rows into the active area, where the ConPTY child's post-resize repaint erased them permanently (measured: 18 lines gone from an 18-row growth). The import lives in PageList.resizeWithoutReflow and is CORRECT on a POSIX pty, where the child does not repaint and the pulled-down history stays readable. So the fix had to be conditional either way; the fork was where to put the condition.

## Resolution

Chosen: Change PageList/Screen resize semantics with a plumbed flag
